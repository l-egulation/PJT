# 임시 플레이 GUI

[분야 개요](README.md)

> 일반 런은 `SketchEquipment`·`SketchRunBinding` 경로를 사용한다. 제품 규칙은 [무기 도면·런 잉크 도감](../../../design/equipment/rules.md), [런 보상](../../../design/run/rewards.md), [증강](../../../design/progression/maintenance-augments.md)이 소유한다. 아래 별도 표시한 `Inventory`·`WeaponGrowth` 팔레트·스탬프 설명은 해당 레거시 경로의 유지 범위이며 현재 런의 가방·제작 규칙이 아니다.

`TemporaryGameGui`는 실제 런·전투·인벤토리 상태를 읽어 만드는 uGUI 화면이다. `Deviant.UI.Theme.ApprovedTheme`가 꾹꾹체와 승인된 개별 무기·잉크·팔레트 에셋을 공급하며, 1920×1080 시안 좌표를 960×540 안전 영역의 절반 단위로 표현한다. 인벤토리는 가방·장비 두 탭과 선택한 스케치의 제작 단계를 사용한다. 인벤토리의 선택·호버는 노란 글씨로, 장착 대상은 얇은 테두리로 표시하며 붓칠 강조는 사용하지 않는다. 다른 화면의 기존 선택 강조는 유지한다. 실제 표시·입력 계약은 [UI·상호작용](../../../design/ui/ui-and-interaction.md)을 따른다. 아이템 그림은 고정 영역에서 비율을 유지하고, 긴 설명은 별도 마스크/스크롤에 두며 하단 행동 버튼은 고정한다. 화면 이미지를 통째로 붙이거나 독립 테스트의 샘플 보유 목록을 런에 복사하지 않는다.

전투 HUD와 타이틀은 이 테마 연결 작업의 변경 대상이 아니다. 전투 HUD·출발 팔레트는 [채택 아트와 사용자 편집 배치](combat-hud-approved.md)의 기존 연결을 유지한다. HUD의 기존 폰트와 픽셀 전용 화면의 Galmuri11, `PaperGuiSkin`이 필요한 레거시 화면도 유지한다. 타이틀은 `WellTitlePresentation`·`SketchTitleScene`·`SketchTitleBlend`가 승인된 `resources/ui/title-sketch-20261115/`를 메인 에셋 배치 계약으로 읽는다. 이전 우물 타이틀 원본은 보존한다. 플레이 중 모달 뒤에는 실행 중인 월드가 남는다.

전투 HUD는 `VillagePixelViewport.CalculateDisplayRect`의 960×540 정수배와 기존 여백을 유지한다. 타이틀 풍경은 창 전체를 채우고, 로고·메뉴는 1600×900 안전 영역을 균일 배율로 확대·축소한다. 승인 메뉴·전체 지도·결과는 별도 `MenuStage`에서 창의 가로·세로 중 작은 비율로 연속 확대·축소한다. 예를 들어 1280×720에서는 메뉴가 창을 채우며, 다른 화면비에서는 16:9 안전 영역을 가운데 유지한다. 전체 화면 모달 음영은 창 전체를 덮는다. 설정과 확인창은 하위 메뉴의 글자·버튼을 가리고, 확인창의 암전과 겹치는 부모 암전도 잠시 숨긴다. 닫으면 원래 가시성과 입력 상태를 복원한다.

승인 꾹꾹체는 원본 TTF의 동적 `HintedSmooth` 렌더링을 사용한다. `ApprovedTheme`가 글꼴 로드와 아틀라스 재생성 시 Bilinear 샘플링을 유지하며, 로딩·데모 완료·포탈 수첩 화면도 같은 공용 샘플링 정책을 사용하며 공용 글꼴을 Point로 바꾸지 않는다. 픽셀 그림과 Galmuri의 Point 설정은 별도로 유지한다. 이름 변경창의 제목·설명·입력·글자 수는 960 기준 15·11·14·11px이다. 이름 오류 안내·장착 표시·지도 스크롤 안내도 11px로 표시하며, 작은 키캡의 기존 크기는 유지한다. 글자 품질 비교는 1920×1080에서 직접 렌더링한 원본으로 확인한다.

화면 설정의 값은 양옆의 화살표로 이전/다음 후보를 고른 뒤 적용한다. 적용 전에는 실제 해상도를 바꾸지 않으며 기존 15초 복원과 미적용 확인을 유지한다. 조작 탭은 `TemporaryGameGui.SettingsKeys`의 단일 스크롤 목록에서 실제 키 바인딩을 바로 편집한다. 최신 이동·공격·포탈·메뉴·지도 바인딩, 충돌 검사와 즉시 저장은 `KeyboardShortcutSettings`를 그대로 사용한다. Esc는 진행 중인 키 변경만 취소하고, 탭 이동/창 종료도 재바인딩 입력 소유권을 반환한다. 기본 키 복원은 기존 확인창을 거친다. 복원·미적용 확인창은 키보드 F/G를 유지하며, 패드는 좌우 선택 후 확인(South), 취소(East/Start)를 사용한다. 키를 지정하는 동안에는 메뉴 제출/복원 입력으로 중복 처리하지 않는다.

## 실행

- Unity **6000.6.5f1**.
- `Assets/ForestCombatV2/Scenes/Chapter1Title.unity`를 열고 Play → 새 게임.
- 실제 런: `Assets/MeadowDuskV3/MapVer2/Scenes/Chapter1Procedural.unity`.
- `InventoryGameBinding`이 1챕터 씬에서 명시적인 `viewPrefab`이 없을 때 새 GUI를 생성한다. 기존 프리팹 주입과 별도 전투 시험 씬의 View는 유지한다.
- 타이틀은 `Chapter1TitleScreen`이 있는 씬에 자동 설치한다.
- 원본 그림이 Git에서 제외된 새 작업 폴더는 Unity를 처음 열기 **전에** [에셋 복원](../../../assets/README.md)을 끝내야 한다. PNG 없이 먼저 임포트하면 Unity가 기존 이미지의 `.meta`를 제거·재생성할 수 있다.

## 배경 암전

전체 화면 가림막은 증강 창의 `ApprovedTheme.MenuBackdrop`(색상 36/39/43, 알파 244/255)으로 통일한다. 가방·제작·장비·상점·공방·기록·결과·설정·전체 지도·일시정지·전체 화면 확인창·보상에 같은 단색을 사용한다. 작은 확인 카드의 바탕과 아이템 선택 강조는 각 역할의 기존 처리를 유지한다.

각 화면의 암전은 한 번만 합성한다. 자체 배경이 있는 화면은 공통 메뉴 암전을 투명하게 하고, 설정 위 전체 화면 확인창은 설정 배경을 잠시 숨긴 뒤 닫을 때 복원한다. 이름 변경처럼 기존 메뉴 위에 뜨는 작은 패널은 피그마의 별도 배경 처리와 질감을 유지한다. 월드 배경과 캐릭터를 교체하거나 흐림 효과를 추가하지 않는다.

## 실제 화면과 시안 적용 범위

이 표의 단위는 일반 플레이에서 열리는 화면/상태다. 독립 테스트의 샘플 화면 수, 소스 파일 수, Build Settings의 씬 수를 실제 적용 완료 수로 세지 않는다. UI 테마 적용과 실제 기능 연결, 화면 검수는 서로 다른 조건이다.

| 진입 경로 | 화면·상태 | 표시 소유자 / 적용 범위 |
|---|---|---|
| 타이틀 → 시작 | 타이틀·시작 연출 | `WellTitlePresentation`·`SketchTitleScene`·`SketchTitleBlend`. 반반 구도를 유지한 채 바로 1.2초 암전을 거쳐 시작한다. |
| 첫 마을 방문 | 오프닝 대사·이동 시연·조사 수첩 | `TemporaryGameGui.Opening`·`OpeningGuide`. 공용 대화 테마와 팀의 실제 사건/시연/수첩을 함께 사용한다. 수첩 페이지를 Figma 정적 시안으로 교체한 상태는 아니다. |
| 마을 건물 상호작용 | 공방·해금·긴 설명·기록 보관소 | `TemporaryGameGui.Hub`·`InkRecord`. 승인 테마와 실제 영구 성장/기록 연결. |
| 조작 다시 보기 / 첫 전투 안내 | 조작 시연·공격/보상 안내 페이지 | `FirstRunTutorialWindow`·`ControlsWindow`. 팀의 픽셀 시연과 페이지를 유지하며 고정 메뉴 키와 현재 행동 키를 표시한다. 일반 설정의 조작 목록과 별도 화면이다. |
| 가방 | 스케치·잉크·제작·장비·빈 상태·확정/거절 | `ApprovedCore`. 실제 SketchEquipment 경로에 승인된 가방·제작·장비 흐름을 연결한다. 확정 무기의 빈 칸 추가 적용은 막고, N 이름 변경은 실제 무기 ID에 별칭을 저장한다. |
| 보상 기회 / 보스 보상 | 후보 선택·즉시 획득·가방 비교 | `SketchRewardChoiceScreen`·`SketchRunBinding`. 실제 후보와 보상 소비 연결. |
| 정비소 | 월드 진열 상품·가격·구매 불가·품절·장인 인사 | `MaintenanceShelfDisplay`·`WorldShop`·`MaintenanceRoomPresentation`. 상품 앞에서 직접 구매한다. 장인 상호작용은 짧은 대사만 표시하고 상점 탭은 열지 않는다. |
| 증강 획득 | 보스/봉인 증강 후보·선택 완료 | `AugmentRewardChoice`·`TemporaryGameGui.Augment`. 실제 후보/효과와 승인 테마 연결. |
| 정비소 첫 대화 | 포탈 사용 수첩 | `MaintenanceRoomPresentation`·`PortalNotebookView`. 팀의 종이 수첩·실제 포탈 동작 시연 유지. |

### 일반 플레이 교체 대상과 구형 경로 구분

`TemporaryGameGui.DiscoverChapter`와 2챕터 연결은 기존 월드·상점·결과·보상·지도 컨트롤러의 `ExternalPresentation`을 켜서 같은 화면이 두 번 그려지는 것을 막는다. 해당 OnGUI 코드가 남아 있다는 사실만으로 일반 플레이에서 구형 UI가 보인다고 판단하지 않는다. 종료 시에는 소유한 외부 표시/입력 설정을 반환한다.

`SketchEquipment`가 없는 구형 Inventory/WeaponGrowth 경로, 명시적으로 주입된 별도 View 프리팹, 훈련/개발 도구는 유지한다. `RoseBlueBoss.unity`는 Build Settings에 포함돼 있지만 일반 챕터 진행 목적지가 아니라 별도 보스 시험 씬이며 페이즈 선택 UI를 유지한다. `TemporaryGameGui.Story.PlayStory`의 구형 정지화면 이야기는 현재 호출부가 없고 첫 방문은 `StartOpening`으로 진행한다. 이 화면들을 승인 메뉴로 임의 대체하거나 삭제하지 않는다.

### 적용 완료와 구분해야 하는 항목

- 이벤트 방 4종은 아래의 실제 기능 미연결 제한을 따른다. 무기 이름 변경은 실제 런에 연결되어 있다.
- 승인 시안에 없는 화면은 기존 기능과 표시를 유지한다. 신규 디자인 필요 여부와 기존 표시의 기능 오류를 구분한다.
- 주요 메뉴의 960×540·1280×720·1920×1080 캡처 및 입력 검사는 전체 화면/모든 상태/모든 화면비의 검수를 대신하지 않는다. 특히 팀 수첩의 모든 페이지, 개발 도구, 비 16:9 환경과 Windows 배포 빌드의 일반 속도 플레이는 별도 확인 대상이다.
- 머지 전 순서: 일반 플레이 진입 경로의 중복/누락 확인 → 긴 설명·빈 목록·잠금·품절·모달 복귀 확인 → 포함할 미연결 기능 확정 → Windows 빌드·저장/재실행 확인. HUD의 디자인 개정은 이 순서와 별도로 보류한다. 타이틀은 위의 채택 스케치 타이틀을 사용한다.

## 레거시 Inventory·WeaponGrowth 경로

이 절은 `SketchEquipment`가 없는 구성에서 사용하는 기존 가방·팔레트·스탬프 경로만 설명한다. 현재 일반 런의 잉크 횟수·미확정 스케치·확정 무기에는 적용하지 않는다.

기존 형태·능력치·특수 잉크의 가방 장착은 기존 정비소 조건을 따른다. 형태·능력치·특수와 `WeaponGrowth` 색상 잉크는 가방 5칸을 함께 쓰며 한 목록에 형태→능력치·색상→특수 순으로 보인다. 소유 모델은 별개이고 보관 한도만 공유한다. 색상 잉크는 가방에서 위치와 관계없이(전투 중 포함) 팔레트 칸(빈칸 또는 바꿀 칸)과 보유 잉크를 고른 뒤 장착·교체 버튼을 눌러야 장착·무료 교체한다(사용자 2026-11-05: 순서는 칸 → 잉크 → 장착이 기본이며 잉크를 먼저 골라도 된다. 칸이나 잉크를 누르는 것만으로는 끼우지 않고, 칸을 자동으로 고르지 않는다. 칸을 고르지 않으면 「장착할 팔레트 칸을 먼저 누르세요.」). 잉크만 골랐을 때 효과 줄은 +0 기준 수치다. 오른쪽 아래 설명은 마지막으로 누른 것을 보여 준다. 장착 중인 팔레트 칸을 누르면 그 잉크의 이름·등급·그 칸 단계 수치·효과를, 가방 잉크를 누르면 그 잉크를 보여 주며, 가방 잉크를 고른 채 장착 칸을 눌러도 선택은 유지되어 이어서 교체할 수 있다(사용자 2026-11-09). 보유 잉크는 두 번 눌러 파괴한다(`InventoryRuntimeHost.TryEquipColor`/`TryDestroyColor`). 가방 잉크를 고르지 않은 채 잉크가 끼워진 팔레트 칸을 누르면 장착 버튼 자리에 「해제」가 보이며, 누르면 무료로 그 잉크를 같은 인스턴스 그대로 가방에 돌려놓고 칸을 비운다(`TryUnequipColor`·`WeaponGrowth.Detach`, 전투 중 포함). 칸의 색과 강화 단계는 유지한다. 가방이 가득 차면 해제 버튼을 끄고 비운 뒤 해제하라고 안내한다. 팔레트 칸은 물방울 색으로 허용 색을 보여주고, 오른쪽 위에 강화 단계(「+0」)를 표시한다. 가방의 무색 칸은 왼쪽 위에 「무색」을 표시한다. 가방이 열린 동안 시뮬레이션과 전투·상호작용 입력을 정지한다. 기존 가방의 장착 잉크는 해제할 수 없다. 가방 아래 안내 줄은 기본으로 색상 잉크 규칙(「색상 잉크 장착·교체·해제는 언제든 무료 · 판매·강화·색 변경은 정비소에서」)을 보이고, 기존(형태·능력치·특수) 잉크를 골랐을 때만 그 고정 규칙(「형태·능력치·특수 잉크는 정비소에서만 장착하며, 장착하면 런이 끝날 때까지 빠지지 않습니다.」)을 보인다. 기존 잉크 동작의 거절·고정 응답은 색상 잉크를 보는 동안 덮어쓰지 않는다. 색상 잉크는 팔레트 관리에서 선택한 무기의 슬롯에 장착·무료 교체·판매할 수 있다. 교체는 `WeaponGrowth.Insert`가 기존 파츠를 같은 인스턴스 ID로 보유 목록에 돌려놓는다. 팔레트 귀속·소멸, 색 변경(런당 2회 공용·남은 횟수 표시), 중복 제한, 강화 한도와 비용은 기존 `WeaponGrowth` 모델을 따른다. 장비 관리의 「무기」·「스킬」 필터와 정비소의 별도 스탬프 탭에서 보유 스탬프를 선택한 무기에 적용한다(빈 칸 무료·종류별 실제 교체 비용·같은 효과 거절, 판매·파괴 없음). 스탬프 탭은 왼쪽에서 현재 형태·스킬과 적용 대상을 고르고 현재→변경 후 미리보기·실제 비용의 적용 버튼을 표시하며, 오른쪽에서 보유 목록과 선택 상세를 읽는다. 적용은 `Chapter1MaintenanceShop.ApplyStamp`가 `RunStash.TryApply`의 검사·결제와 `CombatPlayer.TryReconfigure`의 형태·특수 변경을 함께 처리한다. 1챕터는 가방 잉크를 드롭하지 않는다.

팔레트 관리는 왼쪽 무기 탭·장착 슬롯(잉크 방울과 슬롯 강화 단계 `+N`)·슬롯 강화와 가격·팔레트 미리보기, 오른쪽 색상 필터·스크롤 잉크 격자(5열)·선택 잉크의 방울·이름과 등급 그림 배지·효과(첫 줄에 선택한 슬롯 강화 단계의 실제 값을 「현재 비율 32%」·「현재 수치 15」처럼 굵게 표시한다. 숫자 등급과 「이 칸 +L 적용」은 문장으로 반복하지 않는다. 강화 단계는 잉크가 아닌 칸에 붙고, 등급은 드롭 확률·교체비에만 쓰이며 효과 세기를 바꾸지 않는다)·남은 색 변경 횟수·실행 버튼 넷(장착/교체·색 변경·판매·파괴)으로 구성한다. 반복 목록에 거래 버튼을 붙이지 않는다. 팔레트는 출발 때 무기마다 하나가 정해지므로 보유 팔레트 목록 대신 장착 팔레트의 미리보기를 둔다. 잉크 목록은 실제 인스턴스와 개수로 표시한다. 비용은 현재 경제 모델에서 읽으며 거래 결과가 바뀔 때만 목록을 갱신한다. 버튼으로 보이지 않는 것만 문장으로 적는다(거절 사유). 색상 불일치 안내는 표시하지 않는다. 색 맞는 칸이 모두 같은 단일 잉크로 막혔으면 「같은 잉크는 중복 장착할 수 없습니다」를 표시하며, 호환 검사와 칸 선택·장착 제한은 유지한다. 교체한 잉크는 보유 목록으로 돌아가고, 장착한 잉크의 해제는 가방에서 한다.

## 입력과 수명

- 일반 런: `Tab` 가방, `G` 보상 열기, `M` 지도, 시설 근처 `F` 상호작용. 열린 가방·제작·장비에서는 방향키 선택·탭 이동, `F` 실행, `W/S` 설명 스크롤을 고정하며 Q/E·A/D 탭 단축키는 사용하지 않는다. 상점의 Q/E 탭 전환은 유지한다. 전투 키 변경이 메뉴 키를 바꾸지 않는다.
- `Esc`: 제작 잉크 선택/내용 확인 → 팔레트 → 목록 → 가방 닫기의 한 단계씩 돌아간다. 구매 영수증은 영수증만 닫고, 구매 후 구성에서 나가면 열린 원래 상점으로 돌아온다. 열린 일반 화면이 없으면 일시정지를 토글하며 결과는 Esc로 닫지 않는다.
- 설정의 화면 유지 확인은 `F` 되돌리기·`G` 유지·`Esc` 되돌리기를 사용한다. 이름 입력처럼 별도 입력 범위가 있는 화면은 해당 표시를 따른다.
- 레거시 Inventory 경로의 가방 `E` 장착 등은 그 경로에만 적용한다. 전투 키의 소유권은 `CombatKeyboardBindings`에 있다.
- 지도: 스크롤 또는 +/-로 확대, 드래그로 이동, `C` 현재 위치, `Home` 전체 보기.
- `TemporaryGameGui`가 키를 한 번만 처리한다. 기존 지도·정비소·가방 입력 컴포넌트는 `ExternalInput`일 때 키를 처리하지 않는다.
- `ScreenRouter`/`ScreenView`는 모달의 포커스와 선택 복귀를 관리한다. 가방·지도·정비소·결과 서비스는 각자의 입력/정지 요청을 소유한다. View는 `Time.timeScale`을 쓰지 않는다.
- 모든 uGUI 버튼은 마우스에 반응한다(`ButtonFeel`, 2026-11-05 플레이 「눌리고 있는지 모르겠다」): 올리면 2px 떠오르고, 누르는 동안 1px 내려가며 어두워지고(색 전환 버튼은 자기 색 전환을 쓴다), 버튼 위에서 떼면 2px 짧게 튄다. 확대 없이 정수 픽셀로만 움직인다. 0.2초마다 장면의 켜진 버튼을 찾아 붙이므로 나중에 코드로 만든 버튼과 다른 화면(가방·정비소·2챕터)의 버튼도 같다. 누를 수 없는 버튼은 움직이지 않는다.
- GUI 위의 마우스 누름은 별도 입력 scope로 전투 유출을 차단한다. 해제와 View 종료 시 자기 scope만 반환한다.
- 일반 런 가방·제작·장비·상점·지도·일시정지·결과는 소유한 제어 범위로 시뮬레이션을 정지한다. 메뉴를 열어 둔 시간으로 마지막 공격 적중 이후의 5초 전투 상태 잠금이 진행되지 않는다. UI는 모델의 Tick이나 시간값을 직접 증가시키지 않는다. 입력은 한 프레임에 한 번만 처리해 F/Esc가 다음 단계까지 연속 실행되지 않게 한다.
- 교체된 IMGUI는 `ExternalPresentation`일 때 표시하지 않는다. View 비활성/파괴 시 플래그와 소유한 화면 요청을 해제한다.

- `TemporaryGameGui.FirstRunInk.cs`: 첫 런 잉크 안내의 주인공 말풍선(`MaintenanceBubbleView`)·상단 가방 안내·가방 안 맞는 칸 테두리와 안내 줄. 몬스터·잉크·바닥 테두리·기록은 `ForestCombatV2/Runtime/Chapter1FirstRunInkGuide.cs`.
- `TemporaryGameGui.InkRecord.cs`: 어두운 왼쪽 목록·잠금 미리보기·전체 화면 컷씬·페이드·완독 읽음 상태. 항목은 `data/story/record_stories.json`이 소유하며 책 에셋을 쓰지 않는다.
- `TemporaryGameGui.StationUpdates.cs`: 기록 농가의 새 기록과 우물의 미사용 잉크를 따로 알리는 `!` 표시.
- `PaperGuiSkin.cs`: 재사용 프레임·색상·버튼 상태 표현.
- `PaperGuiButtonStyle.cs`: 선택·비활성 상태의 글자 대비를 통일하는 공통 컴포넌트.
- `InventoryGameBinding.cs`: 기존 세션과 View 연결.

현재 테마의 추가 연결은 보상·증강 선택, 마을 공방의 긴 설명/해금 조건 스크롤, 설정, 결과, 로딩 실패, 봉인 진행·보상 상자, 보스 소개, 공용 대화창, 전체 지도와 기록 보관소다. 전체 지도와 전투 미니맵은 채택 플레이어·시설·번호 포탈 아이콘을 재사용한다. 미니맵 프레임과 가방·일시정지 버튼의 픽셀 그림은 [채택 전투 HUD](combat-hud-approved.md)를 따른다. 최근 팀 오프닝 수첩의 페이지/애니메이션은 유지한다.

시계탑 집행자의 전투 시작 안내는 입장 연출이 끝난 뒤 4초간 표시하고 기존 보스 체력바 아래에 배치한다. 봉인 완료 안내도 4초간 표시하되 보상 상자를 열면 즉시 종료한다. 두 안내의 시간은 전투 시뮬레이션 시계를 따르므로 일시정지 중 숨겼다가 남은 시간 동안 재개한다. 상단 음영은 글자 아래에서 대비를 유지하고 하단에서 자연스럽게 사라지며, 입력을 받지 않는 별도 캔버스(순서 90)에서 기존 게임 GUI(100) 뒤에 그린다. 메뉴 진입·안내 만료 시 음영도 제거한다. 봉인 진행 아이콘은 크기가 다른 현재 페이지도 중심 간격을 유지한다.

포탈의 이동 키 표시는 일시정지·상호작용 차단·플레이어 입력 차단 중 숨기고 조작 복귀 시 연결과 발밑 위치를 다시 확인한다. 인물 대화 말풍선(`MaintenanceBubbleView`)은 승인 분할 프레임 대신 예전 흰 바탕·먹 계단 테두리 말풍선(굵은 Galmuri11 12px, 184px 줄바꿈, 줄 15px)으로 되돌렸다(사용자 2026-11-14, 모든 말풍선). `ApprovedWorldNotice.Interaction`의 분할 프레임은 현재 호출하는 곳이 없다. 원본 PNG와 uGUI용 스프라이트는 유지하고 IMGUI용 색 보정 캐시만 별도로 사용한다. 상단 월드 안내가 표시되는 동안 기존 임시 알림은 하단 중앙에 배치해 문구끼리 겹치지 않게 한다.

기록 보관소의 열기·확인은 고정 F와 게임패드 확인 버튼을 사용하며 월드 상호작용 키 변경을 따르지 않는다. 목록은 방향키로 이동하고 Esc로 닫는다. 상세 페이지는 F와 기존 다음 페이지 입력을 받고 Esc로 목록에 돌아간다. 사용한 입력은 뒤의 게임으로 전달하지 않는다.

로딩 실패의 다시 시도는 실패한 단계에서 이어진다. 장면을 활성화하기 전 불러오기 예외는 같은 불러오기 작업을 다시 실행하고, 활성화된 장면의 준비 상태 조회에서 예외가 발생하면 그 장면을 유지한 채 준비 상태만 다시 확인한다. 이미 소비한 챕터 이동 장비·체력 인계를 재사용하려고 장면을 다시 만들지 않는다. 실패 창에서 타이틀로 돌아가거나 마을에 도착하면 남아 있는 2챕터 인계 예약을 비워 다음 런의 출구가 막히지 않게 한다. 오류가 확인된 실패 창에서는 뒤의 전투 시뮬레이션도 정지한다. 다시 시도할 때는 실패 창이 소유한 정지만 해제하며 다른 메뉴의 정지와 로딩 중 입력 차단은 유지한다.

신규 이벤트 방 4종(잉크 정령 구출·잉크 묘목 생존전·위험 상자방·함정 수집방)은 UI 시안과 독립 테스트의 진행·완료 화면만 있다. 실제 맵의 방 원형·배치와 목표 진행·완료 컨트롤러는 없으며, 독립 테스트의 수치 변경은 실제 런 상태를 읽지 않는다. 기존 봉인 도전·잠긴 상자는 이 범위와 별개로 `IStageGimmickHost`를 통해 1·2챕터 모두 실제 보상까지 연결되어 있다([스테이지 기믹](../../../design/world/stage-gimmicks.md)).

무기 이름 변경은 장비 상세의 N 버튼으로 열며 `SketchArsenal.Rename`이 실제 무기 ID의 `CustomName`에 1~20자 별칭을 저장한다. 가방·장비·장착/보관 목록이 같은 별칭을 읽고, 별칭이 없을 때만 형태 카탈로그 이름을 사용한다. 입력 칸에서 ↓로 저장/취소 행동을 선택한 뒤 F로 실행하며 Esc는 즉시 취소한다. Enter는 저장하지 않고, 입력 중 F는 문자로 유지해 한글 조합과 충돌하지 않는다. 두 행동은 공통 높이의 F/Esc 테두리 키캡을 사용한다. 별칭은 런 상태이며 영구 프로필 저장은 추가하지 않는다. 독립 테스트 화면의 전체 상태 수를 실제 게임 연결 완료 수로 해석하지 않는다.

승인 테마 리소스는 `Deviant/UI/Theme/Resources/ApprovedTheme/`의 manifest와 개별 원본에 연결한다. `ApprovedTheme`가 알파 표시 영역·문양·팔레트 레이어를 적용한다. 별도 독립 테스트 화면은 `ThemePreview`에 유지한다.

레거시 GUI 스프라이트 23개는 `Deviant/TemporaryGUI/Resources/TemporaryGUI/`에 있다. 원본 내보내기는 작업 공간의 `output/gui/temporary-gui-v3`에 보존한다. 이 소규모 GUI PNG는 폴더의 `.gitignore` 예외로 버전 관리 가능하다. 임포터는 해당 폴더만 Point/무압축/FullRect/32 PPU, 패널 4px nine-slice로 설정한다. 기존 이미지 프레임은 2배 PPU 배율을 사용하며, 공통 PaperGuiSkin 프레임은 아래의 네이티브 픽셀 규칙을 따른다. 텍스트는 별도 uGUI Text이며 기존 Galmuri11을 재사용한다. 새 문구·보스 이름의 정적 글리프는 `tools/temporary-gui-preview/update-font-glyphs.py`로 기존 글리프를 보존하며 확장한다. 원본 TTF와 GUID는 바꾸지 않는다.

## 검증

수첩의 화면 배율·고정 닫기 키·공용 글꼴 불변성은 `PortalNotebookLayoutTests`(EditMode), 조사 수첩의 쓰기/그림/페이지 전환은 `NotebookOpeningPresentationTests`(EditMode), 공격 및 장비 안내 5페이지의 이동·닫기·입력 유예는 `FirstRunTutorialTests`(PlayMode)로 확인한다. `KeyboardShortcutSettingsTests`는 변경 키의 저장/재생성과 기본값 복원을 확인한다. 검수 캡처가 전투 카메라를 다른 화면비의 RenderTexture로 전환하면 카메라의 `aspect`도 대상 비율로 설정하고 원복해야 한다. 게임 카메라의 16:9 고정값을 그대로 둔 캡처를 UI 비율 오류로 해석하지 않는다.


현재 인벤토리의 가방·제작·장비는 `Tools/deviant/Approved UI/Verify inventory flow and capture` 또는 `-executeMethod Deviant.Game.Editor.ApprovedCoreVerification.RunInventory`로 검사한다. 명령과 범위는 [검사와 빌드](../../testing/testing.md#가방제작-채택-화면)를 따른다. 상점·설정·보상까지 포함한 전체 연결 검사는 기존 `ApprovedCoreVerification.Run`을 사용한다. Unity 6000.6.5f1의 격리 검증 프로젝트에서 실행하며 `-quit`은 넣지 않는다. 하네스가 종료를 관리한다.

하네스는 메모리 프로필과 실제 Procedural 씬을 사용한다. 실제 모델/버튼으로 6칸 선택, 잉크 10회 획득·예약·해제·확정, 확정 빈 칸 불변, 같은 프레임 입력 중복 방지, 실제 상점 결제·품절·영수증 ID·복귀, 보유 증강, 설정 모달 포커스, 보상/증강 획득과 결과 화면을 검사한다. 검증용 보유 목록·골드·이동은 Editor 하네스에서만 준비하며 제품 실행에 샘플 데이터를 넣지 않는다.

출력은 Git 제외 `outputs/approved-core-verification/`의 `result.json`·`checks.txt`·실패 시 `failure.txt`와 PNG다. 캡처는 검수 대상으로 남기며 자동 검사의 통과가 시안과의 픽셀 일치를 뜻하지 않는다. uGUI는 960×540·1280×720·1920×1080에서 캡처한다. IMGUI 보상 화면은 실제 GameView 합성 프레임을 ScreenCapture로 저장하므로 GameView 렌더링이 가능한 실행 환경이 필요하다.

`TemporaryGuiVerification.Verify`와 `PaperGuiShowcase`는 기존 Inventory/Growth 화면용 검사다. 현재 Sketch 일반 런에 그대로 적용하거나 그 결과로 현재 UI 검증을 대체하지 않는다. 모델 회귀 검사는 `Deviant.Run.Tests`·`Deviant.Inventory.Tests`와 해당 ForestCombatV2 실제 런 테스트를 사용한다.

관련 규칙: [UI·상호작용](../../../design/ui/ui-and-interaction.md), [런 구조](../../../design/run/run-structure.md), [화면 수명과 Back](screen-routing.md), [가방](../../gameplay/equipment/inventory-and-loot.md).

Editor와 모든 플레이어 빌드는 치트 모드 포함 여부와 관계없이 플레이 GUI를 사용한다. 별도의 작업용 인벤토리 전환 버튼은 두지 않으며, 개발용 장비 편집은 [치트 모드](../../tools/debug-menu.md)의 장비·잉크 항목을 사용한다.

플레이 GUI에서는 개발용 맵 재생성·보스 이동 버튼, 포탈 키 안내, 타격 비교 안내의 IMGUI 출력을 숨긴다. 해당 컴포넌트의 게임 동작·단축키·피해 숫자 출력은 유지한다.

실제 최종 합성 화면은 Unity 메뉴 `Tools/deviant/Temporary GUI/Capture paper GUI backbuffer`로 확인한다. Editor 전용 검증 데이터로 타이틀·도면·HUD·가방·정비소·팔레트·지도·일시정지·사망 화면을 순서대로 열고 `outputs/gui-verification/live/`에 저장한다. Game 뷰가 렌더링되는 일반 Editor에서 실행하며, 자동 종료가 필요하면 `-executeMethod Deviant.Game.Editor.PaperGuiShowcase.Capture -paperGuiCapture`를 사용한다. 이 캡처에서는 `-batchmode`를 사용하지 않는다.

레거시 Growth 정비소는 팔레트·성장·스탬프 탭으로 한 종류의 거래만 보여준다. 가격과 실행 버튼을 분리한다. 슬롯 관리 진입은 골드가 없어도 가능하며 실제 강화 버튼에서 비용과 한도를 검사한다. 인벤토리는 반복 종류 라벨 대신 아이콘과 선택 카드(이름·효과·전후 값)를 사용한다. 기존 가방 잉크의 장착은 정비소에서만 활성화하고 해제 버튼은 표시하지 않는다. 색상 잉크는 가방에서 언제든 장착·교체한다.

레거시 바닥 드롭 보상: 임시 잉크는 사망 애니메이션 지연 없이 즉시 생성한다. 골드는 코인으로 바닥에 생성하고 접촉 획득할 때 기존 보상 금액을 한 번만 지갑에 더한다. 잉크와 코인은 서로 가리지 않도록 떨어뜨린다.

현재 씬 기준의 회귀 검사는 잉크 모델·Presenter·정적 폰트, Run/Control, 지도 좌표, 정비소·런·시작 도면·처치 보상·보스·전체 런 테스트를 사용한다. 기존 InventoryBootstrapTests/InventoryIntegrationTests/PixelInventoryIntegrationTests는 제거된 CombatV2Arena 씬, Chapter1FullMapTests는 제거된 Chapter1ForestVer2 씬을 열기 때문에 현재 플레이 검증에 직접 사용할 수 없다. 해당 fixture 이식 전에는 위 GUI 실행 검사로 가방·화면 전환·지도 통합을 확인한다.

도트 잉크 문양은 명암·입자 장식 없는 단색 실루엣으로 표현한다. 원본의 알파 형태를 유지한 흰색 마스크로 임포트하고 uGUI tint로 빨강·노랑·초록·파랑·보라를 입힌다. 슬롯 위쪽의 작은 색상 표시와 필터도 같은 색을 쓴다. 도트 잉크 문양 20종은 "TemporaryGUI/Pixel" 아래 개별 32×32 스프라이트로 둔다. 생성된 부품 아틀라스에서 개별 문양만 내보내며, 게임 화면이나 글자를 잘라 쓰지 않는다. Point 필터·무압축·mipmap 없음으로 표시하고 종류 ID로 연결한다. 원본 아틀라스는 작업 폴더 outputs/gui-art-originals에 보존한다. 공통 프레임은 1px 외곽선·안쪽 밝은 선·계단형 모서리를 코드로 생성하고, 100 PPU 및 1배 PPU 배율로 픽셀 크기를 보존한다.

수첩 화면과 공통 GUI 글씨는 Pretendard(`Deviant/UI/Fonts/Pretendard-Regular.ttf`·`Pretendard-Bold.ttf`, resources `fonts.pretendard`, SIL OFL 1.1)를 쓴다. 맑은 고딕은 Windows 동봉 글꼴이라 게임에 넣어 배포할 수 없어 2026-11-09 데모 검토에서 바꿨다. Pretendard 는 Hinted Smooth로 임포트해 작은 글씨의 획을 화소에 맞춘다. 글씨는 화면 해상도의 960×540 정수배로 다시 그리므로, Editor Game 창을 960×540으로 두고 확대해 보면 흐려 보인다. `Tools/deviant/Hub/Open Approved Starting Village`(루트 `게임_Unity_열기.cmd`)는 Game 창을 「Deviant 1920x1080」으로 맞춘다(플레이 테스트 2026-11-03). Galmuri11의 정적 글리프는 네이티브 12px로 임포트한다. 새 GUI의 본문은 12px, 제목은 24px, 큰 타이틀은 36px로 표시하여 획의 비정수 확대·축소를 피한다. 일반·굵은 글꼴 모두 Point 필터를 사용하며 캔버스는 픽셀 정렬한다.

## 보조 HTML 검토본과 레거시 화면

이 절의 HTML·종이 책·5칸 Inventory/Growth 구성은 해당 보조 검토본과 레거시 분기를 설명한다. 일반 런 가방·제작·장비·상점은 위의 승인 테마 연결을 사용한다. 아래 1챕터 표의 구형 가방/정비소/잉크 배치를 현재 Sketch 경로의 구현 기준으로 사용하지 않는다. HUD·타이틀·월드 기능의 별도 소유 문서는 유지한다.


수첩 GUI의 디자인 검토본은 `resources/ui/journal-preview/preview/index.html`이다. 채택 시안과 부품, 재편집 원본은 같은 리소스 그룹의 색인으로 관리한다. 파일을 브라우저에서 직접 열 수 있다. 1챕터 화면 중 정비소(팔레트·성장·스탬프)·팔레트 관리·보스 제단(보스의 잉크·잉크 선택)·전투 HUD·보스 체력·가방·지도·일시정지·결과는 아래처럼 옮겼다. 일반 타이틀은 `WellTitlePresentation`의 밝은 인간/스케치 잉크가 마주 보는 반반 벌판·중앙 로고·노란 붓펜과 공용 폰트의 시작하기/설정/종료 메뉴를 사용하고, 2챕터 준비 중 안내는 기존 반환 메뉴를 유지한다.

시작 마을 화면(`TemporaryGameGui.Hub.cs`)은 사용자가 확인한 수첩 HTML의 마을 화면 01~07(2026-11-02, `output/gui/journal-preview` 작업 사본)을 같은 그림·글꼴·수치로 옮겼다. 그림은 리소스 `ui.journal-preview`의 `preview/assets/refined/` 13장(종이·책등·제목 탭·버튼 3종·카드·칸·안료·코인·무기 3종)을 배치 계약으로 `Assets/Deviant/TemporaryGUI/Resources/JournalGUI/`에 두고, HTML의 `border-image`처럼 원본 가장자리(버튼 좌우 14px, 카드·닫기 10px, 칸 4px)를 CSS 테두리 폭(9·4·3px)으로 줄여 9분할로 그린다. 둥근 칩·말풍선·자물쇠·닫기 ×·체크·색 원판은 CSS 수치대로 실행 중에 그린다. 글자는 맑은 고딕 보통·굵게(`JournalGUI/JournalFonts`가 `Deviant/UI/Fonts`의 배치 글꼴을 참조)를 HTML 크기(12~24px) 그대로 쓰고, 선형 색 공간에서 어두운 글자가 가늘고 옅게 섞이지 않도록 `JournalGUI/JournalText` 셰이더가 브라우저(sRGB)와 같은 농도로 섞는다. 위치는 HTML 무대 960×540 좌표 그대로다. 1챕터 화면과 `PaperGuiSkin`은 바꾸지 않는다.

버튼·숫자로 이미 보이는 내용을 문장으로 되풀이하지 않는다(구매 성공 문구·남는 안료·시설 설명 줄 없음). HTML이 한 칸으로 보여 주는 연속 공백은 Unity 문구에서도 한 칸이다. HTML 로비의 시설 바로 가기 줄은 미리보기용이라 옮기지 않는다. 마을 화면 캡처는 `StartingVillageCaptureTests.CaptureTheScreensForReview`가 `outputs/hub/capture/`에 960×540·1280×720·1920×1080으로 저장하며, 통합 공방·기록 농가·우물 화면과 보스 처치 뒤 살 수 있는 해금·산 해금·기록을 확인한다. 마을 도면 선택 화면은 만들지 않는다.

지도는 현재 `Chapter1ProceduralMap`의 15개 방 좌표와 연결 구조를 재현한 방향 고정 fixture이며 라이브 런의 seed와 연결되지 않았다. `applyMapSnapshot`에 방과 통로, 방문 ID, 현재 방을 전달하면 실제 실행의 스냅샷을 표시할 수 있다. 방문 전 시설 및 보스 마커는 표시하지 않는다.

브라우저 검증은 `node tools/gui-preview/verify-journal.cjs`로 실행한다. Node 및 playwright 설치가 필요하며 `PLAYWRIGHT_MODULE`, `CHROME_PATH`로 설치 위치를 지정할 수 있다. 검사 캡처는 Git 제외 `outputs/gui-preview/`에 저장한다. Unity 검증이나 실제 게임 서비스 연결을 대신하지 않는다.

팔레트 관리의 「장착된 잉크」 슬롯 클릭은 보유 잉크 선택과 별도의 조회 상태다. 상세란은 실제 장착 파츠와 선택 슬롯의 현재 강화 레벨을 읽으며, 빈 칸·무기 탭 전환·슬롯 강화·장착 직후에도 갱신된다. 장착 조회 중에는 네 잉크 거래 버튼을 끄고 보유 잉크를 선택하면 다시 호환성·비용으로 판정한다. 효과 설명은 별도 마스크/스크롤 영역 안에 두어 긴 문장이 거래 버튼을 덮지 않는다. 장착은 슬롯 먼저·잉크 먼저 둘 다 된다. 슬롯을 고르지 않았거나 고른 슬롯에 맞지 않는 잉크로 「장착」을 누르면 슬롯 고르기 상태가 되어, 그 잉크가 들어갈 수 있는 슬롯만 선택 테두리를 두르고 나머지는 흐리게 하며 「장착할 슬롯을 고르세요」를 띄운다. 맞는 슬롯을 누르면 바로 장착·교체하고, 다른 잉크나 무기 탭을 누르면 취소한다. 팔레트 관리와 가방에서 선택한 슬롯·잉크 칸은 수첩의 활성 칸 그림에 더해 3px 주황 테두리(`SelectionRing`)를 두른다.

가방의 현재 그림은 `ui.inventory-journal-kit`의 800×464 `inventory-base.png`와 분리된 탭/슬롯/닫기 부품이다. `TemporaryGameGui.InventorySkin.cs`는 제공된 `runtime/layout.json` 좌표를 기준으로 두 무기 탭, 형태/특수, 최대 5개 팔레트 칸, 「전체」 탭 하나와 5칸 한 줄의 보관 칸을 배치한다. 종류 필터와 페이지 이동은 두지 않는다. `inventory-base.png`에 그려진 나머지 탭 세 개와 아래 두 줄 칸은 같은 그림의 빈 오른쪽 아래 종이를 잘라 덮는다(`BagPaper`). 원본 그림은 바꾸지 않았다. 이름·잉크·수량·효과·강화 단계는 런 상태에서 표시한다. 긴 설명은 마스크가 있는 스크롤 영역에 표시하며 기존 장착/버리기/파괴/바닥 교환과 Tab/Esc/E 키를 연결한다.

타이틀 진입은 `BuildRoot` 뒤 `InitJournal`을 호출하고 `WellTitlePresentation`을 만든다. 타이틀은 전체 Canvas 아래의 별도 레이어이며, `FitToWorld`가 호출하는 `WellTitlePresentation.FitToCanvas`는 1600×900 기준으로 풍경을 창에 채우고 로고·메뉴는 화면 안에 들어오도록 배율을 맞춘다. 캐릭터와 구름은 가로·세로 배율을 보정해 원본 비율을 유지한다. `SketchTitleScene`은 마을과 같은 구름 애니메이션을 재사용하고, `SketchTitleBlend`의 고정 중앙 경계에서 왼쪽 채색·오른쪽 스케치 원본을 나눈다. 시작 확정은 완전한 암전 후 다음 프레임에 한 번만 실행한다. 플레이 중 네이티브 월드 표시 배율은 유지한다.

정비소의 첫 포탈 대화는 주인공을 다시 부르기, 사용법을 아는지 묻기, 기능 소개, 작별 인사 순서로 짧게 진행하고 `PortalNotebookView`로 연결한다. 기존 마을 잉크 수첩의 종이 원본에 게임의 `ApprovedTraversal` 스프라이트 설치·진입·등장 시연을 재생한다. 위에는 C/V/F 키캡만 놓고 설명은 시연 아래에 모은다. `MaintenanceRoomPresentation.Step.PortalNotebook`이 읽는 동안 제어 범위와 시간 정지를 유지하고, 닫기·사망·씬 종료에서 해당 범위만 반환한다. 포탈 사용 수첩의 글자는 공용 승인 글꼴을 사용해 작은 화면의 비정수 배율에서도 획이 빠지지 않게 한다. 포탈 사용 수첩은 960×540 안전 영역을 화면 크기에 맞춰 연속 확대·축소한다. 사용법의 C/V/F 표시는 실제 탐험 키 변경을 반영하지만, 수첩 닫기는 고정 F/Esc와 게임패드 메뉴 확인/뒤로를 사용한다. 열었던 입력은 0.35초 동안 무시하며 확인 콜백은 한 번만 실행한다. 대사 원본은 `data/story/maintenance_introductions.json`이며 `tools/story/export_maintenance_dialogue.py`로 Unity 사본과 맞춘다.

포탈 지도 표시는 `CombatPlayer.HasPortal(slot)`과 `PortalPosition(slot)`의 설치 완료 상태를 읽는다. 두 지도는 `Resources/RecoveredMapIcons`의 같은 25×25 원본 `portal-1`·`portal-2`를 사용하며 포탈 2의 외곽선·색은 포탈 1과 공유하고 숫자로 구분한다. 별도 13px 원본은 사용하지 않는다. 표시 크기는 미니맵 프레임 좌표 28×28(기존 프레임·HUD 배율 적용), 전체 지도 960 무대에서 25×25로 유지한다. 그림 하단은 실제 설치 위치보다 위에 놓으며 공용 아이콘·범례 규칙은 [채택 전투 HUD](combat-hud-approved.md#지도-공용-픽셀-아이콘)를 따른다. 지형 위에는 이름을 표시하지 않으며 「1번 포탈」「2번 포탈」 설명은 오른쪽 범례에 둔다. 재설치 중 취소는 기존 위치를 유지하고, 완료하면 해당 번호만 옮기며 초기화된 슬롯은 아이콘을 숨긴다.

전투 미니맵은 기존 위치·크기를 유지하며 모서리 ㄱ자 픽셀 프레임을 사용하고 `ApprovedMapGeometry`로 발견한 빈 지형의 밝은 윤곽과 반투명 면을 표시한다. 가로 48유닛(카메라 약 1.5개 폭)을 일정하게 보여 주며 플레이어를 따라간다. 바닥에 선 플레이어보다 위쪽 지형을 더 보여 주도록 시선 중심을 높이의 18%만큼 위로 옮긴다. 현재 위치는 채택 캐릭터 아이콘과 청록 고리, 살아 있는 적은 작은 둥근 산호색 점, 설치된 포탈은 번호 1/2로 표시한다. 시설 아이콘도 채택 원본을 사용한다. 전체 지도 배율과 독립적이고 지형은 발견 상태가 바뀔 때만 다시 구성한다.

공통 메뉴의 일시정지·소리 설정·제작 완료·사망 결과 표시는 [공통 메뉴 표시](../../../design/ui/screens.md#공통-메뉴-표시)를 따른다. `MaintenanceRoomPresentation.TryInteractMerchant`는 재방문 인사 대사를 기존 말풍선으로 표시하고 종료·취소 시 입력 소유권을 반환한다. `CommonMaintenanceShop.TryOpen`은 월드 진열이 활성화된 경우 이 대화만 호출한다. 최초 방문의 안내와 상품 앞 직접 구매는 기존 경로를 유지한다. 최초 안내 후 포탈 수첩으로 이어지는 구간에서는 재방문 인사를 시작하지 않는다.

전투 HUD의 두 무기 사이에는 입력 설정을 따르는 X 키캡을 표시한다. 몬스터 공격 적중 후 5초 동안 X 순서 교환·장착·장비 교체·해제를 막고, HUD 키캡과 인벤토리 슬롯을 흐리게 하며 「전투중이라 변경할 수 없습니다.」를 표시한다. HUD는 첫 무기의 스킬 원과 두 번째 무기 원 사이 간격을 확보해 X 키캡을 중앙에 놓고, 잠금 중에는 키캡 바로 아래에 남은 시간을 n초로 표시한다. 인벤토리가 열린 동안은 기존과 같이 대기가 정지한다. 두 슬롯이 모두 맨손이면 전투 중에도 첫 무기를 장착할 수 있다. 장착 후에는 기존 전투 잠금이 유지되며 추가 장착·교체·해제·X 교환은 막힌다.

제작 확정 모달은 620×354 안전 영역을 가운데 표시한다. 적용 가능한 보유 잉크가 없는 팔레트에서는 「잉크 선택」 버튼과 F 진입을 모두 막는다. 잉크 없이 제작하는 동작은 유지한다.

메뉴 공통 선택은 `ApprovedActionVisual`의 노란 글씨(#D9CB84)를 사용하며 기본 붓칠은 꺼져 있다. 공용 `Tab`은 선택 이벤트를 `ApprovedTabFocus.LateUpdate`에 넘겨 EventSystem 선택 처리 중 화면 재구성을 피한다. 설정은 원래 왼쪽 세로 탭·오른쪽 본문 배치를 유지한다. 탭 ↑/↓로 즉시 전환하고 →로 본문에 진입한다. 본문 CanvasGroup은 탭 포커스에서 alpha .3이며 위/왼쪽 경계는 활성 탭으로 돌아간다(슬라이더 좌우 값 조절 유지). 설정 행 제목은 해당 슬라이더·화살표·키 바인딩에 포커스가 있으면 노란색으로 표시한다. 미적용 화면 변경/화면 복구 확인은 보존한다.

증강은 선택 이름 노랑, 아이콘 63→68 크기의 작은 확대와 선택 카드 아래 F 선택하기를 사용한다. 스케치 보상은 70→76 확대와 같은 노란 이름/선택 버튼을 사용한다. 실제 `SketchRunBinding.TryChooseReward`는 모델 지급 후 영수증 상태를 만들지 않고 자신의 pause를 즉시 갱신한다. 대기 중인 다음 보상은 모델 순서대로 유지한다. 상점 구매와 레거시 보상 경로도 추가 영수증 화면에 진입하지 않는다.

보상 후보는 ←/→로 선택하고 ↑/↓로 선택한 카드의 설명만 스크롤한다(W/S·휠 유지). 증강도 설명이 넘치는 동안 세로 방향키를 스크롤에 사용하고 끝에서는 기존 행동으로 이동한다. 공용 `JournalScroll`의 스크롤바는 생성 시 꺼 두어 방향키 탐색으로 UI를 다시 만들 때 빈 영역에 한 프레임 보이는 현상을 막는다.

받아 둔 보상이 있으면 전투 HUD 중앙 하단에 [G] 보상을 표시한다. 밝은 스케치 맵에서는 글씨와 키캡 테두리를 회색으로, 그 외 맵에서는 흰색으로 표시한다. 보상 기회 증가를 감지하는 기존 게이지 타이밍으로 글씨와 G 키캡의 네모 테두리 외곽 빛을 노란색으로 5초간 함께 점멸하고 이후 빛만 끈다. 보상 창·가방·지도·상점·증강·일시정지 중에는 중복 표시하지 않는다. 표시 버튼도 같은 실제 보상 열기 경로를 호출한다.

공방 방향키는 같은 행으로 제한하지 않고 기존 그리드의 다음 열/행에서 가까운 노드를 찾는다. 기동·경제의 계단 배치와 다른 줄기 선행 노드도 이동할 수 있다. 선행 노드의 F는 그 노드의 원래 줄기를 열며 구매를 직접 실행하지 않는다. 배치·크기·해금 조건은 유지한다.

가방·장비 최상단 탭에 방향키 포커스가 있으면 하위 스케치·잉크 탭의 선택 강조를 끄고, 슬롯·목록·상세 정보·본문 버튼을 30% 밝기의 비활성 영역으로 표시한다. 아래 방향키로 본문에 진입하면 원래 표시와 입력을 복원한다. 상단 탭과 하단 조작 안내는 계속 읽을 수 있다.

정비소 상품 가격은 HUD가 아닌 월드 Canvas에 놓아 안내 컷씬 중에도 유지한다. 상품 받침·아이템보다 앞, 플레이어보다 뒤에 그려 캐릭터와 겹칠 때 가격이 캐릭터를 덮지 않는다. 상세 상품 카드는 기존 HUD 표시를 유지한다. 1챕터 출구의 중앙 상단 「F 2챕터로 이동」 안내 상자는 표시하지 않으며 실제 출구 상호작용은 유지한다.

장비 화면의 무기 해제 버튼과 R 해제 입력은 제공하지 않는다. 장착 슬롯에서 교체를 시작해 무기를 선택한다. 잉크 편집의 칸 비우기 조작과 시스템 내부 장착 해제 처리는 유지한다.

1챕터에서 첫 일반 보상을 G 또는 같은 HUD 경로로 열어 선택을 마치면 같은 중앙 하단에 실제 가방 바인딩 [Tab] 인벤토리를 표시한다. 가방을 열 때까지 유지하고 다른 창이 열린 동안 숨긴다. 이미 가방을 열었던 경우 안내하지 않는다.
