# 1챕터 숲 맵 편집기

메인이 고정한 `resources/`를 받은 뒤 `python3 tools/assets/update_assets.py`로 복원한 `맵 편집기.html`을 브라우저로 엽니다. 원본은 `resources/authoring/map-editor/runtime/맵 편집기.html`과 같은 폴더의 `이전_지형용_편집기.html`이며 Git LFS로 관리합니다. 메인 도구 폴더의 두 HTML은 Git 제외 로컬 배치 사본입니다. 각 HTML에는 필요한 이미지 9장과 코드가 들어 있어 복원 후에는 서버·설치 없이 실행할 수 있습니다. 별도 공유 ZIP·외부 다운로드 경로는 사용하지 않습니다.

사용자는 [안내사항.txt](안내사항.txt)를 읽고 시작합니다. 지형과 배치는 **전체 맵 JSON 저장**으로 저장합니다. 팀원도 같은 고정 resources의 HTML을 복원한 뒤 해당 JSON을 불러옵니다. HTML 파일 자체가 저장 버튼으로 변경되지는 않습니다. 자동 저장은 현재 브라우저에만 남습니다.

## 편집 범위

- 지형: 32px 격자 칠하기·지우기·사각형 채우기/지우기, 1·3·5·9칸 붓.
- 새 지형 타일 자동 연결: 노출 상단은 두꺼운 잎층의 잔디+흙, 옆면·밑면은 흙, 내부는 새 그림과 같은 무늬 없는 짙은 흑갈색입니다. 잔디는 착지선 아래로 겹겹이 내려와 둥근 끝을 감싸며, 돌·뿌리 질감은 가장자리에서 내부로 갈수록 사라집니다.
- 볼록·오목 모서리를 픽셀 단위로 둥글게 연결하고, 한 칸 폭의 천장 끝은 얕은 둥근 끝으로 표시합니다. 지형을 편집하면 주변 연결도 함께 갱신됩니다.
- 고체 발판은 두꺼운 흙층, 통과형은 나무살·뿌리 전용 이미지로 표시합니다. 두 종류 모두 원본 픽셀 크기로 양끝과 중간을 조립합니다.
- 부분 스케치는 새 상단 잎에 종이색 필터를 적용하며 흙 내부와 지형 점유 상태는 유지합니다.
- 발판·보스·상점·몬스터·트램펄린 등 별도 배치 영역 이동·크기 변경·추가·삭제.
- 지형과 배치를 묶은 되돌리기·다시 실행·JSON 저장/불러오기·자동 저장.
- 기존 배치 전용 JSON을 불러오면 현재 지형을 유지하고 배치만 불러오기.

24개 연결 공간의 지형 설계 도구입니다. 보상·잠금 규칙이나 실제 점프·전투를 구현하지 않습니다. 캐릭터는 기존 PNG와 대기 모션 타이밍을 사용한 크기 비교용입니다. JSON이 실제 Unity 씬에 자동 반영되지 않습니다.

## 파일 구성과 재생성

`index.html`은 개발용 템플릿, `editor/`는 UI·지형·배치 편집 소스, `data/`는 기준 맵·추천 배치·타일 연결 규칙으로 메인이 소유합니다. 미디어를 내장한 단일 HTML 원본 두 개는 resources가 소유하며, 일반 사용자는 복원한 `맵 편집기.html`만 열면 됩니다. 이전 지형 JSON은 함께 복원한 이전 지형용 호환판에서 엽니다.

`editor/tile-art.js`는 현재 지형 점유와 5×5 이웃을 읽어 새 256×256 지형 시트 및 512×64 발판 두 장을 조립합니다. 바깥 모서리 64×96px와 안쪽 모서리 128×128px는 잎·뿌리·돌이 연결된 별도 그림이며, 여러 32px 셀에 걸쳐 원본 크기로 표시합니다. 안쪽 모서리의 진입부는 직선 그림과 겹쳐 연결합니다. 내부는 지형 그림과 같은 짙은 흑갈색인 `#241f1d` 단색이고, 뿌리는 가늘어지는 끝과 투명 여백을 통해 내부로 이어집니다. 위가 덮인 천장은 흙 그림을 사용합니다. 한 칸 계단은 큰 안쪽 패치를 생략하며, 더 높은 계단에서도 윗잔디를 안쪽 패치로 덮지 않습니다. 흙 질감은 안쪽으로 갈수록 대표 흙색으로 정리합니다. 모서리 반경은 14px이며, 위쪽에만 연결된 한 칸 끝은 높이 24px·반경 16px로 표시합니다. 이것은 그림의 윤곽 처리이며 편집·JSON의 점유 단위는 32px 사각 격자입니다. Unity 콜라이더를 생성하거나 바꾸지 않습니다.

기존 지형 ID는 복원·편집 모델에 남아 있지만 화면은 새 타일로 그립니다. 재질·32px 좌표·JSON 형식은 유지합니다. 기준 지형 ID는 `A-24-island-combat-20261023`이며 이전 지형과 자동 저장 키를 분리합니다. 이전 지형 편집본은 전용 버튼으로 내려받아 함께 보관한 이전 지형용 편집기에서 엽니다. 상단 풀 9px와 통과형 풀 11px는 착지선 위 장식이며, 발판 아래 64px 그림 때문에 저장된 배치 높이를 바꾸지 않습니다. 지면과 발판은 차분한 이끼색 잔디와 짙은 흑갈색 흙 세트입니다. 모서리 투명 외곽은 실제 노출 벽에만 적용하며, 아래 착지면 속 흙에는 구멍을 만들지 않습니다. 잎도 실제 경계에서 28~40px 안쪽 구간에서는 흙색으로 정리해 짧은 계단 아래에 긴 꼬리가 남지 않습니다. 배경은 큰 줄기·잎 덩어리·수풀을 굵은 도트로 단순화한 2장입니다. 480×270 원본을 3배로 표시하고, 가로 이동 비율은 0.16과 0.52입니다. 청록·청회색·회갈색을 섞어 잔디와 어울리는 어두운 숲 안쪽을 표현합니다. 아트 출처와 해시는 `data/tile-art.json`에 있습니다.

Python 3.9+로 저장소 루트에서 재생성합니다. 외부 패키지는 필요 없습니다. 메인의 `package.py`는 고정 gitlink와 깨끗한 resources 상태를 확인한 뒤 색인·해시가 일치하는 원본 HTML을 읽는 얇은 실행기입니다. 실제 내장 변환은 `resources/tools/build_map_editor.py`가 담당하고 메인의 템플릿·JS·맵 데이터를 명시적으로 읽습니다. `--out`으로 **새 빈 검토 디렉터리**를 지정해야 하며 원본 HTML·로컬 배치 사본·기존 검토 결과는 덮어쓰지 않습니다.

```sh
python tools/chapter1-map-editor/tools/package.py --out "outputs/map-editor-review/맵 편집기.html"
```

새 제작 입력으로 이미지를 모두 교체할 때는 `--assets`에 PNG 9장이 있는 폴더를 지정합니다. `--tile-assets`는 `ground.png`, `solid-platform.png`, `drop-through.png` 3개가 있는 폴더에서 타일만 바꾸고 고정 원본의 배경·캐릭터 6장을 유지합니다. 이 옵션은 새 검토 후보를 만드는 용도이며 일반 실행 준비를 외부 폴더로 대체하지 않습니다.

```sh
python tools/chapter1-map-editor/tools/package.py --tile-assets /path/to/new-sprites --out "outputs/map-editor-art-review/맵 편집기.html"
```

검토 결과를 채택할 때는 resources 작업 브랜치에서 원본·에셋 목록·해시·미디어 내장 LFS 목록을 함께 갱신하고 커밋·push·독립 복원을 확인합니다. 그다음 메인의 배치 계약·gitlink를 갱신합니다. `--zip` 공유 패키징은 지원하지 않습니다. 로컬 검토 출력 생성만으로 원본 교체·기획 승인·Unity 적용이 완료되지 않습니다.

## 검사

Node.js 18+로 저장소 루트에서 실행합니다. 외부 모듈을 설치하지 않습니다.

```sh
node tools/chapter1-map-editor/tools/test_terrain.cjs
node tools/chapter1-map-editor/tools/test_tile_art.cjs
node tools/chapter1-map-editor/tools/test_ui.cjs
node tools/chapter1-map-editor/tools/test_ui.cjs --source
node tools/chapter1-map-editor/tools/test_ui.cjs --html "tools/chapter1-map-editor/이전_지형용_편집기.html" --compat
```

지형 연결·복원·512가지 이웃 배치·JSON 검증과 단일 HTML 및 소스의 편집 이벤트를 검사합니다. 아트 검사는 단색 내부, 모서리 그림의 셀 경계 연속성, 볼록·오목 모서리, 천장 끝, 대각선 편집 후 캐시 갱신, 최소·최대 발판 폭, 착지선과 내장 이미지 규격을 확인합니다. UI 검사는 Node DOM 모의 환경이며 실제 브라우저 렌더·Unity 플레이 검사를 대신하지 않습니다. 브라우저에서는 단일 HTML을 열어 입구의 흙 벽·통과형 발판, 계단형 천장, 지형 칠하기·되돌리기를 확인합니다. 테스트 산출물은 Git 제외 `checks/` 또는 `outputs/`에 둡니다.

## 지형 구성

편집 원본은 `data/relief-layout.json`입니다. 공간마다 지면·천장 윤곽을 따로 정의하며, 연결 길에도 개별 지면 프로필을 둡니다. 긴 나무 데크와 절벽 연결용 짧은 턱을 섞습니다. 일반 전투 8구역마다 폭 14~18유닛·두께 3유닛의 공중 흙섬과 넓은 아래층을 두고, 아래층 6마리·흙섬 위 4마리를 배치합니다. 흙섬은 지형 점유 셀로 생성하여 옆·밑면도 막히는 실제 땅입니다. 섬 밑의 5유닛 통로와 양옆의 4유닛 높이 접근 데크를 확보합니다. `floatingIsland`, `combatDecks`, `encounterGroups`, `platformLayout`이 편집 원본입니다. 정비소 5·13·22번, 상점 7·19번, 엘리트방 12번, 최종보스방 24번을 표시합니다. 서비스·전용 보스/엘리트 전투·보상은 별도 구현 범위입니다.

`node tools/chapter1-map-editor/tools/build_relief.cjs`로 기준 지형·배치를 만들고 `package.py`로 단일 HTML을 갱신합니다. 높이는 원래 발판과 동일한 32px 격자입니다. `test_relief.cjs`는 발판 여유 공간·발 디딤 위치·전투 지면·공간 연결과 간이 점프 궤적의 왕복 경로를 검사합니다. 궤적은 플레이어 이동 원본의 속도·상승/하강 중력과 120Hz를 사용하고, 단일/2단 점프·통과 발판 내려가기를 포함합니다. 몸체 크기와 고체·발판 착지를 검사하지만 Unity 물리 실행 자체는 아닙니다. 복귀 데크 간격은 기본 128px로 두어 2단 점프의 이론 상승 192px에 여유를 둡니다. 흙섬 중심도 진입·복귀 경로 검사 대상입니다.

먼 숲은 밝고 대비가 낮은 청회색, 가까운 줄기는 짙은 회갈색·이끼색입니다. `repeatUnmirrored: true`인 레이어는 좌우반전하지 않고 그대로 반복합니다. 원경 PNG는 양끝의 같은 행 색을 연결하고 근경은 좌우에 24px 투명 여백을 둡니다. 배경 반복 방식은 HTML과 Unity에 함께 적용하며, 24공간 지형은 HTML 편집용 데이터입니다.
