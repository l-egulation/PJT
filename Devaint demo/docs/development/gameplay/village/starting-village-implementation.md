# 시작 마을 → 이야기 → 1챕터 구현 프롬프트

[분야 개요](README.md)

> 장비 성장 이행 범위: 제품 규칙은 [무기 도면·런 잉크 도감](../../../design/equipment/rules.md)을 따른다. 아래 팔레트·스탬프·출발 도면 선택·바닥 아이템 드롭은 현재 구현 설명이며 새 제품 기획이 아니다. 런 도감·무기 잉크 적용·내구도·전투방 3지선다의 구현과 실행 검증은 미완료다.

아래는 새 구현 작업에 그대로 전달하는 실행 지시다. 기획 기준·에셋 준비와 실제 게임 완성을 구분하며, 현재 구현 상태는 [시작 마을](../../../design/world/village/starting-village.md#현재-구현과-목표)을 따른다.

---

너는 Deviant의 시작 마을과 1챕터 연결을 끝까지 구현하는 담당자다. 목표는 **게임 실행 → 시작 마을 → 통합 공방 해금·이야기 → 이정표에서 맨손 출발 → 1챕터 탐험·정비·보스 → 결과 → 마을 귀환**을 실제 빌드에서 플레이 가능하게 만드는 것이다. 아래 A–Z를 순서대로 수행하고, 한 단계의 문서 작성이나 에셋 존재를 전체 기능 완료로 보고하지 마라.

## 반드시 지킬 기준

- 작업 전 실제 브랜치·미커밋 변경·서브모듈 상태를 확인한다. 사용자의 기존 파일을 보존한다. 현행 AGENTS.md와 하위 지침을 따르고, 마을·스케치의 고정 작업 폴더·브랜치 규칙을 임의로 바꾸지 않는다. 지정 폴더를 사용할 수 없으면 정확한 경로와 이유를 알리고 필요한 작업 위치를 확인한다.
- 최신 원격을 fetch하고, 사용자가 승인한 작업 브랜치에서 진행한다. `main`에 직접 push하지 않는다. 기능 단위 커밋 → `glab` MR → 검증 → squash 없는 머지 순서다.
- Unity는 **6000.6.5f1**, 원본 `Packages` 버전만 사용한다. 격리 검증·빌드도 같은 버전이다. 다른 버전으로 낮춰 통과시키지 않는다.
- 원본은 `docs/design/`와 지정 데이터다. `data/combat/roguelite_progression.json`의 효과·ID를 사용하고, 기존 팔레트 개편과 색상/스탬프 규칙을 코드에 맞춰 바꾸지 않는다.
- 해금 가격·마법안료 지급량이 `null`이면 제품 값으로 임의 확정하지 않는다. 필요한 결정을 관련 항목으로 묶어 선택지·추천 근거와 함께 확인한다. 답을 기다리는 동안 독립적인 마을·화면·기본 출발·검증을 진행한다. 거래를 무료로 만들거나 샘플 가격을 제품 저장에 넣지 않는다.
- 기존 무기·캐릭터·몬스터·배경·GUI를 먼저 사용한다. 소스 아트를 덮어쓰거나 새 NPC·색상·무기·엔딩·런 버프를 임의 추가하지 않는다.

## A. 최신 상태와 인수 기준 고정

`git status --short --branch`, `git fetch origin`, `git submodule status`를 확인한다. 원격 변경과 현재 로컬 변경이 겹치면 사용자 변경을 덮어쓰지 않는다. 현재 실행 씬, 실제 클래스·Resources 경로, Unity 설치 버전, 빌드 타깃과 첫 플레이/반복 플레이의 차이를 확인한다.

## B. 명세 읽기

`docs/README.md`, `docs/overview/overview.md`, `run-structure.md`, `story/opening.md`, `starting-village.md`, `systems/roguelite-progression.md`, `systems/ink-blueprint-proposal.md`, `systems/progression-and-economy.md`, `ui-and-interaction.md`, `docs/development/presentation/ui/temporary-gui.md`, `data-pipeline.md`, `testing.md`를 읽는다. 기존 동작과 목표의 충돌은 근거를 남겨 해결하고 미정 수치를 확정값으로 만들지 않는다.

## C. 현재 연결점 확인

현재 타이틀과 `Chapter1Procedural` 진입, `RunFlow`, 두 무기 선택, `WeaponGrowth`, 실제 골드 지갑, 개별 잉크 소유권, 정비소, 보스 클리어, 결과 화면을 찾아 호출 순서를 확인한다. 파일 이름은 예시로 고정하지 말고 최신 코드에서 확인한다. 모델·명령·표현의 경계를 유지한다.

## D. 리소스 복원과 대상 한정 임포트

메인이 고정한 `resources` 커밋을 받는다. `resources/AGENTS.md`, `catalog.json`, 대상 `asset.json`, 시작 마을의 파일/해시·재사용 목록을 확인한다. 필요한 LFS 객체를 내려받고 포인터 텍스트가 아닌 PNG 바이트인지 검사한다. 준비된 마을 건물·작업대·우물·출발 문·도트 문양·인트로 그림·효과를 사용한다.

게임 적용 사본은 `unity/Assets/Deviant/Hub/` 아래 대상 한정 경로로 가져온다. 원본 캔버스·알파·PPU·피벗·프레임 시간은 전달 메타데이터를 따른다. 기존 `.meta`·GUID를 보존하고 새 적용 사본의 `.meta`는 메인 저장소에서 관리한다. 컬러/스케치의 같은 접촉선·실루엣을 실제 화면에서 비교한다. 원본과 미선택 자료를 삭제하지 않는다.

## E. 데이터와 프로필 모델

안정된 프로필 ID·버전, 획득 마법안료, 보스 첫 클리어, 해금 ID, 본 이야기·기록을 모델로 분리한다. UI 인덱스·무기 실행 ID를 영구 콘텐츠 ID로 저장하지 않는다. 알 수 없는 ID·중복 ID·누락 선행·순환·음수 재화·잘못된 가격을 검증한다. 읽기 전용 스냅샷과 명시적 명령을 제공한다.

## F. 저장·복구 경계

프로필 저장과 런 저장을 구분한다. 임시 파일 → 검증 → 원자적 교체를 사용하고 손상·중단 시 마지막 유효 저장을 보존한다. 새 게임·계속하기·프로필 초기화의 의미와 저장 시점을 명세에 맞춘다. 개발 fixture는 별도 저장 영역을 사용해 실제 기록·재화를 건드리지 않는다.

## G. 영구 해금 거래

보스 첫 클리어, 선행 ID, 가격 확정 여부, 잔액, 중복 구매를 실제 명령 실행 시 다시 검사한다. 재화 차감·해금·저장을 같은 거래로 처리한다. 버튼 연타·오래된 UI 콜백·실패·재로드로 이중 차감·이중 해금이 생기지 않게 한다. 가격 미정은 이유를 표시하고 그 거래만 비활성화한다.

## H. 새 런 스냅샷

출발 확정 시 고유 `runId`와 해금 스냅샷을 만든다. 마을의 맨손 출발은 도면을 선택하거나 무기·팔레트를 지급하지 않는다. 기존 칸 수·무색·출발 골드·캐릭터 강화 해금은 스냅샷에 보존하며, 개발용 도면 선택 경로는 기존 두 팔레트 규칙을 유지한다. 무색 해금은 지정된 무기 팔레트의 첫 칸에만 반영하고 나머지 색은 현재 색상 공급 규칙에 따라 시스템이 정한다. 출발 취소로 장비나 재화를 추가 생성하지 않는다.

## I. 출발 지원금

`starting_gold_100`이 있으면 기존 시작 골드에 100G를 더한다. `profileId + runId + unlockId` 지급 영수증을 사용한다. 같은 런 불러오기·씬 재로드·마을 재입장·챕터 이동·F5/개발 리셋·훈련에는 재지급하지 않는다. 지급 실패 시 지갑과 영수증을 함께 복구한다.

## J. 잉크 파괴와 회수 보상

정비소와 인벤토리의 미장착 보유 색상 잉크에 명시적 파괴 명령을 제공한다. 교체로 빠진 이전 파츠는 소멸하지 않고 보관함으로 돌아가므로 파괴 경로를 거치지 않는다. `destroyed_ink_gold_20`이 있으면 서로 다른 실제 파츠 인스턴스마다 20G를 지급한다. 소유권 제거·골드 지급·영수증을 한 번에 확정한다.

판매·칸 색 변경에 따른 해제·바닥 소멸·사망/런 종료 정리·훈련·개발 리셋·롤백에는 지급하지 않는다. 장착 파츠 직접 파괴로 기존 정비 제한을 우회하지 않는다. 기존 판매 수입에 20G를 덧붙이지 않는다.

## K. 시작 마을 씬 조립

기록 농가·우물·장인의 공방·출발 이정표 네 상호작용을 하나의 평지 동선에 배치한다. 공방은 기존 염색공방 그림을 재사용하며 별도 보급소·회수공방 건물과 출발 준비대를 두지 않는다. 기존 원경·지형·담장·식생·주인공을 재사용하고 신규 건물의 발 위치·배율·레이어를 맞춘다. 모든 필수 시설을 기본 이동으로 왕복할 수 있게 한다. 적·전투 보상·숨은 점프 잠금을 두지 않는다. 기존 1챕터 팀 맵은 수정하지 않는다.

## L. 네 지점의 상호작용

F 후보 조회·대상 재검사·상호작용 호스트를 사용한다. 장인의 공방은 보급·팔레트·회수 기능을 같은 화면에서 열고 기능별 해금 조건을 유지한다. 기록 농가는 이야기와 수첩을, 우물은 마을 잉크 사용을, 이정표는 출발을 담당한다. 가까운 표지와 화면 제목·문양으로 역할을 일치시킨다. 여러 시설이 겹칠 때 유효 대상과 입력 소유자가 명확해야 한다.

## M. 공통 작업대 화면

기존 `PaperGuiSkin`·Galmuri·32px 단색 문양을 재사용한다. 보유 마법안료, 선택 항목, 비용·선행·효과·적용 시점을 보여 준다. 잠김·가격 미정·잔액 부족·선행 부족·완료 상태를 글자로 구분한다. ‘두 팔레트 4칸’과 ‘무기 1 첫 칸 무색’의 전후 미리보기를 따로 제공한다. 새 위젯을 반복 항목마다 과도하게 붙이지 않는다.

## N. 입력·포커스·정지 수명

기존 `ScreenRouter`와 `IControlScope`를 사용한다. F/Esc/확인/방향키·패드 포커스 이동, 화면 종료 후 원래 대상 복귀를 연결한다. 클릭이 공격으로 새지 않게 하고 비활성화·씬 언로드·예외에서도 자기 입력/정지 요청만 반환한다. 뷰가 다른 창의 정지를 풀거나 `Time.timeScale`을 직접 바꾸지 않게 한다.

## O. 이야기 시작과 재열람

첫 방문은 [플레이형 오프닝](../../../design/story/opening/opening-playable.md)으로 지워짐·조력자의 희생·첫 각성을 마을 안에서 플레이하고 같은 우물 앞에서 조작을 넘긴다. 반복 런에 같은 안내를 강제하지 않는다. 기존 대화·시퀀스 서비스의 완료/취소/실패를 구분하고, 스킵이 보상 중복이나 사실 누락을 만들지 않게 한다.

예전 정지 이야기 배경과 은인·인간 행정원 그림은 뺀 설정이라 쓰지 않는다. 조력자를 거점 상점 NPC로 재사용하지 않는다.

## P. 이정표 출발 확정

필수 이야기 상태를 검사한 뒤 이정표 F로 맨손 런을 한 번만 생성한다. 기존 시작방 도면 제안과 두 개 선택을 요구하던 출구 잠금은 이 진입에 적용하지 않는다. 맨손 출발은 기존 전투 처리로 [맨손 전용 2타 기본 공격](../../../design/equipment/weapons/rules.md#맨손-기본-공격)을 제공한다. 별도 특수 공격은 없으며 최종 밸런스는 플레이 테스트 대상이다. 훈련·개발용 도면 선택은 마을 출발과 구분한다.

## Q. 기존 팔레트 경로 이행

현재 구현에 남아 있는 엘리트 팔레트 지급·정비소 팔레트 판매·개발용 무기 지급 뒤 팔레트가 누락되는 경로를 최신 시작 팔레트 규칙으로 이행한다. 팔레트는 획득·구매·재제작하지 않는다. 기존 재고·씬·저장·튜토리얼·UI·검증 fixture의 호출부를 함께 확인한다. 남은 경로가 있으면 완료로 표시하지 않는다.

## R. 1챕터 실제 보상과 정비

최신 몬스터·길목·맵·보스·골드 획득·색상 잉크 54종·정비소 규칙을 확인해 현재 동작을 보존한다. 빈칸 장착, 유료 부분 교체, 칸 색 변경과 파츠 반환, 가방 포화, 판매, 파괴의 인스턴스·소유권 경계를 실제 거래로 연결한다. 브라우저 파츠 실험이 본 게임에 이행됐다고 가정하지 않는다. 미정 파츠 효과는 현재 채택 범위와 구분한다.

## S. 마법안료 획득

확정된 지급표가 있을 때만 몬스터 처치·물리 획득/정산과 프로필 지갑을 연결한다. 처치 보상 중복과 개발 리셋 보상 증식을 막는다. 아직 지급량·획득 방식이 미정이면 질문·결정 과정을 거치며, 테스트 공급을 제품 몬스터 보상으로 혼입하지 않는다. 이미 획득한 재화의 사망 유지와 바닥 미획득 보상을 구분한다.

## T. 보스 첫 클리어와 귀환

실제 보스 격파 → 출구 → 결과 → 프로필 첫 클리어·정산 → 시작 마을을 연결한다. 제품의 2챕터 준비 중 안내와 마을 귀환 동선이 서로 덮어쓰지 않게 진입 모드를 명시한다. 사망도 현재 연출·결과 규칙을 거쳐 마을로 돌아가게 한다. 본편 전체 3챕터 완료와 1챕터 클리어를 같은 플래그로 쓰지 않는다.

## U. 미술 합성 검수

960×540을 기준으로 1280×720·1920×1080에서도 확인한다. 기존 게임 화면과 새 마을을 연달아 캡처해 픽셀 크기·선 농도·돌 크기·캐릭터 배율·색감·글자·광원·접지·레이어를 비교한다. 컬러/스케치 전환에서 이중 윤곽·떠 있는 건물·키 컬러 테두리·잘린 알파·흐린 문양을 고친다. 시안 승인과 실행 화면 검수를 구분한다.

## V. 기능·회귀 검사

의미 있는 모델/통합 테스트를 작성한다. 기본/4/5칸 양쪽 적용, 무색 첫 칸만 적용, 맨손 출발 시 도면 제안·출구 잠금 우회와 중복 출발 방지, 개발용 도면 2개 한도, 동일 런 +100G 1회, 실제 잉크 1개 파괴 +20G 1회, 3개면 +60G, 판매/해제/정리/실패/재로드 제외, 이중 구매·손상 저장·잔액 부족·가격 미정·보스 잠금과 입력 scope 수명을 검증한다. 구현을 그대로 복사한 테스트나 파일 존재만 확인한 테스트로 대체하지 않는다.

## W. 실제 플레이 검증

Unity 6000.6.5f1에서 첫 프로필과 진행된 프로필로 모두 확인한다. 타이틀에서 시작해 마을 시설을 왕복하고, 이야기·두 도면 선택을 거쳐 1챕터를 실제 플레이한다. 정비·잉크 파괴·보스·결과·귀환·해금·다음 런 보너스까지 한 흐름으로 확인한다. Editor 검증 주입과 실제 손 플레이를 구분해 기록한다.

## X. Windows 빌드와 패키지 스모크

정확한 Unity 버전·패키지로 Windows 빌드를 만들고 실행한다. 새 설치·저장 재실행·해상도·마우스/키보드·패드·첫 이야기·시설 UI·런 출발·사망 귀환·클리어 해금·보너스 지급을 빌드에서도 확인한다. 씬에서만 되거나 Editor 전용 데이터가 있어야 되는 상태를 제품 완료로 보고하지 않는다. 로그·캡처·빌드는 Git 제외 outputs에 둔다.

## Y. 리소스와 메인 MR

리소스를 수정했다면 LFS·원본·색인·해시·미리보기를 검증해 리소스 MR을 먼저 머지한다. 접근 가능한 확정 외부 SHA를 메인 gitlink에 반영한다. 기능별 구현·호출부·테스트·명세·생성물을 함께 커밋한다. `git diff --cached --submodule=log`와 사용자 변경 미포함을 확인한다. 메인 MR은 검증 근거·실행 환경·미실시 항목을 적고 squash 없이 머지한다. 승인 없이 별도 브랜치의 작업을 섞지 않는다.

## Z. 최종 인수

완성된 플레이 빌드·A–Z 실행 범위·MR 링크·리소스 SHA·확인한 해상도·실행한 테스트·실제 손 플레이 결과·남은 제한을 간결히 전달한다. ‘문서 작성/에셋 생성/Unity 임포트/기능 연결/빌드 실행’의 완료를 각각 구분한다. 가격·스토리 원본·전체 게임 통합 등이 남아 있으면 범위를 정확히 적고 완전 플레이 가능이라고 주장하지 않는다.

장면 선택 창의 **처음부터 전체 플레이 (테스트 저장)** 는 메모리 전용 빈 프로필로 타이틀에서 시작한다. 플레이를 종료하면 기존 프로필로 복원되며 실제 저장 파일은 초기화하지 않는다. 다른 버튼으로 첫 런 귀환·잉크 획득·우물·수첩 장면을 바로 확인할 수 있다.
