## 목적

기존 거래소의 개별 판매 매물, 즉시 구매와 이미 구현된 구매 예약을 별도 기능으로 유지하지 않고 하나의 양방향 가격·시간 우선 주문장으로 재구성한다. 이 문서는 Office Hours에서 비교한 접근, 선택 이유와 기존 구현과의 차이를 보존한다. 현재 규칙은 [거래소·경제 SSOT](../../30-domain/economy/ssot.md), 화면 규칙은 [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md)가 소유한다.

## 문제 정의

현재 백엔드는 매도 지정가에 해당하는 판매 매물과 매수 지정가에 해당하는 구매 예약, 부분 체결, 쌀 escrow, 판매 정산과 구매 물품 수령을 이미 제공한다. 그러나 웹의 `호가 거래`는 여러 품목의 개별 판매 매물만 낮은 가격순으로 보여 주며 매수 호가, 가격대별 잔량, 스프레드와 구매 예약 관리를 노출하지 않는다.

정책에도 구매 주문을 제외한다는 구형 문장과 구매 예약을 확정한 결정이 함께 남아 있고, 가격 단위·구매 수량 상한·가격 수정 우선순위가 문서와 구현 사이에서 일치하지 않는다. 따라서 화면만 양쪽 표로 바꾸는 것이 아니라 주문 유형, 체결 가격, 우선순위, 자산 보관과 전환 정책을 함께 정리해야 한다.

## 확인한 구현 기반

- 판매 등록은 거래 자산을 인벤토리에서 외부 보관하고 낮은 가격·빠른 등록 순으로 부분 체결한다.
- 구매 예약은 수량과 최대 단가에 해당하는 쌀을 확보하고 높은 가격·빠른 등록 순으로 이후 판매 등록과 자동 체결한다.
- 구매 예약 체결 물품은 별도 수령 전까지 외부 보관하고 판매 대금은 수수료 차감 후 정산 우편으로 지급한다.
- 현재 웹은 개별 판매 매물·IOC 성격의 즉시 구매·판매 등록·내 매물·정산·거래 내역만 제공하며 구매 예약 adapter와 UI는 없다.
- 현재 동시 구매 최적화의 잠긴 매물 건너뛰기는 엄격한 가격·시간 우선순위와 충돌한다.

구현 증거와 현재 상태는 [I-01~I-08 작업 색인](../../wiki/06-delivery/tasks/I-marketplace-economy/_index.md), 화면 상태는 [K-13](../../wiki/06-delivery/tasks/K-client-ux/k-13-marketplace-search-price-ui.md)과 [K-14](../../wiki/06-delivery/tasks/K-client-ux/k-14-listing-management-settlement-ui.md)가 소유한다.

## 비교한 접근

### 간편 거래만 유지

기존 구매·판매 탭을 유지하고 구매 예약만 별도 관리 영역에 추가한다. 학습 부담과 구현 변경은 작지만 매수·매도 유동성과 스프레드를 읽을 수 없고 구매 예약이 부가 기능으로 남는다.

### 고급 호가 거래로 완전 전환

첫 화면부터 양방향 depth와 주문 입력을 노출한다. 시장 구조는 가장 명확하지만 방치형 성장 중 부족 재료만 빠르게 사고 싶은 사용자에게 정보와 조작 부담이 크다.

### 간편 거래와 고급 호가 거래 병행 — 선택
거래소를 열 때마다 간편 거래로 시작하고 같은 품목·필터를 유지한 채 화면 안에서 고급 호가 거래로 전환한다. 간편 화면은 가격 보호가 있는 IOC와 지정가 판매를 제공하고, 고급 화면은 양방향 depth를 읽으며 매수·매도 지정가와 IOC를 모두 제출하게 한다. 기존 장비 부족 재료 구매 흐름을 보존하면서 구매 예약을 주문장의 정식 매수 주문으로 승격할 수 있어 선택했다.

## Office Hours에서 확정한 방향

### 주문과 체결

- 간편·고급 화면은 같은 매수·매도 주문 엔진을 사용한다.
- 즉시 구매는 최대 단가, 즉시 판매는 최소 단가를 가진 IOC이며 미체결 잔량을 남기지 않는다.
- 매수·매도 지정가의 미체결 잔량은 8시간 대기한다.
- 체결은 엄격한 가격 우선과 동일 가격의 시간 우선을 지키며, 잠긴 최우선 주문을 건너뛰지 않는다.
- 체결 가격은 먼저 대기한 maker 주문의 가격이다.
- 매수 주문은 본인 매도 주문을 후보에서 제외하고 다른 사용자 주문만 체결한다. 본인 매도 주문만 있으면 매수는 0체결이며, 매도 주문이 본인 매수 주문과 교차하면 새 주문을 거절한다.
- 가격 변경과 수량 증가는 전체 주문의 우선순위를 초기화한다. 수량 감소는 기존 우선순위와 만료 시각을 유지한다.
- 모든 주문은 방향·품목·수량·가격 보호값·예상 체결·지출 또는 정산을 확인한 뒤 제출한다.

### 시장과 주문 화면

이 절은 최초 인터뷰의 화면 제안을 보존한다. 2026-09-11 후속 사용자 요청으로 고급 화면의 표·요약 배치는 [시장 깊이 시각화 결정](../../80-decisions/README.md)과 [UX SSOT](../../30-domain/player/ux/ssot.md#거래소)로 대체됐다.

- 고급 호가 거래는 매수·매도 각 5개 가격대의 가격·잔량·누적량을 표시하고 내 주문 수량을 구분한다.
- 거래소 진입은 항상 간편 화면이며 창을 닫으면 보기 상태를 초기화한다.
- 품목 분류·필터로 탐색한 뒤 한 품목을 선택해 거래한다.
- 최근 체결 10건과 최고 매수·최저 매도·스프레드·최근 체결가를 제공한다.
- 호가 행 선택은 가격만 주문 폼에 채우며 주문 방향·유형·수량을 추정하거나 즉시 실행하지 않는다.
- 서버 상태는 3초 polling과 수동 새로고침으로 갱신하고 실시간 push는 첫 범위에 넣지 않는다.
- 가격 추이의 시간축은 봉의 배열 순서가 아니라 서버가 반환한 `openedAt`과 조회 기간을 비례 배치한다. 사용자는 5분·15분·30분 봉과 캔들·꺾은선 표현을 선택할 수 있고, hover/focus 시 해당 시각·가격·OHLC·거래량을 확인한다.
- 가격 추이는 캔들과 종가 꺾은선을 동시에 표시하고, 봉 간격과 별도로 표시 기간을 선택한다. 시간축은 서버 `from`·`to`·`openedAt` 기준이며 hover/focus에서 시각·OHLC·거래량을 확인한다.

### 가격·수량·수수료

- 주문 가격은 10~999,999쌀의 1쌀 단위 정수다.
- 주문 수량에는 거래소 전용 고정 상한을 두지 않는다.
- 활성 주문은 계정의 전체 품목과 매수·매도를 합해 30개까지 허용한다.
- 같은 사용자·품목·방향·가격의 재주문도 독립 주문과 독립 시간 우선순위를 가진다.
- 판매 수수료는 실제 개별 체결 금액의 10%를 소수점 이하 내림으로 계산하고 모든 판매 대금은 정산함에서 수령한다.
- 주문 등록·수정·취소는 무료이며 계정별 성공한 주문 mutation을 최근 1분 합계 30회로 제한한다.

### 자산 보관과 내역

- 대기 매수는 최대 지출 쌀, 대기 매도는 판매 물품을 서버가 외부 보관한다.
- 사용 가능 쌀과 사용 가능 판매 수량만 주문 입력에 표시한다.
- 대기 매수 체결 물품과 취소·만료 매도 반환 물품은 하나의 거래소 물품 수령함에서 출처를 구분한다.
- 매도 취소는 인벤토리 공간과 무관하게 시장 노출을 즉시 끝내고 남은 물품을 수령함으로 옮긴다.
- 전체 수령은 오래된 건부터 건별 전량 단위로 처리하고 들어가는 건은 수령하며 공간이 부족한 건은 남긴다.
- 종료 주문은 최근 30일을 조회한다.
- 부분·전체 체결, 수령 가능 물품, 받을 정산과 만료는 거래소 배지로 알리고 사용자가 해당 내역을 확인하면 항목별 읽지 않음 상태만 해제한다.

### 품목 동일성과 구현 식별자

재료와 스킬북은 같은 아이템 ID, 보석은 레벨·옵션 종류·실제 옵션 수치가 모두 같아야 하나의 시장 품목이다. 구현 식별자는 canonical key와 프로젝트 고정 namespace에서 생성한 UUIDv5이며, 거래 가능 카탈로그 동기화에서 미리 생성한다. 시장 품목의 표시명·속성은 식별자와 분리하고 거래 당시 표시명 snapshot을 주문·체결·수령 내역에 보존한다.

## 후속 Office Hours에서 확정한 구현 방향

- 매수·매도 주문은 `side`로 구분하는 단일 주문 저장 모델로 전환한다.
- 같은 시장 품목의 등록·IOC·수정·취소·만료와 품목 비활성화는 시장 품목 row 잠금으로 직렬화하고 `SKIP LOCKED`를 사용하지 않는다.
- 5단계 depth는 활성 주문 원본에 대한 동기 SQL 가격대 집계로 시작한다.
- 상태를 바꾼 성공 주문 등록·수정·취소만 append-only 이력에 기록해 최근 1분 30회 제한을 판정하고 30일 보존한다. 검증 실패·멱등 재생·0체결 IOC 실패는 세지 않는다.
- 한 개 이상 체결된 IOC만 종료 주문 내역에 30일 보존하고 0체결 IOC 실패는 공통 command 기록으로 7일 보존한다.
- 체결·물품 수령·판매 정산·주문 만료 읽지 않음은 계정 공용 서버 cursor 네 개로 관리한다. 각 항목의 성공 응답에 포함된 `readThroughEventId`까지 별도 읽음 command로 전진한다.
- 낮은 revision의 늦은 응답은 폐기한다. revision 간격이나 cursor 변경 오류는 선택 시장의 주문장·내 주문과 개인 거래소 요약을 전체 재조회하고 복구 중 주문 폼을 비활성화한다.
- 개별·전체 물품 수령은 `createdAt, deliveryId` 순서로 행 잠금하며 기존 구매·판매 반환 delivery를 합치지 않고 행 단위로 이관한다.
- 시장 품목 비활성화는 새 거래를 즉시 막고 `거래 중단·취소 처리 중`을 표시한 뒤 worker가 bounded batch로 주문을 취소·반환한다.

세부 근거와 명시적으로 수용한 비용은 [거래소 주문장 아키텍처 결정](../../80-decisions/architecture/market-order-book.md)이 소유한다.

## 기존 결정과 구현의 전환

- 구형 개별 판매 매물 정책과 구매 주문 제외 문장은 양방향 주문장 결정으로 대체한다.
- 기존 활성 판매 주문은 행마다 새 매도 주문으로 옮기고 구형 가격 수정 여부와 관계없이 원래 `createdAt` 우선순위를 유지한다.
- 기존 활성 구매 예약은 새 maker 가격 규칙을 소급 적용하지 않고 취소해 남은 escrow를 반환한다.
- 기존 구매 수령 물품과 판매 취소·만료 반환 물품은 원본 행 참조를 보존해 통합 물품 수령함으로 각각 이관한다.
- 잔량과 escrow·외부 보관이 일치하지 않는 주문은 정상 이관을 막거나 자산을 자동 보전하지 않고 `복구 검토 중`으로 격리한다. 운영자는 원장으로 확인한 자산만 반환하거나 무반환 종료하고 근거·결정자·시각을 감사 기록에 남긴다.
- 구형 개별 매물·즉시 구매·구매 예약 API는 새 주문 계약으로 호출자를 모두 전환한 뒤 제거하며 호환 alias를 남기지 않는다.

## 첫 범위에서 제외

- 시스템 유동성 주문
- 시스템 가격 상·하한, 급변 거래 중단과 자동 가격 보정
- Maker/Taker 차등 수수료
- SSE·WebSocket 실시간 호가 push
- 평균·중앙값 기반 가격 보호
- IOC 미체결 잔량의 자동 지정가 전환
- 비동기 matcher queue와 별도 depth read model

## 남은 미해결

비정상 가격 후보의 기준 가격·배수·기간과 저유동성 예외는 실제 30일 주문·호가·체결 분포를 확인한 뒤 확정한다. 임의 기준으로 주문을 막거나 후보 표식을 만들지 않는다.

## 검증 초점

- 처음 보는 사용자가 간편 거래와 호가창의 차이, IOC와 대기 주문의 차이를 설명할 수 있는가.
- 내 주문이 포함된 공개 잔량과 실제 상대 체결 가능량을 구분하는가.
- 부분 체결 확인에서 가격 범위·가중평균·미체결 잔량을 이해하는가.
- 가격 변경·수량 증감이 우선순위와 만료에 미치는 차이를 이해하는가.
- 동시 주문에서도 maker 가격과 엄격한 가격·시간 우선순위가 깨지지 않는가.
- 인벤토리가 가득 찬 상태에서도 주문 취소가 즉시 시장 노출을 끝내고 반환 자산을 보존하는가.

구체 완료 기준과 증거는 연결된 I·J·K 작업 문서에서 관리한다.
