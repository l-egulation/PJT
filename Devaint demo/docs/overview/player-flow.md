# 플레이와 화면의 연결 흐름

[분야 개요](README.md)

전체 경험을 읽기 위한 연결 문서다. 확정 흐름과 아직 결정하지 않은 전환을 구분한다. 상세 규칙은 [런 구조](../design/run/run-structure.md), [초반 이야기](../design/story/opening/opening.md), [전투 명세](../design/combat/rules.md)가 기준이다.

## 첫 플레이의 이야기

| 순서 | 플레이어가 겪는 일 | 의도·확정 조건 | 적용 상태 |
|---|---|---|---|
| 1 | 마을로 가는 길을 지나감(마을 왼쪽, 오프닝 전용) | 이동·점프·대시 튜토리얼, 로그라이트 시설은 아직 안 보임 | 시작 마을에서 플레이 |
| 2 | 지워짐에 쫓겨 마을로 도망치다 우물 앞에서 쓰러짐 | 이길 수 없는 추격, 재난 제시 | 시작 마을에서 플레이 |
| 3 | 조력자가 몸의 잉크를 희생하고 첫 각성 | 같은 우물 앞, 회귀 예고 | 시작 마을에서 플레이 |
| 4 | 잉크 몸으로 마을 기능을 익히고 출발 | 상호작용과 먹빗자루 맨손 공격 튜토리얼 뒤 이정표에서 맨손으로 출발. 런에서도 A로 [맨손 전용 2타 기본 공격](../design/equipment/weapons/rules.md#맨손-기본-공격)을 사용한다. 최종 밸런스는 플레이 테스트 대상이다. 현재 무기 공격과 스킬 키는 첫 런의 [첫 런 수첩](../design/story/tutorials/first-run-guide.md#첫-런-수첩)이 알려 준다. 이 수첩은 새 도면·도감·무기 잉크 적용 규칙에 맞춘 재설계 대상이다 | 시작 마을에서 플레이 |
| 5 | 첫 사망 뒤 우물 앞에서 다시 깨어남 | 회귀를 처음 겪음 | 시작 마을에서 플레이 |
| 6 | 챕터를 처음 깰 때마다 마을 잉크 하나를 얻는다. 런이 끝나 마을로 돌아오면 색이 단계적으로 돌아오고 마을 장인이 통합 공방의 새 기능을 소개 | 영구 해금 동기. 1챕터 출구는 늘 2챕터로 이어지고, 런은 사망하거나 마지막 챕터(지금은 2챕터)를 깨야 끝난다(2026-11-13) | 1, 2챕터에서 플레이 |

상세 연출·튜토리얼과 구현 범위는 [플레이형 오프닝](../design/story/opening/opening-playable.md)을 따른다. NPC 대화·순차 연출의 기술 연결은 [대화 구현](../development/presentation/narrative/narrative-dialogue.md)과 [시퀀스 구현](../development/presentation/narrative/sequence-execution.md)을 따른다.

## 런 안에서의 흐름

1챕터 플레이 빌드는 [런 구조의 1챕터 기준](../design/run/run-structure.md#1챕터-플레이-빌드-기준)을 따른다.

마을에서 맨손으로 출발한다. 몬스터를 잡으면 보상 게이지가 차고, 한 칸이 찰 때마다 보상을 받아 둔다. 받아 둔 보상을 열면 전투가 멈추고 무기·잉크 후보 셋 중 하나를 고른다. 이벤트 방은 클리어할 때 바로 고른다. [런 보상](../design/run/rewards.md)

도감의 잉크로 무기의 팔레트를 확정하고 장착하거나 가방에 보관한다. 빈 팔레트도 확정할 수 있다. [스케치 무기](../design/equipment/sketch-weapons.md)

보스 처치 후 출구로 나가면 같은 런으로 다음 챕터로 이어진다. 처음 깬 챕터면 마을 잉크를 하나 기록한다. 현재 빌드는 2챕터가 마지막이라 2챕터를 깨면 결과 정산 뒤 마을로 돌아오고, 다음 런은 1챕터부터 시작한다. 체력 0이면 사망 결과에서 마을로 돌아간다.

정비·획득·보상은 전체 제품 흐름에 필요한 연결 지점이며 위 흐름의 구현 상태는 [기획·구현 현황](project-status.md)에서 구분한다. 챕터 안의 일반 전투 맵 8개를 독립 방 또는 적 전멸 잠금 구간으로 바꾸지 않는다. 챕터 경계를 넘으면 이전 챕터로 돌아갈 수 없다.

## 현재 시험 환경의 화면 흐름

| 진입·입력 | 현재 동작 | 구분할 점 |
|---|---|---|
| 공통 씬 Play | 숲·공통 전투·HUD 조립 | 전체 런 시작 흐름 아님 |
| F1 | 개발용 장비 패널 | 실제 소유 재고·보상 화면 아님 |
| F2 | 판정·디버그 표시 | 제품 HUD 확정 기능 아님 |
| ESC | 대화상자 닫기 또는 일시정지 전환 | HUD의 소유권 규칙 적용 |
| 가방 버튼 | 안내·요청 이벤트, 입력 제한 | 실제 15칸 재고 편집 미연결 |
| R | 시험 상태 리셋 | 저장·보상·새 런 제품 처리 아님 |

공격 키는 문서별 차이가 있어 [입력 불일치](open-questions.md)를 먼저 확인한다.

## 전환을 구현하기 전에 결정할 내용

각 전환은 시작 조건, 입력 제한, 정지 여부, 카메라·화면 전환, 완료·취소·실패 결과, 유지·정리할 상태를 정해야 한다. 대화 완료를 자동 보상 지급이나 퀘스트 완료로 간주하지 않는다. 아직 없는 메뉴·저장·보상 정책은 연결 문서를 작성하면서 임의로 확정하지 않는다.
