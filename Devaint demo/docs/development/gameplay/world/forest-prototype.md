## 들판 테스트 전체 지도

전투 중에는 좌측 상단 조작 안내 아래에 260×154px 미니맵을 표시한다. 동일한 지형 텍스처를 재사용하고 약 2880px 폭의 주변 지형·구간 번호·카메라 범위와 청록색 플레이어 표시를 그린다. 플레이어 위치는 매 프레임 따라가며 맵 가장자리에서는 이동 범위를 제한한다. 전체 지도의 확대·이동 상태와 독립적이고 전투 시간이나 입력을 차단하지 않는다. M 전체 지도에서는 숨기며 닫으면 다시 표시한다. F3 구간 선택은 미니맵 아래에 펼친다.

기존 들판과 ver2의 `ForestCombatWorld`는 `Chapter1FullMap`을 연결한다. M으로 전체 지도 열기/닫기, Esc 닫기, 휠·+/− 확대/축소, 마우스 드래그 이동, C 현재 위치, Home 전체 보기를 사용한다. 지도는 실제 `ForestWorld.json`의 지면 점유·발판으로 생성한 씬당 한 장의 텍스처를 재사용하며, 별도 카메라나 매 프레임 지형 탐색을 사용하지 않는다. 플레이어 위치·구간 번호와 카메라 범위를 위에 표시한다. 줌은 전체 보기의 1~16배이며 지도 밖으로 화면을 잃지 않도록 이동을 제한한다.

지도는 자기 `IControlScope`로 전투·상호작용과 시뮬레이션을 막는다. 닫기·비활성화·씬 종료는 자기 범위만 반환하고 다른 창의 정지를 유지한다. 지도 클릭은 배치 도구로 전달하지 않는다. 제품용 미니맵·탐험 안개·맵 해금·저장 정책은 이 테스트 도구의 범위가 아니다.

`Assets/Deviant/World`는 공통 게임의 숲 지형·카메라·몬스터 아트를 담당한다. 실행 씬과 담당 영역은 [코드 구조](../../architecture/architecture.md)를 따른다. 별도 숲 플레이어·체력·타격 시스템은 사용하지 않는다.

## 청크와 배경

[InkForestWorld](../../../../unity/Assets/Deviant/World/Scripts/InkForestWorld.cs)는 `followTarget`의 현재 청크 기준 이전 1개부터 이후 2개까지 가로64unit 청크를 유지한다. 음수 청크는 생성하지 않으며 범위를 벗어난 청크는 비활성화해 재사용한다. 지형은 청크 번호를8로 나눈 나머지로 선택하므로512unit마다 반복한다. 정식 챕터 생성·진행·저장 규칙은 아니다.

`World/Contracts`의 `StreamingWindow`는 변경할 수 없는 청크 배치 계획이며 `World/Runtime/Application`의 `RepeatingStripPlanner`가 기존 선택 규칙을 실행한다. 입력은 대상 X와 폭/템플릿 수/앞뒤 보유 수이고, 결과는 물리 청크 인덱스·참조 템플릿 인덱스·월드 X·원본 X다. 0번과 8번 청크는 같은 템플릿을 참조해도 서로 다른 물리 배치다. 같은 청크 안에서는 계획을 재사용하며 뷰 재활용이 이전 계획을 바꾸지 않는다.

InkForestWorld는 기존 순수 창 계획을 공통 IChapterLayoutProvider→WorldAssembler→ChapterSession의 로드/반환으로 적용한다. ForestLayoutSource가 실제 타일 셀·충돌 설정·Composite 구성·one-way 박스를 고정하며 런타임 뷰와 격리 검증이 같은 원본을 사용한다. 0/8 청크는 서로 다른 절대 ID와 같은 템플릿 참조를 갖는다. 기존 64unit 창·풀·512 반복·배치/테마는 유지하고 이전 별도 생성 경로로 대체하지 않는다.

숲의 공통 ChapterSession은 world 수명이고 GameSession의 follow/구독 lease와 별개다. 사망/개발 reset은 지형/레이아웃 ID를 유지한다. 이동 변경은 같은 기하에서 실제 프로필로 재검증하며 맵을 재생성하지 않는다. 원본 기하 변경은 레이아웃을 종료하고 모든 실패 관측자에 통지해 기존 combat 활성 검사로 자동/수동 진행을 막은 뒤 뷰를 반환한다. 현재 증명은 작성된 기술 이동 witness와 반복 접합부이며 정식 챕터 범위·필수 목적지/보상/전환을 확정하지 않는다.

실제 Game의 이동 적용은 명시적 ICombatMovementValidation 하나로 전체 후보의 같은 숲 증명을 미리 준비한다. 준비 중 중첩 Apply/Reset/Step을 막고 세션/원본/프로필/바인딩을 다시 검사한다. 불가능하거나 성공 transaction이 없는 후보는 Movement·전투 reset·이전 증명·로드 ID를 변경하기 전에 false/error로 거부한다. 수락된 proof와 Movement를 콜백 없는 경계에서 확정한 뒤 기존 reset을 한 번 수행하며 rebound 때 같은 증명을 다시 실행하지 않는다. 수락 후 reset 관측자의 예외는 기존 부분 reset 계약을 유지하며 롤백을 꾸며내지 않는다.

`ChunkPopulated` 이벤트와 기존 청크 방문 함수로 공통 게임이 지형 콜라이더에 `ArenaSurface`를 연결한다. 일방향 발판에는 `oneWay`를 지정한다. 청크가 재사용되어도 같은 공통 이동·내려가기 규칙을 적용한다. 테마를 바꾸면 타일과 패럴랙스 스프라이트를 다시 적용한다. 원경·중경·전경은 서로 다른 수평 이동률을 사용한다.

Chapter1 시험 씬 `Assets/MeadowDuskV3/Scenes/Chapter1MeadowCombat.unity`의 지형 표현은 [Chapter1 둥근 지형 연결](../../../../tools/chapter1-rounded-terrain/README.md)을 사용한다. HTML 편집기와 같은 렌더러로 현재 Unity의 8구간 점유 데이터를 구워 둥근 외곽·오목 연결·단색 흙 내부와 목재 통과 발판을 배치한다. 배경은 낮은 채도의 숲 내부 `forest_depth`와 가까운 나무·수풀 `forest_near` 두 레이어이며 `ForestWorld.json`의 `layers`에 이동·크기 설정을 둔다. 잔디는 낮은 채도의 이끼색, 내부는 같은 아트 팔레트의 짙은 흑갈색이다. 배경은 480×270의 큰 도트 군집을 정수 3배로 표시하고 큰 줄기·수풀과 0.16/0.52 이동률로 가까운 숲을 표현한다. 모서리 투명 외곽은 실제 노출 벽에만 적용하며 아래 지면 내부에는 구멍을 만들지 않는다. 깊은 내부의 잎·뿌리 조각은 흙색으로 이어진다. 원래 지형 사각형과 통과 발판 충돌은 유지하며 곡면은 시각 표현이다. 지형 배치가 변경되면 재생성해야 한다. HTML의 24공간 확장 배치를 이 씬에 이식한 것은 아니다.

## 카메라

랜덤 스테이지 `Chapter1Procedural`은 `ForestCombatWorld.cameraVerticalOffsetPixels`를 150px(4.6875unit)로 설정해 추적 중심을 위로 올리고 캐릭터를 화면 중앙보다 아래에 둔다. Inspector의 **Camera Vertical Offset Pixels**로 조정한다. 양수는 위쪽을 더 보여주며, 화면 크기는 960×540으로 유지한다. 초기 배치·추적·리셋은 같은 오프셋을 사용하고 낙하 선행 추적과 맵 경계 제한은 계속 적용한다. 다른 들판 씬은 기본값 0을 사용한다. 낙하 추적 검사는 화면 구도 오프셋의 적용과 중립 구도에서의 추적 지연을 별도로 확인한다.

[InkForestCamera](../../../../unity/Assets/Deviant/World/Scripts/InkForestCamera.cs)는 공통 플레이어의 `Transform`에서 기본 추적 위치를 계산한다. 수평은 비대칭 데드존, 수직은 지형·플레이어 높이를 기준으로 지수 보간한다. 리셋의 `SnapToTarget()`은 기본 위치를 즉시 정렬한다. 씬의 PixelPerfectCamera는 PPU32·기준 해상도640×360을 사용한다. HUD Canvas 기준 해상도와는 별개다.

실제 카메라 Transform은 `Presentation/Unity/CameraOutputBinding` 한 곳에서 적용한다. 숲 카메라와 시험장 `CombatArena`는 기존 추적 계산을 기본 위치 공급자로 연결하며 같은 카메라에 기본 공급자를 둘 이상 등록하면 거부한다. `CombatArena.CameraRequests`와 숲 카메라의 `Requests`는 그 카메라의 같은 `ICameraRequests`를 제공한다. 최종 위치 적용 뒤 패럴랙스를 갱신한다.

`CameraDirector`는 소유자 스코프의 위치 요청을 우선순위로 선택한다. 같은 우선순위는 나중 요청 순번을 선택하며, 실제 대화/연출/모달의 우선순위 값은 아직 정하지 않는다. 가려진 기본 추적 상태는 계속 갱신된다. 요청 완료/취소 시 예전 Transform을 복원하지 않고 남은 소스 또는 최신 기본 위치를 다시 읽는다. 기본 추적 리셋도 다른 소유자의 구도를 해제하지 않는다. 소스 실패는 해당 핸들을 `Failed`로 종료하고 남은 요청으로 돌아간다. 소유자 스코프/개별 핸들은 자기 요청만 반환한다.

출력 컴포넌트/계층의 비활성화와 파괴는 그 출력의 요청 세션을 닫는다. 모든 기존 핸들은 취소되고 캐시한 `ICameraRequests`는 새 요청을 받지 않는다. 재활성화 뒤에는 `Requests`를 다시 얻어 새 세션에 바인딩한다. `Camera.enabled` 등 카메라 가용성 유실은 다음 `ApplyNow` 또는 `Requests` 조회에서 확인하며, 관측 사이에 끝난 일시적 카메라 토글까지 추적하지 않는다. 기본 추적 공급자의 수명은 요청 세션과 별도여서 출력이 꺼진 동안도 현재 위치를 제출할 수 있고, 재활성화 뒤 최신 기본 구도를 적용한다. 과거 요청 위치를 기준 위치로 다시 캡처하지 않는다. 입력/정지·다른 카메라의 요청이나 렌즈 설정은 변경하지 않는다.

소스 조회 콜백이 출력을 비활성화/재활성화하거나 파괴하면 이전 세션의 프레임 쓰기·후속 관측 콜백을 중단한다. 요청 반환은 진행 중 조회가 끝난 뒤 처리해 순수 실행기를 재진입하지 않는다. 적용 후 관측 콜백의 종료는 이미 적용한 위치를 되돌리지 않고 세션을 닫는다.

`ChapterCameraSource`는 `ChapterWorldHost`의 세션 ID/의미 있는 앵커를 조회해 월드 위치에 바인딩 오프셋을 적용한다. 종료된 챕터/재사용된 뷰의 앵커를 옛 카메라 요청에 자동 연결하지 않는다. 실제 대화 구도는 아직 콘텐츠로 연결하지 않았다. 현재 요청은 위치만 지원하며 렌즈/PixelPerfectCamera 설정·줌·흔들림·블렌드·카메라 영역 정책은 이행하지 않았다. 전투/입력/시간 제어 권한도 갖지 않는다.

## 몬스터 표현

들판 시험 씬 `Assets/MeadowDuskV3/Scenes/Chapter1MeadowCombat.unity`는 `ForestCombatV2/Chapter1MonsterPresentation`과 `Chapter1MonstersV4.asset`으로 ZIP v4의 들쥐·두더지·멧돼지·허수아비·짚단·두레박 모션을 재생한다. 미채택 개구리 배치와 전용 정지 이미지는 사용하지 않는다. 두더지는 첫 공터에 추가한 테스트 배치다. 기존 `TestEnemy`의 임시 AI·HP·공격 판정은 유지하며, 6종의 행동 명세를 구현한 것으로 취급하지 않는다.

`python tools/combat/restore_chapter1_monster_sheets.py "C:/Downloads/F109-chapter1-monsters-6species-v4-20261019.zip"`으로 원본 25개 시트를 복원한다. ZIP 전체와 내부 파일 해시, 시트와 개별 프레임의 픽셀 일치를 검사한다. Unity 메뉴 `Tools > Deviant > Meadow Dusk > Apply Six Monster Sprite Sheets`는 시트를 128×128·PPU32·Point·무압축·피벗(0.5, 0.0625)으로 자르고 현재 씬에 연결한다. 이미지 내용과 캐릭터 모션·지형·카메라를 재생성하지 않는다.

이동은 원본 프리뷰 시간으로 반복하고, 대기는 별도 클립이 있는 들쥐만 반복한다. 나머지는 이동 첫 프레임으로 대기한다. 공격 그림은 기존 테스트 공격의 전체 시간에 맞춰 재생하며 피해 타이밍을 변경하지 않는다. 기본 피격은 실제 경직 종료까지 0.30초 동안 피격 자세를 유지하고, 사망은 한 번 재생한 뒤 숨기며 리셋 시 복원한다. 최종 종별 전투 타임라인과의 연결은 별도 작업이다. `-verifyChapter1Monsters <출력 폴더>` 인자로 Editor Play를 실행하면 실제 액터의 이동·공격·피격·사망·리셋과 플레이어 2단 점프를 검사하고 `outputs/`에 화면과 결과를 저장할 수 있다.

[InkMonsterMotion](../../../../unity/Assets/Deviant/World/Monsters/Scripts/InkMonsterMotion.cs)은 제작 모션과 방향을 재생한다. 공통 게임의 [ForestEnemyPresentation](../../../../unity/Assets/Deviant/Game/Runtime/ForestEnemyPresentation.cs)이 공통 적 상태를 읽어 이동·공격·사망 모션과 피격 점멸을 표시한다. 사망 클립이 없으면 회전·하강·압축·페이드한다. 리셋하면 외형을 복원한다. 표현 어댑터는 피해·공격 타이밍·물리 시간을 변경하지 않는다.

[MonsterHealthDisplay](../../../../unity/Assets/Deviant/World/Monsters/Scripts/MonsterHealthDisplay.cs)는 공통 `CombatActor`의 HP를 읽고 중첩된 적의 체력바 높이를 조정한다. 적 AI·피해·고정 피격 영역은 [전투 구현](../combat/combat.md)과 [공통 명세](../../../design/combat/rules.md)를 따른다. 모션별 피격 박스와 별도 숲 무적 시간을 사용하지 않는다.

`InkMonsterData`의 제작용 모션·기하 자료는 유지한다. 전투용 수치 편집 원본은 `data/combat/`이며 제작 자료의 이동속도·공격 수치를 공통 전투에 자동 적용하지 않는다.

먼 숲은 공기 원근법을 반영한 옅은 청회색으로, 가까운 나무는 짙은 회갈색·이끼색으로 구분한다. 두 레이어는 `repeatUnmirrored: true`로 좌우반전 없이 반복한다. 원경 양끝의 행별 색을 연결하고 근경 양옆에는 투명 여백을 둬 대칭 줄기가 생기지 않는다. HTML의 절벽·흙둔덕 배치는 별도 설계 데이터이며 Unity 시험 씬의 8구간 물리 배치는 유지한다.

## HTML ver2 선택 맵

`Assets/MeadowDuskV3/MapVer2/Scenes/Chapter1ForestVer2.unity`는 HTML 편집기의 승인 기본 배치 24공간을 가져온 별도 시험 씬이다. 기본 게임과 기존 8구간 씬에서 화면 오른쪽 아래 `맵 버전`을 눌러 선택하며 같은 버튼으로 돌아온다. 선택 시 현재 전투와 위치를 저장하지 않고 선택한 씬을 새로 시작한다. 기본 빌드의 시작 씬은 기존 deviant 씬이다.

현재 ver2의 편집 원본은 `tools/chapter1-map-editor/data/relief-layout.json`이다. 24개 연결 공간 중 일반 전투 구역은 **2·6·8·9·15·16·18·20번**, 각각 승인 6종을 섞어 10마리씩 총 **80마리**를 배치한다. 각 구역은 아래층 6마리와 공중 흙섬 위 4마리로 구성한다. 멧돼지·짚단 같은 큰 근접 개체는 아래층, 작은 근접과 원거리 개체는 상층에 섞는다. 가장자리에서 최소 3타일 떨어진 완전 지지 위치를 사용하며 짧은 연결턱에는 적을 배치하지 않는다. 몬스터의 점프 길찾기가 없으므로 각 무리는 같은 높이의 넓은 지면에서 싸우도록 구성한다.

지형은 **625개 고체 사각형, 259개 나무 일방향 발판**으로 구성된다. 나무 발판 중 **88개는 폭 10유닛 이상**이다. **공중 흙섬 8개**는 폭 14~18유닛·두께 3유닛이며 아래층에서 높이 8유닛에 놓인다. 밑면은 끝을 좁힌 흙 지형이고, 위·옆·아래 모두 실제 고체 충돌을 가진다. 섬 아래에는 높이 5유닛의 통로를 남기고 양옆의 높이 4유닛 데크에서 2단 점프로 상층에 진입한다. 수직 복귀 데크는 기본 높이 간격 4타일(128px), 폭 9~10유닛이다. 짧은 턱은 절벽 가장자리 연결용으로 남긴다. 이동 수치 원본 `data/combat/locomotion/player.json`을 사용하며, 단일 점프 이론 상승 96px·최적 2단 점프 192px보다 낮은 착지 간격을 둔다. 나무 발판은 아래에서 상승 통과하고 `↓+Space`로 내려갈 수 있다. 흙섬은 옆으로 돌아 오르내린다.

ver2 배치만 비감지 배회를 켠다. 개체별 시드로 0.8~2.8초 대기와 0.5~1.4초 이동을 번갈아 선택하고, 생성 위치의 좌우 1.1unit 이내에서 종별 보행 속도의 45%로 움직인다. 벽·절벽·바닥 지지 검사를 공유하며 감지·속박·기절·경직·AI 정지 시 배회를 중단한다. 감지 이후 공격·추격·복귀와 종별 HP·공격 수치는 기존 정의를 따른다. 경사와 단차를 넘는 몬스터 길찾기는 구현 범위가 아니다.

정비소는 **5·13·22번**, 상점은 **7·19번**, 엘리트 몬스터방은 **12번**, 최종보스방은 **24번**이다. 정비소와 상점에는 일반 몬스터를 배치하지 않는다. 시설/특수방 이름표를 전투 화면과 전체 지도에 표시하고 미니맵에는 색상 마커를 표시한다. 이는 공간 배치 구현이며 구매·강화 서비스, 전용 엘리트/보스 액터·전투·보상·출입 잠금은 구현하지 않았다. 챕터 내부 자유 왕복을 유지한다. F3 목록은 각 공간의 안전한 지면 착지점으로 이동한다.

`node tools/chapter1-map-editor/tools/test_relief.cjs`는 실제 이동 수치와 120Hz 탄도·플레이어 폭/높이·고체 충돌·하강 발판 착지를 사용하는 경로 검사다. 단일/2단 점프 및 내려가기를 포함해 24개 구간의 진입·왕복 경로를 검사하지만 Unity 물리 시뮬레이션 자체는 아니다. Unity `Chapter1MapDesignTests`는 실제 플레이어의 64/128px 발판 착지, 8개 실제 흙섬의 접근 데크→2단 점프→고체 지면 착지, 상·하층 배치, 80마리의 지지·배회·대기·반경·AI 정지·감지 전환을 별도로 검사한다. HTML 자동 저장이나 팀원 JSON 수정본을 자동 동기화하지 않는다.

재생성은 `node tools/chapter1-map-editor/tools/build_relief.cjs`, `node tools/chapter1-map-editor/tools/test_relief.cjs`, `node tools/chapter1-rounded-terrain/import-ver2.cjs` 다음 `node tools/chapter1-rounded-terrain/bake.cjs --ver2`다. 기존 맵의 데이터·씬·아틀라스를 덮어쓰지 않으며 원경과 근경 이미지는 공유한다. Node와 sharp 설치는 지형 재생성 안내를 따른다. 생성된 ver2 아틀라스는 별도 이미지로 승인 드라이브에 게시하고 Git의 에셋 목록을 함께 갱신한다.

손맛 시험 모드의 축소 HUD에서는 미니맵을 우측 상단 154×88px로 표시한다. M 전체 지도와 기존 지도 이동 기능은 유지한다.
