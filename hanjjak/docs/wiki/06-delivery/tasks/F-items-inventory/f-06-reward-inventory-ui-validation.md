# F-06 획득 결과·인벤토리 UI 검증

> 작업 상태와 완료 증거의 SSOT. 도메인 규칙은 [아이템](../../../../30-domain/items/ssot.md)를 따른다.

## 완료 기준

획득 출처, 수량, 거래 가능 여부가 화면에서 식별되고 긴 이름·빈 상태가 깨지지 않는다.

## 선행 작업

F-03, F-04

## 비고

2026-09-11 보유 에셋을 재사용해 인벤토리를 종이 프레임 안의 4열 아이템 격자와 우측 상세 패널 구조로 개편했다. 제목은 `인벤토리`만 표시하고 분류 탭은 장식 아이콘 없이 `전체`, `강화 재료`, `스킬북`, `보석`, `보석함`, `치장 선택 상자` 이름을 사용한다. 재료·스킬북·보석의 로컬 대체 이미지를 연결하고 정렬, 보유 슬롯, 수량, 거래 가능 여부, 획득처·사용처와 보석 잠금 동작을 기존 API 상태로 표시한다. 아이템 진입은 전투 화면과 상태 엔진을 유지한 모달로 연결하고 닫기·바깥 영역·Esc로 전투에 복귀한다. 장비는 공용 200슬롯 인벤토리 항목이 아니라는 [아이템 SSOT](../../../../30-domain/items/ssot.md#아이템-분류와-거래)의 경계를 유지해 이 화면에 임의로 추가하지 않았다. 실제 인증 API와 모바일 브라우저 인수는 남아 있어 진행 중·부분 검증 상태를 유지한다.

2026-09-08 최신 main 통합 후 웹·API·신규 격리 DB 검증은 [F-04 통합 증거](../F-items-inventory/f-04-inventory-query-sort-quantity.md#최신-main-통합-검증)를 따른다. 이번 통합 후 브라우저 인수는 재실행하지 않았으며 아래 브라우저 결과는 통합 전 이력이다.

2026-09-08 실제 서버 연결 데스크톱 인수 추가: 격리 DB `hanjjak_local_verify`와 인증 API에 연결한 화면에서 보석 묶음 선택·칸 잠금/해제, 거래소 등록·회수 후 인벤토리 갱신을 확인했다. 아래 실제 인증 API 미검증 기록은 이전 이력이다. 최신 모바일, 오류·갱신 경합 및 던전 전체 흐름 인수는 남아 상태를 유지한다.

2026-09-08 최신 사용자 승인 반영: 개별 보석 목록·ID·상태 요약과 예약/사용 가능 수량 표시는 제거했다. 선택 칸 수량과 공통 옵션만 표시하고 보석 칸 전체 잠금 버튼을 연결했다. 아래 개별 선택·상태 표시 및 브라우저 증거는 변경 전 이력이며 현재 UI의 인증 API 인수 증거가 아니다.

2026-09-08 목록 후속 구현: 슬롯 ID 기반 선택, 선택 칸과 종류 전체 수량 구분, 보석 묶음의 개별 선택 및 기존 보석 API 기반 잠금·장착 상태 표시를 연결했다. 원본 없는 보석은 상태 미확인으로 표시한다. 분류·정렬·페이지 변경 또는 선택 칸 소멸 시 선택을 해제한다. 아래의 중첩 UI 미구현 기록은 이전 시점 이력이다. 실제 인증 API·DB 연결 인수가 남아 진행 중·부분 검증을 유지한다.

2026-09-08 후속 백엔드 중첩 구현 이후 상태 API의 점유량은 새 계산을 사용한다. 목록은 아직 개별 보석 행과 재료 합계 행을 반환하므로 슬롯별 중첩 표시·그룹 내 개별 선택 구현과 브라우저 검증이 남아 있다. 이번 후속 작업에서는 UI를 변경하거나 브라우저 인수를 수행하지 않았다.

2026-09-08 후속 중첩 정책 승인에 따라 개발을 진행 중으로 전환했다. [아이템 SSOT](../../../../30-domain/items/ssot.md#인벤토리-슬롯과-수량)에 맞는 중첩 목록·수량·점유 슬롯 표시와 그룹 내 개별 보석 선택·상태 식별이 필요하다. 아래 개별 목록 구현과 검증 기록은 이전 기준이며 새 중첩 UI의 완료 증거가 아니다.

화면에 획득처, 총·예약·사용 가능 수량, 거래 가능 여부, 긴 이름 말줄임과 상세 줄바꿈, 빈·로딩·오류 상태를 구현했다. production build는 성공했으나 실제 인증 API를 연결한 브라우저 종단 검증은 남아 있다.

2026-09-08 보석 개별 목록의 instanceId 키와 전투 결과의 지급 건너뜀 알림을 연결했다. 종류별 상세 조회는 합계를 유지한다. 실제 브라우저에서 보석 선택·페이지네이션·알림 접근성은 미검증이므로 부분 검증을 유지한다.

## 증거 링크

- 2026-09-11: `apps/web/src/features/inventory/InventoryScreen.tsx`, `InventoryScreen.css`, `navigationState.ts`, `main.tsx`에서 인벤토리를 전투 화면 위 네이티브 모달로 연결했다. 전투 스테이지 유지, 딤 처리, 우측 상단 닫기, 바깥 영역 선택과 Esc 복귀를 장비·스킬 창과 같은 계약으로 적용했다. 독립 QA의 4열 격자·상세 패널·긴 이름 줄바꿈·재료 대체 이미지·보석 분류와 잠금 상태 변경도 유지한다. 웹 typecheck, 전체 Vitest 50파일 283건, production build를 통과했고 독립 QA에서 X 닫기 후 배경 스테이지 복귀를 확인했다. 실제 인증 API와 모바일 화면은 미검증이다.

- 2026-09-08 최신 main 통합 후 실제 인증 브라우저 `127.0.0.1:5179` 재검증: 같은 옵션 보석 3개 단일 칸, 공통 옵션 1회 표시, 개별 목록·상태 요약 미노출, 칸 전체 잠금의 새로고침 유지·해제, 옥수수 M4 989개 판매 출고·회수 복원 확인. 데스크톱 상세 텍스트 겹침과 브라우저 오류 로그 없음. 신규 격리 DB만 사용했다. [F-04 상세 증거](./f-04-inventory-query-sort-quantity.md#최신-main-통합-검증). 최신 통합 모바일·던전 전체 흐름·갱신 경합은 미검증으로 부분 검증을 유지한다.
- 실제 브라우저 `127.0.0.1:5178`: 같은 옵션 보석 3개가 한 칸에 표시되고 공통 옵션 1회, 개별 보석 목록·상태 요약 미노출 확인. 잠금 저장 후 거래소에 다녀와도 잠금 표시 유지, 해제 후 표시 제거 확인. 데스크톱 스크린샷에서 상세 텍스트 겹침 없음. 기존 아이템 이미지 자산 부재로 대체 글자 표시가 남아 있다.
- 거래소 화면에서 재료 989개 등록 후 아이템 화면에 재료가 사라지고 점유 1칸, 회수 후 989개 및 점유 2칸 복원 확인. 격리 DB에만 V21~V23 적용했으며 기존 `hanjjak` 및 팀 DB는 변경하지 않았다.
