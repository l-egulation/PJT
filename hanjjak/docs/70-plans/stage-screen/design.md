## 목적

사용자가 제공한 스테이지/진행 요구사항·목업과 Office Hours에서 확인한 설계 근거를 보존한다. 현재 정책은 [스테이지 SSOT](../../30-domain/world/ssot.md), [전투 SSOT](../../30-domain/combat/ssot.md), [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md), [계정·저장 SSOT](../../30-domain/player/ssot.md)가 소유하며 세부 계약은 [요구사항](./requirements.md)에 연결한다.

## 문제 정의

이 화면의 핵심은 권장 스펙을 심사하는 것이 아니다. 사용자가 선택 챕터의 해금·클리어·현재·반복 상태를 읽고, 주요 보상·실제 피해 배율·최근 실패를 근거로 입장 또는 반복 대상을 고르는 것이다.

피해 배율은 선택 스테이지의 모든 일반·보스가 공유하는 방어력과 현재 사용자 방어 관통으로 계산한다. 권장 레벨·권장 스펙·내 스펙·성장벽 유형은 화면에서 제거해 입장 조건처럼 오해되는 문제를 막는다.

## 제공 입력에서 확인한 요구

- 선택한 챕터의 스테이지 목록과 클리어·현재·잠금 상태 확인
- 스테이지 선택과 상세 확인
- 현재 관통 기준 실제 피해 적용 퍼센트 확인
- 주요 보상과 최근 실패 원인 확인
- 해금된 스테이지 입장과 반복 대상 설정
- 현재 전투·반복 대상 확인
- 서버가 클리어 결과를 검증하고 다음 스테이지를 자동 해금
- Front 비활성화와 별개로 Backend가 존재·해금·진행 상태를 재검증

## 목업에서 관찰한 입력

- `성심당 · 스테이지 주문서` 화면은 챕터 목표와 총 10개 스테이지를 제시한다.
- 점선 경로 위에 원형 노드가 배치되고 초록 체크, 노란 별, 회색 ×로 서로 다른 상태를 표현한다.
- 선택한 `1-7 · 사라진 튀김소보로`의 상세 패널과 `입장 요청` 동작이 있다.
- 제공 목업의 상세에는 권장 레벨·주요 보상·성장 진단이 있었으나 Office Hours 결정으로 권장 레벨과 성장 진단은 제거한다.
- 색상만으로 상태를 확정할 수 없으므로 실제 UI는 아이콘·텍스트·접근성 이름을 함께 사용한다.
- 목업에는 1-1~1-9만 명시적으로 보이고 10번째 노드는 화면 밖이거나 가려진 것으로 보인다. 실제 구현은 10개 모두 접근 가능해야 한다.

## 메인 전투 화면 UI 시안

[코지 픽셀 메인 화면 시안 v2](./concepts/main-screen-cozy-pixel-v2.png)는 2026-09-09 사용자 요청에 따라 현재 배포 기능을 한 화면에 재배치한 시각 참고 자료다. 좌측 상단 프로필과 하단 캐릭터 메뉴는 사람 얼굴 대신 젓가락 캐릭터의 상단 실루엣을 사용한다. 하단 성장 메뉴는 캐릭터·장비·아이템·스킬·보석을 유지하고, 상단에는 던전·레이드·거래소·랭킹·설정을 배치했다. 중앙 스테이지 패널은 현재 스테이지와 처치 진행도를 중앙에 표시하고, 위쪽에 스테이지 선택·자동 진행·스테이지 반복 조작을 둔다. 전투 기록은 좌측 프로필 아래의 별도 종이 책갈피로 분리하고 우측에는 현재 체류 세션의 획득 누적을 둔다. 이미지 안의 닉네임·재화·스테이지·처치 수·보상·레벨·HP·EXP는 배치 예시일 뿐 고정 이미지 에셋으로 사용하지 않는다. 실제 분해 기준은 [메인 HUD 컴포넌트·에셋 분리 명세](./component-asset-spec.md)를 따른다. 세부 동작과 표시 규칙은 이 이미지가 아니라 [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md)가 소유한다.

2026-09-10 사용자 제공 `젓키 레퍼런스.pptx` 5장은 화면 콘텐츠나 수치가 아니라 공통 색감과 서체의 시각 참고로만 사용한다. 낮 장면의 밝은 크림 종이와 금빛 목재, 초콜릿색 글자, 코랄 조작 강조, 시안 경험치, 초록 상태 표시와 둥글고 굵은 한글 글자 형태를 현재 메인 HUD·거래소·랭킹의 공통 방향으로 반영한다.

## Office Hours에서 비교한 접근

### 독립 스테이지 화면 계획 — 선택

챕터 화면과 스테이지 화면을 각각 독립 계획으로 두고 같은 SSOT를 참조한다. 목록·상세·입장·반복·피해 계산·실패 기록의 계약을 챕터 월드맵 요구와 섞지 않는다.

### 기존 챕터 화면 계획 확장

파일 수는 적지만 월드맵 탐색과 스테이지 전투 전환 계약이 한 계획에 결합된다. 변경 영향과 검증 경계가 흐려져 선택하지 않았다.

### SSOT 직접 확장만 사용

규칙 파일은 적지만 제품 요구·API 후보·근거가 SSOT에 섞인다. SSOT의 단일 책임을 지키기 위해 선택하지 않았다.

## 확정 결정의 출처

이 문서는 Office Hours 논의의 provenance와 검증 질문을 보존한다. 현재 적용 규칙은 아래 책임 문서에서만 읽는다.

- 반복·드롭·콘텐츠 끝 fallback·사이클 적용 시점: [스테이지 SSOT](../../30-domain/world/ssot.md)
- 서버 진행·반복 대상·최근 전투 기록 권한: [계정·저장 SSOT](../../30-domain/player/ssot.md)
- 적 수치와 피해 배율 표시 책임: [스테이지 SSOT](../../30-domain/world/ssot.md), [전투 SSOT](../../30-domain/combat/ssot.md)
- 상세 필드와 상태 표현 책임: [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md)
- 클리어 확정과 해금 경계: [스테이지 SSOT](../../30-domain/world/ssot.md)

Office Hours에서 확인한 제품 의도는 해금·클리어·현재·반복 상태를 읽고 주요 보상·실제 피해 배율·최근 실패를 근거로 입장 또는 반복 대상을 선택하게 하는 것이다. 이 문장은 정책 수치의 정본이 아니라 설계 rationale이다.

## 기존 수치에 미치는 영향

기존 [MVP 적 수치 v1](../../60-content/enemies/mvp-v1.md)은 현재 [스테이지 SSOT](../../30-domain/world/ssot.md)의 공통 적 수치 규칙과 다른 기준으로 작성된 행을 포함한다. 새 규칙은 40스테이지 일반 전투 결과를 바꾸므로 해당 문서의 수치는 재산출 전 `working`이다. 기존 성장벽 실패 원인과 파밍·돌파 구간의 콘텐츠 의도를 보존하는 사건 시뮬레이션이 필요하다.

## 남은 검증

- 피해 퍼센트 하나만 보고 사용자가 관통 효율을 이해하는가.
- 권장 정보 없이 주요 보상·최근 실패만으로 입장/파밍 판단이 가능한가.
- 현재 전투·선택·클리어·잠금·반복 대상을 도움 없이 구분하는가.
- 다음 사이클 적용 예약 상태와 현재 반복 대상을 혼동하지 않는가.
- 16:9·16:10과 최소 창 크기에서 10개 노드와 상세 패널이 읽히는가.
- 공통 방어력으로 재산출한 40스테이지가 기존 성장 속도와 실패 원인을 보존하는가.
