## 책임

아이템 ID·분류·스택·거래 속성·챕터별 누적 재료 세대 풀·세대 간 드롭 비중·획득 결과·인벤토리 수량 처리·보상 원자성을 소유한다. 주력 재료 선택과 세대 안의 계열 비율은 [주력 재료 SSOT](../character/ssot.md), 장비 개별 필드, 보석 성장 규칙과 시장 체결은 각각 [장비 SSOT](./equipment/ssot.md), [보석 SSOT](../gems/ssot.md), [거래소 SSOT](../economy/ssot.md)가 소유한다. 치장 자체와 미등록 중복 재고의 서버 상태·등록·성급은 [치장 SSOT](../cosmetics/ssot.md)가 소유한다.

## 아이템 분류와 거래

스테이지 자동 파밍에서 쌀, 세대별 감자·고구마·옥수수 재료와 스킬북을 획득하고, 전용 보스 던전의 최초 클리어·소탕에서 계정 귀속 보석함을 획득한다. 보석함을 열어 얻은 보석은 거래할 수 있다. 치장 세트 선택 상자는 아이템 인벤토리의 200슬롯 스택 아이템이며, 상자 사용으로 발생하는 치장 지급 결과는 [치장 SSOT](../cosmetics/ssot.md)의 서버 치장 상태로 전환된다. 치장 자체와 미등록 중복 재고는 200슬롯 아이템이 아니며 별도 서버 치장 상태로 관리된다. 주력 재료 선택과 세대 안의 계열 추첨은 [주력 재료 SSOT](../character/ssot.md), 장비 인스턴스는 [장비 SSOT](./equipment/ssot.md), 보석함·보석 옵션·합성은 [보석 SSOT](../gems/ssot.md)를 따른다.

## 챕터별 재료 세대

### 차기 리밸런싱 공급 경계

2026-09-11 승인한 `progression-rebalance-v1`의 1~4장 공급 세대는 현재 세대 풀을 유지하고 1장 수량 판정만 확정 드롭으로 바꾼다.

| 챕터 | 공급 세대 |
| --- | --- |
| 1 | M1 |
| 2 | M1~M2 |
| 3 | M1~M3 |
| 4 | M1~M4 |

5~10장 공급 세대, M5 환산 값과 후속 반복 드롭률·세대 가중치는 unresolved다. 현재 드롭표를 단순 연장해 확정하지 않는다. 1~4장 강화 소비는 [장비 SSOT](./equipment/ssot.md)의 `progression-rebalance-v1` 절을 따른다.

최초 클리어 강화 지원은 해금된 세대까지의 감자·고구마·옥수수를 확정 지급하며 계열 무작위 반복 드롭과 별도다. 수량은 [차기 최초 클리어 콘텐츠](../../60-content/stages/first-clear-rebalance.md)가 소유한다. 최초 보상 재료는 반복 드롭 재료와 같은 거래 가능한 `itemId`·스택에 합산한다.

최초 클리어 시 쌀은 클리어·다음 스테이지 해금과 함께 지갑에 즉시 지급한다. 재료·보석함 아이템 묶음은 전량 수용 가능하면 즉시 지급하고, 공간이 부족하면 클리어·해금·쌀 지급을 유지한 채 전용 최초 보상 수령 대기함에 보존한다. 사용자는 공간을 확보한 뒤 대기 묶음을 전량 원자 수령하며 부분 수령하지 않는다. 신규 최초 클리어와 기존 계정 소급은 `(accountId, stageId, rewardVersion)`의 같은 중복 방지 경계를 사용한다. 기존 클리어 기록에 대한 소급 보상도 같은 거래 가능 속성을 사용하고 계정·버전마다 한 번만 생성한다.



각 계열은 챕터 진행에 따라 상위 세대가 추가되며, 상위 챕터에서도 해금된 이전 세대가 함께 드롭된다.

| 현재 챕터 | 드롭 가능한 세대 |
| --- | --- |
| 1 | M1 |
| 2 | M1, M2 |
| 3 | M1, M2, M3 |
| 4 | M1, M2, M3, M4 |

- 거래소·인벤토리 카탈로그의 등급별 아이템 ID는 `POTATO_M1`~`POTATO_M5`, `SWEET_POTATO_M1`~`SWEET_POTATO_M5`, `CORN_M1`~`CORN_M5`를 사용한다. M1~M5는 순서대로 F·D·C·B·A 등급이며 표시 이름은 `감자 한 조각`·`미니 감자`·`감자`·`황금 감자`·`전설 감자`, `고구마 한 조각`·`미니 고구마`·`고구마`·`황금 고구마`·`전설 고구마`, `옥수수 한 알`·`미니 옥수수`·`옥수수`·`황금 옥수수`·`전설 옥수수`를 사용한다.
- 현재 챕터 1~4 자동 파밍 드롭표는 M1~M4만 공급한다. M5의 자동 파밍 공급처와 장비 소비처는 아직 확정하지 않았으며, 확정 전에는 거래 가능 카탈로그 항목으로만 유지한다.
- 챕터별 세대 간 드롭 비중과 공통 드롭 수치의 working 값은 [MVP 주력 재료 드롭표 v1](../../60-content/items/material-drops-mvp-v1.md)이 소유한다.
- 세대가 선택된 뒤 그 세대 안의 감자·고구마·옥수수 비율은 [주력 재료 SSOT](../character/ssot.md)의 80:10:10을 적용한다.

거래 가능한 아이템은 다음과 같다.

- 세대별 감자·고구마·옥수수 재료
- 스킬별·등급별 스킬북
- 보석

미등록 중복 치장 재고의 거래 가능 범위는 [거래소 SSOT](../economy/ssot.md)와 [치장 SSOT](../cosmetics/ssot.md)가 소유한다. 등록된 치장 외형·등록 수량·성급·도감 상태는 아이템 거래 대상이 아니다. 완성 장비, 보석함과 캐릭터 성장 상태는 거래할 수 없다. `progression-rebalance-v1`의 최초 클리어 재료는 반복 드롭 재료와 같은 거래 가능 속성을 사용한다. 주력 재료 선택과 재료 종류 추첨은 [주력 재료 SSOT](../character/ssot.md), 스킬북의 드롭·강화 소비 규칙은 [스킬 SSOT](../character/skills/ssot.md), 보석의 옵션·합성·던전 공급 규칙은 [보석 SSOT](../gems/ssot.md)가 소유하고 시장 체결은 [거래소 SSOT](../economy/ssot.md)가 소유한다.

## 인벤토리 슬롯과 수량

- 보석은 일반 아이템과 같은 계정 인벤토리 슬롯 한도를 공유한다.
- 보석은 레벨·옵션 종류·옵션 수치가 모두 같은 경우 한 슬롯에 최대 99개까지 중첩한다. 잠금은 슬롯 전체에 적용하며 한 칸에 잠금·미잠금 수량을 섞지 않는다.
- 각 슬롯의 식별자와 소속을 저장한다. 소비 후 다른 칸을 자동 재배열하지 않으며 빈 칸이 되면 해제한다. 신규 지급은 속성과 잠금 상태가 같은 기존 칸의 여유 공간을 먼저 사용한다. 잠금 변경은 다른 칸의 상태나 소속을 바꾸지 않는다. 기존 개별 잠금은 이관 시 상태별 칸으로 분리해 보존하며 용량 초과 시 이관 전체를 거부한다.
- 개별 보석 ID와 프리셋 등록은 내부적으로 유지하지만 인벤토리에서 개별 보석 목록·ID·상태 요약을 표시하지 않는다. 상세에는 선택 칸 수량, 옵션, 설명, 획득처·사용처를 표시하고 잠금은 칸의 잠금 표시와 전체 잠금·해제 조작으로 제공한다.
- 강화 재료는 동일 `itemId`별 한 슬롯에 최대 999개까지 중첩한다. 점유 슬롯은 `ceil(보유 수량 / 999)`이며 상한을 넘는 수량은 추가 슬롯을 사용한다.
- 이번 중첩 상한 결정은 보석과 강화 재료에만 적용한다. 스킬북·보석함·치장 선택 상자의 수치 상한은 별도 결정 전까지 새로 부여하지 않으며 기존 중첩 규칙을 유지한다.
- 보석함은 동일 아이템 수량으로 중첩하며 수량이 1개 이상이면 한 슬롯을 사용하고 0개가 되면 슬롯을 해제한다.
- 아이템을 소비하고 결과를 지급하는 요청은 소비 후 결과까지 반영한 순증가 슬롯을 실행 전에 검사한다.
- 필요한 빈 슬롯이 부족하면 소비·추첨·지급을 시작하지 않고 상태 변경 없이 실패한다.
- 보석 던전 보상처럼 나중에 지급되는 흐름은 도전 시작 전에 필요한 수용량을 검사하고, 기존 보석함 스택 슬롯에 대한 지급 권리 또는 빈 슬롯 하나를 도전 종료까지 예약한다.
- 지급 권리가 예약된 기존 보석함 스택은 도전 종료 전에 수량이 0이 되더라도 해당 슬롯을 다른 아이템이 사용할 수 없으며, 실패·사용자 중단·앱 종료·연결 끊김은 보상 수용량 예약을 해제한다.
- 치장 세트 선택 상자는 `boxItemId`별 동일 아이템 수량으로 중첩되는 200슬롯 아이템이다. 기존 스택이 없을 때 공용 인벤토리 한 슬롯을 사용하고, 상자 자체의 수령·소비·세트 매핑은 [치장 SSOT](../cosmetics/ssot.md)가 소유한다.
- 치장 자체와 미등록 중복 재고는 200슬롯 인벤토리와 분리된 [치장 SSOT](../cosmetics/ssot.md)의 서버 치장 상태이며 일반 아이템 슬롯을 차지하지 않는다.
- 인벤토리는 계정 공용 고정 200슬롯이다. 슬롯 확장은 MVP에서 제공하지 않는다.
- 용량은 개별 수량이 아니라 슬롯 점유량으로 계산한다. 중첩 가능한 아이템은 위 분류별 그룹 기준과 상한으로 슬롯 수를 계산하고, 수량이 0이면 슬롯을 해제한다. 별도 상한이 없는 기존 스택은 양수 수량일 때 1슬롯이며 중첩하지 않는 아이템 인스턴스는 1개당 1슬롯이다. 활성 보상 예약으로 보호되는 슬롯은 수량이 0이어도 예약 종료까지 점유한다.
- 현재 사용량은 점유 중인 슬롯 수이며, 최대 용량은 200, 가득 참은 `usedSlots == maxSlots`이다.
- MVP 아이템 표시 분류는 강화 재료, 스킬북, 보석, 보석함, 치장 선택 상자다. 강화 재료에는 세대별 감자·고구마·옥수수 재료를 포함한다. 주문서와 기타 성장 아이템은 MVP에서 사용하지 않으며, 미래 기능으로 추가할 때 별도 결정과 SSOT 갱신이 필요하다.

## 보유 수량과 거래소 보관

- 목록과 상세 조회의 보유 수량은 인벤토리에 실제로 보관 중인 수량이다. 활성 매도 주문과 거래소 물품 수령함의 외부 보관 수량은 보유량·사용 가능 수량·슬롯 점유량에서 제외하고, 거래소 화면에서 판매 중 또는 수령 대기로 구분한다. 잠금·장착에 따른 소비·판매 가능 여부는 서버가 판정한다.
- 장비 강화·스킬 성장·합성·개봉 등 소비 유스케이스는 클라이언트가 보낸 수량을 잔액으로 신뢰하지 않고 서버가 최신 사용 가능 수량을 검증·차감한다.
- 매도 주문 등록·수정·취소·만료와 구매 체결·물품 수령은 [거래소 SSOT](../economy/ssot.md)의 외부 보관·통합 수령함 흐름을 따른다.

## 용량 초과와 보상 지급

- 보상 지급 전 서버는 보상 결과의 슬롯 수용량을 검사한다. 기존 스택의 남은 한도 안에 합산되는 수량은 추가 슬롯을 요구하지 않으며, 중첩 상한을 넘는 수량은 추가 슬롯이 필요하다.
- 인벤토리가 가득 차면 전투 아이템 지급을 건너뛰고 공간 부족을 알린다. 기존 스택에 합산할 수 있는 아이템도 가득 찬 동안은 지급하지 않는다. 전투·경험치·쌀 보상은 계속 진행한다. 지급 도중 용량에 도달하면 남은 아이템은 지급하지 않으며, 지급 결과에는 실제 지급량과 건너뛴 수량(`skippedQuantity`)을 구분한다. 보유 아이템을 삭제하거나 나중에 소급 지급하지 않는다. 구형 결과 재생 호환용 `discardedQuantity`는 유지하되 신규 결과는 0이다.
- 부분 지급은 보상 command의 원자 처리 범위 안에서 한 번만 확정한다. 재시도는 동일 결과를 반환하며 보상을 다시 지급하지 않는다.
- 보석 던전처럼 보상 수용량을 사전 예약하는 흐름은 기존 예약 규칙을 따른다. 예약된 슬롯 또는 스택 지급 권리는 도전 종료 전까지 다른 아이템이 사용할 수 없다.

## 조회 API 계약

인벤토리 경로는 조회 API만 제공한다. 임의 지급·소비 API는 제공하지 않는다. 보석 칸 잠금은 보석 유스케이스가 소유하고 전투 보상·퀘스트·뽑기·강화·합성·거래소 유스케이스가 서버 권한으로 수량을 변경한다.

### `GET /api/v1/inventory`

- 인증된 사용자 자신의 인벤토리만 조회한다. 선택 query는 `category`, `sort`, `cursor`, `limit`이다.
- `category`는 아이템 표시 분류 필터이고, `sort`는 서버 허용 정렬 키·방향만 받는다. `cursor`는 불투명 페이지 토큰, `limit`은 서버 범위 내 값이다.
- 응답은 `items`, `usedSlots`, `maxSlots`, `isFull`, `nextCursor`를 포함한다. 각 `items` 원소는 위 수량 필드와 아이템 표시 정보, 사용처를 포함한다.
- 존재하지 않는 `category`·정렬 키·잘못된 cursor/limit은 요청 오류로 거부한다. 빈 결과는 성공 응답의 빈 `items`로 반환한다.

### `GET /api/v1/inventory/items/{itemId}`

- 콘텐츠 버전에 존재하는 `itemId`이고 인증 사용자가 접근 가능한 아이템만 조회한다.
- 응답은 아이템 ID·이름·아이콘·종류·설명·획득처·사용처와 총 보유·판매 예약·사용 가능 수량을 포함한다.
- 잘못된 형식은 `INVALID_ITEM_ID`, 존재하지 않는 콘텐츠 아이템은 `ITEM_NOT_FOUND`로 거부한다. 타 사용자 소유 상태를 노출하지 않는다.

### `GET /api/v1/inventory/status`

- 인증된 사용자의 `usedSlots`, `maxSlots`, `isFull`을 반환한다.
- 조회 API는 상태를 변경하지 않는다. 인증되지 않은 요청은 공통 인증 오류로 거부한다.

세부 DTO, 공통 오류 envelope, 인증·재시도 계약은 후속 API 구현 계약에서 확정한다.

## 수량 정합성과 동시성

- 보상·소비·판매 등록·회수·체결의 수량 변경은 단일 원자 command로 기록한다. 수량 검증과 변경 사이에 다른 요청이 끼어들 수 없다.
- 판매 등록과 소비가 동시에 요청되면 먼저 확정된 command 이후의 보유 수량을 기준으로 후속 요청을 판정한다. 잔액이 부족한 요청은 상태를 변경하지 않고 실패한다.
- 모든 상태 변경 command는 idempotency key로 재시도 중복을 막고, 필요하면 최신 인벤토리 상태를 결과에 포함해 클라이언트가 갱신한다.

## 불변 조건

- 보상 지급은 한 전투 결과에 한 번만 적용한다.
- 아이템 ID와 인스턴스 ID를 구분한다.
- 수량 변경은 원자적으로 기록하고, 재시도는 idempotency key로 중복을 막는다.
- 인벤토리 화면은 이 문서의 분류·수량을 표현할 뿐 분류 규칙을 소유하지 않는다.
