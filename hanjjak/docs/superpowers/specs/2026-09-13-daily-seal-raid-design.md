# 일일 공동 봉인 레이드 승인 설계 기록

## 상태

- 승인일: 2026-09-13
- 현재 규칙 정본: [레이드 SSOT](../../30-domain/raid/ssot.md)
- 구현·출시 승인: 아님
- 후속 working 콘텐츠: 보스 절대 수치·기준 빌드·절대 피해 커트라인

이 문서는 승인 과정의 의도, 선택한 구조, 폐기한 대안과 검증 목표를 보존한다. 운영 규칙·상태 전이·수치·보상표는 복제하지 않고 [레이드 SSOT](../../30-domain/raid/ssot.md)를 따른다.

## 문제

공동 보스를 직접 처치하고 즉시 닫는 구조에서는 다음 문제가 생긴다.

- 목표를 일찍 달성하면 늦게 접속한 사용자가 개인 보상 기회를 잃는다.
- 처치 순간 진행 중인 개인 도전을 공동 피해와 순위에 포함할지 결정하기 어렵다.
- 보스가 사라진 뒤 남은 일일 횟수의 의미가 약해진다.
- 서버 인구와 접속 시간대가 개인의 보상 기회를 지나치게 좌우한다.

## 승인된 제품 방향

보스 처치 대신 전체 서버의 **일일 공동 봉인**을 사용한다. 목표를 달성하면 성공 예정 상태만 고정하고 일일 정산 시각까지 개인 도전과 순위 경쟁을 계속한다. 개인 전투의 실제 누적 피해는 등급을 만들고, 확정된 등급은 제한된 공동 봉인 기여로 변환한다.

이 구조의 의도는 다음 세 플레이를 함께 허용하는 것이다.

1. 현재 결과를 확정해 짧게 참여하고 개인 보상을 받는다.
2. 현재 결과를 버릴 위험을 감수하고 같은 보상 슬롯에서 더 높은 등급을 노린다.
3. 공동 목표 달성 뒤에도 최종 정산까지 기여도 순위를 경쟁한다.

## 구조 결정

### 채택: 일일 세션과 명시적 보상 슬롯

전체 서버 일일 세션과 계정별 순차 보상 슬롯을 분리한다. 슬롯은 현재 결과, 시도 횟수와 종료 상태를 명시적으로 소유한다. 이 구조는 다음 경계를 숨은 추론 없이 표현한다.

- 보상 확정 가능 횟수와 실제 도전 시작 횟수의 차이
- 현재 결과만 유효한 재시도
- 전투 중 재시도와 슬롯을 끝내는 무보상 나가기의 차이
- 일일 정산 순간 진행 중·보관·피해 0·미시작 상태의 처리
- 보상 슬롯이 모두 끝난 뒤의 무보상 연습

### 미채택: 일일 공용 카운터

확정 횟수와 총 시도 횟수만 저장하는 방식은 어떤 재시도가 어느 보상 기회에 속하는지, 마지막 결과를 어떻게 보관하는지 불명확해 채택하지 않았다.

### 미채택: 이벤트 재생만으로 현재 상태 계산

모든 명령을 이벤트로 보존하더라도 실시간 봉인 게이지, 현재 슬롯과 TOP 순위를 위해 읽기 상태가 필요하다. MVP 규칙의 직접 표현보다 무거워 현재 구조로 채택하지 않았다.

## 핵심 선택 근거

### 처치 대신 봉인

봉인은 공동 목표 달성과 개인 참여 가능 시간을 분리한다. 목표가 먼저 달성되어도 게이지만 고정되고 모든 사용자는 일일 정산 전까지 남은 보상 슬롯을 사용할 수 있다. 진행 중 도전을 타인이 끝내는 경계도 사라진다.

### 절대 등급과 제한된 공동 기여

개인 등급은 다른 사용자와 비교하지 않는다. 기준 빌드 시뮬레이션에서 만든 절대 피해 커트라인을 사용한다. 공동 봉인에는 등급별 제한된 기여를 반영해 상위 성장 사용자가 전체 목표를 단독 지배하는 정도를 줄이면서도 높은 등급의 효용을 유지한다.

### 현재 결과만 유효한 재시도

최고 결과 자동 보관과 결과 선택은 재시도의 위험을 제거하므로 채택하지 않았다. 새 seed를 얻는 대신 이전 결과를 버리는 선택을 유지한다. 다만 사용자에게 시도 제한을 명확히 보여주고 마지막 결과는 일일 경계까지 보관한다.

### 빠른 복리 강화와 하드 제한

짧은 간격의 공격력·방어력 강화는 최대 HP의 생존 가치와 방어 관통의 후반 피해 가치를 함께 드러낸다. 복리 강화만으로 극단적 생존 빌드의 실행 상한을 보장할 수 없으므로 별도 최대 전투시간을 둔다. 정확한 주기·증가율·제한시간은 [레이드 SSOT의 보스 시간 강화](../../30-domain/raid/ssot.md#보스-시간-강화)가 소유한다.

### 일일 저녁 정산

한국 사용자 다수가 플레이를 시작하는 저녁 시간대에 새 공동 목표와 전일 결과를 함께 제공한다. 정산 시각과 자동 처리 세부 규칙은 [레이드 SSOT의 일일 공동 봉인](../../30-domain/raid/ssot.md#일일-공동-봉인)과 [17:30 자동 처리](../../30-domain/raid/ssot.md#1730-자동-처리)를 따른다.

### 보상 수령권

우편 시스템을 전제로 하지 않는다. 자동 확정 개인 보상과 일일 순위 보상은 서버의 레이드 미수령 보상으로 보존할 수 있다. 공간 부족이 공동 기여와 정산을 취소하지 않되, 혼합 보상 묶음은 부분 지급하지 않는다. 정확한 개인·순위 보상표와 원자성은 [레이드 SSOT의 개인 도전 보상](../../30-domain/raid/ssot.md#개인-도전-보상)과 [일일 순위 보상](../../30-domain/raid/ssot.md#일일-순위-보상)이 소유한다.

## 폐기·대체된 이전안

- 공동 보스 HP를 직접 차감하고 처치 즉시 도전을 닫는 안은 공동 봉인으로 대체했다.
- 처치 후 개인 보상만 계속 지급하는 안은 봉인 목표 달성 후 모든 기여를 최종 순위까지 누적하는 규칙으로 대체했다.
- 자정 초기화 후보는 저녁 일일 정산으로 대체했다.
- 무제한 보상 재시도는 슬롯별 제한 시도로 대체했다.
- 이전 최고 결과 보관과 여러 결과 중 선택은 채택하지 않았다.
- 활성 인원·전날 결과 기반 동적 봉인 목표와 그룹·길드별 보스는 채택하지 않았다.
- 보상 포인트와 확률형 추가 보상은 채택하지 않고 정수 보상표를 사용한다.
- 우편 지급과 보상 전용 임시 인벤토리 슬롯은 채택하지 않았다.

## 후속 콘텐츠 산출

정책 결정이 아니라 시뮬레이션으로 계산해야 하는 항목은 다음과 같다.

- 공동 보스의 콘텐츠 정체성과 프레젠테이션
- 해금 시점 정상 성장 기준 빌드
- 보스 초기 공격력·방어력
- 기준 등급의 절대 피해 커트라인과 전체 등급 고정 정수표
- 레이드·보상 콘텐츠 버전 ID

이 값은 `docs/60-content/raids/`의 working 버전에서 산출하고 검증 후 승격한다. 현재 레이드 정책 SSOT의 승인 상태와 분리한다.

## 검증 목표

### 전투

- 같은 스냅샷·콘텐츠 버전·seed가 같은 종료시각, 누적 피해와 등급을 만든다.
- 보스 강화 경계와 최대 전투시간 경계의 사건 순서가 결정론적이다.
- 기준 빌드가 승인된 확률로 기준 등급을 달성하고 목표 생존시간에 근접한다.
- 같은 투자 규모에서 공격력·최대 HP·방어 관통 부족이 각각 구분 가능한 손실을 만든다.

### 상태 전이

- 슬롯별 시도 상한, 현재 결과 폐기, 마지막 결과 보관과 다음 슬롯 전이가 일관된다.
- 전투 중 재시도와 슬롯 최종 폐기가 다른 상태 전이를 만든다.
- 일일 정산 직전·정확한 경계·직후 요청이 두 세션에 중복 반영되지 않는다.
- 진행 중·보관·피해 0·미시작 슬롯이 정본의 자동 처리와 일치한다.

### 순위와 보상

- 공동 순위와 경쟁 순위 번호, 공개 순위 경계가 일관된다.
- 개인·성공 순위·실패 순위 보상표와 정수화가 정본과 일치한다.
- 혼합 보상 묶음의 수용량 실패는 부분 지급을 만들지 않는다.
- 자동 확정과 수령 command의 재시도·동시 요청이 중복 보상이나 중복 기여를 만들지 않는다.

### 경제

현재 승인 보상은 기존 자동전투와 비교해 큰 공급원이다. 구현 전에 다음을 시뮬레이션한다.

- DAU·참여율·평균 확정 등급별 치장 뽑기 횟수
- 보석함 개봉·합성 후 보석 레벨 분포
- 쌀 공급과 장비·스킬·치장 소비 및 거래소 소각
- 봉인 성공률과 순위 보상 대상 수
- 일일 경계 자동 확정과 미수령 보상 누적량

경제 지표가 기존 성장 시스템을 무력화하면 보상 수치 콘텐츠 버전을 재검토한다. 도전·재시도·봉인 운영 규칙은 별도 사용자 결정 없이 바꾸지 않는다.
