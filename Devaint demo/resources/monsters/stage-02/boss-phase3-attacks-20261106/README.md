# 강화 Blue 3페이즈 공격 제작

3페이즈 네 패턴 몸 동작이 모두 사용자 최종 확정이다: 유도 화살 **D V2**, 튕기는 화살 5연사 **A**, 순차 폭발 화살비 **A-x2**, 확장 광역기 **B4**(`runtime/homing-d-v2/`, `runtime/bounce-a/`, `runtime/rain-a-x2/`, `runtime/fan-final/`). Unity 미적용이다.

확장 광역기: Aether 입력과 영어 프롬프트는 `source/fan-aether/`, 확인 화면은 `preview/fan-input/`이며 결과 원본을 기다린다. 화살비에서 입이 생겼던 만큼 가면 아래쪽 입·콧날·턱 선 금지를 더 분명히 적었다. 사용자가 “갑자기 확대되면서 얼굴도 생긴다”고 해서 프롬프트 v2에 첫 프레임과 같은 크기·구도 고정 단락을 넣었고, 머리 8배 참조는 Aether에 넣지 않도록 했다(v1은 `source/fan-aether/previous/`). 이어서 “광역기인데 더 화려해도 되지 않냐”는 의견으로 v3에서 바닥에서 솟는 마법 바람에 천이 크게 휘날리는 연출, 큰 원호 펼침, 폭풍 움켜쥐기, 세 번 베는 명령으로 바꿨다(v2 보존). 머리·가면·팔 하나·구도 고정은 유지한다. v2·v3 결과(`source/fan-aether-01/`, `source/fan-aether-02/`)를 보고 사용자가 팔 휘적임은 빼고 다른 멋있는 동작을 넣은 새 프롬프트를 요청해 v4로 바꿨다: 큰 원호 펼침 한 번 뒤 팔은 멈추고 천만 휘날림, 천천히 주먹 쥐기, 첫 발사에 한 번 확 펴기, 정지. v3 결과에 그려진 흰 연기·소용돌이 때문에 효과 금지 문장을 강화했다. v4 결과(`source/fan-aether-03/`)는 확대 없이(5연사와 같은 1.04배) 입 없이 나와 생성 가면을 그대로 쓰고 01~31을 정리했다(32~35는 기본 복귀라 제외, 생성된 석궁 반짝이 점과 떨어진 9px 밑창 조각 제거). 06이 0.5초 광역 시작, 19가 2.5초 화살 생성, 25가 3.0초 첫 발사에 오는 타이밍 A/B는 `preview/fan-candidates/`, 확정 회오리 시트·회오리 화살 60개·부채꼴 화살 6개를 게임 계산식대로 함께 그린 화면은 `preview/fan-sim/`. 사용자 검토로 뒷부분(25~31) 편 손을 손목 기준 0.7배로 줄였고(앞부분 손보다 가로세로 약 1.8배 컸다), 외곽 다듬기(1px 가시, 다리 쪽 붕대 혹·밑창 갈고리, 1px 홈, 외딴 점)를 더했다. 줄인 손과 소매 사이 틈은 손목 12px 안에서 손목 피부색으로 이었고, 손금·손 외곽선도 손과 함께 줄여 손바닥 안 구멍이 생기지 않게 했다. B의 빠른 분출은 살리고 뒤쪽이 끊긴다는 의견으로, 12~18을 기존 장만으로 다시 이은 B2(12→18→13→18 왕복, 17장 88ms)와 B3(15~18 두 번 반복, 15장 100ms)를 추가했다. 이어서 주먹 구간(18→24)이 끊긴다는 의견으로 앞뒤 정리본 두 장 윤곽의 가운데를 원본 픽셀만으로 합성한 중간 장 6장(`clean/tXX-YY.png`, `tweens.json`, 도구 `tools/build_stage2_fan_tweens.py`)을 만들고, B2에 넣은 B4(주먹 2.5초 시작, 11장 46ms)와 B5(2.2초 시작, 11장 73ms)를 추가했다. 24→25 손바닥 펴기는 일부러 끊어 둔다. 사용자가 B4(47장, 4.45초, 06이 0.5초·19가 2.5초·25가 3.0초)를 “B4로 확정”했다. 확정본은 `runtime/fan-final/`(정리본·중간 장 바이트 복사, 8열 시트, motion.json, 승인 석궁), 내보내기 도구는 `tools/export_stage2_fan_final.py`이며 정리·중간 장·내보내기 도구는 확정본 덮어쓰기를 막는다. 받은 시트 중 첫 장부터 확대된 유도(1.39배)·화살비(1.53배)에서 얼굴이 사람처럼 그려졌고 확대되지 않은 5연사에서는 생기지 않았다.

화살비: Aether 입력과 영어 프롬프트를 `source/rain-aether/`, 확인 화면을 `preview/rain-input/`에 준비했다. 1차 결과(`source/rain-aether-01/`)의 자세를 채택했고 생성된 입만 지웠다. 12번 가면의 입 줄 하나를 위아래 가면색으로 메운 기준 가면을 35장 모두 후드 정렬 자리에 붙였다(04번은 손 보존). 이 시트는 확대돼 그려져 445×250·(-29,-9) 변환을 쓴다. 정리본 01~35와 타이밍 A/B는 `preview/rain-candidates/`, 게임 시간표대로 화살 12발·폭발 기둥(확정 VFX 시트)과 함께 보는 화면은 `preview/rain-sim/`. 사용자가 A 쪽을 골랐고 시작이 약하다고 해서 앞부분만 덜어낸 A2(02·06 제외)·A3(02·03·06 제외)를 추가했다. 이어서 A의 35장을 그대로 두고 02~07만 1.5배·2배로 빠르게 재생하는 A-x1.5·A-x2를 추가했다(05 0.40초·28 2.45초 유지). 마지막으로 빼도 튀지 않는 두 장(02·06, 정리본 변화량으로 측정)만 덜고 남은 앞부분을 1.5배·2배 빠르게 한 A-trim-x1.5·A-trim-x2를 추가했다. 사용자가 A-x2(35장 그대로, 02~07만 2배속, 3.07초, 05가 0.40초·28이 2.45초)를 골랐다. 확정본은 `runtime/rain-a-x2/`(정리본 바이트 복사, 시트·motion.json·승인 석궁), 내보내기 도구는 `tools/export_stage2_rain_final.py`이며 정리·내보내기 도구는 확정본 덮어쓰기를 막는다. Unity 미적용. 몸은 방향과 무관하게 위로 소환하고 2.45초 첫 폭발에 맞춰 아래로 내리찍는다. `runtime/homing-d-v2/motion.json`에 승인 상태를 기록했으며 원본·V1도 보존한다. 다음 공격은 튕기는 화살 5연사이며 `preview/bounce-input/index.html`에 승인 기본 자세의 흰 배경 시작 이미지와 영어 프롬프트를 준비했다. 사용자가 Aether에서 생성할 단계로, 새 연사 모션 프레임은 아직 없다. 0.5초 간격 5발, 입 없는 가면과 한 팔 형태를 고정한다.

5연사 입력 V2: 사용자 요청으로 전방 내밀기에서 양쪽 사선 교대 시전으로 변경했다. 시작 방향은 위임받아 화면 왼쪽 위부터 `↖ ↗ ↖ ↗ ↖`로 정했다. 오른쪽 시전도 기존 팔 하나가 가슴 앞을 가로지르며 어깨 부착 위치는 유지한다. 머리 위치·각도를 고정하고 가면을 가리지 않는다. 승인 머리의 무수정 8배 확대 참조는 `source/bounce-aether/approved-head-detail-8x.png`, 이전 전방 프롬프트는 `source/bounce-aether/previous/`에 보존한다. 이 변경은 시전 연기 지시이며 실행 코드의 투사체 조준 규칙은 변경하지 않았다.

5연사 1차 결과(Aether 원본 `source/bounce-aether-01/`, 3840×2160 6×6)는 보존한다. 사용자가 “좀 더 절도 있게”를 요청해 프롬프트 v3(`source/bounce-aether/prompt.txt`)로 다시 생성한다. v3는 방출마다 감기→튕기기→정지(약 0.12초)→반동 네 박자, 손을 어깨보다 높은 약 40° 사선, 다섯 번째 방출 뒤 기본 복귀 금지, 보라 눈빛 유지를 지정한다. v2 프롬프트는 `source/bounce-aether/previous/prompt-v2-alternating-soft.txt`. 1차 결과는 승인 크기의 약 96%로 그려져 유도 화살의 0.75배 변환을 쓸 수 없었다. 1차 타이밍 비교는 `preview/bounce-candidates/`. v3로 뽑은 2차 결과(`source/bounce-aether-02/`)를 사용자가 채택했다. 방출 정점 06/12/17/23/28을 0.5초 간격에 맞춘 타이밍 A/B/C를 `preview/bounce-v3-candidates/`에서 비교한다. 11·22는 소매 번짐 장이고 33~35는 기본 복귀라 제외한다. 사용자가 A를 골랐다. 정리본은 `runtime/bounce-a/` (32장, 2.95초, 투명 PNG·시트·motion.json), 재생 검토는 `preview/bounce-cleanup/`. 유도 화살 V2의 배경제거·천 외곽 정리를 쓰되 이 시트에서 장화가 통째로 빠지고 가면 눈가·정강이에 구멍이 나서, 석궁 외 큰 조각을 모두 몸으로 잡고 갇힌 비흰색·정강이 피부색·어두운 밑창 픽셀을 원본 색으로 유지하는 보정을 더했다. 11·22의 소매 옆 잔선만 지웠다. 사용자 검토(“발 부분 약간 덜 제거”)에 따라 장화 3px 안의 회색·밝은 회색·아래쪽 푸른 잔여물과 다리 가장자리의 흰 기, 다리 쪽 외딴 점을 지웠다(캔버스 y≥195만). 도구는 `tools/clean_stage2_bounce_a.py`. 사용자가 “A 확정”으로 승인했다. Unity 미적용.

입력은 승인 fused-idle 픽셀을 수정하지 않고 512×384 논리 캔버스의 (64,64)에 붙인 후 3배 nearest-neighbor 확대했다. 결과 1536×1152, 발 기준 Y=888, 피벗 (768,888)이다. 게임 크기를 3배로 변경한 것이 아니다. 원래 384×256 / (192,232) 기준과 환산식을 JSON에 보존했다.

끝 이미지는 강제하지 않는다. 기존 등장 포효 자세는 유도탄 발사의 자연스러운 끝 자세와 달라 사용하지 않는다. Aether가 같은 팔을 이어 움직이게 하고 프롬프트로 발사 자세 유지를 지정한다.

사용자가 원본 시트/GIF를 제공하면 실제 원본 해상도·그리드·프레임을 확인한다. 의미 있는 프레임으로 타이밍 후보 2~3개를 만들고 선택 후 배경제거·픽셀 보정한다. 전체 클립에 공통 축척·캔버스·기준점을 적용하며 프레임별 꽉 채우기·자동 크롭 확대를 하지 않는다. 이전 흡수 연결본의 matteProcessing은 참고하고 그 클립의 1/4 배율·오프셋·발 행은 복사하지 않는다.
