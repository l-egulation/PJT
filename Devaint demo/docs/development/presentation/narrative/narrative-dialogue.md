# NPC 상호작용과 대화 연결 범위

[분야 개요](README.md)

[대화 목표](../../architecture/presentation-narrative-ui.md#3-npc-상호작용과-대화)의 초기 구현이다. 불변 NPC/직선·선택지 대화 정의 → 후보 조회/명시적 대상 선택 → 세션 → Presenter/uGUI View와 소유자별 제어를 연결한다. 현재 본 게임·시험장의 격리된 챕터 마커와 기술 검사용 텍스트 키로 검사한다. 기본 숲에 제품 NPC/신규 대사를 배치하거나 [초반 이야기](../../../design/story/opening/opening.md)를 변경하지 않는다.

## 정의와 명령

DialogueDefinition은 안정 줄 ID·화자/텍스트 키·다음 줄·조건과 순서 있는 DialogueChoice를 복사한다. 선택지는 줄 안의 유일 ID·텍스트 키·목적지·조건/명령 ID를 가지며 목적지 존재·전체 도달 가능성과 중복/누락/순환/미사용 줄을 검증한다. 내용 해시는 줄 순서에 독립적이고 선택지 순서를 보존하며 명령 참조도 포함한다. NpcDefinition은 NPC ID와 대화 스냅샷/시작 조건을 참조한다. 실제 대사·초상·음성은 바인딩 책임이고 아래의 원본 저작은 지원하는 대화 그래프만 다룬다. 맵 저작이나 제품 대사 확정을 뜻하지 않으며 테스트 문자열은 제품 콘텐츠 원본이 아니다.

`Narrative/Contracts`와 `Narrative/Runtime`은 Unity·Combat·uGUI를 참조하지 않는다. `InteractionService`는 설정한 최대 거리·전투 중 허용·조건으로 후보를 조회하고, 호출자가 명시적으로 고른 배치 ID를 시작 시 다시 읽는다. 후보는 안정적인 ID 순서로 제공하며 최근접 대상을 자동 선택하지 않는다. 실제 키/패드 매핑이나 제품 거리·전투 허용값은 아직 정하지 않았다. 거리 측정점과 전투 상태도 바인딩이 공급한다.

`DialogueSession`은 시작한 정의 버전·챕터/배치·세션 ID·현재 줄·표시 리비전을 보관한다. `TryAdvance`/`TrySelectChoice`/`TryCancel`은 세션·줄·리비전을 확인해 오래된 입력을 거부한다. 선택지가 있는 줄은 명시적 선택만 허용하고 기본/첫 선택지를 자동 실행하지 않는다. 선택은 현재 줄·선택지·목적지 줄의 조건을 실제 입력 때 다시 검사하며, 조건 거부는 현재 줄과 리비전을 유지한다. 명령이 있으면 이 자격 검사 뒤 실행하고 성공 결과를 받은 뒤 목적지 선택지를 읽고 전환한다. 명령 없는 선택지는 기존처럼 다음 선택지 스냅샷 준비 뒤 전환을 확정한다. 조건 공급자 예외는 명시적인 실패이며 부분 줄 전환을 게시하지 않는다. 이미 성공한 명령 뒤 목적지 선택지 조회가 실패하면 성공 영수증을 유지한 채 `ContextFailed`로 끝내며 확정된 효과를 되돌리거나 재실행하지 않는다. 목적지 없는 일반 줄에서 유효한 진행만 정상 완료를 만든다. 수명 종료 명령으로 완료를 강제하지 않는다. 콜백의 상태 변경 재진입은 거부한다.

`DialogueSnapshot.Choices`는 선택지 ID·텍스트 키·선택지 자체의 조건 가용성을 방어 복사한 읽기 전용 목록이다. 목적지/현재 줄 조건과 대상 수명은 선택 명령에서 별도로 검사한다. `Poll`은 현재 선택지 조건을 다시 읽고 가용성이 바뀌었을 때만 표시 리비전을 갱신한다. 이 갱신 전의 입력은 같은 줄이어도 거부한다. 모두 비활성이면 현재 줄을 유지하며 완료나 대체 경로를 만들지 않는다. 이후 조건 회복·명시적 취소·대상 수명 종료를 기존 계약으로 처리한다.

현재 세션 정책은 호출자가 플레이어 취소 허용 여부와 대화 중 시작 자격 재검사 여부를 명시한다. 자격 재검사를 선택하면 거리/전투/시작 조건 유실을 `EligibilityLost`로 취소한다. 선택하지 않으면 진행 중에는 대상 수명만 확인하고 임의의 거리 종료 규칙을 추가하지 않는다. 대상 소멸은 `TargetLost`, 사용자 취소는 `PlayerCancelled`, 뷰 닫힘은 `ViewClosed`, 공급자/표시 오류는 실패로 구분한다. 명시적 호스트 `Close`가 씬/런/소유자 종료 이유를 전달할 수 있다. 여러 종료 경로가 겹치면 먼저 확정한 결과를 유지한다. 일반 비활성화 콜백은 뷰/호스트 종료의 안전 정리 경로이며 실제 Run/씬 전환 조립은 후속 범위다.

## 선택지의 외부 명령

`DialogueChoice.CommandId`는 조립이 등록한 명령 ID 한 개를 선택적으로 참조한다. 대화 데이터에 실행 코드·임의 객체·장비/월드 상태 변경을 넣지 않는다. `IDialogueCommandBindings.Validate`는 정의의 모든 명령 참조를 실행 전에 검사하며, 명령이 있는데 포트/등록이 없으면 대화 시작을 거부한다. 명령 없는 대화는 포트를 요구하지 않는다. `OpenScope`는 대화 세션·기대 챕터/배치·시작 정의를 캡처한 `DialogueCommandContext`로 자기 실행 범위만 얻는다. 이 초기 포트는 동기 명령만 지원하며 지연 작업/비동기 완료·명령 묶음의 트랜잭션은 후속 범위다.

`DialogueCommandBindings`는 명시적으로 주입한 ID→도메인 API 번역 함수를 복사한다. `DialogueCommandRequest`는 표시 토큰·선택지·명령 ID를 넘긴다. 실행 범위는 세션/시작 정의의 줄·선택지·명령 참조를 검사하고, 같은 세션/줄의 종료 결과를 보관한다. 성공한 선택을 새 표시 리비전으로 다시 요청해도 재실행하지 않으며 같은 줄의 다른 명령 선택도 거부한다. 중복 기록은 해당 비순환 정의의 줄 수 안에서만 늘고, 세션 범위 종료에 비운다. 범위/등록 소유자 종료·옛 세션·콜백 재진입은 새 실행을 만들지 않는다.

`Succeeded`는 다음 줄 전환을 허용한다. `Rejected`는 제공 서비스가 변경 없음을 보장하는 결과이며 현재 줄/토큰을 유지해 명시적으로 다시 시도할 수 있다. `Cancelled`/`Failed`는 각각 `CommandCancelled`/`CommandFailed`로 대화를 끝낸다. 예외/결과 누락은 실패이며 자동 재시도하지 않는다. 실패/취소가 외부 효과의 롤백을 뜻하지 않는다. 여러 도메인 변경의 원자성은 담당 서비스가 제공해야 하며 현재 실제 장비/보상 명령은 등록하지 않는다. `DialogueSnapshot.LastCommand`는 마지막 요청/결과 영수증으로, 표시/조건 실패 뒤에도 이미 성공한 명령을 구분한다.

완료·취소·대상 유실·표시/명령 실패·호스트/씬 종료는 자기 명령 범위를 한 번 반환한다. 반환은 확정된 도메인 효과를 되돌리지 않는다. 명령 범위 반환 오류는 원래 완료/취소/실패 사실을 유지하고 `DialogueSnapshot.CleanupError`로 별도 제공한다. Presenter는 이를 자기 반환 오류에 포함하면서 나머지 구독/제어/View 반환도 시도한다. 시퀀스는 이 반환 오류를 실패로 전달한다.

현재 대화·명령 포트는 기술 fixture로 검사한다. 영구/런 이야기 사실, 퀘스트·보상·아이템 지급의 실제 서비스와 제품 명령 콘텐츠는 아직 연결하지 않았다. 명령 없는 선택지는 줄 전환만 수행하며 대화 완료가 임의의 NPC 제거/획득/보상 사실을 만들지 않는다. 실제 반복/재방문 제한은 주입한 조건에 맡기고 새 제품 규칙을 확정하지 않는다.

## 챕터와 NPC 수명

`ChapterNpcTargets`는 `ChapterWorldHost`의 기대 세션 ID, `LayoutPlacement` ID와 의미 있는 앵커를 NPC 정의에 연결한다. 등록 시 없는 배치/앵커를 거부한다. 해당 모듈이 로드되고 배치 사실이 `Present`인 동안만 후보가 존재한다. GameObject 이름·Unity InstanceID·로드 순서를 대화 식별로 사용하지 않는다. 같은 챕터 배치라도 시작 전에 NPC/대화 버전이 바뀌면 이전 후보를 거부한다. 이미 시작한 세션은 기존 정의를 유지한다.

첫 구현의 언로드 정책은 대화 취소다. `Poll`/Presenter 갱신은 NPC 모듈 언로드·배치 반환·챕터 종료를 확인하고 소유한 표시/제어만 정리한다. 언로드 자체를 대화 완료로 기록하거나 `ChapterState` 배치 사실을 초기화하지 않는다. 재로드 후 대상이 다시 존재해도 새 대화는 새 세션 ID를 갖고 옛 입력은 거부한다. 대화 중 청크 유지 로딩·실제 NPC 액터/아트 바인딩과 서사 사실 지속은 아직 후속 범위다.

## Presenter와 uGUI

`UI/Contracts/IDialogueView`는 바인딩 ID·표시 토큰과 사용자 의도만 교환한다. `DialoguePresenter`가 본문/선택지 텍스트 키를 해석하고 `IDialogueCommands`를 호출한다. `DialogueDisplay`는 순서 있는 선택지 표시/가용성 목록을 복사한다. 화면의 입력은 표시된 줄의 토큰과 선택지 ID를 유지하며 다음 갱신에서 새 토큰을 게시하므로 같은 표시에서 중복 클릭으로 다음 줄까지 건너뛰지 않는다. 오래된 바인딩의 입력/해제는 새 뷰 바인딩을 닫지 않는다. 바인딩이 없거나 비활성 뷰의 입력은 무시한다.

`UI/Unity/DialogueView`는 주입된 TMP 텍스트·버튼·패널과 선택적인 선택지 버튼/레이블 배열을 표시한다. 선택지가 있는 동안 일반 진행 버튼은 비활성화하고, 주입한 슬롯에 표시 순서/가용성을 적용한다. 남은 슬롯은 숨긴다. 슬롯 부족·잘못된/중복 참조·누락 텍스트는 명시적인 구성/표시 실패이며 선택지를 자르거나 임의의 버튼을 생성하지 않는다. 레이아웃은 바인딩을 해제한 뒤 교체한다. 버튼 콜백은 표시 당시 바인딩/토큰을 캡처한다. 같은 UnityEvent 앞 콜백에서 줄/세션을 바꾸거나 재바인딩해도 남은 옛 콜백은 새 화면의 선택을 실행하지 않는다. 해제는 자기 리스너만 제거한다. 프리팹/레이아웃을 자동 재작성하거나 도메인 상태를 소유하지 않는다. 기존 uGUI를 유지한다. 테스트는 임시 Canvas/GraphicRaycaster/EventSystem/텍스트/버튼으로 이 경로를 구성하며 제품 대화창 레이아웃을 확정하지 않는다.

표시 정책은 입력 제한 채널과 세계 정지를 별도로 지정한다. Presenter는 자기 `IControlScope`만 반환한다. 다른 모달의 정지/입력 제한은 남으며, `Dialogue` 채널의 다른 제한이 있으면 진행/선택/취소 입력을 거부한다. `Interaction` 채널은 `NpcDialogueHost`의 후보/시작 입력에 적용한다. 대화는 Combat에 직접 의존하거나 `Time.timeScale`·플레이어 bool을 직접 쓰지 않는다. 뷰/호스트 비활성화·재바인딩·완료/취소/실패는 같은 소유권 정리 경로를 사용한다. Presenter의 `CleanupError`는 입력 거부 오류와 별도로 구독·제어·뷰 반환 오류를 모으며, 한 반환이 실패해도 나머지는 시도한다. 시퀀스 바인딩은 이 값을 실패 결과로 전달한다.

`NpcDialogueHost`는 게임/실험장에 동일한 서비스·정책·뷰와 선택적 명령 포트를 명시적으로 연결하는 구성 진입점이다. 기본 게임 조립에 실제 NPC를 자동 추가하지 않는다. 전체 화면 라우터·포커스 복귀·키보드/패드 탐색·레이어 간 확인 입력 소비·카메라/연출 정책은 아직 이 컴포넌트가 대신 결정하지 않는다.

`ChapterSequenceBindings`는 캡처한 NPC 후보/버전으로 같은 Interaction/Dialogue/Presenter/View·명령 포트 경로를 시작하고, 실제 대화 완료·취소·실패를 순차/ParallelAll 실행 결과로 전달한다. 명령 참조 누락은 시퀀스 제어를 얻기 전에 거부하며 대화 단계 시작에도 명령 범위를 다시 얻는다. 그룹 내부 NPC도 시퀀스 시작에 후보 버전을 캡처한다. 현재 단일 View 바인딩은 같은 그룹의 대화 두 개 이상을 사전 거부하며 여러 창/포커스 정책을 확정하지 않는다. 시퀀스 종료가 대화 완료나 이야기 사실을 강제하지 않는다. 현재 격리 fixture의 연결/스킵 계약과 제품 연출·Run 통합의 남은 범위는 [시퀀스 실행](sequence-execution.md)을 따른다.

## 버전 명시 원본과 미리보기

DialogueSourceDocument 스키마 1은 안정 줄/선택지 ID·목적지·화자/텍스트 키·선택적 조건/명령 ID를 보관하고 기존 DialogueDefinition 생성자가 그래프/ID/해시의 의미를 검증한다. 명시적 참조 카탈로그는 Speaker/Line/Choice 텍스트와 조건/명령 ID를 구분하며 실제 서비스를 등록하지 않는다. Tools > deviant > Experiments > Dialogue Source에서 원본/참조 파일을 선택하고 노드·간선·순서 있는 선택지를 편집/Undo한다. Save·생성 TextAsset 내보내기·다음 런타임 세션 적용·미리보기는 별도 동작이다. SourceFiles의 1MiB 한도·읽었던 바이트 해시·원자적 교체를 사용하고 참조 파일 변경도 저장 전에 거부한다. 생성물은 저장 DTO를 운반하며 같은 C# 컴파일러를 사용한다.

NpcDialogueHost의 명시적 sourceBinding은 기존 구성된 같은 NPC에만 후보를 적용한다. 진행 세션은 시작 정의/텍스트를 유지하고 다음 세션만 새 후보를 채택하며 무효 전체 후보는 이전 버전을 보존한다. Editor 미리보기는 private PreviewScene의 실제 Presenter/uGUI·RenderTexture와 전용 ControlSession을 사용한다. 미리보기 명령은 기술 영수증만 기록하고 제품 Run·보상·서사 API를 호출하지 않는다. 기본 숲 NPC·제품 대사·텍스트를 자동 생성하지 않는다.

## 검증

`DialogueContractTests`는 정의/직선 구조·시작 버전·표시 토큰·후보 재검사·조건 재검사·종료 이유·소유자 제어·오래된 바인딩·누락 텍스트 실패를 검사한다. `DialogueChoiceTests`는 분기/합류·직선 해시 호환·순서/불변 목록·잘못된 그래프·명시적 선택/중복/조건 재검사·가용성 리비전·모두 비활성·새 선택지 준비 실패·재진입·오래된 세션·누락 선택지 텍스트와 중첩 제어를 검사한다. `DialogueCleanupTests`는 정리 오류의 구분/집계와 일부 반환 실패 뒤 나머지 반환·중첩 모달 보존을 검사한다. `NpcDialogueIntegrationTests`는 본 게임/시험장의 실제 챕터 마커와 임시 uGUI 버튼으로 정상 진행·연속 클릭·세계 계속/정지·중첩 모달·뷰 비활성화·NPC 모듈 언로드/재로드·취소/명시적 수명 종료를 검사한다. `DialogueChoiceIntegrationTests`는 같은 두 씬/챕터/호스트에서 선택지 표시·조건 변화/옛 토큰·연속 클릭·실행 중 NPC 버전 교체·모달/언로드·명시적 슬롯 실패/재바인딩과 UnityEvent 중 줄/세션 교체의 옛 클릭 거부를 검사한다. `DialogueCommandTests`는 명령 참조/불변 해시·등록 누락/범위 부분 실패·성공/거부/취소/실패·중복/옛 세션/리비전·조건 재검사·명령 후 조건 조회 실패·종료 사실/반환 오류·재진입·다른 소유자 보존을 검사한다. `DialogueCommandIntegrationTests`는 두 씬의 고정/캡처 챕터·실제 NPC 호스트/선택지와 시퀀스에서 포트 누락의 사전 거부·결과/중복·모달·스킵/타임아웃/언로드·반환 오류 전파와 플레이어/배치 사실 보존을 검사한다. 실행 명령과 실제 아트/화면/빌드 검증 구분은 [검사 방법](../../testing/testing.md)을 따른다. 구조 검사만으로 실제 대화 가독성·연출 품질·스토리 콘텐츠·전체 Run 통합을 완료했다고 하지 않는다.
