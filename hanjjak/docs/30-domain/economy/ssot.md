## 책임

거래 대상과 시장 품목 동일성, 매수·매도 주문, IOC·부분 체결, 가격·시간 우선순위, 자산 보관, 수수료·정산·수령과 시장 권한 경계를 소유한다. 체결 원본과 가격 추이 집계의 정본은 `market_trade`이며 화면 배치는 [클라이언트 UX SSOT](../player/ux/ssot.md), 아이템 정의와 공급은 각 책임 도메인을 참조한다.

## 거래 대상과 시장 품목

- 거래 화폐는 쌀이다.
- 1차 거래 품목은 거래 가능한 아이템 카탈로그 중 `MATERIAL`, `SKILL_BOOK`, `GEM` 분류다. 보석함과 완성 장비·큐브·주문서는 거래하지 않으며 미등록 중복 치장 재고는 세부 정책 확정 전까지 구현 범위에 넣지 않는다.
- 재료와 스킬북은 같은 아이템 ID, 보석은 레벨·옵션 종류·실제 옵션 수치가 모두 같아야 하나의 시장 품목이다. 시장 품목의 구현 식별자와 canonical 직렬화는 [거래소 주문장 아키텍처 결정](../../80-decisions/architecture/market-order-book.md)이 소유한다. 표시명·속성은 식별자와 분리하며 거래 당시 표시명 snapshot을 보존한다.
- 보석의 레벨·옵션·합성·잠금 규칙은 [보석 SSOT](../gems/ssot.md), 치장 등록·미등록 중복 재고·성급·도감·외형 슬롯 규칙은 [치장 SSOT](../cosmetics/ssot.md)가 소유한다.

## 주문과 체결

- 주문 가격은 10~999,999쌀 범위의 1쌀 단위 정수다. 주문 수량은 1개 이상이며 거래소 전용 고정 상한을 두지 않고, 사용 가능 자산·시장 잔량과 서버 저장·안전한 곱셈 범위로 제한한다. 강화 재료 구매 UI의 빠른 수량 증가는 10·100·500개를 사용하며 각 클릭은 현재 입력 수량에 더한다.
- 즉시 구매는 개당 최대 단가를 가진 매수 IOC, 즉시 판매는 개당 최소 단가를 가진 매도 IOC다. 가격 조건을 만족하는 상대 주문을 즉시 체결하고 미체결 잔량은 주문장에 남기지 않는다.
- 매수·매도 지정가 주문은 제출 시 교차하는 상대 주문을 먼저 체결하고 미체결 잔량을 8시간 대기시킨다. 같은 사용자·시장 품목·방향·가격의 재주문도 독립 주문과 독립 시간 우선순위를 가진다.
- 매수는 높은 가격, 매도는 낮은 가격이 우선이며 같은 가격에서는 먼저 등록된 주문이 우선이다. 동시 요청에서도 잠긴 최우선 주문을 건너뛰지 않고 엄격한 가격·시간 우선순위를 지킨다.
- 체결 가격은 먼저 대기한 maker 주문의 가격이다. 새 매수가 기존 매도와 체결되면 매도 가격, 새 매도가 기존 매수와 체결되면 매수 가격을 적용한다.
- 매수 주문은 같은 계정의 반대 방향 매도 주문을 체결 후보에서 제외하고 다른 계정의 주문만 체결한다. 본인 매도 주문만 남아 있으면 매수는 체결되지 않으며, 매도 주문이 본인의 반대 방향 매수 주문과 가격상 교차하면 새 매도 주문 전체를 거절한다.
- 가격 변경과 미체결 수량 증가는 전체 주문에 수정 시점의 새 시간 우선순위를 부여하고 만료를 수정 시점부터 8시간 뒤로 갱신한다. 미체결 수량 감소는 기존 우선순위와 만료 시각을 유지한다.
- 시장 잔량, 가격 조건 또는 사용 가능 자산 때문에 요청 수량을 채우지 못해도 한 개 이상 체결하면 부분 체결로 확정한다. IOC 미체결 잔량은 종료하고 지정가 미체결 잔량은 대기한다. 한 개도 체결하지 못한 IOC는 상태를 변경하지 않고 원인을 구분해 실패한다.
- 계정의 활성 지정가 주문은 모든 품목과 매수·매도를 합해 최대 30개다. 등록·수정·취소에는 쌀 비용을 부과하지 않으며 계정별 성공한 주문 mutation은 최근 1분 합계 30회까지 허용한다.
- 상태를 변경한 성공 주문 등록·수정·취소만 최근 1분 mutation 제한에 포함한다. 검증 실패·멱등 재생·0체결 IOC 실패는 포함하지 않으며 성공 이력은 반복 주문 분석을 위해 30일 보존한다.
- 같은 계정·시장 품목·방향의 성공한 취소 후 재등록 또는 가격 변경이 10분 안에 20회 이상이면 주문을 막지 않고 반복 주문 후보와 근거·규칙 버전을 기록한다. 비정상 가격 후보의 수치 기준은 실제 30일 시장 분포 확인 전까지 미확정이다.

## 공개 시장과 거래 기록

- 공개 주문장은 시장 품목별 매수·매도 가격대의 총잔량을 집계한다. 본인 주문도 공개 총잔량에 포함하되 본인 수량을 구분하며, 사용자별 즉시 체결 가능 수량은 본인 주문을 제외해 계산한다.
- 판매자·구매자 식별자는 공개하지 않는다. 전체 거래 내역은 품목·수량·단가·총액·체결 시각만 제공하며 판매자 수수료와 정산액을 숨긴다. 개인 거래 내역은 매수·매도 방향과 상대를 숨긴 체결 정보를 제공한다.
- 종료 주문은 전체 체결·취소·만료 상태와 이미 체결된 수량·금액을 최근 30일 동안 조회한다. 부분 체결된 활성 주문은 확정 체결분과 수정·취소 가능한 미체결 잔량을 구분한다. 한 개 이상 체결된 IOC만 종료 주문으로 보존하고 0체결 실패는 7일 command 결과에만 남긴다.
- 시장 품목별 `marketRevision`은 주문 등록·수정·체결·취소·만료 때 transaction 안에서 원자 증가한다. 낮은 revision의 늦은 응답은 폐기하고 revision 간격이나 cursor 변경 오류는 선택 시장 주문장·내 주문과 개인 거래소 요약을 전체 재조회한다.

## 자산 보관·수령·정산

- 대기 매수 주문은 `미체결 수량 × 지정가`에 해당하는 쌀을 지갑의 사용 가능 잔액에서 분리해 escrow로 유지한다. maker 가격이 매수 상한보다 낮으면 체결 후 차액을 즉시 사용 가능 잔액으로 반환하고 취소·만료·수량 감소는 해제된 미체결분의 escrow를 반환한다.
- 대기 매도 주문은 등록 수량을 인벤토리에서 거래소 외부 보관으로 옮긴다. 체결은 외부 보관 잔량을 차감하므로 판매자 인벤토리를 다시 차감하지 않는다.
- 대기 매수 체결 물품과 취소·만료된 매도 주문의 미체결 반환 물품은 하나의 거래소 물품 수령함에 외부 보관하고 `구매 체결`, `판매 취소 반환`, `판매 만료 반환` 출처를 구분한다. 인벤토리 공간 부족은 매도 주문 취소와 시장 노출 종료를 막지 않는다.
- 물품은 개별 수령과 전체 수령을 지원한다. 전체 수령은 오래된 건부터 각 건의 전량이 들어가는지 검사해 가능한 건은 지급하고 공간이 부족한 건은 수령함에 유지한다. 각 건은 한 번만 수령된다.
- IOC 구매는 체결 transaction에서 구매자 인벤토리 수용량을 검증하고 직접 지급한다. 수용할 수 없는 수량을 체결한 뒤 소급 폐기하지 않는다.
- 판매 수수료는 실제 개별 체결 총액의 10%를 소수점 이하 내림으로 계산하고, 정산액은 체결 총액에서 수수료를 뺀 값이다. IOC와 지정가 체결에 같은 규칙을 적용한다.
- 모든 판매 체결은 판매자 정산 우편을 만든다. 판매자 쌀 잔액은 개별 또는 전체 정산 청구가 성공할 때 증가하며 각 정산은 한 번만 청구된다.
- 체결·물품 수령함·판매 정산·주문 만료의 읽지 않음은 계정 전체에서 공유하는 네 개의 서버 cursor로 관리하고 각 항목의 성공 응답이 제공한 사건까지만 명시적 읽음 명령으로 전진한다.

## 운영 관리 명령

- 운영 관리자는 전용 `market:manage` 권한과 운영 사유로 특정 활성 주문의 미체결 잔량을 강제 취소하거나 시스템이 특정 사용자의 활성 매도 주문을 지정 수량만큼 직접 구매하게 할 수 있다. 강제 취소한 매도 잔량은 사용자 인벤토리로 반환하지 않고 시장에서 제거하며 매수 escrow도 반환하지 않는다. 시스템 구매는 정상 체결 기록과 10% 수수료를 남기고 판매자 정산액을 우편 대기 없이 즉시 지갑에 지급하며 구매 물품은 시스템 sink로 처리한다.
- 운영 관리자는 `MATERIAL`, `SKILL_BOOK` 중첩 아이템을 시스템 보유량과 무관하게 양의 저장 정수 범위의 수량과 일반 주문 가격 범위로 하나의 시스템 매도 주문에 등록할 수 있다. 보석 인스턴스 임의 생성은 허용하지 않는다. 시스템 주문과 구매는 로그인할 수 없는 고정 내부 계정을 사용하고 각 명령은 멱등 키, 운영 사유, append-only 감사와 주문장 도메인 이벤트를 남긴다.
- 이미 체결된 거래의 소급 취소·자산 환수, 자동 유동성 공급과 자동 가격 보호는 허용하지 않는다. 시스템 주문 등록·구매·강제 취소는 관리자가 명시적으로 실행한다.

## 권한·정합성

주문 등록·수정·체결·취소·만료는 시장 품목 row를 먼저 잠가 같은 품목의 모든 주문장 변경을 직렬화하고 잠긴 최우선 주문을 건너뛰지 않는다. 물품 수령은 `createdAt, deliveryId` 순서로 delivery 행을 잠근다. command 멱등성과 최신 계정·주문·지갑·인벤토리 상태를 재검증하고 주문·escrow 또는 외부 보관 자산·개별 체결·수수료·정산·수령·거래 기록·지갑 원장·Outbox·command 결과·revision 변경을 유스케이스별 PostgreSQL transaction으로 확정한다. 동일 command 재시도는 저장 결과를 재생하며 시장 정합성을 Kafka에 위임하지 않는다.

## 기존 데이터 전환

- 기존 활성 판매 주문은 각 행을 새 매도 주문 한 건으로 옮기고 구형 가격 수정 여부와 관계없이 기존 `createdAt`을 우선순위 시각으로 보존한다.
- 기존 활성 구매 예약은 maker 가격 규칙을 소급 적용하지 않고 취소해 남은 escrow를 반환한다.
- 기존 구매 수령 물품과 판매 취소·만료 반환 물품은 합치지 않고 원본 행 참조를 보존해 통합 물품 수령함으로 각각 이관한다. 주문 잔량과 실제 escrow·외부 보관이 일치하지 않는 주문은 정상 이관을 막거나 자동 보전하지 않고 `복구 검토 중`으로 격리한다. 운영자는 원장으로 확인한 자산만 반환하거나 무반환 종료하고 감사 기록을 남긴다.

## 시장 품목 비활성화

카탈로그에서 제거되거나 거래 불가로 바뀐 시장 품목은 삭제하지 않고 비활성화한다. 새 주문·수정·체결을 즉시 막고 `거래 중단·취소 처리 중`을 표시하며 worker가 활성 주문을 bounded batch로 취소한다. 매수 escrow는 반환하고 매도 잔량은 통합 물품 수령함으로 옮긴 뒤 주문 상태를 취소로 확정한다.

## 제외 범위

1차 호가창은 자동 시스템 유동성 공급, 시스템 가격 상·하한·급변 거래 중단·자동 가격 보정, Maker/Taker 차등 수수료와 IOC 잔량의 자동 지정가 전환을 사용하지 않는다. 관리자가 명시적으로 실행하는 운영 주문은 [운영 관리 명령](#운영-관리-명령)을 따른다. 실제 부족·가격 왜곡 지표가 확인되면 별도 결정한다.
