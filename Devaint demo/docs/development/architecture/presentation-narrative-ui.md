# 이펙트·연출·NPC 대화·GUI 목표 구조

[분야 개요](README.md)

[목표 아키텍처](gameplay-architecture.md)의 확장 설계 제안이다. 아래는 전체 목표이며 현재 적용 범위는 [HUD 구현](../presentation/ui/hud.md)과 [모션·이펙트](../presentation/visuals/combat-presentation.md)에서 구분한다. HUD 소유자별 입력/정지와 제어 Presenter, 기본 공격 Sprite Cue·주입 AudioClip의 공통 재생 핸들과 카메라 위치 요청은 연결했다. 음향은 기술 바인딩/샘플링 fixture이며 제품 소리/믹서·시퀀스 음향 조립은 후속이다. 렌즈/줌/흔들림·다른 매체·게임플레이 액터 제어·제품 전체 화면 라우터도 후속 범위다. 시퀀스는 [현재 구현](../presentation/narrative/sequence-execution.md)의 격리 fixture에서 대화·카메라 위치·Sprite Cue·페이드·연출 전용 뷰 이동·대기의 순차/명시적 `ParallelAll`과 스킵 계약을 연결했다. NPC/직선·선택지 대화와 동기 명령 포트는 [현재 구현](../presentation/narrative/narrative-dialogue.md)의 격리 데이터/가짜 도메인 서비스 범위다. 이야기와 연출 콘텐츠는 [초반 스토리](../../design/story/opening/opening.md)를 따르며 새 대사·선택지·보상·반복 귀환 규칙을 확정하지 않는다.

## 1. 책임과 의존성

이펙트 교체, 연출 순서 변경, 대사·선택지 추가, GUI 화면 추가가 전투 실행기 수정을 요구하지 않게 한다. 게임 규칙의 결과를 표현하는 경로와 게임 규칙에 변경을 요청하는 경로를 구분한다.

| 영역 | 소유 책임 | 소유하지 않는 책임 |
|---|---|---|
| `Presentation` | 모션, VFX, SFX, 카메라 반응, 화면 전환 재생 | 피해·실제 이동·아이템 지급·이야기 진행 판정 |
| `Interaction` | NPC 등 상호작용 후보 탐색, 선택, 실행 조건 재검사, 세션 시작 요청 | 대사 분기·대화창 렌더링 |
| `Dialogue` | 대화 정의, 현재 노드, 조건·선택지, 세션 진행 | Canvas·키보드 직접 접근·보상 객체 생성 |
| `NarrativeState` | 명시된 범위의 이야기 사실과 조회/변경 계약 | 모든 게임 상태의 전역 문자열 사전 |
| `Sequences` | 대화·카메라·음향·연출 행동의 순서, 병렬 실행, 완료·중단 조율 | 전투 수치와 런 규칙 자체 |
| `UI` | 화면별 표시 모델·명령 연결, 창 수명, 레이어·포커스·입력 전달 | 전투/대화의 상태 전이·저장 파일 직접 변경 |
| `Control` | 소유자별 입력 제한·시간 제어 요청 관리와 충돌 해석 | 어떤 대화가 세계를 멈추어야 하는지에 대한 콘텐츠 결정 |

`GameComposition`이 이 모듈과 도메인 서비스를 연결한다. 폴더·레이어·공개 계약은 [프로젝트 목표 구조](project-structure.md)를 따르며 `Interaction`·`Dialogue`·`NarrativeState`는 `Narrative` 모듈 안에 배치한다. `Combat`은 `Dialogue`·`UI`·`Sequences`를 참조하지 않는다. 대화/연출 실행기는 좁은 상태 조회·명령 인터페이스를 사용하며 UI나 전체 Game 객체를 조회하지 않는다. 각 영역은 논리 경계이며 최초부터 모두 별도 asmdef로 만들 필요는 없다.

```text
전투·월드의 확정 이벤트 → 표현 바인딩 → VFX / SFX / 카메라 / HUD

플레이어 상호작용 → Interaction → Dialogue 또는 Sequences
                                    ↓              ↓
                              화면 표시 모델    표현 재생 요청
                                    ↓              ↓
                                   GUI          Presentation
                                    ↓
                            선택/진행 명령 → 실행기

대화·연출의 게임 상태 변경 요청 → 담당 도메인 → 성공/실패 결과
```

이벤트는 이미 확정된 사실을 전달한다. 명령은 실행 가능 여부를 검사하고 결과를 반환한다. 모든 연결을 전역 이벤트 버스로 바꾸지 않는다. 실행 순서가 중요한 소비·지급·상태 변경은 명시적인 명령 경로로 처리한다.

## 2. 이펙트·소리·카메라 반응

조명·노말맵·캐릭터/몬스터 동적 그림자·비차단 반응형 랜턴의 확장 구조는 [조명 기술 설계](../presentation/visuals/lighting-and-reactive-props.md)를 따른다. 환경·구역·시퀀스의 소유자별 조명 요청은 Presentation이 합성하고 소품 운동 상태는 World가 소유한다. 현재는 합성 진단 에셋의 공통 전투 실험장과 프로필 요청·근접 접촉 경로를 연결하며, 구역·Cue·시퀀스 조명 단계가 이미 제품 구현에 포함된 것으로 해석하지 않는다.

### 재생 정의와 바인딩

`PresentationCueDefinition`은 안정적인 ID로 스프라이트 시퀀스·파티클·음향·카메라 반응을 참조한다. 전투 정의는 프리팹 경로 대신 Cue ID를 사용한다. 게임플레이 효과와 시각 효과는 구분한다. 피해를 주는 투사체·장판은 전투 상태를 갖고, 해당 상태의 뷰가 Cue를 재생한다.

| 정의 항목 | 예시 책임 |
|---|---|
| 재생 매체 | 프레임별 유지 시간, 파티클/VFX 프리팹, 음향 클립 참조 |
| 공간 바인딩 | 액터 부착, 소켓, 타격 위치 고정, 월드 앵커, 화면 좌표 |
| 배치 | 오프셋, 좌우 반전, 크기, 정렬 레이어 |
| 시간 | 지연·수명·반복, 행동 시간/효과 시간/표현 시간에 대한 연결 |
| 종료 | 소유자 소멸 시 정지 또는 잔류, 취소 시 처리, 루프 정리 |
| 반응 | 카메라 흔들림·줌 요청, 음량·피치·믹서 경로 참조 |
| 중요도 | 판독에 필요한 예고/공격 표현 또는 장식, 동시 재생 제한 정책 |

`CuePlayer`는 재생 핸들을 반환한다. 현재 Sprite 시퀀스·소유자 스코프·주입 시계·지연/중복 미디어 결과 수명은 [전투 표현](../presentation/visuals/combat-presentation.md)에 기술한 범위로 구현했다. 아래는 다른 매체·풀·카메라를 포함한 전체 목표다. 완료·취소·실패를 구분하고 중복 정지를 허용한다. 반복 재생은 반드시 소유자와 정리 경계를 가진다. 풀에서 꺼낼 때 이전 대상 참조·타이머·구독·음량 등을 초기화한다. 지연된 로딩 완료가 리셋 후에 도착하면 세션/세대 ID를 검사해 재생하지 않는다.

행동 Cue는 `ActionExecutionId + CueId + 발생 순번` 등으로 식별해 구독 재연결이나 UI 갱신으로 중복 재생되지 않게 한다. 체력·상태처럼 계속 유지되는 정보는 현재 스냅샷에서 재구성하고, 타격음 같은 일회성 이벤트를 재생 이력 없이 다시 발생시키지 않는다.

시각 효과나 소리가 누락되어도 피해·쿨타임을 변경하지 않는다. 다만 필수 예고 표현의 누락을 정상 품질로 간주하지 않고 검증 오류로 표시한다. 재생 개수 제한은 장식부터 적용하고 필수 판독 요소의 제거 정책은 따로 검토한다.

카메라 추적·대화 구도·컷신 구도·흔들림을 한 컴포넌트가 임의로 덮어쓰지 않는다. `CameraDirector`가 소유자별 구도 요청을 우선순위로 해석하고 허용된 흔들림을 합성한다. 종료 시 옛 Transform 값을 무조건 복원하지 않고 남아 있는 현재 요청으로 돌아간다. 현재는 [카메라 구현](../gameplay/world/forest-prototype.md#카메라)의 위치 소스/요청·기본 추적·챕터 앵커만 연결했고, 실제 콘텐츠 우선순위·렌즈·흔들림·블렌드 정책은 남아 있다.

히트스톱은 시뮬레이션에 영향을 주므로 단순 시각 Cue의 부작용으로 구현하지 않는다. 도입 시 별도 시간 정책을 정의해야 하며 현재 규칙에는 추가하지 않는다.

## 3. NPC 상호작용과 대화

### NPC와 대화 세션 분리

아래는 분기와 도메인 명령을 포함한 전체 목표다. 현재 후보 재검사·직선/비순환 선택지 세션·표시 토큰/선택 조건 재검사·동기 명령 포트의 결과/중복/세션 수명·Presenter/uGUI/제어와 챕터 마커 연결의 범위/제한은 [NPC·대화](../presentation/narrative/narrative-dialogue.md)에서 구분한다. 실제 대사/선택지/반복 정책을 구현을 이유로 확정하지 않는다.

`NpcDefinition`은 NPC 콘텐츠 ID, 표현 참조, 상호작용 항목을 갖는다. 같은 NPC가 여러 곳에 등장할 수 있으므로 배치 인스턴스 ID와 콘텐츠 ID를 구분한다. 진행 사실은 필요한 범위에 따라 NPC 자체·배치·챕터·런 등과 연결하며 GameObject 수명에 매달리지 않는다.

`Interaction`은 가능한 대상을 찾고 안내용 모델을 제공한다. 실제 입력 시 거리·대상 존재·실행 조건을 다시 검사한 뒤 세션을 시작한다. 대화 가능 거리, 전투 중 허용 여부, 복수 대상 선택 방식은 설정/기획으로 받으며 새 규칙을 확정하지 않는다.

`DialogueDefinition`은 안정적인 노드 ID, 화자 ID, 텍스트 키, 다음 노드, 선택지와 조건 참조, 명시적인 도메인 명령 참조를 가진다. 직선 대화부터 지원하고 분기·선택지·재방문 조건은 같은 계약으로 확장한다. 임의 C# 실행문이나 전역 변수를 대화 데이터에 넣지 않는다.

`DialogueSession`은 현재 노드·세션 ID·선택 가능 항목·진행 상태를 소유한다. 대화창은 이 모델을 표시하고 `Advance`·`SelectChoice`·`Cancel` 같은 명령을 보낸다. 현재 노드와 세션을 확인해 더블 클릭이나 이전 화면의 선택 입력을 거부한다. 선택 시 조건을 다시 검사하고 명령 결과를 받은 뒤 다음 노드로 진행한다.

장비·아이템·챕터 상태를 바꾸는 요청은 각각 해당 도메인으로 보낸다. 대화가 직접 인벤토리를 수정하지 않는다. 재시도·중복 콜백이 가능한 명령은 안정적인 실행 키로 중복 수행을 막으며 여러 변경이 하나의 선택에 묶이면 담당 서비스가 원자적 처리 또는 명시적인 실패 처리를 제공한다. 보상/퀘스트 기능의 도입 자체를 확정하는 것은 아니다.

`NarrativeState`는 타입과 수명 범위가 명시된 사실만 제공한다. 런 종료에 사라지는 사실과 영구 진행 후보를 구분하되 실제 영구 저장 목록은 기획 이후 결정한다. 대화 세션의 일시 상태를 자동 저장 대상으로 취급하지 않는다. 텍스트는 키로 참조해 대화 구조와 문구를 분리하고, 번역·음성·초상 추가가 분기 로직을 변경하지 않게 한다.

### 종료와 월드 연결

정상 종료, 플레이어 취소, 대상 소멸, 런 종료, 씬 전환을 별도 결과로 처리한다. 대화 중 전투 정지 여부, 피격 시 종료 여부, 재개 위치, 반복 가능 여부는 명시적인 세션 정책으로 받는다. 세계가 계속 진행되는 대화와 일시정지형 대화를 모두 연결할 수 있지만 실제 사용 정책은 미정이다.

고정 맵과 생성 맵의 NPC는 `ChapterLayout`의 배치 ID와 의미 있는 앵커/역할로 연결한다. 특정 씬 오브젝트 이름·배열 순서·월드 좌표를 대화 그래프에 직접 박아 넣지 않는다. 대화 도중 청크 언로드는 세션 정책에 따라 관련 뷰의 로드를 유지하거나 세션을 취소하고 정리한다. 뷰 언로드만으로 대화 완료 사실을 생성하지 않는다.

## 4. 연출 시퀀스

아래는 병렬·페이드·액터 행동을 포함한 전체 목표다. 현재 순차/중첩 없는 `ParallelAll` 정의·실행기·챕터 바인딩·단일 Image 페이드·전용 Sprite 이동·완료/취소/실패/명시적 스킵은 [시퀀스 실행](../presentation/narrative/sequence-execution.md)의 기술 fixture 범위로 연결했다. 제품 연출이나 스킵 후 이야기·보상·전환 정책을 확정한 것은 아니다.

`SequenceDefinition`은 대화 실행, Cue 재생, 카메라 요청, 페이드, 대기, 연출용 액터 행동 요청을 순차/명시적 병렬 단계로 조합한다. 제어 흐름이 있는 대화 실행기와 전투 행동 실행기는 각각 유지하며 시퀀스가 이들의 시작·완료·취소 계약을 조율한다.

`SequenceRunner`는 실행 핸들, 단계별 상태, 취소 범위, 오류·완료 결과를 갖는다. 각 단계는 취소를 받을 수 있어야 하며 외부 완료를 기다리는 단계에는 타임아웃/실패 경로를 정의한다. 정상 완료·스킵·취소·실패 후 자신이 얻은 카메라·입력·시간·액터 제어를 모두 반환한다.

연출 중 액터를 움직일 때도 게임플레이 액터의 Transform을 임의로 덮어쓰지 않는다. 액터 제어권을 얻어 이동 명령을 보내고 물리 규칙을 통과시키거나, 별도로 정의된 연출 전용 뷰를 사용한다. 어느 방식인지 콘텐츠 바인딩에 명시한다. 현재 `StageMove`는 물리/게임 스크립트가 없는 전용 뷰 모드만 지원한다. 게임플레이 액터의 입력 차단·진행 중 행동·피격 상태를 연출이 우회하거나 제어권 인계 정책을 새로 확정하지 않는다.

Unity Timeline은 카메라·음향·애니메이션 등 저작 도구/재생 어댑터로 선택할 수 있다. 그 Signal이나 재생 종료를 전투 피해·보상 지급의 유일한 권한으로 사용하지 않는다. 사용 패키지 선택은 구현 단계에 남긴다.

**스킵, 취소, 미리보기 스크럽은 다른 동작**이다.

- 스킵: 해당 시퀀스가 선언한 종료 지점·필수 상태 변경만 담당 서비스로 요청한다. 건너뛴 모든 단계의 부작용을 재생하지 않는다.
- 취소: 이미 확정된 변경을 임의로 되돌리지 않는다. 남은 단계와 소유한 제어·표현을 정리하고 명시된 복구 경로를 따른다.
- 스크럽: 기본적으로 표현 미리보기이며 실제 이야기 진행·아이템·런 상태를 변경하지 않는다.

스킵 허용 여부와 스킵 후 결과는 콘텐츠별 명세가 필요하다. 정책이 없는 시퀀스는 스킵 버튼을 노출하지 않는다. 중복 종료·스킵 입력으로 완료 명령이 반복되지 않게 한다.

필수 NPC·위치 앵커·제작 모듈을 시퀀스의 요구사항으로 선언한다. 고정/생성 맵 공통 검증기가 실행 전 바인딩을 확인한다. 예를 들어 초반의 농가와 우물은 의미 있는 앵커로 연결할 수 있지만, 초반 구간을 절차 생성하기로 확정하는 것은 아니다. 기존 스토리의 동일 장소·행동 순서는 보존한다.

## 5. GUI와 공통 제어

### 화면 구조

기존 HUD의 uGUI Canvas·프리팹과 `IBattleHudDataSource` 기반 표시 경계를 활용한다. 초기 리팩토링에서 UI 프레임워크를 교체하지 않는다. GUI는 `View`(표시/입력), 화면별 `Presenter`(표시 모델과 명령 연결), `ScreenRouter`(창 수명·내비게이션)로 구분한다. 대화/재고 같은 도메인 객체가 uGUI를 참조하지 않는다.

HUD·월드 안내·일반 화면·모달·전환 오버레이의 레이어와 포커스 소유권을 명시한다. 어떤 화면이 입력을 소비하는지 라우터가 판단하고, 뒤의 화면/플레이어로 같은 확인·클릭 입력이 새지 않게 한다. 키보드/패드 탐색과 마우스 입력을 공통 UI 명령으로 연결하며 닫힌 화면의 포커스는 유효한 이전 대상으로 반환한다.

각 화면은 열기·닫기·취소·바인딩 해제 계약을 가진다. 닫기 버튼, 뒤로가기, 외부 씬 전환이 동일한 정리 경로를 사용한다. 화면이 비활성화되어도 다른 창의 제어권을 해제하지 않는다. 화면 추가는 해당 표시 모델·명령·뷰와 등록으로 끝내고 전역 UI switch 문을 계속 확장하지 않는다.

공통 위젯은 버튼·게이지·아이템 슬롯·툴팁처럼 실제 반복되는 요소부터 추출한다. 색·폰트·간격 등의 테마와 텍스트 키를 표시 로직에서 분리한다. 해상도·화면 비율·텍스트 길이가 달라도 정보와 포커스가 유지되는지 검증한다. Editor 실험 도구는 제품 GUI와 별도로 같은 모델/서비스를 사용할 수 있다.

### 입력·시간 제어의 소유권

현재 `BattleHudView`의 직접 `Time.timeScale` 변경/입력 차단 bool 쓰기는 `HudControlPresenter`와 소유자 스코프로 이행했다. `ControlSession`은 입력 채널 합성·정지·소유자별 유한 시간 슬로우 요청을 소유하며, 정지가 없을 때 가장 느린 요청을 선택한다. 본 게임의 단일 Unity 시간 어댑터가 바인딩 기준 배율에 현재 합성 결과를 적용한다. TTL의 명시 진행·정지 중 보류·소유자별 반환과 실제 연결 범위는 [HUD 구현](../presentation/ui/hud.md)에 기술한다. 목표 구조에서도 입력 제한, 시뮬레이션 정지, 카메라 제어는 서로 다른 요청이다. 대화창을 열었다고 무조건 시간을 멈추지 않는다.

입력 제한은 활성 요청을 합성하고, 전투 입력·상호작용·대화 선택·UI 내비게이션을 구분한다. 시간 제어는 공통 시계 경계 한곳에서 적용하며 정지 요청이 남아 있으면 다른 창의 종료로 재개하지 않는다. 실험 슬로모션과 정지 요청도 같은 경계에서 조율한다. 표현·텍스트 표시·GUI는 지정된 표현 시계나 비스케일 시간을 사용할 수 있다.

예를 들어 대화가 전투 입력 제한 A를 보유하고 일시정지 창이 제한/정지 B를 보유하면, 일시정지 창을 닫을 때 B만 반환한다. A가 남아 있으므로 공격 입력은 여전히 제한된다. 같은 방식으로 연출이 끝나도 이미 열린 모달의 제어권은 유지한다.

사망·런 종료·씬 전환은 세션 수명 경계에서 대화·연출·화면을 종료하고 해당 소유자의 요청을 회수한다. 입력 차단 중 눌린 공격이 해제 직후 예약 실행되지 않도록 입력 edge/예약 처리 계약을 둔다. 구체적인 대화 중 일시정지·뒤로가기·피격 우선순위는 기획/화면 정책으로 선언하며 각 뷰가 개별 추측하지 않는다.

## 6. 데이터·실험·이행

안정적인 ID와 스키마 버전을 사용하는 다음 정의를 추가한다. 목표 폴더와 원본/생성물 경계는 [데이터 배치](project-structure.md#2-저장소와-데이터-배치)를 따른다. 실제 스키마는 구현 전 확정하고 한 항목에 편집 원본을 두 개 만들지 않는다.

| 정의 | 원본 경계 |
|---|---|
| Cue·카메라 반응 | 재생 시간·오프셋·강도와 아트/음향 참조를 분리. 전투 시간·판정 원본은 계속 `data/combat/` |
| NPC·대화 | NPC ID, 대화 노드/조건/명령, 텍스트 키. 대사 문구와 아트 참조는 별도 바인딩 |
| 시퀀스 | 단계·바인딩 요구사항·스킵/취소 정책. 담당 도메인의 규칙을 복제하지 않음 |
| GUI | 화면 등록·표시 계약·테마와 프리팹. 런타임 데이터는 읽기 모델에서 제공 |

정의와 실행 상태를 분리하고 대화/시퀀스 실행은 시작한 정의 버전을 유지한다. 실행 중 편집은 다음 재생 또는 명시적 세션 재시작에 적용한다. 기존 공유 아트나 프리팹 GUID를 유지하며 실제 런 상태를 건드리지 않는 미리보기 서비스를 사용한다.

실험장에는 Cue 단독 재생·반복, 타격 동기화 A/B, 카메라 반응 비교를 추가한다. 대화는 임시 사실 집합과 선택지 경로를, 시퀀스는 가짜 도메인 명령과 필수 앵커를, GUI는 샘플 읽기 모델을 사용해 독립적으로 미리볼 수 있게 한다. 정상 완료뿐 아니라 누락 에셋·취소·스킵·중첩 모달·씬 전환도 재현한다.

이행은 다음 순서를 권장한다.

1. 현재 HUD의 입력/일시정지 제어를 소유자 핸들 방식으로 이전하고 기존 동작을 검증한다.
2. 기존 타격 이펙트에 Cue 정의·재생 핸들을 연결하고 실험장에서 시간·크기·위치를 조정한다.
3. NPC 상호작용 1개와 직선 대화 1개를 임시 데이터로 연결해 세션/UI/조건 조회 경계를 검증한다. 실제 신규 대사를 확정하지 않는다.
4. 대화→카메라→페이드의 작은 시퀀스로 완료·취소·스킵 정책을 검증한다.
5. 필요한 화면·분기·연출 단계만 추가하고 검증된 경계를 기준으로 어셈블리를 분리한다.

## 7. 검증 계약

아래는 구현 시 수행할 검사이며 실행 완료 결과가 아니다.

- Cue 교체·중단·누락이 타격 시각·피해·쿨타임을 변경하지 않음. 필수 표현 누락은 별도 검증에서 검출.
- 반복 효과·음향·카메라 요청이 리셋/풀 반환 뒤 남지 않으며 취소 후 비동기 완료가 재생을 부활시키지 않음.
- 대화 선택 시 조건 재검사, 이전 세션 입력 거부, 동일 선택/명령 중복 방지, 명령 실패 시 분기 결과가 명시됨.
- 대화와 모달/일시정지/연출이 겹쳐도 한 소유자의 종료가 다른 소유자의 입력·시간·카메라 요청을 해제하지 않음.
- 연출 완료·스킵·취소·실패에서 제어 반환과 도메인 명령 횟수가 계약에 맞음. 미리보기는 실제 진행 상태를 변경하지 않음.
- NPC 뷰 언로드/재로드가 이야기 사실을 초기화하지 않으며 필요한 앵커 누락은 고정/생성 맵 모두에서 검출.
- 화면 뒤로가기·포커스 복귀·키보드/패드 탐색·클릭 입력 소비, 해상도/텍스트 길이 변화, 바인딩 해제와 늦은 콜백을 검사.
