# 잉크 파츠 이펙트 실험실

MVP 잉크 파츠 20종의 아이콘을 누르면 그 파츠를 끼우고, 파츠가 발동하는 상황(몬스터 적중·무기 교체·표식 격발·처치)을 1Stage 무대에서 자동으로 한 번 보여 주는 브라우저 시험장이다. 그다음엔 직접 움직이며 쳐 볼 수 있다. 이펙트 후보를 게임 상황 안에서 비교·판단하려는 것이며, 게임 규칙·수치의 원본이 아니다. Unity에 연결하지 않았다.

- 빌드: `COMBAT_REPO=<그림이 있는 체크아웃> node build.cjs` → 같은 폴더에 `이펙트실험실.html`(에셋 내장 단독 파일, Git 제외). 더블클릭으로 연다.
  - 이 워크트리는 PNG를 추적하지 않으므로 주인공·몬스터·배경·아이콘 그림은 `COMBAT_REPO`(보통 메인 체크아웃)에서 읽는다.
  - 이펙트 시트는 이 워크트리의 Git 제외 `outputs/pixelfx/`에서 읽는다(`FX_SHEETS`로 바꿀 수 있다). 없으면 각 이펙트 폴더(`../표식격발`, `../덧베기`, `../이동속도`, `../회복`, `../보호막`, `../속박`, `../둔화`, `../끌어당김`, `../다음공격강화`, `../파열가시`)의 `export.mjs`로 먼저 뽑는다.
- 입력: 파츠 이름·설명·색·트리거는 `unity/Assets/Deviant/Combat/Resources/WeaponGrowthMvp.json`, 아이콘은 임시 GUI `TemporaryGUI/Pixel/ink-<id>.png`, 무대는 [손맛 테스트](../손맛/README.md)와 같은 CharacterV2(검·망치)·Stage1Monsters·마을 스케치 배경, 피격 밀림은 `data/combat/enemy_hit_reaction.json`.
- 조작: A D 이동, J·클릭 공격, Q 무기 바꾸기(바꾼 무기가 곧바로 자동 공격), H 내가 맞기(보호막 확인), T 느리게(1×→0.5×→0.25×), Backspace 처음부터. 「여러 파츠 같이 끼우기」를 켜면 아이콘을 눌러 여러 개를 함께 끼운다.

## 실험실에서만 정한 것

- 표식: 무기 A(검)로 맞히면 몬스터 머리 위에 하나씩 쌓이고(최대 5개, 8초), 무기 B(망치)로 맞히면 터진다(격발, 피해 10). 표식을 누가 주는지는 기획 미정이라 이전 미리보기와 같은 가정을 썼다.
- 파츠는 두 무기에 함께 적용된다. 장착 수 제한은 없다. 내부 쿨타임은 `weapon-growth-mvp-tuning.md` 표 값이고, 대상별 쿨타임은 구분하지 않는다.
- 몬스터 체력은 처치가 잘 보이도록 일반 90, 엘리트 200으로 낮췄다. 몬스터는 공격하지 않는다.
- 원타격 → 덧베기 0.1초, 격발 → 파열 가시 0.375초는 미리보기 가정값이다(데이터 없음).
- 끌어당김 줄 시트는 72px 거리 기준이라 실제 거리에 맞춰 가로로 늘려 그린다.
- 「표식을 터트릴 시」 파츠를 끼우면 격발이 그 파츠 색 판(`mark-burst_<색>_m<n>`)으로 터진다. 여러 색을 함께 끼우면 덩어리마다 색이 섞인 판(`mark-burst_<색-색…>_m<n>`)으로 터진다.
- 쿨타임 감소 두 파츠·인계된 사거리는 이펙트를 두지 않기로 해서 기록 줄에만 나온다. 파열의 여백은 파랑 격발만 나온다. 사거리·반경은 실제 판정 거리를 늘려 흉내 낸다.
- 흡혈(생명 회수)·가벼운 발끝·무거운 발목은 「칠 때마다 터져 시끄러운가」를 보려고 일부러 매번 이펙트를 튼다(정리 보류 항목).

## 확인한 범위

브라우저(내장 미리보기)에서 20종 각각의 상황 재생을 프레임 단위로 돌려 오류가 없고, 의도한 시트가 생기는 것을 확인했다(덧베기 칼자국, 강해진 한 방, 격발 → 파열 가시, 처치 → 기운 → 강한 한 방, 이속 시작·줄기·끝, 회복 고리, 보호막 생김·유지·깨짐, 둔화 물결·물들임, 끌어당김 줄과 32px 이동, 속박 말뚝과 1초 고정, 쓰러진 자리에서 당기기). 몇 장면은 화면을 떠서 봤다. 사운드·다른 브라우저·느린 컴퓨터에서의 속도는 확인하지 않았다.

## 게임(Unity)에 붙여 보기

실험실에서 고른 연결을 1장 게임에도 시험으로 붙였다. 규칙·수치는 바꾸지 않고 보여 주기만 한다.

- `CombatArena.MvpInk.cs`의 `MvpInkCued` 신호: 파츠가 발동한 순간(파츠 id·색·발동 조건·효과 종류·대상·맞은 자리·지속시간)과, 파츠와 별개인 순간(`detonate` 표식 수·끼운 「표식을 터트릴 시」 파츠 색, `power_release` 강화된 공격 시작, `power_hit` 강화된 공격 적중, `pull_target` 끌려간 대상)을 알린다. `ReadMvpBuff(stat)`로 이속·강화 버프가 남았는지 읽는다.
- `ForestCombatV2/Runtime/Chapter1InkPartFx.cs`: 신호를 받아 `Resources/InkPartFx/<이름>.png + .json`을 잘라 튼다(PPU32, 오른쪽 기준 시트를 맞은 방향으로 반전, 전투 시계를 따라 피격 멈춤에 같이 멈춤). 반복 시트(이속 줄기·보호막·둔화 물결·기운)는 조건이 끝나면 0.2초 흐려진다. 시트가 없으면 아무것도 하지 않는다. `Chapter1RunBinding`이 붙인다.
- `ForestCombatV2/Runtime/Chapter1InkFxTrialKeys.cs`: 에디터·개발 빌드 전용. **F9**를 누를 때마다 적중 → 무기 교체 → 표식을 터트릴 시 → 처치 순서로 파츠 다섯 개 세트를 두 무기에 바로 끼운다(새 5칸 팔레트).
- 시트 그림: 리소스 저장소 `effects/ink-parts/runtime/<이펙트>/`(에셋 `effects.ink-parts`)에 등록했고, `docs/assets/manifests/unity-deployment.json`이 PNG 180장을 `unity/Assets/ForestCombatV2/Resources/InkPartFx/`로 배치한다. 받는 쪽은 `python tools/assets/update_assets.py`만 실행하면 된다. 같은 폴더의 JSON(장 크기·피벗)과 `.meta`(스프라이트·PPU32·점 필터·압축 끔)는 메인이 추적한다.
- 시트를 다시 뽑았을 때: 각 `export.mjs`로 `outputs/pixelfx`를 갱신 → 리소스 저장소 `effects/ink-parts/runtime/`에 그대로 복사하고 `python tools/index_ink_parts.py`(리소스 루트) → 리소스 커밋·push → 메인에서 배치 계약의 해시·바이트와 같은 폴더 JSON 을 맞추고 `resources` 기준점을 갱신한다.
- 확인: Unity 6000.6.5f1 에서 `Chapter1Title`로 시작해 1장 런에 들어가 F9 로 세트를 끼우고 친다. 훈련장(더미)에서 칼 세 번 → 교체 → 격발 장면을 찍어 덧베기·둔화·보호막·이속·세 색 격발·파열 가시·속박이 그려지는 것을 봤다.
- 알려진 제한: 기존 상태 표시(보호막 캡슐·둔화 고리·머리 위 보라 표식)와 겹쳐 그려진다. 머리 위 표식을 우리 방울로 바꾸면 `InkStatusVisualTests`가 깨져 그대로 뒀다. 둔화 몸 물들임은 아직 없다. 파열 가시는 피해가 들어가는 순간보다 0.375초 늦게 보인다(격발에 묻히지 않게 한 미리보기 가정).
