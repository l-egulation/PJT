## 1. 목적

이 문서는 보석 콘텐츠의 기능, 구현 가능한 요구사항과 필요한 API 목록을 정의한다. 현재 게임 규칙은 [보석 SSOT](../../30-domain/gems/ssot.md)가 소유하고, 버전별 옵션·보상·기준 빌드 수치는 [MVP 보석·던전 수치 v1](../../60-content/gems/mvp-v1.md)이 소유한다. 이 문서는 규칙과 수치의 두 번째 정본을 만들지 않고 구현 범위, 데이터 책임, 원자성, 검증 기준과 추적성을 정의한다.

## 3. 범위

### 3.1 포함 범위

- 보석 콘텐츠 해금과 초기 상태 부여
- 보석 보유, 프리셋 슬롯, 장착 교체, 해제
- 보석 옵션의 전투 스탯 반영
- 보석함 개봉과 보석 지급
- 같은 레벨 보석 합성
- 보석 던전 입장권 충전, 보유, 소비
- 시간 슬롯 보스 순환, 보스별 단계 진행, 신규 단계 도전
- 최초 클리어 보상과 소탕 보상
- 거래 가능한 보석과 거래 불가 보석함의 경제 시스템 연계
- 계정 공용 인벤토리 슬롯 점유와 공간 부족 사전 검사
- 재시도, 중복 요청, 실패·사용자 중단·앱 종료·연결 끊김 상황의 원자성·멱등성
- 클라이언트와 서버 사이에 필요한 보석 콘텐츠 API 목록과 요구사항 연결

### 3.2 제외 범위

- 정식 v2 이후 장기 분포 재검증과 보석 포함 3-1~4-10 메인 스테이지 적 수치 재산출
- P10·P50·P90 장기 성장 분포 시뮬레이션
- 실제 UI 화면 배치와 접근성 세부안
- 운영 배포, 모니터링, 어드민 툴 구현

제외 범위의 수치 산출과 승격 조건은 [보석 콘텐츠 수치화 계획](./requirements.md)과 [MVP 보석·던전 수치 v1](../../60-content/gems/mvp-v1.md)의 승격 조건을 따른다.

## 5. 기능 요구사항

### 5.1 해금과 초기 상태

| ID | 요구사항 | 검증 |
| --- | --- | --- |
| GEM-UNLOCK-001 | 계정 진행이 [보석 SSOT](../../30-domain/gems/ssot.md)의 해금 조건을 만족하면 보석 콘텐츠, 6슬롯 프리셋 4개, 보석 던전을 같은 트랜잭션 또는 같은 멱등 처리 단위로 연다. | 해금 조건을 처음 만족한 계정에서 보석 콘텐츠 접근, 메인·생존형·폭주형·장갑형 프리셋 조회, 던전 접근이 모두 가능하다. |
| GEM-UNLOCK-002 | 최초 해금 보상은 계정당 한 번만 지급한다. | 같은 해금 이벤트나 재시도 요청이 반복되어도 초기 입장권 보유량이 중복 증가하지 않는다. |
| GEM-UNLOCK-003 | 해금 전 계정은 보석 장착, 합성, 보석 던전 입장, 소탕을 실행할 수 없다. | 해금 전 호출은 상태를 바꾸지 않고 명확한 실패 결과를 반환한다. |

### 5.2 보석 보유와 슬롯

| ID | 요구사항 | 검증 |
| --- | --- | --- |
| GEM-SLOT-001 | 계정은 메인 스테이지·생존형·폭주형·장갑형 콘텐츠마다 독립된 6슬롯 프리셋 하나를 가진다. | 해금 후 네 프리셋과 각 6개 슬롯을 조회할 수 있다. |
| GEM-SLOT-002 | 옵션 종류는 슬롯 장착 가능 여부를 제한하지 않는다. | 각 옵션 계열 보석을 네 프리셋의 빈 슬롯과 기존 프리셋 슬롯에 장착할 수 있다. |
| GEM-SLOT-003 | 같은 보석 인스턴스를 여러 프리셋에 등록할 수 있다. | 하나의 보석을 두 개 이상의 프리셋에 등록해도 인벤토리 수량이 복제되지 않는다. |
| GEM-SLOT-004 | 메인 스테이지 전투에는 메인 프리셋을, 보석 던전에는 현재 열린 시간 슬롯의 보스 유형과 일치하는 프리셋을 적용한다. | 각 전투 스냅샷에 해당 콘텐츠와 일치하는 프리셋의 보석만 포함된다. |
| GEM-SLOT-005 | 장착 교체는 기존 슬롯과 새 보석의 소유권, 잠금 상태, 거래 상태를 검증한 뒤 원자적으로 반영한다. | 교체 실패 시 기존 프리셋과 보유 상태가 유지된다. |
| GEM-SLOT-006 | 장착 해제는 보석을 잃지 않고 해당 프리셋의 참조만 제거한다. | 한 프리셋에서 해제해도 다른 프리셋의 등록은 유지된다. |
| GEM-SLOT-007 | 어느 프리셋에든 등록된 보석은 장착 중으로 취급하고, 모든 프리셋에서 해제하기 전에는 합성 또는 거래 등록 입력으로 사용할 수 없다. | 복수 프리셋 중 하나에라도 남은 보석의 합성·거래 등록 요청은 상태 변경 없이 실패한다. |
| GEM-SLOT-008 | 메인 프리셋은 언제든 변경할 수 있다. 메인 스테이지 진행 중 변경하면 현재 전투를 종료하고 변경된 프리셋으로 현재 스테이지의 일반 몬스터 0/20부터 다시 시작한다. | 일반 몬스터·보스 전투 중 변경 모두 현재 사이클을 종료하고 0/20, 최대 HP, 초기 공격·스킬 상태로 재시작하며 이미 받은 보상은 유지한다. |
| GEM-SLOT-009 | 현재 열린 보스 프리셋은 보석 던전 도전 시작 전까지 변경할 수 있고, 도전 시작부터 성공·실패·사용자 중단·앱 종료·연결 끊김으로 종료될 때까지 변경할 수 없다. | 도전 중 해당 프리셋 변경 요청은 상태 변경 없이 실패하고 전투에는 도전 시작 시점 구성이 유지되며, 종료 후에는 다시 편집할 수 있다. |
| GEM-SLOT-010 | 사용자는 자신이 소유하고 거래 등록 중이 아닌 보석을 개별적으로 잠그거나 잠금 해제할 수 있다. | 소유 보석의 잠금 상태가 저장되고 타 계정·거래 등록 중 보석의 잠금 변경은 상태 변경 없이 실패한다. |
| GEM-SLOT-011 | 잠긴 보석은 프리셋에 등록하거나 등록 상태를 유지할 수 있지만 수동·일괄 합성과 거래 등록에는 사용할 수 없다. | 잠긴 보석의 장착은 허용되고 합성·거래 등록은 거부된다. |
| GEM-SLOT-012 | 보석함 개봉 또는 합성 결과를 지급할 때 고정 공격력·고정 최대 HP 보석은 미잠금, 공격력%·고정 방어 관통·치명타 확률·공격속도 특수 옵션 보석은 잠금 상태로 생성한다. | 모든 획득 경로에서 고정 옵션은 미잠금이고 특수 옵션은 자동 잠금된다. |
| GEM-SLOT-013 | 자동 잠금된 특수 옵션 보석도 사용자가 직접 잠금 해제할 수 있다. | 잠금 해제 후 프리셋 미등록·미판매 상태이면 합성 또는 거래 등록 대상으로 사용할 수 있다. |

### 5.3 전투 스탯 반영

| ID | 요구사항 | 검증 |
| --- | --- | --- |
| GEM-STAT-001 | 메인 전투에는 최신 메인 프리셋을, 보석 던전에는 도전 시작 시점에 확정한 보스 프리셋을 스탯 스냅샷으로 반영한다. | 다른 프리셋과 보유만 한 보석은 해당 전투 스탯을 바꾸지 않고, 도전 중 보석 던전 스냅샷은 변하지 않는다. |
| GEM-STAT-002 | 고정 옵션과 특수 옵션의 중복 처리, 합산 순서, 상한은 [보석 SSOT](../../30-domain/gems/ssot.md)와 [MVP 보석·던전 수치 v1](../../60-content/gems/mvp-v1.md)을 따른다. | 같은 특수 옵션 여러 개와 서로 다른 특수 옵션 조합의 결과가 기준 문서와 일치한다. |
| GEM-STAT-003 | 보석 보너스는 전투 중 런타임에서 플레이어 상태에 따라 임의로 조정되지 않는다. | 동일 콘텐츠 버전, 동일 장착 상태, 동일 전투 입력은 같은 보석 스탯 결과를 만든다. |
| GEM-STAT-004 | 보석 옵션 추첨과 전투 반영은 콘텐츠 버전 식별자를 저장하고 재현 가능해야 한다. | 저장된 콘텐츠 버전과 seed로 옵션 결과를 재계산할 수 있다. |

### 5.4 보석함 개봉

| ID | 요구사항 | 검증 |
| --- | --- | --- |
| GEM-BOX-001 | 보석함은 거래할 수 없는 계정 귀속 자원으로 저장한다. | 거래 등록 요청에서 보석함이 거부된다. |
| GEM-BOX-002 | 사용자는 보석함 개봉 수량을 1개, 보유 수량 이내의 지정 수량 또는 전체로 선택할 수 있다. | 1개, 일부 수량, 전체 수량 요청이 정확한 개수만 처리하고 0개·초과 수량 요청은 상태 변경 없이 실패한다. |
| GEM-BOX-003 | 일괄 개봉은 선택한 보석함 전체 소비와 결과 보석 전체 지급을 하나의 원자적 결과로 처리한다. | 중간 실패나 재시도에서 일부 보석함만 사라지거나 보석이 일부·중복 지급되지 않는다. |
| GEM-BOX-004 | 여러 개를 열 때 결과 레벨과 옵션은 보석함마다 독립적으로 추첨하고, 결과 목록을 한 번에 반환한다. | 요청 수량과 결과 보석 수가 같고 각 결과가 개별 seed 또는 재현 토큰으로 재현된다. |
| GEM-BOX-005 | 결과 레벨 확률과 옵션 풀은 [보석 SSOT](../../30-domain/gems/ssot.md)와 [MVP 보석·던전 수치 v1](../../60-content/gems/mvp-v1.md)의 콘텐츠 버전을 따른다. | 고정 seed 기반 표본과 경계 seed에서 결과가 재현된다. |
| GEM-BOX-006 | 개봉으로 지급된 보석은 보석 거래 규칙의 대상이며 특수 옵션이면 자동 잠금된다. | 고정 옵션 결과는 미잠금, 특수 옵션 결과는 잠금 상태로 저장되고 사용자가 해제한 뒤 거래 등록할 수 있다. |

### 5.5 합성

| ID | 요구사항 | 검증 |
| --- | --- | --- |

| GEM-INV-006 | 성공 보상은 예약한 스택 슬롯 또는 빈 슬롯에 지급하고, 실패·사용자 중단·앱 종료·연결 끊김은 보상 수용량 예약을 해제한다. | 모든 종료 경로에서 예약이 누수되지 않고, 성공 시 보석함 지급과 예약 정리가 함께 확정된다. |

| 흐름 | 원자적으로 함께 처리할 상태 |
| --- | --- |
| 보석함 개봉 | 필요 슬롯 검사, 보석함 소비, 레벨·옵션 추첨, 보석 지급, 요청 결과 기록 |

| 보석 던전 성공 | 도전 상태 성공 확정, 입장권 차감, 보석함 지급, 보스별 최고 클리어 단계 갱신, 단계별 최초 보상 수령 상태 갱신, 보상 수용량 예약 정리, 요청 결과 기록 |
| 거래 등록 | 보석 거래 등록 상태 반영, 거래소 등록 상태 생성 |

모든 원자 처리 흐름은 같은 멱등 키의 재시도에서 중복 소비나 중복 지급을 만들지 않아야 한다.

계정당 진행 중인 도전은 하나만 허용한다. 시작 API는 서버 전투 계산 결과와 사건 로그를 저장한 뒤 반환하고, 완료 API는 서버가 저장한 결과만 확정한다. `minimumCompleteAt` 전 완료 요청은 거부하며 `expiresAt`이 지난 도전은 미차감·미보상 중단으로 정리한다.

보석 던전 성공 처리 중 하나라도 실패하면 위 상태를 모두 롤백하며, 같은 멱등 키로 재시도하면 이미 기록된 성공 결과를 반환하거나 모든 상태가 한 번만 함께 확정되어야 한다.

## 9. 오류 처리 요구사항

- 해금 전 요청은 상태 변경 없이 실패한다.
- 보유하지 않은 보석, 타 계정 보석, 어느 프리셋에든 등록된 보석, 거래 등록 중인 보석, 잠금 보석을 소비 입력으로 받은 요청은 상태 변경 없이 실패한다.
- 입장권 부족 상태의 보상 수령 또는 소탕 요청은 상태 변경 없이 실패한다.
- 콘텐츠 버전이 누락되었거나 알 수 없는 옵션·보상 테이블을 참조하는 요청은 상태 변경 없이 실패한다.
- KST 시간 슬롯 전환과 새 요청 처리가 겹치는 경우 서버가 확정한 요청 처리 시각으로 새 도전의 보스와 콘텐츠를 결정하고, 이미 진행 중인 도전은 시작 스냅샷을 유지한다.
- 진행 중인 보석 던전의 해당 보스 프리셋 변경 요청은 상태 변경 없이 실패한다.
- 거래 등록 중인 보석의 잠금 변경과 잠긴 보석의 합성·거래 등록 요청은 상태 변경 없이 실패한다.
- 진행 중인 보석 던전에서 앱 종료 또는 연결 끊김을 감지하면 사용자 중단으로 종료하고 보상·입장권을 변경하지 않으며 프리셋 잠금을 해제한다.
- 이미 진행 중인 도전이 있으면 새 도전을 만들지 않는다. 만료된 도전이 있으면 먼저 자동 중단과 예약 해제를 수행한 뒤 새 요청을 평가한다.
- 클라이언트가 승패·피해량·보상 수량을 제출해도 결과 권한으로 사용하지 않는다.
- 보석함 개봉·합성에 필요한 순슬롯이 부족하면 소비·추첨·지급을 시작하지 않고 상태 변경 없이 실패한다.
- 기존 보석함 스택의 지급 권리와 예약 가능한 빈 슬롯이 모두 없으면 보석 던전 도전을 시작하지 않는다.
- 실패 응답은 클라이언트가 사용자에게 재시도 가능 여부를 구분해 표시할 수 있도록 원인 코드를 포함한다.

## 10. 검증 기준

### 10.1 확정 규칙 검증

- 해금 조건 충족 전후의 접근 가능 기능이 [보석 SSOT](../../30-domain/gems/ssot.md)와 일치한다.
- 초기 지급, 1개·지정 수량·전체 보석함 개봉, 합성, 최초 클리어, 소탕 흐름은 재시도에서 중복 결과를 만들지 않는다.
- 입장권 충전은 서버 실제 경과시간과 최대 보유량 규칙을 만족한다.
- 실패·사용자 중단·앱 종료·연결 끊김은 입장권과 보상을 소비하지 않는다.
- 보스 유형 순환은 같은 시간 슬롯, 같은 콘텐츠 버전에서 전 계정에 동일하게 적용된다.
- 보스별 단계 진행과 최초 보상 상태는 서로 독립이다.
- 세 보스의 1단계는 1-5 목표 성장 빌드가 무보석으로 클리어 가능하고, 장비·스킬 성장이 부족하면 실패할 수 있다.
- 단계별 권장 빌드는 모든 검증 seed에서 성공해야 하며, 최악의 seed에서 간신히 성공하는 경계값까지 허용한다.
- 밸런스 기준 스킬은 연결 성장 구간에서 정상 획득·성장 가능한 구성을 사용하되 실제 던전은 플레이어의 도전 시작 시점 장착 스킬을 변경 없이 스냅샷한다.
- 밸런스 기준 보석은 생존형 HP, 폭주형 공격·치명타·공격속도, 장갑형 방어 관통·공격 중심의 보스별 특화 구성을 사용하며 실제 장착을 강제하지 않는다.
- 연결 구간이 없는 8~10단계의 밸런스 기준 스킬은 4-10 기준을 유지한다.
- 장갑형은 권장 관통 빌드에서 약 75% 피해 효율, 관통이 크게 부족한 빌드에서 기존 공식 하한인 약 50%에 가까운 효율이 되도록 방어력을 산출하며 별도 방어막을 추가하지 않는다.
- 권장 미달 표본은 현재 단계보다 한 단계 낮은 권장 빌드다.
- 같은 특수 옵션과 서로 다른 특수 옵션의 장착 결과가 기준 문서와 일치한다.
- 정각 전 시작한 보석 던전 도전은 다음 시간 슬롯에서도 시작 스냅샷으로 결과를 확정하고, 종료 후 새 요청부터 새 시간 슬롯 보스를 적용한다.
- 보석 던전 성공은 도전 상태, 입장권, 보상, 최고 클리어 단계, 최초 보상 상태와 보상 수용량 예약을 모두 함께 확정하며, 중간 실패는 전부 롤백하고 같은 요청의 재시도는 기록된 결과를 반환한다.
- 기존 보석함 스택 슬롯의 지급 권리를 예약한 뒤 다른 흐름이 스택을 0개로 소비하고 슬롯 재사용을 시도해도 성공 보상 수용량이 유지된다.
- 메인 프리셋은 전투 중에도 변경할 수 있고, 변경 후 현재 스테이지가 일반 몬스터 0/20부터 초기 상태로 재시작한다.
- 보석 던전 프리셋은 도전 시작 전에만 변경할 수 있고 도전 종료 전까지 시작 시점 구성이 유지된다.
- 보석은 거래 가능하고 보석함은 거래 불가하다.

### 10.2 working 수치 검증

- 옵션 값, 보석함 확률, 단계별 보상, 기준 빌드와 정식 v2 던전 수치는 [MVP 보석·던전 수치 v1](../../60-content/gems/mvp-v1.md)의 해당 권한 상태와 일치해야 한다.
- 정식 v2 절대 수치는 `applied`다. 장기 성장 분포와 보석 포함 메인 적 수치는 [보석 콘텐츠 수치화 계획](./requirements.md)의 남은 검증이 완료되기 전까지 `working`이다.
- P10·P50·P90 성장 분포, seed별 치명타·공격속도 결과, 장시간 입장권 타이머 드리프트는 후속 시뮬레이션 검증 항목으로 남긴다.

### 10.3 인수 시나리오

1. 신규 계정이 보석 해금 전까지 보석 UI와 던전에 접근하지 못한다.
2. 해금 조건을 만족하면 보석 슬롯과 던전이 열리고 초기 입장권이 한 번만 지급된다.
3. 현재 시간 슬롯의 보스 1단계를 무보석으로 도전해 최초 클리어하면 입장권이 소비되고 보석함을 획득한다.
4. 보석함을 1개, 지정 수량 또는 전체로 개봉하면 선택 수량만큼 독립 추첨된 보석을 한 번에 받고, 보석을 장착하면 전투 스탯에 반영된다.
5. 같은 레벨 보석을 합성하면 입력이 소비되고 결과 레벨의 옵션 풀로 새 보석이 지급된다.
6. 현재 시간 슬롯 보스의 신규 단계를 클리어하면 입장권이 소비되고 보스별 진행과 최초 보상 상태가 갱신된다.
7. 최고 클리어 단계가 있는 현재 보스는 최고 클리어 단계만 소탕할 수 있고, 소탕 보상은 최초 클리어 보상과 구분된다.
8. 실패·사용자 중단·앱 종료·연결 끊김은 입장권과 보상을 바꾸지 않는다.
9. 보석은 거래소에 등록할 수 있고, 보석함은 등록할 수 없다.

## 13. 완료 정의

- 이 문서의 포함 범위 요구사항이 구현 항목으로 분해되어 누락 없이 추적된다.
- 필요한 API 목록의 각 항목이 담당 GEM 요구사항 묶음과 연결된다.
- 확정 규칙 검증 항목이 자동 테스트 또는 인수 시나리오로 검증된다.
- working 수치 항목은 applied로 오인되지 않게 콘텐츠 버전과 결정 상태를 표시한다.
- 보석 도메인은 아이템, 전투, 거래소 규칙을 재정의하지 않고 해당 SSOT를 참조한다.
- 보상 지급, 합성, 보석함 개봉, 거래 등록의 중복 소비·중복 지급 방지가 검증된다.
