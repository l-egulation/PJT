# 보상 선택 UI

[UI·입력 구현](README.md) · [보상 규칙](../../../design/run/rewards.md)

1·2챕터의 `SketchRunBinding`에 연결된다. 추첨·지급·등록은 기존 `SketchEquipment` / `SketchRunState`를 사용한다. 일반 보상은 G로 받아 둔 기회를 열 때, 보스 보상은 실제 보스 처치 흐름에서 표시한다.

## 화면과 데이터

현행 [Figma 시안](https://www.figma.com/design/mcPMyUIW47K4QmJfcdHAoC)의 보상/획득 구조를 960×540 좌표로 그리며 화면 비율을 유지한다. 꾹꾹체, 회색 암전, 노란 선택 이름, 팔레트 슬롯은 승인 테마 리소스를 사용한다. 암전은 증강 창과 같은 `ApprovedTheme.MenuBackdrop`을 사용한다. 보상과 증강의 세 카드 모두 너비 230으로 통일하며 각 화면에서 후보마다 같은 본문 폭을 사용한다. 선택한 아이콘은 70→76으로 작게 확대하고 나머지는 60% 농도로 표시한다. 선택한 이름은 공통 포인트 노랑(#D9CB84)으로 표시하며 카드 전체를 감싸는 금색 테두리는 사용하지 않는다. 비선택 글씨는 74% 농도로 표시한다. 종류 라벨에는 붓칠을 표시하지 않는다.

실제 후보의 이름·스킬명·설명·강화 슬롯, 잉크 ID·효과 설명을 표시한다. 스케치의 정보는 기본 공격, 스킬 이름과 설명, 팔레트 순서로 나누어 표시한다. 긴 설명과 팔레트는 각 후보의 독립적인 스크롤 영역에 들어간다. 무기/잉크 아이콘의 크기가 달라도 이름 행은 고정된다. 실제 후보 데이터가 없으면 미리보기 샘플로 대체하지 않는다.

배치는 보상 선택 창을 기준으로 증강에도 적용한다. 960×540 기준 카드 y=120, 높이 350, 너비 230이며 종류·아이콘·이름·구분선·설명·선택 행동의 행을 공유한다. 이름은 선택 여부와 관계없이 20 크기로 고정하고, 아이콘은 70→76으로 확대한다. 증강의 효과와 대가는 설명 영역 안에서 스크롤한다. 배경 농도의 기준은 증강을 유지하며, 보상 화면도 실제 게임에서는 증강과 동일한 uGUI 전체 화면 가림막을 공유하고 IMGUI 암전을 겹치지 않는다. uGUI가 없는 독립 화면은 자체 암전을 유지한다. Linear 프로젝트의 두 렌더링 방식에서 같은 색상 값만 사용하는 것으로 실제 합성 농도가 같다고 판단하지 않는다.

무기는 선택 즉시 미확정 상태로 가방에 들어가며 잉크는 실제 규칙의 부여 횟수를 더한다. 추가 획득 영수증·가방 넣기·구성 선택은 띄우지 않는다. 필요하면 가방을 다시 열어 구성한다. 확정한 무기는 빈 칸도 수정할 수 없다.

## 조작과 일시정지

좌우로 후보를 바꾸고 F로 선택·획득한다. 선택 카드 아래에 [F] 선택하기를 표시한다. 공용 리롤이 있는 런은 R 또는 하단 리롤 버튼을 제공한다. ↑/↓는 선택한 후보 설명만 스크롤하며 W/S와 휠도 유지한다. 세로 입력으로 선택 카드나 하단 행동 포커스를 옮기지 않는다. 공통 입력의 패드 Navigate/Submit도 유지한다. 후보가 화면에 처음 나타난 프레임의 F·확인 입력은 그 보상을 연 입력(예: F로 연 잠긴 상자)으로 보고 카드를 획득하지 않는다. F를 새로 눌러야 획득한다.

마우스는 눌렀다가 같은 영역에서 놓으면 실행한다. 고정된 포인터가 키보드 선택을 덮어쓰지 않는다. 가방 비교 중에는 같은 후보·선택·스크롤을 유지하며, 아직 선택하지 않은 보상은 Esc로 버릴 수 없다. 대기 보스 보상은 현재 후보를 지급한 직후 표시한다. 각 흐름의 일시정지 범위는 기존 바인딩이 소유한다.

## 승인 에셋 연결

`Deviant.UI.Theme.ApprovedTheme`는 고정 리소스 배포 경로 `Resources/ApprovedTheme`의 폰트·프레임·팔레트·36종 잉크 합성 이미지를 읽는다. 승인 무기 그림이 없을 때만 기존 스킬별/종별 그림을 사용한다. 경로는 다음 순서다.

- 무기: 승인 `ui-assets-v2/{formId}` → `SketchRewardArt/Weapons/{formId}/{skillId}` → `SketchRewardArt/Weapons/{formId}` → `ApprovedItemIcons/{formId}`.
- 잉크: 승인 manifest의 실제 잉크 ID 합성 → 생성 `RunInks.json`의 icon → 기존 아이콘.

원본·폰트는 리소스 저장소에서 관리하고 메인 배포 매니페스트로 적용한다. 로컬 UI design 경로와 프리뷰 fixture를 제품 로더에 연결하지 않는다.

## 검증

`SketchRewardChoiceScreenTests`는 실제 보상 모델을 사용해 후보 유지·중복 선택 방지·잉크 등록·대기 보스 보상, 푸터 가방 왕복과 포인터 좌표를 확인한다. 게임 아트가 필요한 챕터 검사는 `SketchRunBindingTests`와 `RunInkSceneTests`를 사용한다. 시각·입력·일시정지는 실제 장면에서 별도로 확인한다.

공속 빨강 3종은 현재 RunInks 카탈로그의 이름·설명을 사용하며 승인 빨강 병·상태 조건 문양에 기존 공속 문양을 합성한다. 고정 원본의 36종 그림을 수정하지 않고 런타임의 가방·제작·보상·상점에 같은 합성 아이콘을 제공한다.
