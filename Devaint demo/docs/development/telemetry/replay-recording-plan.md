# 용량 절감을 우선한 리플레이 기록 구현 계획

[분야 개요](README.md)

## 범위와 상태

[리플레이 기록 명세](replay-recording.md)를 실제 Player의 로컬 저장까지 구현하는 단계별 계획이다. 현재 로컬 기록·코덱·파일 복구·도식 관찰 창의 구현 범위/사용법은 해당 명세의 10절을 따른다. 아래 제안 모듈·설정 파일과 모든 단계가 완료됐다는 뜻은 아니며, 프로필 생성·외부 manifest 최적화·실제 전체 플레이의 장시간 품질/용량 확인은 구별한다. 서버 구현은 [별도 서버 명세](replay-server-storage.md)를 따른다. 원격 서버 없이 파일을 읽고 기록 정확도·실제 용량을 확인할 수 있게 먼저 완성한다.

작업은 `docs/demo-replay-storage` 브랜치와 별도 워크트리에서 진행한다. Unity 검증·빌드는 6000.6.5f1과 원본 패키지로 고정한다. 이미지·음원 원본이나 resources 서브모듈을 변경할 필요가 없는 기능이다.

## 1. 용량과 품질 목표

**압축 후 5MiB/시간 이하를 최적화 목표**, 기존 10MiB/시간을 대표 플레이의 검토 기준으로 둔다. 둘 다 실측 예상치나 강제 파일 절단 기준이 아니다. 저장 상한을 맞추려고 전체 플레이 시간을 짧게 하거나 확정 사건을 버리지 않는다. 데이터가 많은 전투는 목표를 넘을 수 있으며 실측 결과와 원인을 드러낸다.

5MiB/시간은 약 1.42KiB/초, 일반적인 30초 조각은 평균 약 42.7KiB에 해당한다. 이 예산은 화면 주변 상태·입력/사건·UI/커서·스냅샷·사전·header/footer·최종 manifest의 **실제 보관 바이트 합계** 기준이다. 0분/빈 화면 파일을 길게 재사용해 평균을 낮추지 않는다.

용량을 낮추면서도 보존해야 할 정보는 다음과 같다.

- 자동 기록 시작 이후 전체 관측 시간, 런/씬/맵·카메라 흐름, 기록 공백과 원인.
- 플레이어 조작 edge와 실제 행동/피격/사망/보상·장비 변경의 원본 시각·순서·연결.
- 메뉴의 열기/닫기·hover·selection·input focus·실제 활성화, 클릭 위치, 스크롤의 최종 상태.
- 화면에 들어온 적/탄의 종류와 주요 행동, 당시 플레이어 주변 상황을 이해할 표시 상태.

희생 가능한 것은 원본 영상과 같은 모션의 연속 정밀도, 화면 밖 개체 궤적, 임의 시각 즉시 탐색 속도다. 낮은 기록률 사이에 실제로 발생한 입력/전투 사건을 위치 보간으로 추정하지 않는다.

## 3. 저장량을 줄이는 순서

### 3.1 반복 사실 제거

같은 action 입력을 raw device·game action·전투 ingress 세 형태로 중복 저장하지 않는다. 필요한 입력 edge/변경 값 한 번과 실제 결과를 원본 키로 연결한다. held/continuous 상태는 값 변경 또는 해제·무효화 때만 남기고 매 tick의 동일 값을 생략한다.

AI의 Chase/이동 명령·정상 접수/소비 영수증은 디스크 기록에서 제외한다. 공격의 실제 시작·필요한 종료/취소·실패와 확정 타격은 유지한다. 제외는 수집 설정에 선언하며 원본 cursor 유실을 정상적인 제외와 혼동하지 않는다. AI 경로는 화면 주변 위치 표본으로만 관찰한다.

하나의 accepted hit를 명중·피해·HP 변경 3개의 전체 payload로 저장하지 않는다. 원본 hit 한 건에 필수 원인·결과를 담고, 죽음 등 별도 의미 사건은 그 hit ID를 참조한다. 서로 다른 원본 타격을 시각이 같다는 이유로 합치지 않는다. 통계 요약도 상세 리플레이에 복사하지 않고 소스 키로 연결한다.

### 3.2 변화분과 움직임 중간점 절감

각 필드는 마지막 **디코더가 복원할 값**과 비교한다. 동일한 양자화 값은 쓰지 않으며 bitmask로 바뀐 필드만 저장한다. 누적 작은 변화가 임계값 미만이라는 이유로 영구 생략되지 않도록 단순히 직전 raw sample과만 비교하지 않는다.

플레이어/카메라 최대 10Hz·적 최대 5Hz는 관측 후보의 상한이다. 파일에 모든 후보를 쓰지 않고 조각 확정 전에 시간 기반 선형 보간 오차가 작은 중간점을 제거한다. 각 actor/포인터의 같은 연속 상태 구간 안에서만 단순화하며 코너·방향/행동 변경·범위 진입/이탈·teleport·pause 경계를 넘겨 합치지 않는다.

초기 실험 오차는 플레이어/카메라 1/128unit, 적 1/32unit, 커서 1/2048 viewport 길이를 제안한다. 이는 관측 후보에 대한 추가 단순화 오차이며, 후보 사이의 실제 움직임 오차·양자화 오차와 구별해 평가한다. 이벤트 시각·위치는 변경하지 않는다. 피격·사망·입력 edge·클릭·hover/selection/focus 변경 시 해당 위치를 anchor로 남긴다. 후보 두 점 사이를 직선으로 잇는 표시와 실제 경로가 다를 수 있음을 재생 품질로 명시한다.

상태가 계속 같은 정지 구간은 시작과 종료만 저장한다. 움직임이 선형이면 시작/끝과 필요한 보정만 남긴다. 짧은 곡선·불규칙 이동은 기준 오차를 만족하는 만큼 더 저장한다. 시간차로 재생하므로 정지 구간을 채우는 반복 레코드를 생성하지 않는다.

### 3.3 탄·모션·쿨타임의 매 프레임 수치 제거

직선/정해진 경로의 탄은 생성/발사·초기 조건·경로 ID·소멸·반사만 남긴다. 경로가 바뀐 경우에만 보정한다. 유도 등 동적 탄은 필요한 표본을 남기고 위치 보간 오차로 줄인다. 판정/피해는 기록된 확정 사실만 사용한다.

모션은 ID와 시작/속도/전환 시각, 쿨타임은 다음 사용 가능 시각·용량/잔량 변경을 저장한다. elapsed/remaining을 매 프레임 쓰지 않는다. time scale·pause 변화를 기준 시계에 적용해 표시한다. 카메라도 실제 움직임이 기존 규칙으로 정확히 표현되지 않을 때 필요한 점을 유지한다.

### 3.4 사전·스냅샷의 중복 제거

전체 상태는 **조각 시작 또는 유실/재연결 후 복구 시점**에만 저장한다. 기존 5초 간격의 전체 snapshot은 기본 프로필에서 제거한다. 조각 내 탐색은 조각 시작부터 최대 약 30초의 delta를 적용하며, 파일 밖 재생기 메모리 인덱스로 탐색 비용을 줄인다.

맵의 해석 레이아웃·긴 콘텐츠/target 문자열·고정 UI 구조는 segment 시작 불변 manifest/사전에 한 번 저장하고 해시로 참조한다. 파일 조각은 해당 참조와 현재 표시 상태만 가진다. 같은 레이아웃/타입을 각 entity와 snapshot에 다시 넣지 않는다. 참조 데이터가 없으면 독립 재생 불가를 명시한다. 사용자별 레이아웃/가방을 전역 공용 객체로 공유해 소유권/삭제를 복잡하게 만들지 않는다.

session manifest는 전체 조각 목록을 매번 별도 파일로 추가 보관하지 않고 원자적으로 교체한다. 조각의 불변 바이트와 별도 변경 메타데이터를 구분한다. 손상/범위 재진입을 위한 필요한 snapshot은 절감 대상이라는 이유로 생략하지 않는다.

### 3.5 바이너리 압축

기존 바이너리 + gzip 계약을 유지한다. ID 사전, varuint/ZigZag, 상대 시각·상대 좌표, 변경 bitmask, 양자화로 먼저 데이터량을 줄인 뒤 압축한다. record 순번의 일반 증가 +1도 varuint로 표현하고 반복 바이트는 조각 단위 압축에 맡긴다. 원본 사건 ID는 변경하지 않는다.

관측 후보의 임시 순서와 파일의 `record_seq`를 분리한다. 필터/단순화 뒤 남은 레코드를 원본 시각·동시 사건 순서로 정렬하고 최종 파일 순번을 부여한다. 정상적인 중간점 제거가 서버의 순번 유실로 판정되지 않게 하며, 원본 command/hit 순번과 실제 cursor 유실 정보는 그대로 보존한다.

각 30초 조각은 gzip 1개 스트림으로 압축해 작은 레코드마다 gzip header를 만들지 않는다. 콘텐츠 종류별 분리 압축/다른 코덱은 같은 논리 데이터의 실측으로 저장량·CPU·호환성 이득이 확인될 때만 고려한다. 첫 구현에서는 새 네이티브 압축 플러그인을 추가하지 않는다. gzip 강도는 지원 런타임에서 실제 파일 크기·CPU를 측정해 선택한다. 압축 worker는 메인 스레드에서 Unity 객체를 읽지 않는다.

## 4. 제안 모듈과 파일

필요한 단계에서만 아래 구조를 생성한다. 서로 순환 참조하지 않고 게임플레이 모듈이 기록기에 의존하지 않도록 Integration에서 조립한다.

| `unity/Assets/Deviant/Replay/Runtime/` | 순수 기록 세션·필터·delta·사전·경로 단순화·코덱·검사/디코딩·보관소 |

설정은 기존 프로젝트 데이터 생성 규칙에 맞춰 불변 수집 프로필로 컴파일/배포하고 내용 해시를 기록한다. 런타임 임의 설정 변경으로 파일의 의미가 바뀌지 않게 한다. 새 모듈별 asmdef는 실제 참조 경계를 보고 추가한다. 위치/설정 구조를 문서만으로 구현 완료 처리하지 않는다.

## 5. 기능 단위 구현 순서

### 1단계 — 형식·프로필·측정 기준

versioned registry에 각 레코드의 type ID·필드 순서/폭·nullable·최대 크기·사전/상태 복원 규칙과 원본 키 매핑을 확정한다. 허용 값만 직렬화하고 화면 텍스트/native ID를 배제한다. 수집 프로필 원본·검증·불변 출력, 합성 입력 fixture, 스트림별 바이트 집계기를 만든다.

완료 기준은 고정 합성 데이터의 동일한 의미 round-trip과 잘못된 버전/값 거부, 한 시간 합성 기록의 바이트 분류다. 합성 데이터를 실제 사용자 용량의 근거로 주장하지 않는다. schema 변경·비교 실험은 개발 산출물로 한정한다.

### 2단계 — 순수 기록기·최소 코덱·로컬 보관

세션/segment/조각 순번, 사전·delta·snapshot, gzip writer와 디코더, `.tmp`→`.ready` 확정, manifest 원자적 교체를 만든다. 네트워크 없이 전용 디렉터리에 기록한다. 버퍼/조각/큐 상한과 누락·truncated 표시를 함께 구현한다.

완료 기준은 ready 확정 전후 강제 종료·디스크 부족·손상·재실행 인덱스 복구, 조각 해시 불변, 조회 가능한 실제 압축 크기다. 최종 registry와 디코더가 없는 writer만 완료로 간주하지 않는다.

### 3단계 — UI·커서와 최소 관찰 재생

타이틀·마을·인벤토리·정비소·지도·결과에 의미 target ID를 등록한다. hover/selection/input focus와 화면 수명을 읽고, 포인터·클릭·스크롤·layout revision을 기록한다. 입력 단일 소비와 UI의 실제 성공 처리를 보존한다. 민감 화면 제외·수집 시작/정지/철회·대기 큐 제거를 조립한다.

디코더로 해당 UI 상태·선택 테두리·포인터를 표시하고 시각을 탐색하는 최소 로컬 재생기를 만든다. 완료 기준은 패드/키보드/마우스 전환·해상도/배율·팝업·스크롤·창 포커스·철회에서 기록과 표시가 맞고, 클릭/포커스 anchor가 단순화 전후 유지되는 것이다.

### 4단계 — 플레이어·전투·월드 통합

제품 런/챕터 수명과 해석 레이아웃, entity ID/membership, 읽기 모델·독립 결과/hit cursor, 탄 수명/필요 경로 보정, 장비·가방·경제의 성공 사실을 연결한다. 미지원 포트는 식별하고 필요한 읽기 계약만 추가한다. 전체 준비 상태 복원/새 게임 저장 서비스는 만들지 않는다.

실제 화면의 플레이어·주변 적·카메라·피격/사망·포탈·가방 중 피격·챕터 전환을 최소 재생기와 대조한다. 완료 기준은 전체 타이틀→마을→런→결과/귀환 관측과 성공/시도 구분, scene reset·pause의 시간 축 유지, 원본 유실의 명시다.

### 5단계 — 실측 최적화·품질 확정

기록 전에 줄이는 정책, 양자화, 변화분, 시간 기반 경로 단순화, snapshot 중복 제거를 같은 입력에서 하나씩 적용/비교한다. 후보 표본은 bounded worker 버퍼에서만 잠시 보유하고 `.ready`에는 압축 최종본만 둔다. 오프라인 단순화 때문에 이미 확정한 파일의 사건 순서/해시를 재작성하지 않는다.

탐험·메뉴 집중·보스·탄 다수 각각 10분 이상과 대표 60분 실제 실행을 측정한다. 완료 기준은 원본 사건/anchor 불변·원하는 UI/사망 상황 해석 가능·기록 지연/메모리 상한 준수와 실제 압축 크기다. 5MiB/시간 목표가 안 되면 가장 큰 스트림부터 개선하고 넘은 이유·품질 대안을 검토한다. 측정 없이 목표 달성으로 표시하지 않는다.

### 6단계 — Player 검증·서버 인계 경계

Unity 6000.6.5f1의 실제 데모 대상 Player에서 긴 플레이·강제 종료/재실행·저장 실패·기록 on/off를 검사한다. 기본 반복 기록 구간은 재사용 버퍼를 사용하고 추가 할당·주 스레드 비용·worker 적체·최대 메모리·임시 디스크를 측정한다. 구체적 CPU/메모리 수락 예산은 고정 검증 장치와 함께 프로필 실험에서 정한다.

서버 인계용 ready 파일·메타데이터 열거와 committed 확인 후 삭제 포트, 테스트용 가짜 업로더까지만 검증한다. 원격 API·인증/서버 배포는 별도 기능 작업으로 진행한다. 완료 기준은 로컬 기록만으로 재생·복구·용량 평가가 가능하고, 검증 전 업로드 응답으로 파일을 지우지 않는 것이다.

각 단계는 구현·호출부·의미 있는 테스트·관련 명세를 기능 단위로 함께 리뷰/커밋한다. 이 계획의 단계 수를 구현 완료율로 표현하지 않는다.

## 6. 검증 자료와 용량 평가

자동 검사는 코덱 golden fixture/손상·overflow, ID/시간·reset, 무손실 상태 필드 delta round-trip, 경로 단순화의 오차/anchor/고정 사건 보존, 자동 수집·기록 중단/재개·큐 손상/복구, 실제 UI/전투 어댑터의 부작용 여부를 다룬다. 구현 코드와 같은 계산을 복제하는 검사보다 원본 사실·디코딩 결과와 관찰 가능한 동작을 비교한다.

개발용 고빈도 참조 기록은 합성/담당자 검증 플레이에만 사용하고 `outputs/`에 둔다. 운영 수집 프로필에서 자동으로 원본 고빈도 사본을 함께 만들지 않는다. 실제 사용자 기록과 원본 로그를 Git에 넣지 않는다.

용량 결과에는 전체/스트림별 raw·바이너리·압축 바이트, snapshot·사전·헤더/manifest 비중, 초당 entity/탄/사건 수, 실제 기록 시간·활성 시간, 파일 수·최대 큐/메모리, 후보 대비 출력 좌표 수, 재생 오차/누락을 함께 기록한다. 10분 결과의 단순 6배는 예상치로만 쓰고 60분 측정과 구별한다.

더 작게 만들기 위한 프로필 변경은 데이터를 조용히 버리는 정책이 아니라 명시적인 표시 품질 조정이어야 한다. 먼저 중복·불필요 출력·snapshot·포인터 중간점을 줄이고, 그 후에도 필요하면 주변 적/동적 탄 표본 주기를 조정한다. 플레이어·메뉴의 전체 흐름과 원본 입력/클릭/피해/사망 시각을 유지한다.
