## 1. 읽기 및 상태 규칙

- 주력 재료와 보석은 최종 승인 구조다. 문서 안의 working 수치는 working 상태를 유지한다.
- 스킬은 사용자 승인 초안이다. 최종 승인으로 자동 승격하지 않는다.
- 치장 기능·API 구조와 콘텐츠 기준은 승인됐다. 공통 비용의 절대 정수와 실제 아트 메타데이터는 후속 게임 설계에서 확정한다. 기존 구현·검증 상태는 [K-21 작업](../../wiki/06-delivery/tasks/K-client-ux/k-21-cosmetics-vertical-slice.md)을 따르되, 현재 승인 콘텐츠로의 런타임 이관 완료로 해석하지 않는다.
- 이 통합본은 정본을 대체하지 않으며 외부 Notion에 자동 게시하지 않는다.

### 1. 기능

#### 1.1 기능 개요

플레이어는 최초 로그인 직후 감자·고구마·옥수수 중 하나를 주력 재료로 선택한다. 선택한 재료는 모든 세대에서 80%, 나머지 두 재료는 각각 10%의 비율로 획득한다. 최초 선택은 변경할 수 없으며, 선택을 마치기 전에는 메인 화면과 게임 진행으로 진입할 수 없다.

재료에는 M1~M4 세대가 있다. 챕터가 오르면 상위 세대가 드롭 풀에 추가되고 이전 세대도 계속 획득할 수 있다. 서버는 재료 드롭 성공 여부, 세대와 계열을 차례로 판정하고 최종 `계열 + 세대` 아이템을 인벤토리에 지급한다.

#### 1.2 기능 요약

| 기능 | 요약 |
| --- | --- |
| 최초 선택 | 최초 로그인 직후 감자·고구마·옥수수 중 하나를 선택한다. |
| 진입 차단 | 선택 완료 전에는 메인 화면, 1-1 전투와 게임 진행을 허용하지 않는다. |
| 변경 제한 | 최초 선택 후 다른 재료로 변경할 수 없다. |
| 멱등 재요청 | 같은 재료 재요청은 현재 성공 상태를 반환하고 다른 재료 요청은 거절한다. |
| 서버 저장 | 사용자별로 주력 재료 식별자 하나만 서버 권한 데이터로 저장한다. |
| 계열 비율 | 선택 재료 80%, 두 비선택 재료 각각 10%를 모든 세대에 적용한다. |
| 재료 세대 | 감자·고구마·옥수수는 각각 M1~M4 아이템을 가진다. |
| 누적 세대 풀 | 챕터가 오르면 상위 세대가 추가되고 이전 세대도 드롭 풀에 남는다. |
| 재료 드롭 | 일반 적과 보스의 콘텐츠 수치에 따라 재료 성공 여부를 독립 판정한다. |
| 보상 안정성 | 드롭 결과와 인벤토리 지급을 원자적·멱등 처리한다. |
| API | 주력 재료 조회와 최초 선택 API 두 개를 제공한다. |

#### 1.3 핵심 사용자 흐름

```text
회원가입·로그인
→ 주력 재료 선택 상태 조회
→ 미선택이면 감자·고구마·옥수수와 80:10:10 안내
→ 사용자가 재료 하나 선택
→ 서버가 인증·허용값·기존 선택 상태 검증
→ 주력 재료 1회 저장
→ 메인 화면 진입
→ 자동 사냥에서 재료 추첨
→ 드롭 성공 시 현재 챕터의 가중치로 세대 선택
→ 선택 세대 안에서 주력 80%, 비주력 10%·10%로 계열 선택
→ 계열+세대 아이템 지급
```

#### 1.4 플레이어 가치

- 첫 선택이 장기 재료 수급 성향을 결정한다.
- 주력 재료는 많이 얻되 비주력 재료도 직접 획득할 수 있어 완전한 진행 차단을 피한다.
- 챕터가 오를수록 상위 재료가 추가되어 성장 단계를 체감할 수 있다.
- 이전 세대도 계속 획득해 하위 재료가 필요한 성장 구간을 유지한다.
- 주력 잉여분과 비주력 부족분은 거래소 참여 동기를 만든다.

### 2. 요구사항

#### 2.1 범위

##### 2.1.1 포함 범위

- 최초 로그인 후 선택 상태 조회
- 감자·고구마·옥수수 최초 선택
- 선택 완료 전 게임 진행 차단
- 선택값의 서버 권한 영구 저장
- 같은 재료 재요청의 성공 수렴과 다른 재료 재선택 거절
- 재접속·앱 재실행·다른 클라이언트에서 선택값 복원
- M1~M4 재료 아이템 ID
- 챕터 1~4 누적 세대 풀
- 일반 적·보스 재료 추첨
- 챕터별 세대 가중치
- 세대 안의 80:10:10 계열 추첨
- 보상 원자성·멱등성
- 필요한 API 2개

##### 2.1.2 제외 범위

- 선택 완료 후 변경권·초기화·관리자 변경
- 재료별 별도 선택 API
- 클라이언트가 확률·세대·보상 수량을 결정하는 기능
- 장기 누적 결과를 정확히 80:10:10으로 맞추는 보정이나 천장
- 거래소 등록·구매 API 상세 계약
- 선택 화면의 최종 레이아웃·일러스트·접근성 규격
- working 드롭 수치의 최종 밸런스 승격

#### 2.3 선택 상태 조회

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| MAT-QUERY-001 | 인증된 사용자는 자신의 주력 재료 선택 상태를 조회할 수 있어야 한다. | 미선택 계정은 `selected=false`, 선택 계정은 `selected=true`와 저장값을 받는다. |
| MAT-QUERY-002 | 조회 응답은 감자·고구마·옥수수 식별자, 표시명과 각 선택에 적용되는 비율을 제공해야 한다. | 각 선택의 비율 합계가 100이고 선택 재료가 80이다. |
| MAT-QUERY-003 | 비율은 서버의 현재 게임 규칙에서 계산하고 사용자별 비율 필드나 클라이언트 입력을 사용하지 않아야 한다. | 비율 변경 시 사용자 행 마이그레이션 없이 새 규칙을 표시한다. |
| MAT-QUERY-004 | 선택 완료 계정은 현재 주력 재료와 적용 비율을 조회할 수 있어야 한다. | 재접속·다른 클라이언트에서도 같은 값을 받는다. |
| MAT-QUERY-005 | 비인증 요청은 계정의 선택 상태를 노출하지 않고 실패해야 한다. | 상태 변경 없이 인증 오류를 반환한다. |

| --- | --- | --- |

| MAT-SELECT-006 | 같은 재료 재요청은 새 상태 변경 없이 현재 성공 상태를 반환해야 한다. | 응답 유실 후 재시도가 같은 결과로 수렴한다. |

| MAT-SELECT-008 | 서버·트랜잭션 실패는 선택값을 부분 저장하지 않아야 한다. | 실패 뒤 상태는 미선택 또는 완전히 확정된 선택 중 하나다. |
| MAT-SELECT-009 | 선택값은 재로그인·앱 재실행·다른 클라이언트에서도 유지되어야 한다. | 모든 경로에서 같은 서버 저장값을 조회한다. |

#### 2.6 재료 세대와 working 드롭 수치

챕터별 누적 세대 풀:

| 챕터 | 드롭 가능한 세대 |
| ---: | --- |
| 1 | M1 |
| 2 | M1, M2 |
| 3 | M1, M2, M3 |
| 4 | M1, M2, M3, M4 |

공통 working 수치:

| 항목 | 값 |
| --- | ---: |
| 일반 적 1마리당 재료 추첨 | 1회 |
| 각 추첨 성공률 | 15% |
| 성공당 지급 수량 | 10개 |
| 보스 1마리당 재료 추첨 | 5회 |
| 보스 각 추첨 성공률 | 15% |

챕터별 세대 가중치:

| 챕터 | M1 | M2 | M3 | M4 | 참고 정규화 비중 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 0 | 0 | 0 | M1 100% |
| 2 | 5 | 1 | 0 | 0 | M1 83.333%, M2 16.667% |
| 3 | 25 | 5 | 1 | 0 | M1 80.645%, M2 16.129%, M3 3.226% |
| 4 | 125 | 25 | 5 | 1 | M1 80.128%, M2 16.026%, M3 3.205%, M4 0.641% |

런타임은 반올림된 백분율이 아니라 정수 가중치를 사용한다. 이 값은 최초 구현·시뮬레이션용 working 초안이며 검증 후 조정할 수 있다.

세대 안의 계열 가중치:

| 주력 선택 | 감자 | 고구마 | 옥수수 |
| --- | ---: | ---: | ---: |
| 감자 | 80 | 10 | 10 |
| 고구마 | 10 | 80 | 10 |
| 옥수수 | 10 | 10 | 80 |

#### 2.7 드롭 적용

| ID | 요구사항 | 검증 기준 |

#### 2.8 서버 권한·데이터

사용자별 저장값:

| 필드 | 제약 |
| --- | --- |
| `primaryMaterialType` | 선택 전만 `null`, 선택 후 `POTATO`·`SWEET_POTATO`·`CORN` 중 하나, 이후 변경 불가 |

다음 불변 조건을 지켜야 한다.

- 한 계정은 미선택이거나 주력 재료 하나만 가진다.
- 사용자별 `potatoRate`, `sweetPotatoRate`, `cornRate`를 저장하지 않는다.
- 드롭률·지급 수량·세대 가중치는 콘텐츠 버전에서 관리한다.
- 클라이언트 캐시는 표시용이며 서버 상태를 덮어쓰지 않는다.
- 다른 재료의 동시 선택 요청은 정확히 하나만 최초 성공한다.

#### 2.11 인수 기준

1. 신규 계정은 로그인 후 주력 재료 선택 화면을 먼저 본다.
2. 감자·고구마·옥수수의 최초 선택이 각각 성공한다.
3. 선택 전에는 메인 화면·1-1 전투·게임 진행 API를 사용할 수 없다.
4. 같은 재료 재요청은 같은 성공 상태로 수렴한다.
5. 다른 재료 재요청은 현재 값을 유지하고 실패한다.
6. 동시 최초 선택 요청에서도 값 하나만 저장된다.
7. 재로그인·앱 재실행·다른 클라이언트에서 선택값이 유지된다.
8. 일반 적 20마리와 보스 1마리는 working 버전에서 총 25회 재료 추첨 기회를 만든다.
9. 챕터별 누적 세대 풀과 정수 세대 가중치가 콘텐츠 데이터와 일치한다.
10. 모든 세대에서 선택 재료 80%, 두 비선택 재료 각각 10%를 적용한다.
11. 같은 콘텐츠 버전·전투 입력·seed로 같은 아이템 ID와 수량을 재현한다.
12. 클라이언트의 확률·세대·종류·수량 조작이 결과에 영향을 주지 않는다.
13. 동일 전투 보상 재시도에서 재료가 중복 지급되지 않는다.
14. 보상 응답과 인벤토리 증가량이 일치한다.

### 3. 필요한 API

> 이 장은 주력 재료 전용 API 목록을 정의한다. 드롭 판정은 기존 전투 보상 흐름의 내부 처리이며 별도 클라이언트 API를 추가하지 않는다.

| ID | Method·Path | 기능 | 요청 | 응답 핵심 | 연결 요구사항 |
| --- | --- | --- | --- | --- | --- |
| MAT-API-001 | `GET /api/v1/material-preference` | 선택 상태·선택지·비율 조회 | 없음 | 선택 여부, 현재 재료, 세 선택지, 적용 비율 | MAT-QUERY, MAT-GATE |
| MAT-API-002 | `POST /api/v1/material-preference` | 최초 주력 재료 선택 | `materialType` | 선택 완료 여부, 확정 재료, 적용 비율 | MAT-SELECT, MAT-GATE |

선택 요청 예시:

```json
{
  "materialType": "POTATO"
}
```

성공 응답 예시:

```json
{
  "selected": true,
  "primaryMaterialType": "POTATO",
  "dropRates": {
    "POTATO": 80,
    "SWEET_POTATO": 10,
    "CORN": 10
  }
}
```

같은 재료 재요청은 현재 성공 상태를 반환한다. 다른 재료 요청은 현재 확정 `primaryMaterialType`을 포함한 실패 응답을 반환한다.

### 4. 현재 기준과 후속 검증

#### 4.1 확정 기준

- 정식 재료명 감자·고구마·옥수수
- 주력 재료 최초 로그인 직후 1회 선택

- 챕터 1~4 누적 세대 풀
- 기능 요구사항 32개
- 필요한 API 2개

#### 4.2 Working 수치

다음 값은 최초 구현·시뮬레이션 입력으로 사용하지만 최종 밸런스 검증 후 조정할 수 있다.

- 일반 적 재료 추첨 1회, 성공률 15%
- 보스 재료 추첨 5회, 각 성공률 15%
- 성공당 재료 10개
- 챕터별 세대 가중치 `1`, `5:1`, `25:5:1`, `125:25:5:1`

#### 4.3 후속 검증 항목

- 장비 강화 단계별 M1~M4 소비량과 실제 공급량
- 주력 잉여분 판매와 비주력 부족분 구매 성립 여부
- P10·P50·P90 챕터 도달 시간과 장비 성장 속도
- 총 드롭률·지급 수량·세대 가중치의 `applied` 승격 또는 새 콘텐츠 버전 조정
- API DTO envelope, HTTP 상태, 인증 헤더와 공통 추적 ID
- 선택 화면의 최종 배치·문구·접근성

### 1. 기능

#### 1.1 기능 개요

한짝의 스킬 시스템은 사냥과 거래소에서 획득한 전용 스킬북과 쌀을 사용해 스킬을 해금·승급·강화하고, 해금한 액티브의 자동 사용 우선순위를 설정하는 성장 시스템이다.

#### 1.2 기능 요약

| 기능 | 요약 |
| --- | --- |
| 스킬 구성 | 공격 액티브 2종, 버프 액티브 2종, 패시브 2종으로 총 6종을 제공한다. |
| 스킬북 획득 | 몬스터 처치 시 스킬북 드롭을 판정하고 스킬별·등급별 전용 스킬북을 획득한다. |
| 스킬북 거래 | 스킬북은 거래 가능한 아이템이며 부족한 스킬북은 거래소에서 찾을 수 있다. |
| 최초 해금 | 노말 스킬북과 쌀을 소비해 잠긴 스킬을 노말 1강으로 100% 해금한다. |
| 등급 승급 | 직전 등급 10강에서 책 조합과 쌀을 소비해 다음 등급 1강으로 100% 승급한다. |
| 단계 강화 | 각 등급은 1~10강이며 2~10강은 단계별 성공률로 한 단계씩 강화한다. |
| 강화 실패 | 실패해도 등급·단계는 유지하지만 요구 스킬북과 쌀은 소비한다. |
| 실패 보정 | 같은 스킬·등급·목표 단계에 실패할 때마다 다음 성공률이 5%p 증가한다. |
| 액티브 장착 | 공격·버프 액티브를 공용 4슬롯에 최대 4개까지 중복 없이 장착한다. |

| 패시브 적용 | 패시브는 슬롯과 쿨타임 없이 해금 즉시 항상 적용한다. |

| 장착 화면 | 액티브 장착·해제·순서 변경·저장과 각 액티브 쿨타임 표시를 제공한다. |

#### 1.3 핵심 사용자 흐름

```text
자동 사냥 또는 거래소에서 스킬북 획득

→ 해금·승급·강화 요청
→ 서버가 상태·재료·성공률 검증
→ 스킬북·쌀 차감과 성장 결과를 원자적으로 확정
→ 결과와 다음 성장 견적 표시
→ 해금한 액티브를 4슬롯에 장착하고 우선순위 저장
→ 자동전투에서 저장된 순서대로 스킬 사용
```

#### 1.4 플레이어 가치

- 희귀 스킬북 획득과 거래라는 장기 목표를 제공한다.
- 스킬 성장으로 전투 성능이 명확하게 증가한다.
- 액티브 순서를 조정해 자동전투 효율을 관리할 수 있다.
- 실패 시 단계 하락 없이 실패 보정으로 다음 성공 가능성이 증가한다.
- 패시브는 별도 설정 없이 해금 즉시 효과를 제공한다.

#### 2.4 기능 요구사항

##### FR-SKL-001 스킬북 획득·거래

- 스킬북은 스킬별·등급별 품목 ID를 가진다.
- 스킬북은 거래할 수 있다.
- 일반 몬스터와 보스는 처치 시 전체 스킬북 드롭 판정을 1회 수행한다.
- 기본 드롭 성공률은 0.5%다.
- 보스는 별도 추가 스킬북 판정을 제공하지 않는다.

등급별 드롭 비중:

| 챕터 | 등급 비중 |
| --- | --- |
| 챕터 1~2 | 노말 100% |
| 챕터 3 | 노말:희귀 = 2:1 |
| 챕터 4 | 노말:희귀:영웅 = 4:2:1 |
| 챕터 5 이후 | 노말:희귀:영웅:전설 = 8:4:2:1 |

##### FR-SKL-002 최초 해금

- 노말 스킬북 1개와 정의된 쌀을 소비한다.
- 해금 성공률은 100%다.
- 해금 결과는 노말 1강이다.
- 재료가 부족하면 요청을 실행하지 않는다.

##### FR-SKL-003 등급 승급

- 등급 순서는 노말 → 희귀 → 영웅 → 전설이다.
- 직전 등급 10강에서만 승급할 수 있다.
- 승급 성공률은 100%다.
- 승급 결과는 목표 등급 1강이다.
- 조건 미충족 시 자산을 소비하지 않는다.

승급 비용:

| 목표 등급 | 요구 스킬북 | 쌀 비용 기준 |
| --- | --- | ---: |
| 노말 해금 | 노말 1개 | 60분 자연 획득량 |
| 희귀 승급 | 노말 2개 + 희귀 1개 | 120분 자연 획득량 |
| 영웅 승급 | 노말 4개 + 희귀 2개 + 영웅 1개 | 240분 자연 획득량 |
| 전설 승급 | 노말 8개 + 희귀 4개 + 영웅 2개 + 전설 1개 | 480분 자연 획득량 |

최종 정수 비용은 버전 콘텐츠에서 확정한다.

##### FR-SKL-004 단계 강화

- 각 등급은 1~10강이다.
- 현재 단계보다 한 단계 높은 목표만 요청할 수 있다.
- 성공하면 한 단계 상승하고 해당 목표 실패 보정을 초기화한다.
- 실패하면 등급·단계를 유지한다.
- 성공과 실패 모두 요구 스킬북과 쌀을 소비한다.

| 목표 단계 | 기본 성공률 | 쌀 비용 기준 |
| ---: | ---: | ---: |
| 2강 | 70% | 10분 자연 획득량 |
| 3강 | 65% | 15분 자연 획득량 |
| 4강 | 60% | 20분 자연 획득량 |
| 5강 | 50% | 25분 자연 획득량 |
| 6강 | 45% | 30분 자연 획득량 |
| 7강 | 40% | 35분 자연 획득량 |
| 8강 | 30% | 40분 자연 획득량 |
| 9강 | 25% | 45분 자연 획득량 |
| 10강 | 20% | 50분 자연 획득량 |

##### FR-SKL-005 실패 보정

```text
실패 보정 저장 키 = 스킬 ID × 현재 등급 × 목표 단계
최종 성공률 = min(기본 성공률 + 누적 실패 보정, 100%)
```

- 실패 시 같은 목표의 성공률이 5%p 증가한다.
- 다른 스킬·등급·목표의 보정은 변경하지 않는다.
- 성공 시 해당 목표의 보정만 초기화한다.
- 최종 성공률은 최대 100%다.
- 별도 횟수 기반 확정 천장은 없다.

##### FR-SKL-006 액티브 장착

- 공격·버프 액티브는 공용 4슬롯을 사용한다.
- 0~4개의 액티브를 중복 없이 장착한다.
- 잠긴 액티브와 패시브는 액티브 슬롯에 저장할 수 없다.
- 배열 순서가 자동 사용 우선순위다.
- 전체 배열을 원자적으로 저장한다.
- 저장 실패 시 기존 서버 순서를 유지한다.

##### FR-SKL-007 자동전투

캐릭터 행동 시:

1. 슬롯 1부터 순서대로 검사한다.
2. 유효 대상과 쿨타임 조건을 만족하는 첫 액티브를 사용한다.
3. 사용 가능한 액티브가 없으면 기본공격한다.
4. 액티브는 해당 행동의 기본공격을 대체한다.
5. 다음 행동 시 슬롯 1부터 다시 검사한다.

쿨타임:

- 액티브별로 독립 관리한다.
- 일반 몬스터 전환과 보스 진입 시 유지한다.
- 전투 사이클 완료와 캐릭터 사망 시 초기화한다.

패시브:

- 액티브 슬롯을 사용하지 않는다.
- 해금 즉시 항상 적용한다.

#### 2.5 서버 권한·데이터 요구사항

다음 상태는 서버가 최종 권한을 가진다.

- 스킬 해금 여부
- 현재 등급·단계
- 스킬·등급·목표 단계별 실패 보정
- 액티브 장착 순서
- 스킬북·쌀 보유량
- 콘텐츠 버전
- `stateVersion`
- 멱등성 처리 결과

클라이언트와 로컬 전투 엔진은 서버 확정 상태를 캐시하며 독립적으로 성장 결과를 확정하지 않는다.

#### 2.6 원자성·멱등성 요구사항

성장 명령은 다음 처리를 하나의 서버 트랜잭션으로 수행한다.

1. 현재 상태와 콘텐츠 버전 검증
2. 스킬북·쌀 보유량 검증
3. 성공률·실패 보정 계산
4. 스킬북·쌀 차감
5. 성공·실패 판정
6. 단계 또는 실패 보정 변경
7. `stateVersion` 증가
8. 멱등 결과 저장

- 변경 명령은 `Idempotency-Key`를 사용한다.
- 같은 키·같은 본문은 최초 결과를 반환한다.
- 같은 키·다른 본문은 거절한다.
- 응답 유실 후 재시도해도 자산과 상태를 중복 변경하지 않는다.

필수 요청:

- `Idempotency-Key`
- `If-Match: stateVersion`
- 우선순위 순서의 `skillIds` 배열

반환해야 하는 정보:

- `commandId`
- 멱등 재생 여부
- 서버가 확정한 `skillIds`
- 최신 `stateVersion`

#### 3.4 거래소 검색 API

스킬 시스템은 부족한 스킬북의 `itemId`를 거래소 검색 화면에 전달해야 한다.

예시:

```http
GET /api/v1/market/listings?itemId=skillbook:active_heavy:normal
```

거래소 API 자체의 매물·가격·구매 규칙은 거래소 명세가 소유한다. 스킬 요구사항에서는 정확한 `itemId`로 검색하고 빈 결과에서도 검색 조건을 유지하는 동선만 요구한다.

##### 1. 목적

기획·개발·QA가 동일한 기준으로 스킬 획득, 성장, 장착, 자동 사용과 관리 UI를 구현·검증할 수 있도록 사용자 승인 요구사항을 정리한다. 규칙과 수치의 정본은 [스킬 SSOT](../../30-domain/character/skills/ssot.md), 화면 원칙은 [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md), 기본 화폐 규칙은 [성장 SSOT](../../30-domain/progression/ssot.md)와 [거래소 SSOT](../../30-domain/economy/ssot.md)가 소유한다.

##### 2. 범위

###### 2.1 포함

- 역할 기반 스킬 6종과 기존 전투 성능
- 스킬별·등급별 스킬북 획득과 거래
- 최초 해금, 등급 승급과 2~10강 확률 성장
- 실패 보정과 책·쌀 소비
- 액티브 4슬롯 장착과 사용자 자동 사용 우선순위
- 패시브 상시 적용
- 스킬 성장 탭과 장착·우선순위 탭
- 재료 부족 시 거래소 검색 결과 연결
- 서버 판정, 원자성, 멱등성과 QA 인수 기준

###### 2.2 제외

- 스킬 포인트와 테크트리
- 스킬 진화·교체와 중복 책 옵션 개방
- 궁극기
- 확정 성공 횟수 천장
- 연속 강화와 목표 단계 자동 강화
- 스킬 이름·아이콘·연출의 최종 확정

##### 3. 용어와 콘텐츠

- 프로젝트의 기본 화폐 표시명은 `쌀`이다.
- 스킬은 공격 액티브 2종, 버프 액티브 2종, 패시브 2종으로 구성한다.
- 스킬의 역할 ID와 성능은 스킬 SSOT의 값을 유지한다.
- 첨부 화면의 `센 불 볶기`, `빠른 손질`, `육수 끓이기`, `주방의 집중`, `달궈진 철판`, `마지막 한입`은 시각 참고용 가칭이며 역할 ID와 대응하거나 정식 명칭으로 확정하지 않는다.
- 같은 스킬은 노말→희귀→영웅→전설 순서로 승급하며 각 등급은 1~10강이다.

##### 4. 사용자 흐름

###### 4.1 획득과 성장

1. 플레이어는 자동 사냥 또는 거래소에서 스킬별·등급별 스킬북을 확보한다.
2. 성장 탭에서 스킬을 선택한다.
3. 화면은 현재 등급·단계, 현재·다음 효과, 요구 책·쌀, 보유량과 성공률을 표시한다.
4. 조건과 재료가 충분하면 플레이어가 해금·승급 또는 강화 요청을 보낸다.
5. 서버가 현재 상태와 보유량을 검증하고 소비·판정·상태 변경을 한 번에 처리한다.
6. 화면은 같은 상세 패널에서 결과와 갱신된 상태를 즉시 표시한다.

###### 4.2 장착과 자동 사용

1. 플레이어는 장착·우선순위 탭에서 해금한 액티브를 최대 4개 슬롯에 장착한다.
2. 슬롯 순서를 바꾸고 저장한다.
3. 서버가 해금 여부, 중복 장착과 슬롯 수를 검증하고 순서를 확정한다.
4. 자동전투는 저장된 슬롯 순서로 사용 가능한 첫 액티브를 선택한다.
5. 패시브는 별도 장착 없이 해금 즉시 항상 적용한다.

##### 5. 기능 요구사항

###### FR-SKL-001 스킬 목록

- 시스템은 스킬 6종을 역할 ID 기준으로 식별해야 한다.
- 각 스킬의 해금 여부, 현재 등급·단계, 효과, 책 보유량, 장착 상태를 조회할 수 있어야 한다.
- 이름·아이콘·연출 변경이 역할 ID나 저장 상태를 바꾸지 않아야 한다.

###### FR-SKL-002 최초 해금과 등급 승급

- 최초 노말 해금은 노말 1강을 적용해야 한다.
- 희귀·영웅·전설 승급은 해당 등급 1강을 적용해야 한다.
- 해금과 승급의 성공률은 100%여야 한다.
- 해금·승급은 목표 등급의 요구 스킬북과 쌀을 소비해야 한다.
- 상위 등급 승급은 직전 등급 10강에서만 요청할 수 있어야 한다.
- 승급 조건을 충족하지 못한 요청은 책과 쌀을 소비하지 않아야 한다.

| 목표 등급 | 같은 스킬의 요구 책 | 쌀 비용 기준 |
| --- | --- | ---: |
| 노말 해금 | 노말 1 | 기준 스테이지 60분 자연 획득량 |
| 희귀 승급 | 노말 2 + 희귀 1 | 기준 스테이지 120분 자연 획득량 |
| 영웅 승급 | 노말 4 + 희귀 2 + 영웅 1 | 기준 스테이지 240분 자연 획득량 |
| 전설 승급 | 노말 8 + 희귀 4 + 영웅 2 + 전설 1 | 기준 스테이지 480분 자연 획득량 |

기준 스테이지는 목표 등급이 처음 등장하는 챕터의 10스테이지다.

###### FR-SKL-003 2~10강 강화

- 강화는 현재 등급 안에서 한 단계씩만 진행해야 한다.
- 시도는 목표 등급의 요구 책 조합과 단계별 쌀을 소비해야 한다.
- 성공하면 목표 단계로 올라가고 해당 목표의 실패 보정을 초기화해야 한다.
- 실패하면 책과 쌀을 소비하되 현재 등급과 단계는 유지해야 한다.

2~10강의 자연 획득량도 목표 등급이 처음 등장하는 챕터의 10스테이지를 기준으로 한다.

| 목표 단계 | 기본 성공률 | 쌀 비용 기준 |
| ---: | ---: | ---: |
| 2강 | 70% | 10분 자연 획득량 |
| 3강 | 65% | 15분 자연 획득량 |
| 4강 | 60% | 20분 자연 획득량 |
| 5강 | 50% | 25분 자연 획득량 |
| 6강 | 45% | 30분 자연 획득량 |
| 7강 | 40% | 35분 자연 획득량 |
| 8강 | 30% | 40분 자연 획득량 |
| 9강 | 25% | 45분 자연 획득량 |
| 10강 | 20% | 50분 자연 획득량 |

###### FR-SKL-004 실패 보정

- 실패 보정은 `스킬 ID × 현재 등급 × 목표 단계`별로 독립 저장해야 한다.
- 실패할 때마다 해당 목표의 다음 성공률을 5%p 높여야 한다.
- 최종 성공률은 `min(기본 성공률 + 누적 보정, 100%)`로 계산해야 한다.
- 다른 스킬, 등급 또는 목표 단계를 시도해도 기존 보정은 유지해야 한다.
- 해당 목표에 성공하면 그 목표의 보정만 0으로 초기화해야 한다.
- 횟수 기반 별도 확정 천장은 두지 않는다. 최종 성공률이 100%가 된 시도는 확정 성공한다.

###### FR-SKL-005 액티브 장착

- 공격·버프 액티브는 공용 4슬롯을 사용해야 한다.
- 한 액티브를 두 슬롯에 중복 장착할 수 없어야 한다.
- 잠긴 액티브는 장착할 수 없어야 한다.
- 사용자는 장착, 해제와 순서 변경 후 저장할 수 있어야 한다.
- 패시브는 액티브 슬롯을 사용하지 않고 해금 즉시 항상 적용해야 한다.

###### FR-SKL-006 자동 사용

- 캐릭터가 행동할 수 있는 시점마다 슬롯 1부터 순서대로 검사해야 한다.
- 유효 대상과 재사용시간 조건을 만족하는 첫 액티브 하나를 사용해야 한다.
- 사용할 수 있는 액티브가 없을 때만 기본공격해야 한다.
- 액티브 사용은 해당 행동의 기본공격을 대체해야 한다.
- 행동 종료 후 다음 행동 시점에는 슬롯 1부터 다시 평가해야 한다.
- 네 액티브의 재사용시간은 서로 독립이어야 한다.
- 일반 몬스터 전환과 보스 진입 시 재사용시간을 유지하고, 전투 사이클 완료와 캐릭터 사망 시 초기화해야 한다.

###### FR-SKL-007 성장 화면

- 관리 창은 `스킬 성장` 탭을 제공해야 한다.
- 목록은 각 스킬의 역할, 등급·단계와 최종 성공률을 식별 가능하게 표시해야 한다.
- 선택 스킬의 상세 패널은 다음 정보를 표시해야 한다.
  - 현재 등급·단계와 현재 효과
  - 다음 등급·단계와 다음 효과
  - 기본 성공률, 누적 보정과 최종 성공률
  - 실패 보정 상태
  - 요구 책 종류·수량과 보유량
  - 요구 쌀과 보유량
- 실패해도 등급과 단계가 내려가지 않는다는 규칙을 명시해야 한다.
- 화면의 수치와 성공 여부는 서버 응답을 표시할 뿐 클라이언트가 최종 판정하지 않아야 한다.

###### FR-SKL-008 성장 요청과 결과

- 요청 가능 조건을 만족하지 않으면 버튼을 비활성화하고 정확한 이유를 표시해야 한다.
- 불가 사유에는 최대 단계, 이전 단계 미달, 요구 책 부족, 쌀 부족과 동기화 대기가 포함되어야 한다.
- 요청 중에는 같은 대상에 대한 중복 요청을 차단해야 한다.
- 응답 후 같은 상세 패널에서 성공/실패, 소비한 책·쌀, 새 등급·단계, 최종 성공률과 실패 보정을 즉시 갱신해야 한다.
- 서버 거절 또는 통신 실패는 자산과 성장 상태가 바뀌지 않은 상태로 표시하고 재시도 가능 여부를 안내해야 한다.

###### FR-SKL-009 재료 부족과 거래소 연결

- 스킬북이 부족하면 부족한 품목과 수량을 표시해야 한다.
- 사용자가 구매 동선을 선택하면 해당 스킬·등급 스킬북이 검색된 거래소 결과로 이동해야 한다.
- 매물이 없으면 해당 검색 조건을 유지한 빈 결과와 안내를 표시해야 한다.
- 쌀 부족은 거래소 구매 동선으로 연결하지 않아야 한다.
- 거래소 구매는 기존 가격 보호, 매물 잠금과 서버 재검증 규칙을 따라야 한다.

###### FR-SKL-010 장착·우선순위 화면

- 관리 창은 `장착·우선순위` 탭을 성장 탭과 분리해 제공해야 한다.
- 액티브 4슬롯의 현재 순서, 장착 가능 스킬과 각 쿨타임을 표시해야 한다.
- 장착, 해제, 순서 변경과 저장을 제공해야 한다.
- 저장 전 변경 상태와 서버에 저장된 상태를 구분해야 한다.
- 저장 실패 시 마지막 서버 확정 순서를 보존하고 실패 이유를 표시해야 한다.
- 패시브 2종은 상시 적용 상태로 분리 표시해야 한다.

##### 6. 데이터와 권한 요구사항

###### DR-SKL-001 상태

최소 다음 상태를 식별할 수 있어야 한다.

- 계정 ID와 스킬 ID
- 해금 여부
- 현재 등급과 단계
- `스킬 ID × 등급 × 목표 단계`별 실패 횟수 또는 누적 보정
- 액티브 슬롯 순서
- 스킬별·등급별 책 보유량
- 쌀 보유량
- 적용 콘텐츠 버전

###### DR-SKL-002 권한

- 거래 가능한 스킬북과 쌀의 보유량은 서버가 최종 권한을 가져야 한다.
- 스킬 해금·등급·단계, 목표별 실패 보정과 액티브 장착 순서는 서버가 최종 권한을 가져야 한다.
- 클라이언트와 로컬 전투 엔진의 스킬 캐시는 조회와 동기화 대기 상태를 위한 표시 자료일 뿐 소유권이나 성장 결과를 만들 수 없어야 한다.

###### DR-SKL-003 원자성과 멱등성

- 책·쌀 차감, 성공 판정, 단계 변경과 실패 보정 변경은 하나의 트랜잭션이어야 한다.
- 같은 idempotency key의 재시도는 같은 결과를 반환하고 자산이나 성장 상태를 중복 변경하지 않아야 한다.
- 장착 순서 저장도 하나의 유효한 순서 전체를 원자적으로 교체해야 한다.

##### 7. 오류 처리

| 상황 | 요구 동작 |
| --- | --- |
| 책 부족 | 실행 비활성, 부족 품목·수량 표시, 거래소 검색 결과 이동 제공 |
| 쌀 부족 | 실행 비활성, 부족량 표시, 거래소 이동 미제공 |
| 최대 등급·10강 | 실행 비활성, 최대 성장 표시 |
| 상태 갱신 중 | 실행 비활성, 동기화 중 표시 |
| 중복 요청 | 기존 요청 결과를 재사용하고 추가 차감 금지 |
| 서버 상태가 화면보다 최신 | 서버 상태로 갱신하고 요청 미적용 사유 표시 |
| 통신 실패 | 미확정 결과를 성공/실패로 표현하지 않고 상태 재조회 제공 |
| 거래소 매물 없음 | 검색 조건을 유지한 빈 결과 표시 |
| 잘못된 장착 순서 | 저장 거절, 마지막 서버 확정 순서 보존, 위반 이유 표시 |

##### 8. QA 인수 기준

###### AC-SKL-001 해금·승급

- 충분한 재료로 노말 해금을 요청하면 책과 60분 기준 쌀이 한 번 차감되고 노말 1강이 100% 적용된다.
- 직전 등급 10강에서 각 승급을 요청하면 목표 등급별 책 조합과 120/240/480분 기준 쌀을 한 번 차감하고 해당 등급 1강을 100% 적용한다.
- 직전 등급이 10강 미만이면 승급이 거절되고 책과 쌀이 차감되지 않는다.

###### AC-SKL-002 단계별 강화

- 2~10강 조회에서 성공률과 쌀 비용이 정의된 표와 일치한다.
- 성공 시 한 단계만 상승하고 실패 시 등급·단계가 유지된다.
- 성공과 실패 모두 정의된 책·쌀이 정확히 한 번 차감된다.

###### AC-SKL-003 실패 보정

- 같은 목표에 연속 실패하면 최종 성공률이 매번 5%p 증가한다.
- 다른 스킬·등급·목표 단계의 보정에는 영향을 주지 않는다.
- 최종 성공률은 100%를 넘지 않는다.
- 성공 시 해당 목표 보정만 초기화된다.
- 기본 20%인 10강은 16회 실패 후 다음 시도가 100%가 된다.

###### AC-SKL-004 원자성·멱등성

- 네트워크 재시도, 응답 유실과 강제 종료에서도 책·쌀과 성장 결과가 두 번 적용되지 않는다.
- 차감 중 일부만 적용된 관찰 가능한 상태가 없어야 한다.

###### AC-SKL-005 장착과 전투

- 액티브는 최대 4개만 중복 없이 장착된다.
- 슬롯 1 스킬이 사용 가능하면 후순위 스킬보다 먼저 사용된다.
- 선순위가 쿨타임이면 다음 사용 가능한 스킬을 사용한다.
- 모두 사용할 수 없으면 기본공격한다.
- 액티브를 사용한 행동에는 기본공격이 함께 발생하지 않는다.
- 행동 종료 후 다시 슬롯 1부터 검사한다.
- 패시브는 슬롯과 무관하게 항상 적용된다.

###### AC-SKL-006 UI와 거래소 동선

- 성장 탭과 장착·우선순위 탭이 분리되어 각 책임 정보만 표시한다.
- 재료 부족과 최대 단계에서 요청 버튼이 비활성화되고 이유가 보인다.
- 부족한 스킬북의 구매 동선은 정확한 품목 검색 결과로 이동한다.
- 매물이 없을 때 다른 품목으로 검색 조건이 바뀌지 않는다.
- 요청 결과 패널은 서버 응답 후 소비량, 새 상태와 보정을 즉시 표시한다.

### 1. 기능

#### 1.1 기능 개요

보석 콘텐츠는 메인 스테이지 3-1부터 열리는 계정 성장 시스템이다. 플레이어는 일일 보석 던전에서 보석함을 획득하고, 보석함 개봉과 합성을 통해 보석을 성장시킨다. 획득한 보석은 메인 스테이지와 보스 유형별 프리셋에 장착해 공격력, 최대 HP, 방어 관통, 치명타 확률과 공격속도를 강화할 수 있다.

보석은 거래할 수 있지만 보석함은 계정에 귀속된다. 장착·잠금·거래 등록 상태는 합성과 판매 가능 여부에 영향을 준다.

#### 1.2 기능 요약

| 기능 | 요약 |
| --- | --- |
| 콘텐츠 해금 | 메인 스테이지 3-1 해금 시 보석 콘텐츠, 프리셋 4개와 보석 던전을 함께 연다. |
| 프리셋 | 메인 스테이지·생존형·폭주형·장갑형별 6슬롯 프리셋을 제공한다. |
| 장착 | 옵션 종류와 관계없이 모든 슬롯에 장착할 수 있고 같은 보석을 여러 프리셋에 등록할 수 있다. |
| 전투 반영 | 메인 전투에는 메인 프리셋, 보석 던전에는 그날 보스와 일치하는 프리셋을 적용한다. |
| 보석 레벨 | 보석은 1~7레벨로 구성한다. |
| 합성 | 같은 레벨 보석 3개를 소비해 다음 레벨 보석 1개를 만든다. |
| 보석함 | 보석함 한 개를 열면 1~3레벨 보석 한 개를 지급한다. |
| 잠금 | 특수 옵션 보석은 자동 잠금하며 사용자가 직접 잠금 또는 잠금 해제할 수 있다. |
| 거래 | 보석은 거래할 수 있고 보석함은 거래할 수 없다. |
| 인벤토리 | 일반 아이템과 보석이 고정 200슬롯 계정 인벤토리를 공유한다. |
| 입장권 | 최초 3장, 서버 실제 경과시간 8시간마다 1장, 최대 3장을 제공한다. |
| 일일 보스 | 생존형 → 폭주형 → 장갑형을 KST 기준 3일 주기로 순환한다. |
| 단계 진행 | 보스별 1~10단계를 독립적으로 진행한다. |
| 최초 클리어 | 보스·단계별 최초 클리어 보상은 한 번만 지급한다. |
| 소탕 | 오늘 보스의 최고 클리어 단계만 1회·지정 횟수·전체 소탕할 수 있다. |
| 안정성 | 소비·추첨·지급·진행 변경을 원자적으로 처리하고 동일 요청의 중복 적용을 막는다. |

#### 1.3 핵심 사용자 흐름

```text
메인 스테이지 3-1 해금
→ 보석 콘텐츠·프리셋 4개·보석 던전 활성화
→ 오늘의 보스와 입장권 확인
→ 보스 프리셋 편집
→ 신규 단계 도전 또는 최고 클리어 단계 소탕
→ 보석함 획득
→ 보석함 개봉
→ 보석 확인·잠금·프리셋 장착
→ 같은 레벨 보석 수동 또는 일괄 합성
→ 메인 스테이지와 보석 던전에 보석 효과 적용
→ 필요하면 모든 프리셋과 잠금을 직접 해제한 뒤 거래소에 판매 등록
```

#### 1.4 플레이어 가치

- 일일 던전과 입장권 충전으로 반복 가능한 성장 목표를 제공한다.
- 보스 유형별 프리셋으로 생존, 공격 성능과 방어 관통을 선택적으로 강화할 수 있다.
- 낮은 레벨 보석도 합성해 상위 보석으로 전환할 수 있다.
- 특수 옵션 자동 잠금으로 희귀 보석의 실수 합성을 방지한다.
- 원하는 옵션이 아닌 보석은 거래소를 통해 다른 성장 자원으로 전환할 수 있다.

#### 2.15 오류 처리

다음 요청은 상태 변경 없이 실패해야 한다.

- 해금 전 장착·합성·던전·소탕 요청
- 보유하지 않은 보석 또는 타 계정 보석 사용
- 장착·잠금·거래 등록 중 보석의 합성·판매
- 거래 등록 중 보석의 잠금 변경
- 입장권이 부족한 성공 보상 확정 또는 소탕
- 알 수 없거나 누락된 콘텐츠 버전 사용
- 진행 중 던전의 해당 보스 프리셋 변경
- 보석함 개봉·합성에 필요한 슬롯 부족
- 보석함 스택 지급 권리와 예약할 빈 슬롯이 모두 없는 상태의 던전 시작

실패 응답은 클라이언트가 재시도 가능 여부를 구분할 수 있는 원인 코드를 포함해야 한다.

#### 2.16 인수 기준

1. 해금 전에는 보석 UI와 던전에 접근할 수 없다.
2. 3-1 해금 시 프리셋 4개와 던전이 열리고 입장권 3장이 한 번만 지급된다.
3. 오늘 보스 1단계를 정상 성장 무보석 빌드로 클리어할 수 있다.
4. 성공 시 입장권, 보상, 보스 진행과 최초 보상 상태가 함께 확정된다.
5. 보석함 1개·지정 수량·전체 개봉이 선택 수량만 처리한다.
6. 같은 레벨 보석 수동·일괄 합성이 입력 전체 소비와 결과 전체 지급으로 완료된다.
7. 메인 프리셋 변경 시 현재 스테이지 일반 몬스터 0/20부터 초기 상태로 재시작한다.
8. 던전 도전 중 보스 프리셋을 변경할 수 없다.
9. 자정 전에 시작한 도전은 시작 스냅샷으로 종료하고 다음 요청부터 새 날짜를 적용한다.
10. 최고 클리어 단계만 1회·지정 횟수·전체 소탕할 수 있다.
11. 실패·중단·앱 종료·연결 끊김은 입장권과 보상을 바꾸지 않는다.
12. 보석은 거래할 수 있고 보석함은 거래할 수 없다.
13. 같은 요청을 재시도해도 소비와 지급이 중복되지 않는다.
14. 기존 보석함 스택이 도전 중 0개가 되어도 성공 보상 슬롯이 유지된다.

## 8. 치장 뽑기 요구사항

> [MVP 치장 콘텐츠](../../60-content/cosmetics/mvp-v1.md)는 사용자 승인된 `working` 콘텐츠다.
> 현재 정책 기준은 [MVP 콘텐츠 바이블 설계](../../superpowers/specs/2026-09-02-mvp-content-bible-design.md), [통합 계획](../character-cosmetics-collection/integration-plan.md), [치장 SSOT](../../30-domain/cosmetics/ssot.md), [치장 요구사항](../cosmetic-gacha/requirements.md)이며, 기존 구현 상태는 [K-21 작업](../../wiki/06-delivery/tasks/K-client-ux/k-21-cosmetics-vertical-slice.md)에서 별도로 확인한다.


#### 1. 목적
규칙은 [치장 SSOT](../../30-domain/cosmetics/ssot.md), 확정 통합 결정은 [캐릭터·치장·도감 통합 계획](../character-cosmetics-collection/integration-plan.md), 수치·카탈로그는 [MVP 콘텐츠 v1](../../60-content/cosmetics/mvp-v1.md)가 소유한다. 본 문서는 구현 범위와 검증만 소유한다.

#### 2. 기준 문서와 우선순위
[MVP 콘텐츠 바이블 설계](../../superpowers/specs/2026-09-02-mvp-content-bible-design.md), 통합 계획과 SSOT를 현재 기준으로 사용한다. [2026-09-01 설계](../../superpowers/specs/2026-09-01-cosmetic-gacha-design.md)는 시스템 흐름의 이전 승인 기록이며, 도감·콘텐츠 수치 충돌에는 사용하지 않는다.

#### 3. 범위
1-5 해금, 픽업, 1·10회 추첨, 결제, 보유·등록·도감·세트·상자, 외형 착용 API, 전투 보유 효과 반영, 원자성·멱등성·감사를 포함한다. 실제 렌더링·티켓 공급·최종 UI·상세 HTTP 계약·보존 기간은 제외한다.

#### 4. 용어와 안정 식별자
pickup banner는 전설 세트 하나의 영구 배너다. common cosmetic ticket은 한 회 비용을 대체한다. `registeredQuantity`는 누적 등록 수량, `unregisteredQuantity`는 미등록 중복 재고, `reservedQuantity`는 거래 예약 재고, `availableUnregisteredQuantity`는 `unregisteredQuantity - reservedQuantity`다. `cosmeticStar`는 1~5성이며 `starThresholds`는 성급별 누적 등록 수량 임계값이고 1성 임계값은 1이다. 최초 미보유 결과는 신규이며 자동 등록과 1성을 함께 확정한다. 이후 같은 치장 결과는 중복이며 미등록 중복 재고에 쌓인다.

collection registration은 `registeredQuantity >= 1`인 도감 등록 상태다. 도감은 등록 현황, 미보유 필터, 치장별 등록 수량·성급, 세트 이동과 완성 기록만 제공하며 도감 단계, 단계 보상과 도감 전투 효과는 없다. set은 `HEAD`, `TOP`, `BOTTOM`, `GLOVES`, `SHOES`, `CAPE` 여섯 부위를 정확히 하나씩 가진 묶음, set star는 여섯 구성원 성급의 최솟값, active set effect는 현재 성급 행의 누적 총값이다. 착용은 외형 슬롯 상태만 바꾸며 보유 효과를 바꾸지 않는다. 같은 계정에 현재 메인 전투가 있으면 보유 효과 변경은 현재 사이클 snapshot을 바꾸지 않고 다음 cycle start input에 포함한다. successful draw count·claimed-box count·claimable-box count는 각각 성공 수·수령 수·`floor(totalSuccessfulDraws / 200) - claimedBoxCount`다. selector box는 선택 치장 교환 아이템이다. content version은 콘텐츠 묶음 버전, audit reproduction token은 서버 재현 토큰이다.

#### 5. 사용자 흐름
재화 확인 → 요청 → 서버 추첨 → 지급 → 신규 자동 등록 또는 중복 미등록 재고 적립 → 등록·도감·세트 보유 효과 확정 → 다음 메인 전투 사이클 반영 → 반환. 외형 착용 요청은 별도 슬롯 상태만 확정한다. idempotency key는 공통 요청 헤더다.

draw 입력은 paymentType, user ID, probability, result, reward list를 받지 않는다. registration 입력은 mode 외 목표 성급·수량·효과 값을 받지 않는다. equipment 입력은 cosmeticId 또는 null 외 보유·효과 값을 받지 않는다. 별도 결과등록·collection-add·set-refresh·registration-preview·gacha-history API는 없다.

#### 8. 데이터 요구사항과 불변 조건
서버 소유 최소 레코드는 catalog/version, cosmetic slot, starThresholds, set/banner definition/version, 계정 registeredQuantity·unregisteredQuantity·reservedQuantity·cosmeticStar·equippedBySlot·ticket balance, 배너별 성공·수령 카운터, selector-box stack, idempotency 결과, draw/claim/box/registration/equipment audit, 재구축 가능한 collection-display/set/combat-effect cache다. 물리 테이블은 규정하지 않는다.

#### 9. 원자성·멱등성·동시성
해금은 클리어·해금·10장을, draw는 잠금·결제·추첨·지급·상태·카운터·감사·멱등 결과를, registration은 미등록 재고 소비·누적 등록 수량·성급·도감 표시 상태·세트·다음 전투 사이클 입력·감사를, equipment patch는 슬롯 검증·외형 슬롯·감사를, claim은 권리 검증·차감·상자를, box open은 상자 차감·지급·슬롯·감사를 함께 커밋한다. 같은 키 재시도는 저장 결과를 반환하고 payload 변경은 거절한다. 계정 상태, 재화, 미등록 재고와 거래 예약을 잠가 직렬화한다.

#### 11. 책임 경계
SSOT는 규칙, 콘텐츠는 미승인 수치·카탈로그, 본 문서는 구현 계약·검증을 소유한다. 인증·지갑·일반 인벤토리·전투 계산·HTTP 공통 계약은 각 정본에 위임한다.

#### 12. 검증 기준
- 해금·10장 일회성, 티켓-only·쌀-only·혼합 1/10회와 부족 원자성을 검증한다.
- 순서 보존 신규/중복, 최초 자동 등록·1성, 중복 미등록 재고, 예약 제외 등록, ONE/UNTIL_NEXT_STAR mode, 200/400회 청구·영구 권리, 상자 슬롯·보상을 검증한다.
- 여섯 부위 세트, 누적 등록 임계값, 도감·세트 누적 총 효과, 착용 외형 전용, 응답 유실 재시도, 동시 뽑기·쌀·재고 경합, 무효 콘텐츠, 보유 효과의 다음 메인 전투 사이클 적용을 검증한다.
