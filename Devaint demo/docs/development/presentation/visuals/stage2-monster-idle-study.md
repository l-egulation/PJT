# 2스테이지 픽셀 기본본과 모션 제작 기준

[분야 개요](README.md)

기본본 입구는 `outputs/waterway/pixel-base-step1-20261031/index.html`이다. 일반 근거리3·원거리2·엘리트1·보스 남매2, 총8명의 **정지 기본본**을 제공한다. 현재 대기 검토는 `outputs/waterway/body-idles-8-v2-20261031/index.html`의 몸통 호흡 시안이다. 일반 이동은 별도 반환 프레임 검토 단계이며 공격 모션·실제 게임 적용 완료가 아니다. 역할과 전조는 [2스테이지 몬스터 기획](../../../design/enemies/chapter2/normal/stage2-waterway-monsters.md)을 따른다.

## 기본본 원본

[픽셀 규격 데이터](../../../../data/presentation/stage2_pixel_base.json)가 개체별 높이·팔레트·후속 대기 부위를 소유한다. `pixel_base_prepare.py`는 기본 image_gen에 사용할 입력·프롬프트를 보존한다. 등짐 분사수와 남매만 얼굴·몸의 앞면이 드러나는 사선 자세로 편집한다. 나머지5명은 기존 정지 그림의 크기와 알파 실루엣을 그대로 사용한다. 먹침필경사는 침이 짧아진 생성 모션이 아닌198×59px 정지 원본을 사용한다.

`python tools/stage2_monster_concepts/pixel_base_build.py`는 제한 팔레트 변환, 내부 색면의 작은 잡색 정리, 알파0/255, 고정 캔버스와 정수 확대본을 만든다. 색 정리 과정에서 실루엣의 점유 픽셀을 바꾸지 않는다. 기존 원본과 생성 프롬프트·참조를 결과 폴더에 보존한다. 확대본을 새 고해상도 그림으로 다시 생성하지 않는다.

사용자 크기 JSON과 승인 플레이어는 수정하지 않는다. 플레이어의 PNG 캔버스192×160과 실제 그림66×64를 구분한다. 신호투척수106px는 기존154px에 포함되었던 머리 위 물건을 내린 몸 크기다. 남매102/127px는 분리 작업값이며 별도의 사용자 확정값은 아니다.

## 에테르 전달

- `native/base-frame.png`:384×224 RGBA 기준본. 기준선192, 이전 정지 참고의 지지점 가로 위치를 유지한다.
- `native/base-indexed.png`:같은 그림의 제한 팔레트 PNG. 개별 색은 `palette.json`·`palette.gpl`에 보존한다.
- `eter/ID-base-frame-4x.png`:1536×896 투명 PNG. 에테르 입력의 우선 파일이다.
- `eter/ID-base-frame-8x.png`:3072×1792 투명 PNG. 각 논리 픽셀은 정확한8×8 블록이다.
- `base-cropped` 파일:여백 없는 개별 그림. 연속 프레임 정렬에는 고정 캔버스판을 우선한다.

확대본에는 글씨·격자·배경이 없다. 배율과 캔버스 여백을 유지하고 실제 크기로 가져올 때는 정확한 역배율 최근접 축소를 사용한다. 에테르가 생성한 동작은 기본본과 색·실루엣·발 기준을 다시 비교한다. 기준선은 아트 정렬용이며 Unity 피벗·몸 판정 확정값이 아니다.

## 이전 국소 대기 원본

[국소 픽셀 모션 규격](../../../../data/presentation/stage2_k4_pixel_idle.json)이 기본본 해시, 얼굴·양어깨 마스크, 최대1px 변위와 네 키의 시간을 소유한다. `python tools/stage2_monster_concepts/k4_pixel_idle.py`로 제작한다. 새 이미지 생성 없이 기존 픽셀을 복사하고, 이동 후 빈 경계에는 바로 아래 행의 원본 픽셀을 노출한다. 얼굴 마스크와 양어깨 상단만 움직이며 후드·가슴·팔 아래쪽·손·끈·등통·호스·노즐·하체·발은 고정한다.

기본 → 어깨 상승 → 얼굴이 따라 상승 → 어깨 복귀 → 기본의1.5초 루프는 검토용이다. 고정 영역 전체 RGBA 동일성, 새 색 없음, 첫 키와 기본본 동일성, APNG/WebP 복호화 일치를 검사한다. 원본과 나란히 재생·정지·키 선택·1/4/8배 확대가 가능하다. 검토한 분사수의 네 프레임은8명 묶음에서도 바꾸지 않고 그대로 복사한다.

## 이전 전체8명 국소 대기

[전체 모션 규격](../../../../data/presentation/stage2_pixel_idles.json)과 `python tools/stage2_monster_concepts/pixel_idles.py`를 사용한다. 기본본을 복제한 뒤 선택된 부위만 최대1px 움직인다. 사람형은 얼굴·어깨, 수의는 손끝·안쪽 주름, 필경사는 침과 얼굴을 고정한 등판, 보행기는 강체와 접점을 고정한 내부 관절·판 명암이다. 발과 무기·장비를 고정하고 몸 전체를 확대·축소하거나 매 프레임 image_gen으로 다시 그리지 않는다. 네 키와1.5~2.1초 주기는 아트 검토값이며 전투 타이밍이 아니다.

개체별 `frames/`에384×224 PNG, `enlarged/`에4배/8배, `previews/`에 APNG·WebP·GIF와 기존 맵 합성이 있다. `masks/`에 변경/고정 영역을 보존하며 `metadata.json`에서 실제 변경 픽셀 수와 원본 해시를 확인한다. 공격 패턴 설명은 전투 기획 데이터에서 가져오며 원거리/근거리/엘리트/보스의 미정 수치를 새로 확정하지 않는다.

기존 `idle-motion-8-v1-20261031`의 생성 대기 루프는 현재 제작 기준에서 제외한다. 원본을 삭제하지 않고 참고로만 보존한다. 해당 원화의 형태·침 길이 흔들림을 새 기본본으로 가져오지 않는다.

참고는 [스컬 제작 사례](https://unity.com/resources/skul-the-hero-slayer-case-study)의 해상도·묘사 밀도 통일, [SLYNYRD](https://www.slynyrd.com/blog/2018/8/19/pixelblog-8-intro-to-animation)의 제한 색과 픽셀 덩어리, [Sandro Maglione](https://www.sandromaglione.com/articles/pixel-art-character-animations-guide)의1px 변화와 후행 부위 예시다. 우리 개체의 구체적인 변위·시간은 다음 단계의 아트 검토 사항이다.

## 현재 몸통 호흡 대기

[몸통 모션 규격](../../../../data/presentation/stage2_body_idles.json)과 `python tools/stage2_monster_concepts/body_idles.py`를 사용한다. 이전 국소 대기의 얼굴·어깨 후행을 유지하면서 상체·골반·장비를 정수 픽셀로 함께 이동한다. 일반 개체는 기본 대비 아래2px·위1px, 편측거구는 아래3px·위1px 범위이며 다리·지지대에서 변위를 줄여 지면 접점은 고정한다. 발 없는 수의는 전체가 위3px 범위로 부유한다. 무기·장비는 상체를 따라 이동하며 해당 영역의 모양과 길이는 유지한다.

변형은 기존 행의 정수 샘플링이며 보간·새 색·전체 이미지 확대축소·재생성은 없다. 여덟 키와 개체별 주기는 아트 검토값이다. 첫 키는 정지 기본본과 동일하다. 발 고정 영역, 상체 강체 영역의 원본 키 대비 평행이동 일치, 팔레트, APNG/WebP 복호화를 검사한다. `source-row-displacements.json`에 행별 변위를 보존한다. 비교 페이지는 이전/보정 모션 동시 재생·정지·프레임 선택·1/3/4/8배 확대를 제공한다. `frames/`는384×224 PNG8장, `enlarged/`는4배·8배, `previews/`는 루프와 키 비교·기존 맵 합성이다. 원래 기본본과 이전 국소 대기는 변경하지 않는다.

## 일반5종 이동 검토

`outputs/waterway/walk-review-20261031/index.html`에서 일반4종의 반환 걷기와 수의8키 부유를 검토한다. [반환 모션 규격](../../../../data/presentation/stage2_walk_review.json)과 `python tools/stage2_monster_concepts/walk_review.py`를 사용하며 받은 파일은 해당 출력의 `sources/`에서 읽는다. 보행기2버전을 포함해 GIF5개 전체372장을1280×720 RGBA PNG로 복호화하여 `raw-frames/`에 보존한다. 받은 PNG 시트도 셀을 그대로 분리해 `sheet-frames/`에372장 보존한다. 별도 `native/`는 흰 배경과 작은 잡점 제거·기존 팔레트·클립별 고정 최근접 배율을 적용한384×224 비교 사본이다. 원본 시간·배율·오프셋·소스 경계를 메타데이터에 둔다. 첫 입력 정지는 반복 미리보기에서만 제외하며 원본/정리 프레임 전체에 남긴다.

수의는 기존 정수 픽셀 부유8키를 유지한다. 개체별 전체 프레임과4배 확대·8키 비교·키 선택·원본 GIF·이동 합성으로 형태 변화를 검토한다. 분사수 등통 꼭대기와 첫 입력의 잘림, 생성된 형태 변화·가장자리 잡점은 자동 복원·제작 승인으로 처리하지 않는다. 이동 합성 속도는 연출값이며 전투 이동속도 확정이나 Unity 적용이 아니다.

## 걷기 픽셀 보정

현재 보정 입구는 `outputs/waterway/walk-retouch-v2-20261031/index.html`이다. [보정 규격](../../../../data/presentation/stage2_walk_retouch.json)과 `python tools/stage2_monster_concepts/walk_retouch.py`를 사용한다. 원본 색이 흰 배경과 혼합된 흔적을 고정 좌표로 대조하여 가장자리 오염을 제거한다. 이전384×224 프레임에서 기본본 하이라이트 주변을 보호하며 작은 밝은 외곽 군집과 떨어진 잡점을 제거한다. 팔레트는 개체별 선택 기본본의 실제 RGBA만 사용한다. 보행기 앞발 하단은 기본본의 어두운 자주색 재질로 복원하여 밝은 뼈색·회녹색 선을 정리한다. 신호투척수는 손이 바뀌는 생성 오류를 고치기 위해 선택 기본본 상체·든 팔·손·소품을 강체 복원하고 기존 다리 픽셀을 앞치마 아래에 배치한다. 상체는 최대2px 변위를 따르며 소품의 형태·손·상대 위치는 유지한다. H3의 기존8키 부유는 유지한다.

모든 이전 프레임과 원본을 보존한다. 변경 픽셀·입력 해시·강체 검사·변위는 메타데이터에 둔다. 외곽 정리는 외곽선 추가가 아니며 개별 보정 PNG를 다시 묶어 GIF/WebP를 만든다. 분사수 상단 잘림과 반환 모션의 다른 형태 변화, 다리 접합 경계는 검토 대상이다. 제작 승인·게임 적용과 구분한다.

## 등짐분사수 접합 후보 선택

끝에서 처음으로 돌아가는 구간은 `outputs/waterway/k4-loop-candidates-20261031/index.html`에서 A~D를 비교한다.
