> 문서 상태: 사용자 승인 초안

# 1. 기능

## 1.1 기능 개요

한짝의 스킬 시스템은 사냥과 거래소에서 획득한 전용 스킬북과 쌀을 사용해 스킬을 해금·승급·강화하고, 해금한 액티브의 자동 사용 우선순위를 설정하는 성장 시스템이다.

## 1.2 기능 요약

| 기능 | 요약 |
| --- | --- |
| 스킬 구성 | 공격 액티브 2종, 버프 액티브 2종, 패시브 2종으로 총 6종을 제공한다. |
| 스킬북 획득 | 몬스터 처치 시 스킬북 드롭을 판정하고 스킬별·등급별 전용 스킬북을 획득한다. |
| 스킬북 거래 | 스킬북은 거래 가능한 아이템이며 부족한 스킬북은 거래소에서 찾을 수 있다. |
| 최초 해금 | 노말 스킬북과 쌀을 소비해 잠긴 스킬을 노말 1강으로 100% 해금한다. |
| 등급 승급 | 직전 등급 10강에서 책 조합과 쌀을 소비해 다음 등급 1강으로 100% 승급한다. |
| 단계 강화 | 각 등급은 1~10강이며 2~10강은 단계별 성공률로 한 단계씩 강화한다. |
| 강화 실패 | 실패해도 등급·단계는 유지하지만 요구 스킬북과 쌀은 소비한다. |
| 실패 보정 | 같은 스킬·등급·목표 단계에 실패할 때마다 다음 성공률이 5%p 증가한다. |
| 액티브 장착 | 공격·버프 액티브를 공용 4슬롯에 최대 4개까지 중복 없이 장착한다. |
| 자동 사용 | 행동 시 슬롯 1부터 검사해 사용 가능한 첫 액티브를 사용하고 없으면 기본공격한다. |
| 패시브 적용 | 패시브는 슬롯과 쿨타임 없이 해금 즉시 항상 적용한다. |
| 성장 화면 | 현재/다음 효과, 성공률, 실패 보정, 책·쌀 요구량과 보유량을 표시한다. |
| 장착 화면 | 액티브 장착·해제·순서 변경·저장과 각 액티브 쿨타임 표시를 제공한다. |
| 서버 권한 | 해금·등급·단계·실패 보정·장착 순서·스킬북·쌀은 서버가 최종 확정한다. |
| 안정성 | 자산 차감과 상태 변경을 하나의 서버 트랜잭션으로 처리하고 멱등 재시도를 지원한다. |

## 1.3 핵심 사용자 흐름

```text
자동 사냥 또는 거래소에서 스킬북 획득
→ 스킬 성장 화면에서 현재 상태와 비용 확인
→ 해금·승급·강화 요청
→ 서버가 상태·재료·성공률 검증
→ 스킬북·쌀 차감과 성장 결과를 원자적으로 확정
→ 결과와 다음 성장 견적 표시
→ 해금한 액티브를 4슬롯에 장착하고 우선순위 저장
→ 자동전투에서 저장된 순서대로 스킬 사용
```

## 1.4 플레이어 가치

- 희귀 스킬북 획득과 거래라는 장기 목표를 제공한다.
- 스킬 성장으로 전투 성능이 명확하게 증가한다.
- 액티브 순서를 조정해 자동전투 효율을 관리할 수 있다.
- 실패 시 단계 하락 없이 실패 보정으로 다음 성공 가능성이 증가한다.
- 패시브는 별도 설정 없이 해금 즉시 효과를 제공한다.

# 2. 요구사항

## 2.1 범위

### 2.1.1 포함 범위

- 역할 기반 스킬 6종
- 스킬별·등급별 전용 스킬북과 거래 가능 속성
- 최초 해금, 승급과 등급별 1~10강 강화
- 단계별 강화 성공률과 실패 보정
- 스킬북·쌀 소비
- 액티브 4슬롯과 자동 사용 우선순위
- 패시브 상시 적용
- 성장 화면과 장착·우선순위 화면
- 부족 스킬북 거래소 연결
- 서버 권한, 원자성, 상태 버전과 멱등성
- QA 인수 기준

### 2.1.2 제외 범위

- 스킬 포인트, 스킬 트리와 선행 스킬
- 스킬 진화·교체와 중복 책 옵션 개방
- 궁극기
- 횟수 기반 확정 성공 천장
- 연속 강화와 목표 단계 자동 강화
- 스킬 이름·아이콘·연출 최종 확정

## 2.2 용어

| 용어 | 설명 |
| --- | --- |
| 스킬 해금 | 잠긴 스킬을 노말 1강으로 활성화 |
| 강화 | 같은 등급에서 현재 단계보다 한 단계 높은 목표에 도전 |
| 승급 | 직전 등급 10강에서 다음 등급 1강으로 전환 |
| 실패 보정 | 강화 실패 후 같은 목표의 다음 성공률에 누적되는 보정 |
| 액티브 슬롯 | 자동전투에 사용할 공격·버프 액티브의 우선순위 슬롯 |
| `stateVersion` | 서버가 관리하는 계정별 스킬 상태 변경 버전 |
| `Idempotency-Key` | 같은 사용자 명령의 중복 적용을 막는 재시도 키 |

| 역할 ID | 분류 | 역할 | 쿨타임 |

| `active_dot` | 공격 액티브 | 지속 피해 | 10초 |

- 표시 이름이 바뀌어도 역할 ID와 저장 상태는 유지한다.

## 2.4 기능 요구사항

### FR-SKL-001 스킬북 획득·거래

- 스킬북은 스킬별·등급별 품목 ID를 가진다.
- 스킬북은 거래할 수 있다.
- 파밍 스테이지 1~9의 일반 몬스터와 보스는 처치 시 전체 스킬북 드롭 판정을 1회 수행한다.
- 10스테이지 돌파 전투는 스킬북을 드롭하지 않는다. 기본 드롭 성공률은 0.5%다.
- 보스는 별도 추가 스킬북 판정을 제공하지 않는다.

등급별 드롭 비중:

| 챕터 | 등급 비중 |
| --- | --- |
| 챕터 1~2 | 노말 100% |
| 챕터 3 | 노말:희귀 = 2:1 |
| 챕터 4 | 노말:희귀:영웅 = 4:2:1 |
| 챕터 5 이후 | 노말:희귀:영웅:전설 = 8:4:2:1 |

### FR-SKL-002 최초 해금

- 노말 스킬북 1개와 정의된 쌀을 소비한다.
- 해금 성공률은 100%다.
- 해금 결과는 노말 1강이다.
- 재료가 부족하면 요청을 실행하지 않는다.

### FR-SKL-003 등급 승급

- 등급 순서는 노말 → 희귀 → 영웅 → 전설이다.
- 직전 등급 10강에서만 승급할 수 있다.
- 승급 성공률은 100%다.
- 승급 결과는 목표 등급 1강이다.
- 조건 미충족 시 자산을 소비하지 않는다.

승급 비용:

| 목표 등급 | 요구 스킬북 | 쌀 비용 기준 |
| --- | --- | ---: |
| 노말 해금 | 노말 1개 | 60분 자연 획득량 |
| 희귀 승급 | 노말 2개 + 희귀 1개 | 120분 자연 획득량 |
| 영웅 승급 | 노말 4개 + 희귀 2개 + 영웅 1개 | 240분 자연 획득량 |
| 전설 승급 | 노말 8개 + 희귀 4개 + 영웅 2개 + 전설 1개 | 480분 자연 획득량 |

최종 정수 비용은 버전 콘텐츠에서 확정한다.

### FR-SKL-004 단계 강화

- 각 등급은 1~10강이다.
- 현재 단계보다 한 단계 높은 목표만 요청할 수 있다.
- 성공하면 한 단계 상승하고 해당 목표 실패 보정을 초기화한다.
- 실패하면 등급·단계를 유지한다.
- 성공과 실패 모두 요구 스킬북과 쌀을 소비한다.

| 목표 단계 | 기본 성공률 | 쌀 비용 기준 |
| ---: | ---: | ---: |
| 2강 | 70% | 10분 자연 획득량 |
| 3강 | 65% | 15분 자연 획득량 |
| 4강 | 60% | 20분 자연 획득량 |
| 5강 | 50% | 25분 자연 획득량 |
| 6강 | 45% | 30분 자연 획득량 |
| 7강 | 40% | 35분 자연 획득량 |
| 8강 | 30% | 40분 자연 획득량 |
| 9강 | 25% | 45분 자연 획득량 |
| 10강 | 20% | 50분 자연 획득량 |

### FR-SKL-005 실패 보정

```text
실패 보정 저장 키 = 스킬 ID × 현재 등급 × 목표 단계
최종 성공률 = min(기본 성공률 + 누적 실패 보정, 100%)
```

- 실패 시 같은 목표의 성공률이 5%p 증가한다.
- 다른 스킬·등급·목표의 보정은 변경하지 않는다.
- 성공 시 해당 목표의 보정만 초기화한다.
- 최종 성공률은 최대 100%다.
- 별도 횟수 기반 확정 천장은 없다.

### FR-SKL-006 액티브 장착

- 공격·버프 액티브는 공용 4슬롯을 사용한다.
- 0~4개의 액티브를 중복 없이 장착한다.
- 잠긴 액티브와 패시브는 액티브 슬롯에 저장할 수 없다.
- 배열 순서가 자동 사용 우선순위다.
- 전체 배열을 원자적으로 저장한다.
- 저장 실패 시 기존 서버 순서를 유지한다.

### FR-SKL-007 자동전투

캐릭터 행동 시:

1. 슬롯 1부터 순서대로 검사한다.
2. 유효 대상과 쿨타임 조건을 만족하는 첫 액티브를 사용한다.
3. 사용 가능한 액티브가 없으면 기본공격한다.
4. 액티브는 해당 행동의 기본공격을 대체한다.
5. 다음 행동 시 슬롯 1부터 다시 검사한다.

쿨타임:

- 액티브별로 독립 관리한다.
- 일반 몬스터 전환과 보스 진입 시 유지한다.
- 전투 사이클 완료와 캐릭터 사망 시 초기화한다.

패시브:

- 액티브 슬롯을 사용하지 않는다.
- 해금 즉시 항상 적용한다.

## 2.5 서버 권한·데이터 요구사항

다음 상태는 서버가 최종 권한을 가진다.

- 스킬 해금 여부
- 현재 등급·단계
- 스킬·등급·목표 단계별 실패 보정
- 액티브 장착 순서
- 스킬북·쌀 보유량
- 콘텐츠 버전
- `stateVersion`
- 멱등성 처리 결과

클라이언트와 로컬 전투 엔진은 서버 확정 상태를 캐시하며 독립적으로 성장 결과를 확정하지 않는다.

## 2.6 원자성·멱등성 요구사항

성장 명령은 다음 처리를 하나의 서버 트랜잭션으로 수행한다.

1. 현재 상태와 콘텐츠 버전 검증
2. 스킬북·쌀 보유량 검증
3. 성공률·실패 보정 계산
4. 스킬북·쌀 차감
5. 성공·실패 판정
6. 단계 또는 실패 보정 변경
7. `stateVersion` 증가
8. 멱등 결과 저장

- 변경 명령은 `Idempotency-Key`를 사용한다.
- 같은 키·같은 본문은 최초 결과를 반환한다.
- 같은 키·다른 본문은 거절한다.
- 응답 유실 후 재시도해도 자산과 상태를 중복 변경하지 않는다.

## 2.7 UI 요구사항

### 스킬 성장 탭

표시 정보:

- 스킬 역할
- 현재 등급·단계·효과
- 다음 등급·단계·효과
- 기본 성공률·실패 보정·최종 성공률
- 요구/보유 스킬북
- 요구/보유 쌀
- 실패해도 단계가 내려가지 않는다는 안내

실행 불가 조건:

- 스킬북 부족
- 쌀 부족
- 직전 등급 10강 미달
- 최대 전설 10강
- 서버 상태 동기화 중
- 요청 처리 중

성장 결과 표시:

- 성공·실패
- 소비한 스킬북·쌀
- 변경 전후 등급·단계
- 새 실패 보정
- 다음 최종 성공률
- 변경 후 보유 자산

### 장착·우선순위 탭

- 액티브 4슬롯
- 장착 가능한 해금 액티브
- 현재 순서와 쿨타임
- 장착·해제·순서 변경·저장
- 저장 전 변경 상태
- 서버 확정 상태
- 패시브 상시 적용 상태

### 거래소 연결

- 스킬북 부족 시 해당 스킬·등급 검색 결과로 이동한다.
- 매물이 없으면 검색 조건을 유지한 빈 결과를 표시한다.
- 쌀 부족은 거래소 구매 동선으로 연결하지 않는다.

## 2.8 오류 처리

| 상황 | 요구 동작 |
| --- | --- |
| 스킬북 부족 | 실행 비활성, 부족 품목·수량 표시, 거래소 검색 제공 |
| 쌀 부족 | 실행 비활성, 부족량 표시, 거래소 이동 미제공 |

| 최대 전설 10강 | 성장 비활성, 최대 성장 표시 |
| 상태 버전 충돌 | 요청 미적용, 서버 상태 재조회 |
| 응답 유실 | 같은 멱등 키로 재시도 |
| 통신 실패 | 미확정 결과를 성공·실패로 표시하지 않음 |
| 잘못된 장착 순서 | 저장 거절, 기존 서버 순서 유지 |

# 3. 필요한 API

| Method | Endpoint | 목적 | 관련 기능 |
| --- | --- | --- | --- |
| GET | `/api/v1/skills` | 스킬 상태·성장 견적·보유 자산·장착 순서 조회 | 조회, 성장 화면, 장착 화면 |
| POST | `/api/v1/skills/{skillId}/growth` | 스킬 해금·승급·강화 실행 | 해금, 승급, 강화, 실패 보정 |
| PUT | `/api/v1/skills/loadout` | 액티브 4슬롯과 우선순위 전체 저장 | 액티브 장착, 자동 사용 |
| GET | `/api/v1/market/listings?itemId={itemId}` | 부족 스킬북 검색 결과 조회 | 거래소 연결 |

## 3.1 GET `/api/v1/skills`

반환해야 하는 정보:

- `contentVersion`
- `stateVersion`
- 보유 쌀
- 스킬 6종의 해금·등급·단계
- 현재·다음 효과
- 쿨타임
- 장착 슬롯
- 패시브 적용 여부
- 기본 성공률·실패 보정·최종 성공률
- 요구/보유 스킬북
- 요구 쌀
- 성장 실행 가능 여부와 차단 이유
- 서버 확정 액티브 순서

## 3.2 POST `/api/v1/skills/{skillId}/growth`

필수 요청:

- `Idempotency-Key`
- `If-Match: stateVersion`
- `action`: `UNLOCK | PROMOTE | ENHANCE`
- `targetGrade`
- `targetLevel`
- `contentVersion`

반환해야 하는 정보:

- `commandId`
- 멱등 재생 여부
- 성공·실패
- 소비한 스킬북·쌀
- 변경 전후 상태
- 새 실패 보정
- 다음 성장 견적
- 변경 후 보유 자산
- 최신 `stateVersion`

## 3.3 PUT `/api/v1/skills/loadout`

필수 요청:

- `Idempotency-Key`
- `If-Match: stateVersion`
- 우선순위 순서의 `skillIds` 배열

반환해야 하는 정보:

- `commandId`
- 멱등 재생 여부
- 서버가 확정한 `skillIds`
- 최신 `stateVersion`

## 3.4 거래소 검색 API

스킬 시스템은 부족한 스킬북의 `itemId`를 거래소 검색 화면에 전달해야 한다.

예시:

```http
GET /api/v1/market/listings?itemId=skillbook:active_heavy:normal
```

거래소 API 자체의 매물·가격·구매 규칙은 거래소 명세가 소유한다. 스킬 요구사항에서는 정확한 `itemId`로 검색하고 빈 결과에서도 검색 조건을 유지하는 동선만 요구한다.
