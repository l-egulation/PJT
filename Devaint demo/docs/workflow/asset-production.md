# 프로젝트 폴더 구조와 저장 규칙

제작 작업 공간은 아래 폴더와 단계별 저장 규칙을 따른다.

## 최상위 폴더

```text
자율 프로젝트/
├─ 00_안내/     폴더 규칙, 에셋 목록, 새 에셋 템플릿, 정리 기록
├─ 01_기획/     게임 기획, 스토리 명세, 계획서와 행정 문서
├─ 02_에셋/     에셋 제작 기준본
├─ 03_개발/     팀 GitLab 저장소와 본 게임 개발
├─ 04_테스트/   전투·무기전환·Unity 프로토타입
├─ 05_공유/     팀 전달용 사본과 포장본
├─ 90_도구/     에셋 라이브러리, 픽셀 편집기, 제작 도구
└─ 99_보관/     과거 공유본, 프로젝트 이력, 실행 기록
```

번호는 탐색기의 표시 순서를 고정한다. 최상위에 개별 에셋이나 생성 출력물을 추가하지 않는다.

## 에셋 분류

```text
02_에셋/
├─ 캐릭터/
│  ├─ 잉크/
│  │  ├─ 공통몸체/
│  │  └─ 무기/검·채찍·레이피어·단검·깃털펜·공통제작·공통참고/
│  ├─ 스토리등장인물/주인공·동료·할머니·기사·잉크주인공·조력자·공통자료/
│  └─ 테스트용/숲_테스트캐릭터/
├─ 몬스터/각 몬스터 이름·공통자료/
├─ 배경/숲·대도서관·할머니집/
├─ UI/전투HUD·대화상호작용/
├─ 이펙트/가위베기·기본공격/
├─ 스토리연출/부적전달·장면시안/
└─ 사운드/     제작 원본·후보·확정 WAV와 제작 설정
```

같은 대상의 컨셉과 모션은 한 에셋 안에서 관리한다. 채찍 컨셉과 채찍 모션을 채찍 폴더로 합쳤고, 레이피어와 단검은 각각 분리했다. 두 무기가 함께 사용하는 생성기와 비교 화면은 공통제작에 둔다. 스토리 설명과 구현 명세는 `01_기획/스토리`, 장면 그림과 연출은 `02_에셋/스토리연출`에 둔다.

## 각 에셋의 내부 구조

```text
캐릭터/잉크/무기/채찍/
├─ 00_안내.md
├─ 01_참고자료/
├─ 02_제작원본/
├─ 03_작업중/
├─ 04_확정본/
├─ 05_미리보기/
└─ 99_이전시안/
```

| 위치 | 저장할 자료 |
| --- | --- |
| 00_안내.md | 현재 상태, 사용할 파일, 미리보기, 규격·설정 경로 |
| 01_참고자료 | 레퍼런스와 컨셉 |
| 02_제작원본 | 편집 원본, 받은 생성 원본, 리터치 데이터, 에셋 전용 제작 코드 |
| 03_작업중 | 검토 중인 프레임·파츠와 승인 기록이 불분명한 출력 |
| 04_확정본 | 승인 기록이 있는 게임 적용용 결과와 설정 |
| 05_미리보기 | 재생·비교 HTML, GIF, 확대 이미지와 편집 화면 |
| 99_이전시안 | 수정 전 결과, 이전 버전, 선택하지 않은 후보 |

44개 에셋에 위 폴더를 모두 만들었다. 비어 있는 단계는 앞으로 사용할 자리다. 그 아래에는 필요에 따라 `기본모션`, `공격/1타`, `공격/2타`, `이펙트` 등 실제 작업 단위를 둔다. 기존 모션 이름, 프레임 번호와 Unity 출력 내부 구조는 보존했다.

## 최신본과 확정 상태

각 에셋의 `00_안내.md`에서 사용할 파일을 찾는다. 전체 목록은 에셋목록.json (`00_안내/에셋제작/에셋목록.json`, 제작 작업 공간 기준), 그림으로 찾는 화면은 에셋 홈 (`02_에셋/index.html`, 제작 작업 공간 기준)에 있다.

디자인, 기본 모션, 공격, 이펙트는 각각 확정될 수 있다. 디자인만 선택됐거나 Unity 출력이 있다는 이유로 전체 확정 처리하지 않는다. 숲은 확정 초안, 등장인물 6인은 디자인 확정으로 표기한다. 레이피어 공격, 단검 전체 공격·이펙트, UI와 공용 효과의 승인 여부는 아침 확인사항 (`00_안내/에셋정리_20261014/아침_확인사항.md`, 제작 작업 공간 기준)에 기록했다.

프레임 번호와 재생 순서는 설정 JSON을 따른다. 이전 시안을 새로 보관할 때는 `99_이전시안/YYYYMMDD_수정내용`으로 구분하고 안내 파일에 현재 대체 경로를 적는다.

## 개발·테스트·공유·도구

| 자료 | 현재 위치 |
| --- | --- |
| 팀 GitLab 저장소 | `03_개발/GitLab/S15P31F109` |
| 전투 HTML 테스트 | 플레이.html (`04_테스트/전투/플레이.html`, 제작 작업 공간 기준) |
| 무기전환 통합 시험 | `04_테스트/무기전환` |
| 숲 Unity 프로젝트 | `04_테스트/숲_Unity/UnityProject` |
| 시골 Unity 검증 | `04_테스트/시골_Unity` |
| 전투 UI Unity 검증 | `04_테스트/전투UI_Unity` |
| 대도서관 프로토타입 | `04_테스트/대도서관_v14` |
| 무기 제작 공유본 | 공유 홈 (`05_공유/무기제작/index.html`, 제작 작업 공간 기준) |
| 배포 ZIP·unitypackage | `05_공유/에셋포장` |
| 에셋 라이브러리 | 실행.cmd (`90_도구/에셋라이브러리/실행.cmd`, 제작 작업 공간 기준) |
| 몬스터 픽셀 편집기 | index.html (`90_도구/몬스터픽셀편집/index.html`, 제작 작업 공간 기준) |
| 새 에셋 템플릿 | 00_안내.md (`00_안내/에셋_기본템플릿/00_안내.md`, 제작 작업 공간 기준) |

Unity의 `Assets`, `Packages`, `ProjectSettings`는 한 프로젝트 안에 유지한다. 에셋 단계 폴더는 제작 기준본의 규칙이며 Unity 프로젝트 내부를 같은 방식으로 쪼개지 않는다. 팀 Git 저장소 내부도 이번 작업에서 재구성하지 않았다.

게임용 확정 효과음 119종과 런타임·편집 입력 WAV 원본은 `resources/audio/approved-combat/`에서 LFS로 관리하고 `unity/Assets/Deviant/Audio/`에는 메인의 고정 배치 계약으로 복원한다. `.meta`·GUID와 [선택 매핑·재생 시점·제작 설정](../development/presentation/audio/audio-production.md)은 메인 소유이며 실제 게임 오디오 연결과 구분한다. 폰트·보유 VFX 텍스처도 원본은 resources, Unity 연결·가져오기 설정은 메인으로 나눈다. 미선택 후보·모델 가중치는 별도 제작 작업 공간에 보관하며 자동 등록하지 않는다.

이미지·음원·폰트·VFX를 포함한 HTML 보고서·비교 화면·제작 검토 자료는 내장형·상대 참조형 모두 resources의 대상 에셋 `preview/` 또는 공통 `authoring/`에 저장한다. 본문과 필요한 미디어·스타일·스크립트를 함께 색인화하고 링크를 검사한다. 미디어 내장 HTML·JS·JSON은 LFS payload 목록도 갱신한다. 일회성 로그·검증 캡처는 계속 Git 제외 `outputs/`에 둔다. 비공개 저장 여부는 개별 라이선스 확인을 대신하지 않는다.

공유본은 제작 기준본의 사본이다. 현재 원본 해시와 사용 파일을 명시한다. 변경 내역과 검증 결과는 Git 커밋에 남긴다.

## 새 에셋 추가하기

1. 분류 폴더 안에 대상 이름의 폴더를 만들고 기본 템플릿 (`00_안내/에셋_기본템플릿/00_안내.md`, 제작 작업 공간 기준)을 복사한다.
2. 참고·원본·작업 결과를 해당 단계에 저장하고 `00_안내.md`에 최신 미리보기와 규격을 적는다.
3. 승인된 부분만 확정본으로 옮긴다. 입력 경로와 HTML 링크를 함께 갱신한다.
4. `에셋목록.json`에 새 에셋을 등록하고 라이브러리의 목록 새로 스캔을 실행한다.
5. 팀에 전달할 때 `05_공유`에 내보내고 날짜·출처·검토 상태를 남긴다.

## 에셋과 도구의 구분

도구에는 라이브러리·공용 편집기·생성 프로그램을 둔다. 제작한 그림·모션·소품·타일의 기준본은 에셋에 둔다. 테스트의 적용 사본과 Unity 프로젝트가 있어도 제작 기준본을 에셋에 함께 등록한다.
