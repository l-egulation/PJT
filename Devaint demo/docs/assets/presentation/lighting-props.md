# 랜턴·창문·횃불 에셋 제작 계약

[분야 개요](README.md)

[조명 제품 명세](../../design/presentation/lighting-and-reactive-props.md)와 [기술 설계](../../development/presentation/visuals/lighting-and-reactive-props.md)에 연결할 에셋의 제작 계획·규격이다. 부품 구성과 원본 보존 원칙은 적용 기준이며, 전체 노말·마스크 제작과 실제 아트의 전면 조명 통합·미술 검증은 아직 완료하지 않았다. [2챕터 소수 배치 시험](lighting-props.md#2챕터-소수-배치-시험)은 분리 컬러 부품과 반응형 랜턴을 먼저 연결하는 범위다. 공통 실험장의 메모리 생성 도형·노말은 합성 진단 자료이며 승인 제작본이나 resources 원본이 아니다. 제안 크기와 모션 수치를 최종 승인으로 해석하지 않는다.

실제 제작·등록 순서는 [조명 소스 옆 AGENTS.md](../../../unity/Assets/Deviant/Presentation/Unity/Lighting/AGENTS.md)를 따른다. 발광 맵과 점광원 투과 쿠키의 구분, 리소스 색인·Unity 배치, 현재 API의 연결 방법과 미지원 자동화 범위를 설명한다.

## 2. 랜턴 부품

| 부품 | 제작 자료 | 조립·용도 |
|---|---|---|
| 천장 고정구 | 브래킷·못·고리 컬러, 필요 시 노말 | 천장에 고정. 흔들리는 본체와 분리 |
| 줄·체인 | 사슬 정면/측면 고리 짝 또는 줄 반복 부품, 각 부품의 양끝 연결점 | 길이는 부품 수·연결로 조절. 본체를 세로로 늘이지 않음 |
| 하우징 | 금속 프레임·유리 컬러와 노말 | 흔들리는 본체. 기존 하우징을 우선 활용 |
| 발광부 | 불꽃 또는 전구 그림, 발광 마스크 | 소등·점등·깜빡임. 불꽃만 별도 짧은 루프 사용 |
| 광원 소켓 | 본체 내부 로컬 좌표·방향 | `Light2D`·빛줄기의 부착점 |
| 그림자 입력 | 불투명 프레임 위주의 마스크·형상 | 발광·유리 표현과 별개로 외부 광원 차폐 |
| 접촉 영역 | 본체 기준의 별도 기하·앵커 | 몸·공격 접촉. 투명 여백·불꽃·빛 번짐은 제외 |

### 조립 규칙

- 전체 흔들림의 기준은 천장 부착점이다. 이미지 중심 회전을 사용하지 않는다.
- 줄·하우징 연결점과 광원 소켓을 등록한다. 초기에는 고정구 아래를 한 진자로 움직이고 고리별 물리를 만들지 않는다.
- 흔들림 스프라이트시트는 제작하지 않는다. 정지 부품을 운동시키고 불꽃 루프와 밝기 변화만 별도로 연결한다.
- 하우징은 불을 꺼도 자연스럽게 보여야 한다. 주변 벽 조명·큰 후광을 하우징 컬러에 굽지 않는다.
- 유리는 초기에는 투명·발광 표현이며 굴절·색유리 투과는 제외한다. 유리 그림과 빛 차폐 마스크를 같은 알파로 간주하지 않는다.
- 자기 광원을 완전히 가리는 차폐와 외부 광원 차폐를 구분해 검증한다. 랜턴 내부 발광을 표현한다고 금속까지 발광시키지 않는다.

### 사슬·줄 연결 바인딩

`HangingConnectorView`는 천장 고정구 아래 소켓과 랜턴 상단 소켓 사이를 연결한다. 연결부를 본체 중심까지 관통시키지 않는다. 사슬/줄 전환은 기존 진자와 접촉을 재생성하거나 리셋하지 않고 준비된 렌더러·메시를 재사용한다. 각도·각속도에 따른 표현 굽힘은 전투 시계에서만 진행하며, 렌더 샘플링·일시정지 중에는 새로운 운동을 만들지 않는다.

- 합성 실험장은 속이 빈 정면/측면 고리 메시와 연속 줄 메시를 사용한다. 최종 미술이나 새로운 리소스 원본이 아니며 이미지 파일을 main에 생성하지 않는다.
- 실제 제작본은 Unity의 `Create > deviant > Lighting > Hanging Connector Art` 바인딩으로 연결한다. 사슬을 사용할 때는 `chainFace`·`chainEdge`를 함께 지정하고, 줄은 선택적으로 `rope` 반복 스프라이트를 지정한다. 해당 외형의 스프라이트가 없으면 진단용 메시를 사용한다.
- `spriteMaterial`은 스프라이트용 공유 재질이다. 각 부품의 `topSocket`·`bottomSocket`은 원래 Sprite 피벗 기준의 Unity 로컬 좌표다. 부품은 이 두 소켓을 곡선의 대응 지점에 맞춰 균일 배율·회전으로 배치하며, 투명 캔버스 중앙이나 공통 피벗을 가정하지 않는다.
- 제작 연결점의 원본은 resources에서 보존하고 이 바인딩에는 선택 버전의 Unity 좌표 변환 결과를 연결한다. 실제 아트의 자동 임포트·소켓 변환 도구와 최종 미술 승인은 별도 범위다.
- 실험장의 연결 부품 수는 초기 길이·간격으로 한 번 정한다. 최대 128개 제한은 진단용 렌더러 예산이며 초과는 `LinkCountClamped`로 노출한다. 실제 길이가 크게 달라지는 소품의 재저작·로프 감기/늘이기·고리별 충돌은 지원하지 않는다.

## 3. 창문 부품

| 부품 | 제작 자료 | 조립·용도 |
|---|---|---|
| 프레임·창턱 | 컬러·노말 | 벽에 고정된 구조 |
| 창살 | 별도 컬러, 필요 시 노말·차폐 형상 | 앞쪽 구조·그림자. 기존 `grille` 활용 |
| 개구부 | 실제 열린 영역의 마스크·경계 | 창밖 풍경·발광 표시 범위와 배경벽 처리 |
| 유리·외부 풍경 | 선택적 유리 레이어, 도시·하늘 참조 | 프레임과 독립. 전체 풍경을 새 창문마다 복제하지 않음 |
| 발광 마스크 | 밝아지는 유리·개구부 영역 | 창문 자체 밝기. 프레임은 기본적으로 제외 |
| 조명 소켓·설정 | 방출 위치·방향·형태·영향 범위 | 실내 유입광 또는 실외 약한 주변광 |
| 빛줄기 | 별도 효과, 클리핑 영역·앵커 | 선택적인 빛·먼지 표현 |

### 개구부·차폐 규칙

투명한 창문 PNG를 불투명 벽 위에 올리는 것만으로 벽에 구멍이 생기지 않는다. 배경벽의 해당 영역을 마스킹하거나 개구부가 있는 벽 모듈로 구성한다. 이 렌더 개구부가 이동 충돌의 구멍을 자동 생성하지는 않는다.

창틀 전체 사각형을 차폐 형상으로 사용해 빈 공간까지 막지 않는다. 프레임·창살과 개구부를 구분하며 가는 창살의 정확한 그림자·빛줄기 재현 여부는 실제 렌더에서 확인한다. Sorting Layer만 맞추어 같은 레이어의 옆 공간 빛샘까지 해결했다고 간주하지 않는다.

실내에서 보는 외부 유입광과 실외에서 보는 밝은 창문은 같은 외형을 재사용할 수 있지만 조명 방향·범위는 별도 모드다. 창문 개폐·파괴·실내 진입 같은 게임 규칙은 추가하지 않는다.

### 면적·각도 광원 연결

`WindowLightView`는 사각형 또는 `WindowApertureArt`에 지정한 열린 볼록 다각형들의 합집합을 지정 각도로 펼친 평행 조명과 선택적 빛줄기를 사용한다. 최대 8개 조각·총 64개 꼭짓점으로 십자 프레임을 제외한 네 유리 영역, 다각형 아치·곡선 근사를 저작한다. 오목 외곽·구멍은 볼록한 열린 조각으로 분리하며, 꼭짓점은 둘레 순서로 지정하고 마지막에 시작점을 반복하지 않는다. 바깥 사각형 전체를 투과시키는 방식으로 대체하지 않는다. `Create > deviant > Lighting > Window Aperture Art`에서 Unity 바인딩을 만들고 `Capture`/`Bind`로 검증·연결한다. 자동 알파 추출·윤곽 분해는 아직 제공하지 않는다.

표면·노말·그림자·빛줄기는 같은 평행 방향이며 창문 중심이나 출구의 한 점에 의존하지 않는다. 개구부·수신 실내 사각형은 앵커 기준 로컬 좌표이고, 방향은 0°=오른쪽·-90°=아래다. 방향·길이·경계 감쇠·장식 표시 강도는 메인의 `windowBeam` 설정에서 읽는다. 실제 부품을 연결할 때도 원본의 개구부 경계를 이 좌표로 해석하며 창틀의 투명 캔버스 전체를 발광 면적으로 쓰지 않는다. 수신체는 최대 4개 창문을 누적하며 각 창문의 소등·해제는 다른 창문과 독립이다.

실험장의 테두리 부품은 렌더 전용 trim으로 취급해 자기 광원을 가리지 않는다. 실제 구조 벽·바닥·액터의 `SpriteShadowSource`를 창문 차폐 목록에 명시적으로 연결하고 해당 수신 Sprite에는 방향성 창문 지원 셰이더를 사용한다. 준비된 윤곽과 현재 프레임·반전·배치가 표면과 빛줄기의 동일한 평행 차폐에 쓰인다. 빛줄기는 배경 위·캐릭터 뒤에 별도로 그리며 실제 노말 조명의 대체물이 아니다. 2D 평행 투영에서 유입 방향과 나란한 프레임은 겹쳐 보일 수 있다. 프레임 두께·원근 투영·3D 체적 산란과 실제 제품 아트 적용은 미완료다. 실험장 버튼은 조명 투과 기하만 전환하며 실제 배경벽 마스킹·창틀 그림까지 자동 생성하지 않는다.

### 랜턴·횃불 방출 패턴

`LightEmitterView.transmissionMask`는 선택적 URP 점광원 쿠키다. 아틀라스에 패킹하지 않은 정사각 전체 텍스처 Sprite, Clamp·mipmap 없음, 데이터 색공간으로 준비한다. **RGB 흰색은 빛을 통과시키고 검정은 막는다.** 알파만 투명한 흰색은 점광원 차폐 마스크가 아니다. 곡선·복잡한 프레임의 빈 영역을 흑백 패턴으로 그릴 수 있고 null로 원형 점광원에 복귀한다. 패턴은 광원 반경과 소켓 자세에 따라 펼쳐지며, 실제 금속 프레임에서 물리적 그림자를 자동 계산하는 기능은 아니다. 이 자료는 발광부 자체의 알파 마스크와 외부 광원용 그림자 마스크를 대신하지 않는다. 런타임 바인딩은 구현돼 있으나 실제 제작 원본·제품 프리팹 연결은 후속이다.

## 4. 벽 횃불 부품

벽 고정구, 손잡이·화로 본체와 노말, 불꽃 루프·발광 마스크, 광원 소켓을 준비한다. 연기·불티는 선택적 효과다. 벽 횃불은 고정형으로 시작하고 랜턴 진자를 강제하지 않는다. 불꽃 그림만으로 화재·접촉 피해를 발생시키지 않는다.

## 5. 공통 제작 규격

### 크기·피벗·좌표

- 월드 기준은 PPU32·루트 scale 1이다. 주인공 신체 높이 64px와 실제 960×540 출력에서 비교한다.
- 소형 랜턴 본체 약 20×36px는 첫 검토 기준이다. 기존 승인 고해상도 원본은 보존하고 필요한 경우 별도 게임용 파생본을 제작한다. 원본 캔버스 크기를 신체 대비 크기로 해석하지 않는다.
- 창문은 현재 배치·실측 크기를 우선 유지한다. 기존 지역 그림을 임의 비균일 축소·확대해 재질·선 굵기를 바꾸지 않는다.
- 각 부품의 부착점·연결점·광원 소켓·실제 그림 영역·접촉 영역·개구부·그림자 형상을 명시한다. 투명 캔버스 크기나 공통 하단 중앙 피벗으로 추정하지 않는다.
- 제작 좌표의 원점·축·단위를 선언하고 Unity 변환을 한곳에서 수행한다. 컬러·노말·마스크의 캔버스·rect·피벗 대응을 유지한다.
- 새 픽셀 출력은 Point·mipmap 없음·무압축을 기본으로 검토하고 부품의 실제 여백·메시 범위를 보존한다. 기존 원본을 이 규칙에 맞춘다는 이유로 재인코딩하지 않는다.

### 텍스처·형상별 역할

| 자료 | 기준 |
|---|---|
| 컬러 | 강한 주변 빛 번짐·벽 조명을 굽지 않음. 기존 고정 명암과 동적 조명의 중첩 검토 |
| 노말 | 금속·목재·옷의 큰 형태 중심. 선·빗금·무늬를 그대로 높이로 바꾸지 않음 |
| 발광 마스크 | 실제 발광 부분만 지정. 광원 범위나 접촉 영역을 대신하지 않음 |
| 개구부 마스크 | 창문 내부 표시·배경벽 처리 영역. 이동 충돌과 분리 |
| 그림자 마스크 | 불투명 차폐의 원본. 투명 유리·발광·외곽선·VFX와 독립 |
| 그림자 형상 | 마스크에서 사전 생성·단순화·중복 공유. 런타임 알파 추출 금지 |

노말과 마스크는 색 그림이 아닌 데이터로 임포트하고 색공간·압축 설정을 구분한다. `_NormalMap` secondary texture 연결과 런타임 생성·크롭·아틀라스의 동일 프레임 연결을 검사한다. 별도 노말 애니메이션 타이머는 만들지 않는다.

### 캐릭터·몬스터의 대응 자료

캐릭터·몬스터도 기존 컬러 프레임에 대응하는 노말과 그림자 형상 바인딩을 준비한다. 무기·스카프의 차폐 포함 여부는 명시하고 본체 이미지에 포함된 공격 이펙트는 별도 마스크로 제외한다. 플레이어 외곽선·피격 점멸·잔상은 차폐 원본에 넣지 않는다. 모션 교체가 공격 시간·기하를 바꾸지 않는다.

### 화풍·상태

[마을 미술](../world/village/stage1-village-art-direction.md)의 따뜻한 종이·흑연선·성긴 빗금과 [지하수로](../world/stage2-waterway-registration.md)의 저채도 청회색·녹회색 재질을 구분한다. 한 지역 그림의 색만 바꾸어 모든 지역의 최종 아트로 사용하지 않는다.

스케치/컬러와 점등/소등은 독립이다. 석양색·횃불색은 조명 프로필로 조절하고 분위기마다 전체 하우징 PNG를 복제하지 않는다. 필요한 컬러/스케치 짝은 부착점·실루엣 정합을 검사하고 기존 원본의 알파를 임의 재절단하지 않는다.

## 6. 저장·변환·Unity 소유권

- [리소스 기준](../resource-repository.md), `resources/AGENTS.md`, [제작 규칙](../../workflow/asset-production.md)을 따른다. 이미지·노말·마스크·편집 원본·미디어 포함 미리보기는 `resources/` 대상 에셋의 `source/`·`runtime/`·`preview/`에 둔다.
- 기존 세트 옆에 이름이 명시된 파생 세트를 추가하고 출처·원본 해시·변환 설정·승인 범위를 등록한다. 구체적인 새 디렉터리는 실제 리소스 작업 브랜치에서 확정한다. 기존 원본·이관 매핑 해시를 새 결과로 덮어쓰지 않는다.
- 대상 `asset.json`, 전체 `catalog.json`, 해당 생성 검증 목록·LFS 속성을 함께 갱신한다. 미디어 내장 미리보기는 `.lfs-payloads.json`에도 등록한다. 일회성 실행 캡처·로그는 메인의 `outputs/`에 둔다.
- 아트 변환은 `resources/tools/`에서 새 검토 디렉터리로 수행한다. 메인 Unity의 이미지 배치는 [고정 배치 계약](../README.md)을 따르고 별도 공유 드라이브·배포 ZIP 경로를 만들지 않는다.
- 부착점·마스크 등 아트 저작 원본은 resources, 해당 버전의 Unity 참조·변환 바인딩·임포트 설정·`.meta`·GUID·프리팹·재질·셰이더·형상 캐시는 메인이 소유한다. 같은 앵커를 양쪽에서 독립 편집하지 않는다.
- 밝기·깜빡임·진자·충격 수치는 메인의 게임 데이터가 소유한다. 제작 기본 불꽃 시간과 게임에서 선택한 재생 바인딩을 구분하며 중복 편집 원본을 만들지 않는다.
- 리소스 커밋·LFS의 원격 복원을 먼저 확인한 뒤 메인의 배치 계약·gitlink·Unity 연결을 반영한다. 제작 규격의 확정만으로 리소스 파일·배치 계약·gitlink를 갱신하지 않는다.

## 7. 첫 제작·인수 범위

### 2챕터 소수 배치 시험

`environments.waterway-lighting`의 분리 제작본은 2챕터 S 시작 구역과 F01 첫 전투방에서 외형을 확인하는 시험 세트다. 24×36px 랜턴 본체, 고정구, 사슬 앞/옆 고리, 24×27px 횃불과 별도 불꽃을 PPU32로 배치한다. 제작 좌표·소켓은 리소스의 `source/recipe.json`, Unity 참조·변환 결과는 `Chapter2Lighting/Art.asset`이 소유한다. 원본 디자인 시안과 생성 그림은 리소스에 보존한다.

`data/presentation/lighting/chapter2-props.json`이 위치·진자·광원의 시험 설정이며 `python tools/lighting/export_lighting.py --chapter2`로 Unity 카탈로그를 갱신한다. 고정 리소스를 배치한 뒤 `Tools > deviant > Chapter2 Lighting > Rebuild Art Binding`으로 선택 버전의 소켓·부품 바인딩을 만든다. 다른 레이아웃의 지형과 겹치는 후보는 배치하지 않는다. 전체 방에 자동 보급하거나 기존 정비소 랜턴을 교체하지 않는다.

몸·지원 근접 접촉은 기존 `ReactiveLanternBridge`로 처리하며 통행·피해 판정은 만들지 않는다. 국소 조명은 뒷벽만 수신하며, 기본 환경광 아래에서도 랜턴·횃불 주변의 따뜻한 빛과 원형 감쇠가 구분되도록 광원 강도를 설정한다. 본체와 불꽃·광원 소켓은 함께 흔들린다. 창문은 기존 미술을 유지한다. 이 시험은 캐릭터/몬스터 노말·동적 그림자·전체 맵 조명 통합이나 최종 미술 승인을 뜻하지 않는다.

기존 맵에 실제 배치된 창문은 창틀 안쪽 개구부와 6개 창살 차폐 윤곽을 연결한다. 좌표 원본은 리소스 `source/recipe.json`의 `window`, Unity 변환 캐시는 `Art.asset`이 소유한다. `window` 광원과 `windowBeam`의 방향·길이·강도로 뒷벽 수신광과 빛줄기를 함께 표시한다. 창살은 보수적인 사각형 근사이며 원본 PNG 알파의 자동 추출이나 정확한 3D 그림자가 아니다. 빛줄기는 액터 뒤에 표시하고 방 내부로 제한한다.

플레이어의 새 몸 접촉에는 0.055초 접촉 섬광과 0.26초 불티 5개가 나오고, 수락한 지원 근접 타격에는 0.08초 아이보리색 중심 섬광과 0.32초 방향성 불티 8개가 나온다. 몸 불티는 약 3px 폭, 공격 불티는 약 3.5px 폭과 더 긴 궤적으로 구분한다. 테두리·갈고리 오버레이는 생성하지 않는다. `contactFlash.body`와 `.melee`가 각각 수명·속도·크기·확산·중력과 중심 섬광을 소유한다. 빛 조각은 충돌점에서 바깥으로 퍼지고 떨어지며 짧아진다. 코드 메시와 셰이더로 그리며 이전 10×26px `contact-glint` 원본·요청문·출력 recipe는 리소스에 보존한다. 같은 시뮬레이션 시계를 사용하며 몸 접촉 유지·같은 타격의 반복 스윕·일시정지·리셋은 새 섬광을 만들지 않고 적 몸·적 공격은 표시하지 않는다. 몸과 근접 입력은 별도 수락 경로로 유지한다.

첫 세트는 천장 랜턴 1종, 기존 지하수로 창문 1종, 고정 벽 횃불 1종이다. 여기에 대표 캐릭터·몬스터 각 1종의 노말·그림자 자료를 연결한다. 세 종류의 조립 계약을 먼저 검증하고 지역별 외형·크기와 전체 모션을 확대한다.

| 인수 항목 | 기대 결과 |
|---|---|
| 정지·실제 화면 크기 | 기존 미술과 선·재질·크기가 어울림 |
| 소등 | 하우징·금속·유리가 자연스럽고 빛이 컬러에 남지 않음 |
| 최대 흔들림 | 연결점이 벌어지지 않고 광원·발광부·빛줄기가 본체와 정합 |
| 창 개구부 | 풍경·발광·빛줄기가 벽 밖으로 새지 않고 빈 공간이 차폐되지 않음 |
| 동적 명암·그림자 | 플레이어·몬스터의 모션·반전과 이동 광원에 함께 반응 |
| 기존 효과 이행 | 장식용 빛 번짐과 새 조명이 중복되지 않음 |
| 원본·임포트 | 해시·프레임·피벗·소켓·노말·그림자 형상 연결이 검증 가능 |

정지 미술 승인, 파생 에셋 제작, Unity 임포트, 실험장 연결, 본 게임 통합, 실제 화면·성능 검증을 각각 구분한다. 체크 목록의 존재를 통과 결과로 기록하지 않는다.
