# Deviant — 게임 개요

[분야 개요](README.md)

게임의 공식 명칭은 **Deviant**다. 문서와 사용자에게 보이는 게임명은 `Deviant`로 표기한다. 기존 코드 식별자·씬 이름·경로의 대소문자와 구분한다.

잉크 컨셉의 세계관을 가진 2D 액션 로그라이트다. 책·기록·필기 소재를 사용하며 깃털펜은 플레이 무기와 소개 설정에서 제외한다.

## 팀이 공유할 게임의 중심

서사는 기록 삭제로 존재와 풍경이 사라지는 세계, 지나가던 마을에서 휩쓸려 쓰러진 주인공의 첫 잉크 몸 각성, 마을을 지운 것이 있는 「저 너머」로 향하는 동기를 중심으로 한다. 전투는 두 무기의 교체와 무기별 잉크 구성으로 행동을 바꾸며, 챕터 안에서는 이동과 전투가 이어지는 자유 탐험을 목표로 한다. 구체적인 보상·경제·반복 귀환 규칙은 이 방향에서 별도로 결정한다.

상세 이해는 [플레이 흐름](player-flow.md), [맵·챕터](../design/world/world-and-levels.md), [몬스터](../design/enemies/chapter1/monsters.md), [성장·경제](../design/run/progression-and-economy.md), [UI](../design/ui/ui-and-interaction.md), [아트·연출](../design/presentation/art-and-presentation.md)로 이어진다. 용어는 [공통 용어](glossary.md)를 따른다.

## 런과 성장

3챕터, 전체 목표 플레이 시간 45~60분, 챕터당 일반 전투 맵 8개다. 챕터 내부는 방 없이 자유 이동하며 챕터끼리는 물리적으로 연결되지 않고 이전 챕터로 돌아갈 수 없다. 전투 맵 8개는 독립 방이나 전멸 잠금 구간 8개를 의미하지 않는다. [런 구조](../design/run/run-structure.md)를 따른다.

맨손으로 출발해 스테이지 누적 처치 보상에서 무기나 잉크를 고른다. 일반 보상은 여섯 번, 보스 무기 선택은 별도 한 번이다. [보상과 상점](../design/run/rewards.md)

스케치 무기의 팔레트를 확정해 장착한다. 잉크는 런 도감에서 반복 사용하며 색이 일치하는 강화 슬롯에서 강화 수치를 쓴다. 무기와 잉크는 무제한 보관하고, 무기는 누적 실피해로 파괴된다. [장비 기획](../design/equipment/rules.md)

## 이야기와 미정 범위

마을 기록 삭제·잉크 조력자·첫 잉크 몸 각성·회귀는 [초반 스토리](../design/story/opening/opening.md)를 따른다(어르신·행정원·대서적 설정은 2026-11-01에 뺐다). 지워짐에 휩쓸린 쓰러짐, 조력자의 희생, 첫 각성은 스케치가 된 마을의 같은 우물 앞에서 이어진다.

조력자의 잉크가 남아 있는 한 주인공은 쓰러져도 우물 앞에서 다시 깨어난다. 회귀의 대가와 세계 시간, 적 재등장과의 서사 연결은 미정이다. 체력 0 시 런 종료·결과·새 런의 게임 규칙은 [전투 명세](../design/combat/rules.md)를 따른다.

챕터 전환 조건·연출·이동 방식, 연결 공간의 전투 구획·전투 종료·안전 정비 조건, 벽 점프 해금·저장·카메라 세부 사항은 후속 설계다. 미정 규칙을 임의로 확정하지 않는다.

시작 마을의 시설별 영구 해금과 새 장비 구조에 맞춘 재설계 범위는 [로그라이트 영구 성장](../design/progression/roguelite-progression.md), 마을 동선·이야기·현재 구현 구분은 [시작 마을](../design/world/village/starting-village.md)을 따른다.

## 현재 구현과 목표의 구분

현재는 독립 Combat V2 시험장 외에도 기존 숲·전투·HUD를 연결한 공통 씬, 들판의 들쥐 행동, 챕터·대화·순차 실행의 격리 기술 연결이 있다. 정식 3챕터 런·실제 획득·경제·저장·초반 이야기 전체를 완성한 상태는 아니다. [분야별 현황](project-status.md), [전투 구현](../development/gameplay/combat/combat.md), [현재 코드 구조](../development/architecture/architecture.md)를 확인한다.

문서·원본 데이터 사이의 잔여 불일치와 미정 사항은 [확인 목록](open-questions.md)에 모은다. 개발자는 임의로 미정을 채우거나 현재 코드에 맞춰 기획을 바꾸지 않는다.
