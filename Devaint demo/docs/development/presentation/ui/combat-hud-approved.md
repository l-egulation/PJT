# 채택 전투 HUD 연결

[분야 개요](README.md)

> 장비 성장 이행 범위: 제품 규칙은 [무기 도면·런 잉크 도감](../../../design/equipment/rules.md)을 따른다. 아래 팔레트·스탬프·출발 도면 선택·바닥 아이템 드롭은 현재 구현 설명이며 새 제품 기획이 아니다. 런 도감·무기 잉크 적용·내구도·전투방 3지선다의 구현과 실행 검증은 미완료다.

공통 `TemporaryGameGui`의 전투 HUD와 출발 팔레트는 리소스 `ui.combat-hud-expanded-20261106`의 독립 PNG를 사용한다. `runtime/layout-edited.json`은 사용자가 편집한 위치·크기와 같은 배치로 맞춘 두 번째 무기의 기준이다. 원본 사용자 JSON은 리소스의 `source/layout-user.json`에 보존한다.

`TemporaryGameGui.CombatHud.cs`는 1670×942 기준 좌표를 기존 게임 화면의 안전 영역에 맞춘다. 가방·전체 지도·일시정지의 화면 라우터와 입력 소유권은 유지한다. HP·최대 HP, 골드, 보유 마법안료, 무기별 장비·스킬·사용 횟수·쿨타임, 현재 차징 진행률과 실제 팔레트를 표시한다. 쿨타임은 스킬 원에만 표시하며, 큰 무기 원의 선택 테두리와 별개다. 쿨타임 숫자에는 저장된 개별 배치에 더해 스킬 묶음 좌표 기준 아래로 6의 오프셋을 적용한다. 설명 키 줄은 일반 배포 빌드에서 표시하지 않는다.

전투 HUD의 팔레트는 빈 칸에 슬롯 색의 민무늬 방울을 알파 40%로 표시하고, 잉크를 장착한 칸은 인벤토리와 같은 파츠 문양 방울을 선명하게 표시한다. 실제 슬롯의 파츠를 매번 읽어 장착·교체·해제를 바로 반영한다. 정사각형 아이템 그림의 투명 여백은 중앙을 유지한 1.35배 표시로 보정해 무색 방울과 보이는 높이를 맞춘다.

`TemporaryGameGui.RunPalette.cs`는 무기 두 개와 실제 슬롯 색만 두 카드로 표시한다. 기존 런 소유자와 3.5초 표시 수명을 유지하며, 3~5칸을 지원한다. 기존 미니맵의 실제 지형·현재 위치·발견된 표시는 새 프레임 안쪽으로 마스킹한다.

피격 시 초상·체력 숫자·프레임·게이지 전체를 한 묶음으로 0.24초간 감쇠 진동시킨다. 흔들림 최대 크기는 960×540 기준 가로 2.5픽셀, 세로 1.375픽셀이다. 현재 체력에 해당하는 게이지만 같은 알파 윤곽을 유지해 0.12초간 하얗게 번쩍였다 원래 빨강으로 돌아온다. `ReceivedHitCount`의 실제 피격 증가를 관측하므로 회복·직접 체력 대입은 재생하지 않는다. 연속 피격은 한 효과의 시간을 갱신하고 강도를 누적하지 않는다. 비활성화·플레이어 교체·피격 카운트 초기화 후에는 원래 위치와 색으로 복귀한다. 실시간으로 감쇠하므로 짧은 히트스톱이 효과를 늘이지 않으며, 체력량·피해·카메라 동작은 변경하지 않는다. 강도·수명은 `HealthHitShakePixels`, `HealthHitShakeSeconds`, `HealthHitFlashSeconds`에서 조절한다.

플레이어 체력판은 승인 초상 그림 `hero-portrait`와 `Deviant.Presentation.Unity.HealthPlaque`가 그리는 960×540 게임 화소 276×60 도트 판으로 이루어진다. HUD는 도트 판을 `combatHealthRoot` 자식 `Health plaque`(`RawImage`, 점 필터)로 게임 화소 (49, 32)(1670×942 기준 약 85.2, 55.8)에 두어 판 왼쪽 끝이 초상 뒤에 숨게 하고, 초상은 기존 크기(147×118, 비율 유지)로 기존 위치보다 게임 화소 6 아래에 판보다 앞(마지막 형제)에 그린다. 승인 그림의 판·게이지와 Pretendard 숫자(`health-plaque`, `health-fill-red`, `healthText`, `healthMax`)는 만들어 두되 숨기며 값은 계속 갱신한다. 도트 판의 모양은 pixelfx 시안 `전투테스트/체력바/_bar.js`와 같은 계산(화소 중심 판정)이다: 바깥 먹선 2화소·크림 선 1화소의 검은 판, 판 안쪽 위 선과 게이지 틀 사이 빈 칸 가운데(지역 y -21)에 큰 도트(5×7, 2배) 현재 체력과 아래쪽을 맞춘 작은 도트(3×5, 2배) `/ 최대`, 길이 200·높이 9·위쪽 4화소 기울기의 평행사변형 게이지(위 한 줄 밝은 빨강, 아래 두 줄 어두운 빨강, 값의 끝도 같은 기울기)와 그 바깥 1화소 크림 틀이다. 피격 흔들림은 기존처럼 초상과 판을 묶어 움직이고, 게이지 흰 번쩍임은 같은 시계로 도트 게이지를 하얗게 칠한다.

게이지 위의 회복·보호막·피해 연출은 `HealthBarInk`가 그리고 `HealthPlaque`가 게이지 자리에 겹친다(판 밖으로 튄 점은 그리지 않는다). 매 갱신마다 실제 체력·최대 체력과 보호막(지속 중인 스킬 보호막 `shield` + 런 잉크를 포함한 잉크 보호막 `CombatArena.ReadInkShield()`, 전투가 피해를 흡수하는 값과 같다)을 관측해 변화로 연출을 시작한다. 보호막 감소는 같은 갱신 사이 `ReceivedHitCount`가 늘었을 때만 피격으로 보고, 아니면 런 잉크 보호막의 시간 감소로 보고 번쩍임·조각 없이 칸만 줄인다. 처음 관측·플레이어 교체·비활성화 후에는 연출 없이 기준값만 잡는다. 시계는 기존 피격 흔들림과 같은 `Time.unscaledTime`이다.
- 회복: 단색 게이지는 이전 값에 머물고, 늘어난 칸을 0.26초 동안 붓질로 칠한다(줄마다 앞끝이 들쭉날쭉, 앞쪽으로 튀는 잉크). 젖은 결은 0.55초 동안 마르고, 광택이 한 번 훑은 뒤 바닥 게이지로 넘어간다. 체력 숫자는 초록으로 물들고, `/ 최대` 옆에 큰 도트 `+N`(0.5초 안 회복 합산)이 0.85초 떠올랐다 사라진다.
- 보호막: 생기면 0.42초 동안 체력 끝에서부터 게이지 틀 바로 바깥 1화소(판의 크림 선 위)를 민트로 한 바퀴 덧그리고, 체력 끝 뒤 칸을 민트 붓질로 칠한다. 칠한 뒤에는 광택 줄이 흐른다. 피격으로 보호막이 깎이면 칸 끝이 번쩍이고 깎인 양만큼 민트 조각이 흩날린다. 0이 되면 덧그린 틀이 0.3초 동안 거꾸로 풀리고, 피격으로 깨졌으면 남은 칸이 조각으로 흩어진다. 체력+보호막이 최대 체력을 넘으면 분모를 그 합으로 바꿔 게이지 전체를 줄인다.
- 피해: 바닥 게이지는 즉시 새 값으로 줄고, 깎인 칸이 0.07초 하얗게 번쩍인 뒤 연해진다. 0.1초 뒤부터 0.36초 동안 오른쪽에서 왼쪽으로 좌우로 문지르듯 지워지고, 지운 자리에 옅은 얼룩이 0.5초 남으며 가루가 옆으로 튄다. 체력 숫자는 0.35초 빨강으로 물든다. 기존 피격 흔들림·게이지 번쩍임은 그대로 함께 재생한다.

보호막이 끝나기 직전의 깜빡임은 만료 시각을 HUD가 읽지 않아 넣지 않았다. 원본 시안은 pixelfx 코드 `전투테스트/체력바/`(`heal-a`·`shield-b`·`damage-a`)다. 수치·색은 `HealthBarInk`의 상수에서 조절한다.

전투 HUD는 실제 장착된 무기의 묶음만 표시한다. 미장착 슬롯의 빈 무기 원·키·스킬·팔레트는 숨기고 장착 시 함께 표시한다. 큰 무기 원은 기본 공격을 겸하고 A/S 키가 위쪽 테두리에 걸치도록 표시한다. 중복 기본공격 원은 없애고 Q/W 스킬 원만 무기 원 바로 옆에 붙인다. 스킬 원은 기준 지름 96으로 표시하며 평타 원 뒤에 일부 겹친다. 스킬 그림·충전 링·쿨타임은 같은 비율로 확대하고, 키캡은 기존 크기로 두 원보다 앞에 표시한다. 선택 링은 큰 원, 충전·쿨타임은 작은 원의 역할을 유지한다. 팔레트는 두 원 바로 아래에 겹쳐 놓고 5칸용 프레임 폭을 고정하며, 실제 3~5개 색상은 가운데 정렬한다. 개별 그림은 사용자 편집 원본을 사용하고 Unity의 묶음 배치만 조정한다. 첫 무기 묶음은 왼쪽으로 20, 두 번째는 110만큼 이동한다(1670×942 기준). 두 묶음의 시작점 간격은 280이다. 미니맵은 오른쪽 끝과 상단 위치를 유지한 채 프레임·내용 전체를 82%로 표시한다. `CombatWeaponLeftShift`·`CombatWeaponGapReduction`와 `CombatMinimapScale`로 전체 배치를 조절할 수 있다.

발사기는 [launcher_skills.json](../../../../data/combat/launcher_skills.json)의 실제 스킬 ID(`launcher_basic_special`, `launcher_range_special`, `launcher_move_special`, `launcher_followup_special`)로 모아쏘기·레이저·샷건·유탄·파편을 연결한다. 큰 무기 원과 출발 카드는 장착 스킬의 외형을 따르며, 기본 공격의 실제 동작은 항상 볼 탄환이다. 모아쏘기 충전 중에는 실제 ChargePolicy의 진행률을 표시하고, 발사 후 실제 쿨타임으로 전환한다. 기본 쿨타임은 6/8/7/9초이며 강화된 값은 런타임 충전 풀에서 읽는다. UI가 피해·차징 시간·쿨타임을 따로 계산하거나 인덱스 순서를 가정하지 않는다. 보유 열쇠와 입력 장치별 안내도 공통 게임 상태를 따른다.

버프칸은 `TemporaryGameGui.BuffSlots.cs`가 그린다. 두 칸 모두 승인 HUD 그림(1670×942)이 아니라 960×540 캔버스에 직접 놓고, 칸 크기를 아이콘 원본과 같은 24로, 좌표를 정수로 둔다. 캔버스는 화면을 정수배로만 키우므로(1080p·1440p에서 2배) 아이콘도 정확히 정수배(1080p에서 48px, 원본 1픽셀=화면 2×2)가 된다. 승인 HUD 그림의 가로 0.575·세로 0.573배 축소를 거치지 않기 위해서다. 캐릭터칸은 도트 체력판(`HealthPlaque`) 아래 게이지 왼쪽 끝 밑 (95, 96)에서 8 간격으로 한 줄 6칸(아래 보상 게이지 줄이 보이면 8 내린 (95, 104)), 보스칸은 보스 체력바 아래 y 45에 6 간격으로 놓고, 보스칸이 보이면 획득 알림과 안내 문구를 32만큼 내린다. 칸마다 아이콘·발동 조건 배지·어두운 덮개·남은 초 네 겹이며, 덮개는 아이콘과 같은 그림(알파 모양)을 `Radial360`·12시 시작·반시계 채움으로 두고 남은 비율만큼 채워 시간이 흐를수록 12시부터 시계방향으로 지워진다. 덮개의 비스듬한 경계와 남은 초 숫자는 화면 해상도로 그려져 2×2 블록을 따르지 않는다. 그림은 `Resources/BuffSlotIcons/`(원본 `resources/ui/buff-slot-icons/runtime`)다. 캐릭터칸의 원본은 `CombatActor.BuffSlotSource`(`IBuffSlotSource`)이며, `EnableSketchEquipment`가 `RunInkBuffSlots`를 연결한다. `RunInkGroup`은 같은 무기·같은 잉크 ID를 묶고 강화 슬롯을 반영한 최종 설명을 만든다. `BuffSlot`은 내부 쿨타임(`ReadyAt`·`Cooldown`)과 효과 지속(`ActiveUntil`·`ActiveDuration`)을 따로 담는다. 지속은 보라 부여 창(`SketchMount.ActiveRemaining`)과 이동속도·빨강 플레이어 버프(`CombatArena.ReadRunInkMountBuff`) 중 묶음에서 가장 긴 값이고, 분모는 `RunInkGroup.Duration`(중첩 계산된 부여 시간·빨강 지속)이다. 지속 중에는 덮개와 초를 숨기고 `BuffSlotGlow`(Presentation.Unity)가 칸마다 44×44 도트 텍스처(아이콘 사방 10)를 그린다. 아이콘 모양은 스프라이트 알파를 한 번 읽은 24×24 마스크로 지킨다. 읽기용 GPU 복사와 연출 텍스처는 사용 종료·GUI 파괴 때 해제한다. 준비 상태에서 지속·쿨타임이 새로 생기면 발동(섬광 0.22초·별빛)으로 보고, 지속 중 갱신(빨강)은 수면만 다시 올린다. 빛 알갱이는 태어난 자리·시각을 기억하는 파티클(0.1초 간격, 수명 약 1초, 14화소 상승)이라 갱신·깜빡임·지속 종료와 관계없이 이미 뜬 것은 끝까지 올라가며 사라진다. 지속이 끝나면 바닥 줄 번쩍임, 쿨타임이 끝나면 테두리 훑기를 그린다. 시계는 전투 시계(`arena.Now`)라 일시정지 중에는 멈춘다. 잉크색은 아이콘 계열(초록·빨강·금색·파랑·보라)의 6단계다. 빛은 Unity UI의 알파 혼합으로 표현한다. 연출이 이웃 칸(간격 8)까지 몇 화소 번지는 것은 사용자 판단으로 허용했다. 일부 장착본만 준비됐다면 준비 칸 수를 툴팁에 표시한다. `TemporaryGameGui.BuffSlots`의 마우스 툴팁과 장비 정보의 `DrawGroupedInkEffects`는 같은 간결한 묶음 설명을 사용한다. 장비 정보는 `ApprovedGroupedEffect`에서 기존 발동 조건·효과 색상을 적용하며, 보스 예외·갱신·상한 처리 설명은 묶음 설명에서 제외한다. 툴팁은 포인터 입력을 가로채지 않고 화면 안으로 위치를 제한한다. 보스칸은 `BossBuffSlots`가 `CombatActor.BossControl`의 실제 기절·속박 내부 쿨타임을 읽는다. Rose·Blue는 HUD가 따르는 보스 개체(`HudActor`)의 쿨타임만 표시한다.

## 에셋과 배치 수정

리소스 편집기에서 저장한 배치를 확정한 뒤 `python tools/assets/prepare_combat_hud.py`를 실행한다. 이 도구는 메인의 `ApprovedCombatHUD/bindings.json`, Unity 메타데이터, 명시적인 미디어 배치 계약을 준비한다. 이미지 원본 바이트는 변경하지 않는다. 메타데이터 GUID와 기존 계약의 다른 에셋은 보존한다.

무기 표시 이름은 `검`·`망치`·`발사기`를 사용한다. HUD 생성기는 먼저 `python tools/combat/export_unity_catalog.py`로 생성한 `MeleeCatalog.json`에서 무기 이름과 발사기 기본 외형의 표시 이름을 읽는다. 리소스의 보존된 검토 자료에 있는 예전 이름으로 되돌리지 않는다.

`WeaponDisplayNameIntegrationTests`는 1·2챕터의 실제 씬에서 세 무기를 획득·확정·장착한 뒤 인벤토리 이름, 로드된 HUD 무기·발사기 외형 이름과 열린 가방의 표시 문구가 일치하는지 검사한다. 가방 렌더링 캡처는 Git 제외 `outputs/weapon-display-names/captures/`에 저장한다.

개발 중 사용자가 요청한 로컬 적용 검토는 Unity를 닫고 `python tools/assets/update_assets.py --asset ui.combat-hud-expanded-20261106 --local-preview`로 수행한다. 이 명시적 옵션은 해당 에셋만 선택하며 원본 색인·해시, 목적지, 메타데이터, 로컬 수정 보호와 백업 검사를 그대로 수행한다. 미커밋 제작본을 검토하는 모드이며 배포 가능한 리소스 커밋을 뜻하지 않는다. 일반 적용은 기존의 깨끗한 고정 gitlink 검사를 유지한다. 팀 배포 전에 리소스 커밋·push·gitlink 확정이 필요하다.

## 확인

이미 배치한 로컬 제작본은 Unity 메뉴 `Tools > deviant > Combat HUD > Play Applied HUD`로 1챕터에서 바로 확인한다. 시작 도면 두 개를 F로 선택하면 출발 팔레트가 표시된다. 이 메뉴는 에셋을 덮어쓰거나 게임 규칙·프로필을 변경하지 않는다. 일반 게임 실행·팀 배포의 리소스 검증은 기존 경로를 따른다.

Unity 6000.6.5f1에서 `Chapter1SkillCooldownHudTests`와 전투 HUD 통합 검사를 실행한다. 실제 씬의 HP·독립 쿨타임·런 시작 팔레트·새 미술, 지도·가방·일시정지와 1920×1080 게임 캡처, 1280×720 안전 영역 배율과 런 1~6칸 팔레트(구형 경로 3~5칸)를 확인한다. 배치용 카메라 캡처는 창 바깥 검은 여백을 만드는 최종 backbuffer 캡처와 구분한다. 파일 검사, 컴파일, 게임 실행 결과는 각각 구분한다.

전투 키캡은 기본공격 1·2에 A/S, 스킬 1·2에 Q/W를 표시한다. HUD와 첫 런 전투 수첩은 `Weapon1Basic`, `Weapon2Basic`, `Weapon1Special`, `Weapon2Special`의 현재 바인딩을 직접 읽으므로 재설정한 키와 패드 표기도 즉시 반영한다. 키 글자를 이미지에 고정하지 않는다.

무기가 내구도로 부서질 때(사용자 결정 2026-11-13) `TemporaryGameGui.WeaponBreak.cs`가 `SketchArsenal.WeaponDestroyed`(가방 보관 중 파괴는 제외)를 받는다.
- HUD: 실제 칸은 곧바로 맨손이 되고, 그 위(바로 다음 형제)에 부서지기 직전 무기 묶음의 복제를 얹는다. 복제의 원판·링·무기 그림은 한 장(화면 2배 해상도)으로 구워 그 칸을 왼쪽 위에서 오른쪽 아래로 물결지며 지우고(12칸), 지우는 가장자리에서 가루가 떨어진다. 스킬 원·스킬 키·팔레트는 4칸째부터 8칸에 걸쳐 흐려진다. 한 칸 60ms, 모두 23칸 뒤 복제를 지운다. 층 순서는 묶음 그대로라 지워지는 원은 키캡·팔레트 판 뒤에 있다. UI `Mask`(스텐실)는 캡처·일부 환경에서 가려진 것이 통째로 사라져 쓰지 않는다.
- 캐릭터: `Deviant.Presentation.Unity.WeaponBreakBurst`가 손 자리(발 가운데에서 앞 19, 위 23 게임 화소)에 게임 화소(32 = 1유닛) 한 장으로 연출을 그린다. 처음 두 칸은 반지름 16·24의 꽉 찬 하얀 원과 긴 십자 빛, 다음 두 칸은 퍼지는 고리, 파티클 44개(흰색·크림·먹, 1~3화소). 14칸 뒤 스스로 지운다. 무기 그림은 바꾸지 않으므로 무기 종류와 상관없이 같은 연출이고, 공격 도중이면 공격은 기존 규칙대로 끊기고 맨손이 된다.

잉크 묶음은 `Deviant.Combat.Tests.RunInkCombatTests`에서 같은 무기의 중복 합산·무기/발동 조건별 분리·강화 환산·부분 준비·실제 활성 시간(보라 부여 창·이동속도·빨강 갱신)과 쿨타임의 분리 연결을 검사한다. 지속 연출은 `Deviant.Presentation.Tests.BuffSlotGlowTests`(발동 판정·수면 높이·갱신·종료·준비·마스크)와 `Chapter1BuffSlotHudTests`(지속 칸의 덮개 숨김·연출 층, 보스 덮개에는 시험용 12/8초 주입; 실제 게임은 재부여 제한 0초)가 검사한다. 실제 전투 화면에서의 가독성은 플레이 확인 대상이다. `ForestCombatV2.Tests.GroupedInkTooltipTests`는 툴팁 텍스트 갱신·줄바꿈·화면 경계·입력 비차단·HUD 없는 상태의 숨김을 검사한다. 실제 마우스 조작의 가독성은 플레이 확인 대상이다.

## 공용 일시정지 버튼

마을·1챕터·2챕터의 상단 일시정지 버튼은 공통 `HudButtonSprite`와 승인된 `HudPixelKit.Button` 그림을 사용한다. 기본 그림은 34×34 게임 화소·Point 필터이며 가운데 정렬된 밝은 두 막대와 어두운 판·얇은 크림색 테두리로 표시한다. 마을의 기존 위치 기준(위 14, 오른쪽 16 게임 화소)과 `HubPause` 동작은 유지하며 별도 둥근 버튼이나 막대를 그리지 않는다.

## 지도 공용 픽셀 아이콘

전체 지도와 전투 미니맵은 `Resources/RecoveredMapIcons`의 같은 25×25 스프라이트 14종을 사용한다. 별도 13px판을 사용하지 않는다. 원본은 `resources/ui/map-icons-recovered-25`이며 Unity 적용은 배치 계약의 `ui.map-icons-recovered-25`를 따른다. 포탈 2는 수정된 숫자를 유지하고 포탈 1과 외형을 공유하며, 위험 상자는 상자방 그림에 느낌표를 더한다. 미니맵의 외곽 크기·확대·발견/클리어 판정·이벤트 구현 범위는 기존 규칙을 유지한다. 가져오기는 Point·무압축·밉맵 없음으로 고정한다.

지도상의 현재 위치·설치 포탈·회복소·출구 및 실제 봉인 석판은 월드 발 좌표를 그대로 유지하고, 그림 하단을 그 점보다 UI 2화소 위에 둔다. 캐릭터의 발밑 좌표에 그림 중심을 맞추지 않는다. 방 종류는 방 중앙 표시를 유지한다. 미탐험 방향의 물음표는 통로 상단보다 위에 표시하여 좁은 발판 사이에 끼지 않게 한다.

전체 지도 범례 상단은 현재 위치 → 살아 있는 적 → 포탈 1 → 포탈 2 → 미탐험 방향 → 출구 순서다. 중간 구분선 아래에는 보스·엘리트 → 상점 → 잉크 충전소 → 봉인 도전방 → 상자방 → 정령 구출 → 묘목 생존 → 위험 상자 → 함정 수집을 모은다. 출구의 챕터별 이름과 범례 스크롤은 유지한다.

카메라 범위는 범례 항목에서 제외한다. 하단 조작 안내의 전체 보기 옆에 지도 안의 점선과 같은 색의 작은 점선 사각형 및 현재 화면 범위 문구로 안내한다. 이 안내는 클릭 동작이 없는 표시다.

지도 하단 네 키 안내와 확대율은 Figma `14:50309`의 1920×1080 원본 좌표를 기준으로 표시한다. 키 박스는 높이 41.195·모서리 4·테두리 1 디자인 화소이며, 테두리 `#939ca6`, 글자 `#b3bbc4`, 키 글자 22·설명 23을 사용한다. 기본 표기는 `방향키`, `＋ / −`, `C`, `Home`이고 `확대·축소`의 가운데점을 유지한다. 원본 글꼴이 지원하지 않는 기호만 기존 공용 글꼴로 보완하며 다른 화면의 문구 변환은 바꾸지 않는다. 키 재설정과 게임패드 전환 시 실제 바인딩을 표시하고, 현재 위치·전체 보기의 클릭 동작을 유지한다.

지도 검수는 Unity 6000.6.5f1의 `Tools > deviant > Approved UI > Capture recovered map icons` 또는 `-executeMethod Deviant.Game.Editor.RecoveredMapCapture.Run -quitAfterHudCapture`로 실행한다. 일반 Editor는 실제 1920×1080 Game View를 `outputs/recovered-map-camera-footer/`에 캡처하고, `-batchmode` 실행은 실제 합성 화면을 캡처하지 않고 `outputs/recovered-map-batch-verification/`에 검사 결과를 남긴다. 검사는 아이콘의 크기·Point 필터·RGBA 해시, 지상 마커 좌표, 범례 순서·구분선·하단 범위 안내, 하단 키 박스 좌표·크기·문구·글리프 지원·확대 키 재설정 반영을 확인한다. 두 실행 방식 모두 각자의 출력 폴더에 `footer-ui-reference-1920.png`·`footer-ui-reference-1280.png`를 별도로 저장한다. 이 두 이미지는 1920×1080·1280×720의 독립 UI 렌더 비교본이며 실제 Game View 캡처와 구분한다. 하네스는 메모리 프로필과 실제 2챕터 씬을 사용하며, 포탈 두 개의 설치 상태는 검증용으로만 준비한다. 배치 검증이나 독립 UI 비교본을 실제 합성 화면이나 플레이어 빌드의 확인으로 대신하지 않는다.
