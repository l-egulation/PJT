# 캐릭터·치장·도감 통합 계획

## 목적

2026-09-01에 병렬로 정리된 캐릭터·치장·도감 통합 명세와 치장 뽑기 설계를 하나의 구현 기준으로 합친다. 이 문서는 원문을 다시 정본으로 만들지 않고, 어떤 결정을 현재 SSOT와 요구사항에 전파할지 기록한다.

## 확정 결정

1. 최초 획득은 자동 등록한다. 처음 얻은 치장은 즉시 외형 해금, 도감 등록, 1성 상태가 된다.
2. 중복 획득은 미등록 중복 재고로 보관한다. 사용자는 이 재고를 거래하거나 성급 등록에 사용할 수 있다.
3. 거래 가능한 치장은 미등록 중복 재고뿐이다. 이미 등록된 외형 권한, 등록 수량, 성급, 도감 상태는 거래할 수 없다.
4. 중복 등록은 `1개 등록`과 `다음 성급까지 등록` 두 명령만 제공한다. 서버가 필요한 수량을 계산하고 거래 예약 수량을 제외한다.
5. 치장 최대 성급은 5성이다. 1~5성 임계값은 버전된 콘텐츠 설정이 소유하며 1성 임계값은 1이다.
6. 도감은 고유 등록 치장 수, 등록 현황, 미보유 필터, 세트 이동과 완성 기록만 제공한다. 도감 단계, 단계 보상과 도감 전투 효과는 제공하지 않는다.
7. 세트는 `HEAD`, `TOP`, `BOTTOM`, `GLOVES`, `SHOES`, `CAPE` 여섯 부위를 정확히 하나씩 가진다.
8. 세트 성급은 여섯 부위 치장 성급의 최솟값이다. 하나라도 미등록이면 0성이고 효과가 없다.
9. 세트 성급 효과 행은 해당 성급까지의 누적 총값이다. 서버는 이전 단계 행을 다시 합산하지 않는다.
10. 모든 완성 세트 효과는 착용 상태와 무관하게 동시에 적용한다.
11. 치장 착용, 교체, 해제는 외형만 바꾸며 전투 능력치에 직접 영향을 주지 않는다.
12. 세트 보유 효과는 서버 권한 상태에는 즉시 확정하지만, 진행 중인 메인 전투에는 현재 사이클을 유지하고 다음 사이클 시작부터 적용한다.
13. 클라이언트는 확률, 결과, 성급, 도감 단계 부재, 세트 효과, 최종 능력치를 계산하지 않는다.
14. 원문 `design-input.md`는 reference이며 현재 구현 기준은 각 SSOT와 이 통합 계획이다.
15. 2026-09-02 콘텐츠 바이블 결정은 치장 표시명, 카탈로그, 비용 기준, 확률, 성급 임계값, 세트 효과와 도감 무효과 원칙을 [MVP 치장 콘텐츠 v1](../../60-content/cosmetics/mvp-v1.md)과 [치장 SSOT](../../30-domain/cosmetics/ssot.md)에 전파한다.

## 확정 구현 콘텐츠와 후속 콘텐츠 입력

[MVP 치장 콘텐츠 v2 임시 카탈로그](../../60-content/cosmetics/mvp-v1.md)은 다음 값을 현재 구현 입력으로 제공한다.

- `cosmetic-001`~`cosmetic-066` 번호형 영구 ID
- 노말 4·희귀 3·영웅 3·전설 1의 임시 11세트 배치
- 세트별 여섯 부위 구성
- 공통 1회 5,000쌀과 등급별 확률
- 등급별 1~5성 누적 등록 임계값
- 세트 성급별 기본 3축 누적 총 효과

실제 치장·세트 표시명, 이미지와 전설 고유 효과는 후속 콘텐츠 입력이다. 현재 UI는 번호형 fallback과 이미지 준비 상태를 표시하며 이를 영구 콘텐츠 이름이나 실제 외형으로 해석하지 않는다. 런타임은 기존 30종 개발 초안을 유지하지 않고 이 임시 카탈로그로 clean cutover한다.

## 업로드와 검증 계획

1. 이 디렉터리에 원문 입력과 통합 계획을 보존한다.
2. 결정 로그에 병렬 승인 충돌을 통합 결정으로 기록한다.
3. 치장·아이템·거래소·전투·계정·UX·저장·네트워킹·콘텐츠 문서를 책임별로 갱신한다.
4. 요구사항 문서의 기존 `targetStar` 승급 검증을 `1개 등록`과 `다음 성급까지 등록` 검증으로 교체한다.
5. Markdown 링크와 공백 오류를 검사한 뒤 커밋한다.
