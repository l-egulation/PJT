## 범위와 책임

이 계획은 장비의 다음 강화 비용에서 재료가 부족할 때 장비 화면을 이탈하지 않고 부족 재료 하나를 거래소 매수 IOC로 구매하는 흐름을 연결한다. 강화 비용과 실행 가능 여부는 [장비·제작·강화 SSOT](../../30-domain/items/equipment/ssot.md), 주문·체결·가격 상한은 [거래소·경제 SSOT](../../30-domain/economy/ssot.md), 화면 상호작용은 [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md)가 소유한다.

이번 범위는 `강화`에만 적용한다. 최초 제작·승급, 스킬 성장, 여러 부족 재료의 일괄 구매, 대기 매수 주문, 구매와 강화의 결합 명령은 포함하지 않는다.

## 확정 요구

1. 장비 강화 카드의 부족 재료 행마다 해당 재료의 간편 구매 동작을 제공한다.
2. 한 번의 구매 흐름과 거래소 command는 사용자가 선택한 재료 하나만 처리한다.
3. 구매 확인은 본인 주문을 제외한 현재 최저 매도호가를 수정 가능한 개당 최대 단가 기본값으로 사용한다.
4. 예상 즉시 체결 수량·가격 범위·가중평균 단가·미체결 수량과 최대 예상 지출을 확인한 뒤 매수 IOC를 제출한다.
5. 서버는 최대 단가 이하의 상대 매도 주문만 엄격한 가격·시간 순서와 maker 가격으로 체결한다.
6. 시장 잔량·사용 가능 쌀·가격 상한 때문에 요청 수량을 채우지 못해도 한 개 이상 체결했으면 실제 체결분을 확정하고 잔량은 주문장에 남기지 않는다.
7. 부분 구매 뒤 부족량이 남으면 강화는 계속 비활성화한다.
8. 구매로 모든 강화 비용을 충족해도 강화를 자동 실행하지 않고 기존 강화 확인을 별도로 거친다.

## 용어와 수량

- `부족 수량 = max(강화 필요 수량 - 현재 사용 가능 수량, 0)`이며 서버 장비 조회 응답을 사용한다.
- 구매 요청 수량은 부족 수량 전체다. 거래소 전용 999개 상한으로 나누지 않으며 사용 가능 쌀·시장 잔량·저장 정수와 안전한 곱셈 범위를 서버가 검증한다.
- `현재 최저 매도호가`는 활성 상대 매도 주문 중 가장 낮은 단가다. 본인 주문은 공개 시장 잔량에는 포함되지만 구매 기본값·예상 체결·실제 체결에서는 제외한다.
- `개당 최대 단가`는 총액 상한이 아니며 10~999,999쌀 범위의 1쌀 단위 정수다.

## 사용자 흐름

1. 장비 화면은 서버가 반환한 다음 강화 비용의 재료별 필요량·보유량·부족 여부를 표시한다.
2. 부족한 재료 행에만 `거래소 구매` 동작을 표시한다. 쌀 부족, 조건 미충족과 최대 단계에는 제공하지 않는다.
3. 사용자가 재료 하나를 선택하면 해당 시장 품목의 IOC 견적을 조회한다. 다른 부족 재료를 동시에 선택하거나 자동 처리하지 않는다.
4. 확인 화면은 재료명, 현재 보유·필요·부족 수량, 요청 수량, 현재 최저 매도호가, 수정 가능한 최대 단가, 예상 체결 수량·가격 범위·가중평균 단가·미체결 수량, 사용 가능 쌀과 최대 예상 지출을 표시한다.
5. 최대 단가는 현재 최저 매도호가로 채우되 사용자가 수정하고 명시적으로 `구매 확인`을 눌러야 한다.
6. 상대 매도 주문이 없으면 매물 없음과 수동 새로고침을 표시하고 구매를 막는다. 본인 주문만 있으면 상대 주문이 없다는 이유를 구분한다.
7. 최대 단가가 현재 최저 매도호가보다 낮으면 현재 조건에서 즉시 체결할 수 없음을 표시하고 구매를 막는다.
8. 확인하면 선택한 시장 품목, `BUY`, 요청 수량, 최대 단가와 `IOC`를 하나의 거래소 주문 command로 전송한다.
9. 성공 후 실제 구매 수량·가격 범위·가중평균 단가·총 지출·미체결 수량·남은 부족 수량을 표시하고 장비 상태와 거래소 견적을 다시 조회한다.
10. 모든 강화 비용을 충족하면 기존 강화 버튼을 활성화하되 구매 결과 화면에서 강화 command를 전송하지 않는다.

## 가격 상한과 체결

- 견적은 조회 시점 정보이며 가격이나 수량을 예약하지 않는다.
- 주문 command는 최신 주문장, 매수 시 본인 매도 주문 제외, 매도 시 본인 반대 주문 교차 거절, 사용 가능 쌀과 인벤토리 수용량을 서버 권한으로 재검증한다.
- 상대 매도 주문은 최저 가격·같은 가격의 빠른 주문부터 maker 가격으로 체결한다.
- 조회 뒤 더 싼 매도가 생기면 더 싼 maker 가격을 적용하고 최대 단가보다 비싼 매도에는 체결하지 않는다.
- 상한 이하 물량이나 쌀이 일부뿐이면 가능한 수량만 체결하고 미체결 잔량은 자동 예약하지 않는다.
- 체결·쌀 차감·재료 지급·매도 주문 잔량·거래 기록·정산 우편은 거래소 transaction 경계를 유지한다.

## 조회·명령 계약

### 단일 재료 IOC 견적

`GET /api/v1/market/instruments/{instrumentId}/order-quote?side=BUY&timeInForce=IOC&quantity={quantity}&limitUnitPrice={price}`

응답은 예상 체결·미체결 수량, 최저/최고 체결 단가, 가중평균 단가, 총액, 사용 가능 쌀과 `marketRevision`을 제공한다. 상대 주문이 없으면 가격과 가중평균은 `null`, 예상 체결 수량은 0이다.

### 단일 재료 IOC 구매

`POST /api/v1/market/orders`

요청 body:

```json
{
  "instrumentId": "POTATO_M1",
  "side": "BUY",
  "quantity": 1000,
  "limitUnitPrice": 2500,
  "timeInForce": "IOC"
}
```

- 멱등성 fingerprint에는 시장 품목, 방향, 수량, 최대 단가와 IOC를 모두 포함한다.
- 성공 결과는 실제 체결·미체결 수량, 가격 범위·가중평균 단가·총액과 개별 체결을 반환한다.
- 한 개도 체결하지 못하면 상대 잔량 없음, 가격 상한 불충족, 쌀 부족과 자기 주문 교차를 구분하며 상태를 변경하지 않는다.

### 장비 재조회와 강화

구매 성공 뒤 `GET /api/v1/equipment`를 다시 호출한다. 강화는 기존 `POST /api/v1/equipment/{slot}/enhance`만 사용하며 구매와 다른 멱등성 키·사용자 확인을 가진다.

## 상태와 오류 표시

| 상태 | 화면 동작 |
| --- | --- |
| 견적 조회 중 | 선택 재료의 중복 구매를 막고 다른 재료를 자동 처리하지 않는다. |
| 상대 주문 없음·본인 주문만 존재 | 구매할 상대 물량이 없다는 이유와 새로고침을 표시하고 구매를 막는다. |
| 상한 입력 오류 | 10~999,999쌀·1쌀 단위 범위를 안내하고 구매를 막는다. |
| 상한 이하 물량 없음 | 가격 변화를 표시하고 최신 견적을 다시 조회한다. |
| 부분 구매 | 실제 구매량·가격 범위·가중평균·지출·미체결 및 남은 부족량을 표시한다. |
| 모든 비용 충족 | 강화 가능 상태를 표시하되 별도 강화 확인 전에는 실행하지 않는다. |
| 응답 유실 | 같은 멱등성 키로 결과를 조회·재시도하며 새 주문으로 간주하지 않는다. |

## 검증 기준

- 세 재료가 모두 부족해도 한 번의 확인과 주문에는 선택한 재료 하나만 포함된다.
- 부족 수량이 1,000 이상이어도 인위적으로 999개로 줄이지 않는다.
- 본인 매도 주문은 공개 시장 정보에는 포함되지만 최저 상대 매도호가·견적·체결에서는 제외된다.
- 예상 체결 수량·가격 범위·가중평균 단가와 수정 가능한 최대 단가를 구분한다.
- 상한 이하 상대 주문만 maker 가격과 엄격한 가격·시간 순서로 체결한다.
- 부분 체결 후 미체결 잔량을 주문장에 남기지 않고 장비 상태를 다시 조회한다.
- 다른 부족 재료를 자동 구매하지 않고 모든 비용 충족 뒤에도 강화를 자동 실행하지 않는다.
- 구매와 강화의 멱등성 키가 분리되고 구매 재시도가 중복 체결을 만들지 않는다.
