# 타격감 개선 계획

[분야 개요](README.md)

## 목적과 적용 상태

공격의 화려함보다 **빗나감·일반 명중·강타·처치가 즉시 구별되는 것**을 목표로 한다. 보유한 **`VFX - Impact and Hit - Vol 2`**를 중심으로 명중 VFX, 물리 시체 파편, 카메라 킥, 화면 왜곡 충격파, 짧은 슬로모션을 단계적으로 추가한다.

이 문서는 작업 범위와 적용·검증 기준이다. 공통 명중 정보·프리팹 Cue/풀·Game/Lab 연결·로컬 잔해 물리·카메라 킥·월드 왜곡·독립 슬로우 요청은 코드에 연결돼 있다. **승인 아트 전체 복원, 종별 실제 잔해 전환·게임 화면 튜닝·전체 씬/빌드는 별도 완료 조건**이다. 발동 자격과 시험 수치를 제품 확정값으로 취급하지 않는다.

### 현재 사용 경로

- `HitFeedbackBridge`: 공통 `CombatContentLoader`가 아트 사용 모드의 Game/Lab에 명시 주입한다. 이미지 없는 구조 검사는 테스트에서만 별도 주입한다.
- 몬스터 명중 그림은 **도트 타격 + 종이 화풍 프리팹**으로 확정이다. 보유 팩의 44개 프리팹(SimpleImpact 22개·ImpactOrange 10개·ImpactStreetArt 12개)을 로컬 Variant로 연결한다. 큰 둥근 고리 `VFX_ImpactOrange (1)`(`hit_blunt`)은 치명타 전용이고, 평소 수락된 플레이어 명중은 나머지 43개 중 하나를 무작위로 재생한다. 같은 효과가 연속으로 나올 수 있다. 원본 내부의 복합 파티클을 사용하며 `hit_core`·`hit_fragments`를 별도 프리팹으로 중복 생성하지 않는다.
- 무작위 선택은 명중 사건의 seed를 섞어 결정하고 게임 전역 난수 상태를 소비하지 않는다. 치명타 여부는 피해를 정할 때 굴린 결과를 명중 기록에 그대로 실어 읽는다. F1의 종류 고르기와 F11의 조합 비교는 없으며 편집기·개발 빌드·배포 빌드가 같은 규칙을 쓴다. 끄기는 기존 명중 VFX 스위치를 사용한다.
- 명중 VFX의 표시 크기는 [`data/presentation/hit_feedback.json`](../../../../data/presentation/hit_feedback.json)의 `recipes[].scale`이 소유한다. 현재 배율은 `hit_slash` 1.632·`hit_pierce` 1.152·`hit_blunt`(치명타) 1.824·`hit_projectile` 1.056이며, 나머지 후보는 공통 시험 배율 1.632를 사용한다. 하위 파티클도 계층 배율을 따라 확대하며, 무기 공격 궤적·시체 파편·카메라 반응·공격 판정의 크기와는 독립이다. 설정 변경 후 리소스를 재생성하고 Player 빌드를 갱신해야 실행 파일에 반영된다. 개별 후보의 최종 화면 튜닝은 별도다.
- `distortAllHits=true`인 현재 시험 설정에서는 플레이어의 모든 기본·특수 공격이 실제 명중하고 공통 명중 VFX 재생이 수락됐을 때 왜곡 충격파를 요청한다. 빗나감·거절된 타격·중복 재샘플에는 요청하지 않으며 동시 파동 상한 4개와 F1 화면 반응 강도를 유지한다. `false`이거나 필드가 없으면 `strongActions`에 명시된 공격만 요청한다.
- 왜곡의 현재 지속시간·최대 반경·단일 파동 변위·띠 폭은 표현 원본의 `waveSeconds`·`waveRadiusPixels`·`wavePixels`·`waveWidthPixels`를 따른다. 중첩 변위의 총 상한은 같은 원본의 유한 양수 `waveMaxPixels`를 사용하며 출력 코드의 고정 수치로 다시 제한하지 않는다. F1 강도는 파동 변위와 총 상한에 함께 적용한다. 설정된 지속시간에 걸쳐 반경이 0에서 최대값으로 퍼지며 강도는 감쇠한다. 지속시간 변경은 사망 슬로우나 명중 VFX 수명을 변경하지 않는다.
- 큰 카메라 킥 강조는 비어 있는 `strongActions`에 명시 콘텐츠가 등록돼야 한다. 모든 명중 왜곡을 켜도 일반 명중을 강타로 승격하지 않는다. 슬로우는 플레이어 본인의 실제 사망 때만 발동하며 일반·엘리트·보스 처치에는 발동하지 않는다. 이전 `HitFeedbackTarget.importantDeath` 값은 시간 자격으로 사용하지 않는다.
- 카메라·왜곡 감소/끄기는 `HitFeedbackBridge.motionIntensity`의 0..1 출력 설정이다. F1 전투 테스트 장비 패널의 슬라이더·끄기/50%/100% 버튼과 Inspector/API로 조정한다. 게임 수치·사망 슬로우는 바꾸지 않으며 제품 영구 옵션 저장 메뉴를 추가한 것은 아니다.
- 일반 숲·들판 몬스터는 실제 death clip 완료가 잔해 생성 포트다. 1챕터 마을 몬스터는 체력이 0이 되는 프레임에 처치 보상과 함께 물리 파편을 생성하고(물리 세계 투입은 다음 전투 단계), 마지막 타격의 짧은 흰 점멸(0.08초) 뒤 몸을 숨겨 파편이 몸을 대신한다. 처치 실루엣과 작은 잉크 파편은 유지한다. 모션·이미지·캐시가 없으면 해당 출력을 진단하고 기존 사망 처리는 유지한다.
- `paperInk=true`인 현재 설정에서는 프리팹 명중 VFX를 흰 몸·1게임픽셀 안쪽 외곽선·빗금으로 그린다. 외곽선 기본색은 표현 원본의 `paperOutlineColor`(`#RRGGBB`, 현재 검정 90% 정도의 짙은 중성 회색 `#1A1A1A`, RGB 26·26·26)이며 빗금색과 독립적이다. 960×540 화소 격자에서 이진 경계를 사용하며 안티앨리어싱은 적용하지 않는다. 적용 대상은 종이 화풍 명중 VFX다. F1의 **명중 VFX 외곽선 설정**에서 색상 코드 적용·원본 기본값 복원을 제공한다. 변경은 현재 재생·정지 중인 효과와 이후 명중에 즉시 반영하며 전투 시각·피해·효과 재생 시각을 변경하지 않는다. F5는 선택을 유지하고 새 씬은 원본 기본값으로 시작한다. 실행 중 재질 사본만 변경한다.
- F1에서 명중 VFX·명중 흰 점멸·시체 물리 파편·명중 카메라 반응·명중 화면 왜곡·플레이어 사망 슬로우를 독립 제어한다. 기본은 모두 켜짐이며 전투 리셋에서도 선택을 유지한다. 끄기는 자기 출력만 즉시 정리하고 다시 켜기는 과거 사건을 재생하지 않는다. `CombatFeelFeedback`의 F6/F7/F8, 검 접촉광, 검·채찍 궤적·피해 숫자·처치 실루엣은 함께 유지한다.

현재 들판 6종은 승인 idle Sprite의 분할 캐시와 실제 death clip을 사용한다. 구형 공통 숲의 `World/Monsters/Data/{boar,eye}.asset`에는 move/attack만 있고 death 바인딩이 없으므로, 두 종은 기존 0.6초 페이드를 유지하고 파편 전환을 미지원으로 진단한다. 기본 Sprite 캐시가 생성돼 있다는 이유로 다른 종의 죽음 그림이나 임의 완료 시각을 연결하지 않는다.

### 로컬 보유 에셋 복원·생성

팩은 Asset Store 제품 **382436 / 버전 1.0**이다. 원본 아카이브 SHA256은 `04ee5667913bca16e0986783b5372aa5388338947922aa1b28c48c643510ef85`다. [보유 VFX 관리 규칙](../../../assets/README.md#기존-추적-파일과-라이선스)에 따라 원본 텍스처는 비공개 resources의 `effects/wallcoeur/`에서 LFS로 관리하고, 메인의 고정 배치 계약으로 기존 Unity 경로에 복원한다. 프리팹·재질·셰이더·`.meta`·GUID는 메인에 유지한다. 프로젝트용 생성 Variant·바인딩은 별도 구현에 의존하는 로컬 산출물로 Git에서 제외한다. 비공개 저장 여부만으로 라이선스 확인을 완료 처리하지 않으며 공개·제3자 전달·외부 배포 전에는 라이선스와 수신자의 사용 권한을 별도로 확인한다.

```sh
python3 tools/combat/import_hit_feedback.py '/보유경로/VFX - Impact and Hit - Vol 2.unitypackage'
python3 tools/combat/export_hit_feedback.py
python3 tools/combat/export_hit_feedback.py --check
```

생성 바인딩(`Presentation/Resources/HitFeedback/Generated/`)은 Git에서 제외되므로 체크아웃마다 만들어야 한다. 사람이 여는 에디터는 시작할 때 바인딩이 없거나 원본 JSON 해시/후보 목록이 오래됐으면 `HitFeedbackBindingsGuard`가 자동으로 생성하고, `GameBuilder.BuildWindows`(공용 Windows 빌드)는 빌드 직전에 항상 다시 생성한다. 배치 테스트는 자동 생성하지 않으므로 `-executeMethod Deviant.Presentation.Editor.HitFeedbackBindingsGuard.EnsureBuilt`를 먼저 실행한다. 수동으로는 기존 승인 이미지 복원 후 Unity 6000.6.5f1의 **Tools > deviant > Presentation > Build Hit Feedback Bindings**를 실행한다. 원본은 `Assets/ThirdParty/Wallcoeur`, 로컬 산출물은 `Assets/Deviant/Presentation/Resources/HitFeedback/Generated`다. 생성기는 파일/GUID를 참조하고 원본 픽셀·프리팹을 덮어쓰지 않는다. 이미지 없는 체크아웃은 [검증 절차](../../testing/testing.md)의 격리 프로젝트를 사용해 orphan `.meta`가 원본에서 제거되지 않게 한다.

일반 이미지·벽 이동·점프·포탈·마을·시작 마을은 [고정 리소스 배치 계약](../../../assets/README.md)으로 준비한다. 승인 바이트만 운반하고 게임 카탈로그·`manual_checkpoint.json`의 시간표·Unity GUID를 이미지 준비에서 다시 생성하지 않는다. 필요한 미디어가 계약에 없거나 원본/해시가 맞지 않으면 검증을 중단하며 다른 패키지로 자동 보충하지 않는다. 배경 재제작은 이 전투 작업의 범위가 아니다.

데이터 계약·실행 순서·시간·소유권·실패 처리의 구체적인 v1 제안은 [타격감 개선 기술 설계](combat-hit-feedback-design.md)에 둔다. 이 문서는 작업 범위·구현 단계·검증 방법을 관리한다.

## 1. 작업 범위

### 포함

- 보유 VFX 팩을 활용한 실제 명중 위치의 접촉 효과와 장식 파편
- 기존 몬스터 피격 점멸의 가독성·정렬 보완
- 몬스터 기본 프레임을 자동 분할한 물리 시체 파편
- 짧은 방향성 카메라 킥
- 명중점에서 퍼지는 월드 화면 왜곡 충격파
- 플레이어 본인 사망 순간의 짧은 슬로모션
- 중복 재생·동시 효과 제한, 풀링, 정지·리셋·씬 전환 정리

### 제외·보존

- 효과음 제작·교체·튜닝은 제외하고 기존 음향을 유지한다. 신규 팩의 음향도 자동 연결하지 않는다.
- 히트스톱은 추가하지 않는다.
- 피해량·공격 판정·공속·경직·넉백 수치를 변경하지 않는다.
- 승인 캐릭터·몬스터 원본 이미지와 모션을 변경하지 않는다.
- 시체 파편에 피해·보상·피격 대상·공격 차폐 역할을 추가하지 않는다.
- 새 몬스터 종류나 치명타·속성 규칙을 이 작업에서 확정하지 않는다.
- 슬로모션만 명시적인 시간 정책 확장으로 다루며, 기본 공속 변경과 구분한다.

## 2. 적용 에셋과 역할

### 보유 팩에서 선별

`VFX - Impact and Hit - Vol 2`의 제공 파티클·메시 효과를 실시간으로 렌더링하는 방향이다. 2D 스프라이트로 변환하거나 기존 Sprite Cue에 맞춰 베이크하는 것을 전제로 하지 않는다.

아래 ID는 **계획상 역할 이름**이며, 이미 등록된 Cue ID나 확인된 패키지 프리팹명이 아니다.

| 역할 | 선별할 표현 | 적용 대상 |
|---|---|---|
| `hit_core` | 첫 순간부터 보이는 짧고 선명한 명중 섬광 | 공통 명중 |
| `hit_slash` | 베는 방향의 짧은 절단선·접촉 파열 | 검·대검 등 베기 |
| `hit_pierce` | 좁은 접촉점과 진행 방향으로 뻗는 충격 | 레이피어·단검 등의 찌르기 |
| `hit_blunt` | 뭉친 중심이 압축되었다가 깨지는 충격 | 망치·방패 등 둔격 |
| `hit_projectile` | 작은 탄착점과 방향성 조각 | 탄환·레이저 등 원거리 명중 |
| `hit_fragments` | 빠르게 흩어지고 사라지는 작은 장식 파편 | 명중 주변 보조 표현 |

역할마다 별도 프리팹이 반드시 필요한 것은 아니다. 적합한 원본을 크기·색·방향·재생 속도로 변형하고, 부족한 부분만 보완한다. 기존 PPU32는 Sprite의 크기 기준이며 신규 VFX까지 픽셀 이미지로 제작해야 한다는 제약이 아니다. 월드 크기와 최종 화면에서의 조화를 기준으로 조정한다.

### 기존 에셋 재사용

| 표현 | 재사용 대상 |
|---|---|
| 무기 공격 궤적 | `EffectsApproved11`의 무기별 승인 효과 |
| 총구·레이저·유탄 폭발 | 기존 `ApprovedRangedEffects` 바인딩 |
| 몬스터 흰 점멸 | `Chapter1HitFeedback/UnlitHit` 셰이더·머티리얼 |
| 피격·죽음 자세 | 기존 승인 몬스터 스프라이트·모션 |
| 물리 시체 파편 | 몬스터 기본 프레임의 원본 텍스처 |

신규 구매는 하지 않는다. 별도 픽셀 VFX 팩, Cartoon FX, Feel 등을 초기 필수 의존성으로 추가하지 않는다. 보유 팩의 라이선스상 팀 사용·원본 공유 범위를 확인한 뒤 저장·전달 방법을 정한다.

### 직접 구현할 부분

- 기존 Cue 재생 경계의 프리팹 매체 바인딩·재생·풀 반환
- 실제 명중 정보와 무기별 효과 매핑
- 시체 분할 메시·충돌 모양 생성과 파편 물리·걷어차기
- 기존 카메라 출력에 합성하는 방향성 킥
- 필요 시 월드 합성 화면용 왜곡 셰이더·머티리얼
- 기존 공통 시간 제어의 슬로모션 요청 합성

## 3. 상황별 표현

다음은 적용 기준과 조정할 구성안이다. 현재 시험 설정은 모든 수락된 플레이어 명중에 왜곡을 요청한다. 큰 카메라 킥 강조의 발동 목록은 별도 확정하며, 사망 슬로우의 자격은 플레이어 본인 사망으로 한정한다.

| 상황 | 적용할 구성 |
|---|---|
| 빗나감·무적 등으로 거절된 타격 | 기존 공격 궤적만 유지하고 신규 명중 효과는 생성하지 않음 |
| 일반 명중 | 공통 섬광 + 무기별 접촉 효과 + 작은 파편 + 기존 흰 점멸 보완 + 시험 설정의 왜곡 충격파 |
| 강한 공격 명중 | 일반 명중 구성 + 짧은 방향성 카메라 킥 |
| 중요한 강타·큰 폭발 | 카메라 킥에 짧은 왜곡 충격파 추가 시험 |
| 일반 몬스터 처치 | 마지막 명중 효과 + 기존 죽음 모션 + 물리 시체 파편 |
| 엘리트·보스 처치 | 명중 효과·기존 죽음 표현·지원 바인딩의 파편. 처치 슬로우 없음 |
| 플레이어 사망 | 실제 사망 통지에 짧은 슬로우를 생명당 한 번 요청 |
| 시체 파편을 지나감 | 파편만 굴러가고 튐. 신규 명중 VFX·카메라 킥·충격파·슬로우 없음 |

큰 카메라 킥과 사망 슬로우를 매 타격마다 함께 쓰지 않는다. 현재 왜곡은 모든 수락된 명중을 대상으로 시험하되, 몬스터 처치에는 슬로모션을 사용하지 않으며 동시 명중·처치가 화면 효과를 무제한 중첩하지 않게 한다.

## 4. 명중 VFX 연결과 렌더링

### 판정과 표현의 분리

- 공격 궤적은 공격 동작에, 신규 접촉 효과는 실제 수락된 명중에 연결한다.
- 기존 수락된 명중 이벤트를 입력으로 사용하고, 필요한 접촉 위치·입사 방향·무기 표현 정보를 판정 시점에 보존한다. 이후 플레이어 위치나 변경된 장비로 추정하지 않는다.
- 명중 발생 식별자로 중복 재생을 방지한다. 프레임 사이의 여러 명중을 현재 상태 하나로 덮어쓰지 않는다.
- 효과 누락이나 재생 실패는 표현 오류로 다루며 피해·공격 실행·쿨타임을 바꾸지 않는다.
- 검과 망치에서 위치·크기·차별화를 확인한 뒤 다른 무기로 확장한다.

### 재생 수명과 소유권

현재 공통 Cue의 Sprite·Audio 경로와 프리팹 매체 확장을 구분한다. 기존 `CuePlayer`의 소유자·주입 시계·중복 방지·완료·취소·실패 경계를 재사용하며, VFX용 별도 전투 시계나 피해 실행기를 만들지 않는다.

- 풀에서 꺼낼 때 파티클·트레일·시간·색·대상 참조를 초기화한다.
- 정지·슬로우 시 매체의 시간 진행을 공통 정책과 맞춘다.
- 이미 생성된 독립 효과의 잔류 수명과 공격 취소를 구분하고, 전투 리셋·소유자 종료·씬 전환의 정리 경계를 명시한다.
- 팩에 자동 음향·카메라 제어·독자적인 시간 제어·파괴 스크립트가 있으면 프로젝트 수명과 충돌하지 않도록 분리·연결한다.

### 렌더 호환성

기준 환경은 **Unity 6000.6.5f1 / URP 17.6.0 / 현재 2D Renderer**다. 3D VFX를 사용한다는 이유만으로 프로젝트 전체를 3D Renderer로 바꾸지 않는다.

- 실제 프리팹의 셰이더·블렌딩·메시 방향·직교 카메라 표시를 확인한다.
- 명중 섬광이 공격 궤적 뒤에 묻히지 않게 정렬한다. 캐릭터·지형·HUD의 앞뒤 관계도 함께 확인한다.
- Soft Particles, 깊이·화면 색 참조, 왜곡 등은 일반 파티클 표시와 별도로 검증한다.
- 기존 필수 이미지 복원과 가림 문제를 먼저 확인한다. 패키지 임포트 성공을 게임 화면 검증으로 간주하지 않는다.

## 5. 물리 시체 파편

몬스터별 파츠 그림은 새로 제작하지 않는다. 기본 프레임의 불투명 몸체를 불규칙하게 나누는 자동 분할 방식이며, 팔·머리를 의미적으로 인식하는 방식은 아니다.

### 생성·물리

- 에디터에서 종별 분할 메시·단순 충돌 모양을 미리 생성해 캐시한다.
- 원본 텍스처를 공유하고 원본 PNG를 수정하지 않는다. 사망할 때마다 픽셀을 읽거나 새 텍스처를 만들지 않는다.
- 너무 작거나 투명한 조각은 제외하고, 생성 위치·좌우 반전·크기를 원래 몸체에 맞춘다.
- 파편에 `Rigidbody2D`와 단순 콜라이더를 사용해 지형과 충돌하며 낙하·회전·굴림 운동을 하게 한다. v1 제안은 전용 로컬 물리 공간에서 지형 프록시와만 충돌하는 방식이다.
- 기존 죽음 모션이 끝난 뒤 파편으로 전환하는 방식을 우선 시험한다. 전환 시각은 승인 모션과 겹쳐 확인한 뒤 확정한다.

### 캐릭터 상호작용·정리

- 캐릭터와 파편의 물리 충돌은 제외한다. 파편을 발판·장애물·피격 대상·공격 차폐물로 취급하지 않는다.
- 실제 발밑 이동 구간을 감지해 파편에만 이동 방향의 충격·작은 상향 충격·회전력을 전달한다.
- 가만히 서 있을 때 계속 튀지 않게 하고, 잠든 파편은 다시 지나가면 깨운다.
- 지형 충돌은 유지한다. 캐릭터와 같은 기본 레이어를 사용한다는 이유로 전역 충돌 설정을 일괄 비활성화하지 않는다.
- 풀링·개수 상한·Sleep·화면 밖 정리를 적용한다. 조각 수·유지시간·정리 조건은 시험 후 확정한다.
- 일시정지에는 멈추고, 슬로우에는 공통 물리 시간 정책을 따르며, 전투 리셋·씬 전환에는 정리한다.

## 6. 화면 반응과 시험값

카메라·왜곡의 픽셀 수치는 **960×540 내부 출력 기준 시험값**이다. 실제 적용 씬의 출력 해상도·확대 방식을 확인하고 환산한다. 표의 수치를 확정 제품 데이터나 전투 수치로 취급하지 않는다.

| 효과 | 시작 시험값 | 적용 원칙 |
|---|---|---|
| 일반 명중 카메라 킥 | 없거나 1 내부 픽셀 이내, 40~70ms | 연타에서 누적되지 않게 제한 |
| 강타 카메라 킥 | 2~3 내부 픽셀, 80~120ms | 충격 방향으로 짧게 밀렸다가 감쇠 |
| 큰 폭발·특별한 처치 카메라 킥 | 3~4 내부 픽셀, 120~180ms | 일반 명중과 구별되되 빠르게 정리 |
| 왜곡 충격파 | 표현 원본의 `waveSeconds`·`wavePixels`·`waveRadiusPixels`·`waveWidthPixels` | 지정 지속시간 동안 명중점에서 얇은 왜곡 띠가 한 번 퍼짐 |
| 플레이어 사망 슬로우 | 0.35배속, 실제 시간 150ms | 실제 사망 통지에 한 번. 몬스터 처치 제외 |

### 카메라 킥

`CameraOutputBinding`의 기존 추적 결과에 합성한다. 개별 VFX가 카메라 Transform을 직접 덮어쓰지 않는다. 첫 버전은 회전·줌 진동 없이 위치 이동만 사용한다. HUD는 고정하고 화면 가장자리 노출, 동시 요청 상한, 감소·끄기 설정을 검증한다.

### 왜곡 충격파

밝은 고리 이미지가 아니라 화면을 짧게 밀어내는 무색 파동을 기본형으로 한다. 블러·색수차는 넣지 않는다.

- 투명 캐릭터·파편까지 그려진 월드 화면을 대상으로 하고 HUD는 제외한다.
- Opaque Texture만으로 투명 Sprite까지 포함된다고 가정하지 않는다.
- 팩의 왜곡 효과가 현재 렌더러에 맞지 않으면 공용 화면 합성 셰이더·머티리얼로 구현한다. 단순 파동에는 신규 PNG가 필수는 아니다.
- 씬별 월드 출력 연결을 확인하며, 한 씬의 전용 출력 경로가 다른 씬에도 연결되었다고 간주하지 않는다.
- 중첩 강도 상한과 감소·끄기 설정을 둔다.

### 슬로모션

플레이어의 실제 사망 순간에만 발동한다. 피격량이나 몬스터 처치를 추정해서 만들지 않으며 기존 `CombatPlayer.Died` 통지를 사용한다. 죽음 모션 종료나 파편 등장까지 기다리지 않는다. 치명 낙사도 같은 사망 통지를 사용한다.

공통 제어의 소유자별 요청 합성과 단일 Unity 시간 어댑터를 사용하며 VFX 스크립트가 `Time.timeScale`을 직접 쓰지 않는다. 같은 생명의 사망 통지를 반복해 시간을 연장하지 않는다.

- 전투·투사체·파티클·물리 파편을 같은 시간 정책으로 조율하고 HUD는 실시간을 유지한다.
- 일시정지가 항상 우선한다. 연속 발동·무한 연장을 제한한다.
- 종료·실패·리셋·씬 전환 시 자기 시간 요청만 반환한다. 다른 소유자의 정지나 시간 요청을 해제하거나 무조건 1배속으로 덮어쓰지 않는다.

## 7. 구현 순서

아래 신규 타입·파일명은 구현 배치를 설명하기 위한 제안이다. 이미 존재하는 API로 간주하지 않으며 주변 코드의 명명·어셈블리 경계를 따라 확정한다. 초기부터 모든 하위 도구를 만들지 않고 각 단계의 최소 검증을 먼저 통과시킨다.

열려 있던 구현 선택 중 캡처된 factory, 세션 단위 카탈로그, 전용 잔해 물리 공간, 시계 분리는 [기술 설계](combat-hit-feedback-design.md)의 v1 우선안으로 구체화한다. 기술 검증에 따라 이 설계와 계획을 함께 갱신한다.

### 7.0. 선행 기술 검증

**작업**

1. 지정 Unity 버전과 원본 패키지 버전을 확인하고, 보유 팩을 내려받아 버전·구성·라이선스를 확인한다.
2. 원본 에셋을 보존한 채 프로젝트용 프리팹 Variant 또는 바인딩을 만든다. 처음에는 공통 명중 1개와 둔격 후보 1개만 고른다.
3. 실제 직교 카메라·2D Renderer·정렬·HDR 설정에서 표시한다. 프로모션 영상과 같게 만들려고 프로젝트 색 공간·렌더러·패키지 버전을 일괄 변경하지 않는다.
4. 각 프리팹의 ParticleSystem, 서브 이미터, 트레일, Animator, 셰이더 시간, 자동 파괴·음향·라이트·카메라 스크립트를 확인한다. 팩 전체를 동일한 방식으로 제어할 수 있다고 가정하지 않는다.
5. 같은 효과를 시작·정지·재개·풀 반환·재사용하고, 주입한 경과시간만으로 재생 가능한지 작은 fixture에서 검증한다.
6. 시간 제어와 왜곡 출력은 전체 콘텐츠 이식 전에 최소 기술 검증을 한다. 기능의 제품 적용 순서와 위험 해소 순서는 구분한다.

**완료 기준:** 프리팹 단독 표시뿐 아니라 기존 Sprite와 함께 보이며, 정지·재사용 때 잔상이나 자기 파괴가 남지 않는다. 지원하지 못한 매체·셰이더 기능은 식별하고 조정 또는 제외할 수 있다. 실제 패키지 확인 전에는 전체 구현 기간을 확정하지 않는다.

### 7.1. 실제 명중 정보 계약 보강

**현재 연결점**

- [CombatHitEvents.cs](../../../../unity/Assets/Deviant/Combat/Contracts/CombatHitEvents.cs): 명중 순번·tick·전투 시각·공격 출처·대상·전후 체력·대상 자세와 시작 `Origin.Stamp`·수신 직전 `Contact`를 보존한다.
- [CombatActor.cs](../../../../unity/Assets/Deviant/Combat/Runtime/CombatActor.cs): `Receive`/`ReceiveControl`에서 피해를 수락한 뒤 명중 사실을 기록한다.
- [CombatArena.HitEvents.cs](../../../../unity/Assets/Deviant/Combat/Runtime/Unity/CombatArena.HitEvents.cs): 기록 시 세션·액터 자격을 검사한다.
- [ActorDamageExecution.cs](../../../../unity/Assets/Deviant/Combat/Runtime/Application/ActorDamageExecution.cs): 명중 사실은 제어·로그·사망 콜백보다 먼저 게시된다. 이 순서를 유지한다.

**구현안**

- Unity 객체가 없는 작은 값 구조체로 표현용 명중 문맥을 추가한다. 내용은 유효성, 월드 접촉 앵커, 입사 방향, 위치 산출 방식, 시작에 캡처한 공격 표현 키다. `Vector2`, 프리팹, Material이나 Presenter를 Combat 계약에 넣지 않는다.
- `Receive`/`ReceiveControl`의 호출부에서 문맥을 명시적으로 전달하고, 수락된 사실에 함께 보존한다. 기존 직접 피해 호출의 미지정 문맥도 구분해 호환시킨다.
- 공격 표현 키는 행동 시작·투사체 방출 시 고정한다. 뒤늦게 맞은 수리검·독립 효과가 현재 무기의 VFX로 바뀌지 않게 한다. 반사 시 원래 방출 출처와 반사 원인도 보존한다.
- 근접은 수락한 공격 박스·스윕 구간과 대상 피격 기하를 바탕으로 시각 앵커를 계산한다. 박스 겹침에는 유일한 물리 접촉점이 없으므로, 산출 규칙을 명시하고 실제 충돌 접점과 구분한다.
- 투사체는 실제 스윕 접촉 위치·이동 벡터, 레이저는 빔 방향·대상 피격 기하, 폭발은 폭심·대상 방향을 사용한다. 이미 얻은 접촉 정보를 재사용하고 표현 계산 때문에 피해 후보·정렬·차폐 검사 순서를 바꾸지 않는다.
- 정확한 접점이 없는 직접 피해는 같은 시점의 대상 피격 기하로 명시적 대체 앵커를 만들거나 지원 범위를 진단한다. 나중의 플레이어 위치를 숨은 대체 규칙으로 쓰지 않는다.

**완료 기준:** 검·수리검·폭발·레이저에서 명중 위치와 방향을 재현한다. 무기 교체·공격 취소 후 명중, 실드 흡수·0 피해 수락, 거절·반사, 콜백 중 리셋의 기존 결과가 보존된다.

### 7.2. 공통 명중 표현 소비자

**구현 위치:** `Presentation/Runtime`의 순수 효과 선택·중첩 정책, `Integration`의 전투 사실 번역, `Game`·시험장 조립의 명시적 주입으로 나눈다. 전역 검색이나 전투 모듈의 VFX 프리팹 직접 생성을 추가하지 않는다.

- 전투당 공통 소비자가 페이지를 한 번씩 읽고, 액터별 출력 바인딩에 명중 표현을 전달한다. 각 몬스터가 전체 이벤트 페이지를 반복 순회하는 구조로 신규 VFX를 확장하지 않는다.
- 소비 시작은 현재 끝 cursor에 연결해 과거 타격을 재생하지 않는다. 세션과 `EventSequence`로 처리 진행을 관리한다.
- cursor뿐 아니라 각 사실의 액터 세션도 현재 세션과 비교한다. 기존 스트림에는 콜백 중 리셋 이전에 확정된 사실이 남을 수 있으므로 새 액터에 재해석하지 않는다.
- `DroppedBefore`는 누락으로 진단한다. 사라진 사실을 체력 감소나 `ReceivedHitCount` 차이로 다시 만들지 않는다.
- 한 명중의 섬광·접촉 효과·파편은 서로 다른 레이어로 묶고, 화면 킥·충격파는 상한 정책을 거쳐 별도 요청한다. 같은 공격의 여러 대상을 하나의 명중으로 오인하지 않는다.
- `CueOccurrence`의 현재 중복 키에는 대상·명중 순번이 없고 ordinal은 int다. 명중별 발생 ID와 레이어를 명시적으로 연결하며 long 이벤트 순번을 int에 무검사 변환하지 않는다.
- 명중별 Cue 스코프는 꼬리 효과가 끝나면 반환한다. 전투 전체 스코프에 완료 핸들을 영구 누적하지 않는다.
- 공통 숲의 `ForestEnemyPresentation`과 들판의 `Chapter1MonsterPresentation`이 사용하는 다른 피격 감지 경로를 확인한다. 기존 점멸·자세와 새 공통 명중 VFX의 소유자를 나누어 이중 생성하지 않는다.
- 기존 `Chapter1HitFeedback`의 시각 파편과 신규 팩 효과가 중복될 때 시각 경로만 조정한다. 효과음은 이번 범위에서 바꾸지 않는다.

**완료 기준:** 한 표시 프레임 사이에 같은 적이 여러 번 맞거나 한 공격이 여러 적을 맞혀도 발생별 효과가 유지된다. 소비자 비활성화·재바인딩·리셋으로 과거 명중이 재생되지 않으며 장시간 전투에서 완료 이력이 무제한 증가하지 않는다.

### 7.3. 프리팹 Cue 매체와 풀

**현재 연결점:** [CueMediaFactory.cs](../../../../unity/Assets/Deviant/Presentation/Unity/CueMediaFactory.cs)는 Sprite·Audio만 선택한다. [CuePlayback.cs](../../../../unity/Assets/Deviant/Presentation/Contracts/CuePlayback.cs)의 `ICueView.Sample(elapsed)`가 주입된 경과시간으로 출력하고 [CuePlayer.cs](../../../../unity/Assets/Deviant/Presentation/Runtime/CuePlayer.cs)가 완료·정리를 소유한다.

**구현안**

- `Definitions/Runtime/Presentation`에 프리팹 Cue의 순수 정의, `Presentation/Unity`에 `PrefabCueFactory`·뷰·풀을 추가하는 방향이다. 팩 내부 클래스명을 공통 계약으로 노출하지 않는다.
- 논리 정의에는 stable ID·버전·지속시간·루프·표현 설정을, Unity 바인딩에는 실제 프리팹·Material 참조를 둔다. v1은 새 세션·명시적 리셋에서만 효과 카탈로그를 게시하며 진행 중 효과와 독립 투사체가 참조하는 바인딩을 교체하지 않는다.
- 현재 `CueAnchor`는 X·Y·좌우 방향만 가진다. v1은 기존 서명을 유지하고 명중별 factory override에 2D 입사 각도·월드 깊이·프리팹 축 보정을 캡처한다. 자의적인 음수 scale로 모든 메시·파티클의 방향이 맞는다고 가정하지 않는다.
- ParticleSystem의 자동 진행을 멈추고, 주입된 경과시간의 증가분을 `Simulate`로 반영하는 방식을 먼저 검증한다. 같은 경과시간에는 다시 방출하지 않는다.
- 역방향 샘플·새 풀 재사용은 고정 seed와 초기 상태에서 재구성한다. 매 표시 프레임마다 0초부터 재시뮬레이션하지 않는다. 자식·서브 이미터를 중복 시뮬레이션하지 않도록 제어 루트를 구분한다.
- 셰이더 `_Time`, Animator, 독자 Update는 ParticleSystem의 수동 진행만으로 통제되지 않는다. 필요한 시간 속성을 명시 주입하거나 해당 기능을 조정한다. 지원하지 않는 매체를 정상 재생으로 숨기지 않는다.
- 생성 직후에는 숨기고 첫 Sample에서 표시한다. `Dispose`는 즉시 방출·트레일·라이트를 정리하고 중복 반환에도 안전해야 한다. 런타임 Material 복제·텍스처 생성은 반복 경로에서 피한다.
- 동시 출력·풀 용량·장식 우선 감축은 프리셋으로 조정한다. 준비 누락·매체 파괴·지원 불가를 기존 핸들의 실패로 전달하고 전투에는 전달하지 않는다.

**완료 기준:** 1배속·정지·재개·느린 시계·같은 시각 재샘플·시각 역행·재사용·출력 파괴에서 기존 Cue 수명 계약이 성립한다. Sprite·Audio 회귀도 통과해야 한다.

### 7.4. 설정 원본과 게임·시험장 연결

- 역할 매핑, 크기·색·수명, 카메라·왜곡 강도와 상한은 승인된 표현 설정 원본 한곳에서 관리한다. 공통 표현 설정은 [목표 데이터 배치](../../architecture/project-structure.md#2-저장소와-데이터-배치)에 맞춰 `data/presentation/` 아래에, 게임 시간에 영향을 주는 슬로우 설정은 `data/combat/`에 두는 설계다. 신규 파일·스키마가 이미 구현됐다고 간주하지 않는다.
- 프리팹 내부 기하·실제 Unity 참조는 제작 에셋·바인딩이 소유한다. JSON에 GUID와 수치를 중복 수작업 관리하지 않는다.
- 시작에 고정할 표현 키·정의와 조정 가능한 출력 설정의 버전 경계를 명시한다. 공격 판정 시각·피해를 표현 파일에 복제하지 않는다.
- Game·시험장 조립에서 동일한 정책과 매체를 주입한다. 검·망치의 빗나감/일반/처치 표본을 먼저 확인하고 형태별로 확장한다.
- 단독 프리팹 미리보기, 실제 명중 연결, 본 게임 통합을 각각 검증한다. 1Stage 마을 전용 씬·콘텐츠 수정과 검증은 저장소 작업 기준의 지정 브랜치·폴더를 별도로 확인한 뒤 진행하며 이 전투 워크트리에서 임의로 대신하지 않는다.

**완료 기준:** 에셋·표현 설정을 바꾸어도 피해 정의는 바뀌지 않는다. 진행 중 효과의 버전·취소·꼬리 수명과 새 명중의 매핑을 구분할 수 있다.

### 7.5. 자동 분할 잔해와 걷어차기

**에디터 산출물**

- `Presentation/Editor`의 분할 도구와 `Presentation/Unity`의 잔해 바인딩·풀을 추가하는 방향이다. 일반 피격 파티클과 바닥에 오래 남는 물리 잔해는 다른 수명으로 관리한다.
- 승인 기본 Sprite의 불투명 마스크를 고정 seed로 영역 분할하고, 경계 단순화·삼각분할·단순 충돌 모양을 만든다. 첫 버전부터 해부학적 파츠나 정밀 오목 콜라이더를 목표로 하지 않는다.
- Sprite의 rect·pivot·PPU·실제 UV와 packing 상태를 확인한다. 텍스처 전체를 한 Sprite로 가정하지 않는다. 조각의 원래 로컬 좌표를 보존하고 질량 중심 기준점으로 재배치해 회전이 부자연스럽지 않게 한다.
- 마스크·UV·기하 캐시는 원본 Sprite 식별자·내용과 분할 설정에 연결한다. 아트 교체 시 재생성 필요를 검출하며 게임 실행 때 원본 텍스처의 Read/Write를 일괄 켜지 않는다.

**런타임 연결**

- 명중의 전후 체력으로 치명 타격 후보를 식별하되, 이것만으로 최종 사망이나 죽음 모션 완료를 확정하지 않는다. 기존 피해 콜백은 부활·리셋을 일으킬 수 있다.
- 실제 죽음 표현 시작을 대상 바인딩에서 확인하고, 같은 생명·세션의 모션 완료에만 한 번 생성한다. 완료 전 리셋·부활·언로드는 대기 생성을 취소한다.
- v1은 캐릭터가 없는 전용 PhysicsScene2D에 지형 프록시와 잔해만 둔다. 기본 물리 공간의 캐릭터·지형 충돌 설정은 변경하지 않는다. 지원 지형의 geometry revision·pose·언로드를 동기화하는 어댑터가 필요하다.
- 잔해에는 `ArenaSurface`·`HurtRegion`을 붙이지 않는다. [UnityActorSurfaceQuery.cs](../../../../unity/Assets/Deviant/Combat/Runtime/Unity/UnityActorSurfaceQuery.cs)의 지형 표식 기반 질의와 투사체 질의에서 발판·피격·차폐로 해석되지 않는지 확인한다.
- 실제 이동 전후의 발밑 구간을 tick 경계에서 받아 잔해 공간 인덱스에 질의한다. 작은 swept 영역으로 대시도 놓치지 않되, 순간이동·맵 이동·리셋을 걷어차기로 취급하지 않는다.
- 한 이동 구간에서 같은 조각에 한 번만 충격을 적용한다. 정지 중에는 적용하지 않으며 속도·거리·회전 충격의 상한과 재접촉 정책은 시험한다.
- 조각별 수명 대신 풀 관리자가 활성 수·sleep·회수 조건을 관리하고 재사용 시 물리 속도·회전·충돌 제외 상태를 초기화한다.

**물리 시계 검증**

본 게임의 자동 Physics2D와 시험장의 수동 전투 tick을 구분한다. [CombatArena.Simulation.cs](../../../../unity/Assets/Deviant/Combat/Runtime/CombatArena.Simulation.cs)의 수동 Step은 전투 시뮬레이션만 진행하며 전역 Unity 물리를 함께 진행하지 않는다. v1은 성공한 전투 step의 완료 통지로 전용 잔해 PhysicsScene2D만 명시적으로 진행한다. 로컬 fixture와 실제 본 게임의 지형 프록시·출력 연결을 각각 검증하며, `Physics2D.simulationMode`를 전역으로 전환해 다른 씬까지 진행시키지 않는다. 시간 budget·생성 시각·이동 impulse의 처리 순서는 기술 설계를 따른다.

**완료 기준:** 한 종의 좌우 분할·사망 전환·낙하·재접촉을 먼저 통과한 뒤 종별로 확장한다. 캐릭터 통과·점프·공격 결과 불변, 정지 중 물리 정지, 누적 처치의 용량 제한을 검사한다. 모션 완료 기반 생성과 단순 치명 타격 기반 강조를 혼동하지 않는다.

### 7.6. 카메라 킥

- `Presentation/Runtime`에 위치 오프셋 계산·감쇠·상한을 두고 명중 소비자가 방향·강도 요청을 보낸다.
- [CameraOutputBinding.cs](../../../../unity/Assets/Deviant/Presentation/Unity/CameraOutputBinding.cs)의 구도 선택 후, 최종 Transform 쓰기 전에 합성한다. 기본 추적 상태나 fallback 위치에 킥을 누적 저장하지 않는다.
- 패럴랙스의 기존 afterApply 순서, 월드→화면 좌표 투영, 정지·출력 비활성화·해제 수명을 유지한다. 픽셀 양자화 여부는 실제 확대 출력에서 비교한다.
- 기존 카메라 요청과 새 킥은 다른 소유자의 종료로 함께 사라지지 않게 한다. 화면 가장자리 여백과 감소·끄기 설정도 시험한다.

**완료 기준:** 같은 방향의 연타·반대 방향 동시 명중에서도 지정 상한 안에 있고, 효과 종료 후 현재 추적 위치로 돌아간다. 별도 카메라 writer를 추가하지 않는다.

### 7.7. 월드 화면 왜곡

- 공통 `WorldFrameOutput`에 해당하는 출력 포트를 제안한다. 월드 카메라·원본 RenderTexture·내부 크기·표시 사각형을 명시적으로 받고 특정 마을 컴포넌트를 공통 표현 모듈에서 탐색하지 않는다.
- 불투명·투명 Sprite·파티클이 모두 그려진 뒤, HUD를 합성하기 전에 왜곡한다. 실제 타깃 2D Renderer의 RenderGraph/렌더 패스 연결 또는 기존 월드 RenderTexture 출력에 맞춘 어댑터를 선택한다.
- 동일 RenderTexture를 읽으면서 쓰지 않는다. 원본과 왜곡 결과 버퍼를 분리하고 해상도 변경·장치 손실·출력 해제 때 소유한 버퍼만 정리한다.
- 명중 월드 위치를 현재 최종 카메라의 viewport로 변환해 파동 중심을 계산한다. 레터박스·내부 해상도·확대 배율을 혼합하지 않고 화면 비율을 보정해 원형 파동이 타원이 되지 않게 한다.
- 한 번의 합성 패스에서 제한된 파동 배열을 처리하는 방향으로 과도한 전면 복사를 피한다. 화면 경계 샘플을 clamp하고 흔들림과 겹친 빈 영역을 검사한다.
- 왜곡을 껐을 때 월드 원본이 그대로 표시되는 경로와 캡처 도구의 외부 targetTexture 소유권을 보존한다. 에셋이 URP 지원이라고 해서 투명 월드 왜곡까지 자동 호환된다고 간주하지 않는다.

**완료 기준:** 캐릭터·파편·배경은 함께 왜곡되고 HUD는 변하지 않는다. 창 크기·종횡비·좌우 화면 끝·카메라 킥 동시 재생·출력 재생성·끄기에서 깨짐이 없다.

### 7.8. 공통 시간 제어 확장과 슬로우

**현재 연결점:** [ControlSession.cs](../../../../unity/Assets/Deviant/Control/Runtime/ControlSession.cs)와 [ControlRequests.cs](../../../../unity/Assets/Deviant/Control/Contracts/ControlRequests.cs)는 입력 차단·정지·소유자별 slow lease를 합성한다. [CombatControlBinding.cs](../../../../unity/Assets/Deviant/Combat/Runtime/Unity/CombatControlBinding.cs)의 단일 Unity 어댑터는 바인딩 때의 기준 배율에 현재 해석 결과를 한 번 반영한다.

- `IControlScope`·`ControlState`에 소유자별 시간 배율 요청과 해석 결과를 추가한다. 정지는 항상 우선하고, 여러 슬로우의 선택·상한·재발동 정책은 순수 제어 계층에서 정의한다.
- 시험 설계는 정지가 없을 때 가장 느린 유효 요청을 선택하고 무제한 곱셈을 피하는 방향이다. 실제 요청 합성 규칙은 명세·테스트와 함께 확정하며 개별 VFX에서 결정하지 않는다.
- Unity 어댑터의 기준 배율과 요청 배율을 구분하고, 요청 해제 시 남은 현재 요청을 다시 해석한다. 슬로우 중 정지→슬로우 만료→정지 해제 때 과거 0.35배속으로 복원되는 오류를 막는다.
- 실제 시간 120~180ms인 강조 수명의 기준과 일시정지 중 잔여 시간 처리 정책을 명시한다. 처음에는 일시정지 동안 강조 수명도 보류하는 방향으로 시험하며, UI 비스케일 시간과 무조건 동일하게 진행시키지 않는다.
- 전투는 기존 fixed step의 게임 시간 dt를 유지하고 실제 tick 진행 빈도로 느려지는지 확인한다. `Time.timeScale`과 전투 dt를 함께 줄여 이중 감속하거나 기본 공속 정의를 바꾸지 않는다.
- 파편의 Unity 물리·ParticleSystem 매체·죽음 모션·독립 투사체가 같은 진행 정책을 따르는지 확인한다. UI는 실시간을 유지한다.
- 사망 슬로우는 플레이어의 실제 사망 이벤트만 받는다. 몬스터의 `isBoss`, 체력·방 이름·이전 중요 처치 플래그로는 발동하지 않는다. 살아 있는 플레이어의 정리용 Die 호출과 중복·오래된 통지는 배제한다.

**완료 기준:** 슬로우 단독·중첩·정지 중 만료·입력 차단 중 종료·리셋·씬 전환·다른 시간 소유자 잔류를 검증한다. 수동 전투 시험과 실제 Unity 물리·입력·표시 검증을 각각 통과한다.

### 단계 의존성과 기능 작업 단위

- 패키지 호환·시간 샘플링·왜곡 출력의 최소 기술 검증을 먼저 수행한다.
- 제품 연결은 명중 문맥 → 공통 소비자·프리팹 Cue → 검·망치 → 다른 무기 순으로 한다.
- 파편은 사망 전환과 물리 소유권을 확보한 뒤, 카메라·왜곡은 명중 요청과 출력 경계를 확보한 뒤 통합한다. 슬로우 제품 발동은 공통 시간 제어와 각 매체 정지·배율 회귀가 통과한 후 연결한다.
- 명중 계약 확장, 프리팹 Cue, 실제 명중 통합, 물리 잔해, 카메라 킥, 왜곡 출력, 시간 배율 합성·슬로우를 독립적으로 검토·검증할 수 있는 기능 단위로 나눈다. 각 기능의 호출부·테스트·관련 문서·필요 생성물은 함께 다룬다.
- 시험장 적용과 본 게임 통합을 구분한다. 각 단계에서 관련 명세·설정 원본과 구현을 함께 갱신하되, 실행하지 않은 기능이나 검증을 완료로 표시하지 않는다. 게임 수치 변경이 필요하면 [데이터 파이프라인](../../data/data-pipeline.md)의 원본 편집·재생성 절차를 따른다.

## 8. 완료 판단과 검증

Unity **6000.6.5f1**과 원본 패키지 버전을 사용한다. 격리 검증 프로젝트도 같은 버전을 사용하며 다른 Editor나 패키지 버전으로 낮춰 검증하지 않는다. 자동 검사와 실제 화면·플레이 검토를 각각 수행한다.

### 자동·구조 검사

- 빗나감·거절된 타격에는 명중 VFX가 없고, 같은 명중의 중복 통지는 재생을 늘리지 않는다.
- 좌우·공중·고공속·다중 명중에서 캡처된 위치·방향·발생 정보와 수명을 유지한다.
- 효과 누락·취소·풀 반환·재사용·소유자 종료에서 다른 실행에 영향을 주거나 이전 효과가 되살아나지 않는다.
- 파편은 지형과 충돌하지만 캐릭터의 발판·장애물·피격 대상·공격 차폐물이 되지 않는다.
- 정지·재개·리셋·씬 전환 후 잔류 VFX·카메라·시간 요청이 없다. 한 요청의 종료가 다른 소유자의 요청을 해제하지 않는다.
- 슬로우 외 시각 효과의 활성 여부가 피해·판정·행동 시각·경직·넉백 결과를 바꾸지 않는다.
- 슬로우는 의도한 진행 속도만 바꾸고 기본 공속·판정·피해 정의를 변경하지 않는다.

### 실제 화면·플레이 검사

- 검과 망치의 빗나감·일반 명중·강타·처치가 즉시 구별된다.
- 효과가 적의 자세·공격 예고를 덮지 않고 기존 공격 궤적과 조화를 이룬다.
- 파편은 몸체에서 자연스럽게 분리되며, 멈춘 뒤에도 지나가면 다시 구른다.
- 실제 해상도에서 Sprite·지형·VFX의 정렬과 카메라 방향, HUD 고정·왜곡 제외가 맞다.
- 연타·다수 적·처치 누적·화면 가장자리에서 가독성·멀미·프레임 비용을 확인한다.
- 흔들림·왜곡 감소 또는 끄기 설정이 적용된다.

## 9. 구현 전·시험 중 확정할 항목

- 실제 패키지 버전·프리팹명·셰이더 의존성과 역할별 채택 효과
- 개별 효과의 크기·색·방향·수명·동시재생 한도
- 강타·중요한 폭발의 시각 강조 자격과 중복 제한. 슬로우 자격은 플레이어 사망으로 확정
- 파편 분할 수·충돌 모양·충격량·전환 시각·개수 상한·유지시간·정리 조건

위 항목은 기존 명세·콘텐츠와 실제 화면 검증을 근거로 확정하며, 에셋 선택이나 문서 작성만으로 자동 확정하지 않는다.

## 10. 구현상 난관과 위험 해소 기준

**가장 큰 통합 난관은 전투·VFX·물리 잔해·죽음 모션이 서로 다른 갱신 경로를 사용하는 상태에서 시간과 수명을 일관되게 만드는 것이다.** 프리팹을 화면에 한 번 띄우는 일보다 정지·슬로우·취소·리셋·씬 전환 뒤에도 결과와 소유권이 맞는지를 증명하는 일이 어렵다.

| 위험 | 구체적인 난점 | 해소 방법·선행 확인 |
|---|---|---|
| 최우선: 시간·수명 통합 | 전투 fixed/manual tick, Cue의 주입 시계, 로컬 물리·파티클과 몬스터별 표시 경로의 시간 경계가 다름 | 소유자별 slow/pause 합성·주입 시계·완료 step 계약을 유지하고 연속 운용·씬 전환을 검증 |
| 명중 문맥의 유실 | 원래 Stamp/Contact를 캡처하더라도 새로운 판정 경로가 문맥을 누락할 위험이 있음. 근접 박스에는 유일한 물리 접점도 없음 | 새 호출부의 수신 직전 문맥과 AnchorKind를 검사. 피해 후보·정렬·콜백 순서는 보존 |
| 투명 월드 왜곡 | URP 지원만으로 2D Renderer·투명 Sprite·HUD 제외·기존 RT 출력이 함께 해결되지 않음 | 최종 월드→왜곡→HUD의 경계를 최소 그래픽 fixture에서 확인. 색/깊이 참조나 마을 전용 출력을 공통 지원으로 오인하지 않음 |
| 잔해의 충돌·생성 시점 | 캐릭터는 Kinematic 직접 이동이고 파편은 Dynamic 물리다. 기본 레이어가 지형과 겹치며 치명 타격과 최종 사망도 항상 같지 않음 | 실제 죽음 표현 전환과 이동 구간에 연결. 액터 충돌만 제외하고 지형은 유지. 부활·리셋과 수동 물리 fixture를 별도 검증 |
| 장기 성능·가독성 | 다중 대상·고공속에 VFX·핸들·물리 조각·왜곡 패스가 누적될 수 있음 | per-hit 스코프 회수, 제한된 풀·파동 수, 장식 우선 감축과 실제 누적 처치 프로파일링 |

순수 그래픽 기능의 주요 경계는 **투명 캐릭터·파편까지 포함하면서 HUD를 제외하는 화면 왜곡**이다. 현재 바인딩은 명시 카메라의 URP 2D RenderGraph 패스를 사용하며, 다른 카메라 스택·월드 공간 UI·그래픽 설정에서도 자동 성립한다고 간주하지 않는다. 씬과 출력 경계가 추가될 때 별도 fixture와 실제 화면 검토가 필요하다.

### 피해 숫자의 강타 표시

`CombatFeelFeedback`의 적 피해 숫자는 공격별 `actions[].heavy` 지정이 있으면 해당 값을 우선한다. 검 기본 1·2타는 흰색, 망치 기본 1·2타와 검 강베기는 주황색이다. 별도 지정이 없으면 실제 HP 피해와 보호막 흡수량의 합이 **100 이상**일 때 강타 크기·주황색을 사용한다. 기준은 검 기본 피해 65에 맞춘 피해 단위를 따르며 원본은 `data/combat/presentation/hit_feedback.json`의 `heavyDamageThreshold`다. 치명타 여부와 별개의 표시이고, 플레이어가 받는 피해는 항상 빨간색이다.
