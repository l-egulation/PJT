# 기획과 구현 현황

[분야 개요](README.md)

팀원이 전체 범위와 다음 작업의 전제 조건을 확인하는 문서다. 현재 유효한 상태만 유지하고 작업 이력과 실행 결과는 Git 커밋에 남긴다. 제품 규칙은 각 분야 명세와 지정된 데이터가 기준이며, 이 표가 이를 대신하지 않는다.

## 상태를 읽는 방법

기획 확정, 코드 연결, 본 게임 통합, 실행 검증은 각각 별개다. 코드나 테스트 파일의 존재는 테스트 통과를 뜻하지 않는다. 아래 구현 범위는 저장소 문서와 소스에 근거하며, 이 표 자체는 최신 빌드의 검증 증거가 아니다. 실행 증거를 찾지 못한 항목은 검증 완료로 해석하지 않는다.

## 다음 작업의 전제 조건

1. 실행 담당자는 필요한 에셋 패키지를 확보하고 [실행 안내](../getting-started/playtest.md)의 준비 조건을 확인한다.
2. 기획 담당자는 [미정 사항과 충돌](open-questions.md)에서 해당 기능의 미결정을 확인한다.
3. 구현 담당자는 [개발 연결 안내](../development/team-guide.md)에서 원본 데이터와 연결 지점을 찾는다.
4. 기능을 넘길 때는 [협업 규칙](../workflow/contributing.md)에 따라 기대 동작·적용 범위·검증 증거·남은 제한을 구분한다.

## 현황 갱신 기준

- 새 문서를 썼다는 이유로 구현·검증 상태를 올리지 않는다.
- 시험장 적용을 본 게임 통합으로, 제작본 승인을 Unity 적용으로 표시하지 않는다.
- 전체 진행률을 임의로 합산하지 않는다. 기존 [전투 설계 체크리스트](../design/combat/checklist.md)의 비율은 그 설계 범위만 뜻한다.
- 담당자 실명과 작업 기한은 확인된 배정만 적는다. 현재 문서에서 새 배정을 만들지 않는다.
