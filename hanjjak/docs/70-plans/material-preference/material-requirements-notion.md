# 1. 기능

## 1.1 기능 개요

플레이어는 최초 로그인 직후 감자·고구마·옥수수 중 하나를 주력 재료로 선택한다. 선택한 재료는 모든 세대에서 80%, 나머지 두 재료는 각각 10%의 비율로 획득한다. 최초 선택은 변경할 수 없으며, 선택을 마치기 전에는 메인 화면과 게임 진행으로 진입할 수 없다.

재료에는 M1~M4 세대가 있다. 챕터가 오르면 상위 세대가 드롭 풀에 추가되고 이전 세대도 계속 획득할 수 있다. 서버는 재료 드롭 성공 여부, 세대와 계열을 차례로 판정하고 최종 `계열 + 세대` 아이템을 인벤토리에 지급한다.

## 1.2 기능 요약

| 기능 | 요약 |
| --- | --- |
| 최초 선택 | 최초 로그인 직후 감자·고구마·옥수수 중 하나를 선택한다. |
| 진입 차단 | 선택 완료 전에는 메인 화면, 1-1 전투와 게임 진행을 허용하지 않는다. |
| 변경 제한 | 최초 선택 후 다른 재료로 변경할 수 없다. |
| 멱등 재요청 | 같은 재료 재요청은 현재 성공 상태를 반환하고 다른 재료 요청은 거절한다. |
| 서버 저장 | 사용자별로 주력 재료 식별자 하나만 서버 권한 데이터로 저장한다. |
| 계열 비율 | 선택 재료 80%, 두 비선택 재료 각각 10%를 모든 세대에 적용한다. |
| 재료 세대 | 감자·고구마·옥수수는 각각 M1~M4 아이템을 가진다. |
| 누적 세대 풀 | 챕터가 오르면 상위 세대가 추가되고 이전 세대도 드롭 풀에 남는다. |
| 재료 드롭 | 일반 적과 보스의 콘텐츠 수치에 따라 재료 성공 여부를 독립 판정한다. |
| 보상 안정성 | 드롭 결과와 인벤토리 지급을 원자적·멱등 처리한다. |
| API | 주력 재료 조회와 최초 선택 API 두 개를 제공한다. |

## 1.3 핵심 사용자 흐름

```text
회원가입·로그인
→ 주력 재료 선택 상태 조회
→ 미선택이면 감자·고구마·옥수수와 80:10:10 안내
→ 사용자가 재료 하나 선택
→ 서버가 인증·허용값·기존 선택 상태 검증
→ 주력 재료 1회 저장
→ 메인 화면 진입
→ 자동 사냥에서 재료 추첨
→ 드롭 성공 시 현재 챕터의 가중치로 세대 선택
→ 선택 세대 안에서 주력 80%, 비주력 10%·10%로 계열 선택
→ 계열+세대 아이템 지급
```

## 1.4 플레이어 가치

- 첫 선택이 장기 재료 수급 성향을 결정한다.
- 주력 재료는 많이 얻되 비주력 재료도 직접 획득할 수 있어 완전한 진행 차단을 피한다.
- 챕터가 오를수록 상위 재료가 추가되어 성장 단계를 체감할 수 있다.
- 이전 세대도 계속 획득해 하위 재료가 필요한 성장 구간을 유지한다.
- 주력 잉여분과 비주력 부족분은 거래소 참여 동기를 만든다.

# 2. 요구사항

## 2.1 범위

### 2.1.1 포함 범위

- 최초 로그인 후 선택 상태 조회
- 감자·고구마·옥수수 최초 선택
- 선택 완료 전 게임 진행 차단
- 선택값의 서버 권한 영구 저장
- 같은 재료 재요청의 성공 수렴과 다른 재료 재선택 거절
- 재접속·앱 재실행·다른 클라이언트에서 선택값 복원
- M1~M4 재료 아이템 ID
- 챕터 1~4 누적 세대 풀
- 일반 적·보스 재료 추첨
- 챕터별 세대 가중치
- 세대 안의 80:10:10 계열 추첨
- 보상 원자성·멱등성
- 필요한 API 2개

### 2.1.2 제외 범위

- 선택 완료 후 변경권·초기화·관리자 변경
- 재료별 별도 선택 API
- 클라이언트가 확률·세대·보상 수량을 결정하는 기능
- 장기 누적 결과를 정확히 80:10:10으로 맞추는 보정이나 천장
- 거래소 등록·구매 API 상세 계약
- 선택 화면의 최종 레이아웃·일러스트·접근성 규격
- working 드롭 수치의 최종 밸런스 승격

## 2.3 선택 상태 조회

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| MAT-QUERY-001 | 인증된 사용자는 자신의 주력 재료 선택 상태를 조회할 수 있어야 한다. | 미선택 계정은 `selected=false`, 선택 계정은 `selected=true`와 저장값을 받는다. |
| MAT-QUERY-002 | 조회 응답은 감자·고구마·옥수수 식별자, 표시명과 각 선택에 적용되는 비율을 제공해야 한다. | 각 선택의 비율 합계가 100이고 선택 재료가 80이다. |
| MAT-QUERY-003 | 비율은 서버의 현재 게임 규칙에서 계산하고 사용자별 비율 필드나 클라이언트 입력을 사용하지 않아야 한다. | 비율 변경 시 사용자 행 마이그레이션 없이 새 규칙을 표시한다. |
| MAT-QUERY-004 | 선택 완료 계정은 현재 주력 재료와 적용 비율을 조회할 수 있어야 한다. | 재접속·다른 클라이언트에서도 같은 값을 받는다. |
| MAT-QUERY-005 | 비인증 요청은 계정의 선택 상태를 노출하지 않고 실패해야 한다. | 상태 변경 없이 인증 오류를 반환한다. |

## 2.4 최초 선택

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| MAT-SELECT-001 | 선택 미완료 계정은 `POTATO`, `SWEET_POTATO`, `CORN` 중 하나를 선택할 수 있어야 한다. | 세 값의 최초 선택이 각각 성공한다. |
| MAT-SELECT-002 | 선택 요청은 `materialType`만 입력받아야 한다. | 사용자 ID·확률·보상 수량 입력이 선택 결과에 영향을 주지 않는다. |
| MAT-SELECT-003 | 서버는 허용 enum을 검증해야 한다. | 알 수 없는 값·빈 값·잘못된 형식은 `INVALID_MATERIAL_TYPE`으로 실패한다. |
| MAT-SELECT-004 | 계정당 주력 재료는 최대 하나만 저장해야 한다. | 동시 요청에서도 서로 다른 두 값이 저장되지 않는다. |
| MAT-SELECT-005 | 성공 응답은 선택 완료 여부, 확정 재료와 서버 계산 비율을 반환해야 한다. | 클라이언트가 별도 확률 계산 없이 상태를 표시한다. |
| MAT-SELECT-006 | 같은 재료 재요청은 새 상태 변경 없이 현재 성공 상태를 반환해야 한다. | 응답 유실 후 재시도가 같은 결과로 수렴한다. |
| MAT-SELECT-007 | 다른 재료 재요청은 변경 없이 거절해야 한다. | 현재 선택을 유지하고 `MATERIAL_ALREADY_SELECTED`를 반환한다. |
| MAT-SELECT-008 | 서버·트랜잭션 실패는 선택값을 부분 저장하지 않아야 한다. | 실패 뒤 상태는 미선택 또는 완전히 확정된 선택 중 하나다. |
| MAT-SELECT-009 | 선택값은 재로그인·앱 재실행·다른 클라이언트에서도 유지되어야 한다. | 모든 경로에서 같은 서버 저장값을 조회한다. |

## 2.5 최초 로그인 차단

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| MAT-GATE-001 | 로그인 후 주력 재료가 없으면 선택 화면으로 이동해야 한다. | 신규 계정은 메인 화면보다 선택 화면을 먼저 본다. |
| MAT-GATE-002 | 선택 미완료 계정은 메인 화면·1-1 전투·게임 진행 명령을 실행할 수 없어야 한다. | 경로·API 직접 호출도 `MATERIAL_SELECTION_REQUIRED`로 실패한다. |
| MAT-GATE-003 | 선택 화면은 세 재료, 각 비율과 변경 불가를 선택 전에 표시해야 한다. | 사용자가 선택 효과와 영구성을 확인한다. |
| MAT-GATE-004 | 클라이언트는 요청 처리 중 추가 클릭을 막고 서버도 중복·동시 요청을 검증해야 한다. | 연속 클릭에도 하나의 선택만 확정된다. |
| MAT-GATE-005 | 선택 성공 응답을 받은 뒤에만 메인 화면으로 이동해야 한다. | 실패 응답에서는 선택 화면을 유지한다. |
| MAT-GATE-006 | 이미 선택한 계정은 최초 선택 화면을 건너뛰어야 한다. | 재로그인 시 선택 화면이 반복되지 않는다. |

## 2.6 재료 세대와 working 드롭 수치

챕터별 누적 세대 풀:

| 챕터 | 드롭 가능한 세대 |
| ---: | --- |
| 1 | M1 |
| 2 | M1, M2 |
| 3 | M1, M2, M3 |
| 4 | M1, M2, M3, M4 |

공통 working 수치:

| 항목 | 값 |
| --- | ---: |
| 일반 적 1마리당 재료 추첨 | 1회 |
| 각 추첨 성공률 | 15% |
| 성공당 지급 수량 | 10개 |
| 보스 1마리당 재료 추첨 | 5회 |
| 보스 각 추첨 성공률 | 15% |

챕터별 세대 가중치:

| 챕터 | M1 | M2 | M3 | M4 | 참고 정규화 비중 |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1 | 1 | 0 | 0 | 0 | M1 100% |
| 2 | 5 | 1 | 0 | 0 | M1 83.333%, M2 16.667% |
| 3 | 25 | 5 | 1 | 0 | M1 80.645%, M2 16.129%, M3 3.226% |
| 4 | 125 | 25 | 5 | 1 | M1 80.128%, M2 16.026%, M3 3.205%, M4 0.641% |

런타임은 반올림된 백분율이 아니라 정수 가중치를 사용한다. 이 값은 최초 구현·시뮬레이션용 working 초안이며 검증 후 조정할 수 있다.

세대 안의 계열 가중치:

| 주력 선택 | 감자 | 고구마 | 옥수수 |
| --- | ---: | ---: | ---: |
| 감자 | 80 | 10 | 10 |
| 고구마 | 10 | 80 | 10 |
| 옥수수 | 10 | 10 | 80 |

## 2.7 드롭 적용

| ID | 요구사항 | 검증 기준 |
| --- | --- | --- |
| MAT-DROP-001 | 재료 추첨 횟수, 성공률과 지급 수량은 적용 중인 콘텐츠 버전에서 읽어야 한다. | working 버전은 일반 적 1회·15%, 보스 5회·각 15%, 성공당 10개를 사용한다. |
| MAT-DROP-002 | 일반 적과 보스의 각 추첨은 독립적으로 성공 여부를 판정해야 한다. | 일반 적 20마리와 보스 1마리의 한 사이클에 25회 추첨 기회가 생긴다. |
| MAT-DROP-003 | 챕터 1~4는 각각 M1, M1~M2, M1~M3, M1~M4 누적 풀을 사용해야 한다. | 미해금 상위 세대는 나오지 않고 이전 세대는 풀에 남는다. |
| MAT-DROP-004 | 성공한 추첨의 세대는 콘텐츠 버전의 정수 가중치로 선택해야 한다. | working 버전은 `1`, `5:1`, `25:5:1`, `125:25:5:1`을 사용한다. |
| MAT-DROP-005 | 세대 선택 후 주력 80%, 두 비주력 각각 10%로 계열을 독립 추첨해야 한다. | 모든 세대에서 계열 가중치 합계가 100이다. |
| MAT-DROP-006 | 서버 저장 주력 재료와 서버 콘텐츠 규칙만 드롭 판정에 사용해야 한다. | 클라이언트 조작값이 결과에 반영되지 않는다. |
| MAT-DROP-007 | 여러 재료 보상의 성공·세대·계열은 계정 누적 결과와 무관하게 독립적으로 판정해야 한다. | 한 보상 묶음에 여러 세대·계열이 함께 나올 수 있다. |
| MAT-DROP-008 | 같은 콘텐츠 버전·전투 입력·seed는 같은 결과를 만들어야 한다. | 최종 아이템 ID와 수량을 재현할 수 있다. |
| MAT-DROP-009 | 콘텐츠 버전은 보상 결과와 함께 추적 가능해야 한다. | 수치 변경 전후 결과를 버전으로 구분하고 사용자별 확률 필드를 저장하지 않는다. |
| MAT-DROP-010 | 선택 미완료 계정에는 기본 재료나 임의 비율을 적용하지 않아야 한다. | 재료를 지급하지 않고 `MATERIAL_SELECTION_REQUIRED`를 기록한다. |
| MAT-DROP-011 | 결과 기록과 인벤토리 수량 증가는 한 멱등 처리 단위로 처리해야 한다. | 재시도·타임아웃에도 일부·중복 지급이 없다. |
| MAT-DROP-012 | 응답과 인벤토리는 같은 아이템 ID와 수량을 반영해야 한다. | 보상 응답 합계와 실제 인벤토리 증가량이 일치한다. |

## 2.8 서버 권한·데이터

사용자별 저장값:

| 필드 | 제약 |
| --- | --- |
| `primaryMaterialType` | 선택 전만 `null`, 선택 후 `POTATO`·`SWEET_POTATO`·`CORN` 중 하나, 이후 변경 불가 |

다음 불변 조건을 지켜야 한다.

- 한 계정은 미선택이거나 주력 재료 하나만 가진다.
- 사용자별 `potatoRate`, `sweetPotatoRate`, `cornRate`를 저장하지 않는다.
- 드롭률·지급 수량·세대 가중치는 콘텐츠 버전에서 관리한다.
- 클라이언트 캐시는 표시용이며 서버 상태를 덮어쓰지 않는다.
- 다른 재료의 동시 선택 요청은 정확히 하나만 최초 성공한다.

## 2.9 책임 경계

| 주체 | 책임 | 하지 않는 일 |
| --- | --- | --- |
| Frontend | 선택 상태 조회, 선택지·비율·변경 불가 표시, `materialType` 전송, 중복 클릭 방지, 서버 결과·오류 표시 | 확률·세대·보상 수량 결정, 로컬만으로 선택 확정 |
| Backend | 인증·enum 검증, 선택 유일성·불변성, 재요청 처리, 진입 차단, 드롭 판정, 원자성·멱등성 | 클라이언트 확률 신뢰, 사용자별 확률 저장, 미선택 기본값 처리 |
| Database | 계정별 선택값 0개 또는 1개 보장, 허용 enum, 동시 선택 충돌 방지, 보상·인벤토리 영속화 | 게임 확률 결정 |
| Content | 적별 추첨 횟수, 성공률, 지급 수량, 챕터별 세대 가중치와 콘텐츠 버전 | 사용자 선택 저장, 보상 지급 |
| QA | 선택·재선택·동시성·재접속·진입 차단·가중치·재현성·중복 지급 검증 | 짧은 표본 비율만으로 확률 구현 판정 |

## 2.10 오류 처리

| 코드 | 의미 | 상태 변경 | 클라이언트 처리 |
| --- | --- | --- | --- |
| `AUTHENTICATION_REQUIRED` | 인증 없음 또는 만료 | 없음 | 로그인 화면으로 이동 |
| `INVALID_MATERIAL_TYPE` | 허용되지 않은 값·빈 값·형식 오류 | 없음 | 선택 화면 유지, 입력 오류 표시 |
| `MATERIAL_SELECTION_REQUIRED` | 미선택 상태에서 게임 진행·재료 보상 요청 | 없음 | 선택 화면으로 이동 |
| `MATERIAL_ALREADY_SELECTED` | 현재 저장값과 다른 재료로 변경 요청 | 없음 | 서버 확정값 반영, 변경 불가 안내 |
| `MATERIAL_PREFERENCE_UNAVAILABLE` | 일시적 서버 오류 | 없음 또는 이미 확정된 상태 | 재조회·재시도 안내 |

## 2.11 인수 기준

1. 신규 계정은 로그인 후 주력 재료 선택 화면을 먼저 본다.
2. 감자·고구마·옥수수의 최초 선택이 각각 성공한다.
3. 선택 전에는 메인 화면·1-1 전투·게임 진행 API를 사용할 수 없다.
4. 같은 재료 재요청은 같은 성공 상태로 수렴한다.
5. 다른 재료 재요청은 현재 값을 유지하고 실패한다.
6. 동시 최초 선택 요청에서도 값 하나만 저장된다.
7. 재로그인·앱 재실행·다른 클라이언트에서 선택값이 유지된다.
8. 일반 적 20마리와 보스 1마리는 working 버전에서 총 25회 재료 추첨 기회를 만든다.
9. 챕터별 누적 세대 풀과 정수 세대 가중치가 콘텐츠 데이터와 일치한다.
10. 모든 세대에서 선택 재료 80%, 두 비선택 재료 각각 10%를 적용한다.
11. 같은 콘텐츠 버전·전투 입력·seed로 같은 아이템 ID와 수량을 재현한다.
12. 클라이언트의 확률·세대·종류·수량 조작이 결과에 영향을 주지 않는다.
13. 동일 전투 보상 재시도에서 재료가 중복 지급되지 않는다.
14. 보상 응답과 인벤토리 증가량이 일치한다.

# 3. 필요한 API

> 이 장은 주력 재료 전용 API 목록을 정의한다. 드롭 판정은 기존 전투 보상 흐름의 내부 처리이며 별도 클라이언트 API를 추가하지 않는다.

| ID | Method·Path | 기능 | 요청 | 응답 핵심 | 연결 요구사항 |
| --- | --- | --- | --- | --- | --- |
| MAT-API-001 | `GET /api/v1/material-preference` | 선택 상태·선택지·비율 조회 | 없음 | 선택 여부, 현재 재료, 세 선택지, 적용 비율 | MAT-QUERY, MAT-GATE |
| MAT-API-002 | `POST /api/v1/material-preference` | 최초 주력 재료 선택 | `materialType` | 선택 완료 여부, 확정 재료, 적용 비율 | MAT-SELECT, MAT-GATE |

선택 요청 예시:

```json
{
  "materialType": "POTATO"
}
```

성공 응답 예시:

```json
{
  "selected": true,
  "primaryMaterialType": "POTATO",
  "dropRates": {
    "POTATO": 80,
    "SWEET_POTATO": 10,
    "CORN": 10
  }
}
```

같은 재료 재요청은 현재 성공 상태를 반환한다. 다른 재료 요청은 현재 확정 `primaryMaterialType`을 포함한 실패 응답을 반환한다.

# 4. 현재 기준과 후속 검증

## 4.1 확정 기준

- 정식 재료명 감자·고구마·옥수수
- 주력 재료 최초 로그인 직후 1회 선택
- 선택 완료 전 게임 진행 차단
- 선택 후 변경 불가
- 모든 세대의 계열 비율 80:10:10
- M1~M4 아이템 ID 12개
- 챕터 1~4 누적 세대 풀
- 기능 요구사항 32개
- 필요한 API 2개

## 4.2 Working 수치

다음 값은 최초 구현·시뮬레이션 입력으로 사용하지만 최종 밸런스 검증 후 조정할 수 있다.

- 일반 적 재료 추첨 1회, 성공률 15%
- 보스 재료 추첨 5회, 각 성공률 15%
- 성공당 재료 10개
- 챕터별 세대 가중치 `1`, `5:1`, `25:5:1`, `125:25:5:1`

## 4.3 후속 검증 항목

- 장비 강화 단계별 M1~M4 소비량과 실제 공급량
- 주력 잉여분 판매와 비주력 부족분 구매 성립 여부
- P10·P50·P90 챕터 도달 시간과 장비 성장 속도
- 총 드롭률·지급 수량·세대 가중치의 `applied` 승격 또는 새 콘텐츠 버전 조정
- API DTO envelope, HTTP 상태, 인증 헤더와 공통 추적 ID
- 선택 화면의 최종 배치·문구·접근성
