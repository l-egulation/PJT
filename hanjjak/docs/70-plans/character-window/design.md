# 캐릭터 창 풀스택 설계

## 합의와 문서 책임

사용자가 합의한 화면 동작은 [UX SSOT](../../30-domain/player/ux/ssot.md)의 캐릭터 창 절이 소유한다. 이 문서는 구현 접근, 제안 API, 기존 코드와의 차이, 검증 계획을 소유한다. 2026-09-04 사용자의 구현 진행 요청으로 승인되었으며, 실제 구현·검증 상태는 [K-22](../../wiki/06-delivery/tasks/K-client-ux/k-22-character-window.md)가 소유한다.

계산은 [전투](../../30-domain/combat/ssot.md), [보석 콘텐츠](../../60-content/gems/mvp-v1.md), [스킬](../../30-domain/character/skills/ssot.md), 등록·착용은 [치장](../../30-domain/cosmetics/ssot.md), 콘텐츠는 [치장 콘텐츠](../../60-content/cosmetics/mvp-v1.md), 권한은 [계정](../../30-domain/player/ssot.md), 전송은 [Networking](../../50-architecture/networking.md)를 따른다.

## 접근 비교와 추천

| 접근 | 장점 | 한계 |
| --- | --- | --- |
| 기존 API를 화면에서 조합 | 초기 연결이 작음 | 일관된 스탯 스냅샷·출처와 미획득 카탈로그 정보가 부족함 |
| 서버 조회 모델 추가, 기존 변경 명령 재사용 — 추천 | 화면에 필요한 정보를 일관되게 제공하고 기존 자산 처리를 유지 | 공통 계산과 조회 계약 정비 필요 |
| 별도 캐릭터 서비스·저장소 신설 | 독립 배포 가능 | 기존 계정·치장 자산 중복과 동기화 비용이 발생함 |

한 기능 담당자가 UI, 계약, 조회 조합, 기존 명령 연결과 검증을 끝까지 맡는다. 기존 도메인은 자기 규칙·저장을 유지하며 다른 팀 기능을 이 화면으로 옮기지 않는다.

## 화면 구현 경계

- `apps/web/src/features/character`에 창, 탭, 능력치 툴팁, 치장 미리보기, 세트 상세를 분리한다. 작은 화면에서는 같은 정보 순서로 세로 배치한다.
- `apps/web/src/main.tsx`의 화면 교체와 별도로 창 열림 상태를 둔다. 캐릭터 창을 열고 닫아도 BattleScreen을 unmount하지 않는다. 현재 전투 화면 자체는 수동 사이클 기반이므로 이 작업의 전투 유지 검증과 전체 자동전투 완성은 구분한다.
- 창 제목과 닫기는 고정하고 본문만 스크롤한다. 탭·닫기·행 동작은 키보드로 접근 가능하게 하고 포커스를 창 안에 유지한다. 닫으면 진입 버튼으로 포커스를 돌린다. Escape로 닫고 배경 클릭으로는 닫지 않는 것을 제안한다.
- 서버 조회는 TanStack Query, 선택 탭·선택 부위·미리보기는 컴포넌트 상태가 소유한다. 닫거나 탭을 떠날 때 미적용 미리보기를 버린다.
- 치장 해금 전에도 능력치는 제공한다. 잠긴 치장·도감 탭은 조건 안내를 표시하고 전용 API를 호출하지 않는다.
- 뽑기 버튼은 기존 뽑기 화면으로 연결하고 복귀 시 캐릭터 창 치장 탭으로 돌아오는 내비게이션을 제안한다. 새로 캐릭터 버튼을 눌러 여는 경우와 구분한다.
- 시각 디자인은 중립적인 박스·간격·표로 구성한다. 실제 아트가 없으면 부위·이름과 이미지 없음 상태를 표시한다. 대체 표시를 실제 외형 미리보기 완료로 인정하지 않는다.

## 능력치 조회 제안

`GET /api/v1/character/stats`를 추가한다. 인증 계정 자신의 최신 성장 상태와 메인 보석 프리셋을 입력으로 일시 버프를 제외한 상시 계산을 수행한다. 현재 전투 중인 사이클 스냅샷과 동일하다고 표현하지 않는다.

응답은 공통 envelope 안에 콘텐츠 버전, 계산 기준, 능력치 행을 제공한다. 행에는 stat ID, 표시 단위, 합계, 기본, 추가 효과 목록, 출처 내역을 둔다. 출처는 레벨·장비 인스턴스·보석 인스턴스·스킬·세트의 안정 ID와 표시명, 원래 효과, 적용 단계, 반영 여부·상한 또는 중복 제외 사유를 제공한다.

추천 표시 행은 공격력·최대 HP·방어 관통과 상시 치명타 확률·기본공격 속도·피해 보너스·버프 지속시간 보너스다. 지속시간 증가 옵션 자체는 상시 효과로 표시하되 실제 발동 중 버프는 포함하지 않는다. 스킬 효과의 피해 적용 대상을 함께 표시한다.

퍼센트 효과를 임의의 고정 증가량으로 바꾸어 독립 기여처럼 보이지 않게 한다. 툴팁에는 실제 계산 단계의 입력·효과·출력과 최종 반올림·상한을 서버가 제공한다. 같은 단계의 여러 퍼센트 출처는 각 원래 효과를 표시하고 단계 총계만 제공한다. 적용되지 않은 낮은 중복 보석도 제외 이유를 확인할 수 있게 한다.

전투 입력 provider와 화면 조회가 같은 순수 계산 결과를 사용하게 한다. 화면 전용 공식은 만들지 않는다. 미착용 장비 처리와 반올림 위치도 전투 정본에 맞춰 회귀 검증한다.

## 치장·도감 조회와 변경

기존 `GET /api/v1/cosmetics/collection`은 소유 상태 조회로 재사용한다. 세트·미획득 구성원·효과표·이미지 참조가 필요한 화면을 위해 `GET /api/v1/cosmetics/catalog` 추가를 제안한다. 서버가 동일 콘텐츠 버전으로 제공하며 버전이 다르면 관련 조회를 함께 갱신한다.

카탈로그에는 세트 표시 정보, 구성원 참조, 치장 부위·표시 정보·이미지 참조, 성급별 누적 효과가 필요하다. 소유 응답에는 전체 세트의 서버 계산 성급과 현재 효과, 치장별 다음 단계 필요량·가용 재고·실행 가능 여부·비활성 사유가 필요하다. 미획득 치장도 표시할 수 있도록 카탈로그와 소유 상태를 연결한다. UI는 세트 성급을 계산하지 않는다.

| 동작 | 기존 API 재사용 | 처리 |
| --- | --- | --- |
| 성급 올리기 | `POST /api/v1/cosmetics/{cosmeticId}/registrations` | 기존 `UNTIL_NEXT_STAR` 명령 |
| 착용 | `PATCH /api/v1/cosmetics/equipment/{slotId}` | 선택한 cosmeticId 전송 |
| 해제 | 같은 착용 API | cosmeticId에 null 전송 |
| 뽑기 | 기존 cosmetic-gacha API | 기존 화면과 기능으로 연결 |

성급 올리기 버튼 옆에는 사용 가능한 중복 수량 / 다음 단계 필요 수량을 명시한다. 누적 등록량과 총 미등록량을 같은 분수로 혼용하지 않는다. 실제 차감·성급·세트 갱신은 서버 결과만 사용한다.

명령 생성 시 멱등 키를 한 번 만들고 응답 유실 재시도에서 재사용한다. 진행 중 중복 실행을 막고 성공 후 소유 상태·능력치 조회를 갱신한다. 실패 시 실제 착용 상태를 유지하고 안전한 오류 문구와 재시도를 제공한다. 창을 닫아도 이미 전송한 명령의 성공을 취소로 취급하지 않는다. 인증 만료 시 계정 캐시를 비운다.

## 기존 코드와의 차이

- 기존 `CosmeticsController`의 등록·착용 명령과 CosmeticsService를 재사용한다. 서버 치장 스냅샷과 TypeSpec에 구형 `collectionTier`·`collectionEffect`와 3축 고정 StatEffect가 남아 있다. 최신 SSOT의 도감 무효과·세트 효과 ID와 맞추는 계약 이행이 필요하다.
- `AccountBattleStatsProvider`는 현재 치장 효과를 고정 증가량으로 더한다. 최신 전투 정본의 퍼센트 적용과 반올림 순서에 맞추고 조회와 공유해야 한다. `AccountBattleSkillProvider`의 보석 공속과 액티브 버프 공속 표현도 상시 조회에서 섞이지 않도록 분리해야 한다.
- 현재 치장 API의 stateVersion은 0으로 고정되어 있다. 실제 버전으로 갱신하거나 관련 공통 작업과 통합하기 전에는 최신 스냅샷 정합성을 완료로 주장할 수 없다.
- TypeSpec을 편집 원본으로 하고 생성물을 직접 편집하지 않는다. 기존 호출자와의 계약 이행을 함께 검증하며, 다른 기능의 수작업 계약까지 일괄 개편하지 않는다.
- DB에는 표시 합계·미리보기·탭 상태를 저장하지 않는다. 기존 소유·등록·착용 저장을 재사용하고, 실제 스키마 차이 때문에 필요한 변경만 migration으로 다룬다.

## 검증 계획과 작업 연결

구현 시작 시 전용 캐릭터 창 task를 추가하고 A–K 색인과 UX 기능 경로에 연결한다. 기존 [K-21](../../wiki/06-delivery/tasks/K-client-ux/k-21-cosmetics-vertical-slice.md)의 관련 남은 범위도 함께 조정하며, 실행 상태와 완료 증거는 task만 소유한다.

1. 순수 계산: 장비·레벨 기본, 보석·패시브·세트 추가, 중복 보석 제외·상한·반올림, 일시 버프 제외, 전투 입력과 조회 합계 일치.
2. PostgreSQL 통합: 자기 계정 권한, 잠금 해금, 가용 재고 부족, 최대 성급, 중복 클릭·동시 등록·동일 키 재요청, 착용/해제 원자성, 서버 세트 자동 갱신.
3. 화면: 매번 기본 탭, 창 안 탭 전환, hover·focus 툴팁, 미획득·로딩·실패·이미지 없음, 미리보기와 실제 착용 분리, 접근성.
4. 브라우저: 전투 실행 중 창 열기·탭 전환·닫기에서 기존 전투가 중복 실행되거나 상태가 초기화되지 않음, 성장 이후 능력치 갱신, 성급 변경과 세트 표시, 새로고침 후 착용 복원.
5. 계약: TypeSpec 생성 검증, 기존 치장/뽑기 호출자 회귀, 공통 envelope·멱등성·오류 처리.

실제 외형 아트와 정식 전투 세션 연결이 준비되지 않으면 해당 인수 항목은 부분 상태로 남긴다. 작업 자체의 범위를 넘어 전체 자동전투·뽑기·거래소 완료를 선언하지 않는다.
