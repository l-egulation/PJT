# 2D 조명·동적 그림자·반응형 소품 기술 설계

[분야 개요](README.md)

[제품 명세](../../../design/presentation/lighting-and-reactive-props.md)의 확정 방향을 구현하기 위한 구조다. [프로젝트 구조](../../architecture/project-structure.md), [표현·시퀀스 설계](../../architecture/presentation-narrative-ui.md), [에셋 제작 계약](../../../assets/presentation/lighting-props.md)을 따른다. 아래의 현재 구현 범위와 나머지 목표 구조를 구분한다.

**조명 전체 기능의 구현은 합성 진단 에셋을 사용하는 공통 전투 실험장이다. 별도로 2챕터 S/F01의 [소수 미술 배치 시험](../../../assets/presentation/lighting-props.md#2챕터-소수-배치-시험)이 분리 랜턴·횃불과 기존 접촉 bridge를 연결한다. 본 게임의 실제 아트 전체 노말·그림자·모션·시퀀스·스트리밍 통합은 미완료다.** 이 문서는 실행 결과나 작업 이력을 기록하는 보고서가 아니다.

## 현재 구현·실행 방법

- Unity 6000.6.5f1의 `Tools > deviant > Experiments > Lighting > Open Lab`으로 `Assets/Deviant/CombatLab/Scenes/LightingLab.unity`를 열고 Play한다. 이 메뉴는 실험장을 Play 시작 씬으로 지정하므로 본 게임 작업으로 돌아갈 때 기존 `Open Common Game` 메뉴로 시작 씬을 복원한다. 제품 빌드 씬 목록은 바꾸지 않는다.
- 작은 실내의 창문 개구부, 고정 횃불, 천장 랜턴, 대표 플레이어·몬스터를 공통 `CombatArena`로 실행한다. `Opening` 버튼으로 사각형/네 개 유리 영역/다각형 아치의 투과 기하를 전환하고 `Second window`로 반대 방향 진단 광원을 추가한다. `Lantern transmission`은 원형/프레임을 제외한 다각형 진단 쿠키를 전환한다. 두 번째 광원은 합성 확인용이며 실제 벽 개구부·외부 풍경을 추가한 제품 배치가 아니다. 현재 이미지는 메모리에서 생성한 합성 진단 도형과 노말이며 최종 미술·resources 제작본을 대체하지 않는다.
- ←/→ 이동, Space 점프, A/S 기본 공격, F5 리셋과 기존 전투 입력을 사용한다. 오른쪽 진단 패널에서 실내/석양 환경광 블렌드, 일시정지, 노말/평면 A/B, 국소 광원 켜기/끄기를 확인한다. `Window angle` 슬라이더로 창문의 유입 각도를 바꾸고 `Hide lighting controls`로 패널을 숨길 수 있다. 창문을 가리지 않도록 패널은 오른쪽에 둔다. 현재 석양 버튼은 환경광 전환이지 방향성 태양·배경·안개 전체 연출이 아니다.
- `LightingCatalog`가 전체 입력을 검증·불변 캡처한다. `LightingDirector`는 우선순위·동순위 최신 요청·블렌드·소유자 핸들을, `World.ReactivePendulum`은 진자·타격 중복을 소유한다. 구현 이름 `ReactivePendulum`은 목표 전체의 `ReactivePropWorld`나 청크 상태 보관까지 제공하지 않는다.
- `ObserveEnvironmentContacts()`의 소유자 핸들이 있을 때만 실제 모터 이동과 컴파일된 근접 기본/직접 특수의 스윕 표본을 수집한다. `SimulationCompleted`에서만 소비하며 피해 수락 이벤트와 분리한다. 순간이동은 몸 스윕으로 추정하지 않는다. 표본 상한은 틱별 공격/몸 각각 2048이고 초과는 명시 경고로 노출한다. 해당 상한은 제품 성능 예산이 아니다.
- `ReactiveLanternBridge`는 공통 시계의 몸·지원 근접 공격, 고체 차폐, 단일 충격·리셋을 연결한다. 투사체·폭발·지속 공격·적 전용 공격 경로와 소품 언로드 상태 인계는 후속이다. 실험장 밖에 자동 부착하거나 기존 장식 불빛을 교체하지 않는다.
- `SpriteLightingBinding`은 원본/노말/명시적 평면 노말 프레임 대응과 기존 잉크 외곽선을 지원한다. 런타임 생성 Sprite는 `_NormalMap` secondary texture 메타데이터 검증과 함께 캐시 머티리얼의 `_SurfaceNormal`도 명시적으로 바인딩한다. A/B는 별도 평면 노말 프레임을 사용하고 종료 시 원본으로 돌아간다. 머티리얼은 바인딩 시 노말 텍스처별로 준비하며 렌더 프레임마다 생성하지 않는다. 형상별 캐스터를 준비하고 활성 캐스터만 전환한다. `CachedSpriteShadowProvider`는 공개 URP 형상 API로 최초 사용 시 내부 채움이 있는 메시를 한 번 초기화하고 이후 재사용한다. 프레임 전환·반전마다 알파 추출·메시 재생성을 하지 않는다. 이 캐시는 실제 아트 마스크의 임포트 도구나 모든 제품 프레임의 바인딩 완성을 뜻하지 않는다.
- URP 17.6에서 2D 타입은 `Unity.RenderPipelines.Universal.2D.Runtime` 어셈블리에 있다. 광원의 노말 품질·거리는 공개 런타임 setter가 없으므로 Editor의 `SerializedObject`로 템플릿에 저작하고 런타임 바인딩에서 값 일치를 검사한다. 런타임 reflection은 사용하지 않는다.
- 국소 광원의 그림자 경계는 URP 2D의 반그림자를 사용한다. `LightEmitterView`는 광원별 `shadowSoftness`·`shadowFalloff`·`lightFalloff`를 정의에서 읽어 `Light2D.shadowSoftness`·`shadowSoftnessFalloffIntensity`·`falloffIntensity`에 적용한다. 모두 유한한 0~1 값이며 softness 0은 명시적인 하드 그림자 비교용이다. 기본 실내 광원은 양수 softness를 사용한다. 전체 화면 블러·Sprite 셰이더·원본 알파·텍스처 필터·플레이어 잉크 외곽선은 바꾸지 않는다.
- `HangingConnectorView`는 천장·랜턴 상단 소켓 사이를 사슬 또는 줄로 표시한다. 화면의 `Connection: CHAIN/ROPE` 버튼으로 전환한다. 사슬은 속이 빈 정면/측면 고리를 번갈아 놓고 줄은 연속 곡선으로 그린다. `HangingConnectorCurve`가 각속도에 대한 작은 표현 지연을 계산하되 실제 본체·광원 위치는 기존 `ReactivePendulum`만 결정한다. 양끝은 항상 실제 소켓에 고정하고 메시·렌더러는 초기화 후 재사용한다. 선택적 실제 부품 바인딩은 [사슬·줄 제작 계약](../../../assets/presentation/lighting-props.md#사슬줄-연결-바인딩)을 따른다.
- `WindowLightView`는 복수의 볼록 다각형 개구부를 지정 방향으로 펼친 유한 영역의 조명·노말 입사·그림자·빛줄기를 같은 평행 방향으로 평가한다. `Light2D.Freeform`은 바깥 범위 확인용 핸들만 남기고 창문의 Native 기여와 점 기준 그림자는 끈다. 실제 표면 기여는 등록된 수신체의 전용 Sprite 셰이더가 계산한다. 빛줄기 표시를 끈 실제 수신체의 픽셀 변화와 반대편 미조명, 서로 다른 위치·깊이에서 벌어지지 않는 그림자를 구분해 검사한다. 랜턴·횃불은 Native 점광원 경로에 선택적 투과 쿠키를 연결한다.
- `Zone blending`은 기본 OFF인 구역 진단이다. 켜고 데이터가 지정한 따뜻한 구역으로 걸어가면 경계 안쪽 거리로 환경광을 혼합한다. 패널의 active/entries로 경계 왕복 중 요청이 유지되는지 확인한다. `LightingZoneTracker`는 양수 delta의 `SimulationCompleted`에서 플레이어의 실제 시뮬레이션 위치만 읽는다. 렌더 샘플링·정지 중에는 구역을 새로 선택하지 않는다. 구역 토글/소유자 비활성화는 자기 요청만 해제하고 재활성화는 다음 시뮬레이션 스텝에서 재평가한다. 실제 맵·씬의 구역 등록이나 시퀀스 실행기 연결은 아니다.

편집 원본은 `data/presentation/lighting/lab.json`의 schema 5이며 모든 수치는 실험용이다. `suspension`은 기본 외형, 곡선 분할 수, 고리 간격·너비·겹침, 줄 너비, 최대 굽힘·지연·복구 속도의 원본이다. `windowBeam`은 창문 유입 각도·거리·가장자리 감쇠·빛줄기 불투명도·끝 감쇠의 원본이다. `zones`는 구역 ID·프로필·사각 범위·우선순위·안쪽 혼합 폭·바깥 이탈 여유·전환 시간의 원본이며 구역이 없어도 빈 배열을 명시한다. 창문에 점 기준점을 배치하는 `exitOffset`은 제공하지 않는다. 진자 수치와는 별도이며 스키마가 누락된 기존 입력을 임의 기본값으로 채우지 않는다. 다음 명령은 바이트 전달과 동기화만 담당하고 의미 검증은 C# `LightingCatalog`가 소유한다.

```sh
python3 tools/lighting/export_lighting.py
python3 tools/lighting/export_lighting.py --check
```

프로필·진자·광원·구역 값 변경 후 생성 카탈로그를 갱신한다. 광원의 반그림자 폭은 `shadowSoftness`, 반그림자 내부 감쇠는 `shadowFalloff`, 광원 반경 내 밝기 감쇠는 `lightFalloff`로 편집한다. 실제 값은 JSON 한 곳이 원본이며 재시작/재바인딩 시 적용한다. 광원 노말 거리 변경이나 바인딩 누락 시 같은 Unity의 `Deviant.CombatLab.LightingLabBuilder.Build`를 호출하거나 `Open Lab` 메뉴로 Unity 템플릿·바인딩을 재생성한다. 생성된 Unity `.meta`·참조는 함께 보존한다. 임의 배포 빌드 핫리로드·전용 편집 창·시퀀스 단계는 아직 제공하지 않는다.

## 창문 면적·각도 광원의 구현 계약

- `WindowLightDefinition`은 `angleDegrees`(-180~180), 양수 `length`, 음수가 아닌 `edgeFeather`, 0~1 `beamOpacity`, 도달 거리 이내의 양수 `endFade`를 불변 캡처한다. 초기 각도는 JSON에서 읽고 슬라이더·`SetAngle`은 실행 중 미리보기다. 미리보기가 원본 파일을 저장하지 않는다.
- `WindowAperture`는 최대 8개 볼록 조각·총 64개 꼭짓점의 합집합을 불변 캡처한다. CW/CCW를 정규화하고 퇴화·중복점·오목/자가교차 윤곽·예산 초과를 거부한다. 구멍·십자 프레임은 열린 유리 조각 사이의 빈 공간으로, 곡선은 다각형 근사로 저작한다. 오목 외곽은 명시적으로 볼록 조각으로 나눈다. 런타임 알파 추출이나 자동 분해 도구는 아니다.
- `WindowLightGeometry`는 개구부 바운딩 사각형을 평행 스윕·실내 클리핑해 바깥 메시만 만든다. 실제 표면·빛줄기는 각 열린 볼록 조각까지의 평행 역추적을 추가 평가하므로 바운딩 사각형 전체가 밝아지지 않는다. `ContainsWorldPoint`도 실제 조각의 유한 스윕을 사용한다. 창문 중심의 점·원뿔이나 크기를 늘린 원으로 대체하지 않는다.
- `WindowLightView.Bind`의 개구부와 수신 구역은 모두 컴포넌트 앵커의 로컬 좌표다. 실험장은 창문과 실내가 고정된 좌표를 사용하고 수신 범위에 바닥 표면까지 포함한다. Freeform 바깥 감쇠가 수신 범위 밖으로 확장되지 않도록 코어를 감쇠 폭만큼 안쪽으로 제한한다. 이 명시적 범위는 월드 충돌을 재추첨하거나 물리 구멍을 만들지 않는다.
- 창문 도달 거리는 `windowBeam.length`가 소유하고 기존 점광원의 `radius`·거리 기반 감쇠는 사용하지 않는다. 창문 `LightEmitterView.SetNativeContribution(false)`는 Native 강도와 Native 그림자를 0/비활성으로 유지하고, 논리 밝기는 `ComputedIntensity`로 별도 제공한다. Inspector에서 창문 `Light2D.intensity`가 0인 것은 의도한 상태다. 먼 곳의 점광원으로 평행광을 흉내 내는 방식도 사용하지 않는다.
- `LitInkOutline`의 창문 표면 기여는 위치와 무관한 일정한 입사 벡터로 노말을 평가한다. XY 방향은 유입 방향의 반대이며 Z 기울기는 해당 광원 정의의 `normalDistance`를 XY 단위 방향 대비 비율로 정규화한다. 위치가 달라져도 같은 노말은 같은 창문 입사각을 받는다. 기존 Native 점광원 결과에 창문 기여만 더하고 외곽선·알파는 유지한다.
- `WindowDirectionalLighting.hlsl`은 표면과 빛줄기가 공유하는 평행 투과·차폐 평가다. 각 픽셀에서 일정한 역방향으로 열린 조각의 가장 가까운 면까지만 추적하고 열린 조각에 도달하지 않는 광선은 기여하지 않는다. 등록된 윤곽 선분과의 교차로 차폐하고, 소유자 ID로 자신의 본체 윤곽은 제외한다. 부드러운 경계는 투과·차폐에 함께 적용하는 평행 횡방향 표본으로 처리하며 한 점으로 모이는 광선이나 부채꼴 투영은 만들지 않는다.
- `SpriteShadowSource`의 사전 캡처 윤곽·현재 프레임·반전·Transform을 읽어 방향성 선분을 제공한다. point용 캐스터 메시를 바꾸거나 새 알파 윤곽을 추출하지 않는다. `SetShadowCasters`와 `AddReceiver`는 조립 루트가 명시적으로 연결한다. 등록되지 않은 물체를 자동으로 찾거나 실제 콜라이더를 그림자 원본으로 사용하지 않는다.
- `WindowLightReceiver`가 수신체별 `MaterialPropertyBlock`을 단독 합성한다. `WindowLightView.AddReceiver`/`RemoveReceiver`로 명시 연결하며 수신체당 최대 4개 창문의 방향·색·노말·개구부·차폐를 독립 평가해 더한다. 다섯 번째 등록은 기존 연결을 유지한 채 예외로 거부한다. 전역 레지스트리·전역 셰이더 상태를 사용하지 않으며 기존 블록의 다른 값은 보존한다. 광원 소등·비활성화·파괴·등록 해제는 다른 창문의 기여를 지우지 않는다. 풀 반환 시 조립 소유자가 `RemoveReceiver`를 호출하고 재등록한다. 실험장의 창틀은 렌더 전용 trim이며 구조적 벽·바닥·액터 윤곽은 차폐에 참여한다.
- 빛줄기는 같은 개구부 투과·평행 차폐·가장자리/끝 감쇠를 사용하는 별도 메시다. 액터보다 뒤에 표시하고 `SetShaftVisible(false)`로 꺼도 실제 조명은 유지한다. `beamOpacity`만 장식 강도이며 `endFade`는 표면과 빛줄기의 같은 끝 감쇠다. 유입 방향과 나란한 프레임의 2D 투영은 겹칠 수 있으며, 두 차원의 마스크를 원근 투영하거나 정확한 3D 체적 산란·창살 두께를 재현하는 기능은 아니다. 방향별 프레임 차폐가 필요하면 실제 프레임 윤곽도 캐스터로 연결한다.
- 방향성 선분은 창문당 최대 128개다. 초과 시 `ShadowEdgeOverflow`와 경고를 노출하고 해당 창문 기여를 끈다. 일부 차폐를 누락하거나 점광원으로 조용히 대체하지 않는다. 이 고정 예산은 제품 GPU 성능 승인이나 전체 콘텐츠 적용 완료를 뜻하지 않는다.
- 각도 변경 때만 볼록 영역·Freeform 경로·메시를 갱신하고 같은 각도의 반복 샘플은 재생성하지 않는다. `SetEnabled`는 조명과 빛줄기를 함께 정리하며 비활성 광원이 각도 변경으로 되살아나지 않는다. 완료·비활성화·소멸에서도 뷰 자원을 정리하고 전투 시각·피해·입력·랜턴 운동을 변경하지 않는다.

### 제작 바인딩과 점광원 마스크

- `Create > deviant > Lighting > Window Aperture Art`의 `openings[].vertices`는 앵커 기준 Unity 로컬 좌표다. `Capture()` 후 `WindowLightView.Bind(art, ...)`로 연결하거나, 기존 사각형 Bind를 사용한다. `SetAperture`는 유효한 불변 후보를 받아 실행 중 교체하고 미리보기로 원본을 저장하지 않는다. 제작 앵커의 자동 변환은 후속이다.
- `LightEmitterView`의 `transmissionMask` 또는 `SetTransmissionMask`는 URP 공개 `lightCookieSprite` API를 사용하는 선택적 점광원 투과 쿠키다. 창문의 평행 개구부와 구분하며 창문에 이 API를 호출하면 거부한다. null은 기존 원형 점광원으로 복귀한다. 소켓·부모 Transform을 그대로 사용하므로 랜턴과 함께 이동·회전하되 진자·전투를 변경하지 않는다.
- 쿠키는 아틀라스에 넣지 않은 정사각 전체 텍스처 Sprite, Clamp, mipmap 없음으로 준비한다. URP 점 쿠키는 Sprite rect가 아니라 **전체 텍스처의 RGB**를 읽으므로 흰색=투과·검정=차폐인 데이터로 저작한다. 알파만 비운 흰색 이미지는 차폐 마스크가 아니다. 잘린/패킹된 Sprite·비정사각·Repeat·mipmap 입력은 이전 유효 쿠키를 보존한 채 거부한다. 데이터 색공간은 임포트에서 관리한다.
- 이 쿠키는 광원 반경에 펼치는 2D 방출 패턴이다. 하우징 자체의 발광 마스크·외부 광원을 가리는 금속 그림자 형상과 독립 자료이며 물리적인 랜턴 프레임 투영·3D 굴절을 자동 계산하지 않는다. 실제 쿠키 원본·노말 제작과 제품 프리팹 연결은 resources 절차가 필요하다.

## 런타임 점광원의 Player 셰이더 보존

2챕터는 `Lighting/Bindings`의 광원 템플릿을 실행 중 생성한다. URP 17.6의 기본 조명 분석은 빌드 씬에 저장된 `Light2D`만 수집하므로 이 템플릿의 사용을 찾지 못한다. `RuntimeLightShaderVariants`는 SRP의 공개 `IShaderVariantStripper`·`IShaderVariantStripperScope`에 자동 등록되어 모든 일반 Player 빌드에서 `Hidden/Light2D`의 필요한 조합을 보존한다. 별도 메뉴 호출·빌드 인자·씬의 더미 광원이나 전역 stripping 설정 변경은 필요하지 않다.

보존 대상의 노말 품질·겹침 합성·볼륨 사용 여부는 실제 `LightingBindings` 템플릿에서 읽는다. 일반 점광원은 한 개 MRT 출력, 볼륨은 기본 출력을 사용하며, 실행 중 그림자 강도와 투과 쿠키를 바꿀 수 있도록 두 키워드의 ON/OFF를 포함한다. 다른 셰이더와 미사용 조합의 제거는 기존 URP 정책을 따른다. 바인딩이 누락되거나 `Hidden/Light2D`의 최종 프로그램 목록이 비면 불완전한 Player 대신 빌드 오류로 알린다. 패키지 변경 시 공개 stripper의 조합 규칙과 URP 키워드 계약을 함께 검증한다.

`Deviant.Chapter2.Tests.RuntimeLightShaderVariantsTests`는 자동 빌드 발견, 런타임 조합 보존, 미사용 조합·다른 셰이더의 기존 제거 정책을 검사한다. 실제 Player 빌드 로그에서 `Hidden/Light2D`의 보존 프로그램이 0개가 아닌지 확인하고, Player의 랜턴·횃불이 원형 감쇠와 지정 색을 출력하는지 별도로 확인한다.

## 3. 프로필 요청·합성 계약

`LightingDirector.RequestProfile(owner, profile, priority, transition, weight = 1)`은 `ProfileLease`를 반환한다. `SetWeight(0..1)`은 같은 핸들의 가중치만 바꾸며 원래 등록 순서를 유지한다. 해제는 `Dispose()`로 수행한다.

- 기본 환경 위에 낮은 우선순위부터 높은 우선순위로 요청을 혼합한다. 같은 우선순위는 최초 등록 순서로 겹치므로 가중치 1인 최신 요청이 우선한다. 부분 가중치는 아래의 현재 합성 결과와 혼합하고 0은 아래 결과를 그대로 통과시킨다. 구역의 가중치 갱신은 새 요청을 만들거나 동순위 순서를 바꾸지 않는다. 상위 전량 오버라이드에 가려진 구역이 바뀌어도 동일한 최종 목표의 시간 블렌드를 재시작하지 않는다.
- 구역의 공간 가중치와 시간 전환은 별도다. `LightingZoneTracker`는 경계 안으로 들어왔을 때 한 번 요청하고, 네 가장자리까지의 최소 안쪽 거리 `d`로 `smoothstep(clamp(d / blendWidth, 0, 1))` 가중치를 계산한다. 밖으로 잠깐 나가도 확장 사각형의 `exitHysteresis`까지는 가중치 0의 같은 핸들을 유지한다. 경계선 자체는 가중치 0이고 이탈 여유를 완전히 벗어난 경우에만 해제한다. 시각 전환은 게임플레이 구역 판정·충돌을 변경하지 않는다.
- lease 해제는 중복 호출에 안전하며 자기 요청만 제거한다. 종료 시 과거 Transform·색을 복구하지 않고 남은 현재 요청으로 전환한다.
- 프로필 전환은 지정된 시계를 사용한다. 일반 월드 전환과 소품 운동은 시뮬레이션 정지·슬로우를 따르고, 정지 중 진행해야 하는 시퀀스 표현은 명시한 표현 시계를 사용한다. 임의 `unscaledTime` 루프로 정지 정책을 우회하지 않는다.
- 시퀀스 완료·취소·실패·스킵·씬 전환에서 소유 핸들을 정리한다. 스킵의 최종 상태는 콘텐츠가 선언하고 건너뛴 깜빡임·접촉을 재생하지 않는다.
- 같은 프로필 인스턴스의 가변 상태를 여러 구역에서 공유하지 않는다. 무효 데이터의 적용은 거부하고 이전 유효 상태를 유지한다.

### 구역 데이터·수명 구현

- `LightingZoneDefinition`은 `id`, 기존 `profile` ID, `bounds: [left, bottom, right, top]`, `priority`, 양수 `blendWidth`, 음수가 아닌 `exitHysteresis`·`transitionSeconds`를 캡처한다. 범위는 유한 양수 사각형이고 혼합 폭 두 배가 너비·높이 안에 들어와 중심의 전량 가중치에 도달해야 한다. ID 중복·미등록 프로필·무효 좌표/수치는 전체 카탈로그 생성 전에 거부한다. 입력 배열을 바꿔도 이미 생성한 정의는 변하지 않는다.
- 현재 실험장 bounds는 월드 XY 좌표이며 플레이어 시뮬레이션 위치를 같은 좌표로 전달한다. 실제 맵의 로컬 구역을 연결할 때 좌표 변환은 해당 맵 조립이 소유한다. 자동 Trigger2D·장면 검색·새 게임플레이 구역 시스템은 추가하지 않는다.
- `Sample(x, y)`는 공간 요청만 갱신하고 자체 시간을 진행시키지 않는다. 루트가 완료된 시뮬레이션 스텝에서 Sample 후 `LightingDirector.Advance(delta)`를 한 번 호출한다. 정지·슬로우는 기존 delta를 따르고 `LateUpdate`나 `unscaledTime`으로 우회하지 않는다. 같은 가중치의 반복 표본은 시간 전환을 재시작하지 않는다.
- `Reset`은 해당 구역의 요청과 진단 입장 횟수를 정리하고, `Dispose`는 중복 호출에 안전하게 자기 요청만 해제한다. 실험장의 F5는 모든 구역을 먼저 정리한 뒤 기존 director를 폐기하고 새 기본 환경을 만든다. 외부 소유자는 새 director에 다시 연결해야 한다. 실험장 컴포넌트 비활성화는 자기 구역/진단 연출/일시정지만 해제하고 독립 요청은 보존한다.
- 현재 `Blend to sunset`은 고우선 환경광 요청의 진단 경로다. 구역 안팎 이동 중에도 해제 시점의 현재 구역으로 복귀하지만, 실제 시퀀스 단계의 완료·취소·실패·스킵 정책과 표현 시계 연결은 후속이다. 청크 상태 인계·제품 맵 통합도 별도 범위다.

석양의 `Global Light 2D`는 환경광이지 방향성 태양광이 아니다. 큰 형태 기반 광원과 환경색으로 먼저 검증하고, 평행 광선·긴 바닥 그림자가 필요하면 별도 셰이딩·투영 표현을 검토한다.

## 4. 노말·머티리얼 계약

본체, 근거리 지형·소품, 원경·하늘, 발광부, 필수 예고·UI의 조명 수신 정책을 분리한다. 기존 `arena.spriteMaterial` 한 개를 교체하는 방식으로 이행하지 않는다.

- 컬러와 노말의 캔버스·rect·피벗·프레임 연결을 일치시키고 secondary texture `_NormalMap`을 기본 연결 경로로 사용한다.
- 기존 모션 실행이 선택한 프레임을 그대로 읽는다. 노말·그림자용 별도 모션 타이머나 공격 시각을 만들지 않는다.
- 런타임 `Sprite.Create`·크롭·아틀라스 패킹에서도 같은 연결을 보존한다. 프레임마다 머티리얼 인스턴스를 만들지 않는다.
- `flipX`·`flipY`·회전에서 노말 방향과 투영 실루엣을 검증한다. 표시용 보간은 본체·그림자·광원 소켓에 일관되게 적용하되 게임플레이 상태에 역으로 쓰지 않는다.
- 선택적 노말 누락은 평면 노말로 대체할 수 있지만, 필수 노말·바인딩 누락은 검증 오류로 구분한다.
- 플레이어 외곽선, 피격 점멸, 색 바램, 알파를 보존한다. 외곽선·점멸·잔상은 그림자 실루엣의 입력이 아니다.

## 5. 캐릭터·몬스터 동적 그림자

지형·소품뿐 아니라 캐릭터·몬스터를 초기 지원 대상으로 둔다. 대표 각 1종의 성공을 모든 모션·개체의 적용 완료로 표시하지 않는다.

### 형상 저작·출력

1. 리소스 제작 단계에서 본체 실루엣 또는 명시적 그림자 마스크를 준비한다. 무기·스카프 포함 여부는 바인딩으로 명시하고, 본체에 구워진 공격 VFX는 별도 마스크로 제외한다.
2. 임포트 단계에서 작은 투명 잡음·불필요한 돌기를 정리한 단순 윤곽을 생성한다. 동일 형상은 공유하고 원본·파생 관계와 버전을 보존한다.
3. Unity 바인딩에 프레임 ID·형상 ID를 연결하고 런타임에는 사전 생성 형상을 선택한다. 매 렌더 프레임 알파 분석·윤곽 추출·메시 생성을 하지 않는다.
4. 본체 표시 프레임·반전·자세와 같은 결과로 그림자를 출력한다. 그림자 형상은 몸·피격 콜라이더를 대체하지 않는다.

우선 `ShadowCaster2D`를 사용하되, URP 17.6.0의 지원 API로 사전 생성 형상을 교체·재사용하는 방법과 비용을 기술 실험에서 확인한다. 비공개 필드 reflection 수정에 의존하지 않는다. 지원 경로가 요구를 충족하지 못하면 다른 어댑터·사전 구성 방식의 비용을 검토하고, 검증되지 않은 API·자기 차폐 제어가 동작한다고 단정하지 않는다.

### 자기 차폐·영향 범위

자기 표면 명암은 노말, 다른 광원의 차폐는 투영 그림자로 구분한다. 자신의 평면 실루엣 때문에 본체 전체가 검게 뭉개지지 않아야 한다. 랜턴은 외부 광원에는 차폐할 수 있지만 자기 광원을 완전히 막지 않도록 검증한다.

Sorting Layer 대상, 지형 차폐, 창 개구부, 구역 영향 범위를 함께 검증한다. 같은 Sorting Layer의 옆 공간까지 빛이 새는 문제를 레이어 설정 하나만으로 해결했다고 간주하지 않는다.

## 6. 반응형 랜턴·환경 접촉

### 감쇠 진자

고정 천장 앵커, 줄 길이, 각도·각속도, 복원력·감쇠, 최대 각도·충격 제한을 사용한다. 초기에는 줄과 본체를 한 진자로 움직이고 고리별 강체·관절은 사용하지 않는다. `Rigidbody2D`·관절 부착만으로 기존 자체 이동 모터와의 접촉이 자동 해결된다고 가정하지 않는다.

본체 접촉 영역과 그림·빛 번짐 영역을 분리한다. 광원은 불꽃·전구 소켓을 따라가며 빛줄기 방향도 같은 자세에 연결한다. 원형 광원의 회전과 위치 이동이 다른 효과라는 점을 유지한다.

### 사슬·줄 표현

`HangingConnectorDefinition`과 `HangingConnectorCurve`는 Presentation 전용 설정·상태다. `ReactiveLanternBridge`가 성공한 전투 스텝의 delta·진자 각속도를 전달하고, 리셋은 표현 굽힘도 정리한다. `HangingConnectorView.SampleNow`·`LateUpdate`는 상태를 진행시키지 않고 두 소켓의 현재 위치에서 곡선을 다시 표시한다. 외형 전환은 각도·각속도·충격 기록·피해·제어 요청을 변경하지 않는다.

고리 중심은 곡선의 표본 호 길이를 따라 배치하고 양끝 부품은 실제 소켓에서 잘 맞도록 범위를 제한한다. 정면/측면 고리와 줄 스트립은 초기화 시 한 번 준비하고, 줄 정점 버퍼만 현재 곡선에 맞춰 갱신한다. 실제 부품 스프라이트는 바인딩의 두 로컬 소켓으로 회전·균일 스케일을 해석한다. 영 길이 연결은 렌더러를 숨기고 NaN이나 물리 충격을 만들지 않는다. 모든 연결부는 콜라이더·강체·자체 월드 시계를 가지지 않는다.

현재 굽힘은 팽팽한 연결의 작은 시각적 지연 근사다. 로프의 정확한 장력·중력 처짐, 링크마다의 진동·충돌, 랜턴 본체의 독립 회전, 끊어짐·파손은 구현하지 않는다.

### 몸 접촉

- 이동 전후의 실제 몸 경로와 소품 영역을 스윕 검사한다. 시각 보간 위치로 충격을 만들지 않는다.
- 상대 속도·방향·접촉 위치를 입력으로 충격을 계산한다. 단순 겹침이나 접촉 유지가 매 프레임 충격 누적이 되지 않도록 접촉 키·재접촉 조건을 명시한다.
- 소품은 액터를 막거나 밀지 않으며 WorldSolid·Hurtbox로 위장하지 않는다. 빠른 대시 접촉도 누락하지 않게 한다.

### 공격 접촉

실제 공격 활성 구간·형상·이동 스윕과 차폐 결과를 환경 접촉 포트로 전달한다. 별도 공격 타이머·더 큰 장식 VFX 범위나 `ICombatHitEvents`의 피해 수락만으로 랜턴 적중을 추정하지 않는다.

- `세션/세대 + 실행 ID + 타격 ID + 소품 배치 ID`를 기본 중복 키로 사용하고 독립 효과에는 해당 효과 식별자를 보존한다.
- 충격 강도는 피해와 독립된 반응 프로필에서 읽는다. 전투 난수와 장식 깜빡임 난수를 분리한다.
- 환경 접촉이 피해 수락·처치·잉크 트리거·적중 보상·콤보 성공을 발생시키지 않는다.
- 초기 비차단 소품은 투사체의 종단 접촉·관통 소비·반사 대상으로 처리하지 않는다. 적·지형 후보의 기존 순서도 변경하지 않는다.
- 직접 근접, 투사체, 폭발, 지속 공격을 명시적으로 지원한다. 초기 연결은 대표 근접부터 하며 나머지 지원 여부를 구분한다. 지속 공격은 별도 반복 충격 간격을 선언한다.
- 소품 접촉 처리의 실패가 기존 피해 확정을 되돌리거나 동일 타격을 다시 실행하지 않도록 호출 경계를 분리한다.

## 7. 시간·리셋·스트리밍

소품 운동은 기존 시뮬레이션 시계·정지·슬로우를 따른다. 렌더 보간은 출력 전용이다. 정지 중 입력된 접촉이 해제 후 새로운 충격으로 재생되지 않아야 한다.

리셋은 각도·각속도·접촉 기록·광원 요청과 구독을 정리한다. 풀 재사용은 이전 소유자·세대·소켓·깜빡임 상태를 남기지 않는다. 장식 광원 컬링과 소품 상태 초기화는 별개다. 청크 언로드가 배치 재추첨이나 새 소품 상태 생성을 뜻하지 않으며, 상태 보관·재활성화 경계는 World와 명시적으로 연결한다. 세이브·로드 지원을 자동 추가하지 않는다.

## 8. 데이터·도구 경계

| 자료 | 목표 원본·소유자 |
|---|---|
| 환경·광원·소품 반응 프로필 | 제안 경로 `data/presentation/lighting/`; 순수 정의와 내용 해시로 컴파일 |
| 구역·배치 ID·앵커 | 해당 맵의 기존 배치 원본. 새 월드 원본 이행은 [구조 계약](../../architecture/project-structure.md)을 따름 |
| 조명 전환 시퀀스 | 제안 경로 `data/sequences/`; 기존 시퀀스 포트와 연결 |
| 실제 공격 시간·기하 | 기존 `data/combat/`; 조명 프로필에 복사하지 않음 |
| 컬러·노말·발광·그림자 마스크·아트 변환 도구 | `resources/`의 대상 에셋·`tools/` |
| Unity 형상 캐시·에셋 바인딩·머티리얼·프리팹·GUID | 메인의 담당 모듈과 Unity 임포터 |
| 임시 실험·캡처·로그 | 메모리 오버라이드·Git 제외 `outputs/`; 재사용 프리셋만 명시 저장 |

경로는 구현 전 제안이며 아직 생성하지 않는다. 같은 설정을 JSON과 ScriptableObject 양쪽 편집 원본으로 만들지 않는다. 프리팹 내부 기하를 JSON에 수작업 복제하지 않고, 아트 제작 앵커와 Unity 연결 바인딩의 소유권을 나눈다. 실험장에서는 임시 적용·리셋·A/B·원본 저장을 구분하고 잘못된 후보는 전체 적용을 거부한다.

## 9. 성능·검증·이행

비용은 광원 수뿐 아니라 화면 겹침 면적, 그림자 대상 수·형상 복잡도, Sorting Layer 조합, 노말 텍스처 메모리로 측정한다. 형상 재사용·광원 영향 범위·해상도 조정부터 적용하고 캐릭터 그림자를 조용히 제거하지 않는다. 대상 PC 성능 예산·품질 상한은 실측 전 미정이다.

| 단계 | 구현·제작 범위 | 완료 조건 |
|---|---|---|
| 1 | 캐릭터·몬스터 각 1종, 움직이는 광원, 사전 생성 그림자 | 모션·반전·겹침·자기 차폐와 URP 지원 경로 확인 |
| 2 | 노말·완만한 픽셀 명암·외곽선·피격 표현 | 실제 픽셀 출력에서 화풍·판독성·프레임 정합 유지 |
| 3 | 천장 랜턴, 몸·대표 근접 공격 | 광원·명암·그림자가 함께 반응하고 전투 결과 불변 |
| 4 | 기존 창문·고정 횃불·석양 프로필·시퀀스 | 개구부·빛샘·구역 전환·중첩 요청·취소·스킵 정리 |
| 5 | 적용 대상 전체 모션·투사체·폭발·지속 공격 | 누락·리셋·풀·언로드 검사와 CPU/GPU·메모리 측정 |

첫 인수 장면은 작은 실내의 창문·매달린 랜턴·플레이어·몬스터다. 본 게임과 실험장은 같은 런타임을 사용하되 실제 콘텐츠 전체 연결과 구분한다.

검증은 다음을 포함하며 아직 수행 완료 결과가 아니다.

- 순수 검사: 프로필 유효성, 요청 수명·우선순위, 진자 안정성·한계, 충격 중복 제거·세대 정리.
- 임포트 검사: 컬러/노말/마스크·프레임·피벗 정합, 그림자 형상·앵커 누락, 아틀라스·런타임 생성 연결.
- Unity 통합: 일시정지·슬로우·리셋·풀·구역 경계·시퀀스 정상/취소/스킵·언로드, 조명 유무에 따른 피해·이동·자원 결과 불변.
- 실제 화면: 이동 광원 아래 모션·반전·겹침, 완전 소등, 최대 흔들림, 자기 차폐·빛샘, 필수 예고 가독성, 장식 불빛 이중 적용 없음.
- 성능: 실제 지원 화면에서 광원·액터 겹침 부하와 텍스처 메모리 측정. [검사·빌드 기준](../../testing/testing.md)의 Unity 버전을 유지하고 로그·캡처는 `outputs/`에만 둠.
