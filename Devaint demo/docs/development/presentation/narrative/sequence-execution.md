# 시퀀스 실행과 바인딩 범위

[분야 개요](README.md)

[연출 목표](../../architecture/presentation-narrative-ui.md#4-연출-시퀀스)의 첫 구현이다. 불변 정의 → 순수 실행기 → 챕터 바인딩으로 직선·선택지 대화·카메라 위치 요청·Sprite Cue·페이드·연출 전용 뷰 이동·대기를 순차 단계와 명시적 `ParallelAll` 그룹으로 연결한다. 현재 본 게임/시험장과 고정/캡처 레이아웃의 격리 fixture에서 검사한다. 기본 게임 조립에 제품 연출을 추가하거나 [초반 이야기](../../../design/story/opening/opening.md)의 대사·행동·장소·순서를 바꾸지 않는다.

## 정의와 실행

SequenceDefinition은 안정 시퀀스/단계/바인딩 ID·필수 앵커·선택 스킵 계약을 복사한 불변 정의다. 해시는 단계/자식 순서·시간·앵커·스킵을 포함하고 기존 순차 해시를 유지한다. 빈/중복 ID·없는 단계·무효 시간·중첩 ParallelAll을 거부한다. 아래 스키마 1 원본은 같은 SequenceStep/SequenceDefinition 생성자를 의미/해시 권한으로 사용하며 제품 콘텐츠를 자동 등록하지 않는다.

| 단계 | 현재 계약 |
|---|---|
| Dialogue | 바인딩한 NPC의 직선/선택지 대화와 명시적 명령 포트를 시작하고 실제 세션 종료를 기다림. 양수 타임아웃 필수 |
| Camera | 바인딩한 챕터 앵커의 위치 요청을 지정 시간 동안 보유. 우선순위·오프셋은 바인딩이 명시 |
| Cue | 명시적 버전 카탈로그에서 캡처한 유한 Sprite/Audio Cue를 같은 CuePlayer/단계 시계로 재생하고 핸들 종료를 기다림. 양수 타임아웃 필수 |
| Fade | 명시한 색·불투명도·길이의 화면 전환을 재생하고 완료를 기다림. 양수 타임아웃 필수이며 완료 뒤 유지 여부는 페이드 정의가 지정 |
| StageMove | 물리/게임 스크립트가 없는 전용 Sprite 뷰를 두 앵커 사이로 이동. 명시적 길이/방향/깊이와 양수 타임아웃 사용 |
| Wait | 주입 시계의 단계 경과시간으로 대기. 외부 게임 상태를 변경하지 않음 |
| ParallelAll | 명시한 자식 단계를 함께 시작하고 모두 완료할 때까지 대기. 현재 중첩 없는 잎 단계 그룹만 지원 |

그룹은 정의 순서로 자식을 시작/갱신하며 진행 중인 자식에게 같은 그룹 경과시간을 전달한다. 실제 스레드를 병렬로 실행하지 않는다. 시작/결과 조회/갱신에서 처음 관측한 실패·취소·타임아웃이 그룹 결과가 되며 남은 활성 자식을 정리한다. 시작 실패 뒤의 미시작 자식은 `Pending`으로 구분한다. 일부 자식이 이미 완료했다면 그 결과를 취소나 롤백으로 바꾸지 않는다. 완료한 자식 핸들은 다른 자식을 기다리는 동안에도 먼저 반환하고 다시 갱신하거나 마감을 적용하지 않는다. 빈 그룹·중첩 그룹은 정의 생성에서 거부하며 경쟁/첫 완료 종료 정책은 제공하지 않는다.

`Sequences/Contracts`와 `Sequences/Runtime`은 Unity·Combat·Narrative·Presentation·UI 구현을 참조하지 않는다. `SequenceRunner`는 `ISequenceBindings`와 `IControlRequests`를 사용하며 한 인스턴스가 실행 한 번만 소유한다. `SequenceSnapshot`은 실행 ID·시작 정의 버전·단계 ID/인덱스·스킵 여부·결과/이유/오류를 제공한다. 현재 그룹의 `Children`은 자식 ID별 `Pending`/`Running`/`Completed`/`Cancelled`/`Failed`와 종료 이유/오류를 방어 복사한 스냅샷이다. 이전 조회 결과가 나중의 완료/취소로 바뀌지 않는다. 새 실행은 새 ID를 가지며 종료된 실행이나 다른 ID의 취소/스킵은 거부한다. `TryCancel`/`TrySkip`의 반환값은 요청 접수 여부이며, 실제 완료·스킵 성공과 정리 실패는 스냅샷 결과로 확인한다.

호출자는 입력 제한 채널과 세계 정지를 `SequenceControlPolicy`로 각각 지정한다. 실행기는 자기 제어 스코프만 반환한다. 대화·모달·다른 카메라 요청이 남아 있으면 시퀀스 종료로 해제되지 않는다. 정지 요청 자체가 주입 시계를 선택하지는 않는다. 예를 들어 정지 중 진행할 fixture는 명시적으로 비스케일/표현 시계를 연결해야 한다. `UnscaledSequenceClock`은 선택 가능한 Unity 어댑터다.

`ISequenceClock`은 유한한 0 이상의 단조 시각을 반환한다. 실행기는 처음과 매 갱신/스킵에서 검사하며 역행·예외는 실패로 종료한다. 외부 단계는 마감 시각 **이상**에서 처음 관측한 성공을 채택하지 않고 타임아웃으로 실패한다. 카메라/대기 시간은 단계 시작부터 계산한다. 이전 단계 완료를 늦게 관측했다고 새 단계의 시간까지 소급해 소비하지 않는다. 콜백의 상태 변경 재진입은 거부한다.

## 완료·취소·실패·명시적 스킵

| 결과 | 현재 의미 |
|---|---|
| Completed | 순차 단계와 각 ParallelAll 그룹의 모든 자식을 실제로 완료. 대화는 유효한 마지막 진행, Cue는 재생 완료를 관측해야 함 |
| Cancelled | 명시적 취소·소유자 종료 또는 자식 단계의 취소. 이미 확정된 변경은 자동 롤백하지 않음 |
| Failed | 누락 바인딩·단계/시계 오류·타임아웃·정리 실패. 자동 재시도·대체 연출을 실행하지 않음 |
| Skipped | 정의에 선언된 종료 요청 하나가 실제로 완료됨. 정상 완료와 구분하며 건너뛴 단계는 실행하지 않음 |

스킵 정의가 없으면 `TrySkip`은 작업을 시작하지 않는다. 스킵 정의에는 종료 서비스 키와 타임아웃이 필요하며 실행 전 서비스의 지원 여부를 검증한다. 스킵은 현재 단계/그룹의 활성 자식을 모두 정리한 뒤 `ISequenceSkipEndpoint`에 실행 ID와 종료 키를 한 번 전달한다. 현재 단계 정리가 실패하면 종료 요청도 시작하지 않는다. 중복 스킵은 거부하고 지연 종료 요청에는 같은 실행 ID를 제공한다. 실제 도메인 명령의 중복 방지·허용 상태 변경·실패 처리는 해당 서비스의 책임이다. 현재 fixture의 종료 서비스는 호출 수/완료만 검사하며 실제 이야기 사실·보상·전환 명령은 제공하지 않는다.

종료는 단계 핸들 → 바인딩 스코프 → 제어 스코프 순으로 반환한다. 하나의 정리에서 예외가 나도 나머지는 반환을 시도하고 오류를 남긴다. 정리 오류가 있으면 완료/스킵을 성공으로 보고하지 않는다. 취소된 단계의 늦은 미디어 완료나 옛 입력은 실행을 부활시키지 않는다. 반환은 중복 호출할 수 있다.

## 챕터와 기존 모듈 연결

`Integration/Unity/ChapterSequenceBindings`는 기대 챕터 세션과 명시적 대화/Cue/카메라 바인딩 목록을 복사해 보관한다. 실행 전 모든 `RequiredAnchors`, 그룹 내부를 포함한 모든 잎 단계의 NPC 배치·Cue/카메라 바인딩과 스킵 종료 서비스를 검사한다. Cue/카메라에 사용한 앵커도 정의의 필수 앵커에 선언해야 한다. 누락되면 제어권이나 뷰를 얻기 전에 실패한다. 같은 검사는 고정 제작과 캡처한 생성 결과 양쪽에 적용한다. 실제 생성 알고리즘을 추가하거나 전체 맵 검증기에 제품 시퀀스 카탈로그를 등록한 것은 아니다.

실행 스코프는 그룹 내부를 포함한 모든 사용 NPC 후보/정의 버전을 시작 시 캡처한다. 해당 단계 시작 시 `InteractionService`가 현재 대상·버전·조건·거리/전투 정책을 다시 검사한다. 기다리는 동안 NPC 바인딩이 다른 정의로 바뀌면 실패하며 새 정의를 조용히 채택하지 않는다. 시작한 대화는 기존 `DialogueSession`/`DialoguePresenter`/uGUI View와 선택적 `IDialogueCommandBindings` 경로를 사용한다. 대화의 명령 참조는 실행 전 검증하고, 단계 시작에 해당 대화 세션의 명령 범위를 얻는다. 성공/거부는 대화의 줄 전환 계약을 따르고, 명령 실패/취소는 시퀀스 실패/취소로 전달한다. 정상 대화 종료 뒤 명령 범위 반환 오류도 시퀀스의 표시/정리 실패로 전달한다. 스킵·타임아웃·언로드는 자기 명령 실행 기록만 반환하며 선택하지 않은 명령을 실행하거나 이미 확정된 효과를 되돌리지 않는다. NPC 모듈 언로드의 취소와 표시 실패도 시퀀스 결과에 전달하며 실제 제품 대화 규칙은 [NPC·대화](narrative-dialogue.md)를 따른다.

현재 챕터 바인딩은 대화 View 하나를 주입받으므로 같은 그룹 안의 동시 대화 두 개 이상을 제어/뷰 획득 전에 거부한다. 이는 어댑터의 표시 용량 제한이며 순수 실행기는 독립 핸들을 제공하는 바인딩의 여러 대화를 조합할 수 있다. 실제 동시 대화 콘텐츠나 창/포커스 정책을 선택하지 않는다.

`SequenceFadeBinding`은 불변 `FadeDefinition`과 우선순위를 연결한다. RGB/불투명도는 0~1, 시간은 초 단위이며 현재 선형 불투명도 변화만 지원한다. 색·시작/목표 불투명도·길이·`HoldAtEnd`는 호출자가 모두 명시한다. 정의와 수치는 C# 기술 fixture이며 제품 페이드 카탈로그/JSON 저작 원본은 아직 없다. 화면 페이드는 월드 앵커를 사용하지 않지만 챕터 수명과 출력 서비스의 시작 세션 ID를 확인한다. 실행 전 바인딩/출력/Canvas/Image 가용성을 검사하며 페이드를 쓰지 않는 기존 시퀀스는 출력 공급이 없어도 동작한다.

완료한 페이드의 `HoldAtEnd=true` 요청은 재생 작업이 끝난 뒤 바인딩 스코프가 보관한다. 같은 소유자의 다음 페이드는 이전 재생/유지 요청을 교체해, 나중 페이드 종료 뒤 옛 화면이 되돌아오지 않게 한다. `false`는 재생 완료 때 요청을 반환한다. 시퀀스 완료·취소·실패·스킵 종료는 자기 유지 요청도 반환하며, 스킵 종료 서비스를 기다리는 동안은 스코프가 유지된다. 현재 스코프는 화면 채널 하나이므로 한 ParallelAll 그룹의 페이드 두 개 이상을 사전 거부한다. 다른 소유자의 요청은 우선순위/최신 순번으로 선택하며 반환 뒤 남은 현재 요청/기준 프레임을 다시 적용한다. 자동 씬 전환·세계 정지·입력 차단을 페이드 부작용으로 추가하지 않는다.

`FadeOutputBinding`은 주입한 비레이캐스트 uGUI Image의 색만 쓴다. Canvas 생성·레이아웃·포커스·키 매핑은 선택하지 않는다. 출력/Canvas/Image의 비활성·유실·쓰기 오류나 재바인딩은 가용성 또는 세션 세대를 바꾸며, 이미 시작한 시퀀스는 오래된 출력을 새 화면으로 재지정하지 않고 실패/정리한다. Image 콜백 중 닫힘/파괴는 현재 쓰기 뒤 정리하고 자동 재활성화 갱신은 재진입하지 않는다. 실제 제품 화면 구성·곡선·마스크·화면 전환 정책은 후속 범위다.

Cue는 CuePlayer의 실행 ID/발생 순번과 단계 시계를 사용한다. 각 잎 단계는 자기 시각을 갱신한 뒤 자기 핸들만 Poll하며 다른 자식의 갱신이 미래 Cue를 재생하지 않는다. 늦은 준비 결과가 재생 종료 시각에 처음 도착하면 실패하고 중간 시각이면 현재 표본부터 표시한다. 유한 Sprite/Audio 정의·매체는 시작 버전을 유지하고 늦은 결과도 같은 핸들 수명을 검사한다. 카메라는 ChapterCameraSource와 기존 소유자 요청을 사용하며 종료 시 남은 현재 요청/기본 추적을 선택한다. 가려진 단계도 앵커 수명을 검사하고 실제 출력은 CameraOutputBinding 한 곳에서 적용한다. 출력 유실 취소는 시퀀스로 전달하며 재활성화한 새 세션에 옛 요청을 조용히 연결하지 않는다. 새 실행은 현재 Requests로 바인딩을 조립해야 한다.

명시 Sprite/Audio 원본 편집·저장·private audition은 [Cue 원본 저작](../visuals/combat-presentation.md#cue-원본-저작)을 따른다. 독립 Cue 저작의 loop 지원이 시퀀스의 유한 one-shot 사전 검증을 완화하거나 제품 바인딩을 자동 등록하지 않는다.

SequenceCueBinding은 안정 CueId·앵커/방향을 참조하고 ChapterSequenceBindings는 명시적 ICueCatalog를 받는다. 모든 Cue 잎의 정의/필수 매체를 제어 획득 전에 검사하고 실행 스코프가 정의·Sprite/AudioClip·카탈로그 버전과 CuePlayer 세션을 캡처한다. 대기 중 게시/같은 정의 해시의 매체 교체도 현재 실행을 재지정하지 않으며 다음 실행만 최신 카탈로그를 채택한다. CuePlayer.Reset 뒤 미래 단계도 옛 세션을 부활시키지 않는다. SequenceCueCatalog는 전체 후보 검증 뒤 원자 게시하고 기존 Sprite/Audio 팩토리의 캡처 포트를 같은 CuePlayer.OpenScope에 전달한다. AudioSource의 샘플 seek/유지/증가 시 재생·완료 권한은 기존 주입 시계 정책이며 새 DSP 시계·믹서·공간 음향 정책을 만들지 않는다. 취소/스킵/실패/마감/유실/늦은 결과는 자기 핸들/Source만 정리한다.

`SequenceStageActorBinding`은 뷰 역할 ID·시작/도착 앵커와 불변 `StageMoveDefinition`을 연결한다. 이 모드는 연출 전용 뷰이며 게임플레이 액터의 제어권·물리·피격/행동 정책을 대신하지 않는다. 길이·좌우 방향·깊이는 호출자가 명시하고 위치는 단계 시작의 같은 챕터 앵커에서 캡처한다. 현재는 선형 위치 이동과 Sprite 반전만 지원하며 새 제품 행동/대사/전환 콘텐츠는 없다.

`StageActorSession`은 뷰 하나의 독점 소유권과 시작 정의 버전·포즈를 보관한다. 완료 포즈는 다음 이동 또는 시퀀스 스코프 종료까지 유지하고, 반환은 현재 기준 포즈로 복귀한다. 같은 그룹에서 같은 뷰를 두 번 사용하거나 여러 역할 ID를 같은 출력 세션으로 중복 연결하면 사전 거부한다. 다른 실행이 이미 소유한 뷰는 빼앗지 않으며, 실행 전 검증 뒤 생긴 경합도 실제 시작에서 다시 거부한다. 서로 다른 두 뷰는 병렬로 사용할 수 있다.

`StageActorOutputBinding`은 SpriteRenderer/Transform만 있고 자식이 없는 전용 뷰를 받는다. 물리 컴포넌트·Animator/Animation·게임 스크립트가 있는 뷰/상위 계층을 거부한다. 실행 중 이 제한이 깨지면 포즈 적용뿐 아니라 기준 포즈 복구 쓰기도 중단해 새 물리 소유자의 이동을 우회하지 않는다. 가시성은 SpriteRenderer만 제어하며 월드/게임 액터의 Transform·HP·입력·시간은 변경하지 않는다. Sprite 교체는 명시적 재바인딩이 필요하고, 뷰 비활성·유실·재바인딩과 출력 세대 변경은 기존 실행을 무효화한다. 기본 게임에 액터나 아트를 자동 배치하지 않는다.

`SequenceHost`는 본 게임/시험장에 같은 실행기를 명시적으로 연결하는 수명 어댑터다. 실행 중 다른 시작은 거부하고 비활성화/파괴는 소유 실행을 취소한다. 시작·갱신·스킵 콜백 도중 닫힘 요청은 현재 호출이 끝난 뒤 정리한다. 이전 실행의 명령/해제가 새 실행을 닫지 않도록 실행별 핸들을 유지한다. 기본 게임 씬·프리팹에 자동 등록하지 않는다.

## 버전 명시 원본과 실제 미리보기

SequenceSourceDocument 스키마 1은 stable ID·requiredAnchors·순서 있는 단계와 hasSkip/종료 키·타임아웃을 명시한다. 기존 Dialogue/Cue/Camera/Wait/ParallelAll/Fade/StageMove와 중첩 없는 그룹만 지원하며 불필요한 필드·참조·시간을 거부한다. 바인딩 ID는 조립 서비스 참조이지 실행 코드/씬 이름이 아니다. Tools > deviant > Experiments > Sequence Source는 노드/종류/바인딩/시간·앵커/스킵과 그룹 순서를 편집·Undo한다. 미완성 새 항목은 임의 유효값을 채우지 않고 명시 완성 전 무효다.

SourceFiles의 1MiB/읽었던 바이트 해시/원자 교체를 사용하고 Save·저장 DTO TextAsset 내보내기·다음 실행 적용·미리보기를 구분한다. SequenceHost의 선택적 명시 SourceBinding은 실제 ISequenceBindings preflight 뒤 전체 후보만 게시하며 진행 runner는 시작 버전을 유지한다. Stage 출력이 이미 소유 중이면 같은 출력을 요구하는 후보를 거부하고 빼앗지 않는다. private 미리보기는 실제 챕터/대화/uGUI/Cue/카메라/Fade/Stage 바인딩과 전용 제어/표현 시계·RenderTexture를 사용하며 기술 미디어/영수증만 허용한다. Run·보상·서사 API를 호출하거나 제품 스킵/정지 규칙을 만들지 않는다. SpriteCueFactory의 명시 outputRoot는 private 출력 격리를 제공하고 유실한 root에서 active 씬으로 대체 생성하지 않는다.
