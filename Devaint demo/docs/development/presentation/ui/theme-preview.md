# 승인 UI 테마 독립 테스트

[UI·입력 구현](README.md)

게임 장면에 연결하기 전에 승인 프레임·팔레트 레이어·한글 폰트·키 입력을 확인하는 별도 uGUI 장면이다. 가방·제작·장비와 보상·상점·증강의 연결 흐름을 메모리 안의 테스트 목록으로 확인한다. 실제 게임 가방·제작·저장 기능과는 연결하지 않는다. HUD와 타이틀은 범위에서 제외한다.

## 실행

1. Unity 6000.6.5f1로 `unity` 프로젝트를 연다.
2. `l-egulation/deviant-work`의 `work/ui-design` 브랜치를 별도로 내려받는다. 승인 패키지는 `ui/work/theme/ink-pixel-v1/unity-handoff-v1`이며 manifest version은 3이다.
3. Unity 메뉴 `Deviant > UI Theme Preview > Configure local sources`에서 위 패키지 폴더와 로컬 메모먼트 폰트 파일을 선택한다.
4. `Open bag crafting equipment`를 누르면 가방·제작·장비를 연다. 이전 프레임·팔레트·글자 테스트는 `Open independent scene`으로 계속 열 수 있다. 기존 장면에 저장되지 않은 변경이 있다면 Unity의 저장/취소 선택을 먼저 따른다.
5. 테스트를 끝내려면 Play를 정지한다.

장면 경로는 `Assets/Deviant/UI/ThemePreview/ThemePreview.unity`다. 구성은 런타임에 생성한다. 로컬 파일 경로는 저장소 밖으로 공유하지 않는 `outputs/ui-theme-preview/config.json`에 기록한다. 폰트 파일은 복사·커밋하지 않고 메모리에서 TMP 폰트로 생성한다.

## 검증 범위

- **프레임:** 일반 창은 `ApprovedTheme.CreateFrame`의 공통 픽셀 프레임으로 원본 내부 질감과 정수 화면 화소 외곽선을 함께 표시한다. 1920 좌표계의 기준 배율은 2다. 말풍선은 가로 5열/세로 3행으로 분리해 중앙 꼬리와 양 끝 모서리의 크기를 고정한다.
- **팔레트:** 슬롯 바탕 → 잉크 칠 → 효과 문양. 동일 색·다른 색·무색·빈 칸을 한 화면에서 비교한다. 패키지의 view/rect 좌표를 그대로 적용한다.
- **글자:** 한국어, 숫자, 효과의 조건/결과 색 강조와 긴 설명 스크롤을 확인한다.
- **입력:** Q/E 탭, 방향키 선택, F 진입/확정, Esc 한 단계 복귀. 최상위 Esc는 테스트 UI만 닫으며 F로 다시 연다. W/S는 글자 탭의 설명 스크롤이다.
- **상태:** 선택 강조/확대, 비선택 감쇠, 비활성 버튼. 테스트용 임시 잉크 배치는 실제 제작/저장 데이터와 무관하다.

PNG는 Point/Clamp, mipmap 없이 읽는다. 패키지의 에셋 파일은 manifest SHA-256과 대조한다. 승인 이미지 원본은 수정하지 않는다.

## 자동 확인

Play 중 `Run keyboard and render checks`를 실행하면 Input System에 테스트 키를 입력하여 화면 전환·선택·복귀를 확인한다. 1920×1080과 960×540의 실제 Game View 캡처와 검사 결과는 `outputs/ui-theme-preview/`에 남는다. 키 입력 검증 도중에는 사용자 입력을 섞지 않는다. 테스트가 끝나면 가상 키보드를 제거한다.

이 검증은 Unity Editor의 독립 장면 기준이다. 전체 게임 회귀 테스트, 실제 게임 입력 라우터 연결, 빌드 검증을 대신하지 않는다.

## 격리와 다음 단계

기존 장면, Build Settings, Project Settings, 패키지, 저장 데이터, resources 서브모듈은 변경하지 않는다. 프리뷰 코드의 조립/입력 규칙은 게임 코드와 분리되어 있다.

정식 반영 시에는 승인 원본을 팀 resources 배포 절차로 등록하고, 게임 화면별 프리팹과 기존 입력/포커스 라우터에 연결한다. 프리뷰의 로컬 경로 로더를 제품에 그대로 포함하지 않는다. 폰트 배포 방식도 별도 확정한다.

## 가방·제작·장비 연결 테스트

동일한 승인 패키지 v3와 로컬 폰트를 사용한다. 별도 설치나 resources 변경은 없다. Play 모드라면 먼저 정지한 뒤 메뉴를 실행한다. 선택한 테스트 모드는 로컬 config에만 기록한다.

- **가방:** 스케치/잉크 4열 목록. 첫 줄에서 ↑를 누르면 분류에 초점이 이동하고 ←→로 분류를 바꾼다. F/↓로 목록에 돌아온다. 열람 전용이다. 현재 목록은 선택을 따라 8개 단위로 넘어간다.
- **제작:** 스케치 선택 F → 팔레트 선택 F → 잉크 선택 F로 임시 적용한다. 같은 잉크를 여러 칸에 적용해도 보유 잉크는 줄지 않는다. 6칸은 선택을 따라 가로로 이동한다.
- **제작 작업:** 팔레트에서 ↓를 누르면 ‘잉크 선택 / 임시 적용 해제’, 다시 ↓면 ‘제작 내용 확인’에 도착한다. ↑는 팔레트로 돌아간다. F로 검토 후 다시 F로 확정한다. 빈 칸을 남겨도 제작 가능하며 확정 후에는 변경할 수 없다.
- **제작 완료:** ←→로 장착/보관을 선택한다. 보관 또는 Esc는 제작 목록으로 돌아간다. 장착은 무기1/2 선택 → F → 장착 F다. 마우스로 장착 버튼을 누르면 바로 실행한다.
- **장비:** 자리 선택 F → 완성 무기 3열 탐색 → F 장착. 첫 줄 ↑ 또는 Esc는 자리 선택으로 돌아간다. 마지막 줄 ↓는 장착/해제 행동으로 이동한다. 다른 자리에 장착 중인 무기는 자리 교환한다.
- **상세:** W/S 및 마우스 휠로 우측 설명을 스크롤한다. 모든 잉크 설명은 같은 포맷터를 사용하고 조건은 파랑, 효과는 초록, 기본/일치 적용값은 노랑이다.
- **공통:** Q/E 탭, 방향키 선택, F 확정, Esc 이전 단계. 최상위 Esc는 테스트 화면만 닫는다. F로 다시 연다. 임시 배치는 탭을 옮겨도 유지되지만 Play 종료 시 모두 초기화된다.

### 데이터와 범위

승인 manifest의 잉크36종 ID·이름·설명·문양을 그대로 읽는다. 스케치는 시안의 레이피어/발사기/기본검 설명을 사용한 9개 테스트 항목이며 1~6칸을 포함한다. 완성 무기4개와 두 장착 자리가 초기 상태로 제공된다. 초기 장착 효과는 조합을 확인하기 위한 샘플이며 게임 지급 규칙이 아니다.

이 독립 프리뷰의 `CorePreviewState`는 장착/해제 후 공유 10초 대기와 `Simulate 10 seconds of gameplay` 검수 메뉴를 유지한다. 실제 게임의 [스케치 무기 런타임](../../gameplay/equipment/sketch-weapons-runtime.md)은 몬스터 명중 후 5초 전투 상태 잠금을 사용하며, 독립 프리뷰와 실제 규칙을 혼동하지 않는다. 현재 인벤토리 HTML의 적중/허공 공격 체험도 실제 게임의 5초 잠금을 시연하며 저장 데이터에 영향을 주지 않는다.

이번 단계는 주요 연결 흐름 검증이다. 실제 플레이 데이터·상태 저장은 포함하지 않는다. 보상에서 가방을 열었다 복귀하는 경로는 아래 나머지 Figma 화면 테스트에서 확인한다. 기존 HTML 명세의 해당 기능은 삭제하거나 변경한 것이 아니다. 실제 게임에 연결하기 전에 별도로 옮긴다.

### 재검증

Play 중 `Run bag crafting equipment checks`를 실행한다. 실제 Input System 키 입력으로 36번째 잉크, 6번째 칸, 임시 해제, 초안 유지, 확정/보관, 교환/대기, W/S, Esc를 확인한다. 1920×1080과 960×540 캡처를 남기고 텍스트 영역의 넘침을 검사한다. `core-checks.json`은 시작 시 지우므로 이전 성공 결과가 실패를 가리지 않는다. 모델 검사에는 반복 잉크, 빈 잉크, 빈 제작, 중복 확정 방지도 포함한다.

검사 결과와 캡처는 `outputs/ui-theme-preview/`에만 저장하며 팀 저장소에 커밋하지 않는다. Windows Editor에서는 같은 메뉴로 확인할 수 있으나 이 변경의 실행 검증은 macOS Editor 기준이다.

### 시안과의 시각 대응

선택 붓칠은 클릭 영역 너비와 분리하여 실제 글자 너비에 좌우 14px 여백으로 맞춘다. 여러 줄 슬롯 이름은 줄바꿈된 텍스트 높이에 맞춘다. 승인 HTML과 같이 붓칠 불투명도는 48%다. 스케치 상세는 기본 공격 → 스킬 → 팔레트, 잉크가 적용된 무기는 팔레트 → 적용 효과 → 기본 공격 → 스킬 순서다.

배경은 UI design 체크아웃의 `ui/work/theme/ink-pixel-v1/screen-set-v6/assets/village.jpg`를 읽는다. 패키지 폴더만 따로 복사하지 말고 UI 저장소 구조를 유지한다. 기존 게임 장면의 배경을 수정하지 않는다. HTML의 흑연색 `#24272b` 96%→95% 합성을 sRGB에서 먼저 계산하여 Unity 선형 색공간에서도 배경이 과하게 밝아지지 않게 한다.

상단은 x130의 Q 키캡, 가방/제작/장비 탭, x642의 E 키캡이며 우측에는 일시정지를 표시한다. 하단 구분선은 y983, 키 안내는 y1004를 기준으로 한다. F는 선택 중이고 활성인 행동에만 테두리 키캡으로 표시한다. 붓칠은 키캡과 글자를 포함한 폭에 맞추며 버튼 클릭 영역 전체로 늘리지 않는다.

1920×1080 기준 가방/장비는 좌측680px, 중앙140px, 우측840px이며 제작은 좌측860px, 중앙140px, 우측660px다. 가방 목록은 하단 안내를 침범하지 않는 2행을 표시하고 선택에 따라 이동한다. 제작 슬롯은 바탕·칠·문양을 그대로 겹치며 5칸 표시 창에서 6번째 칸으로 이동할 수 있다. 상세의 구분선과 제목/본문 여백은 승인 시안의 구조를 따른다.

비교 시 테스트 목록의 개수·내구도·효과 조합은 HTML의 샘플 목록과 다를 수 있다. 폰트는 동일 파일을 사용하지만 브라우저와 TMP의 글리프 렌더링은 픽셀 단위로 일치하지 않는다. 위에서 제외한 외부 연결 기능은 여전히 별도 범위다. 조작 검증 통과를 최종 시각 승인으로 취급하지 않는다.

Crafting uses three columns and shows applied effects during review. Completion keeps weapon details on the left and destination actions on the right. Equipment target names and durability groups are centered within each column. Review captures include every crafting stage, not only initial screens.

## Figma 기준 독립 화면

현행 디자인 기준은 [Figma UI 시안](https://www.figma.com/design/mcPMyUIW47K4QmJfcdHAoC)이다. 가방 `14:39340`, 제작 `14:40861`, 장비 이름 변경 `14:46033`의 1920×1080 배치와 공통 키캡을 따른다. 화면 이미지를 통째로 붙이지 않고 기존 uGUI 텍스트·이미지·입력란으로 구성한다.

- 공통 키 안내는 x130/y1004, 높이41.195px이며 키 텍스트는 여백 없이 중앙 정렬한다. 프레임·팔레트 테스트와 핵심 화면이 동일한 안내를 사용한다.
- 탭과 슬롯 붓칠은 실제 글자 폭에 좌우14px를 더한다. 클릭 영역은 별도로 유지한다.
- 장비 목록은 3열의 고정 이미지·이름·내구도 행을 사용한다. 선택을 따라 다음 3개로 넘어가므로 하단 행동 영역을 침범하지 않는다.
- 무기 이름 변경은 장비 목록에서 ↓로 행동 영역에 진입한 뒤 다시 ↓, F로 연다. 상세의 ‘이름 변경’을 클릭해도 된다. Enter는 저장, Esc는 취소하고 직전 선택 단계로 돌아온다. 입력 중 Q/E/F는 메뉴 단축키로 처리하지 않는다.
- 이름은 공백만으로 저장할 수 없고 최대20자다. 이름 변경은 메모리의 해당 무기 ID에만 적용하며 실제 저장 데이터와 연결하지 않는다.
- 이름 변경 프레임은 448×362.2px로 중앙 배치하며 일반 창과 같은 공통 픽셀 프레임을 사용한다. 원본의 흐린 외곽선과 바깥 흔적 대신 직각 모서리와 정수 화면 화소 테두리를 그린다.
- 화면 안의 ‘팀 데이터 기준 · 조작 검토용’ 문구는 표시하지 않는다. 테스트 도구 안내는 이 문서와 Editor 메뉴에서 제공한다.

## 나머지 Figma 화면 테스트

`Deviant > UI Theme Preview > Open remaining Figma screens`로 연다. 기존 핵심 화면과 같은 독립 장면이며 기존 게임 장면을 저장하거나 변경하지 않는다.

- 선택 메뉴에서 Q/E로 카테고리, ↑↓로 화면, ←→로 10개 단위, F로 진입한다.
- 보상·상점·증강29, 설정·일시정지·결과18, 마을34, 월드38의 **119개 승인 상태**를 각각 열 수 있다. HUD2개와 타이틀은 제외한다.
- 화면 안에서 방향키는 가까운 선택 대상, F는 선택/실행, Esc는 이전 화면과 선택 단계로 복귀한다. 긴 설명은 W/S로 스크롤한다.
- 보상 선택 → 획득 확인, 가방 확인 → 보상 복귀, 증강 결제 → 선택 대기 → 동일 후보 재진입, 보유 증강 스크롤을 연결한다.
- 상점 구매는 프리뷰 골드에서 화면의 가격을 차감하고 해당 자리의 품절을 유지한다. 골드 부족·품절·구매 불가 시안에서는 구매하지 않는다. 실제 재화/저장 데이터는 읽거나 쓰지 않는다.
- 설정은 분류 선택 F → 항목 ↑↓ → 값 ←→ → Esc 분류 복귀다. F/G 확인창은 화살표로 버튼을 선택하지 않는다. 실제 시스템 해상도·오디오·게임 키 설정은 변경하지 않는다.
- 로딩 중 일반 입력을 막는다. 실패 확인 F는 재시도, G는 타이틀 대신 화면 선택 메뉴로 인계한다. 보류 중인 타이틀을 새로 만들지 않는다.
- 봉인·구출·함정의 진행 트리거는 `Simulate world progress` 또는 F로 주입한다. 생존전 시간은 독립 화면에서 흐른다. 실제 적 생성·피해·물리 상호작용은 없다. 이벤트 완료는 혼합 보상으로, 봉인은 증강으로 연결한다.
- 보스 소개와 무기 소진 알림은 시간이 지나면 사라진다. 포탈은 C/V로 설치 상태를 확인한다. 지도는 방향키 이동, +/- 확대·축소, C/Home 기본 위치, M/Esc 닫기다.
- 오프닝 대화·안내 상태를 순서대로 연결한다. 테스트 안내 기록은 `Deviant.ThemePreview.Tutorial`이라는 별도 키를 사용하며 실제 게임 저장과 분리한다.

### 레이어와 원본 대응

`Assets/Deviant/UI/ThemePreview/Layout/figma-layouts.json`은 Figma 노드 ID·부모 관계·좌표·크기·글자·행간·색상·마스크·지도 벡터와 45개 원본 이미지 참조를 보관한다. 화면 전체 PNG를 사용하지 않는다. Unity JSON 중첩 제한을 피하려고 레이어를 평면 목록으로 저장하고 런타임에 부모 관계를 복원한다.

원본 파일은 지정된 `unity-handoff-v1`의 상위 UI 폴더에서 상대 경로로 읽고 SHA-256으로 대조한다. UI design 저장소 전체 구조가 필요하다. 에셋/폰트 바이트를 팀 저장소에 추가하지 않는다. 잉크 아트처럼 불투명도를 함께 적용하는 이미지 묶음은 원본 레이어를 메모리에서 합성한다. 프레임 모서리와 키 안내·텍스트는 별도 요소다.

### 확인 방법과 적용 한계

Play 중 `Run remaining Figma checks`를 실행하면 119개 상태를 두 해상도로 캡처하고 입력·상태 연결을 검사한다. `extended-checks.json`, `native-text-overflow.txt`, `figma-<상태>-1920.png`와 `-960.png`는 `outputs/ui-theme-preview`에만 생성된다. 글리프 안티앨리어싱과 블러는 Figma와 Unity 렌더러 차이가 있으므로 수치 대응과 실제 캡처를 함께 확인한다.

이 화면들은 승인 시안의 상태와 조작을 확인하는 독립 프리뷰다. 후보는 검수 시안의 고정 예시이며 게임의 추첨·진행·경제·전투 시스템 구현을 대신하지 않는다. 설정 변경은 프리뷰 표시만 바꾼다. 이벤트의 실제 전투 완료, 재접속 저장, 보상/상품의 실제 가방 지급은 본 게임 연결 단계에서 별도로 검증한다. HUD·타이틀은 계속 보류한다.

### 선택 상태와 프레임 경계

후보 선택은 분류명(스케치/잉크)이 아닌 실제 이름을 강조한다. 보상·증강 카드의 아트는 기준 크기의 113%/90%(선택/비선택)를 사용하며 중심과 이름 행은 고정한다. 비선택 아트는 알파60%, 채도55%로 표시하고 선택 시 원본 색과 알파100%로 복원한다. 상점·가방·제작·장비는 각 화면의 기존 이미지 영역을 유지하면서 같은 활성/비활성 대비를 적용한다. 월드 진열은 이름 대신 아트 확대와 인접 설명 팝업으로 식별한다. 선택 이동과 이전 선택 복귀에서도 상태를 다시 계산한다.

말풍선 프레임은 승인된 분할 좌표로 원본 조각들을 메모리에서 합성하여 표시한다. 분할 조각마다 RectMask2D를 적용할 때 생기던 내부 경계선을 제거하며, 꼬리·모서리는 기존 비율을 유지한다. 화면 전체를 이미지화하는 처리가 아니며 텍스트·버튼·키캡은 별도 uGUI 요소다.

검사에는 보상 후보를 두 번째/세 번째로 이동한 캡처와 명칭 강조·아트 확대·활성 불투명도 확인을 포함한다. Figma 선택 상태 수정은 같은 파일의 기존 프레임에 반영되어 있다.

전체 대조에서 확인한 선형 색공간 차이를 보정하기 위해 로딩·최종 결과·오프닝의 전면 어둠 레이어는 배경 이미지와 sRGB로 합성한다. 960×540에서 키캡 선이 사라지지 않도록 최소 화면1px을 유지한다. 이름 변경 등 공통 프레임의 외곽선은 화면 화소 격자에 맞춰 별도로 그리며, 원본 내부 질감과 픽셀 아이콘의 Point 필터는 유지한다.


## 보상·상점·증강 항목 연결

`Layout/commerce-fixtures.json`은 승인 시안의 스케치13개 모델, 정비소 증강39종, 봉인 증강12종과 화면별 후보 ID·가격·팔레트의 텍스트 스냅샷이다. 원본은 UI design의 `sketch-v3/runtime-content.js`, `app.js`, `content-flows.js`와 승인 Figma 배치다. 파일 안에 당시 team/ink source commit을 기록한다. 잉크36종은 별도 복제하지 않고 승인 manifest의 ID·이름·효과·병·문양을 읽는다. 모든 지급과 구매는 독립 프리뷰 메모리에서만 처리한다.

- **보상:** 선택한 ID의 이름·아트·설명·팔레트로 획득 확인창을 구성한다. 잉크는 중복 없이 도감에 추가하고 스케치는 새 인스턴스로 보관한다. 일반 보상 수와 챕터 획득 수를 갱신한다. 이벤트·보스는 일반 보상 수를 차감하지 않는다. 보스는 해당 챕터 최대 칸 수의 무기3중1택이며 획득 후 추가 잉크 선택 단계 없이 영수증으로 이동한다.
- **가방 비교:** ‘가방 확인’은 같은 프리뷰 보유 목록을 연다. 다시 생성하지 않으며, Esc는 원래 보상과 후보 선택으로 복귀한다. 핵심 화면을 단독으로 여는 메뉴는 계속 전체36종 검수용 목록을 사용한다. 보유 잉크의 표시 순번과 원본 ID 인덱스를 분리해 새로 얻은 잉크도 제작에서 올바른 효과로 연결한다.
- **상점:** 무기3+잉크3의 6자리다. 패널은 3열2행, 월드는 6개 가로 진열이며 방향키로 상품을 고르면 상세 또는 월드 말풍선의 이름·아이콘·설명·구매 가격이 함께 바뀐다. F는 해당 가격을 한 번 차감하고 가방에 추가한다. 구매 후 실제 획득한 내용의 영수증으로 이동하고 계속하면 같은 상점으로 돌아온다. 재진입하면 상품과 품절을 유지한다. 다른 경로로 먼저 등록된 미판매 잉크만 미보유 잉크로 교체하며 후보가 없으면 빈 자리로 둔다. 서로 다른 갤러리 상점 상태는 독립 예시이며 품절을 공유하지 않는다. 부족·미정 가격·기존 품절 상태는 구매하지 않는다.
- **정비소 증강:** 60G부터 구매할 때마다 다음 가격이30G 증가한다. 최대10회, 보유 증강/내구도 대기9종 제외, 안정형1개와 서로 다른 계열의 도박형2개를 유지한다. 검수 재현을 위해 승인된 세 후보를 우선하고 이미 가진 후보만 데이터 순서로 대체한다. 결제 뒤 Esc나 ‘나중에 선택’은 후보 ID와 순서를 유지하며 재결제하지 않는다. 선택한 증강의 효과와 대가를 보유 목록에 추가하고 소비한 제안으로 돌아가지 않는다.
- **봉인 증강:** 골드를 차감하지 않는다. 같은 ID는 기존 보유 항목의 중첩을 늘리고 최대 중첩에 도달하면 후보에서 제외한다. 보유 목록에는 중첩 수와 1중첩당 효과를 구분해 표시한다.
- **획득 후 구성:** 무기는 ‘가방에 넣고 계속 / 지금 구성하기’, 잉크는 ‘계속 / 지금 부여하기’를 제공한다. 이미 획득한 인스턴스·도감 ID를 가방에 전달한다. 미확정 임시 배치는 닫았다 열어도 유지한다. 확정 무기는 빈 칸도 변경할 수 없으므로 잉크 부여 대상으로 표시하지 않는다. 구성 중 Esc는 소비된 보상 후보로 돌아가지 않고 상점 또는 독립 테스트 화면 목록으로 복귀한다. 일반 보상 다음 회차를 자동으로 열지 않는다.
- **입력·긴 설명:** 후보 ←→, 상점 패널 ↓는 아래 잉크 행으로 이동하고 다시 ↓는 행동 영역, ↑는 이전 행/후보로 이동한다. F 실행, Esc 이전 화면. 선택 의무가 있는 보상에서는 Esc로 포기하지 않는다. W/S는 현재 후보나 상세/보유 목록의 실제 내용 높이에 맞춰 스크롤한다. 항목명이 긴 경우 이름 영역 안에서 줄바꿈하고 붓칠도 그 영역을 따른다.

시작 샘플은1200G·일반 보상2회·잉크5종·핵심 화면과 같은 스케치/무기 예시다. 보유 증강에는 정석대로 갑시다·보호 코팅·손에 익은 필체와 공격 속도2중첩을 둔다. 초기 샘플 증강은 구매 횟수에 넣지 않는다. Play 종료 또는 화면 선택 초기화 메뉴로 시작 상태가 되며 게임 저장은 읽거나 쓰지 않는다.

### 현재 규칙과 실제 게임 연결 범위

상점 가격은 팀 `docs/design/run/rewards.md`에 맞춘다. 1챕터 무기는200+칸당100+강화칸당50G, 잉크220G, 2챕터는350+칸당175+강화칸당90G, 잉크400G다. 3챕터 가격은 미정이므로 구매를 막는다. 잉크가 부족하면 남은 진열 자리는 비어 있으며 스케치로 대체하지 않는다.

`Assets/Deviant/UI/Integration`에 실제 `SketchEquipment`/`SketchRunState`를 읽는 어댑터와 EditMode 검사를 별도로 제공한다. 기존 게임 화면에는 아직 연결하지 않았으며 [게임 연결 계약](commerce-integration.md)에 호출부·입력·pause·에셋 적용 경로를 정리했다. 프리뷰의 고정 후보/경제는 게임 추첨 규칙을 대신하지 않는다.

검사는 기존 `Run remaining Figma checks`에 포함된다. 선택 잉크/스케치의 획득 확인, 상품별 금액과 품절 재구매 방지, 가방 복귀와 원래 선택, 증강의 다음 가격·후보 보존·보유 제외·무료 봉인 중첩을 실제 키 입력으로 확인한다. 동적으로 줄바꿈한 텍스트는 렌더된 글자 경계와 높이를 확인한다. 검증 캡처는1920×1080과960×540이며 출력은 계속 Git 제외 `outputs/ui-theme-preview/`에만 둔다.
