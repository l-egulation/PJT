## 범위와 책임

이 계획은 MVP 챕터 화면을 구현 가능한 화면·계약 요구로 연결한다. 챕터 수와 해금·진행 규칙은 [스테이지 SSOT](../../30-domain/world/ssot.md), 화면 표현은 [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md), 진행 권한은 [계정·저장 SSOT](../../30-domain/player/ssot.md), 저장·서비스 배치는 [데이터 권한과 저장 경계](../../50-architecture/persistence.md)를 따른다.

## 사용자 흐름

1. 사용자가 전투 화면 또는 전체 메뉴에서 챕터 화면을 연다.
2. 화면은 서버 권한의 통합 챕터 목록을 조회한다.
3. 사용자는 현재 전투 챕터, 최고 미완료 진행 목표, 각 챕터 진행률·완료·잠금 상태를 확인한다.
4. 해금된 챕터를 선택하면 해당 챕터의 스테이지 목록을 조회해 스테이지 선택 화면으로 이동한다.
5. 잠긴 챕터를 선택하면 서버가 접근을 거부하고 화면은 필요한 이전 챕터 마지막 스테이지를 안내한다.
6. 스테이지 선택 전까지 현재 전투와 진행 데이터는 바뀌지 않는다.

## 화면 조회 계약

`GET /api/v1/chapters`는 정적 챕터 정보와 인증된 사용자의 진행 상태를 한 응답으로 제공한다.

### 챕터 항목

| 필드 | 의미 |
| --- | --- |
| `chapterId` | 챕터 식별자 |
| `name` | 콘텐츠 버전에 속한 표시 이름 |
| `stageRange` | 챕터의 시작·끝 스테이지 표시 정보 |
| `unlocked` | 서버가 판정한 챕터 접근 가능 여부 |
| `clearedStageCount` | 해당 챕터에서 최초 클리어한 스테이지 수 |
| `stageCount` | 해당 챕터의 전체 스테이지 수 |
| `progressPercent` | `clearedStageCount / stageCount × 100`의 정수 퍼센트 |
| `completed` | 해당 챕터 마지막 스테이지 최초 클리어 여부 |
| `isCurrent` | 현재 전투 중인 스테이지가 이 챕터에 속하는지 여부 |
| `isProgressTarget` | 해금된 챕터 중 가장 높은 미완료 챕터인지 여부. 모든 MVP 챕터 완료 시 모든 항목이 `false` |
| `unlockRequirement` | 잠금 상태일 때 필요한 이전 챕터·마지막 스테이지 안내 정보 |

MVP의 `stageCount`는 챕터마다 10이며 `completed`가 참이면 `clearedStageCount`는 10, `progressPercent`는 100이어야 한다. `progressPercent`는 화면이 별도로 추정하지 않고 서버 응답을 표시한다.

## 스테이지 목록 접근

`GET /api/v1/chapters/{chapterId}/stages`는 다음을 검증한다.

- `chapterId`가 현재 콘텐츠 버전에 존재한다.
- 인증된 사용자의 서버 권한 진행 상태에서 해당 챕터가 해금되어 있다.
- 존재하지 않는 챕터는 `CHAPTER_NOT_FOUND`, 잠긴 챕터는 `CHAPTER_LOCKED` 오류 계약으로 거부한다.
- `CHAPTER_LOCKED`에는 화면이 해금 조건을 안내할 수 있는 `requiredChapterId`와 `requiredStageId`를 포함한다.

챕터 선택만을 위한 POST와 수동 해금 API는 만들지 않는다. 챕터 마지막 스테이지의 최초 클리어를 서버가 확정하는 같은 유스케이스에서 현재 챕터 완료와 다음 챕터 해금을 원자적으로 반영한다. 마지막 MVP 챕터 완료 시 존재하지 않는 다음 챕터를 만들거나 해금하지 않는다.

## 화면 상태와 상호작용

- 네 챕터를 한 월드맵에 표시하며 MVP에는 페이지·스크롤 탐색을 두지 않는다.
- 카드의 기본 정보는 챕터 번호·이름·스테이지 범위와 진행 상태다.
- 잠긴 챕터는 잠금 상태를 표시하고 선택 시 해금 조건을 안내한다.
- 해금된 미완료 챕터는 진행률을 표시한다.
- 완료 챕터는 완료 배지와 100%를 함께 표시한다.
- 현재 전투 챕터와 진행 목표 챕터는 서로 다른 표식과 접근성 이름을 사용한다. 같은 카드일 수 있다.
- 해금된 챕터 선택은 스테이지 목록으로 이동할 뿐 현재 전투를 중단하지 않는다.
- 실제 스테이지 입장을 확정할 때만 기존 방치모드를 유지한 채 전투를 전환한다.
- 로딩 중에는 중복 요청을 막고, 조회 실패 시 잠금·해금 상태를 임의로 추정하지 않는다.
- 인증 만료와 서버 오류는 공통 오류 패턴으로 복구 동작을 제공한다.

## Front·Backend·저장 책임

| 경계 | 책임 |
| --- | --- |
| Front | 서버 응답 상태 표시, 현재·진행 목표 구분, 잠금 안내, 해금 챕터의 스테이지 화면 이동, 로딩·오류·재시도 |
| Backend | 챕터 목록 조합, 진행률·현재·진행 목표 판정, 마지막 스테이지 최초 클리어와 다음 챕터 해금, 모든 직접 접근 재검증 |
| 저장 | 사용자별 현재·최고·최초 클리어 상태와 챕터 해금의 무결성, 존재하지 않는 콘텐츠 참조 방지, 클리어·해금 원자성 |
| 콘텐츠 | 챕터 ID·이름·순서·스테이지 소속·해금 선행 관계와 콘텐츠 버전 |

물리 테이블·컬럼과 프레임워크는 구현 단계에서 정한다. 계약과 권한 경계를 DB 스키마보다 먼저 고정한다.

## 검증 기준

- 신규 계정은 챕터 1만 해금되고 진행률 0%, 현재 전투와 진행 목표가 챕터 1로 표시된다.
- 중간 진행 계정은 현재 전투 챕터와 진행 목표 챕터가 달라도 각각 정확히 표시된다.
- 챕터의 최초 클리어 수가 0·1·9·10일 때 진행률이 각각 0·10·90·100%다.
- 마지막 스테이지 최초 클리어 시 현재 챕터 완료와 다음 챕터 해금이 한 결과로 반영된다.
- 같은 클리어 결과를 재시도해도 해금이나 보상이 중복되지 않는다.
- 존재하지 않는 `chapterId`와 잠긴 챕터 직접 요청이 각 오류 계약으로 실패한다.
- 목록 조회 뒤 권한이 바뀌어도 스테이지 목록 접근에서 최신 서버 상태로 다시 검증한다.
- 해금된 챕터 선택만으로 현재 전투·현재 스테이지·방치모드가 바뀌지 않는다.
- 챕터 4 완료는 완료 배지와 100%를 표시하되 다음 챕터를 생성하지 않는다.
- 4-10 완료 뒤에는 모든 챕터의 `isProgressTarget`이 `false`이고 진행 목표 표식을 표시하지 않는다.
- 키보드·포인터 입력, 16:9·16:10과 최소 창 크기에서 현재·목표·잠금·완료 상태를 색상만으로 구분하지 않는다.
