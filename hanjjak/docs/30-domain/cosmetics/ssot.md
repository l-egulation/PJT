# 치장 뽑기·도감·세트 SSOT

## 책임

치장 시스템의 해금, 배너·추첨, 결제 우선순위, 등록·미등록 중복 재고·성급, 거래 가능 경계, 도감, 세트, 외형 착용, 픽업 마일스톤과 선택 상자의 게임 규칙을 소유한다. 배너 비용·확률·활성 풀·세트 구성·`starThresholds`·세트 효과 수치는 [MVP 콘텐츠 v1](../../60-content/cosmetics/mvp-v1.md)가 소유한다. 계정 권한과 공통 지갑은 [Player SSOT](../player/ssot.md), 아이템 수량·인벤토리 슬롯은 [Items SSOT](../items/ssot.md), 최종 전투 계산은 [Combat SSOT](../combat/ssot.md)가 소유한다. 티켓의 반복 공급처·공급량과 렌더링 자체는 이 문서의 책임이 아니다.

## 해금

- 계정이 스테이지 1-5를 처음 클리어할 때 해금한다.
- 해금 상태와 공용 치장 뽑기권 10장 지급은 계정당 한 번, 같은 원자적·멱등 처리 단위로 확정한다.
- 최초 클리어 결과 재전송·재접속으로 반복 지급하지 않는다.
- 해금 전 치장 전용 조회·명령 API는 거절한다.
- 메뉴 잠금과 최초 클리어 조건은 공통 계정 진행 상태가 제공한다.

## 배너·등급·추첨

- 일반 배너는 제공하지 않는다. 전설 세트마다 상시 픽업 배너 하나를 연결하며 관계는 `전설 세트 1 : 픽업 배너 1`이다. 각 배너의 200회 마일스톤은 전설 치장 선택 상자를 지급하고, 활성 선택 상자는 모두 같은 전체 전설 치장 풀을 사용한다.
- 모든 픽업은 항상 열려 있고 기간 종료나 회차 초기화가 없다. 모든 배너의 1회 쌀 비용과 전설 총확률은 같다.
- 안정 등급 식별자는 `NORMAL`, `RARE`, `EPIC`, `LEGENDARY`다.
- 모든 배너는 동일한 노말·희귀·영웅 전체 활성 풀을 사용한다. 전설 당첨은 해당 배너의 전설 세트 구성품에서만 나온다.
- 서버가 등급을 먼저 추첨하고, 등급 안의 활성 치장은 동일 정수 가중치 `1`로 독립 추첨한다. 1회·10회 모두 같은 공개 확률표를 사용하며 같은 치장이 한 요청에서 반복될 수 있다.
- 최소 등급 보장, 미보유 보정, 중복 방지, 셔플백과 자연 획득 초기화형 천장은 적용하지 않는다. 10회 비용은 1회 비용의 10배이며 할인·추가 결과·보장 보상은 없다.
- 확률은 백만분율 정수로 관리하고 합계는 정확히 `1,000,000`이어야 한다. 0보다 큰 확률 등급에는 활성 치장이 하나 이상 있어야 한다. 개별 확률은 등급 확률을 활성 치장 수로 나눈 값이다.
- API는 확률·풀·개별 확률의 정확한 분자·분모와 표시 문자열을 제공하며, 클라이언트는 표시만 하고 추첨하지 않는다. 표시 반올림으로 합이 달라져도 분자·분모가 권한 원천이다.

## 재화와 결제 순서

- 쌀은 공통 계정 지갑의 서버 권한 잔액을 참조한다. 공용 치장 뽑기권은 슬롯을 점유하지 않는 서버 권한 계정 재화다. 둘 다 0 이상의 정수다.
- 뽑기권 1장은 어느 픽업에서든 1회 비용 전체를 대체한다. 서버는 가능한 뽑기권을 먼저 사용하고, 남은 유료 회차에 공통 1회 쌀 비용을 곱한다. 사용자가 우선순위를 선택할 수 없다.
- 티켓과 쌀의 합산 결제 능력이 부족하면 일부 실행 없이 전체 요청을 실패시키고 어느 재화도 소비하지 않는다.
- 목록 조회는 현재 잔액 기준 예상 티켓·쌀, 실행 가능 여부와 부족 원인을 제공한다. 실행 시 최신 잔액으로 다시 계산하며 조회는 예약이나 가격 고정이 아니다.

## 치장 보유·등록 수량·성급

- 치장은 일반 200슬롯 인벤토리를 점유하지 않는 계정 단위 도감 상태다. 서버 권한 최소 상태는 `cosmeticId`, `registeredQuantity`, `unregisteredQuantity`, `reservedQuantity`, `cosmeticStar`다.
- `registeredQuantity`는 누적 등록 수량이며 등록 명령으로 감소하지 않는다. `unregisteredQuantity`는 미등록 중복 재고이고, `reservedQuantity`는 거래 예약 재고다. `availableUnregisteredQuantity`는 파생값 `unregisteredQuantity - reservedQuantity`이며 항상 0 이상이어야 한다.
- 최초 획득은 자동 등록한다. 미보유 치장을 처음 획득하면 `registeredQuantity`가 1이 되고 `cosmeticStar`가 1성이 되며 외형이 해금된다. 최초 획득 수량은 미등록 재고로 남기지 않는다.
- 이미 등록된 치장의 중복 획득은 결과 수만큼 `unregisteredQuantity`를 늘린다. 5성 이후의 중복도 변환·환급 없이 미등록 재고로 보관한다.
- 한 10회 결과에서 같은 미보유 치장이 반복되면 결과 순서대로 첫 결과는 최초 획득·자동 등록, 뒤 결과는 미등록 중복으로 판정하고 응답도 순서를 보존한다. 클라이언트가 재계산하지 않는다.
- 거래 가능한 자산은 미등록 중복 재고로 한정한다. 등록된 외형 권한, `registeredQuantity`, `cosmeticStar`, 도감 상태는 거래하지 않으며, 거래 예약 수량은 등록에 사용할 수 없다.
- 등록 명령은 `1개 등록`과 `다음 성급까지 등록`만 제공한다. `ONE`은 사용 가능한 미등록 중복 재고 1개를, `UNTIL_NEXT_STAR`는 서버가 치장 등급에 대응하는 활성 `starThresholdsByGrade`의 다음 임계값과 현재 `registeredQuantity`의 차이로 계산한 전량을 원자적으로 등록한다. 필요한 `availableUnregisteredQuantity`가 부족하면 일부만 처리하지 않고 전체 요청을 실패시킨다. 5성에 도달하면 추가 등록을 차단하며 남은 미등록 재고는 보유하거나 거래할 수 있다.
- `cosmeticStar`는 누적 `registeredQuantity`와 활성 콘텐츠의 등급별 누적 `starThresholdsByGrade`에서 파생한다. 각 등급의 1성 임계값은 1이고 최대 성급은 5성이다. 별도 성급 소비량·확률·승급 상태를 저장하지 않는다.

```text
cosmeticStar = max(star where registeredQuantity >= starThresholdsByGrade[grade][star])
```

등록·재고 예약·성급 파생값 갱신은 한 서버 트랜잭션으로 확정하며, 실패하면 등록 수량·미등록 재고·예약 수량을 변경하지 않는다.

## 도감

- `uniqueRegisteredCount`는 세트 소속과 무관하게 `registeredQuantity >= 1`인 서로 다른 치장 수다. 중복 미등록 재고와 성급은 늘리지 않는다.
- 도감은 등록 현황, 미보유 필터, 치장별 등록 수량·성급, 세트 이동과 완성 기록을 표시하는 탐색 상태다.
- 도감 단계, 도감 단계 보상과 도감 전투 효과는 제공하지 않는다. `uniqueRegisteredCount`는 완성률 표시와 정렬용 파생값으로만 사용한다.
- 콘텐츠 버전 변경 시 도감 완성률과 세트 이동 상태는 현재 등록 상태로 재계산하지만 전투 보유 효과를 만들지 않는다.

## 세트 구성·성급·효과

- 세트는 `HEAD`, `TOP`, `BOTTOM`, `GLOVES`, `SHOES`, `CAPE`에 대응하는 서로 다른 치장 6개를 정확히 하나씩 포함한다. 정식 출시 후 세트 구성은 불변이며 치장 하나는 한 세트에만 속한다. 정식 출시 전 임시 콘텐츠는 개발 데이터를 초기화하는 clean cutover에서만 배치를 교체할 수 있다.
- 치장 정의에는 현재 콘텐츠 버전의 외형 부위가 하나 있으며 세트는 부위별 구성 누락·중복 없이 정확히 6부위여야 한다. 치장·세트의 실제 명칭과 이미지는 nullable 콘텐츠 메타데이터다. 세트와 배너·선택 상자 연결 및 구성 카탈로그는 콘텐츠 문서가 소유한다.
- 세트 성급은 여섯 구성 치장 성급의 최솟값이다.

```text
setStar = min(cosmeticStar of HEAD, TOP, BOTTOM, GLOVES, SHOES, CAPE members)
```

- 미등록 구성원은 0성으로 보며 하나라도 미등록이면 세트 0성·효과 없음이다. 여섯 구성원이 모두 최초 등록되면 세트 1성이 활성화된다.
- 각 세트의 1~5성 효과 행은 해당 성급까지의 누적 총값이다. 현재 세트 성급 행 하나를 그대로 사용하며 이전 성급 행을 다시 합산하지 않는다.
- 완성된 모든 세트의 현재 성급 효과 행을 스탯 ID별로 합산해 보유 효과를 제공한다. 스탯 허용 목록·최종 합산 순서·상한은 전투 SSOT가 소유한다. 콘텐츠 버전 변경 시 기존 계정도 현재 등록 상태로 재계산한다.
- 효과 수치와 세트 구성은 콘텐츠 문서가 소유하며, 도감 단계 보상이나 도감 전투 효과로 보정하지 않는다.

## 외형 착용과 등록 API

- 외형 슬롯 ID는 `HEAD`, `TOP`, `BOTTOM`, `GLOVES`, `SHOES`, `CAPE` 정확히 6개다. 각 슬롯은 비울 수 있고 한 슬롯에는 현재 외형 하나만 둔다.
- 등록된 치장만 고정 부위 슬롯에 착용할 수 있다. 착용·교체·해제는 외형만 바꾸며 도감·세트 보유 효과와 전투 능력치를 변경하지 않는다.
- 메인 전투와 보석 던전의 플레이어 외형은 계정의 현재 6부위 착용 상태를 사용한다. 별도 테스트용 또는 고정 세트 외형으로 덮어쓰지 않는다.
- 현재 콘텐츠에서 완성 전투 프레임이 제공되는 완전한 6부위 세트는 장착 ID 조합으로 해당 프레임을 선택한다. 부분 착용, 혼합 세트, `imageUrl`이 없거나 완성 전투 프레임이 없는 조합은 존재하지 않는 레이어를 합성하지 않고 기본 캐릭터를 명시적 fallback으로 사용한다. 어떤 fallback도 천사 테스트 세트로 대체하지 않는다.
- 등록은 다음 API 하나로 처리한다.

```http
POST /api/v1/cosmetics/{cosmeticId}/registrations
```

```json
{ "mode": "ONE" | "UNTIL_NEXT_STAR" }
```

- 착용·교체·해제는 다음 API로 처리한다. `cosmeticId: null`은 해당 슬롯을 비운다.

```http
PATCH /api/v1/cosmetics/equipment/{slotId}
```

```json
{ "cosmeticId": "<cosmeticId>" | null }
```

- 별도 성급 승급 API는 제공하지 않는다. 성급은 등록 수량과 치장 등급에 대응하는 `starThresholdsByGrade`에서 자동 파생된다.

## 픽업 200회 마일스톤과 선택 상자

- 픽업 배너별 성공 결과 수를 영구 누적한다. 1회는 `+1`, 10회는 `+10`이며 결제 방식과 무관하다. 실패·롤백·멱등 재요청·선택 상자 사용은 누적하지 않고 자연 추첨으로 리셋하지 않는다.
- 200회마다 전설 치장 선택 상자 수령 자격이 1개 생긴다. 누적과 수령 수를 분리 보존하며 미수령 자격은 만료되지 않는다.

```text
claimableBoxCount = floor(totalSuccessfulDraws / 200) - claimedBoxCount
```

1개·미수령 범위 지정 수량·전체를 수령할 수 있다. 선택 상자는 동일 `boxItemId`끼리 중첩한다. 기존 스택이 있으면 슬롯 없이 늘리고, 없으면 공용 200슬롯 인벤토리의 한 슬롯만 필요하다. 공간 부족 시 전체 요청을 실패시키고 수령 수와 인벤토리를 유지한다.

- 선택 상자는 한 번에 하나만 사용한다. 사용자는 활성 콘텐츠에 존재하는 전체 전설 세트를 먼저 확인하고, 한 세트를 고른 뒤 그 세트의 6부위 구성품 중 하나를 선택한다. 서버는 유효한 선택 상자와 선택 치장의 `LEGENDARY` 등급·콘텐츠 유효성을 검증한다. 성공 시 상자 1개 소비와 치장 1개 지급을 원자적으로 처리하고, 전설이 아니거나 존재하지 않는 선택은 소비하지 않는다.
- 선택 상자 지급은 뽑기와 같은 신규·중복·도감·세트·전투 반영 규칙을 따르지만 픽업 성공 횟수에는 포함하지 않는다.

## 서버 권한·원자성·멱등성

서버가 인증·해금·배너·콘텐츠·비용·추첨·지급·도감 표시 상태·세트·마일스톤·전투 반영을 확정한다. 뽑기는 해금·콘텐츠 검증, 계정 재화 직렬화, 티켓 우선 비용 재계산, 조건부 차감, 독립 추첨, 결과 순서 반영, 세트 효과·마일스톤 재계산, 감사·멱등 결과 저장을 하나의 성공 또는 롤백 흐름으로 처리한다.

- 서로 다른 멱등 키 요청은 최신 계정 잔액 기준으로 직렬 처리하거나 동등한 원자 조건부 차감을 사용한다. 재화는 음수가 될 수 없다.
- 상태 변경 명령은 공통 멱등 키를 요구한다. 같은 계정·명령·키의 동일 입력 성공은 최초 결과를 반환하며 재추첨·추가 소비·지급·누적을 하지 않는다. 다른 입력은 상태 변경 없이 충돌로 거절한다.
- 성공 추첨은 계정·요청·키, 배너·횟수, 비용·확률·풀 버전, 실제 차감, 결과 순서와 신규·중복, 지급 후 상태, 누적 전후, 감사 재현 토큰을 추적 가능하게 기록한다. 토큰은 클라이언트에 노출하지 않으며 보존 기간은 운영 명세가 소유한다.
- 활성 콘텐츠가 허용 등급·확률 합계·동일 하위 풀·전설 세트와 배너의 1:1 매핑·배너별 유효한 선택 상자 식별자·세트 구성·효과 행·임계값 조건을 만족하지 않으면 조회·실행을 제공하지 않는다. 누락 풀 제외, 재분배, 기본 배너 대체, 임의 지급으로 보정하지 않는다.

## 전투 반영

치장 등록·성급 파생 또는 콘텐츠 버전 전환으로 세트 보유 효과가 바뀌면 서버 권한 상태와 다음 전투 입력을 재계산한다. 같은 계정에 현재 메인 전투가 있으면 현재 사이클의 효과와 스냅샷은 바꾸지 않고, 갱신된 보유 효과를 다음 메인 전투 사이클 시작 입력에 포함한다. 진행 중 사이클에 효과를 소급하거나 외형 착용만으로 전투 능력치를 변경하지 않는다.

## 불변 조건

- 해금과 최초 티켓은 계정당 한 번만 지급한다.
- 최초 획득은 자동 등록·1성·외형 해금으로 확정하고, 중복은 미등록 재고로 분리한다.
- `availableUnregisteredQuantity = unregisteredQuantity - reservedQuantity`이며 등록은 이 가용 재고만 소비한다. 등록된 자산과 성급·도감 상태는 거래하지 않는다.
- 결제 부족·검증 실패·중간 실패는 모든 상태를 변경하지 않는다.
- 추첨은 독립적이며 결과 순서와 콘텐츠 버전·seed로 재현 가능해야 한다.
- 세트는 6부위 고유 구성과 최소 성급으로 계산하고 현재 성급의 누적 총 효과 행을 한 번 사용한다.
- 완성 세트 효과는 착용과 무관한 보유 효과이며, 도감은 전투 효과를 제공하지 않고, 진행 중 메인 전투에는 다음 사이클부터 세트 효과를 적용한다.
- 마일스톤 수령·상자 사용·등록은 재시도해도 중복 지급·소비·등록하지 않는다.
- 치장은 200슬롯을 차지하지 않으며 선택 상자는 기존 스택이 없을 때만 한 슬롯을 사용한다.
