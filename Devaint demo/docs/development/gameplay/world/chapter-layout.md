# 챕터 레이아웃 계약과 구성 범위

[분야 개요](README.md)

[맵 공급 목표](../../architecture/gameplay-architecture.md#고정-맵과-절차-생성-맵의-공통-경계)에 따라 고정 레이아웃 공급, 불변 배치 결과, 공통 검증, 모듈 뷰 구성과 세션 상태를 연결한다. 본 게임·실험장의 격리 평지 모듈과 실제 반복 숲이 같은 공급/검증/세션 경계를 사용한다. [숲 프로토타입](forest-prototype.md)의 기존 청크 창·기하·풀·반복 배치는 유지하며 정식 챕터 콘텐츠나 실제 생성기를 채택한 것은 아니다.

실제 반복 숲도 선택적 불변 반복 descriptor와 절대 모듈 주소로 같은 공급/검증/세션 경로를 사용한다. 구조 검사는 항상 공통이며 one-way 표면을 고체와 구분한다. 주입 IChapterTraversalProof는 실제 격리 Tilemap/Composite/effector와 같은 Motor/Contact/Facing/Jump/Dash/Platform 실행으로 기술 witness를 검사한다. FloorTop이나 Composite AABB를 충돌 증명으로 대체하지 않는다. 완전 프로필·고정 기하 endpoint/이동 종류에서 결정적인 유한 입력을 만들고 profile/input/trace 해시를 레이아웃 해시와 분리한다. 프로필 재검증은 로드 ID/맵을 유지하고 실패 시 이전 증명을 보존한다. 정식 챕터의 필수 경로/콘텐츠·임의 큰 좌표의 부동소수점 동일성을 증명한 것은 아니다.

기술 witness의 수평 제어는 목적지를 처음 지난 tick에 정지하고 실제 몸의 수평 범위가 목적지를 포함하는지 native 0.005 skin으로 검사한다. 고정 정수 입력의 overshoot를 반대로 진동시키거나 속도 기반 임의 허용 오차를 만들지 않는다. 첫 점프가 부족한 명시 Jump witness는 실제 첫 정점에서 남은 둘째 점프를 사용한다. Prepare/commit 재검증은 분리되어 실패·옛 세션/기하 preparation이 현재 증명을 바꾸지 않는다.

Dash witness는 실제 몸이 원래 목적지/Y 영역을 안전하게 지난 사실을 먼저 기록하고 취소할 수 없는 기존 대시가 자연 종료한 뒤 실제 현재 위치에서 두 grounded tick·native clearance를 확인한다. nominal 거리에서 강제 정지하거나 최종 위치 허용 오차를 늘리지 않는다. Walk/Jump는 정지한 실제 몸이 목적지를 포함해야 한다.

## 데이터와 소유권

`World/Contracts/ChapterLayout`은 Unity 객체를 참조하지 않는다. 모듈·콘텐츠 배치·앵커·연결·위험 영역 목록을 복사하고 읽기 전용으로 제공한다. 모듈과 배치의 ID는 씬 인스턴스나 로드 순서가 아니라 공급 데이터가 정한다. 제작 모듈은 `ContentId`로 참조하며 프리팹 내부 기하를 JSON에 다시 작성하지 않는다. 새 맵 저작/저장 형식은 아직 없다.

| 계약 | 현재 의미 |
|---|---|
| `LayoutOrigin` | 고정 제작/캡처한 생성 결과 구분, 공급기 ID·버전, 콘텐츠 버전, 선택적 seed. 실제 생성 알고리즘은 없음 |
| `LayoutModule` | 안정적인 모듈 배치 ID, 제작 콘텐츠 ID, 챕터 원점 기준 위치 |
| `LayoutAnchor` | 모듈 기준 위치와 안정적인 ID. `Traversal`은 발 위치/이동 지점, `Binding`은 표현·상호작용 등에 넘길 의미 있는 위치 |
| `LayoutConnection` | 이동 앵커 사이 양방향 연결과 필요한 이동 종류. 전멸 잠금/챕터 전환을 수행하지 않음 |
| `LayoutPlacement` | 모듈에 속한 콘텐츠 배치 ID·참조·위치. 현재 Unity 바인딩은 충돌 없는 마커 뷰만 지원 |
| `RequiredAnchors` | 없으면 구성을 거부하는 앵커. 이동 앵커는 시작점으로부터 연결도 검사 |
| `Hazards` | 챕터 좌표의 검증용 위험 사각형. 실제 피해/낙사 규칙을 실행하거나 위험 뷰를 자동 생성하지 않음 |

`ContentHash`는 목록의 ID 순서에 독립적인 배치/출처 해시다. 검증 결과의 `ResolvedHash`와 세션의 `ResolvedLayoutHash`는 실제 모듈 기하 해시도 포함한다. 이동 프로필 해시는 별도로 보관한다. 같은 배치 참조라도 제작 모듈의 기하가 달라지면 같은 공간으로 취급하지 않는다. `LayoutRequest.ExpectedResolvedHash`를 지정하면 재생 시 다른 기하를 거부한다. 플랫폼 간 물리 결과의 비트 단위 결정성을 보장하는 값은 아니다.

## 공급과 검증

`AuthoredLayoutProvider`는 요청한 챕터 ID/레이아웃 버전에 맞는 고정 스냅샷을 제공한다. seed를 바꿔도 고정 결과가 재생성되지 않는다. `IChapterLayoutProvider`의 다른 구현은 이미 해석된 생성 결과를 같은 계약으로 넘길 수 있다. 테스트의 캡처 공급기는 결과 형식을 검증하는 대역이며 난수 생성기나 제품 콘텐츠가 아니다.

`WorldAssembler.TryOpen`은 공급기를 한 번 호출하고 같은 `LayoutValidator`로 검사한 뒤 세션을 만든다. 실패한 공급/검증을 다른 맵으로 대체하거나 자동 재시도하지 않는다. 공급기는 활성 씬을 변경하지 않으며, 검증에 실패하면 모듈/배치 뷰를 준비하지 않는다.

현재 검증은 다음을 수행한다.

- 모듈·앵커·연결·배치 ID 중복과 잘못된 참조, 시작 이동 앵커 및 필수 앵커 누락, 필수 이동 지점의 연결 여부.
- 제작 모듈 기하와 마커 콘텐츠의 존재, 비유한/빈 기하 거부.
- 실제 몸 크기·오프셋의 양쪽 방향에서 앵커 충돌/위험 겹침과 바닥 지지.
- 평지 보행 연결의 몸 전체 통과 공간, 바닥 연속성/접합부, 위험 영역, 양수 보행 속도.

이는 **축에 맞춘 정적 박스와 연속된 같은 높이 바닥의 보수적인 검증**이다. 몸 아래가 발 원점과 일치해야 한다. 점프/대시 연결, 높이차, 경사, 일방향 발판 등의 통과 증명은 아직 지원하지 않아 명시적으로 거부한다. 그래프 연결만으로 이 이동을 통과했다고 기록하지 않는다. 실제 몸 크기·보행 속도·이동 버전은 `UnityChapterModules.ProfileFor`가 공통 플레이어에서 읽는다. `TryRevalidate`는 같은 고정 공간에서 이동 프로필만 다시 검사하며 공급기를 재호출하지 않는다. 실패하면 이전 검증을 보존한다. 게임의 이동 편집과 챕터 검증을 자동으로 묶는 전체 Run 조립은 후속 범위다.

## Unity 바인딩과 뷰 수명

`Integration/Unity/UnityChapterModules`는 작성된 GameObject/프리팹의 BoxCollider2D 크기·오프셋·변환을 읽는다. 현재 바인딩은 회전/배율 없는 정적 박스, 일반 고체만 지원한다. trigger·effector·원본 composite·둥근 모서리·auto tiling·Rigidbody2D·모션/사용자 스크립트는 해석 없이 통과시키지 않는다. 마커는 Collider2D/Rigidbody2D/사용자 스크립트 없는 콘텐츠다. 챕터 루트도 회전/배율이 없고 Rigidbody2D 조상 아래에 있지 않아야 한다. 이 제한은 제작 기준 전체나 NPC/액터 프리팹의 제품 규칙이 아니다.

모듈은 비활성 계층에서 준비한 뒤 활성화한다. 런타임 고체는 바인딩이 소유한 정적 Rigidbody2D/CompositeCollider2D로 병합하고 공통 `ArenaSurface`를 붙인다. 맞닿은 모듈 바닥의 내부 경계를 별도 벽으로 남기지 않으며 기존 전투 모터를 그대로 사용한다. 모듈 활성화/반환 시 병합 기하를 갱신한다. 원본 프리팹·씬·GUID를 변경하지 않는다.

`ChapterSession`은 검증된 레이아웃/기하/프로필, 뷰 로드 목록, `ChapterState`를 소유한다. 모듈을 다시 로드할 때도 기하 해시를 검사한다. 기하 편집을 이동 재검증으로 몰래 채택하지 않으며 새 공간은 명시적으로 새 세션을 열어야 한다. 모듈 중복 로드/언로드는 중복 뷰를 만들지 않는다. 준비/활성화 실패는 해당 로드에서 준비한 뷰만 반환하고 다른 로드와 배치 상태를 유지한다. 콜백의 상태 변경 재진입은 거부한다.

`ChapterState`는 안정적인 배치 ID의 `Present`/`Retired` 사실만 보관한다. 뷰 언로드는 이 사실을 초기화하지 않는다. `TryRetirePlacement`는 세션 ID를 확인하며 이미 반영한 사실을 중복 실행하지 않는다. 배치 사실 반영 뒤 뷰 정리에 실패하면 사실을 임의로 되돌리지 않고 오류를 반환한다. 이 모델은 실물 적 HP·아이템 재고·리젠·획득·보상·영구 저장을 대신하지 않는다. 현재 마커를 [NPC·직선 대화](../../presentation/narrative/narrative-dialogue.md)의 대상 가용성에도 연결하며, 대화 완료가 배치 제거/보상 사실을 만들지는 않는다.

`IChapterAnchors`는 세션 ID를 확인한 뒤 챕터 좌표의 앵커를 조회한다. `ChapterWorldHost.TryGetWorldAnchor`는 이를 Unity 월드 좌표로 연결한다. `ChapterCameraSource`는 같은 세션/앵커와 바인딩 오프셋을 카메라 위치 요청에 공급하며 챕터가 끝나면 소스 실패로 반환한다. 종료된 세션이나 이전 세션 ID의 조회/변경은 거부한다. `ChapterWorldHost.Close`/파괴는 자기 세션과 뷰를 정리하며 새 세션은 새 ID/초기 상태를 갖는다. 화면을 숨기거나 개별 모듈 뷰를 내리는 것과 챕터 종료는 구분한다. 자동 챕터 전환이나 실제 런 종료 규칙은 추가하지 않는다.

`ChapterSequenceBindings`는 같은 기대 세션의 필수 앵커/배치에 대화·Cue·카메라 단계를 연결한다. 실행 전 병렬 그룹 내부의 모든 잎 단계까지 바인딩/필수 앵커 누락을 거부하고 종료된 세션을 다른 챕터로 재연결하지 않는다. 현재 두 씬의 고정/캡처 fixture에서 검사하며 제품 시퀀스 카탈로그를 전체 레이아웃 검증기에 등록하거나 실제 Run 전환을 연결한 것은 아니다. 화면 페이드는 앵커를 요구하지 않으며 챕터 수명과 별도 출력 세션 세대를 확인한다. 시퀀스 종료는 자기 페이드 유지 요청도 반환하고 배치/챕터 진행 사실을 만들지 않는다. 연출 전용 StageMove는 같은 세션의 시작/도착 앵커를 요구하고 실제 단계 시작의 좌표를 캡처한다. 뷰 역할 ID/출력 세대·독점 소유권은 바인딩이 검사하며 게임플레이 액터를 생성하거나 배치/HP 사실을 변경하지 않는다. 종료/스킵·소유자 제어와 현재 제한은 [시퀀스 실행](../../presentation/narrative/sequence-execution.md)을 따른다.

## 검증과 남은 연결

`ChapterLayoutTests`는 고정/캡처 공급의 공통 경로, 불변/해시/버전, 누락·충돌·틈·필수 경로·미지원 이동 거부, 재로드 상태, 오래된 세션, 실패 정리·재진입, 같은 공간의 이동 재검증을 검사한다. `ChapterWorldIntegrationTests`는 본 게임/실험장에서 실제 모듈을 같은 바인딩으로 구성해 공통 플레이어로 접합부를 왕복하고, 이동 버전 재검증·뷰 재로드·앵커·기하 편집 거부를 검사한다. `ChapterModuleAdapterTests`는 미지원 제작 기하를 뷰 생성 전에 거부하는지 확인한다. 실행 명령과 아트/빌드 검증 구분은 [검사 방법](../../testing/testing.md)을 따른다.

기본 숲의 정식 챕터 콘텐츠·필수 목적지 채택, 실제 생성 알고리즘, 작성된 기술 witness 밖의 임의 경로 통과 증명, 카메라 영역/복귀 후보/위험 뷰, 제품 NPC/아이템 아트 바인딩과 상태 수명, Run 시작·챕터 전환·저장 정책은 후속 범위다. 현재 공통 숲 공급과 실제 모터의 점프/대시/발판 witness를 전체 맵/런 통합 또는 실제 아트·플레이 검증 완료로 확대하지 않는다.
