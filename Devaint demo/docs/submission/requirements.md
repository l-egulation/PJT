## 1. 제품 개요

플레이어는 기록이 지워지는 재난 속에서 잉크로 되살아난 주인공이 되어 마을을 출발한다. 챕터를 탐험하며 적을 처치하고 스케치 무기와 잉크를 획득한다. 무기별 팔레트 구성을 확정하고 두 장착 칸을 활용해 전투하며, 보스를 처치한 뒤 다음 챕터로 이동한다. 사망하거나 현재 빌드의 마지막 챕터를 클리어하면 마을로 돌아온다.

장기 목표는 3챕터, 전체 런 45~60분이다. 현재 제출 범위는 1·2챕터다.

## 2. 사용자와 시스템 경계

| 구분 | 역할 |
|---|---|
| 플레이어 | 타이틀·마을·전투·보상·제작·장착·상점·설정 조작 |
| 개발·기획 담당자 | 구조화 데이터 편집, 자동 검사, 시안 비교와 수동 플레이 평가 |
| 수집 서버 관리자 | Bearer 인증 후 플레이 기록 조회·다운로드·삭제 |
| Unity 클라이언트 | 전투·진행·영구 프로필의 실행 주체, 리플레이 생성과 전송 |
| Go 수집 서버 | 플레이 기록 수집·조회·삭제 |

## 3. 기능 요구사항

기능별 검증 결과는 [테스트 계획·결과서](test-plan-results.md)에 정리한다.

| ID | 영역 | 요구사항 및 수락 기준 | 현재 범위 |
|---|---|---|---|
| FR-01 | 시작 | 타이틀에서 시작하면 페이드 후 시작 마을로 한 번 진입한다. 설정에서 복귀할 때 입력 포커스를 회복한다. | 구현 |
| FR-02 | 이야기 | 첫 마을 방문에서 지워짐·희생·잉크 각성을 전달하고 플레이 조작으로 이어진다. | 초반 오프닝 구현, 후속 연출 일부 남음 |
| FR-03 | 런 시작 | 마을 출발로 새 런을 시작하며 맨손 기본 공격을 사용할 수 있다. 무기 없는 A/B 칸에서도 기본 공격이 가능하다. | 구현 |
| FR-04 | 탐험 | 챕터 내부 자유 이동과 재방문을 허용한다. 적 처치 여부와 관계없이 일반 구역을 이동할 수 있다. | 1·2챕터 절차 생성 구현 |
| FR-05 | 이동 | 이동·점프·대시·벽 기어오르기·벽 차기·일방향 발판 내려가기를 공통 입력으로 처리한다. | 구현 |
| FR-06 | 전투 | 두 무기의 기본 공격·스킬 입력을 구별하고 피해·상태·취소·쿨타임을 처리한다. 행동별 실행 결과를 기록한다. | 공통 전투 런타임 구현 |
| FR-07 | 보상 | 일반·엘리트 처치로 게이지와 받아 둔 보상을 누적하고, 보상을 열 때 후보를 제시한다. 선택 화면 중 전투를 멈추며 중복 선택을 막는다. | 구현 |
| FR-08 | 무기 구성 | 신규 도면은 스테이지별 4·5·6칸 규격을 따른다. 잉크 임시 배치 때 횟수를 예약하고 확정 시 소비한다. 확정한 빈 칸도 잠겨 이후 편집을 거부한다. | 1·2스테이지 구현, 3스테이지 콘텐츠는 범위 밖 |
| FR-09 | 잉크 | 39종 도감·색상별 효과를 제공한다. 재획득 시 사용 횟수를 더하고 예약 초과를 거부한다. 이미 소비한 확정분은 무기 폐기로 반환하지 않는다. | 구현, 일부 충전형 스킬의 파랑 쿨감 설계 남음 |
| FR-10 | 장착 | 확정 무기를 A/B에 장착·해제·교환한다. 보관·재장착으로 스킬 대기시간이나 확정 잠금을 초기화하지 않는다. | 구현 |
| FR-11 | 내구도 | 적의 실제 HP 감소량을 공격 원본 무기에 누적한다. 파괴 뒤 남은 공격이 다른 무기의 내구도를 소모하지 않는다. | 구현 |
| FR-12 | 상점 | 방 안 진열 상품에 접근해 상호작용으로 구매한다. 잔액 부족·품절 시 추가 차감하지 않고 구매 상태를 유지한다. | 스케치 런 직접 구매 구현 |
| FR-13 | 회복 | 잉크 충전소의 거리·입력 유지·가격·이용 예산을 검사한다. 중단·피격·잔액 부족 때 회복과 결제를 중복 적용하지 않는다. | 구현 |
| FR-14 | 보스·챕터 | 보스 처치 연출과 보상 처리 후 출구를 사용한다. 1→2챕터는 같은 런의 장비·체력·경제 상태를 유지한다. | 구현 |
| FR-15 | 종료·성장 | 사망 또는 2챕터 클리어 시 결과를 표시하고 마을로 돌아간다. 마법안료·해금은 영구 프로필에 저장하며 런 중단 이어하기는 제공하지 않는다. | 구현, 전체 귀환 회귀 검사 필요 |
| FR-16 | 가방·장비 UI | 방향키·확인·뒤로 입력과 포인터로 구성·장착·설명 읽기를 수행한다. 카드 아이콘·이름·여백이 같은 선택 대상이다. | 구현 |
| FR-17 | 지도·HUD | 실제 체력·장비·내구도·보상 상태를 표시한다. 지도는 발견 영역·현재 위치·시설·이벤트 완료 상태를 반영한다. | 구현 |
| FR-18 | 설정 | 화면·소리·조작 설정과 키 재설정을 제공하고 취소·충돌·포커스 복귀를 처리한다. | 구현, 화면별 적용 범위는 UI 명세 참조 |
| FR-19 | 기록 | 플레이를 자동 기록하고 설정된 서버로 전송한다. 기존 기록 중단 설정을 유지한다. | 구현 |
| FR-20 | 수집 API | 플레이 세션 등록, 기록 업로드, 수집 상태 확인을 제공한다. | 서버 구현 |
| FR-21 | 관리자 API | 조회·원본 다운로드·플레이어 삭제는 별도 Bearer 인증을 요구한다. 게임 클라이언트에 관리자 토큰을 포함하지 않는다. | 서버 구현 |

## 4. 비기능 요구사항

| ID | 요구사항 | 확인 기준 |
|---|---|---|
| NFR-01 | 실행 환경 일치 | Editor·테스트·빌드는 Unity 6000.6.5f1과 원본 패키지 버전 사용 |
| NFR-02 | 데이터 일관성 | 기획 데이터와 게임 적용 데이터의 일치 확인 |
| NFR-03 | 저장 안전성 | 영구 프로필 저장·백업·손상 복구, Web 저장 유지, 서버 기록 무결성 확인 |
| NFR-04 | 기록 완전성 | 기록 누락·수집 완료·중단 상태 표시 |
| NFR-05 | 접근 통제 | 관리자 인증, 허용된 웹 주소의 접근, 업로드 크기·동시 요청·저장량 제한 |
| NFR-06 | 데이터 최소화 | 계정·이메일·하드웨어 지문·자유 입력·화면 캡처를 플레이 수집 대상에 포함하지 않음. 기본 보관은 세션 시작 기준 30일 |
| NFR-07 | 조작성·가독성 | 키보드·패드 전환, 메뉴 포커스, 1280×720·1920×1080 UI를 자동 검사와 수동 화면 검토로 평가 |
| NFR-08 | 성능 | 동일한 맵·몬스터·입력 조건에서 처리 성능과 실제 플레이 프레임률 측정 |

## 5. 후속 개발 범위
