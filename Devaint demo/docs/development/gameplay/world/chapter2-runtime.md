# 공통 게임의2챕터

[분야 개요](README.md)

실행 기준은 이 저장소의 unity이며 Unity6000.6.5f1을 사용한다. Tools → deviant → Game → Open Common Game은 기존 타이틀·시작 마을·1챕터 흐름이다. 1챕터 보스 처치 후 보상을 고르고 출구에서 F로 철창을 열면, 열림 연출과 페이드 후 장비·체력·가방·골드·귀속 팔레트를 이어서 2챕터로 바로 이동한다. 1챕터 결과 화면이나 마을 복귀 선택은 거치지 않는다. 같은 런을 유지하며 첫 보스 클리어 해금만 먼저 저장하고, 사망 또는 현재 마지막 챕터인 2챕터 클리어에서 런을 한 번 정산한다. 결과 화면은 1챕터와 같은 항목을 런 전체 값으로 보여 준다. Esc 일시정지의 「마을로」는 1챕터처럼 정산하지 않는다. 방 섬멸 회복은 1챕터와 같은 초록 몸 연출과 화면 테두리를 띄운다. 2챕터 보스 출구의 철창 열림 후 런 정산을 완료하면 공통 GUI가 데모 완료 창을 표시한다. 감사·정식 출시 안내와 플레이 시간·처치·마법안료, 마을/타이틀 버튼을 제공한다. 사망 결과 화면과 정산 서비스는 기존 경로를 유지한다. Game → Build Windows는 타이틀·마을·1챕터·2챕터를 포함한다.

개발용 단독 실행은 Tools → deviant → Chapter2로 Assets/Chapter2/Scenes/Chapter2Procedural.unity를 열고 Play한다. 이 메뉴는 다른 실행 시작 씬 설정의 영향을 받지 않도록2챕터 시작 씬을 지정한다. 공통 게임 메뉴로 돌아가면 기존 타이틀 진입을 따른다. 단독 실행에는 기본 장비와 기본3칸 팔레트를 제공하며 마을 프로필을 새로 정산하지 않는다.

Chapter2World의 seed가-1이면 새 시드,0이상이면 재현 시드다. family는 공란이면8계열 중 선택하며 current,v01,v03,v04,v05,v07,v08,v10으로 고정할 수 있다. 각 계열에 최소2개 후보가 있다. 균등 family/variant 선택은 현재 시험 정책이며 난도별 가중치는 미정이다.

공통 GUI의 A/S 기본 공격,Q/W 스킬,Space 점프,Shift 대시,F 상호작용,Tab 가방,M 지도,Esc 메뉴,H 키 안내를 그대로 쓴다. 정비소·지도·일시정지·결과는 공통 제어 범위로 시뮬레이션과 입력을 제어한다. UI·폰트·월드960×540 픽셀 출력·정비소의 성장 거래를 별도 화면으로 복제하지 않는다.

Chapter2CommonComposition은 현재 VillagePixelViewport와 Chapter1FullMap의 일반 데이터 소스를 구성한다. 지도만 월드 좌표에서 양수 픽셀 좌표로 변환한다. Chapter1MapSource.WorldToMap이 없으면1챕터의 기존 변환을 그대로 쓴다. CommonMaintenanceShop은1챕터 서비스 또는2챕터 서비스로 공통 GUI 거래를 전달한다. 기존1챕터 정비소 도메인 규칙은 유지한다.

## 카메라

2챕터는 마지막 착지 높이를 기준으로 세로 구도를 유지한다. 서 있을 때 카메라 중심은 발보다 3.7칸 위다. 발이 마지막 구도의 바닥보다 0.5칸 아래부터 6.5칸 위까지인 점프 범위에서는 카메라가 움직이지 않는다. 따라서 일반 점프와2단 점프(최고6칸)의 상승·하강·같은 높이 착지는 같은 구도를 유지한다. 실제 다른 높이의 지면에 착지하면 새 높이로 부드럽게 이동한다.

낙하·발판 통과·벽차기 수직 통로처럼 점프 범위를 벗어난 세로 이동에서는 카메라가 진행 방향을 먼저 보여 준다. 수직 속도의 0.12초 거리만큼 앞서 보며 아래는 최대4칸, 위는 최대2.5칸까지다. 이 앞보기는 진행 방향으로만 갱신되므로 낙하 중2단 점프나 벽차기 사이 미끄러짐으로 시야가 되돌아가지 않는다. 추적 중에는 세로 지연을 0.1초로 줄이고, 지연 때문에 플레이어가 점프 범위 경계보다 화면 끝으로 밀려나지 않도록 즉시 따라간다. 착지하면 서 있는 구도로 돌아간다. 방향 전환에 따른 좌우 시야 반전은 사용하지 않는다.

## 지하수로 미술

실제2챕터의 방·통로·충돌은 승인된 레이아웃을 유지하고 `Chapter2WaterwayArt`가32px 지형을 선택한다. 원본은 리소스의 `environments/waterway-tile-variants`이며 내부 명암40px 승인본을 사용한다. 기본 돌·드문 이끼·2/3칸 연결 이끼는 고정 좌표 선택으로 재현된다. 모서리·세로 면은 주변 지형 패턴에 맞춘 승인 셀에서 선택한다. 공용 배치 계약의 `Assets/Chapter2/Resources/Chapter2Waterway`를 통해 복원하며1챕터 팔레트를 교체하지 않는다.

`Chapter2WaterwayBackground`는 승인 뒷벽·아치와 안쪽 통로·배관·철창 창문·창밖 도시를 배치한다. 캐릭터와 지형 앞을 가리는 초근경 버팀벽 기둥은 배치하지 않는다. 벽과 아치 입구는 월드에 고정하고 창밖 도시만 작은 시차를 사용한다. 창문은 구조물과 지형이 없는 위치에만 배치한다.

실제 배치된 창문마다 `Chapter2LightingProps`가 `WindowLightView`와 평행 빛줄기를 연결한다. 리소스 recipe의 창틀 개구부·창살 6개 차폐 사각형을 Unity 바인딩으로 변환하며, 창틀·도시 그림은 유지한다. 빛은 방 경계와 도달 길이 안에서 뒷벽에만 수신하고 창살 윤곽을 공유해 빛줄기도 차폐한다. 빛줄기만 숨겨도 벽 조명은 남는다. 액터 노말·내부 발판의 동적 차폐는 아직 연결하지 않는다.

`Chapter2LightingProps`는 S/F01의 [조명 미술 시험 세트](../../../assets/presentation/lighting-props.md#2챕터-소수-배치-시험)를 소수 배치한다. 랜턴의 몸·지원 근접 반응은 공통 진자/환경 접촉을 사용하며, 불꽃과 국소 뒷벽 광원은 같은 시뮬레이션 시계로 진행한다. 캐릭터·지형 재질과 충돌은 유지하고, 컴포넌트를 끄면 시험 부품·조명과 접촉 관측을 함께 끈다. 실제 그림 크기·밝기의 미술 검토와 전체 노말·동적 그림자 연결은 별도다.

`ReactiveLanternBridge.BodyImpacted`는 수락한 몸 접촉의 actor ID·스윕 최초 진입 위치·면 방향을, `MeleeImpacted`는 진자가 새로 수락한 실제 근접 타격의 유효 소스 ID·접촉 면을 전달한다. 같은 실행/타격의 중복 제거와 벽 차폐를 통과한 경우에만 근접 섬광을 보낸다. `LanternContactFlash`는 두 경로의 플레이어 ID를 확인해 몸 충돌에는 작은 접촉 섬광과 불티, 근접 공격에는 아이보리색 접촉 섬광과 더 긴 방향성 불티를 만든다. 테두리 오버레이는 생성하지 않는다. 빛 조각은 월드 접촉점을 출발해 퍼지고 아래로 떨어지며 줄어든다. 흔들리는 랜턴에 붙어서 이동하지 않으며 32px/unit 출력의 반 픽셀 가장자리에 형상을 맞춰 얇은 조각의 양쪽 면이 같은 좌표로 반올림되지 않게 한다. `contactFlash.body`와 `.melee`의 수명·속도·길이·폭·확산각·중력·중심 섬광 수치와 공유 시뮬레이션 시계를 사용한다. 렌더 프레임만으로는 수명을 진행하지 않는다. 이벤트는 피해·적중 보상·잉크 발동 신호가 아니다.

## 레이아웃 원본

2챕터 맵은 런타임에 조립한다. 방 원형은 `data/map/block_rooms.json`이고 조립·배치는 [블록 맵](block-map.md)을 따른다. `C2Bank.Generate(seed)`가 `Chapter2BlockLayout.Generate`의 결과를 검증해 돌려준다. 같은 시드는 같은 배치를 만들며 `family` 인자는 쓰지 않는다. 배치의 `id`는 `runtime`, `variant`는 시드다. X오른쪽·Y위쪽·Unity unit을 사용한다.

## 검증

`Deviant.Chapter2.Tests.Chapter2BlockLayoutTests`가 런타임 배치 계약(봉인 도전방·잠긴 상자방 포함)과 실제 물리의 벽타기 통로, 2챕터 봉인 도전 3페이지·열쇠 운반자 선정과 처치 즉시 열쇠 자동 습득을 검사한다([블록 맵](block-map.md#시험)).

봉인 도전방·잠긴 상자·열쇠 운반자는 1챕터 구성품(`Chapter1SealChallenge`, `Chapter1KeyChest`)을 `Chapter2GimmickHost`(`IStageGimmickHost`)로 붙인다. 떨어지는 몹은 `Chapter2World.SpawnGimmickMonster`가 2챕터 일반 몹으로 만들고 골드만 준다. 운반자는 `Chapter2NormalEnemy.FollowsMovementOverride`로 공격 없이 운반자 경로만 따른다. 그림은 `Chapter2/Resources/Chapter2Gimmicks/`이며 `python tools/assets/register_stage2_gimmicks.py`가 리소스 `environments/stage2-gimmicks-recolor-20261113`에서 배치하고 배치 목록에 기록한다. 일반 적은 `BindEncounter`로 2챕터의 방 범위, 대상 판정(플레이어가 보스방 밖에 있는지), 열린 좌우 출입구 접근 구역(이동 영역에서 제외)을 받는다. 기존 1챕터는 자신의 방 조회를 계속 사용한다.

비교 캡처는 `C2_REVISION_OUTPUT`의 `views.json`과 수정 전 레이아웃을 사용한다. 동일한 960×540·월드 배율과 방 안의 상대 카메라 위치를 유지하며, 재배치한 외부 통로는 같은 연결부를 다시 중심에 둔다. 캡처·XML·로컬 비교 페이지는 Git 제외 outputs에만 둔다.

EditMode Test Runner의 Deviant.Chapter2.Tests는8계열 데이터·시드 재현·방별 섬멸·공통 게임과2챕터 메뉴·실제1→2챕터 장비/팔레트/체력/가방 이관·공통 GUI·지도·정비소 정지·벽차기·보스 출구를 검사한다. 그래픽 장치가 있으면 실제 지형·적 카메라 렌더도 검사한다. 전 구간 양방향 수동 완주와 화면·전투 난도 피드백은 이 검사와 구별한다.

격리 복사본·로그·화면·빌드는 outputs에만 둔다. Windows 패키지의 깊은 경로 때문에 검증용 경로를 짧게 유지한다. 실제 게임 폴더와 검증 사본을 혼동하지 않는다. 기존 사용자 파일·Unity 메타·미추적 에셋을 초기화하지 않는다.


## 일반 몬스터 승인 아트와 피격

`Chapter2World`는 일반 몬스터 생성 직후 `Chapter2MonsterArt.Apply`로 [표시 바인딩](../../../../data/presentation/stage2_monster_unity_bindings.json)을 적용한다. 일반 5종은 등짐분사수 K4, 쐐기보행기 B3, 먹침필경사 M3, 신호투척수 R-selected, 늘어진 수의 H3다. 기존 1챕터 장면의 표시에는 적용하지 않는다. 엘리트와 보스는 기존 표시를 유지한다.

피격은 사용자 선택 단일 자세를 종별 승인 팔레트와 이진 알파로 정리한 PNG다. 전체 모션은512×384 캔버스, PPU32, Point, 무압축·밉맵 없음, FullRect, 피벗320,124(Unity 하단 기준)을 공유한다. 기존 `Stage1MonsterPlayer`가 있는 개체는 기존 피격/경직 상태를 계속 사용하며, 프로토타입 두 종은 `Chapter2PrototypeArt`가 실제 수락 피격 횟수와 전투 시계로150ms 피격 표시 후 복귀한다. 점멸·검 접촉광은 공통 `Chapter1HitFeedback`과 기존 타격감 설정을 사용한다. 원본 Sprite 크기를 상태별로 자동 맞추지 않는다.

미디어는 resources의 `monsters/stage-02/normal-approved/runtime/unity`, Unity 선택은 공통 `docs/assets/manifests/unity-deployment.json`을 따른다. `Chapter2MonsterArtImporter`가 이미지 설정을 적용하며 로딩/시간표는 `Chapter2MonsterArt.json`을 사용한다. 일반5종은 `Chapter2NormalEnemy`가 승인 모션과 전용 공격 시간을 함께 소유한다. 편집 원본은 `data/combat/stage2_*.json`이며 `python tools/combat/export_chapter2_approved_normals.py`로 확정 수치·판정·시간표와 재생 카탈로그를 생성한다. 기존 `export_chapter2_normal_attacks.py` 진입점도 같은 생성기에 연결한다. 원본 프레임 바인딩은 `data/combat/presentation/chapter2_approved_motion_bindings.json`이며 HP·피해량·피격 크기는 [일반5종 확정 명세](../../../design/enemies/chapter2/normal/stage2-waterway-monsters.md)를 따른다. 사망은 별도 그림 대신 각 종 승인 대기 첫 프레임의 80ms 마무리 표시와 1챕터 공통 `HitFeedbackBridge` 물리 파편을 사용한다. `HitFeedbackAssetBuilder`가 같은 설정으로 5종의 파편 캐시를 생성하고, 기존 캐시에 2챕터 본체가 없거나 오래되면 편집기 가드가 다시 생성한다. 예전 몬스터 사망 그림은 재사용하지 않는다.

## A3 전용 엘리트

기존 E방의 `E:elite`는 HP 1,200(`data/combat/chapter2_elite.json`의 `hp`)의 `Chapter2EliteEnemy`로 생성한다. E방 첫 진입 뒤에는 챕터 전체로 추격하며 다른 방에서 처치해도 E방 섬멸·엘리트 보상으로 한 번 정산한다. 일반 적은 방을 벗어나도 멈추지 않으며 보스방 진입 시에만 공격을 멈춘다. 다만 발견(「!」과 추적 시작)은 그 적이 화면 안에 있고, 플레이어가 그 적의 소유 방(`Layout.RoomAt`) 안에 있으며, 감지 거리·높이 안에서 벽·발판에 가리지 않을 때만 한다(`Chapter2NormalEnemy.Detects`). 연쇄 경보도 플레이어가 받는 적의 소유 방에 있을 때만 받는다(`EnemyAlert.Receives`). 발견 전의 근접 이동형은 다가가거나 경로를 찾지 않는다. 화면 밖 적은 제자리에 있다가 화면에 들어와 플레이어를 보면 쫓기 시작하고, 쫓다가 화면 밖에 오래 있으면 기존 추적 규칙대로 포기하고 돌아간다. 예전에는 맵의 모든 적이 시작과 함께 발견해 길 찾기·포기·재발견을 반복했고, 적 144마리 맵에서 전투 틱 하나가 14ms 가까이 걸려 렉이 났다(2026-11-13). 공격 3종·최신 시간표·피격 면역·데이터 생성·통합 검사와 승인 아트 범위는 [A3 본 게임 연결](../enemies/chapter2-elite.md)을 따른다.


일반 공격의 전조·활성·회복·재공격 대기는 [공격 시간](../../../design/enemies/chapter2/normal/stage2-monster-attack-timing.md)과 [Unity 연결](../../testing/stage2-unity-validation.md)을 따른다. 분사는 전조650ms 후650ms 동안 최대3회, 먹침필경사는570–640/720–790/870–940ms에만 3연타 판정을 낸다. 쐐기보행기는600ms 전조 후12u/s로 최대6u 돌진하며 최초 접촉1회와 끌기를 적용한다. 벽·낭떠러지·끌리는 플레이어의 지형 막힘에 정지하면 끌기를 해제하고450ms 찍기 전조·150ms 판정·900ms 회복으로 이어진다. 준비·회복·파편에는 새 접촉 피해가 없다.

원거리2종은 발사 직전 플레이어 위치와 그 아래 가장 가까운 목표 바닥을 고정한다. 신호투척수는650ms에 발사하고700ms 회복하며, 수의는1600ms에 발사하고900ms 회복한다. 비행은 본체 회복과 독립이고, 탄은 벽·천장·다른 바닥을 통과하며 목표 바닥에만 충돌한다. 탄속·곡선·직격·장판은 [투사체 규칙](../../../design/enemies/chapter2/normal/stage2-projectiles.md)을 따른다. 수의 장판은121×15px·4초이며 생성0.5초 후부터 착지한 플레이어에게 피해를 준다. 여러 수의 장판을 합쳐 플레이어당0.5초에 최대1회·3피해다.

각 공격은 arena 시뮬레이션 시간으로 재생하며 정지 시 모션·탄도·피해가 함께 멈춘다. 일반 피격은 본체 공격을 취소하지만 수의는 비치명 피격에도 공격 시계를 유지한다. 이미 발사한 탄·장판은 본체 회복과 분리하며, 투척수 탄은 본체 사망 후에도 유지하고 수의의 공·장판은 수의 사망 시 제거한다. 보스방 진입·리셋은 독립 효과까지 정리하고 방 경계 전환·단순 화면 이탈은 발사탄을 취소하지 않는다. 배치 바닥 구역 내 이동·첫 공격 대기·높이·화면 조건은 [공격 참여 조건](../../../design/enemies/chapter2/normal/stage2-monster-engagement.md)을 따른다. 승인 효과 원본은 `monsters/stage-02/attack-fx-selected`, 엘리트 원본은 `monsters/stage-02/elite/stone-fist`다. 맷돌은1챕터의 원본8장/320ms 회전과 기존 돌진 판정을 유지하며, 최종 LateUpdate에도 회전 그림을 확정한다.
