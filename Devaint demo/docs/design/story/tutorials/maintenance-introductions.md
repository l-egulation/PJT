# 챕터별 정비소 첫 만남과 포탈 안내

[분야 개요](README.md)

## 범위와 상태

사용자 요청에 따른 연출 구성안이다. 각 챕터의 정비소 최초 방문에 검은 띠와 자동 접근을 넣고, 주인공은 대사를 하지 않는다. 1챕터는 정비소·포탈 안내, 2챕터는 다른 상인과의 짧은 첫 만남으로 구분한다. 공간은 벽감 정비소를 유지하고 상인과 작업대 외형을 다르게 만든다. 각 챕터 정비소 방의 중앙에 채택된 뒤 구조물·상인·작업대를 함께 배치한다. 시설을 방마다 임의의 벽 끝에 붙이지 않는다.

채택 에셋·첫 방문 대사·물리 이동 접근·말풍선·실제 정비 UI 연결을 Unity에 적용한다. 편집 원본은 `data/story/maintenance_introductions.json`, Unity 로딩 사본은 `Assets/Deviant/Game/Resources/MaintenanceShops/MaintenanceDialogue.json`이다. 두 파일은 `python tools/story/export_maintenance_dialogue.py`로 동기화하며 새 대사에 필요한 Bold 정적 폰트 글자도 함께 추가한다. 공통 `tools/temporary-gui-preview/update-font-glyphs.py` 재생성 역시 이 대사 원본을 포함한다. 상인은 포탈 기능을 짧게 소개하고 작별 인사로 마친다. 이후 포탈 수첩에서 `{CheckpointInstall}`·`{CheckpointReturn}`·`{Interact}`를 표시 시점의 장치·바인딩으로 해석한다. 수첩을 읽는 중 장치를 바꿔도 현재 버튼 이름을 보여 준다. 검은 띠는 현재 즉시 표시하며 별도 카메라 확대·이동은 추가하지 않는다. 아래의 손짓·고개 동작과 포탈 실습 성공 안내는 의도 설명이며, 현재 모션은 몸통 호흡·간판 흔들림·등불 점멸이다. 이 문서는 화자·대사·동작·전환 시점을 지정한다. 정비 기능은 [성장·경제](../../run/progression-and-economy.md), C/V의 현재 동작은 [수동 체크포인트](../../run/run-structure.md#수동-체크포인트포탈), 세계관은 [초반 이야기](../opening/opening.md)를 따른다.

## 인물과 작업대

| 항목 | 1챕터 마을 장인 | 2챕터 수로 정비공 |
|---|---|---|
| 인상 | 살갑고 말이 많다. 처음 만난 아이를 걱정하며 먼저 말을 건다. | 무뚝뚝하고 귀찮아한다. 말은 짧지만 필요한 물건은 챙겨 준다. |
| 실루엣 | 둥글고 든든한 검은 잉크 몸, 초승달처럼 갈라진 밝은 뿔·가면, 작은 세로 금색 눈 | 넓고 낮은 남색 잉크 도롱뇽 몸, 양옆 아가미, 굵은 꼬리와 반쯤 감긴 금색 눈 |
| 재질·소품 | 크림색 가면, 황토색 작업 앞치마·주머니, 잉크가 묻은 천 | 크림·회녹색 아가미와 목, 올리브색 앞치마·주머니, 탁한 자주색 천 |
| 기본 동작 | 천 닦기 → 몸통을 기울이기 → 잉크 손을 펴서 반기기 | 턱 아래를 손으로 받치기 → 눈만 들기 → 병을 밀어 주기 → 다시 늘어지기 |
| 작업대 | 나무 서랍장과 튼튼한 목재 다리, 작은 수동 압착기, 천과 잉크병 | 짙은 나무 상판, 철제 모서리, 배관·플랜지 다리, 부품 서랍과 바이스 |
| 환경 처리 | 건물·작업대는 따뜻한 종이색과 연필선·빗금. 인물은 컬러를 유지하되 뿔·가면까지 전부 외곽선 없이 색 면·명암으로 표현 | 무광 청회색·녹회색 석재와 낮은 채도의 금속. NPC 아가미·앞치마과 배경 구조물 모두 검은 외곽선을 추가하지 않음 |
| 공통 표식 | 팔레트 간판, 잉크병 3개 안팎, 작은 등불 | 같은 팔레트 간판으로 정비소임을 인식. 간판 재질과 낡음은 구분 |

둘은 서로 다른 지역 상인이며 인간 얼굴·코·입·머리카락 대신 잉크·종이·눈·자세로 성격을 표현한다. 외형 선택은 C안의 1상인(둥근 가면 장인)과 A안 오른쪽의 2상인(졸린 도롱뇽 정비공)이며, NPC 윤곽선을 제거한 표현과 정비소 디자인은 채택했으며, 게임의 정비소 방 중앙에 배치한다. 같은 NPC의 복장 교체나 주인공 후드의 복제 인물로 만들지 않는다. 검은 잉크 몸 자체의 면은 유지하며 검은 테두리와 구분한다. NPC PNG는 작업대·간판·배경과 분리하고 대화용 포즈·모션은 별도 제작한다. 새로운 종족·탄생 규칙, 인물의 이름·두 상인의 관계·삭제 사건에 대한 상세 지식은 확정하지 않는다. 정비공을 대서적의 기록 작성자나 주인공을 되살린 조력자로 설명하지 않는다.

## 공통 첫 진입 연출

| 순서 | 화면·동작 | 제어와 완료 조건 |
|---|---|---|
| 1. 진입 감지 | 정비소 입구를 지나 내부의 안전한 접지 지점에 도착한다. | 챕터별 미열람 상태이고 살아 있으며 다른 대화·메뉴·연출이 없을 때만 시작한다. 공중 진입은 착지 뒤 처리한다. |
| 2. 프레이밍 | 검은 띠가 약 0.3초에 걸쳐 들어오고 일반 상호작용 표시를 숨긴다. | 기준 화면 960×540에서 상·하 약 32px 제안. 띠는 플레이어가 보는 게임 화면의 맨 위·맨 아래 가장자리에 붙인다(창 크기에 맞춘 정수배 표시 영역 기준). 인물 발·작업대·말풍선 앵커를 가리지 않게 최종 말풍선과 조정한다. |
| 3. 접근 | 주인공이 상인 앞으로 약 1~2초 달려가 멈추고 상인을 바라본다. | 접근 구간은 점프·낭떠러지 없는 짧은 평지. 실제 충돌·발 위치와 그림이 함께 이동해야 한다. 반대편 입구에서는 동선을 반전한다. 이미 앞이면 달리기를 생략한다. |
| 4. 첫 대화 | 상인이 말을 건다. 주인공은 시선·잠깐 멈춤·가벼운 고개 동작으로만 반응한다. | 주인공 이름의 대사나 `…` 말풍선도 만들지 않는다. 대사는 줄별 진행이며 무응답 동작은 대화 사이의 짧은 연기다. |
| 5. 기능으로 전환 | 마지막 안내 뒤 정비 화면으로 연결한다. | 대화와 정비 UI가 동시에 입력을 받지 않도록 소유권을 넘긴다. 검은 띠는 정비 화면을 열기 전에 걷는다. |
| 6. 일반 이용 | 이후 재방문은 F로 정비 화면에 바로 접근한다. | 재방문마다 달리기·검은 띠·긴 인사를 반복하지 않는다. 짧은 반복 대사는 있어도 조작을 뺏지 않는 방향이다. |

보스처럼 화면을 정돈하는 연출이지만 보스 등장음·경고·전투 잠금·화면 흔들림을 추가하지 않는다. 현재 승인된 점프 중 세로 카메라 고정을 유지하고, 대화 내내 확대·상하 이동을 반복하지 않는다. 필요하면 진입 시 수평 구도만 한 번 부드럽게 맞춘다.

현재 `StageMove`는 물리 없는 연출 전용 Sprite 이동 계약이다. 정비소는 실제 플레이어 입력으로 접근하며 충돌·중력을 유지하고 착지 뒤 대화를 시작한다. 실제 플레이어 자동 접근을 그 기능 하나로 완료했다고 간주하지 않는다. 구현 시 안전 동선·정지점·도달 실패를 처리하는 실제 액터 제어 연결이 필요하다. 통로가 막혀 있으면 벽을 관통하거나 무기한 달리게 하지 않고 안전한 현재 위치에서 대화하거나 조작을 돌려준다.

## 1챕터 대화·안내 순서

따뜻한 관심에서 시작해 정비 기능을 보여 주고, 떠나려는 주인공을 다시 부르는 흐름이다. 대사는 초안이며 말풍선에서 긴 줄을 나눌 수 있다.

| ID | 화자·대사 초안 | 동작·다음 단계 |
|---|---|---|
| `m1.greet` | 상인: 「오, 너는 누구니? 못 보던 얼굴인데.」 | 닦던 병을 내려놓고 반긴다. |
| `m1.silent-look` | 대사 없음 | 주인공이 상인을 보고 멈춘다. |
| `m1.recognize` | 상인: 「스케치 사건에 휘말렸다고? 그런데 어떻게 살아 있는 거지?」 | 주변의 지워진 마을을 잠깐 본다. 주인공 신원을 이미 안다고 단정하지 않는다. |
| `m1.body` | 상인: 「그리고… 몸이 잉크구나? 흠… 평범한 인간은 아니군.」 | 주인공이 자기 손을 잠깐 내려다본다. |
| `m1.reassure` | 상인: 「말하기 싫으면 안 해도 돼. 일단 필요한 것부터 챙기자.」 | 답변을 강요하지 않고 작업대를 가리킨다. |
| `m1.maintenance` | 상인: 새 도면·런 도감·무기 잉크 적용 구조에 맞춘 시설 안내 대사 미정 | 병·팔레트 표식·도구 쪽을 차례로 가리킨다. |
| `m1.growth` | 상인: 「강화도 할 수 있단다. 하나씩 살펴보렴.」 | 검은 띠를 걷고 조작을 돌려준다. 방 안의 상품을 바로 둘러볼 수 있다(상점 창 없음, 2026-11-14). |
| `m1.service-preview` | 상인 대사 없음 | 기능을 아래의 세 묶음으로 안내한다. 구매를 요구하지 않는다. |
| `m1.call-back` | 상인: 「얘야, 잠깐만!」 | 조작을 돌려준 지 0.35초 이상 지난 뒤, 주인공이 상점 구역(장인 4.5unit 안쪽부터 진열 끝 0.75unit 바깥까지, 발판 위 1.5unit 아래)을 벗어난 접지 상태에서 다시 부른다. 상품을 둘러보는 동안에는 부르지 않는다. 상점 창을 쓰는 옛 성장 경로는 창을 닫은 지 0.35초 이상 지난 뒤, 닫았던 자리에서 수평으로 1.5unit 이상 이동하고 상인과의 거리가 1.25unit 이상 늘어난 접지 상태에서 부른다. 제자리 대기·카운터 쪽 접근에는 시작하지 않는다. 안내 중 화면을 닫는 행위와 전체 연출 스킵은 구분한다. |
| `m1.portal-question` | 상인: 「너, 포탈을 쓸 줄은 아니?」 | 떠나는 주인공에게 사용법을 아는지 묻는다. 주인공 대사나 응답 선택지는 추가하지 않는다. |
| `m1.portal-notice` | 상인: 「포탈 두 개를 세워 두면 두 곳을 자유롭게 오갈 수 있단다.」 | 포탈의 용도만 짧게 설명한다. |
| `m1.portal-guide` | 상인: 「그럼 다음에 또 보자!」 | 상인은 인사로 대화를 마친다. 대화 직후 게임의 포탈 수첩을 열어 조작 설명을 그림과 키캡으로 전달한다. |

### 마을에서 먼저 만난 경우

첫 런에서 1챕터 정비소에 닿기 전에 쓰러지면 마을 첫 귀환에서 장인을 먼저 만난다(「나 마을 밖에서 정비소 하거든. 지나가다 들러!」, [플레이형 오프닝](../opening/opening-playable.md)). 그 뒤 정비소에 처음 들어오면 위 10줄 대신 8줄을 쓴다(2026-11-09 사용자 결정). 처음 만남을 전제로 한 `m1.greet`, `m1.recognize`, `m1.body`, `m1.reassure` 네 줄 대신 아래 두 줄로 맞이하고, `m1.maintenance`부터는 위 표와 같다.

| ID | 화자·대사 | 동작·다음 단계 |
|---|---|---|
| `m1.village-greet` | 상인: 「오, 정말 왔구나! 우물가에서 본 그 손님이네.」 | 닦던 병을 내려놓고 반긴다. |
| `m1.village-praise` | 상인: 「여기까지 오다니 대단한걸?」 | 이어서 `m1.maintenance`로 간다. |

판정은 프로필의 마을 첫 귀환 기록(`artisan-first-run`)이다. 대사 원본은 `data/story/maintenance_introductions.json`의 `firstAfterVillage`이며, 두 판 모두 끝에서 다섯 번째 줄(「강화도 할 수 있단다…」)에서 조작을 돌려준다.

기존 대화 표의 ‘정비소’는 해당 장면과 대사에서 쓰던 명칭이다. 새 시설의 화면 표기는 **상점**이다. 도입 대사를 갱신할 때 다음 규칙을 따른다.

- 상인은 골드로 무기와 잉크를 판매한다. 상품과 품절 처리는 [상점 규칙](../../run/rewards.md)을 따른다.
- 무기 확정과 잉크 부여는 인벤토리에서 무료로 진행한다.

상세 비용·가능 여부는 실제 정비 서비스의 값을 표시한다. 기능 소개를 위해 구매를 강제하거나 돈·아이템을 지급하거나 장착 상태를 임의로 바꾸지 않는다. 골드가 없어도 안내를 끝내고 떠날 수 있어야 한다.

## 포탈 사용법 수첩

1챕터 정비소의 짧은 포탈 소개가 끝나면 수첩을 바로 연다. 공격·보상·조작 안내와 같은 어두운 바탕과 모서리가 깎인 픽셀 테두리 창을 쓴다. 제목은 하이라이트 없이 중앙 상단에 두고, 하단에는 현재 상호작용 키와 닫기 버튼을 둔다. 글꼴은 튜토리얼 전용 Galmuri11 12px와 정수 화면 배율을 사용한다. 보스 처치나 마을 귀환을 기다리는 안내가 아니다.

- 위에는 C, V, F 키캡만 표시한다. 현재 시연 중인 키를 강조한다.
- 왼쪽 C 설치 → 오른쪽 V 설치 → 오른쪽에서 왼쪽으로 진입·등장 → 왼쪽에서 오른쪽으로 왕복하는 시연을 반복한다.
- 시연은 게임에서 쓰는 `ApprovedTraversal` 설치·포탈·걷기 진입·등장 스프라이트 프레임과 `ManualCheckpoint` 재생 데이터를 재사용한다. 생성 삽화는 표시하지 않는다. 원본 프레임을 자르거나 변형하지 않고 1배 크기로 그린다. 설치 위치의 간격과 진입·등장 이동 거리도 같은 비율로 맞춘다.
- 좌우 시연의 중심 간격은 220px로 두고 키캡도 각 중심에 맞춘다. 캐릭터는 원본 스프라이트 색과 투명도를 유지하고 별도 외곽선을 덧붙이지 않는다.
- 설명은 스프라이트 아래에 1번(C)과 2번(V) 설치, 같은 키로 현재 위치에 재설치, 가까이에서 F 왕복, 지도에서 각 포탈의 위치 확인 순서로 모은다.
- 키캡과 설명은 현재 입력 설정을 읽으므로 키를 바꾸거나 게임패드를 쓰면 해당 표시로 갱신한다.
- 시연은 수첩의 시간으로 재생한다. 실제 캐릭터·포탈 상태를 바꾸지 않으며 시뮬레이션 정지 중에도 계속 움직인다.

수첩을 읽는 동안 시뮬레이션과 이동·전투·월드 상호작용을 막는다. F/진행/뒤로 입력 또는 확인 클릭으로 닫고 해당 연출의 제어권만 반환한다. 대화 진행에 쓰인 입력으로 즉시 닫히지 않도록 0.35초 동안 입력을 받지 않는다. 대화를 Esc로 생략해도 수첩 안내는 표시하며, 수첩을 닫으면 포탈 조작을 해금한다. 설치·왕복은 자동 실행하지 않고 실습 성공으로 기록하지 않는다.

C와 V를 다시 누르면 해당 포탈만 현재 위치로 옮긴다. 두 포탈을 설치한 뒤 가까이에서 F로 반대편으로 이동한다. 기존 포탈 상태, HP, 장비, 적 상태를 수첩 표시 때문에 초기화하지 않는다. 사망·씬 종료·연출 취소는 수첩 완료로 처리하지 않는다. 2챕터에서는 이 안내를 반복하지 않는다.

## 2챕터 첫 만남 — 짧은 버전

1챕터와 동일하게 최초 한 번 검은 띠·짧은 접근을 사용한다. 상인은 턱 아래를 손으로 받친 채 몸을 거의 움직이지 않고 눈만 들어 본다. 정비소 기능과 포탈 사용법의 긴 재교육은 반복하지 않는다.

| ID | 화자·대사 초안 | 동작·다음 단계 |
|---|---|---|
| `m2.greet` | 상인: 「뭐야, 넌 누구냐?」 | 턱 아래를 받친 채 눈만 올린다. |
| `m2.silence` | 대사 없음 | 주인공은 말없이 작업대와 상인을 본다. |
| `m2.guess` | 상인: 「…정비하러 왔냐. 쓰는 법은 알지?」 | 플레이어 답변이나 선택지를 만들지 않고 병을 밀어 준다. |
| `m2.service` | 상인: 「그럼 빨리 필요한 거 챙겨. 나 쉬게.」 | 검은 띠를 걷고 조작을 돌려준다. 방 안의 상품을 둘러본다. |

대화만 약 6~10초를 목표로 하고 자동 읽기 속도를 강제하지 않는다. 1챕터 안내를 건너뛰었거나 개발 메뉴로 2챕터에 바로 들어온 경우에는 UI 안의 간단한 사용 안내를 볼 수 있게 한다. 상인의 첫 만남 대사를 늘리거나 이미 체험한 것으로 허위 기록하지 않는다. 두 상인의 영업 기능은 같은 서비스이며 퉁명스러운 태도를 가격 불이익·기능 제한으로 바꾸지 않는다.

## 최초 기록·스킵 제안

- 챕터별 첫 만남은 프로필의 스토리 열람 기록 `maintenance-intro-chapter1`·`maintenance-intro-chapter2`로 따로 저장한다. **실제 런(RunSession)에서는 프로필당 챕터마다 최초 한 번**만 재생하고, 이후 런에서는 첫 만남 대화·검은 띠·1챕터 포탈 호출(`m1.call-back`~`m1.portal-guide`)을 모두 생략하고 F 정비소 이용만 남긴다. 첫 대화를 끝내고 정비 화면으로 넘어간 시점, 또는 Esc 전체 스킵으로 기록한다. 그 전에 사망·씬 종료로 취소되면 기록하지 않는다. RunSession이 없는 단독 시험 씬은 프로필을 쓰지 않고 해당 씬 생명주기 동안 한 번이다. PlayerPrefs 저장은 추가하지 않는다.
- 포탈은 `portal_hint_seen`과 실제 설치·귀환 성공 기록을 분리한다. 대화 완료·스킵을 실제 실습 성공으로 취급하지 않는다.
- 정상 첫 만남 완료 또는 명시적인 전체 스킵일 때 해당 첫 만남의 재생 억제 상태를 갱신하는 제안이다. 씬 종료·사망·오류·앱 종료는 완료와 구분한다.
- 1챕터 대화 생략 시 검은 띠와 말풍선을 숨기고 포탈 수첩으로 연결한다. 수첩을 닫으면 해당 연출의 입력 잠금과 시간 정지를 반환한다. 생략을 이유로 구매·강화·포탈 설치·왕복을 실행하지 않는다.
- 1챕터 상점 구역을 벗어나 떠나려 하면 `m1.call-back`으로 이어지고, 2챕터에는 이 포탈 후속 대화를 넣지 않는다. 연출 취소와 일반 UI 닫기를 같은 신호로 취급하지 않는다.

## 말풍선 작업 전달 계약

말풍선 작업은 이 문서의 줄 ID를 사용하되 아래 정보만 받아 표시하도록 한다. HTML은 Galmuri11 Bold12px, 폭184px, 2px 테두리와 화자 이름표, 30자/초 출력 및 Space/F/Enter 진행을 사용한다. 현재 Unity에는 동일한 표시 규격과 상인별 합성 글자 효과음이 연결되어 있다.

| 전달값 | 용도 |
|---|---|
| `lineId`, `speakerId`, `text` | 대사 식별과 화자 표시. 화자는 `merchant_village` 또는 `merchant_waterway`. |
| `speakerAnchor`, `focusAnchor` | NPC 머리 위 표시와 카메라 구도 기준. 생성 맵에서 실제 배치한 앵커를 사용한다. |
| `gesture` | `welcome`, `look_hand`, `point_bench`, `call_back`, `bored_glance`, `slide_jar` 등의 동작 의도. 실제 모션 에셋 유무와 구분한다. |
| `onLineFinished` | 다음 줄·동작으로 넘어가는 신호. UI 클릭 자체가 제품 상태를 직접 바꾸지 않는다. |
| `onSequenceSkipped`, `onSequenceCancelled` | 의도적인 스킵과 실패·종료를 구분하고 늦게 도착한 UI 응답이 이전 연출을 다시 진행하지 않게 한다. |
| `onServiceClosed` | 실제 정비 화면 종료. 1챕터의 호출 대사로 이어지는 지점. |
| `onPortalPlaced`, `onPortalReturnCompleted` | 실제 포탈 서비스의 성공 신호. 말풍선 뷰가 성공을 대신 판단하지 않는다. |

검은 띠와 대화·정비 화면이 각각 얻은 제어 범위만 반환해야 한다. 첫 만남 종료가 일시정지·다른 메뉴의 제어까지 해제하지 않는다. 실제 동작 연결 시에는 [시퀀스 계약](../../../development/presentation/narrative/sequence-execution.md)과 [NPC·대화 계약](../../../development/presentation/narrative/narrative-dialogue.md)의 완료·스킵·취소 구분을 따른다.
