# 화면 포커스·뒤로가기 소유권 범위

[분야 개요](README.md)

[GUI 목표](../../architecture/presentation-narrative-ui.md#5-gui와-공통-제어)에 따라 호출자가 주입한 포커스 가능한 View·명시적 우선순위/입력/정지/뒤로가기 정책을 일반 C# `ScreenRouter`와 uGUI `ScreenView`에 연결한다. 격리 화면 fixture와 실제 Game HUD가 같은 라우터를 사용한다. HUD는 기존 cancel 액션 매핑을 유지하며 다른 제품 화면/대화 전체 등록이나 새 키 정책을 자동 확정하지 않는다.

## 계약과 소유권

`UI/Contracts`의 `IScreenView`는 가용성·포커스 적용 가능 여부, 실행별 바인딩, 포커스 적용/해제와 View 입력을 제공한다. `IScreenHandle`은 새 바인딩 ID와 `Open`/`Closed`/`Failed`, 종료 이유/오류를 제공한다. 같은 View를 한 라우터가 동시에 두 번 소유할 수 없고 이름이 같은 다른 View는 독립된 소유자다. 종료된 핸들·옛 입력·옛 View 해제는 새 바인딩을 닫지 않는다.

`ScreenPolicy`는 우선순위·제한 채널·시뮬레이션 정지·뒤로가기 허용을 각각 받는다. 라우터는 View 바인딩 뒤 자기 `IControlScope`만 얻고, 바인딩 중 닫힘/소유자 종료를 받으면 새 제어 요청을 얻지 않는다. 부분 획득 실패나 정리 예외에서도 나머지 View/구독/제어 반환을 시도한다. 다른 HUD·대화·모달의 요청은 유지한다. View는 전투 상태나 `Time.timeScale`을 쓰지 않는다.

포커스는 열린 요청의 우선순위, 동률이면 최근 요청 순번으로 선택한다. 부모/자식은 화면 요청 순서의 관계이며 별도의 제품 레이어/전환 규칙이 아니다. 뒤 화면은 포커스를 놓고, 위 화면이 닫히면 남은 현재 요청에 다시 포커스를 준다. 최초 화면을 열기 전의 기준 포커스 반환은 라우터가 하나만 보관하고 모든 화면이 닫힐 때 한 번 반환한다. 마지막 화면의 개별 이전 선택만 복원해 이미 닫힌 부모로 돌아가거나 기준 선택을 잃지 않는다.

## 뒤로가기와 입력 소비

입력 조립은 물리 입력 edge 하나에 대해 `FocusedBindingId`를 한 번 읽어 `Back(expectedBinding)`에 전달하고 `Consumed`를 확인한 뒤 뒤 화면/HUD/게임으로 전달해야 한다. 같은 edge를 닫힘 뒤 새 포커스 ID로 다시 요청하지 않는다. 입력 장치 매핑은 호출자가 제공하며 라우터는 ESC/패드 버튼을 직접 읽지 않는다.

`UI/Unity/ScreenInputBinding.Configure`는 기존 라우터와 외부에서 소유하는 Input System Button 액션을 주입받는다. 키보드/패드 바인딩·활성화는 조립이 지정하며 어댑터가 Enable/Disable하거나 제품 키를 고르지 않는다. performed 한 번에 현재 포커스 토큰을 먼저 캡처해 Back을 한 번 호출하고 `LastResult`/`BackProcessed`로 소비 결과를 반환한다. 재바인딩/비활성/파괴는 자기 구독 세대를 무효화해 같은 액션 콜백 열의 옛 delivery가 새 화면을 닫지 못한다. 소비한 edge를 뒤 화면/HUD/게임으로 다시 보내지 않는 최종 입력 조립은 호출자의 책임이다. 기본 HUD/대화의 제품 매핑은 자동 변경하지 않는다.

현재 화면의 유효한 토큰과 허용 정책만 화면을 닫는다. 허용되지 않은 뒤로가기, `Navigation` 채널 제한, 옛 비어 있지 않은 View 토큰과 아직 처리 중인 포커스 전환은 입력을 소비하면서 화면을 닫지 않는다. 열린 화면이 없는 새 입력(`Guid.Empty`)은 소비하지 않는다. 이 계약은 같은 화면 입력이 부모를 연달아 닫거나 뒤의 게임 입력으로 새는 것을 막는 연결 경계이며, 제품 전체의 확인/클릭 라우팅을 완성한 것은 아니다.

View의 비활성/닫힘 통지는 정책상의 사용자 Back과 구분한다. `Poll`은 View/제어 수명을 확인하고 보류된 포커스를 재평가한다. 포커스 콜백 중 닫힘/라우터 종료는 현재 작업 뒤 처리하며 새 화면 열기 등 상태 변경 재진입은 거부한다. 기준 포커스 반환 오류는 라우터의 `LastFocusError`와 해당 Back 결과에서 확인한다.

## uGUI View

`ScreenView.Configure`는 기존 패널·그 패널의 CanvasGroup·EventSystem·첫 Selectable·선택적 Back 버튼과 포커스 중 상호작용/Raycast 정책을 주입받는다. 화면 레이아웃/Canvas/EventSystem을 만들거나 제품 프리팹을 다시 쓰지 않는다. 현재 단위는 Selectable을 가진 포커스 가능한 화면이며 읽기 전용 안내/월드 힌트 등은 별도 범위다.

바인딩은 패널을 열되 포커스 전에는 CanvasGroup의 상호작용/Raycast를 막는다. 포커스를 받으면 주입 정책을 적용하고 기억한 유효 선택 또는 첫 선택에 EventSystem 포커스를 준다. 첫 선택이 화면 상태 때문에 비활성·상호작용 불가이면(예: 출발 준비에서 두 개를 고른 뒤 고르지 않은 첫 카드) 패널 안에서 지금 선택할 수 있는 첫 Selectable에 대신 포커스를 주며, 선택할 수 있는 것이 하나도 없을 때만 포커스 실패로 화면을 닫는다. 해제는 패널을 숨기고 바인딩 전에 있던 CanvasGroup 플래그를 반환한다. 뒤 화면의 Back 버튼 콜백은 입력을 보내지 않는다. 한 EventSystem의 화면들은 같은 라우터로 조율하고 독립적인 패널 수명을 제공해야 한다.

EventSystem이 선택 콜백을 실행 중이면 새 포커스 적용은 기다렸다가 다음 `Poll`에서 재평가한다. 기준 반환은 선택 트랜잭션 뒤 EventSystem의 코루틴으로 미룰 수 있다. 원래 대상이 파괴·비활성·상호작용 불가 상태면 선택하지 않고, 다른 유효한 선택이 이미 있으면 빼앗지 않는다. 재바인딩/종료 뒤 옛 반환이 새 선택을 덮어쓰지 않는다.

## 검증과 남은 범위

`ScreenRouterTests`는 순수 경계·우선순위/동률·중첩 제어·뒤로가기 소비·옛 토큰·부분 실패·View 수명·콜백 종료·기준 반환·정리 예외와 일시적인 포커스 트랜잭션을 검사한다. `ScreenFocusIntegrationTests`는 실제 CanvasGroup·버튼·EventSystem으로 기억한 선택/기준 선택 복귀·상호작용 불가 첫 선택의 대체 포커스·뒤 화면 버튼 거부·동일 Back 소비·동시 종료·옛 세대·선택 콜백 중 닫힘/파괴된 원래 선택을 검사한다. 실행 절차와 실제 화면 검증의 구분은 [검사 방법](../../testing/testing.md)을 따른다.

`ScreenInputBindingTests`는 실제 Play Mode의 합성 Keyboard/Gamepad와 주입 InputAction으로 포커스 한 화면만 닫기·유지 입력 비반복·Navigation 제한 시 소비/유지·화면 없음의 미소비 결과, 앞 콜백에서 재바인딩한 뒤 옛 입력 무효화와 외부 액션 활성 수명 보존을 확인한다. 장치 매핑 fixture는 제품 입력 정책이나 수동 가독성 검증을 뜻하지 않는다.

실제 Game HUD는 GameComposition이 주입한 라우터와 기존 InputSystemUIInputModule.cancel.action을 사용한다. ScreenInputBinding만 물리 Back을 처리하고 기존 액션 매핑/활성 수명을 변경하지 않는다. busy 가드 아래 재사용 snapshot으로 Poll/닫기 콜백 순서를 보존하며 용량 증가는 화면 열기 때만 발생한다. 정상 Poll은 매 프레임 배열/정렬을 만들지 않는다. 다른 제품 화면/대화 전체 등록·확인/포인터 전체 라우팅·재고/설정 콘텐츠·화면 비율/가독성·제품 빌드/수동 플레이는 후속 범위다. 현재 HUD 이행을 전체 GUI 완료로 표현하지 않는다.
