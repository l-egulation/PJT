# 메인 Git 객체 정리 대상과 실행 조건

[분야 개요](README.md)

이 문서는 **메인 이력 정리의 대상 계약과 승인 조건**이다. 과거 보류 원본은 콜드 아카이브에, 현재 음원·폰트·VFX·보스 PNG bytes·맵 편집기 내장 HTML 원본은 일반 resources에 보존한다. 현재 미디어의 원본 소유 위치·배치 계약 변경과 메인 Git 이력 말소·원격 교체·서버 cleanup은 별도 작업이며, 원본 이관만으로 이력 정리 완료를 뜻하지 않는다. 작업·검증 이력을 보관하는 보고서가 아니며, 기준 커밋이나 보존 조건이 바뀌면 목록을 갱신한다.

**현재 운영 상태:** 원격 main은 검토한 대상이 제거된 재작성 이력이며 활성 원격 브랜치는 main 하나다. 아래 객체·경로·용량 표는 원본 분석 스냅샷과 보존 근거이며, 다시 실행할 자동 삭제 목록이 아니다. 서버 내부 refs의 commit-map cleanup과 실제 공간 회수 확인은 별도 미완료 단계다. 추가 이력 변경에는 새로운 범위 승인·백업·기능 검증이 필요하다.

**이후 받기:** 이전 clone에서 pull/merge하거나 옛 브랜치를 push해 새 main에 합치지 않는다. 미커밋 작업과 기존 clone을 보존한 채 새 clone을 받고, 고정 resources를 복원해 개발을 재개한다. 필요한 미병합 변경은 보존본에서 기능별 패치로 검토·이행하며 옛 이력을 다시 유입하지 않는다.

실행 승인·작업 동결·선행 의존 해소·격리 필터·Unity 검증·원격 교체·서버 cleanup은 [GitLab 실행 이슈 #14](https://lab.ssafy.com/s15-final/S15P31F109/-/work_items/14)의 체크리스트로 추적한다. 계획 문서 게시를 실제 정리 완료로 취급하지 않는다.

**정리 범위:** 현재 사용하는 **음원·폰트·보유 VFX 원본도 `resources` 서브모듈의 필수 이관 대상**이다. 메인에 영구 유지하는 선택안으로 두지 않는다. 원본은 resources의 Git LFS로 관리하고, Unity 적용 경로·`.meta`·GUID·씬·프리팹·게임 연결은 메인이 소유한다. 이관 대상 확정은 개별 라이선스 확인이나 실제 업로드·삭제·이력 재작성 승인을 대신하지 않는다.

**권장 순서:** 구형 빌드 참조 의존 해소 → 원본의 외부 보존·필수 미디어 이관과 배치 도구 구현 → 원격 복원·Unity/편집기 검증 → 검토·승인된 메인 중복 이력 제거와 서버 cleanup. 단계적으로 진행할 수 있지만 **약 59MB는 현재 미디어 이관 전의 중간 단계이며 전체 작업의 완료 목표가 아니다.** 기존 분석의 현재 미디어 207개 전체를 이관한 모델은 **약 20~30MB**가 목표다. 음원·폰트·VFX 204개와 보스 bytes 1개·편집기 내장 HTML 2개 모두 일반 resources의 원본 보존 대상으로 등록한다. 원본 보존·복원과 전체 기능·품질·권리 검증은 구분하며, 어느 수치도 자동 삭제 승인이나 실제 서버 회수를 뜻하지 않는다.

## 범위와 판정 기준

- 메인 기준: `origin/main`의 `274f1fd337622a9de77ef77b378a79cce1472371`.
- 외부 보존 기준: `resources`의 `66ae206116cb6b7017636fdd18f901264d83612e`.
- 현재 음원·폰트·VFX 원본의 보존 기준은 별도 일반 resources 커밋 `df1c405713c7e826141afa253645b1a47960a3d6`과 `imports/main-media/mapping.json`이다. 원본 main `c9255ddf`의 WAV 170개·TTF 6개·VFX 텍스처 43개 경로(고유 blob 204개)를 등록하고 기존 분석의 해당 SHA256·바이트와 대조한다. 아래 pack 수치는 기존 분석 스냅샷의 비교값이며 이 커밋으로 재측정한 결과가 아니다.
- 보스 PNG bytes·현재/이전 지형용 맵 편집기 HTML 3개의 보존 기준은 일반 resources `24ac96781cbb67d99bd2d6f198b5b3940e93b059`과 `imports/main-boss-map-editor/mapping.json`이다. main `f13a4417`의 원본을 바이트 그대로 등록하며, 두 매핑을 합쳐 현재 미디어 207개 고유 blob·222개 메인 경로의 보존 근거를 연결한다. HTML의 텍스트 편집 원본·맵 데이터와 보스 Unity 메타데이터는 계속 메인이 소유한다.
- 콜드 아카이브: 별도 [archive/main-history-274f1fd3 브랜치](https://lab.ssafy.com/h0422ys/deviant-resources/-/tree/archive/main-history-274f1fd3)의 `18d998fde9d9b760ba69e8bc6ab562a1153e9cce`. 일반 리소스 `master`와 메인 gitlink는 그대로다. ZIP 원본 **341,453,131B**를 Git LFS로 보존하며 원본 2,032개/경로 별칭 2,675개를 포함한다.
- 로컬의 commit/tree/blob/tag 전체 **37,923개**, 그중 blob **24,335개**를 읽었다. 모든 commit의 root tree를 순회해 같은 blob의 과거 경로를 합쳤다. 경로 하나만 보고 다른 이름의 동일 객체를 놓치지 않는다.
- 이 목록은 바이너리 4,392개·내장 미디어 텍스트 165개와 관련 제작 원본/출력 경로의 텍스트 3,299개, 합계 **7,856개 blob·13,930개 과거 경로 별칭**을 다룬다. 모두 기준 main에서 도달 가능하다. 나머지 일반 소스/텍스트 메타데이터와 Git 구조 객체는 유지한다.
- 단순히 현재 경로나 정적 참조가 없다는 사실을 「불필요」의 근거로 삼지 않는다. 이전 보류 2,032개는 사용자 결정에 따라 하나의 ZIP으로 보존했으며 미사용·미술/라이선스 승인을 새로 확정한 것이 아니다. 앞으로 동일 바이트의 보존을 확인하지 못한 새 원본은 보류한다.
- 판정은 **메인 이력에서의 소유권**이다. 메인에서 제거한다고 외부 원본도 삭제하는 것은 아니다. 현재 `.meta`·GUID·씬·프리팹·shader·게임 데이터는 메인에 유지한다.
- 숨겨진 GitLab MR refs, 서버 전용 unreachable 객체, 포크·백업은 로컬 목록에 포함되지 않는다. 실제 말소 범위에는 관리자 확인이 추가로 필요하다. 서브모듈의 이력은 재작성 대상이 아니다.
- 실행 시 기준 main/외부 SHA와 이 목록의 일치를 먼저 확인한다. 다른 브랜치 소유자의 동의 없이 브랜치·태그를 삭제하거나 덮어쓰지 않는다.

## 용량과 단계별 목표

단위는 **십진 MB = B / 1,000,000**다. 원본 용량은 압축 해제한 고유 blob의 합이고, 현재 저장 용량은 Git의 기존 delta/압축 표현 크기 합이다. 후자는 개별 객체의 확정 회수량이 아니므로 최종 용량은 별도 pack으로 측정한다. 같은 SHA를 여러 경로의 용량으로 중복 합산하지 않는다.

| 분류 | 고유 blob | 원본 용량 | 현재 저장 표현 합 | 처리 |
|---|---:|---:|---:|---|
| 방향 1: 출력·구형 빌드 | 1,350 | 277.93MB | 267.44MB | 호출부 조건을 해결한 뒤 메인 이력에서 제거 |
| 방향 2: 보존·이관 | 4,557 | 574.19MB | 402.61MB | 일반 외부 보존 2,318개 + 아카이브 2,032개 + 현재 미디어 207개 모두 원본 보존 근거를 연결. 전체 기능·품질·권리 검증과 메인 이력 말소는 별도 |
| 유지: 공유 소스·메타데이터 | 1,949 | 24.88MB | 1.14MB | 구형 alias 경로만 제거 가능, 객체 SHA 말소 금지 |

### 메인 Git 객체의 단계별 예상

아래 pack은 **실제로 새로 압축한 pack+index의 바이트 크기**다. 원래 commit/tree를 유지하고 선택한 blob만 제외한 용량 비교용이므로, 이 자체는 체크아웃 가능한 재작성 저장소가 아니다. 실제 filter 후의 tree/commit 재작성, 새 코드/카탈로그/이 문서의 추가분, 서버 보존 refs와 GC 상황에 따라 최종 값은 달라진다.

| 단계 | 제외하는 고유 blob 누계 | 메인 pack+index | 선행 조건 |
|---|---:|---:|---|
| 현재 로컬 객체 디렉터리 | 0 | 약 723.53MB | loose·중복 pack·index 등 포함 |
| 같은 객체를 단일 pack으로 압축한 참고값 | 0 | **690.08MB** | 정리 실행이 아닌 비교값 |
| 방향 1까지 | 1,350 | **422.59MB** | 구형 ZIP을 읽는 검증 도구의 의존 먼저 해소 |
| 방향 1 + 일반 외부 보존 확인분 | 3,668 | **384.92MB** | 일반 외부 SHA/LFS 복원·기존 배치 검증 |
| 콜드 아카이브 보존 2,032개까지 활용 | 5,700 | **59.34MB** | 아카이브 ref/LFS 장기 보존 + 메인 필터/서버 cleanup. **미디어 이관 전 중간 단계**이며 음원·폰트·VFX 필수 이관은 미완료 |
| 현재 사용 미디어 207개 전체 이관 완료 모델 | 5,907 | **19.56MB** | 필수 음원·폰트·VFX 204개와 보스 bytes·편집기 내장 미디어 3개의 권리 확인·배치 어댑터 구현·복원/Unity 검증. 신규 파일 증가분을 고려한 목표는 **20~30MB** |

기존에 받아 둔 Git 객체·worktree index·LFS 캐시는 위 목록 작성으로 줄어들지 않는다. 이력 재작성 후에도 GitLab cleanup·보존 refs 처리·GC가 완료돼야 서버 공간이 실제 회수된다.

### resources와 두 프로젝트 전체 용량

아카이브 게시 전 분석의 GitLab 통계는 메인 Git **690.26MB**, 메인 첨부파일 **30.89MB**, resources Git **4.97MB** + LFS **303.63MB**, 합계 **1,029.76MB**다. 당시 콜드 ZIP **341.45MB**와 작은 아카이브 Git 메타데이터가 추가되는 모델을 사용했다. 이는 현재 서버 사용량이 아니다. main 재작성 후에도 내부 보존 refs·GC 유예·통계 갱신 때문에 서버 수치는 바로 줄지 않을 수 있다. 첨부파일은 Git blob 제거 대상이 아니며 그대로 남는다.

- 이미 보존된 2,318개는 새 미디어 업로드가 필요 없다.
- 기존 분석에서 현재 미디어 207개 전체를 이관할 때의 추가 LFS payload 상한은 **71.99MB**다. 해당 207개는 위 일반 resources 커밋들에 보존하므로 같은 원본을 다시 업로드하거나 이 용량을 재차 추가분으로 계산하지 않는다.
- 과거 원본 2,032개/428.00MB는 **단일 ZIP 341.45MB로 이미 보존**했다. ZIP 안팎의 SHA 목록에 원래 바이트와 경로를 유지한다. 일반 게임 체크아웃은 이 별도 브랜치의 ZIP을 받지 않는다.
- LFS 원본은 메인의 delta 압축률을 그대로 얻는다는 보장이 없다. 따라서 **메인의 크기가 줄어드는 것과 두 저장소 총량이 줄어드는 것은 다르다.**

| 가정 | 두 프로젝트 합계 근사 | 포함·제외 |
|---|---:|---|
| 메인 정리 전 | **약 1,371.21MB** | 기존 두 프로젝트 + 콜드 ZIP. 작은 새 아카이브 Git 메타데이터는 별도 |
| 미디어 이관 전 중간 단계 | **약 740.28MB** | 메인 59.34MB + 기존 resources + 콜드 ZIP + 메인 첨부파일. 필수 미디어 이관의 완료값이 아님 |
| 현재 미디어 207개 전체 이관 모델 | **최대 약 772.50MB** | 메인 19.56MB + 위 보존분 + 신규 LFS payload 71.99MB. 메인은 더 작아도 총량은 늘 수 있음 |

두 프로젝트 근사값에는 **새 LFS pointer·색인·어댑터·문서 Git 객체 증가량**과 서버의 숨겨진 보존 객체를 넣지 않았다. 서버 실제 청구/디스크 수치의 보장값이 아니다. 19.56MB는 위 분석 스냅샷의 207개 전체 모델이며 204개만 처리한 단계나 최신 refs의 결과로 그대로 사용하지 않는다. 이관 원본의 추가 payload 상한도 당시 비교값이며, 원본 보존을 개별 라이선스·재배포 권리 확인이나 전체 기능 검증 완료로 간주하지 않는다.

## 1. 메인 이력에서 제거할 대상

전체 SHA·모든 과거 경로·원본 B·현재 저장 B는 [방향 1 전체 목록](git-object-cleanup-remove.md)에 있다.

| 묶음 | blob | 원본 / 현재 저장 | 어떻게 정리하는가 |
|---|---:|---:|---|
| 격리 검증 출력·사본 | 1,340 | 33.09 / 23.58MB | 제품 입력이 아닌 `outputs/`의 기록된 경로를 이력에서 제거. 현재 main에 남은 사본도 함께 추적 해제. canonical 소스와 SHA가 같으면 이 묶음이 아니라 유지 목록을 적용 |
| 기타 빌드 ZIP·동봉 안내 | 9 | 180.31 / 179.58MB | `Playtest/`의 세 구형 빌드 ZIP과 관련 안내 버전 제거. 배포 빌드를 resources의 제작 원본으로 옮기지 않음 |
| 구형 참조 빌드 ZIP | 1 | 64.53 / 64.27MB | `verify_combat_v2.ps1`은 지정 Unity Editor/원본 패키지로 실제 Editor/테스트와 Linux/Windows Player 스크립트를 컴파일한다. 이 호출부 검증과 refs·백업·승인 조건을 충족한 격리 정리에서만 제거 |

마지막 ZIP은 현재 파일 트리에 없고 검증 도구의 입력에서도 제외한다. [검증 안내](../testing/testing.md)의 실제 Unity 컴파일 경로를 확인한 뒤 이력 정리 대상으로 삼는다. `-RulesOnly`는 별도 순수 규칙 검사이며 실제 Editor/Player 타입 검사 완료로 기록하지 않는다.

`outputs/`는 원래 Git 제외 경로지만 이미 추적된 파일은 `.gitignore`로 자동 제거되지 않는다. 사본의 `.meta`와 원본 코드가 동일 SHA일 수 있으므로 디렉터리 경로 제거와 객체 SHA 제거를 구분한다. 로컬 출력·개인 백업 파일 자체는 삭제하지 않는다.

## 2. resources 보존·이관 후 제거할 대상

Unity 적용 사본·`.meta`·GUID·씬·프리팹·재질·셰이더·카탈로그는 계속 메인이 소유한다. resources 등록/커밋/push·독립 원격 복원·배치 검증 후 메인 payload 추적만 해제하고 로컬 파일·메타데이터는 보존한다. 이는 과거 이력 말소와 다르며 Unity 회귀·실제 청취·GUI/글리프·VFX 품질·개별 라이선스 검증을 대신하지 않는다. resources의 저장소 권한이 높다는 사실은 제3자 저작물 재배포 권리를 뜻하지 않는다.

현재 런타임 근거는 `ApprovedCombatAudio.cs`의 카탈로그 로딩, [음원 전달 명세](../presentation/audio/audio-production.md), `ClockExecutionerBoss.cs`의 `StationaryBytes` 로딩, [VFX 검증 안내](../testing/testing.md), [맵 편집기 안내](../../../tools/chapter1-map-editor/README.md)다. 동적 로딩이 있어 정적 GUID 미참조만으로 미사용 판정을 내리지 않는다.

리소스 등록은 원본·asset 목록·색인·해시·LFS를 함께 맞춘 뒤 **외부 커밋·push·원격 복원을 먼저** 완료하고, 메인의 배치 계약·어댑터·gitlink를 갱신한다. 공통 실행기는 PNG·지정 시계탑 환경/보스 `.bytes`·지정 오디오/폰트 경로의 WAV/OGG/MP3/FLAC·TTF/OTF와 정확히 두 맵 편집기 HTML 경로만 허용한다. Unity 목적지는 기존 `.meta`를 요구하며 임의 코드·문서 출력으로 허용 범위를 넓히지 않는다. 편집기 변환은 새 빈 검토 디렉터리만 사용하고 원본·소비자 사본을 덮어쓰지 않는다.

### 과거 원본 2,032개: 단일 ZIP으로 보존 완료

[아카이브 전체 목록](git-object-cleanup-archive.md)에 모든 SHA·경로·원본 크기·ZIP entry와 entry별 압축 크기를 남겼다. 현재 트리에는 없으며 원본 428.00MB/현재 메인 저장 표현 325.84MB다. 기존 외부 색인·추적 LFS 파일과 보존 ZIP 17개에서 동일 바이트를 찾지 못했던 대상 전부를 새 아카이브로 보존했다. 이름이 `v1`, `preview`, `legacy`라는 이유로 원본을 폐기한 것이 아니다.

- 아카이브 경로: `archives/main-history-274f1fd3/objects.zip`.
- ZIP SHA256: `dfb8e5e5a607455d78f3ba062f3ff02f30d7fecb8d9dfe8195adbad15a0c15de`.
- ZIP 안의 `objects/<SHA1>`와 `objects.json`은 같은 과거 경로의 다른 버전, 다른 경로의 동일 내용, 전체 원래 경로 별칭을 구분한다. 외부 `manifest.json`에는 ZIP 전체 해시와 객체별 SHA1/SHA256·바이트·압축 크기가 있다.
- 원격 브랜치를 새 `--depth 1` 체크아웃으로 받은 뒤 빈 LFS 캐시에서 이 ZIP 하나만 내려받아 전체 2,032개를 다시 검증했다. 아카이브 브랜치에는 자체 검증/단일 복구 도구와 색인을 함께 둔다.
- 일상적인 게임 리소스 받기에는 ZIP을 추가하지 않는다. 아카이브를 읽기 위해 현재 `resources` 체크아웃이나 게임 gitlink를 바꾸지 않는다. 필요할 때 별도 archive 체크아웃에서 객체 하나만 새 파일에 복구한다.

## 실행 순서와 검증 조건

1. **승인·작업 동결:** 실제 계정의 Maintainer 권한과 보호 `main`의 force push 허용 여부를 API로 확인한다. 과거 권한 기록이나 fast-forward push 성공을 실행 권한으로 간주하지 않는다. Maintainer와 이력 교체 범위·브랜치/태그·열린 MR·팀원 복구 절차·정지 시간을 합의하기 전에는 이력 재작성·원격 교체를 실행하지 않는다. 음원·폰트·VFX의 resources 이관은 필수 범위지만 개별 라이선스·재배포 권리 확인과 이력 재작성 승인은 별도로 충족해야 한다.
2. **대상 확정:** 기존 보류분은 아카이브 보존으로 처리했다. 새 미확정 항목은 유지하고 기준 SHA가 달라지면 파일·호출부·원본을 다시 조사한다. 임시 분석용 pack이나 이 JSON을 검토 없이 자동 삭제 명령의 입력으로 쓰지 않는다.
3. **복구 준비:** 승인된 범위의 저장소·refs·필요 LFS를 격리된 로컬 백업에 확보한다. 평소의 현재 체크아웃만 받는 절차와 구분하는 별도 승인 작업이다. Drive 공유용 export를 만들지 않으며 백업을 메인에 커밋하지 않는다.
4. **의존·이관 먼저:** 참조 ZIP 호출부를 고치고, 방향 2 원본을 보존/등록/검증한다. 음원·폰트·VFX 원본의 resources 등록과 WAV/TTF/VFX 배치·생성기 어댑터는 필수 작업이다. resources 커밋·push·독립 원격 복원을 먼저 확인하고 메인의 기준 문서·배치 계약·필요한 gitlink를 갱신한다. 변경된 배치 계약으로 깨끗한 격리 소비자에서 현재 파일만 받아 재구성하고 바이트·GUID·호출부를 검사한다. 원격에서 복원되지 않는 리소스 SHA를 메인에 기록하지 않는다.
5. **격리 이력 재작성:** 검토한 대상 refs에만 경로 필터와 blob 필터를 적용한다. 공유 SHA는 전역 제거하지 않는다. 텍스트 메타데이터·게임 SSOT·현재 소스의 의도하지 않은 손실과 외부 gitlink 변경이 없어야 한다. 원본 작업 트리와 기존 worktree를 reset/prune/GC로 정리하지 않는다.
6. **기능·복원 검증:** Unity **6000.6.5f1**·원본 패키지 버전으로 타이틀→시작 마을→랜덤 스테이지, GUI/글꼴·승인 오디오·VFX·보스·편집기·기존 회귀 검사·Player 빌드를 확인한다. 원본/카탈로그 검사는 실제 실행·청취·미술 승인과 구분한다. 여기서는 해당 Unity 검증을 수행하지 않았다.
7. **원격 교체·서버 정리:** 승인된 ref의 실제 tip을 다시 확인하고 동시 작업을 덮어쓰지 않는 lease 조건으로 교체한다. 다른 branch/tag·MR refs가 옛 blob을 잡고 있으면 용량이 안 줄어든다. Maintainer/관리자와 GitLab repository cleanup·보존 refs·GC를 처리한 후 서버 통계를 다시 확인한다. LFS·첨부·아티팩트·포크·백업은 별도 정책이며 자동 말소되지 않는다.

   GitLab 18.11의 commit-map cleanup은 **Settings → Repository → Repository maintenance**에서 object/commit-map 파일을 업로드하고 **Start cleanup**으로 실행한다. 사용자 직접 업로드가 필요한 환경에서는 이 단계를 CLI housekeeping 접수와 구분해 미완료로 남긴다. 새 main과 은퇴한 원격 refs에 대한 검토된 매핑만 사용하며 resources 저장소에는 적용하지 않는다. 완료 알림과 통계 갱신 후 실제 용량을 확인하고, 필요하면 관리자와 GC 유예 이후의 prune을 처리한다.
8. **팀원 갱신:** 협의한 재clone/새 checkout 절차로 옛 이력이 다시 push되지 않게 한다. 사용자의 미커밋 작업을 보존하고 완료되지 않은 보호·배치·라이선스 조건을 통과한 것으로 기록하지 않는다.

**완료 판정:** 현재 미디어 207개 원본의 resources 보존·독립 복원·Unity/편집기 검증과 메인 이력 정리의 완료를 구분한다. 59.34MB 중간 단계나 원본 이관만으로 전체 정리를 완료로 닫지 않는다. 20~30MB 전체 모델을 완료값으로 제시하려면 최신 refs 기준의 승인·재조사·재측정·기능 검증과 서버 cleanup 결과를 확인한다.

## 재생성과 알려진 제한

- 구조화 원본의 기준 커밋·refs·정확한 byte·SHA를 입력 계약으로 삼는다. 확인에는 `git cat-file --batch-all-objects --batch-check='%(objectname) %(objecttype) %(objectsize) %(objectsize:disk)'`, `git ls-tree -r -z <기준 SHA>`, `git rev-list --objects --all --reflog`를 사용한다. 전체 과거 별칭은 각 commit root tree를 중복 제거 순회해 수집하며 `rev-list --objects`의 대표 경로 하나만으로 대체하지 않는다.
- UTF-8/UTF-16/UTF-32 텍스트·바이너리와 실제 Base64 미디어를 내용으로 구분했다. 텍스트 확장자라도 내장 이미지가 있으면 후보이며, `.asset`/`.meta`라는 이름만으로 지우지 않는다. 모든 후보의 원본 SHA256을 계산하고 외부 동일 바이트를 대조했다. ZIP 보존 검사는 후보와 크기가 같은 entry와 중첩 ZIP을 읽어 SHA256을 비교했다.
- 각 시나리오는 제외할 blob 집합을 달리하여 임시 `git pack-objects --stdout --delta-base-offset --threads=2 --window=10 --depth=50`로 압축하고 `git index-pack --index-version=2`로 확인한 pack+index 값이다. 실제 commit/tree를 필터한 기능 저장소가 아니므로 사용 가능한 저장소로 clone하지 않는다. 원본 저장소의 refs·이력·에셋 내용은 변경하지 않았다.
- 새 adapter·색인·보존 pointer·이 목록 문서의 Git 객체는 추정에 들어 있지 않다. 압축 옵션·Git 버전·서버 refs·권한·정리 시점에 따라 결과가 달라지므로 최종 19.56MB를 보장하지 않는다.
- 이 계획은 **7,856개 후보의 분류와 13,930개 경로 별칭을 빠짐없이 기록**하지만, 사용하지 않는다는 제품 판정까지 모두 확정한 것은 아니다. 과거 2,032개는 폐기하지 않고 아카이브로 보존했으며 현재 미디어의 라이선스/소유권 차단 항목은 그대로다. 과거 버전 보존의 필요성은 용량만으로 결정하지 않는다.
