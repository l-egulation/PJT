# 점진형 온보딩·가이드 설계안

전체 MVP 콘텐츠별 적용안은 [전체 콘텐츠 퀘스트·튜토리얼 맵](./content-quest-tutorial-map.md)에서 관리한다.
캐릭터가 직접 설명하는 화면 구성과 자세 에셋 후보는 [캐릭터 대화형 튜토리얼 시안](./dialogue-presentation-concept.md)에서 관리한다.
역할 의상으로 묶은 큰 튜토리얼 단위는 [역할 의상별 튜토리얼 장 구성](./tutorial-chapters-and-costumes.md)에서 관리한다.

## 1. 한 줄 제안

튜토리얼을 특정 스테이지 구간에 묶지 않고, `초보자 여정 퀘스트`와 `기능별 상황 가이드`를 함께 운영한다.

- 여정 퀘스트는 플레이어가 지금 무엇을 해보면 좋은지 알려준다.
- 상황 가이드는 새로운 기능이 실제로 열리거나 도움이 필요한 순간에만 나타난다.
- 1-5의 보석·던전·치장 개방은 이 체계가 작동하는 하나의 사례다.

## 2. 해결하려는 문제

게임 최초 진입 시 모든 메뉴를 한꺼번에 설명하면 아직 사용할 수 없는 기능까지 외워야 한다. 반대로 설명이 전혀 없으면 자동 전투를 바라보기만 하다가 무엇을 해야 하는지 놓칠 수 있다.

따라서 다음 두 문제를 분리해서 해결한다.

1. **다음 행동을 모르겠다.**
   - 초보자 여정 퀘스트가 해결한다.
2. **새로 열린 기능을 어떻게 쓰는지 모르겠다.**
   - 기능별 상황 가이드가 해결한다.

## 3. 온보딩의 세 층

### 3.1 초보자 여정 퀘스트

게임 첫 진입부터 일정 기간 동안 메인 화면에 작게 유지되는 목표 카드다.

```text
┌ 한짝의 첫 여정 ───────────┐
│ 다음 목표                 │
│ 전투에서 얻은 보상 확인하기│
│                           │
│ [바로 가기]        2 / 7  │
└───────────────────────────┘
```

- 스테이지 번호에 고정하지 않고 실제 계정 상태와 기능 가용성을 기준으로 목표를 준다.
- 한 번에 목표는 하나만 보여준다.
- 자동 전투를 지켜보거나 특정 화면을 방문하는 것도 정상적인 목표가 될 수 있다.
- 사용할 수 없는 메뉴나 보유하지 않은 재료를 요구하지 않는다.
- 접으면 작은 의뢰서 아이콘만 남긴다.
- 퀘스트 보상은 기존 경제 정책과 별도로 결정하며, 가이드가 임의로 생성하지 않는다.

목표 후보:

- 첫 전투 결과 확인
- 획득한 아이템 확인
- 캐릭터 상태 확인
- 사용 가능한 스킬 확인
- 다음 스테이지 도달
- 새로 개방된 콘텐츠 첫 방문

목표의 정확한 순서와 조건은 각 기능의 실제 개방 시점과 가용 행동을 확인한 뒤 확정한다.

### 3.2 기능 개방 안내

새 기능이 실제로 열린 순간에 `무엇이 열렸는지`와 `왜 필요한지`만 알린다.

```text
        새로운 기능이 열렸어요

        [기능 아이콘]
          보석 던전
     보석을 얻어 한짝을 성장시켜요

       [둘러보기]  [나중에]
```

- 서버의 개방 상태가 확인된 기능만 표시한다.
- 현재 전투나 결과 연출을 덮지 않는 안전한 시점에 노출한다.
- `둘러보기`를 선택했을 때만 기능별 가이드가 시작된다.
- `나중에`를 선택하면 내비게이션에 `NEW` 표시를 남긴다.
- 여러 기능이 동시에 열리면 팝업을 연속으로 띄우지 않고 한 장의 묶음 화면으로 보여준다.

### 3.3 기능별 상황 가이드

특정 기능에 처음 들어왔을 때 핵심 행동만 2~3단계로 설명한다.

예시:

```text
1. 이곳에서 오늘 열려 있는 던전을 확인해요.
2. 입장권과 예상 보상을 확인해요.
3. 준비가 끝났다면 도전을 시작해요.
```

- 화면 전체를 막는 설명보다 대상 UI 주변 강조를 기본으로 한다.
- 문구는 두 줄 이내, 한 화면에 대상 하나만 가리킨다.
- 기능을 사용하는 데 꼭 필요하지 않은 설명은 도움말로 보낸다.
- 이미 해당 행동을 한 사용자는 자동으로 다음 단계로 넘어간다.
- 가이드를 닫아도 실제 기능 사용을 막지 않는다.

## 4. 전체 작동 흐름

```text
게임 상태 변화
    │
    ├─ 첫 진입/다음 목표 필요 ──> 여정 퀘스트 갱신
    │
    ├─ 기능 실제 개방 ─────────> 개방 안내 대기열 등록
    │                               │
    │                               └─ 안전한 시점에 안내
    │                                      │
    │                              둘러보기 / 나중에
    │                                  │          │
    │                         기능별 가이드     NEW 표시
    │
    └─ 반복 실패/정체 ─────────> 선택형 도움말 제안
```

전투 중에는 전체 화면 안내를 새로 열지 않는다. 전투 결과 확인 후, 메인 화면 복귀 후, 사용자가 직접 기능 화면에 들어온 직후처럼 조작이 안정된 시점을 사용한다.

## 5. 최초 진입 경험

최초 진입에서는 게임의 모든 시스템이 아니라 다음 세 가지만 이해시키는 것을 목표로 한다.

1. 한짝이 자동으로 전투한다.
2. 전투를 통해 성장에 필요한 것을 얻는다.
3. 다음에 해볼 행동은 여정 퀘스트에서 확인한다.

권장 순서:

| 순간 | 표현 | 전달 내용 |
| --- | --- | --- |
| 재료 선택 완료 후 메인 화면 진입 | 한짝 말풍선 또는 짧은 쪽지 | `이제 함께 모험을 시작해요.` |
| 첫 전투 진행 | 비차단 포인터 | 자동 전투와 현재 스테이지 위치 |
| 첫 결과 확인 | 여정 퀘스트 카드 등장 | 획득 결과를 확인할 위치 |
| 첫 목표 완료 | 도장 애니메이션 | 목표 완료와 다음 행동 |

최초 진입 직후에는 전체 메뉴를 차례대로 누르게 하는 강제 투어를 사용하지 않는다.

## 6. 1-5는 어떻게 사용되는가

1-5는 온보딩 시작점이 아니다. 현재 정책상 관련 콘텐츠가 개방되는 조건이므로 `기능 개방 안내`가 실행되는 대표 사례다.

권장 흐름:

1. 플레이어가 평소처럼 1-5를 진행한다.
2. 최초 클리어와 서버 개방 상태를 확인한다.
3. 승리·보상 연출이 끝난 안전한 시점에 개방 안내를 한 번 보여준다.
4. 보석·던전·치장 중 실제 개방된 항목을 묶어 표시한다.
5. 플레이어가 하나를 선택하면 해당 기능의 2~3단계 가이드를 시작한다.
6. 선택하지 않은 기능은 `NEW` 상태로 남기고 첫 방문 때 안내한다.

```text
        새로운 길이 열렸어요!

   [보석/던전]       [치장]
   성장 재료를       한짝의 모습을
   얻는 새로운 도전   꾸미는 공간

    [먼저 둘러볼 곳 선택]
          나중에 보기
```

이 화면은 1-5 자체를 가르치는 튜토리얼이 아니라 **1-5로 인해 바뀐 게임 상태를 설명하는 화면**이다.

## 7. 상황형 도움말

사용자가 실제로 막혔을 때만 추가 안내를 제안한다.

| 감지 상황 | 제안 예시 |
| --- | --- |
| 같은 전투에서 반복 실패 | 현재 가능한 장비·스킬·캐릭터 성장 경로 하나 추천 |
| 입장권이 없는데 던전 진입 시도 | 충전 시간 또는 획득 경로 안내 |
| 새 기능 개방 후 오래 미방문 | 여정 퀘스트에 선택형 둘러보기 목표 추가 |
| 기능 화면에서 오래 머무름 | `이 화면이 처음인가요?` 도움말 버튼 노출 |
| 이미 기능을 사용함 | 해당 기능 가이드를 완료 처리하고 반복 노출하지 않음 |

정체 감지는 도움을 제안하는 근거로만 사용하며 조작을 강제하지 않는다.

## 8. 노출 우선순위와 충돌 방지

여러 안내 조건이 동시에 생길 수 있으므로 하나의 가이드 대기열로 관리한다.

우선순위:

1. 플레이 진행에 꼭 필요한 오류·차단 안내
2. 기능 개방 안내
3. 사용자가 직접 시작한 기능 가이드
4. 여정 퀘스트 갱신
5. 반복 실패 기반 도움말

규칙:

- 한 번에 오버레이는 하나만 표시한다.
- 전투 중에는 중요 오류 외의 팝업을 대기시킨다.
- 같은 기능의 개방 안내와 첫 방문 안내가 겹치면 하나로 합친다.
- 닫은 안내를 같은 세션에서 반복 노출하지 않는다.
- 앱 종료 후 미확인 안내는 서버 상태를 다시 확인한 뒤 재구성한다.

## 9. 진행 상태 후보

가이드 상태는 기능 개방 상태와 분리한다.

```text
OnboardingJourney
├─ status: NOT_STARTED | ACTIVE | COMPLETED | SKIPPED
├─ currentQuestId
└─ completedQuestIds

FeatureGuideProgress
├─ featureKey
├─ unlockNoticeSeen
├─ guideStatus: NOT_STARTED | ACTIVE | COMPLETED | DISMISSED
├─ currentStepId
└─ updatedAt
```

- 기능 해금 여부는 기존 도메인 상태가 소유한다.
- 가이드 완료 여부는 콘텐츠 해금이나 보상을 발생시키지 않는다.
- 다기기 중복 노출을 막기 위해 계정 단위 저장을 권장한다.
- 화면 강조 위치와 접힘 상태 같은 일시적인 표현만 로컬에 저장할 수 있다.

## 10. 다시 보기와 건너뛰기

- `설정 > 도움말`에서 기능별 가이드를 다시 볼 수 있다. (제안, 미구현)
- 전투 화면 HUD 왼쪽 `전투 기록` 아래의 `튜토리얼 보기` 단추로도 모험가의 장 기반 안내를 다시 연다. 두 진입점의 단일화는 [결정 로그](../../80-decisions/README.md)의 `튜토리얼 다시 보기 진입점`에서 unresolved 로 남았다.
- 다시 보기는 안내만 재생하며 해금·보상을 반복하지 않는다.
- 여정 퀘스트는 접기와 전체 건너뛰기를 제공한다.
- 건너뛴 뒤에도 새 기능 개방 알림은 별도 설정에 따라 받을 수 있다.
- 대상 UI가 사라졌거나 구조가 바뀌면 화면을 잠그지 않고 설명형 도움말로 대체한다.

## 11. 비주얼 방향

튜토리얼 UI를 별도 시스템처럼 보이게 하지 않고 기존 요리 모험 세계 안의 도구로 표현한다.

- 여정 퀘스트: 작은 양피지 의뢰서와 완료 도장
- 기능 개방: 잠긴 주방 문이나 책갈피가 열리는 짧은 연출
- 대상 강조: 두꺼운 외곽선, 작은 손가락 또는 잎사귀 화살표
- 완료 피드백: 화려한 폭발보다 도장 찍힘과 짧은 반짝임
- 문구: 친근한 대화체, 두 줄 이내, 시스템 용어 최소화
- 안내자: 새 NPC 추가보다 기존 한짝 초상과 표정 변형을 우선 활용

## 12. 검증 지표

- 최초 진입 → 첫 목표 완료율
- 여정 퀘스트 단계별 완료·접기·건너뛰기 비율
- 기능 개방 안내의 `둘러보기` 선택률
- 기능 개방 후 첫 방문 및 첫 핵심 행동 완료율
- 동일 안내 반복 노출 횟수
- 연속 실패 도움말을 본 뒤 재도전·성공률
- 튜토리얼 오버레이 노출 직후 이탈률

## 13. 현재 기준과 미결정 사항

### 현재 기준에서 가져온 사실

- 가입 후 첫 진입에는 주력 재료 국가 선택 과정이 존재한다.
- 스테이지는 기존 진행 규칙에 따라 자동 진행된다.
- 1-5 최초 클리어는 보석·던전과 치장 콘텐츠 개방에 연결된다.

### 아직 결정이 필요한 항목

1. 초보자 여정의 정확한 목표 목록과 종료 조건
2. 여정 퀘스트 자체에 별도 보상을 지급할지 여부
3. 기능별 가이드 진행도를 서버 계정에 저장할지 여부
4. 각 기능 개방 직후 안내를 표시할 안전한 화면 시점
5. 전체 온보딩 건너뛰기와 기능 개방 알림 설정을 분리할지 여부

## 14. 다음 산출물

이 구조가 확정되면 다음 두 묶음을 따로 설계한다.

1. **최초 진입 플로우**
   - 메인 화면 첫 진입부터 첫 여정 퀘스트 완료까지
2. **기능 개방 템플릿**
   - 1-5 보석·던전·치장을 예시로 한 개방 안내와 첫 방문 가이드
