# 드롭·개별 잉크 가방·임시 정비 UI

[분야 개요](README.md)

`TemporaryGameGui.ApprovedCore`는 공개 탭을 가방·장비로 표시하며 제작은 선택한 스케치의 하위 단계로 연다. `ApprovedBagCraft`는 가방의 스케치/잉크 4열 목록, 왼쪽 편집 팔레트·오른쪽 3열 잉크 선택, 제작 확인 모달, 장착 자리와 F/C 행동을 합친 제작 완료 화면을 구성한다. 방향키·F가 현재 포커스 단계에만 작동하며, 제작 완료의 F 장착/교체와 C 보관은 즉시 전투로 복귀한다. 제작 완료의 새 무기 카드는 중앙에서 시작해 선택한 슬롯 위로 이동하며, 화살표와 F 행동은 카드에 따라 이동한다. 이동·화살표 반복은 메뉴 정지 중에도 진행하는 unscaled 시간으로 처리하고, UI 재생성 시 현재 X 위치를 보존한다. 미리보기는 실제 장착 상태를 변경하지 않는다. 목록과 상세의 스크롤 위치는 독립 보존하고 선택 항목이 가려질 때 해당 영역만 이동한다. 자세한 표시·입력 계약은 [UI·입력·상호작용](../../../design/ui/ui-and-interaction.md)을 따른다.

`ApprovedEquipment`는 장착 중인 두 칸과 미장착 확정 무기 목록을 분리한다. 슬롯을 먼저 선택해 F로 교체를 시작하면 `inventoryTargetLocked`가 목적지를 보존하여 다음 무기 선택 F에서 바로 장착한다. 무기를 먼저 선택하면 목적지 선택을 한 번 연다. N 이름 변경은 같은 무기 ID에 1~20자 별칭을 저장하며 한글 조합 보호를 유지한다. 이름 입력 뒤 ↓로 행동을 선택해 F로 저장하며 Esc로 취소한다. Enter는 저장 명령으로 사용하지 않고 입력 칸의 F는 문자 입력으로 남긴다. 저장/취소에는 공통 높이의 F/Esc 테두리 키캡을 표시한다. 실제 장착·해제·교환과 대기시간은 `SketchEquipment`/`SketchArsenal` 명령을 사용한다.

무기·잉크 그림과 `ApprovedTheme.Palette`의 `palette/bases`, `palette/paint`, 효과 마크는 승인된 테마 에셋을 그대로 조합한다. 원본은 `resources/ui/approved-theme-v3/runtime/sources/palette-package-v6/`다. HTML 팔레트 도형은 게임 에셋으로 복사하지 않는다. 가방의 미확정 무기는 `ApprovedUi/InactiveArt`의 채도를 0으로 설정하되 불투명도를 유지하여 확정 무기의 컬러와 구분한다. 잉크 목록은 선택 항목만 컬러, 나머지는 흑백이며 장비 목록은 비선택 항목을 흐리게 한다. `ApprovedActionVisual.DrawWash=false`는 인벤토리만 붓칠 강조를 끄고 노란색 선택·호버 글씨를 사용하게 한다. 다른 화면의 기존 강조는 유지한다.

실제 씬의 방향키/F·패드·모델 명령·1920/1280 캡처 검증 진입점은 Unity 6000.6.5f1의 `Deviant.Game.Editor.ApprovedCoreVerification.RunInventory`다. `-batchmode -projectPath <unity> -executeMethod Deviant.Game.Editor.ApprovedCoreVerification.RunInventory -logFile <log>`로 실행하며 로그·캡처는 Git 제외 `outputs/unity-inventory-flow-20261116/`에 저장한다. `-nographics`는 화면 캡처에 사용하지 않는다.

제품 규칙은 [무기 도면·런 잉크 도감](../../../design/equipment/rules.md)을 따른다. 1·2챕터의 일반 런은 `WeaponGrowth.Sketch`의 새 장비 경로를 사용한다. 훈련장과 구형 검증 경로는 아래의 기존 팔레트·스탬프 구현을 유지한다. 로그라이트 영구 해금의 런 혜택 연결 범위는 아래 [로그라이트 해금과 새 무기 공급](#로그라이트-해금과-새-무기-공급) 절을 따른다.

## 런 도감과 스케치 무기

`Run/Runtime/SketchEquipment.cs`는 main의 `SketchRunState`·`SketchArsenal`을 사용하는 잉크 실행 어댑터이며 획득한 잉크 종류 36종, 미확정·확정·장착·보관·파괴 무기 개체, 장착본별 내부 쿨타임, 보상 게이지·받아 둔 보상과 상점 재고를 같은 main 모델에 위임한다. 슬롯은 스테이지별 4·5·6칸, 최대 내구도는 2000 + 1500 × 칸 수다. 원본은 `data/combat/weapon_ink_run_design.json`, Unity 입력은 `export_run_inks.py`가 생성하는 `RunInks.json`이다. 가방과 잉크 도감은 보관 한도가 없다. 잉크는 획득당 기본 10회를 합산하며 미확정 슬롯마다 1회를 예약하고 확정 시 소비한다. 인벤토리는 소진한 등록 종류도 0/총 횟수로 표시하되 적용은 비활성화한다. 보상·상점 등의 기존 부여 가능 종류 조회는 유지한다. `TotalInkUses`는 획득 때만 증가하고 예약·소비로 줄지 않으며 목록의 분모에 사용한다. 무기 확정은 빈칸을 포함한 모든 슬롯을 잠가 이후 잉크 추가·교체·해제를 막으며, 장착·교체·해제·X 순서 교환은 플레이어 공격이 몬스터에게 실제 적중한 후 5초 동안 잠긴다. 허공 공격은 잠금을 만들지 않으며 재적중하면 5초를 갱신한다. 전투 시간 정지 중에는 이 잠금 시간도 진행하지 않는다. 변경 자체는 별도 대기를 만들지 않는다.

`CombatArena.RunInks`가 효과 부여 27종·빨강 3종·파랑 6종을 실제 공격 원본과 연결한다. 이동속도 증가·회복의 실행 트리거, 적중 방어막, 상태 부여·광역 타격의 사전 판정과 원본 무기의 실제 HP 감소량 내구도 귀속을 처리한다. 기본 공격 빨강과 스킬 파랑은 증강·영구 성장 등 같은 피해 범위의 기존 증가율에 합산한다. 빨강은 모든 무기 기본 공격에 적용하며 조건 적중마다 유지시간을 갱신하고, 보라는 활성 중 원본 무기의 매 기본·스킬 적중에 상태를 부여한다. 강화 환산과 시간 계산은 [잉크 효과](../../../design/equipment/inks/effects.md)를 따른다. 가방 속 스킬·노랑·초록·파랑 쿨타임은 정지하지만, 보라 활성·재사용 시간과 이미 얻은 플레이어 버프·방어막·적 상태는 전투 시계로 진행한다. 무기 파괴 시 장착 슬롯을 비우고 생성 전 부착 공격을 취소하되 이미 발사된 투사체·진행 중 대쉬는 원본 잉크를 유지한다.

장비 동기화는 구성이 같은 빈 슬롯의 맨손 인스턴스와 진행 중인 공격을 유지한다. 두 슬롯 모두 기본 공격을 받을 수 있어 빈칸의 A/S는 맨손 공격을 실행하고, 빈칸의 Q/W는 스킬을 실행하지 않는다. 현재 무기가 파괴되면 다른 칸의 생존 무기를 현재 무기로 표시하며, 비워진 칸의 키로도 맨손 공격을 사용할 수 있다.

이미 장착된 무기를 반대 슬롯으로 이동하거나 두 슬롯을 교환하면 전투 쪽에서도 두 무기 인스턴스를 한 번에 교환한다. 동일한 무기 인스턴스의 스킬 쿨타임과 장착 효과는 슬롯이 바뀌어도 유지된다.

[공통 치트 모드](../../tools/debug-menu.md)의 일반 런 편집도 같은 `SketchEquipment`를 갱신한다. 치트 모드가 바꾼 무기 형태·스킬은 동일한 무기 ID의 전투 리소스에 반영하고, 팔레트·잉크는 런 장착본에 적용해 이후 동기화에서 이전 구성으로 되돌아가지 않는다.

런 잉크의 대상별 상태는 실제 감속·독 부여 시에만 등록한다. 중립 대상의 조회는 상태를 만들지 않으며 만료·사망·생명 주기 교체 시 상태를 정리한다. 독의 마지막 예정 틱을 먼저 처리한 뒤 만료를 정리한다. 틱 시작 시점의 대상과 대시 대상 목록은 재사용 버퍼로 고정해 피해 콜백이 실행 중 목록을 편집해도 같은 틱의 순회가 깨지지 않게 한다. 새 런의 이동 속도 조회는 구형 잉크 상태를 새로 생성하지 않으며 이미 존재하는 유효 감속은 함께 읽는다.

`TemporaryGameGui.RunInks`는 가방의 무기 목록·임시 배치·확정·A/B 장착·보관·버리기, 런 도감, 3지선다 보상과 고정 상점 재고를 표시한다. 잉크 아이콘은 카탈로그의 `icon` 경로로 읽으며 노랑·초록·보라·빨강·파랑을 각각 `LootPickups/ink-flat-{color}`에 연결한다. 도감·무기 구성 슬롯·전투 HUD·보상·상점은 장착 잉크 자체의 색을 표시하며 강화 슬롯 색은 아이콘 선택에 사용하지 않는다. 아이콘은 경로별로 캐시한다. 이름과 기본/강화 수치는 생성 문구로 구분한다. 인벤토리는 내구도 수치를 표시하며 전투 HUD는 일시정지 메뉴에서 게이지/숫자를 선택한다. 지도·인벤토리의 몬스터 아이콘 옆에는 받아 둔 보상 수를 표시한다. 전투 HUD는 main의 보상 게이지와 보상 수 배지를 사용하며, G 또는 가방 버튼으로 보상을 연다.

가방·제작·장비 목록과 제작 중 잉크 선택·팔레트 칸은 아이콘과 표시명의 가로 중심을 같은 카드 중앙에 맞춘다. 아이콘·표시명·그 사이 여백을 포함한 카드 전체를 클릭하면 같은 항목을 선택한다. 이미 선택한 항목을 다시 누르는 동작과 키보드·패드 탐색은 기존 규칙을 유지한다. 방향키·Q/E로 항목이나 탭을 전환해 버튼을 다시 만들 때 선택 강조는 초기 기본 크기로 표시하지 않고, `Canvas.preWillRenderCanvases`에서 현재 글자 크기와 위치를 계산하고 강조를 켠 뒤 uGUI 메시를 생성한다. 방향키·Q/E 전환으로 새로 만든 강조도 첫 프레임부터 그리며, 메시 생성 후에 켜서 한 프레임 비는 깜빡임을 만들지 않는다.

영구 프로필의 `equipmentRevision=2`가 새 저장 체계를 식별한다. 실제 파일 저장소는 이보다 이전인 기존 프로필과 백업을 함께 삭제하고 새 초기 상태를 생성한다. 새 저장은 다음 실행에서 유지한다. 테스트용 메모리 저장소와 정상 새 저장을 매 실행마다 삭제하지 않는다. 구형 프로필을 새 도감으로 환산하지 않는다.

충전 수를 보유하는 스킬에 대한 파랑 쿨감은 설계 미정이므로 용량 1 스킬에만 적용한다. 3스테이지 상점 가격 역시 미정으로 구매를 열지 않는다. 자동 규칙·전투 검증과 실제 전체 런의 밸런스·아트 가독성 검증은 구분한다.

## 기존 팔레트·스탬프 경로

몬스터 처치부터 바닥 아이템 생성, 접촉 획득, 개별 가방, 획득 알림과 잉크 정비를 연결한다. 화면은 기준 도트 시안에서 분리한 공통 프레임·슬롯·아이콘과 한글 픽셀 글꼴을 사용한다. UI와 기능 원본을 분리해 GUI를 편집해도 같은 명령과 상태를 재사용하게 한다. 실제 아이템 합성·같은 아이템 스택·무기 전용 파츠는 추가하지 않는다.

## 로그라이트 해금의 런 혜택

`RunPerks`는 출발 스냅샷의 공용 리롤·부활·추가 보상 예산과 소수 골드 증가분·파괴 지급 영수증을 소유한다. 같은 `RunSession`이 2챕터로 이어져 예산을 다시 지급하지 않는다. `ProgressionService`는 카탈로그 개정 번호에 따라 제거된 해금을 일회 환급한다.

스케치 무기 런의 혜택은 `SketchRunBinding`이 출발 계획에서 한 번 설정한다. 잠긴 런 잉크는 `SketchRunState.LockInks`로 보상·상점·잠긴 상자 후보에서 빠지고, 상점 진열 확장은 `ExtraShopItems`로 새 판매대의 무기·잉크 자리를 늘린다. 훈련 런은 둘 다 적용하지 않는다.

출발 보상은 1스테이지에서 플레이 가능 상태가 되면 잉크 → 무기 순서로 연다. 출발 잉크 보상은 `OpenStartingInkOffer`로 열린 미등록 잉크 3종(제목 "출발 잉크"), 출발 추가 보상은 `OpenStartingOffer`로 무기 3개 제안을 일반 3지선다 보상 화면(제목 "출발 보상")에 표시한다. 일반 보상 회차·무기 획득 보장에 넣지 않는다. 보상 화면의 R 또는 "공용 리롤"은 `RerollPending`으로 화면의 제안을 그 제안의 규칙(일반·보스·잠긴 상자·출발 잉크·출발 무기)대로 다시 뽑는다. 정비소 진열 각 줄 끝의 새로고침 종(바닥은 무기, 발판은 잉크)은 `RerollShop`으로 그 줄의 미구매 자리만 바꾼다. 둘 다 후보가 바뀔 때만 `RunPerks`의 공용 횟수를 차감한다.

무기 파괴 골드는 `SketchArsenal.WeaponDestroyed`(내구도 소진)에서 무기마다 한 번 지급한다. 버리기는 이 이벤트를 내지 않는다. 부활은 `RunRevivalBridge`가 플레이어의 사망 직전 처리에 연결한다. 보스 처치·봉인 보상 상자의 무료 증강 선택(`AugmentRewardChoice`)과 보스 잉크 제단도 같은 리롤 잔여 횟수를 사용한다. 잠긴 증강은 `MaintenanceAugments.LockCards`로 무료 추첨에서 빠진다. 충전소는 새 챕터마다 추가 이용 횟수를 포함한 예산을 받는다. 구형 팔레트·스탬프 경로(`sketchWeapons` 끔)의 잉크 판매대는 기존처럼 진열 확장·새로고침을 쓴다.

생성은 `python tools/combat/export_roguelite_progression.py`, 대사만 갱신할 때는 `python tools/assets/build_hub_bindings.py --visits-only`를 사용한다. 잉크 묶음의 잉크 ID는 `export_run_inks.py`와 같은 원본으로 검사한다. 검증 방법은 [검사와 빌드](../../testing/testing.md)를 따른다.

## 기존 개별 잉크 기능 범위

| 기능 | 현재 동작 |
|---|---|
| 1. 사망·드롭 | 공통 전투 적의 HP 0을 관측하면 새 공격을 취소하고 몸/피격 콜라이더를 끈다. 사망 표시 종료를 기다리지 않고 설정된 잉크를 즉시 한 번 생성한다. 골드는 같은 처치 시점에 즉시 한 번 지급하고 작은 동전이 떨어진 자리에서 노란 가루로 터진다. 마법안료도 즉시 지급하며 마을의 팔레트 아이콘이 바닥에 떨어진 뒤 사라질 때 그 자리에 실제 지급량이 나타나 획득을 표시한다. |
| 2. 바닥 획득 | 여러 개가 떨어지면 처치 위치를 중심으로 0.8unit 간격으로 펼치되, `CombatArena.DropPoint`가 옆의 고체 벽·계단 단차 직전까지만 이동시켜 벽 안에 놓이지 않게 한다(잉크·골드·보상 아이템 공통). 몬스터 처치로 생긴 잉크·스탬프·파츠·색상 잉크는 몬스터 발 위 0.8unit(몸)에서 튀어나와 포물선으로 그 자리까지 날아가고, 바닥에 닿은 뒤 두 번 작게 튕기며 조금 굴러 멈춘다(`LootToss`). 여러 개가 떨어지면 착지 간격·높이·비행 시간을 조금씩 흩뜨리며, 흩뜨림은 고정 시드와 처치 위치·드롭 순번으로 정해져 같은 처치는 같은 궤적을 다시 그린다. 하나만 떨어져도 옆으로 최소 0.35unit 흩어진다. 착지점은 벽·단차 앞까지만 옮기고 원래 바닥보다 2.5unit 넘게 낮거나 바닥이 없는 구덩이 쪽이면 처치 위치 쪽으로 물린다. 천장이 낮으면 솟는 높이를 줄이고, 궤적이 지형을 지나면 더 낮춘 뒤 그래도 막히면 착지점에서 제자리로 튀어 오른다. 완전히 멈춘 뒤에만 획득할 수 있다. 처치가 아닌 생성(버리기·교환·개발 도구)은 기존처럼 제자리에서 0.6초 동안 1.1unit 솟았다 내려앉는다. 골드 동전과 마법안료 팔레트의 제자리 연출은 바꾸지 않는다. 수치의 편집 원본은 [loot_drop_toss.json](../../../../data/presentation/loot_drop_toss.json)이며 `python tools/inventory/export_loot_toss.py`로 `Inventory/Resources/LootDropToss.json`에 복사한다(`--check`로 최신성 확인). 살아 있는 공통 플레이어가 접촉한 경우에만 획득한다. |
| 3. 획득 알림 | 성공한 획득마다 별도 알림을 큐에 넣고 본 게임 화면 상단 중앙에 `[이름] 잉크 획득` 또는 `[이름] 스탬프 획득`을 배경·테두리 없이 글씨만 2.2초씩 표시한다. 이름에 이미 잉크·스탬프가 있으면 같은 종류명을 반복하지 않는다. 형태·스킬 스탬프의 실제 바닥 획득도 같은 큐를 사용한다. 보스 체력바가 있을 때는 그 아래에 둔다. 같은 종류도 알림을 생략하지 않는다. 가방/일시정지 중에는 알림을 대기시킨다. |
| 4. 개별 가방 | 종류 구분 없는 가방 하나에 기본 5칸. 마을 가방 확장 해금이 있는 런은 출발 때 7~15칸으로 늘어나며(`WeaponGrowth.InkCapacity` → `InkInventory.SetCapacity`, 줄지 않음) 가방 화면이 칸을 다시 만든다. 형태·능력치·특수와 현재 색상 잉크가 같은 5칸을 나눠 쓴다. 같은 정의의 잉크도 고유 인스턴스로 한 칸씩 차지한다. 장착분은 용량에서 제외한다. |
| 열기/닫기 | `Tab`으로 토글하고 HUD 가방 버튼으로 연다. `Esc` 또는 ×로 닫는다. 열린 동안 전투·상호작용 입력과 시뮬레이션을 정지한다. 닫으면 가방이 요청한 정지만 해제한다. |
| 플레이 HUD | 도트 테마가 준비되면 기존 HUD의 표시/포인터 수신을 숨기고 같은 공통 부품의 HP·실제 무기2개·가방·정지 버튼을 표시한다. 클릭 교체·Tab 가방·Esc 정지는 실제 전투/제어 요청에 연결한다. 연결 종료 시 기존 표시 상태로 복구한다. |
| 목록/설명 | 가방 화면은 종류 필터·페이지 없이 5칸을 모두 한 번에 보이고, 선택한 개별 아이템의 이름·효과를 표시한다. |
| 장착 | 무기 2개, 각 형태 1·능력치 5·특수 1칸. 가방 잉크 선택→빈 목표 슬롯 클릭, 또는 무기 선택→장착 버튼/`E`. 장착한 잉크는 런 동안 고정된다. 해제 버튼은 숨기며, 이미 찬 슬롯에 장착하거나 장착 잉크를 해제·이동하면 `InkInventory.LockedMessage`로 거절한다. 이 고정은 기존(형태·능력치·특수) 잉크만의 규칙이다. 색상 잉크 팔레트 칸은 언제든 장착·교체·해제하며, 가방 안내 줄도 기존 잉크를 골랐을 때만 고정 문장을 보인다([임시 GUI](../../presentation/ui/temporary-gui.md)). |
| 버리기 | 가방에서 잉크를 고르면 왼쪽 아래 **버리기** 버튼이 나온다. 누르면 그 잉크를 가방에서 빼서 플레이어 발밑 바닥에 내려놓는다(`InventoryRuntimeHost.DiscardAt`). 플레이어가 그 자리를 한 번 벗어났다가 다시 닿아야 재획득한다. 장착 중인 잉크는 먼저 해제해야 하며, 삭제·재화 변환은 하지 않는다. |
| 파괴 | 가방에서 잉크를 고르면 **파괴** 버튼이 나온다. 처음 누르면 확인 안내만 표시하고(다른 잉크를 고르면 해제), 같은 잉크에서 한 번 더 누르면 가방에서 영구히 없앤다(`InventoryRuntimeHost.DestroyAt`). 바닥에 남기지 않고 골드·재화를 주지 않는다. 사용자 결정(2026-10-31, 추천안): 되돌릴 수 없는 동작이라 두 번 눌러 확정한다. |
| 가방 포화 | 획득 실패 시 바닥 개체를 지우지 않는다. 가까운 바닥 아이템이 대기 중이면 가방 아이템 선택→바닥 교환 버튼으로 수동 교환한다. 기존 아이템은 바닥에 남고 잠시 자동 재획득을 막는다. |
| 획득 실패 | 가득 찬 가방의 실패는 획득 성공과 다른 알림으로 표시하고 같은 실패만 중복 억제한다. 실제 획득 성공 알림은 합치지 않는다. |
| 실제 효과 미리보기 | 선택한 잉크를 자동 장착할 실제 슬롯과 현재 무기 상태를 읽는다. 기본 피해+20%가 이미 있다면 다음 +20%의 예시는12→14다. 장착 후 실제 타격/특수 변환은 기존 전투 카탈로그를 따른다. |
| 리셋 | 전투 테스트 리셋에서 미획득 드롭·사망 지급 예약·가방·장착 잉크·획득 알림·선택/창 상태를 정리한다. 실물 잉크가 변경한 필드만 기반 장비로 복구하고 개발 도구로 공급한 나머지 설정은 유지한다. 실제 저장/영구 해금은 쓰지 않는다. |

장착 허용은 현재 전투 코드의 `CombatPlayer.EditingAllowed`를 사용한다. 씬이 `MaintenanceSite` 판정을 제공하면 전투 여부 대신 그 위치 판정과 행동·대시 중 여부를 사용한다. 1챕터 랜덤 스테이지는 `Chapter1MaintenanceFacility`가 정비소 방(상점 자리 포함) 안에서만 허용하며, [1챕터 기준](../../../design/run/run-structure.md#1챕터-플레이-빌드-기준)의 정비소 한정 규칙을 따른다. 판정을 제공하지 않는 공통 씬·들판 씬은 기존처럼 비전투·비행동 상태에서 허용한다. 허용되지 않으면 가방 확인·획득만 가능하고 장착 거래는 상태 변경 없이 거부한다.

## 이전 1~2번과 현재 코드의 관계

`chore/unity-initial-setup`의 MR !1~!3은 `VillageCombatant`·`InkMonsterController` 기반 사망/확정 드롭/픽업/ID별 수량을 구현했다. 현재 메인은 공통 `CombatActor`·`TestEnemy`를 사용하므로 옛 플레이어·피격·폐기 잉크 시스템을 통째로 복원하지 않는다.

현행 구현은 사망 후 일회 지급, 착지 전 획득 차단, 살아 있는 플레이어 접촉, 재시작 정리라는 동작을 유지한다. 이전의 ID별 수량 사전은 사용하지 않고 `InkDefinition`과 `InkInstance`를 분리한다. 수량 3 지급은 같은 ID의 물리 아이템 세 개로 생성한다. 종류가 같아도 장착·교환 시 각각의 인스턴스를 옮긴다.

경로는 `unity/Assets/Deviant/` 기준이다. 기능 어셈블리 `Deviant.Inventory`는 UnityEngine·전투·UI를 참조하지 않는다. 장착 거래는 `IInkEquipmentPort`로 현재 전투의 허용 여부와 카탈로그를 검증한 뒤 확정한다. 거부된 거래는 가방/장착 상태를 바꾸지 않는다.

각 무기의 실제 `StatSlots`, 형태/특수 선택과 쿨타임 부담을 기존 `Reconfigure`에 연결한다. 발사기의 특수 피해/쿨감 잉크는 장착 상태를 유지하며 비활성 이유를 표시한다. 미정 공용 노란 파츠의 효과나 전용 파츠 콘텐츠를 새로 구현하지 않는다.

## 데이터·에셋 교체

바닥 아이템은 `Deviant/Inventory/Resources/LootPickups/`의 투명 PNG를 사용한다. 색상 잉크 5종과 무기·스킬 스탬프는 16×16 격자에서 직접 구성한 일정한 1픽셀 외곽선의 아이콘이다. 색상 잉크 드롭은 파츠의 고정 등급에 따라 1등급 나무, 2등급 황동 띠, 3등급 은빛 마개, 4등급 금빛 마개와 띠를 사용하며 오른쪽 아래에 해당 등급 숫자를 표시한다. 다섯 색의 1~4등급 원본은 리소스의 `ui/monster-loot-grades/source/icons.json`에 있다. 스탬프는 7색으로 나무 손잡이·받침의 얕은 입체감·무기와 스킬의 구분 기호를 표현한다. 큰 색 면과 실루엣을 유지하며 미세한 문양·그라데이션·디더링은 넣지 않는다. 기본 아이콘의 편집 원본은 리소스의 `ui/monster-loot-flat/source/icons.json`이며 큰 이미지를 축소하는 과정은 없다. 잉크·스탬프는 16 PPU로 가져와 32 PPU 카메라에서 정수 2배 도트로 표시한다. 코인은 12×12, 마법안료 팔레트는 16×16이며 둘 다 16 PPU로 표시해 같은 1픽셀 외곽선을 쓴다. 코인의 실제 지름은 10픽셀로, 이전 14픽셀보다 약 30% 작다. 코인은 4색으로 짧은 하이라이트와 가장자리 명암만 더하고, 팔레트는 바탕·외곽선·짧은 하이라이트에 잉크와 같은 5색의 큰 색점을 사용해 최대 8색으로 구성한다. 모두 Point 필터, 압축·밉맵 없음이며 별도 색 곱을 하지 않는다. 착지 높이와 벽 옆 펼침의 여유 폭은 실제 월드 캔버스(코인 0.75unit, 나머지 아이콘 1unit)에 맞춘다. `GroundLootArt`는 월드 표시만 선택하고 가방 아이콘·소유권·드롭률은 바꾸지 않는다. 이전 상세 그림은 리소스의 `ui/monster-loot/`에 보존한다.

마법안료는 마을의 팔레트 상징을 단순화한 `pigment-palette-flat.png`를 사용하며, 드롭 아이콘은 모두 같은 픽셀 격자와 외곽선 굵기를 따른다. 팔레트가 0.2초 동안 작은 포물선으로 떨어지고 바닥에서 0.12초 머문다. 이후 팔레트를 숨기는 동시에 착지 위치에 실제 획득량(+1, +5 등)을 2배 정수 배율의 작은 픽셀 숫자로 표시한다. 숫자만 0.6초 동안 0.5unit 위로 떠오르며 마지막 구간에 투명해진다. 전체 안료 연출은 0.92초다. 골드는 12×12 동전 한 알이 약 0.2초 튀고 잠시 머문 뒤 제자리의 세 지점에서 밝은 노랑·크림색 입자 80개를 흩뿌린다. `CurrencyPowderBurst`의 골드 입자는 2·3픽셀이며 중력·반발·마찰을 작은 고정 시간 간격으로 계산한다. 입자 크기에 맞춘 충돌 여유 폭으로 실제 `ArenaSurface` 지형을 조회해 바닥에서 작게 튄 뒤 옆으로 미끄러지며 느려지고, 벽에서도 반사된다. 지형 조회 버퍼를 재사용하며 입자에 플레이어나 적을 밀어내는 물리 콜라이더는 추가하지 않는다. 전체 골드 연출은 약 1.27초다. 두 연출의 위치는 1/32unit 격자로 표현하고 플레이어를 추적하지 않으며 전투 일시정지에 따라 멈춘다. 안료 숫자가 나타날 때와 골드 가루가 터질 때 기존 재화 획득음을 재생하고 같은 순간의 소리는 하나로 합친다.

골드·안료는 처치 즉시 한 번 지급하며 연출 도착이나 입자 소멸 때 재지급하지 않는다. 1·2챕터에서 실제 지급에 성공했을 때만 표시한다. 생성 원본·요청문은 리소스 저장소의 `ui/monster-loot/`, 단순 아이콘의 픽셀 격자 원본은 `ui/monster-loot-flat/`, Unity 적용 경로·해시는 메인의 배치 계약에서 관리한다.

검증용 편집 원본은 [temporary-inks.json](../../../../data/inventory/temporary-inks.json), Unity 생성물은 [TemporaryInventoryContent.asset](../../../../unity/Assets/Deviant/Inventory/Resources/TemporaryInventoryContent.asset)이다. 생성은 다음과 같다.

```sh
python tools/inventory/export_inventory_content.py
python tools/inventory/export_inventory_content.py --check
```

기존에 확정된 4개 능력치·형태·특수 변환만 검증 데이터로 제공한다. 지급표는 임시 확정 지급 시나리오이며 정식 드롭률·보상량·밸런스를 뜻하지 않는다. 몬스터별 `InkDropSource.tableKey`로 테이블을 지정할 수 있고, 없는/빈 테이블은 지급하지 않는다. 미지정 공통 적에는 프로필별 임시 테이블을 사용한다.

아이콘을 바꾸려면 Unity 콘텐츠 에셋의 `icon`·`tint`를 연결한다. 비어 있으면 코드로 만든 작은 임시 잉크 Sprite를 사용한다. 외부 이미지가 없어도 기능은 실행된다. 생성기를 다시 실행하면 임시 에셋의 수동 아이콘 연결도 생성 원본 기준으로 돌아가므로, 최종 아트 공급 시 별도 콘텐츠 에셋을 만들어 `InventoryGameBinding.content`에 지정한다.

최종 GUI는 `InventoryPanelView`를 구현한 프리팹을 만들어 `InventoryGameBinding.viewPrefab`에 지정한다. 같은 `InventoryRuntimeHost`/`InventoryPresenter`의 명령과 상태를 사용하고, Sprite·폰트·배치만 바꾼다. 기본 뷰의 공개 위젯 참조를 최종 프리팹에 연결하는 방식도 가능하다. 화면 교체를 위해 가방 재생성이나 아이템 ID 변환을 수행하지 않는다.

### 도트 UI 에셋과 편집

`Resources/PixelInventory/Theme.asset`은 기준 이미지에서 분리한 프레임/슬롯/고정 타이틀, 실제 아이템 종류별 아이콘과 무기10형태 아이콘을 연결한다. `InventoryView.prefab`을 Prefab Mode에서 편집하면 배치와 개별 그림을 바꿀 수 있다. 저장된 프리팹에는 인벤토리 소유 데이터가 없고 실행 시 현재 상태로 모든 셀을 갱신한다. 플레이어 미리보기는 현재 캐릭터 Sprite를 읽는다.

현재 플레이 GUI의 이미지·문양은 [고정 리소스 배치](../../../assets/README.md)로 준비하고 메인의 `.meta`를 유지한다. 제작 원본·예전 테마 목록은 `resources`가 보존한다. 구형 PixelInventory 테마의 선택적 이미지 22장은 현재 원본 묶음에 동일 바이트가 없어 기본 플레이 GUI의 배치 계약에 포함하지 않는다. 이를 필요로 하는 별도 시각 작업은 원본 확보·해시 대조부터 수행하며 다른 그림으로 대체하지 않는다.

`Tools > deviant > UI > Build Pixel Inventory Theme`는 메인 소유 글리프·테마 연결 작업이다. 실행 중 `Save Live Pixel Inventory Prefab`은 현재 UI 구조를 저장하며 EventSystem/씬 카메라/캐릭터 이미지 같은 실행 인스턴스를 프리팹의 필수 의존성으로 남기지 않는다. 미술 제작과 게임 데이터·프리팹 편집을 구분한다.

글꼴은 Galmuri2.40.3의 Galmuri11/11-Bold(OFL-1.1)이며 원본과 라이선스를 `PixelInventory/Fonts`에 보존한다. 기본 프레임/검/채찍/잉크 아이콘은 기준 시안에서 분리했고, 나머지 무기 아이콘은 같은 시안을 참조한 Sunburst CLI 제작 시트를 사용한다. 문구/수량/선택/효과는 그림에 굽지 않고 실제 상태로 표시한다. 고정 창 제목과 닫기 기호만 장식 그래픽으로 제공한다.

테마 PNG가 없으면 개발 경고를 출력하고 기능 확인용 기본 화면으로 실행한다. 그 결과를 도트 테마의 시각 검증으로 사용하지 않는다. 한글 비트맵 폰트의 문구가 추가되면 글리프 목록과 테마를 다시 가져온다.

## 실행과 확인

공통 게임·들판 씬에서 공통 `CombatArena`를 발견하면 설치된다. 실제 배경·캐릭터 화면 확인에는 해당 씬의 별도 배포 아트 복원이 필요하다. `InventoryRuntimeHost`의 Inspector 컨텍스트 메뉴 `Spawn temporary test inks`로 승인된 임시 잉크를 바닥에 생성해 기능을 확인할 수 있다.

1. 적을 처치한다. 사망 중에는 판정이 꺼지고 처치 직후 설정된 개수의 잉크와 골드가 생성되는지 본다.
2. 드롭 아래에서 기다린다. 착지 전에는 획득하지 않고 착지 후 재진입 없이 획득해야 한다.
3. 같은 잉크를 두 번 얻어 두 칸과 두 알림이 생기는지 확인한다.
4. `Tab`으로 가방을 열고 목록과 설명을 확인한다. 열린 동안 적과 전투 시간이 멈추고, 닫으면 재개되는지 확인한다. 가방을 닫은 뒤 `Esc` 메뉴에서도 같은 정지·재개 동작을 확인한다.
5. 비전투 상태에서 빈 슬롯 장착과 실제 공격 스탯, 장착 잉크의 해제·교체·이동 거절을 확인한다.
6. 가방 5칸이 찬 상태에서 추가 드롭이 사라지지 않는지, 수동 교환 후 기존 잉크가 바닥에 남는지 본다.
7. 전투 중 장착 거부, 비호환 형태 장착 거부, 발사기 비활성 설명을 확인한다.
8. 사망 진행·드롭·알림이 남은 상태에서 테스트 리셋하고 이전 실행의 아이템/알림이 나타나지 않는지 본다.

자동 검사는 Unity Test Runner의 `Deviant.Inventory.Tests`다. 개별 인스턴스, 용량·교환·호환 거부의 원자성, 입력 소유권·알림 큐와 실제 전투/픽업/임시 UI 연결을 검사한다. 실행 결과와 환경은 변경 커밋 본문에 남기며, 이 문서의 절차 자체를 통과 결과로 간주하지 않는다.

외부 아트가 없는 환경에서는 `python tools/inventory/prepare_verification_project.py --output outputs/inventory-verification/UnityProject`로 새 격리 프로젝트를 준비할 수 있다. 이 도구는 최신 명시 조립·장비·HUD 의존성이 빠지지 않도록 전체 Assets·Packages·ProjectSettings를 복사하며 원본을 변경하지 않는다. 기존 출력 폴더는 덮어쓰지 않으므로 새 출력 경로를 지정한다. 격리 프로젝트도 원본과 같은 Unity 6000.6.5f1·패키지 버전을 사용한다. 정적 HUD/Galmuri 글꼴은 복사하고, 가져오기 정지가 확인된 구형 UI 원본 TTF 3개는 격리 복사본에서만 제외한다. 이 제외는 구형 글꼴의 시각 검증을 뜻하지 않는다.

```powershell
& '<Unity 6000.6.5f1 경로>/Unity.exe' -batchmode -projectPath '<저장소>/outputs/inventory-verification/UnityProject' -runTests -testPlatform EditMode -assemblyNames Deviant.Inventory.Tests -testResults '<저장소>/outputs/inventory-verification/results.xml' -logFile '<저장소>/outputs/inventory-verification/unity.log'
```

격리 테스트의 통과는 원본 배경/캐릭터 복원·지정 버전의 전체 프로젝트 빌드·수동 게임 플레이 검증을 대체하지 않는다. 자동 시작/GUI 교체 테스트는 같은 프로젝트의 `inventory-preview.png`에 실제 임시 uGUI를 렌더링한다.

## 남은 범위

정식 보상 경제·확률 추첨·런/영구 저장·바닥 아이템의 챕터 재로드 보존·정식 안전 정비 판정은 포함하지 않는다. 무기 자체의 바닥 교환도 별도 기능이다. 현재 UI는 마우스/키보드용 임시 16:9 배치이며 최종 아트·게임패드 내비게이션·전체 화면 라우팅은 후속 범위다. F1 직접 장비 공급 패널은 개발 도구이며 실물 가방을 통한 정비와 별도 경로다.

현재 런의 가방은 `InkInventory`의 5칸과 `WeaponGrowth`의 색상 잉크를 하나의 한도로 함께 조회한다. `InventoryRuntimeHost`는 두 모델의 보관 수를 서로의 `ExternalUsage`로 연결해 어느 쪽에서 얻어도 합계 5개를 넘지 않게 하되 소유 인스턴스를 복제하지 않는다. 색상 드롭·제단은 `TryGrantInk`로 한도를 검사하고 정비소 잉크 판매대 구매(`TryBuyInk`)도 결제 전에 같은 한도를 검사하며, 가방 목록과 장착 팔레트 조회는 런의 같은 `GrowthInk`/슬롯을 표시한다. 색상 장착·교체·파괴는 위치와 관계없이(전투 중 포함, 사망 제외) `InventoryRuntimeHost.TryEquipColor`/`TryDestroyColor`로 실행한다. 교체는 무료이고 빠진 잉크는 같은 인스턴스로 가방에 돌아오므로 보관 수가 늘지 않는다. 판매·강화·색 변경은 정비소 팔레트 관리에서 수행한다. 가방과 정비소에서 색상 잉크는 파츠별 효과 문양을 사용한다. 추가 12종은 고유 문양이 없어 색별 임시 문양을 쓴다. 보유 잉크 그림의 오른쪽 위에는 철·황동·은·금 문장으로 고정 등급 숫자(1~4)를 표시한다. 편집 원본은 리소스의 `ui/ink-part-symbols/source/pixels.json`에 있다. 팔레트 칸 오른쪽 위에는 슬롯 강화 단계(+0~+5)를 표시한다. 색상 팔레트 칸은 물방울 색으로 허용 색을 보여주며, 빈 칸의 물방울에는 문양을 넣지 않는다. 가방의 무색 칸은 왼쪽 위에 표시한다. 빈 팔레트 칸도 강화 단계를 표시하며 잠긴 칸과 빈 보관함 칸에는 숫자를 표시하지 않는다.
