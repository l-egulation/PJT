## Problem Statement

현재 게임에는 유저끼리 실시간으로 소통하고 거래·아이템 정보를 교환할 공간이 없다. 기존 게임 UI는 코지 픽셀 전투·관리 화면을 중심으로 구성되어 있으므로, 새 커뮤니티 기능도 기존 전투 흐름과 시각 언어를 깨지 않아야 한다.

동시에 공용 채팅은 욕설, 성희롱, 사기성 거래 유도, 반복 스팸에 노출될 수 있다. 자유로운 대화를 허용하되 전송 전 유해 표현 차단, 고정 이용 안내, 메시지별 신고, 개인 차단, 단계적 제재를 함께 설계해야 한다.

## What Makes This Cool

채팅을 별도 서비스처럼 보이게 하지 않고, 게임 안의 작은 광장처럼 만든다. 유저는 전투 중에도 우측 패널에서 대화를 확인하고, 거래 정보는 게시판에서 다시 찾아볼 수 있다.

핵심은 실시간 대화와 오래 남겨야 하는 거래 정보를 같은 화면 언어 안에서 분리하는 것이다.

- 광장 채팅: 짧은 인사·잡담·질문·즉시 반응 중심
- 거래 게시판: 아이템·수량·가격·구매/판매 의도처럼 다시 찾아볼 정보 중심
- 코지 픽셀 종이 패널, 황금빛 목재, 초콜릿색 글자, 코랄 강조, 시안·초록 상태색을 기존 HUD와 공유
- 채팅 상단에는 짧은 경고문을 항상 고정하고, 상세 이용 규칙은 클릭해 확인

## Constraints

- 이번 Office Hours 단계에서는 구현하지 않는다. 설계 문서만 작성한다.
- 구현을 시작할 때는 새 기능 브랜치에서 작업하고 PR을 통해 main에 병합한다.
- PR 병합 후에도 이번 범위에서는 배포하지 않는다. 배포는 별도 승인·작업으로 남긴다.
- 기존 메인 전투·거래소·랭킹 화면의 공통 HUD와 코지 픽셀 시각 언어를 재사용한다.
- 채팅과 거래 게시판은 서버 권한 데이터로 설계한다. 클라이언트 필터만으로 안전성을 보장하지 않는다.
- 유저가 작성한 메시지는 전송 전에 서버가 필터링한다.
- 차단은 광장 메시지와 거래 게시글 모두에 적용하며, 차단한 유저의 콘텐츠를 차단한 사용자 화면에서만 숨기는 개인 환경 설정이다. 계정 제재나 상대방의 채팅 접근 제한으로 사용하지 않는다.

## Premises

- 유저는 게임 안에서 다른 유저에게 거래·아이템 정보를 묻고 답할 동기가 있다.
- 공용 채팅 하나만으로 거래 정보를 보존하기 어렵기 때문에, 초기 범위에서도 광장과 거래 게시판을 분리하는 편이 낫다.
- 한국어 욕설·성희롱은 단순한 단어 목록만으로 완전히 판정할 수 없다. 변형·띄어쓰기·우회 표현과 문맥 오탐을 운영 정책에 포함해야 한다.
- 전송 차단은 유해 메시지의 일반 유저 노출을 줄이지만 정상 문장의 오탐 비용이 있다. 차단 사유와 수정 안내를 함께 제공해야 한다.
- 자동 제재는 오신고와 다계정 악용에 취약하다. 반복 위반 대응은 경고, 일시 채팅 금지, 계정 제재의 단계와 운영자 검토 경계를 분리해야 한다.

## Approaches Considered

### Approach A: 태그형 광장 채팅

하나의 광장에 메시지를 모으고 작성 시 잡담 또는 거래 태그를 선택한다. 구현과 운영은 작지만 거래 정보가 계속 흘러가 다시 찾기 어렵다는 문제가 남는다. 사용자가 선택했지만 최종적으로 거래 게시판이 더 적합하다고 판단해 채택하지 않았다.

### Approach B: 광장 채팅 + 거래 게시판

실시간 광장과 거래 정보 게시판을 분리한다. 광장은 짧은 대화와 질문을 담당하고, 게시판은 아이템·수량·가격·거래 상태가 있는 글을 담당한다. 첫 범위는 커지지만 사용자가 원하는 거래 정보를 다시 찾을 수 있고, 채팅과 게시판의 보존·신고 정책을 각각 명확히 만들 수 있다.

### Approach C: 자유 채팅 자동 분류

사용자가 태그를 선택하지 않고 서버가 대화·거래·유해 표현을 자동 분류한다. 입력 부담은 줄지만 한국어 문맥 오판과 운영 신뢰 문제가 커진다. 초기에는 태그와 구조화된 게시판을 사용하고 자동 분류는 후속 검토로 남긴다.

## Recommended Approach

**Approach B: 광장 채팅 + 거래 게시판**

### 광장 채팅

- 한 개의 공용 광장 채널
- 짧은 자유 텍스트 메시지
- 열림 기본 상태의 우측 접이식 패널
- 메시지별 시간, 닉네임, 본문, 더보기 메뉴
- 더보기 메뉴에서 신고·차단 제공
- 상단 고정 경고문: 욕설·성희롱·사기성 거래 유도 금지 및 위반 시 제재 안내
- 경고문을 클릭하면 신고·차단·제재 기준 상세 표시
- 새 메시지와 읽지 않은 메시지는 배지로 표시
- 좁은 화면에서는 패널이 전투 정보와 겹치지 않도록 단일 열로 접힘

### 거래 게시판

- 광장 패널 안에서 `광장`과 `거래 게시판` 두 탭으로 진입한다. 별도 전체 화면 라우트는 만들지 않는다.
- 광장 탭은 실시간 메시지 목록과 입력 영역을 제공한다. 거래 게시판 탭은 게시글 목록·상세·작성 화면을 제공한다.
- 판매/구매 의도, 아이템 식별자, 수량, 희망 가격, 본문, 작성 시각, 상태를 표시한다.
- 게시글 작성 시 서버가 아이템·수량·가격 형식을 검증한다.
- MVP에서는 게시판 글이 거래소 체결을 대신하지 않는다. 실제 판매 등록·구매·정산은 기존 거래소 흐름을 사용한다.
- 게시글은 `ACTIVE → CLOSED|EXPIRED → DELETED` 상태 전이를 갖는다. 작성자는 활성 글을 닫거나 삭제할 수 있고, 만료 글은 읽기 전용이다. 끌어올리기는 MVP에서 제공하지 않는다.
- 게시글에도 신고를 제공한다. 차단은 광장 메시지와 거래 게시글 모두에 적용하며, 차단한 유저의 콘텐츠를 해당 사용자 조회 결과에서만 숨긴다.

### 전송 전 필터링

서버는 메시지와 거래 게시글을 저장·브로드캐스트하기 전에 다음을 검사한다.

1. 길이·빈 문자열·반복 문자·링크·도배 빈도 검증
2. 욕설·비속어·성희롱·혐오·사기 유도 표현 탐지
3. 한글 띄어쓰기·기호 삽입·반복 문자 등 우회 표현 정규화
4. 정상 게임 용어와 아이템명에 대한 허용 목록 확인
5. 차단 사유와 사용자가 수정할 수 있는 안내 반환

유해 표현의 정확한 목록과 차단 단계는 운영 정책 문서에서 별도로 확정한다. 필터 정책의 정본은 운영 정책 문서, 필터 사전의 버전과 변경 이력은 서버 관리 데이터가 소유한다. 차단된 원문은 일반 조회·브로드캐스트에 포함하지 않으며, 신고·운영 검토에 필요한 원문·정규화 결과·판정 코드의 접근 권한과 보존 기간을 별도 정책으로 제한한다. 클라이언트는 미리보기용 검사를 제공할 수 있지만 서버 판정을 대체하지 않는다.

### 제재 단계

- 1단계: 전송 차단과 규칙 안내
- 2단계: 반복 또는 운영자 확인 후 일정 시간 채팅 금지
- 3단계: 심각하거나 반복적인 위반은 계정 제재 검토

신고 누적만으로 즉시 계정 정지를 자동 확정하지 않는다. 신고는 증거와 운영 큐를 만들고, 정책에 정한 일부 명백한 반복 행위만 자동 채팅 제한 후보로 삼는다. 운영자 역할은 `MODERATOR`와 `ADMIN`으로 분리하며, 게시글·메시지 삭제와 채팅 금지는 MODERATOR, 계정 제재와 제재 해제·이의 처리 권한은 ADMIN이 가진다. 모든 운영자 결정은 대상·사유·증거 스냅샷·결정자·시각·이전/이후 상태를 감사 로그에 남기고, 이용자는 제재 사유와 종료 시각을 확인하며 제재 이의를 제출할 수 있다.

### UI 방향

기존 `CozySharedNavigation`과 공통 HUD의 디자인 원칙을 유지한다.

- 밝은 아이보리 종이 패널
- 햇빛 받은 황금빛 목재 프레임
- 짙은 초콜릿색 본문과 한글 제목
- 코랄 강조색: 선택, 신고, 위험 안내
- 시안: 읽지 않음·새 정보 배지
- 초록: 정상 게시·전송 가능 상태
- 기존 Jua 계열 서체와 종이 프레임 패턴 재사용
- 전투 중에도 채팅 패널을 열고 닫을 수 있지만 전투 상태·타이머는 중단하지 않음
- 상태별 UI를 제공한다: 로딩, 빈 광장, 빈 게시판, 전송 중, 전송 차단, 연결 끊김, 재연결 중, 운영자 삭제, 차단된 작성자 숨김.
- 키보드 포커스 순서와 화면 낭독 이름을 제공하고, 코랄·시안·초록만으로 상태를 구분하지 않는다. 좁은 화면에서는 패널을 단일 열로 표시하고 입력·신고 메뉴가 화면 밖으로 밀리지 않게 한다.

## MVP 범위와 구현 게이트

첫 PR의 유저 노출 범위는 광장 메시지, 거래 게시판, 서버 전송 전 필터, 메시지·게시글 신고, 개인 차단, MODERATOR의 콘텐츠 삭제와 기간제 채팅 금지다. `ADMIN`의 계정 제재·제재 해제·이의 처리는 첫 PR의 유저 노출·인수 범위가 아니다. 해당 기능은 운영 API·감사 로그 계약만 설계하고, 별도 운영 게이트를 통과한 뒤 후속 PR에서 활성화한다. 계정 제재와 이의 처리 UI가 준비되지 않은 상태에서는 광장 기능을 운영 환경에 노출하지 않는다.

첫 PR에서 제외한다.

- 1:1 메시지, 친구·길드 채널, 음성·이미지·파일 첨부
- 자동 분류 모델, 자동 계정 정지, 실시간 글로벌 랭킹
- 거래 게시글에서 거래소 체결·자동 가격 제안·아이템 소유권 이전
- 게시글 끌어올리기, 외부 링크·연락처 공유, 필터 사전의 운영자 UI 편집

운영 활성화 전 필수 게이트는 권한 검사, 신고 증거 보존, 삭제·채팅 금지 감사 로그, 필터 사전 버전 고정, 이의 처리 경로, no-deploy 기능 플래그 확인이다.

## Recommended Contracts

- 전송 방식은 기존 HTTP API와 짧은 polling으로 시작한다. 실시간 소켓은 첫 PR에서 사용하지 않는다. 서버는 `createdAt`, 단조 증가 `eventId`, `resourceType`으로 광장과 게시판 스트림을 정렬한다. 생성·삭제·채팅 금지 결과는 다음 polling 응답에 반영한다.
- 모든 mutation은 `Idempotency-Key`를 필수로 받는다. 키 유일성은 `accountId + resourceType + key`이고 보존 기간은 7일이다. 동일 키·동일 payload는 저장된 결과를 반환하며, payload hash가 다르면 `409 IDEMPOTENCY_KEY_REUSED`를 반환한다. 처리 중 동일 키는 기존 command 상태를 반환하고, DB command row·도메인 row·Outbox event를 같은 트랜잭션으로 확정한다.
- 목록 cursor는 불투명하고 `(createdAt, eventId)` 정렬의 exclusive-after 기준이다. cursor는 `resourceType`, 필터, snapshot version을 포함한다. 다음 페이지와 polling은 cursor 이후만 반환하고 eventId로 클라이언트 중복을 제거한다. cursor가 만료되면 서버는 새 snapshot의 첫 페이지와 `CURSOR_RESET`을 반환한다. 클라이언트는 새 snapshot을 기준으로 현재 화면을 교체하며 이전 이벤트와의 겹침은 eventId로 제거한다.
- 전송 전 필터가 timeout·내부 오류이면 저장하지 않고 재시도 가능한 오류를 반환한다. 필터 결과는 `ALLOW`, `BLOCKED_POLICY`, `BLOCKED_RATE_LIMIT`으로 구분한다. 연결 오류 동안 입력은 로컬 임시 보관하지 않고, 사용자가 다시 전송해야 한다.
- 차단 목록은 서버 조회, polling 결과, 상세 조회, 읽지 않은 수, cursor 재조회에 동일하게 적용한다. 이미 표시된 행은 차단 즉시 숨기고, 캐시·상세 화면·신고 작성 화면에서도 같은 유저 콘텐츠를 숨긴다. 운영자 조회·신고 증거 조회에는 차단을 적용하지 않는다.
- 운영자 감사 데이터의 책임자는 운영 도메인이고 접근 역할은 `MODERATOR`·`ADMIN`으로 제한한다. 감사 데이터에는 원문·정규화 원문·판정 코드·신고 사유·증거 대상·결정 전후 상태·결정자·시각을 포함한다. 일반 사용자에게 원문을 노출하지 않는다. 보존 기간·삭제·법적 보존 예외·계정 삭제 시 처리 규칙은 개인정보 정책 확정 전까지 운영 활성화의 차단 조건으로 둔다.
- 첫 PR의 MODERATOR는 신고 증거 확인, 콘텐츠 삭제, 기간제 채팅 금지를 수행한다. ADMIN 계정 제재·해제·이의 처리의 권한과 상태 전이는 후속 운영 게이트 문서에서 확정하며 첫 PR 성공 기준으로 주장하지 않는다.

## Success Criteria

첫 PR과 운영 활성화 기준을 분리한다.

첫 PR:

- 유저가 전투 화면의 우측 패널에서 광장과 거래 게시판을 전환하고, 전투 타이머와 상태는 변하지 않는다.
- 유해 표현 메시지는 저장·polling 전에 차단되고, 사용자는 차단 사유와 수정 안내를 받는다.
- 고정 경고문은 채팅 화면에서 항상 확인 가능하고 상세 정책으로 이동한다.
- 사용자는 메시지 또는 게시글 단위로 신고하고, 특정 유저를 차단해 자신의 조회·polling·상세·읽지 않은 수에서 해당 유저 콘텐츠를 숨긴다.
- MODERATOR는 신고 증거를 확인해 게시글·메시지를 삭제하거나 기간제 채팅 금지를 적용하며 감사 로그가 남는다.
- 동일 명령 재시도와 연결 재시도에서 메시지·게시글·신고가 중복 생성되지 않는다. payload 충돌은 명시적 오류로 끝난다.
- cursor 페이지와 polling은 exclusive-after 순서를 보장하고, cursor reset 후 eventId 중복 없이 복구된다.
- 로딩, 빈 상태, 전송 중, 차단, 연결 오류, 재연결, 운영자 삭제 상태를 텍스트와 아이콘으로 표현한다. 키보드로 탭·입력·더보기·신고·차단을 조작할 수 있고, 새 메시지·오류·삭제는 적절한 live-region 알림으로 전달한다.
- 기존 코지 픽셀 HUD와 색상·프레임·서체가 시각적으로 일관된다.
- PR은 main에 병합하되 운영 배포 파이프라인은 실행하지 않고, 기능 플래그는 기본 비활성이다.

운영 활성화 후속 게이트:

- ADMIN의 계정 제재·해제·이의 처리와 그 권한 경계가 구현·검증된다.
- 원문·신고 증거·감사 로그의 보존·삭제·접근 정책이 확정되고 검증된다.
- 운영자 도구와 필터 사전 변경 절차가 준비된다.

## Distribution Plan

이번 단계의 산출물은 설계 문서다. 구현 단계에서는 `feature/chat-design`에서 기능 브랜치를 파생하거나 해당 브랜치를 구현 브랜치로 사용하고, 테스트·리뷰가 끝난 뒤 PR로 main에 병합한다. 병합 이후 운영 배포는 실행하지 않으며, 배포 여부는 별도 결정과 작업 문서에서 관리한다.
