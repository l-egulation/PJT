## 책임

이 문서는 계정, 캐릭터 진행, 브라우저 로컬 저장, 탭·브라우저 종료 복원과 웹 UI의 상태 공유를 소유한다. 전투 공식·아이템 정의·거래 규칙은 소유하지 않는다. 치장 상태의 상세 규칙은 [치장 SSOT](../cosmetics/ssot.md)가 소유하며, 이 문서는 계정별 서버 권한 상태와 동기화 경계만 참조한다.

Kakao는 비즈니스 앱 권한이 없는 구성에서도 `openid`와 검증된 `sub`만으로 가입·로그인을 지원하며 이메일·프로필 닉네임을 요구하지 않는다. 공급자 access·refresh·ID token은 인증 처리 뒤 장기 저장하지 않는다. |

| 거래 가능한 쌀·재료·아이템·매물·정산 | 서버 권한 데이터 | 클라이언트 계산값을 최종값으로 인정하지 않음 |
| 계정 탈퇴·이메일 재사용·캐릭터 카드 | 서버 계정 상태·치장 장착 상태 | `deleted_at` soft delete와 이메일·닉네임 익명화 후 세션·인증을 차단한다. 설정 카드는 장착 치장 이미지, 없으면 닉네임 첫 글자를 표시한다. |

| 콘텐츠 버전·저장 버전·마지막 시각 | 서버 진행 저장과 로컬 체크포인트 | 재실행·마이그레이션과 중복 처리의 입력 |

로컬 캐시는 서버 권한 자산·진행·성장·스킬·치장 상태의 표시·동기화 대기 상태일 뿐, 소유권이나 최종 상태를 의미하지 않는다. 치장 소유권·등록/미등록/예약 재고·성급·외형 슬롯·뽑기 결과·세트 효과도 [치장 SSOT](../cosmetics/ssot.md)가 정한 서버 확정 상태를 표시할 뿐 로컬에서 확정하지 않는다.

## 최근 전투 기록

- 서버는 사용자별 최신 전투 사건 50건을 발생 시각 역순으로 보관한다. 51번째 사건이 확정되면 가장 오래된 기록을 제거한다.
- 기록 대상은 스테이지 입장·클리어·실패·던전 입장·복귀다. 각 기록은 사건 종류, 발생 시각, 관련 스테이지 또는 던전 식별자와 사용자 메시지에 필요한 결과 코드를 가진다. 스테이지 클리어 기록은 해당 전투의 스테이지 입장 시각, 전투 시간, 사이클 회복 직전 남은 HP, 획득 경험치·쌀과 실제 지급된 모든 아이템의 표시명·수량을 함께 보관한다.
- 스테이지 실패 기록은 실패 코드, 스테이지 입장 시각, 처치한 일반 몬스터 수, 마지막으로 전투한 몬스터의 남은 HP, 전투 시간, 플레이어의 남은 HP, 해당 전투에서 획득한 경험치·쌀과 실제 지급된 모든 아이템의 표시명·수량, 실패 당시의 전투 결과를 재현·설명하는 데 필요한 콘텐츠 버전·캐릭터 전투 스펙 스냅샷을 함께 가진다. 성공하지 않은 추정 실패는 기록하지 않는다.
- 스테이지 상세는 최근 50건 중 선택한 스테이지의 가장 최근 실패 1건만 반환한다. 해당 기록이 없으면 실패 기록 없음 상태를 반환한다.
- 전체 메뉴의 전투 기록은 같은 서버 기록을 사용한다. 화면별 로컬 기록을 두 번째 정본으로 만들지 않는다.

## 단일 상태 엔진

MVP의 펫 UI와 관리 UI는 하나의 브라우저 문서, 하나의 게임 인스턴스, 하나의 전투 타이머를 공유한다. 별도 탭·팝업은 기준 구현이 아니며, 한 상태 변경은 이벤트 또는 명령으로 한 번만 적용하고 화면은 그 상태를 구독해 표현한다.

## 실행 중 진행

백그라운드 탭은 렌더링 갱신과 브라우저 타이머에 의존하지 않고 서버 기준 경과시간 또는 서버 확정 결과로 메인 전투·성장·보상을 계속 진행한다.
- 로그아웃·탭 discard·기기 절전·네트워크 단절·브라우저 종료는 게임 세션의 heartbeat를 중단한다. 새로고침은 같은 탭의 저장된 게임 세션을 heartbeat로 재개한다. 저장값을 잃은 새 문서가 새 세션을 요청해도 서버는 1분 미만의 기존 활성 세션을 그대로 반환하며, 1분 이상 무신호일 때만 오프라인 결과를 고정하고 새 세션을 연다.
- 오프라인 경과시간은 마지막 heartbeat 또는 명시적 로그아웃 서버 시각부터 첫 재로그인 서버 시각까지의 UTC 차이다. 1분 미만이면 보상 작업을 취소하고, 1분 단위로 내림해 최대 480분(8시간)만 인정한다.
- 보상률은 복귀 시점의 현재 스테이지를 1분 자동전투했을 때 얻는 쌀·경험치·주력 재료 기대량의 50%다. 인정된 분 수만큼 비례 지급한다.
- 서버는 실제 오프라인 경과시간과 보상 적용시간을 함께 고정해 UI에 표시한다. 계정당 `ACTIVE` 또는 `CLAIMABLE` 오프라인 작업 하나만 허용하며, claim은 UUID 멱등성 키로 한 번만 자산에 반영한다.
- 서버는 계정당 하나의 게임 실행 세션만 허용한다. 새 실행 세션이 열리면 기존 실행 세션을 대체하고 단일 전투 타이머와 명령 멱등성은 새 실행 세션을 기준으로 한다.

## 보안 경계

- 클라이언트는 command와 idempotency key를 보낸다.
- 서버는 계정 권한, 현재 진행, 현재 보유량, 거래 가능 여부, 스킬 진행 상태와 콘텐츠 버전을 다시 검증한다.
- 서버는 치장 해금·티켓·`registeredQuantity`·`unregisteredQuantity`·`reservedQuantity`·`cosmeticStar`·6부위 외형 착용 상태와 배너/상자 카운터를 다시 검증하고, 뽑기 결과·등록·도감 표시 상태·세트 효과는 [치장 SSOT](../cosmetics/ssot.md)와 [치장 뽑기 요구사항](../../70-plans/cosmetic-gacha/requirements.md)에 따라 확정한다.
- rewardId 또는 commandId는 클리어·해금·반복 설정·중복 지급과 중복 스킬 성장을 막는 키다.
- 서버 권한 진행·자산·스킬·치장 상태의 동기화 실패는 복구 가능한 상태로 남기며 로컬 값으로 최종 확정하지 않는다.
- 비밀번호 재설정 요청은 이메일·IP별 요청 제한을 적용하되 제한 여부나 계정 존재 여부를 응답으로 구분하지 않는다. 재설정 토큰은 URL fragment에 실어 HTTP 요청·접근 로그에서 분리하고 서버에는 SHA-256 해시만 저장한다.
- 소셜 인증은 서버 주도 Authorization Code를 사용한다. 지원 공급자에서는 PKCE S256을 함께 사용하고, 콜백의 일회성 `state`와 OIDC `nonce`를 검증한다. OIDC ID token은 허용된 RS256 서명 키, 정확한 issuer, client ID audience와 만료를 검증한 뒤에만 `sub`를 사용한다. Naver는 access token으로 HTTPS 사용자 정보 API를 호출해 공급자 subject를 확인하며 token을 저장하지 않는다.
- 공급자 설정은 서로 독립적이다. client ID·secret과 필수 endpoint/issuer가 완전하지 않거나 비활성화된 공급자만 로그인 화면에서 숨기고, 다른 공급자는 계속 제공한다.

관련 실행 항목은 [B 작업](../../wiki/06-delivery/tasks/B-account-storage/_index.md), 저장 권한의 경계는 [책임 경계](../../50-architecture/boundaries.md)에서 확인한다.
