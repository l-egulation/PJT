# Design: PVP Arena

Generated by /office-hours
Branch: feature/pvp-arena
Status: APPROVED

## Problem Statement
메이플키우기 스타일의 PVP 아레나를 기존 한짝 전투 시스템에 추가한다. 양쪽 캐릭터가 각자의 스킬 우선순위에 따라 공격하고, 아레나 전투에서만 최대 HP를 30배로 적용한다.

## What Makes This Cool
기존 자동전투의 스킬 운용을 두 플레이어에게 동시에 적용한다. 결과는 서버가 계산하지만 클라이언트는 양쪽의 스킬 사용과 피해 사건을 재생하므로, 단순 승패 비교가 아니라 상대 빌드가 어떻게 무너졌는지 확인할 수 있다.

## Constraints
- PvE 전투 수치와 진행에는 영향이 없어야 한다.
- 아레나 전투의 최대 HP 배율은 ARENA 모드에서만 30배다.
- 공격력, 방어 관통, 스킬 효과와 쿨다운 규칙은 기존 전투 규칙을 재사용한다.
- 양쪽 캐릭터의 장비·스킬·보석 상태는 전투 시작 시 서버 스냅샷으로 고정한다.
- 서버가 seed, 스탯, 스킬 순서, 피해량, 승패와 이벤트 순서를 최종 결정한다.
- 네트워크 단절·재접속 시에도 전투 결과를 재현할 수 있어야 한다.

## Premises
- 1차 구현은 실시간 입력 대전이 아닌 서버 판정 비동기 전투다.
- 상대는 계정의 아레나 방어 스냅샷으로 표현하고, 공격자와 방어자의 현재 온라인 상태를 요구하지 않는다.
- 전투 코어는 양쪽 전투원을 처리하도록 확장하되, PvE 호출 경로의 기존 입력과 결과는 보존한다.
- 초기 매칭은 점수 범위 내 상대 목록으로 제한하고, 시즌·보상·부정행위 도구는 최소 수직 슬라이스 범위로 둔다.

## Approaches Considered
### Approach A: Existing combat core extension (selected)
`sim-core`에 양쪽 전투원과 ARENA 모드를 추가하고 HP 배율을 모드별 입력으로 둔다. `modules/battle`에 아레나 스냅샷·전투 서비스·이벤트 저장을 추가하고, `apps/web`에 아레나 화면과 이벤트 재생을 추가한다.

선택 이유: 기존 서버 판정·스킬·결정론 전투 규칙을 재사용해 구현량과 PvE 회귀 위험을 줄인다.

### Approach B: Dedicated arena module
아레나 계산과 API를 별도 모듈로 분리한다.

보류 이유: 장기 확장성은 높지만 현재 수직 슬라이스에서 전투 규칙 중복과 결과 불일치 위험이 크다.

## Recommended Approach
- `packages/sim-core`: `ARENA` 전투 입력, 공격자·방어자 상태, 양쪽 행동·쿨다운·피해 이벤트, 승패 결과를 추가한다. 기존 PvE 실행기는 기존 단일 전투 경로로 유지한다.
- `modules/battle`: 아레나 상대 조회, 방어 스냅샷, 공격 전투 시작·완료, idempotency, 전투 기록을 담당한다.
- DB: 아레나 프로필/점수, 전투 스냅샷, 전투 이벤트와 결과를 별도 테이블로 저장한다. 기존 PvE 진행·인벤토리·거래 테이블은 갱신하지 않는다.
- API: 상대 목록, 방어 프로필, 전투 시작, 전투 상태/완료, 내 전투 기록을 제공한다.
- Web: 아레나 진입, 상대 선택, 양쪽 HP/스킬 이벤트 재생, 승패와 기록을 제공한다. 기존 전투 화면과 런타임 상태는 공유하지 않는다.
- HP: 양쪽 `maxHp`에만 30을 곱하고, 현재 HP와 피해 계산의 나머지 입력은 아레나 스냅샷 기준으로 계산한다.

## Open Questions
- 시즌 기간과 점수 변동식
- 상대 목록의 정확한 매칭 범위와 방어 스냅샷 갱신 주기
- 아레나 보상 재화와 보상 지급 시점
- 실시간 관전·재대결·리플레이 공유의 후속 범위

## Success Criteria
- 서버가 같은 양쪽 스냅샷과 seed에 대해 같은 아레나 결과·이벤트를 반환한다.
- 양쪽 액티브 스킬이 각자의 우선순위와 쿨다운에 따라 실행된다.
- 양쪽 최대 HP만 30배가 되고 PvE 결과는 기존과 동일하다.
- 전투 완료 재시도는 결과·보상·점수를 중복 적용하지 않는다.
- 브라우저에서 상대 선택부터 전투 이벤트 재생과 결과 조회까지 동작한다.
- API·sim-core·웹 테스트와 실제 로컬 스모크가 통과한다.

## Distribution Plan
기존 game-api와 web 배포 파이프라인에 포함한다. 아레나 전용 Flyway migration은 애플리케이션 배포 전에 적용한다.

- “피통은 30배로 조정 아레나에서만 적용”이라고 밸런스 변경의 적용 범위를 분리했다.
- 구현보다 먼저 초안을 요구했고, 이후에는 새 브랜치·설계·PR·배포까지 한 흐름으로 결정했다.
