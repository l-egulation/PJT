# 리밸런싱 산술 검증 메모

수치 정본은 [장비 SSOT](../../30-domain/items/equipment/ssot.md)와 [최초 보상 콘텐츠](../../60-content/stages/first-clear-rebalance.md)다. 아래는 그 수치의 검증 결과이며 비용표를 대체하지 않는다.

- 1~4장 최초 보상 선형 정수 배분의 스테이지별 합계가 M1·M2·M3·쌀·보석함 구간 총량과 일치함을 확인했다.
- 노말 장비 구간 합산, 희귀·영웅 부위별 20%·30%·50% 구간 배분과 29회 합계가 등급 총량과 일치함을 확인했다.
- 환산가치 `1:5:25`에서 노말 9,996, 희귀 34,200, 영웅 185,400이 일치함을 확인했다. M1 비감소 제약을 도입하며 기존의 희귀 이후 1.5배 증가 규칙은 폐기했다.
- 비감소 제약을 M1뿐 아니라 모든 세대로 확장했다. 영웅 M2가 희귀 M2의 29강 비용 23개 아래인 2개에서 시작하던 급락을 없애고, 영웅부터는 세대별 소비량을 드롭 가중치와 같은 1/5 사다리에 맞췄다(영웅 부위별 M2 120→2,060, M3 120→412). 전설은 이미 같은 사다리였으므로 변경하지 않았다.
- 승급 스타터가 현재 등급 29→30 비용과 다음 등급 신규 세대 1→2 비용의 10% 올림을 사용함을 확인했다. 비어 있던 영웅→전설 행을 같은 규칙으로 채웠다(M1 573·M2 115·M3 23·M4 1·쌀 2,670). 이전 값은 재료 M4 1개·쌀 0으로 규칙을 따르지 않았다.
- 1~79레벨 목표시간을 기존의 1/3로 계산한 1-10·2-10·3-10·4-10 P50 값과 P90 1.25배 상한을 대조했다.
- 3장 보석함 합계 120개와 2-10 스타터 6개를 확인했다.

문서 산술 검수 결과는 A-05가 소유한다. 2026-09-12에는 적용 콘텐츠와 런타임 도메인 규칙을 읽는 결정론 모델로 300계정 축소 표본을 실행했고, 2026-09-14에는 리밸런싱 전용 스테이지·치장 콘텐츠의 비변경 회귀를 보강한 뒤 같은 표본을 재실행했다. 결과 파일은 [진행 CSV](../mvp-release/verification/progression-rebalance-v1.csv)와 [경제 JSON](../mvp-release/verification/progression-rebalance-v1-economy.json)이다.

## 관찰 결과

- 적용 `stages.json`의 실제 20일반+보스/보스 단독 편성을 실행한 300개 기준 빌드 표본에서 1-10·2-10·3-10·4-10 P50은 70.6·245.6·519.5·891.7분, P90은 70.7·245.7·519.7·891.9분이었다.
- 챕터별 4·7·10 성장벽 12개에서 기준 빌드 성공률은 90~100%, 해당 성장축 부족 빌드 성공률은 0%였다. 보스 검사축은 스테이지 SSOT의 챕터별 회전을 따르고 3-10·4-10 기준 보석 프리셋을 포함했다.
- 별도 account 경제 표본은 각 계정이 실제 보유한 레벨·장비·최초 해금 스킬로 같은 전투를 실행하고, 실제 재료·쌀만 장비에 소비한다. 4-10 P50은 거래 이용 899.0분, 거래 미이용 1,168.8분, 유동성 부족 897.5분이며 노말→희귀와 희귀→영웅 최초 승급 P50 stage index는 11과 31이었다(희귀 per-slot M1 500·승급 M1 28 등 보정 이전 M1 비용으로 측정한 값이며, 보정된 비용에서의 재측정은 A-05가 추적하는 10,000계정 재시뮬레이션 완료 후로 미룬다).
- peer-only 시장 표본은 시스템 판매자 수량 0을 유지했고, 체결 413,458개·미체결 993,608개·수수료 20,720,032쌀을 기록했다. 거래 이용·미이용·유동성 부족 행동군을 별도 집계했다.
- 1장 1~9 반복 한 사이클은 M1 50개, 10스테이지 반복 아이템은 0개였다.
- 격리 PostgreSQL과 실제 브라우저에서 신규 계정 1-1·1-2 최초 클리어의 stage별 단일 reward row, 즉시 쌀·재료·Normal 1 스킬 지급, 다음 stage 진행, 수령함 진입·reload 복원과 responsive layout을 확인했다.
- 2026-09-14 재검증에서 `writeProgressionPackages()` 실행 전후 `progression-rebalance-v1/stages/stages.json`과 `cosmetics/cosmetics.json`의 본문이 동일함을 회귀 테스트로 명시했다. 이번 변경은 적 HP·공격력·방어력, 경험치·쌀, 장비 비용, 재료 드롭 수치를 변경하지 않는다.

## 남은 검증

- Windows 가상 메모리 commit 한도 오류 때문에 10,000계정 시뮬레이션은 완료하지 않았고, 300계정 표본만 현재 증거로 사용한다.
- live pending 생성·capacity error·claim success·동시 claim과 backfill dry-run·apply·replay의 자동 PostgreSQL 회귀는 통과했으나 실제 운영 데이터 대상으로는 실행하지 않았다.
- web 전체 회귀 suite는 통과했다. 전체 server suite는 실행하지 않았고, browser console에는 progression과 무관한 기존 chat endpoint 403/NPE가 남아 있다.
- 80레벨 이후와 5~10장, 4-10 추가 보상, raid 보상과 cosmetic balance는 이번 검증 범위에서 제외한다.
