# 행동 발동 자원 계약과 현재 어댑터

[분야 개요](README.md)

[목표 자원 경계](../../architecture/project-structure.md#5-도메인주요-객체소유권)의 초기 구현이다. `IActionResources`가 실행당 발동 결과를 보관하고 `IActionResourceSource`가 무기 원본의 실제 소비/스탯 조회를 제공한다. 현재 `WeaponActionResourceSource`는 기존 테스트 프로필의 `WeaponState`에 연결하고, 충전 숫자 상태는 Equipment가 소유한다. 기존 `ChargePool`은 그 원본의 명령/조회 어댑터다. 무기/재고·Run 조립 전체를 이행한 것은 아니다. 충전·정비·발동 시점은 [무기·잉크](../../../design/equipment/rules.md)와 [전투 규칙](../../../design/combat/rules.md)을 유지한다.

## 키·시간·스냅샷

`ActionResourceKey`는 공격 실행 ID·원본 무기 인스턴스 ID·기본/특수 분류를 묶는다. `WeaponState.InstanceId`는 Equipment 인스턴스가 생성 때 한 번 정한 ID를 조회하며 교체/전투 리셋으로 바꾸지 않는다. 현재 테스트 프로필 객체의 실행 식별이며 실물 아이템의 저장/재획득 식별·재고 구현이 아니다.

`ActionResourceSnapshot`은 키·발동 콜백의 시뮬레이션 시각·피해 배율을 읽기 전용으로 보관한다. 기본 공속과 행동 시간/형상은 기존처럼 시작 정의에 고정하고 피해 증가율은 실제 발동에 캡처한다. 발동 콜백 시각을 논리 접촉 시각으로 소급하거나 새 타이머를 누적하지 않는다. 이후 슬롯 편집/교체/표시 갱신이 시작된 공격·독립 효과의 피해를 다시 계산하지 않는다.

## 실행 결과와 소유권

`Combat/Contracts`와 `Combat/Runtime/Application/ActionResourceExecution`은 UnityEngine·씬·장비 구현을 참조하지 않는다. 실행기는 원본 소스와 키를 명시적으로 받고 결과 한 개만 보관한다. 별도 쿨타임 복사본이나 전역 실행 이력을 만들지 않는다.

`TryActivate`는 기대 실행 ID와 유한한 0 이상 시각을 검사한다. 오래된/잘못된 입력·콜백 재진입은 소스를 호출하거나 현재 결과를 바꾸지 않는다. 첫 유효 요청의 `Succeeded`/`Rejected`/`Cancelled`/`Failed` 결과를 캐시하며 같은 실행은 나중에 조건이 바뀌어도 재소비/재시도하지 않는다. 새 행동은 새 실행 ID를 갖는다. 성공 스냅샷의 실행/무기/분류/시각이 요청과 다르거나 소스가 예외/결과 누락을 반환하면 명시적인 실패로 보관한다. 제공자가 이미 확정한 상태의 자동 롤백은 제공하지 않는다.

소스의 거부는 자원 미소비를 보장해야 한다. 현재 어댑터는 키/시각과 스탯 캡처를 검증한 뒤 특수만 기존 `ChargePool.Spend`를 호출한다. 기본 공격은 특수 충전을 소비하지 않는다. 충전형의 순차 회복/추가 사용 시 타이머 보존·정비 부담 정규화·비활성 무기 회복은 같은 기존 원본을 사용한다. 원본 소스의 직접 호출은 실행당 중복 방지를 제공하지 않으며 실제 캐스트는 항상 `ActionResourceExecution`을 거친다.

반환은 새 발동을 차단하고 기존 성공/실패 결과를 읽을 수 있게 남긴다. 이미 소비한 충전을 환불하거나 시작된 독립 효과를 종료하지 않는다. 발동 전 취소·배치/대상 자격 실패는 소비 없이 자기 실행권만 반환한다. 완료·취소·실패·파괴는 같은 중복 가능한 반환을 사용한다. 리셋/소유 효과 제거·같은 연막 교체는 Unity의 지연 파괴 전에 실행권을 먼저 닫는다.

## Equipment 충전 원본

`Equipment/Contracts/IWeaponCharges`는 Reset·Tick·Spend·Debt·Reconfigure와 읽기 전용 `ChargeState` 조회를 제공한다. `Equipment/Runtime/WeaponResources.CreateCharges`가 이 계약의 실제 소유자를 만든다. 가변 구현과 충전 수/용량/주기/다음 회복시각은 Equipment 내부에만 둔다. `Read`는 그 시점의 값 복사이며 조회 자체로 시각을 진행하지 않는다. `Tick`/`Spend`/`Debt`/`Reconfigure`에는 기존 시뮬레이션 시각을 명시적으로 전달한다.

순차 회복과 회복 부담 정규화는 [검·둔기 명세](../../../design/equipment/weapons/forms/melee.md#충전정비취소의-예외)를 유지한다. 추가 사용은 이미 진행 중인 첫 회복시각을 초기화하지 않고, 1↔3 충전/주기 변경은 같은 잔여 부담을 보존한다. float 연산 순서·epsilon·최소 용량/주기 호환도 기존 경로를 유지한다. 명시적인 테스트 Reset만 현재 용량을 채운다. 정비를 충전 리셋으로 바꾸지 않는다.

`Deviant.Combat.ChargePool`은 `IWeaponCharges` 참조 하나를 보관하고 기존 프로퍼티/명령을 전달한다. 별도 타이머·충전 수·동기화 캐시는 없다. 같은 소유자를 주입한 다른 어댑터도 같은 원본을 읽으며, 기본 생성은 각 무기별로 별도 원본을 만든다. 기존 Unity 쪽 호환 조립은 Equipment의 공개 생성 진입점을 호출한다. 순수 Combat.Contracts/Execution은 Equipment 구현을 참조하지 않으며 Equipment 계약/실행도 Combat·UnityEngine·UnityEditor를 참조하지 않는다. 실제 게임/실험장 소비와 비활성 무기 회복은 이 소유자를 사용한다.

## Equipment 능력치 슬롯 원본

`IWeaponStats`는 현재 테스트 프로필의 능력치 잉크 5칸을 SetSlot·ReplaceSlots·Clear 명령과 불변 `WeaponStatSnapshot`으로 제공한다. `StatInkKind`의 Empty/BasicDamage/SpecialDamage/BasicSpeed/SpecialCooldown은 기존 0~4 슬롯 값의 이름이며 신규 아이템 카탈로그/전용 잉크 콘텐츠가 아니다. 실제 슬롯 배열과 스탯 계산은 Equipment 내부에만 둔다. 기본/특수 피해 증가를 따로 +20% 합산하고 기본 공속은 +10% 합산한다. 쿨감 슬롯은 기존 감소율을 제공하고 실제 쿨타임의 상한/적용은 기존 발동/정비 경계를 유지한다.

`WeaponStatSnapshot`은 슬롯 목록을 복사하고 읽기 전용으로 제공한다. 이전 스냅샷과 입력 배열 편집은 현재 원본을 바꾸지 않는다. 일괄 교체는 5칸과 지원 종류 전체를 검증한 뒤 반영하며 무효 입력은 원본을 유지한다. 슬롯 변경은 충전 수/타이머·형태/특수 선택·무기 실행 ID를 바꾸지 않는다. 실제 쿨타임 주기 적용은 `IEquipmentCommands`/`IWeaponInstance.Reconfigure`에서 정규화 부담을 유지하며 수행한다. 이 저수준 슬롯 명령이 제품의 안전 정비/재고 판정을 대신하지 않는다.

기존 `WeaponState.StatSlots`는 `StatSlotView`로 연결한다. 인덱스 편집은 Equipment 명령에 전달하고 Length/열거/Clone 조회를 지원한다. Clone은 분리된 int 배열이며 원본 배열이 아니다. 배열을 직접 비우거나 덮어쓰던 기존 도구/검사는 Clear/CopyFrom 명령으로 이행한다. `WeaponState`의 기본/특수 피해·공속·쿨감 조회도 Equipment 스냅샷을 읽고 별도 슬롯/스탯 원본을 보관하지 않는다. 발사기 전환의 비활성 슬롯/효과 정책은 기존 소비/표시 경로를 유지한다.

## Equipment 무기 인스턴스 원본

`IWeaponInstance`는 프로필 무기 한 개의 실행 ID·`WeaponSelection`·스탯/충전 소유자를 묶는다. `WeaponResources.CreateWeapon`은 각 새 인스턴스에 별도 ID와 원본을 만들고, `WeaponSnapshot`은 선택·스탯·충전의 불변 조회를 제공한다. 같은 인스턴스를 보는 다른 호환 어댑터도 같은 ID·상태를 읽는다. 명시적으로 주입한 스탯 계약을 사용하는 기존 검증 조립도 지원한다.

`WeaponSelection`은 현재 카탈로그의 형태/특수 인덱스 쌍이다. 음수는 거부하고 쌍 전체를 한 명령으로 바꾸며 스탯/충전/ID를 초기화하지 않는다. 실제 카탈로그 참조 유효성과 정비 허용은 기존 플레이어/실험 조립이 검사하고, 검증한 선택·용량/기본 쿨타임의 반영은 아래 Equipment 정비 명령이 맡는다. 이 인덱스를 영구 콘텐츠 ID나 실물 아이템 저장 형식으로 사용하지 않는다.

`WeaponState`는 `IWeaponInstance`와 스탯/충전 뷰만 보관한다. 실행 ID·선택 인덱스의 두 번째 원본은 없다. 기존 인덱스 프로퍼티는 명령을 전달하고 플레이어 정비·A/B 설정/복원은 `Select`로 쌍을 함께 전달한다. 테스트 Reset은 같은 인스턴스/선택/슬롯을 유지하며 기존 규칙으로 충전만 초기화한다. 인스턴스의 실제 Run 수명/획득/바닥 아이템/저장 처리는 후속 범위다.

## Equipment 장착 목록과 활성 슬롯 원본

`IWeaponLoadout`은 현재 테스트 프로필의 장착 무기 두 개와 활성 슬롯을 소유한다. `WeaponResources.CreateLoadout`은 새 프로필 쌍을 만들거나 명시적으로 받은 두 `IWeaponInstance`를 연결한다. 입력 목록은 복사하며 없는 무기·중복 실행 ID·범위를 벗어난 초기 슬롯은 거부한다. 현재 프로필의 점유된 두 슬롯은 수명 동안 고정하며 획득/바닥 무기 교환·추가 보관·Run 시작 장비 정책을 제공하지 않는다.

`SelectSlot`은 범위를 검사한 뒤 활성 슬롯만 바꾼다. 무기 ID·형태/특수 선택·잉크·충전/회복시각은 유지하고 잘못된 명령은 이전 상태를 보존한다. `WeaponLoadoutSnapshot`은 활성 슬롯과 두 무기의 불변 스냅샷을 복사해 제공한다. 이전 조회는 이후 교체·정비·회복을 따라 변하지 않는다.

`CombatPlayer.weapons`는 인덱스/Length/열거를 지원하는 읽기 전용 `WeaponLoadoutView`다. 내부의 고정 `WeaponState` 뷰는 같은 Equipment 원본을 보며 캐스트/접근 효과가 참조하는 무기 객체를 조회마다 새로 만들지 않는다. 별도 활성 슬롯 원본은 없고 기존 `selected` 프로퍼티와 `Weapon`은 같은 Loadout을 조회한다. 테스트/실험의 직접 슬롯 선택은 저수준 프로필 명령이며, 일반 교체 입력의 실행 자격·예약/공격 우선순위·취소는 계속 `PlayerActionArbiter`/기존 호스트가 검사한다. 테스트 Reset은 기존처럼 활성 슬롯·무기 원본/선택/잉크를 유지하고 충전만 초기화한다. 비활성 무기도 기존 시뮬레이션 갱신에서 같은 충전 원본을 회복한다.

## Equipment 정비 명령

`WeaponConfiguration`은 현재 카탈로그에서 해석한 형태/특수 선택·용량·기본 쿨타임을 불변 값으로 전달한다. 양수 용량과 유한한 0 이상 기본 쿨타임을 요구한다. `IEquipmentCommands`는 장착 슬롯·기대 무기 ID·설정·시뮬레이션 시각을 받아 결과를 반환한다. 없는 슬롯·다른 무기·잘못된 시각/설정·같은 서비스의 재진입은 원본을 바꾸지 않는 `Rejected`다. `Succeeded`는 적용한 무기의 불변 스냅샷을 제공하며 기대 ID와 현재 슬롯의 무기 ID가 다르면 거부한다. 명령은 동기식이고 실행 이력/자동 재시도·Run 수명이나 제품 재고를 제공하지 않는다.

실제 `IWeaponInstance.Reconfigure`는 외부 스탯 조회와 쿨감의 유한성을 먼저 확인하고, 같은 소유자의 충전을 기존 부담 정규화로 재설정한 뒤 선택 쌍을 함께 반영한다. ID·스탯 원본·활성 슬롯과 다른 무기는 유지한다. 쿨타임 계산의 80% 상한/기존 float 식도 Equipment에 두며 `CombatRules.Cooldown`은 같은 함수를 조회한다. 스탯 조회 실패/누락·무효 쿨감은 선택/충전을 바꾸기 전에 실패한다. 외부 구현 예외나 잘못된 반환 스냅샷은 `Failed`로 진단하며 서비스가 외부 구현의 확정된 부작용을 자동 롤백하지 않는다.

`CombatPlayer.TryReconfigure`는 기존 `EditingAllowed`와 요청한 슬롯/카탈로그 참조·수치를 먼저 검사한다. 성공한 명령 뒤에만 기존 접근 표식과 연계 상태를 정리한다. 거부는 선택·쿨타임/충전·스탯·접근 표식을 유지하고 이유를 반환한다. 기존 void `Reconfigure`도 같은 경로를 사용한다. 테스트 장비 패널의 저수준 슬롯 편집·A/B 직접 설정과 실제 잉크 아이템/안전 정비 정책은 구분한다. 제품의 전투 종료·안전 정비·획득/교환·재고·저장 규칙을 새로 정하지 않는다.

## 공통 전투 연결

`CombatCast.Create`는 키를 정하고 기본 소스로 기존 무기 어댑터를 조립한다. 명시적 검증 소스를 주입할 수도 있다. 기존 행동·근접 기본 17타·직접 근접 특수 강베기/장침/반월참의 `MeleeActionHost`가 같은 자원 경계에서 발동 피해를 받는다. 물리/대상/설치 자격 검사는 기존 발동 순서대로 소비 전에 수행한다.

직접 근접 특수 3개는 공통 시간표를 사용해도 기본 공격으로 재분류하지 않는다. 실제 발동 때 특수 충전/피해 증가율을 읽고 기본 공속은 적용하지 않는다. 준비 취소의 미소비와 발동 후 취소/교체 뒤 회복은 기존 무기 원본을 유지한다.

`IMeleeActionHost.TryActivate`의 정상 거부는 타격/완료 콜백 없이 해당 행동을 실패로 끝내고 전체 시뮬레이션 예외로 만들지 않는다. 기존 호스트 예외의 시뮬레이션 실패 경계는 유지한다. `CombatCast.ResourceResult`/`ResourcesActive`는 결과와 실행권 수명을 구분해 조회한다. 실제 피해는 기존 Unity 판정/독립 효과 경로가 처리하며 표현 완료가 소비를 결정하지 않는다.

## 차지 정책과 발동 소비

레이피어/대검의 기본 특수는 `ChargeExecution`에 기존 전투 시각과 특수 유지 표본을 넘긴다. 최소보다 일찍 놓아도 최소 유지 시각까지 기다리고, 계속 유지하면 최대 시각에서 자동 해제한다. 해제 지연·최소 모션 종료에 더할 값·기준 피해 보간은 시작 `ChargeDefinition`에서 한 번 확정한다. 이는 차지 유지 시간이며 단검의 3충전 자원과 다른 개념이다.

차지 정책은 자원을 소비하거나 타격/위치를 바꾸지 않는다. `ChargedMeleeDefinition`을 사용하는 레이피어/대검 기본 특수의 Unity 연결은 시작 nearest 기하로 발동 자격을 재검사한 뒤 동일 `IActionResources`로 실제 발동 스탯/소비를 확정한다. 시작/예약의 대상 검사도 같은 불변 정의를 읽는다. 발동 전에 대상을 잃으면 기존 0.10초 실패 회복을 유지하고 자원을 소비하지 않는다. 해제 전에 취소하면 미소비이며 발동 후 취소·교체는 이미 소비한 원본 회복을 유지한다. 정책 취소는 이미 확정한 해제값/피해 스냅샷을 지우거나 재해제하지 않는다. 리셋/소유 효과 제거의 실행권 반환도 Unity 지연 파괴 전에 정책을 닫는다. 차지 판정 실행/표현 전체의 순수 이행이나 새로운 차지/충전 규칙은 추가하지 않는다.

## 검증과 남은 범위

`ActionResourceTests`는 순수 참조 경계·키/스냅샷·실행당 결과·잘못된/옛 입력·포트 오류·재진입·반환과 완료 사실 보존·기본/특수 분류·실제 무기 원본의 독립 충전/순차 회복을 검사한다. `MeleeActionRunnerTests`는 정상 활성화 거부에서 타격/완료를 실행하지 않고 예외를 던지지 않음을 검사한다.

`ActionResourceIntegrationTests`는 본 게임/시험장의 공통 전투에서 기본 공격의 발동 스탯·특수 준비 취소·발동 후 취소/교체/편집에도 유지되는 잔상 피해·비활성 원본 무기 회복·자원 거부·리셋 뒤 옛 호출·시간 0 패링 소비·발사기 S 예외를 확인한다. 기존 입력/취소/특수/프레임 적용 회귀와 함께 실행한다. 절차와 아트/제품 검증의 구분은 [검사 방법](../../testing/testing.md)을 따른다.

`EquipmentChargeTests`는 순수 참조 방향·읽기 전용 스냅샷·독립 소유자·기존 어댑터와 공유한 원본·순차 회복·정비 부담/주기/리셋 호환을 검사한다. `EquipmentChargeIntegrationTests`는 두 씬의 실제 단검 3회 발동/취소 뒤 교체·비활성 회복, 1↔3 정비와 원래 회복시각/무기 ID·리셋을 검사한다.

`EquipmentStatTests`는 스냅샷/입력 방어 복사·읽기 전용 목록·혼합 곱 중첩/분류·무효 단일/일괄 명령의 상태 보존·원본/호환 뷰·분리된 Clone·무기 독립성과 충전/선택 불변을 검사한다. `EquipmentStatIntegrationTests`는 두 씬에서 시작 공속/발동 피해·기존 정비 쿨타임·발동 스냅샷·교체/리셋·발사기 예외를 확인한다. 기존 A/B 상태 복원과 독립 효과/프레임 적용 회귀도 같은 명령 경로를 검사한다.

`EquipmentInstanceTests`는 순수 참조 방향·ID/선택/스탯/충전 소유·무효 선택 보존·불변 전체 조회·독립 인스턴스·같은 원본을 보는 호환 뷰/기존 스탯 주입을 검사한다. `EquipmentInstanceIntegrationTests`는 두 씬의 발동 키/선택·활성 정비 거부·교체·비활성 무기 정비 부담·리셋의 선택/스탯/ID 보존과 다른 무기의 독립 소비를 확인한다.

`EquipmentLoadoutTests`는 두 무기/활성 슬롯의 실제 소유·입력 목록 방어 복사·중복/누락/무효 슬롯 거부·불변 전체 조회·같은 원본을 보는 안정적인 호환 뷰와 교체 중 자원 보존을 검사한다. `EquipmentLoadoutIntegrationTests`는 두 씬의 실제 교체 예약/공격 우선순위·대시 취소 뒤 예약 폐기·발동 원본/비활성 회복·리셋의 활성 슬롯/무기/잉크 보존과 차단 입력을 검사한다. 고정/프레임 A/B의 같은 프로필 설정/복원 회귀도 함께 확인한다.

`EquipmentCommandsTests`는 순수 참조 방향·성공 스냅샷·같은 무기/자식 원본·1↔3 부담 정규화·스탯 쿨감/기존 계산·없는 슬롯/옛 무기/시각/설정 거부·스탯 예외/누락/무효값의 사전 실패·재진입·호환 뷰 공유를 검사한다. `EquipmentMaintenanceIntegrationTests`는 두 씬의 실제 정비에서 무효 카탈로그 요청의 무변경/무예외 거부·유효 선택/충전 보존·기존 행동/전투 중 정비 거부·실패 뒤 접근 표식 유지와 성공 뒤 표식 정리를 확인한다.

현재 충전·능력치·프로필 무기의 실행 ID/형태·특수 선택·장착 목록/활성 슬롯과 해석된 설정의 정비 원본 변경은 Equipment로 이행했다. 카탈로그 인덱스를 안정적인 콘텐츠 정의에 연결하는 전체 무기/획득·교환·재고/정비·아이템 장비 명령·Run 수명으로의 이행, 전체 행동 정의/독립 효과의 버전 이행, 제품 장비 UI와 저장/드랍 정책은 후속 범위다. 현재 포트/자동 검사만으로 전체 장비 또는 리팩토링 목표를 완료했다고 하지 않는다.
