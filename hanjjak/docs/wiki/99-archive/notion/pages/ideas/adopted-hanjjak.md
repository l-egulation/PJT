## 1. 아이디어 설명
‘한 짝’은 버려진 나무젓가락이 재료를 모아 자신을 강화하는 방치형 게임이다.
핵심은 한 사용자의 플레이 결과가 다른 사용자의 게임에 실시간으로 영향을 준다는 점이다. 사용자가 강화에 실패해 아이템이 파괴되면 해당 데이터가 이벤트로 전송되고, 파괴된 아이템은 ‘잔해 재료’로 변환되어 전체 시장에 공급된다.
`사용자 A의 강화 파괴 → 잔해 생성 → 시장 공급량·가격 변화 → 사용자 B가 구매`
즉, 사용자의 실패 데이터가 다른 사용자의 성장 재료가 되며, 모든 사용자가 하나의 실시간 경제를 함께 만들어간다.

## 2. 빅데이터·분산 특징
게임에서는 채집, 강화, 파괴, 거래, 분리수거 등의 행동 데이터가 지속적으로 발생한다. 이 이벤트들은 Kafka를 통해 분산 수집되고 여러 처리 시스템에서 동시에 활용된다.
예를 들어 강화 파괴 이벤트 하나로 다음 작업이 수행된다.
- 잔해 재료 생성
- 시장 공급량과 가격 갱신
- 단계별 실제 파괴율 집계
- 시즌 공동 목표 반영
- 비정상적인 강화·거래 패턴 탐지
사용자가 증가하면 이벤트 수도 함께 증가하므로 Kafka 파티션과 처리 서버를 확장해 부하를 분산한다. 처리 서버에 장애가 발생하더라도 저장된 이벤트를 다시 처리할 수 있으며, 이벤트 ID를 이용해 재화가 중복 지급되는 문제를 방지한다.
## 3. 데이터 활용
수집된 데이터는 단순한 운영 통계가 아니라 실제 게임 콘텐츠에 사용된다.
- 실제 거래량과 공급량에 따른 시장 가격 형성
- 강화 단계별 성공·실패·파괴율 분석
- 사용자 이탈 구간 및 게임 밸런스 개선
- 비정상 거래와 재화 획득 탐지
- 시즌별 전체 사용자 기여도 집계
실시간 처리 결과는 WebSocket을 통해 사용자 화면에 즉시 전달한다. 다른 사용자의 아이템이 파괴되면 시장 재고와 가격, 서버 전체 통계가 바로 변경된다.
## 4. 구현 방법
`게임 클라이언트 → 게임 서버 → Kafka → 실시간 분산 처리 → Redis·DB → WebSocket → 사용자 화면`
- 게임 서버에서 사용자 행동을 이벤트로 생성
- Kafka에서 이벤트 종류와 사용자별로 데이터 분산
- Kafka Streams 또는 Flink로 시장 가격과 통계 실시간 계산
- Redis에 실시간 결과, PostgreSQL에 거래와 사용자 상태 저장
- WebSocket으로 시장 변화와 시즌 진행률 전달
- 원본 이벤트를 장기간 저장해 Spark로 사용자 행동과 시장 변화 분석
