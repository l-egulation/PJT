## 범위와 책임

이 계획은 선택한 챕터의 스테이지 목록·상세·입장·반복 설정을 구현 가능한 화면·계약 요구로 연결한다. 해금·진행·반복 규칙은 [스테이지 SSOT](../../30-domain/world/ssot.md), 피해 배율은 [전투 SSOT](../../30-domain/combat/ssot.md), 화면 표현은 [클라이언트 UX SSOT](../../30-domain/player/ux/ssot.md), 서버 진행·최근 전투 기록은 [계정·저장 SSOT](../../30-domain/player/ssot.md)를 따른다.

## 사용자 흐름

1. 사용자가 해금된 챕터를 선택한다.
2. 화면은 선택 챕터의 스테이지 목록과 현재 전투·클리어·잠금·반복 대상 상태를 조회한다.
3. 사용자는 스테이지를 선택해 주요 보상, 현재 관통 기준 피해 퍼센트와 해당 스테이지의 최근 실패를 확인한다.
4. 해금된 스테이지의 입장을 확정하면 현재 전투를 즉시 중단하고 선택 스테이지의 0/20부터 시작한다.
5. 해금된 1~9스테이지를 반복 대상으로 설정하면 서버가 검증·저장하고 현재 사이클 종료 뒤 적용한다.
6. 서버가 클리어를 확정하면 다음 스테이지를 자동 해금한다. 클라이언트는 별도 해금 명령을 보내지 않는다.

## 조회·명령 계약

아래 경로는 구현 계약 후보이며 전송 프로토콜·물리 스키마보다 의미와 권한을 먼저 고정한다.

### 스테이지 목록

`GET /api/v1/chapters/{chapterId}/stages`

- 챕터 존재와 최신 서버 해금 상태를 다시 검증한다.
- 존재하지 않는 챕터는 `CHAPTER_NOT_FOUND`, 잠긴 챕터는 해금 선행 정보를 포함한 `CHAPTER_LOCKED`로 거부한다.
- 응답은 챕터 식별자와 스테이지 항목 목록을 포함한다.

| 필드 | 의미 |
| --- | --- |
| `stageId` | 스테이지 식별자 |
| `number` | 챕터 안 표시 번호 |
| `name` | 콘텐츠 버전의 표시 이름 |
| `cleared` | 서버가 확정한 최초 클리어 여부 |
| `locked` | 서버가 판정한 입장 불가 여부 |
| `isCurrent` | 현재 전투 중인 스테이지 여부 |
| `isRepeatTarget` | 서버에 저장된 현재 반복 대상 여부 |
| `repeatEligible` | 해금된 1~9스테이지인지 여부 |

### 스테이지 상세

`GET /api/v1/stages/{stageId}`

- 현재 콘텐츠 버전의 스테이지 존재 여부와 인증 사용자의 최신 진행 상태를 검증한다.
- 응답은 `stageId`, 번호·이름, 잠금·클리어·현재·반복 상태, `majorRewards`, `damagePercent`, `latestFailure`를 포함한다.
- `damagePercent`는 [전투 SSOT](../../30-domain/combat/ssot.md)의 `round(100 × D_mult)`다. 현재 사용자 방어 관통과 스테이지 공통 방어력을 입력으로 계산하며 입장 조건이 아니다.
- `latestFailure`는 서버의 최근 전투 사건 50건 중 이 스테이지의 가장 최근 실패 1건이다. 기록이 없으면 `null`이다.
- 권장 레벨·권장 공격력·권장 HP·권장 관통·현재 내 스펙·성장벽 유형은 응답과 화면에서 제공하지 않는다.

### 스테이지 입장

`POST /api/v1/stages/{stageId}/enter`

- 존재하는 스테이지인지, 최신 서버 진행에서 해금됐는지, 현재 진행 상태와 명령이 양립하는지 검증한다.
- 성공하면 `enteredStage`, `battleState`를 반환하고 선택 스테이지의 0/20부터 즉시 시작한다. 웹 상태 엔진은 브라우저 수명주기와 서버 명령 재동기화를 따른다.
- 잠긴 스테이지는 `STAGE_LOCKED`, 존재하지 않는 스테이지는 `STAGE_NOT_FOUND`로 거부한다.
- 권장 정보나 피해 퍼센트는 입장 조건이 아니다.

### 반복 대상 설정

`PATCH /api/v1/battle/repeat-stage`

- 요청 body는 `stageId`를 가진다.
- 서버는 스테이지 존재·해금·1~9 여부를 검증한다.
- 10스테이지는 무드롭 돌파 시험이므로 `STAGE_NOT_REPEATABLE`로 거부한다.
- 성공하면 `idleMode`, `repeatStageId`, `appliesAfterCurrentCycle`을 반환하고 반복 대상을 서버 권한 상태로 저장한다. `stageId: null`은 자동 진행으로 전환한다. 진행 중인 사이클이 없거나 저장값과 같은 요청이면 `appliesAfterCurrentCycle`은 `false`다.
- 현재 사이클은 중단하지 않는다. 웹 상태 엔진은 사이클 경계에서 로컬 방치모드를 `스테이지 반복`으로 전환하고 서버 반복 대상을 사용한다.

### 스테이지 진행 조회

`GET /api/v1/progression/stages`

- `currentStage`, `highestClearedStage`, `repeatStage`를 반환한다.
- `repeatStage`는 서버에 저장된 반복 대상이며 로컬 캐시가 권한을 대신하지 않는다.

### 클리어와 자동 해금

스테이지 클리어는 전투 결과 확정 유스케이스가 처리한다. 같은 서버 경계에서 현재 스테이지 최초 클리어, 다음 스테이지 또는 다음 챕터 해금과 멱등 기록을 원자적으로 반영한다. 클라이언트용 `POST /stages/{stageId}/unlock`은 제공하지 않는다.

## 화면 상태와 상호작용

- 스테이지 노드는 클리어·현재 전투·잠금·반복 대상을 색상 외 아이콘·텍스트·접근성 이름으로 구분한다.
- 선택 상태는 진행 상태와 별개다. 선택만으로 전투 위치·반복 대상·클리어 상태를 바꾸지 않는다.
- 잠긴 노드도 선택해 이름·주요 보상·`피해 N%`·최근 실패를 포함한 전체 상세를 확인할 수 있지만 입장·반복 설정 동작은 비활성화한다. 직접 API 호출은 서버가 다시 차단한다.
- 상세 패널은 번호·이름, 주요 보상, `피해 N%`, 최근 실패 1건과 입장 동작을 제공한다.
- 최근 실패가 없으면 `실패 기록 없음`을 표시한다.
- 1~9의 반복 설정은 웹 상태 엔진의 현재 적용 상태와 다음 사이클 적용 예정 상태를 구분한다. 10에는 반복 설정을 제공하지 않는다.
- 현재 전투 스테이지를 확인할 수 있어야 하며 목록 탐색 중 전투는 계속된다.
- 로딩 중 같은 명령의 중복 전송을 막고 인증 만료·서버 오류·콘텐츠 버전 불일치에 공통 오류와 재시도를 제공한다.

## Front·Backend·저장·콘텐츠 책임

| 경계 | 책임 |
| --- | --- |
| Front | 서버 상태 표시, 노드 선택, `피해 N%`·보상·최근 실패 표시, 잠금·10스테이지 반복 동작 비활성화, 로딩·오류·접근성 |
| Backend | 목록·상세 조합, 피해 퍼센트 계산, 존재·해금·반복 가능 여부 재검증, 입장·반복 명령 처리, 클리어와 다음 해금 원자성 |
| 저장 | 현재·최고·최초 클리어·챕터 해금·반복 대상 무결성, 최근 전투 사건 50건, 존재하지 않는 콘텐츠 참조 방지 |
| 콘텐츠 | 스테이지 ID·순서·이름·공통 적 레벨·방어력·보상·보스 패턴·해금 관계·버전 |

## 검증 기준

- 선택 챕터의 10개 스테이지가 클리어·현재·잠금·반복 대상 상태와 함께 조회된다.
- 선택만으로 현재 전투·반복 대상·진행 상태가 바뀌지 않는다.
- 같은 스테이지의 일반 몬스터와 보스가 같은 적 레벨·방어력을 사용한다.
- `damagePercent`가 현재 관통과 스테이지 공통 방어력으로 전투 공식과 일치하며 화면은 `피해 N%`만 표시한다.
- 권장 레벨·권장 스펙·내 스펙·성장벽 유형이 응답과 화면에 없다.
- 해금 스테이지 입장은 즉시 전환되고 0/20부터 시작하며 기존 방치모드를 유지한다.
- 잠긴 스테이지 직접 입장 요청과 존재하지 않는 `stageId`가 각각 실패한다.
- 잠긴 스테이지 선택에서도 전체 상세가 조회되지만 입장·반복 동작은 비활성화되고 직접 명령은 서버에서 거부된다.
- 1~9 반복 설정은 현재 사이클을 보존하고 다음 사이클부터 적용된다.
- 잠긴 스테이지와 10스테이지의 반복 설정이 서버에서 거부된다.
- 반복 대상 설정 응답은 서버 반복 대상, 방치모드와 다음 사이클 적용 여부를 반환하고, 로컬 상태 엔진은 현재 사이클과 다음 사이클의 방치모드·반복 대상을 구분한다.
- 해당 스테이지의 최근 실패가 있으면 최근 1건만, 없으면 빈 상태가 반환된다.
- 사용자별 최근 전투 사건은 최신 50건만 서버에 남고 51번째 확정 시 가장 오래된 기록이 제거된다.
- 최초 클리어 결과를 재처리해도 클리어·다음 스테이지 해금이 중복되지 않는다.
- 클라이언트가 호출할 수 있는 수동 해금 API가 없다.
